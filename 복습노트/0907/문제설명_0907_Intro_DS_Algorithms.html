P1. 두 정수 바꾸기

textbook-ch01-q01 · 원 문제 보기

2개의 정수를 서로 교환하는 알고리즘을 의사 코드로 작성해보자.

교과서 원문 보기

1장 자료구조와 알고리즘 · 01번 · 책 36쪽

2개의 정수를 서로 교환하는 알고리즘을 의사 코드로 작성해보자.

문제를 내 말로 읽어요

원래 a와 b의 값을 서로 바꿔요. 한 값을 덮어쓰기 전에 보관할 곳이 필요해요.

이 문제를 봤을 때 떠올릴 개념과 공식

“서로 교환”은 swap이에요. 대입은 오른쪽 값을 읽어 왼쪽 저장소를 바꾸므로, 임시 변수 temporary variable로 옛 a를 보존해야 해요.

종이에 적을 첫 줄

temp ← a

왜 이렇게 푸는지 함께 따라가요

temp ← a
a ← b
b ← temp

완성 답과 검산

a=3,b=8에서 temp=3 → a=8,b=8 → a=8,b=3이에요. 임의의 옛 값 A,B도 최종 a=B,b=A이므로 두 조건을 만족해요.

이 문제에서 조심할 점

a←b 다음 b←a를 쓰면 원래 a가 이미 사라져 두 값이 같아져요.

설명을 닫고 다시 해 봐요

  1. temp ← a
  2. 임시 보관 → a에 b → b에 옛 a
  3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

첫 줄

temp ← a

떠올릴 개념·공식

임시 보관 → a에 b → b에 옛 a

검산

본문의 조건과 독립 추적을 함께 확인해요.

조건·구분과 확인

  • a←b 뒤 b←a를 쓰면 옛 a를 잃어 두 값이 같아져요.
  • 옛 값이 A,B이면 최종 a=B,b=A예요.

P2. 1부터 n까지 더하기

textbook-ch01-q03 · 원 문제 보기

1부터 n까지의 합을 계산하는 알고리즘을 의사 코드로 작성해보자.

교과서 원문 보기

1장 자료구조와 알고리즘 · 03번 · 책 36쪽

1부터 n까지의 합을 계산하는 알고리즘을 의사 코드로 작성해보자.

문제를 내 말로 읽어요

1부터 양의 정수 n까지 빠짐없이 더하는 알고리즘이에요.

이 문제를 봤을 때 떠올릴 개념과 공식

“1부터 n까지”는 누적 합 accumulator의 단서예요. 합의 항등원은 0이고 각 반복에서 현재 i를 정확히 한 번 더해요.

종이에 적을 첫 줄

sum ← 0

왜 이렇게 푸는지 함께 따라가요

sum ← 0
for i ← 1 to n
    sum ← sum + i
output sum

완성 답과 검산

n=4에서 sum은 0→1→3→6→10이에요. i까지 끝났을 때 sum=1+…+i라는 불변식이 초기·유지·종료를 만족해요. 별도 공식 n(n+1)/2도 10을 주어요.

이 문제에서 조심할 점

i<n으로 반복하면 n을 빼먹어요. C로 옮길 때는 합이 정수 타입 범위 안에 있어야 해요.

설명을 닫고 다시 해 봐요

  1. sum ← 0
  2. 0에서 시작해 1..n 누적
  3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

첫 줄

sum ← 0

떠올릴 개념·공식

0에서 시작해 1..n 누적

검산

본문의 조건과 독립 추적을 함께 확인해요.

조건·구분과 확인

  • 양의 정수 n에 대해 sum=0에서 1..n을 한 번씩 더해요.
  • i<n이면 n이 빠지고, C에서는 합의 타입 범위도 확인해요.
  • i까지 끝나면 sum=1+…+i이고, n=4에서 10으로 n(n+1)/2와 일치해요.

P3. 큐에서 꺼내는 순서

textbook-ch05-q01 · 원 문제 보기

문자 A, B, C, D, E를 큐에 넣었다가 다시 꺼내어 출력하면 어떻게 되는가?

(a)

A, B, C, D, E

(b)

E, D, C, B, A

(c)

A, B, C, E, D

(d)

B, A, C, D, E

교과서 원문 보기

5장 큐 · 01번 · 책 171쪽

문자 A, B, C, D, E를 큐에 넣었다가 다시 꺼내어 출력하면 어떻게 되는가?

(a)

A, B, C, D, E

(b)

E, D, C, B, A

(c)

A, B, C, E, D

(d)

B, A, C, D, E

문제를 내 말로 읽어요

A부터 E까지 차례로 큐에 넣고 모두 꺼내요.

이 문제를 봤을 때 떠올릴 개념과 공식

“큐(queue)”는 먼저 온 것이 먼저 나가는 FIFO의 단서예요. enqueue는 뒤(rear)에 붙이고 dequeue는 앞(front)에서 꺼내요.

종이에 적을 첫 줄

첫 삭제 직전 큐를 [A,B,C,D,E]로 적어요.

왜 이렇게 푸는지 함께 따라가요

정답이에요. 앞에서 차례로 삭제하면 A→B→C→D→E예요.
E부터 꺼내는 것은 스택의 LIFO예요. 큐의 첫 삭제 A와 달라요.
처음 세 글자는 맞지만 D가 E보다 먼저 들어왔으므로 끝 두 글자를 바꿀 수 없어요.
B가 A보다 먼저 나가면 먼저 들어온 A를 건너뛰므로 FIFO를 위반해요.

완성 답과 검산

다섯 삭제 뒤 큐는 빈 상태이고 출력은 ABCDE예요.
첫 출력만 비교해도 E≠A로 배제돼요.
네 번째 삭제는 D여야 하므로 E가 나오는 보기를 배제해요.
첫 삭제가 A여야 하므로 B가 나오는 보기를 배제해요.

이 문제에서 조심할 점

큐와 스택을 혼동하지 않아요. 보기 a~d를 각각 비교하되 답은 하나예요.

설명을 닫고 다시 해 봐요

  1. 첫 삭제 직전 큐를 [A,B,C,D,E]로 적어요.
  2. FIFO → (a) ABCDE
  3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

첫 줄

첫 삭제 직전 큐를 [A,B,C,D,E]로 적어요.

떠올릴 개념·공식

FIFO → (a) ABCDE

검산

본문의 조건과 독립 추적을 함께 확인해요.

조건·구분과 확인

  • 뒤(rear)에 넣고 앞(front)에서 꺼내므로 (a) ABCDE예요.
  • E부터 꺼내는 LIFO와 달리 첫 삭제는 A이고 D는 E보다 먼저 나와요.

P5. 자료구조·알고리즘과 설계·분석 구별

lecture-s01-p6-design-analysis-contract · 원 문제 보기

강의 예제 기반 자체 출제 S1 p6

벽돌을 지그재그로 쌓아 튼튼한 벽을 만드는 비유와 프로그램 개발 과정을 생각해요.

구할 것

  1. (a) 벽돌 자체, 벽돌을 조직한 벽의 구조, 벽을 쌓는 절차는 각각 데이터·자료구조·알고리즘 중 무엇에 대응하는지 쓰고, 알고리즘 정의에서 유한한 명령과 순서가 필요한 이유를 설명하세요.
  2. (b) 문제를 풀 새 방법을 고르는 일과 주어진 방법의 비용을 계산하는 일을 각각 설계·분석과 연결하고, 시간·공간·재사용성·가독성을 함께 고려해야 하는 이유를 설명하세요.
강의 예제 보기

S1 p6 · 추가 근거 p2,5,7 · Software_1_자료구조및알고리즘.pdf. 강의의 개념·그림·코드 연산을 바탕으로 조건과 질문을 새로 작성한 자체 출제예요. 제시 코드는 있는 경우 학습 확인용 자체 코드이며 강의 원문 발췌가 아니에요. 질문·입력 조건·검산은 자체 작성했어요.

문제를 내 말로 읽어요

벽돌 쌓기 비유를 통해 데이터·자료구조·알고리즘의 역할과 유한한 순서의 중요성을 구별하고, 알고리즘의 설계·분석 및 좋은 프로그램의 평가 기준을 정리하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

재료 자체는 데이터(data), 재료를 조직한 구조는 자료구조(data structure), 수행 절차는 알고리즘(algorithm)을 떠올리게 해요. 새 해결 방법은 설계(design), 주어진 방법의 비용 평가는 분석(analysis)의 단서이며, 시간·메모리는 실행 비용이고 가독성·재사용성은 유지보수 품질이에요.

종이에 쓰는 첫 줄

벽돌 자체 → 데이터, 조직한 벽의 구조 → 자료구조, 쌓는 절차 → 알고리즘.

왜 이렇게 푸는지 함께 따라가요

(a) 벽돌 자체는 재료인 데이터, 벽돌을 지그재그로 맞물려 배치한 벽의 구조는 자료구조, 벽돌을 한 단씩 쌓아 올리는 절차는 알고리즘이에요. 같은 명령이라도 순서가 바뀌면 결과가 달라지고, 절차가 유한 번 안에 끝나야 결과를 얻을 수 있으므로 유한한 명령과 순서가 필요해요.

(b) 문제를 풀 새로운 절차를 고안·선택하는 일은 설계이고, 이미 주어진 절차의 시간·공간 비용을 계산하는 일은 분석이에요. 실행 시간(빠르기)과 메모리(공간) 비용을 줄이는 것뿐 아니라, 읽기 쉽고(가독성) 다른 곳에서도 쓸 수 있게(재사용성) 작성해야 수정과 협업 비용을 줄일 수 있어요.

완성 답과 검산

(a) 벽돌(데이터)·벽 구조(자료구조)·쌓는 법(알고리즘)이 서로 일대일 대응하며, 종료 조건과 순서가 빠지면 알고리즘 정의를 만족하지 않음을 확인해요.

(b) 비용을 평가할 절차가 이미 주어졌으면 분석, 절차를 새로 만들면 설계로 구별되고, 시간·공간·가독성·재사용성 네 가지 기준이 모두 포함되었는지 확인해요.

이 문제에서 조심할 점

코드가 짧다는 사실만으로 실행이 빠르다고 결론내리지 않아요. 가독성과 실행 비용은 별도로 판단해요.

설명을 닫고 다시 해 봐요

  1. 벽돌·벽 구조·쌓는 절차를 데이터·자료구조·알고리즘에 대응해 적어요.
  2. 알고리즘 정의에서 유한성과 순서가 필요한 이유를 한 문장으로 설명해요.
  3. 설계와 분석을 구별하고 네 가지 품질 기준을 점검해요.

떠올릴 개념·공식

데이터(재료)·자료구조(조직 구조)·알고리즘(유한한 명령의 순서), 설계(방법 고안)와 분석(비용 계산).

첫 줄

벽돌 자체 → 데이터, 조직한 벽의 구조 → 자료구조, 쌓는 절차 → 알고리즘.

핵심 답

(a) 벽돌=데이터, 벽 구조=자료구조, 쌓는 절차=알고리즘(유한한 명령과 순서 필요) (b) 새 방법=설계, 비용 계산=분석(시간·공간·가독성·재사용성 고려).

조건·구분과 확인

  • 순서가 바뀌면 결과가 달라지고 유한 번 안에 끝나야 결과를 얻어요.
  • 코드 길이만으로 빠르기를 판단하지 않아요.

P6. 지역 변수·함수 분리와 자원 공유

lecture-s01-p7-resource-scope-sharing · 원 문제 보기

강의 예제 기반 자체 출제 S1 p7

한 함수 안에서만 쓰는 큰 임시 배열의 선언 위치, 포인터를 통한 자원 공유, 그리고 정수형 배열의 공간 크기를 비교하려고 해요(재귀 호출은 동시 활성 객체 수를 따지기 위한 보충 조건이에요).

구할 것

  1. (a) 임시 배열을 전역 변수로 두는 설계와 지역 변수로 두는 설계의 범위·수명을 비교하고, 지역 변수가 재귀 호출에서도 언제나 전역 변수보다 메모리를 적게 쓰는지 설명하세요.
  2. (b) 역할별 함수 분리와 포인터 주소 공유의 장점·주의점을 쓰고, int를 unsigned int로 바꿀 때의 바이트 크기 변화와 원소 10개만 필요한데 100칸 배열을 잡을 때 남는 칸 수를 구하세요.
강의 예제 보기

S1 p7 · 추가 근거 p6 · Software_1_자료구조및알고리즘.pdf. 강의의 개념·그림·코드 연산을 바탕으로 조건과 질문을 새로 작성한 자체 출제예요. 제시 코드는 있는 경우 학습 확인용 자체 코드이며 강의 원문 발췌가 아니에요. 질문·입력 조건·검산은 자체 작성했어요.

문제를 내 말로 읽어요

임시 배열을 전역·지역 변수로 둘 때의 범위·수명과 재귀 호출 시 메모리 변화를 비교하고, 함수 분리·포인터 주소 공유 및 정수 배열의 공간 크기를 점검하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

‘임시 배열’은 범위(scope)와 수명(lifetime), ‘주소 공유’는 한 객체를 여러 경로에서 가리키는 포인터 공유의 단서예요. 메모리 비용은 선언 위치 이름만이 아니라 동시에 살아 있는 활성 객체 수를 세어 판단하며, int와 unsigned int는 표현 범위만 다르고 바이트 크기는 같아요.

종이에 쓰는 첫 줄

누가 쓰는가(범위) · 언제까지 살아 있는가(수명) · 동시에 몇 개가 존재하는가(활성 호출 수)를 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) 한 함수에서만 쓰는 임시 배열을 지역 변수로 두면 접근 범위와 수명을 그 함수 실행 동안으로 제한할 수 있지만, 전역 변수는 프로그램 전체 실행 동안 메모리를 차지해요. 그러나 지역 변수가 항상 메모리를 적게 쓰는 것은 아니며, 동시에 활성인 재귀 호출마다 별도의 지역 배열이 스택에 생성되면 전체 메모리가 더 많이 들 수 있어요.

(b) 역할별로 함수를 분리하면 가독성과 재사용성이 좋아지고, 큰 원본을 포인터 주소로 공유하면 복사 비용을 줄일 수 있지만 한쪽에서 바꾼 값이 다른 쪽에도 반영되는 점에 주의해야 해요. 또한 int를 unsigned int로 바꿔도 바이트 크기는 줄지 않으며, 10개만 필요한데 100칸 배열을 잡으면 100 - 10 = 90칸이 사용되지 않고 남아요.

완성 답과 검산

(a) 단일 호출(배열 1개)과 재귀 깊이 $d$인 동시 활성 호출(배열 $d$개)을 비교하면 지역 변수가 항상 메모리를 적게 쓴다는 절대 명제가 거짓임을 확인해요.

(b) C 표준에서 대응하는 signed와 unsigned 정수형의 크기는 같고, 배열 칸 수는 10(사용) + 90(미사용) = 100으로 검산돼요.

이 문제에서 조심할 점

지역 변수가 언제나 공간을 절감한다는 절대 명제는 틀려요. 주소로 넘긴다고 호출자 객체의 복사본이 새로 생기는 것도 아니에요.

설명을 닫고 다시 해 봐요

  1. 전역 변수와 지역 변수의 범위·수명 및 재귀 호출 시 메모리 차이를 적어요.
  2. 함수 분리와 포인터 주소 공유의 장점·주의점을 정리해요.
  3. unsigned int 크기 변화 여부와 100칸 중 미사용 칸 수를 계산해요.

떠올릴 개념·공식

변수 범위(scope)·수명(lifetime), 동시 활성 재귀 프레임 수, 포인터 주소 공유와 타입 크기.

첫 줄

누가 쓰는가(범위) · 언제까지 살아 있는가(수명) · 동시에 몇 개가 존재하는가(활성 호출 수)를 적어요.

핵심 답

(a) 지역 변수는 범위·수명을 제한하나 동시 재귀 호출마다 배열이 생기면 메모리가 늘 수 있음 (b) 함수 분리는 가독성·재사용성 향상, 포인터 공유는 복사 절감·변경 전파 주의, unsigned int 크기는 동일, 미사용 90칸.

P7. 일상 예제로 고르는 자료구조

lecture-s01-p13-everyday-structure-selection · 원 문제 보기

강의 예제 기반 자체 출제 S1 p13

일상생활의 다섯 가지 데이터(할 일의 순서, 도시와 도로의 연결, 상하 관계 조직도, 맨 위부터 꺼내는 책더미, 단어로 뜻을 찾는 영어사전)를 알맞은 자료구조로 표현하려고 해요.

구할 것

  1. (a) 다섯 가지 예시를 리스트·그래프·트리·스택·사전 중 알맞은 자료구조와 각각 짝짓고, 보존하려는 관계를 기준으로 이유를 쓰세요.
  2. (b) 책 A, B, C를 차례로 쌓은 뒤 한 권을 꺼낼 때 나오는 책을 쓰고, 먼저 줄 선 사람이 먼저 나가는 매표소 줄(큐)과 어떤 점이 다른지 설명하세요.
강의 예제 보기

S1 p13 · 추가 근거 p14 · Software_1_자료구조및알고리즘.pdf. 강의의 개념·그림·코드 연산을 바탕으로 조건과 질문을 새로 작성한 자체 출제예요. 제시 코드는 있는 경우 학습 확인용 자체 코드이며 강의 원문 발췌가 아니에요. 질문·입력 조건·검산은 자체 작성했어요.

문제를 내 말로 읽어요

일상생활의 다섯 가지 데이터 사례를 리스트·그래프·트리·스택·사전에 짝짓고, 책더미(스택)와 매표소 줄(큐)에서 원소가 나오는 순서를 비교하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

‘어떤 관계를 보존하는가’가 자료구조 선택의 단서예요. 리스트(list)는 선형 순서, 그래프(graph)는 일반 연결, 트리(tree)는 상하 계층을 표현하고, 스택(stack)은 후입선출(LIFO), 큐(queue)는 선입선출(FIFO), 사전(dictionary)은 키→값 탐색을 사용해요.

종이에 쓰는 첫 줄

할 일: 선형 순서 → 리스트라고 첫 대응을 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) 보존할 관계를 기준으로 짝지으면 할 일 목록은 선형 순서가 있으므로 리스트, 도시와 도로는 그물망 연결 관계이므로 그래프, 조직도는 상하 계층 구조이므로 트리, 맨 위에서만 넣고 빼는 책더미는 스택, 단어를 키로 뜻을 찾는 구조는 사전이에요.

(b) 책 A, B, C를 차례로 쌓으면 가장 마지막에 올린 C가 맨 위에 놓이므로 한 권을 꺼내면 C가 먼저 나와요(후입선출, LIFO). 반면 매표소 줄(큐)은 가장 먼저 줄을 선 사람이 가장 먼저 나가는 선입선출(FIFO) 구조예요.

완성 답과 검산

(a) 리스트(순서)·그래프(연결)·트리(계층)·스택(맨 위 입출)·사전(키 조회) 다섯 가지가 중복 없이 일대일로 대응되는지 확인해요.

(b) A → B → C 순서로 넣을 때 스택에서는 C가 먼저 나오고 큐에서는 A가 먼저 나와 입출 순서가 정반대임을 확인해요.

이 문제에서 조심할 점

연결이 있다는 이유만으로 모두 트리라고 하지 않아요. 계층 관계인지 확인하고, 스택의 후입선출과 큐의 선입선출을 바꾸지 않아요.

설명을 닫고 다시 해 봐요

  1. 다섯 가지 일상 사례가 보존하는 관계를 적고 알맞은 자료구조와 연결해요.
  2. A, B, C를 쌓은 책더미에서 먼저 나오는 원소를 적어요.
  3. 스택(LIFO)과 큐(FIFO)의 인출 순서 차이를 비교해요.

떠올릴 개념·공식

리스트(선형 순서), 그래프(연결), 트리(계층), 스택(LIFO), 큐(FIFO), 사전(키→값).

첫 줄

할 일: 선형 순서 → 리스트라고 첫 대응을 적어요.

핵심 답

(a) 할 일=리스트, 도시·도로=그래프, 조직도=트리, 책더미=스택, 영어사전=사전 (b) C가 먼저 나오며(LIFO), 큐인 매표소 줄은 먼저 온 사람이 먼저 나감(FIFO).

조건·구분과 확인

  • 연결이 있다는 이유만으로 트리라 하지 말고 계층 관계인지 확인해요.

P4. 최대값 탐색의 초기값과 종료 조건

lecture-s01-p21-find-max · 원 문제 보기

후속 수업 보충: 이 최대값 알고리즘의 분석은 0914 수업에서 다뤘어요. 이 문항은 보존하되 0907 핵심 범위의 평가 문항으로 세지 않아요.

강의 예제 기반 자체 출제 S1 p21

아래 함수는 전역 배열 int score[MAX];(MAX는 n 이상인 상수)의 앞 n개 원소를 입력으로 받으며, 현재 score = {-8, -3, -10, -1}, n = 4예요.

int find_max_score(int n)
{
    int i, tmp;
    tmp = score[0];
    for(i=1;i<n;i++){
        if(score[i] > tmp) tmp = score[i];
    }
    return tmp;
}

구할 것

  1. (a) find_max_score(4)를 실행할 때 tmp의 값 변화와 최종 반환값을 쓰세요.
  2. (b) tmp = 0으로 초기화할 때 생기는 오류와, 이 함수가 유효한 알고리즘으로 유한하게 종료하기 위한 n의 조건 및 종료 이유를 설명하세요.
강의 예제 보기

S1 p21 · Software_1_자료구조및알고리즘.pdf. 강의 코드의 해당 연산을 발췌해 들여쓰기를 정리했습니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

int find_max_score(int n)
{
    int i, tmp;
    tmp = score[0];
    for(i=1;i<n;i++){
        if(score[i] > tmp) tmp = score[i];
    }
    return tmp;
}

후속 수업 보충: 이 최대값 알고리즘은 0914 수업에서 분석했어요. 0907 핵심 범위의 평가 문항으로 세지 않아요.

문제를 내 말로 읽어요

음수 원소 네 개가 들어 있는 배열 score = {-8, -3, -10, -1}에서 최대값을 찾는 함수를 따라가며 tmp의 변화를 구하고, 초기값 0 오류와 유한 종료 조건을 확인하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “최대값 탐색의 초기값과 종료 조건”이에요. 배열은 데이터를 보관하는 자료구조이고 반복·비교는 최대값을 찾는 알고리즘이에요. 최대값 후보 변수 tmp는 반드시 배열의 실제 첫 원소 score[0]으로 초기화해야 음수 입력에서도 성립해요.

종이에 적을 첫 줄

tmp = score[0] = -8, i = 1로 상태 추적을 시작해요.

왜 이렇게 푸는지 함께 따라가요

(a) 첫 원소 score[0] = -8을 tmp에 넣어요. i = 1에서 score[1] = -3 > -8이므로 tmp = -3으로 갱신하고, i = 2에서는 score[2] = -10 < -3이므로 tmp = -3을 유지하며, i = 3에서 score[3] = -1 > -3이므로 tmp = -1로 갱신해 -1을 반환해요.

(b) tmp = 0으로 초기화하면 모든 원소가 음수일 때 어떤 원소도 0보다 크지 않아 배열에 없는 0을 잘못 반환해요. 함수가 유효한 알고리즘이 되려면 1 <= n <= MAX이고 앞 n개 원소가 초기화되어 있어야 하며, i가 1부터 매 반복 1씩 증가해 유한한 상한 n에 도달하므로 유한 번 만에 종료해요.

완성 답과 검산

(a) {-8, -3, -10, -1} 중 가장 큰 값은 -1이며, 단계별 tmp 값 -8 → -3 → -3 → -1의 마지막 값과 일치해요.

(b) tmp = 0일 때 -8, -3, -10, -1과 비교하면 조건문 score[i] > tmp가 한 번도 참이 되지 않아 0이 반환됨을 대입으로 확인할 수 있어요.

이 문제에서 조심할 점

최대값의 초기값을 무조건 0으로 놓으면 음수만 있는 입력에서 틀려요.

설명을 닫고 다시 해 봐요

  1. tmp = score[0] 초기값과 i = 1..3 비교 결과를 차례로 적어요.
  2. 음수 배열에서 tmp = 0이 왜 틀리는지 반례로 확인해요.
  3. 입력 범위 1 <= n <= MAX와 루프 종료 근거를 점검해요.

첫 줄

tmp = score[0] = -8, i = 1로 상태 추적을 시작해요.

떠올릴 개념·공식

배열 최대값 탐색은 첫 원소 score[0]을 초기 최대값 후보로 삼고 i = 1..n-1을 비교해요.

검산

(a) tmp: -8 → -3 → -3 → -1, 반환값 -1 (b) tmp = 0이면 음수 배열에서 0 오반환, 1 <= n <= MAX 및 i 증가로 유한 종료.

조건·구분과 확인

  • 후속 수업 보충(0914 분석): 0907 핵심 평가 범위에서는 제외해요.
  • 1 <= n <= MAX이고 앞 n개 원소가 초기화되어야 하며, i가 1씩 증가해 n에 도달하므로 종료해요.

### P1. 배열 크기를 sizeof로 비교

textbook-ch03-q03 · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0928_ArrayStructureList.html#p1)

다음 배열 중에서 크기가 가장 큰 배열은?

(1)

int array1[10];

(2)

double array2[10];

(3)

char array3[40];

(4)

float array4[10];

비교 기준: 이 팩의 C 검산 환경은 int 4, double 8, char 1, float 4바이트예요.

(4)

#### 문제를 내 말로 읽어요

네 배열의 전체 크기를 주어진 검산 환경의 바이트 수로 비교해요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

sizeof는 byte 단위의 객체 크기예요. array 크기는 원소 수×sizeof(타입)이에요. 여기의 int=4,double=8,char=1,float=4는 현재 환경 조건이에요.

#### 종이에 적을 첫 줄

array1=10×4=40바이트라고 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

array1=40, array2=80, array3=40, array4=40바이트예요. 최대는 (2) double array2[10]이에요.

#### 완성 답과 검산

C sizeof 출력에서 40,80,40,40을 독립 확인해요. 현재 타입 크기 전제가 바뀌면 비교도 다시 해야 하므로 모든 C 구현에 8바이트 double을 단정하지 않아요.

#### 이 문제에서 조심할 점

원소 개수만 비교하면 char[40]을 고르게 돼요.

#### 설명을 닫고 다시 해 봐요

1. array1=10×4=40바이트라고 적어요.
2. 개수×타입 크기 → double[10] 80
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

#### 첫 줄

array1=10×4=40바이트라고 적어요.

#### 떠올릴 개념·공식

개수×타입 크기 → double[10] 80

### P2. 복소수 구조체 더하기

textbook-ch03-q07 · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0928_ArrayStructureList.html#p2)

복소수를 구조체로 표현해보자. 복소수 a와 복소수 b를 받아서 a+b를 계산하는 함수를 작성해보자. 함수는 구조체를 반환할 수 있다. 알다시피 복소수는 real+imag\*i와 같은 형태를 갖는다.

`Complex complex_add(Complex a, Complex b) {
    ...
}`

3장 배열, 구조체, 포인터 · 07번 · 책 98쪽

복소수를 구조체로 표현해보자. 복소수 a와 복소수 b를 받아서 a+b를 계산하는 함수를 작성해보자. 함수는 구조체를 반환할 수 있다. 알다시피 복소수는 real+imag\*i와 같은 형태를 갖는다.

`Complex complex_add(Complex a, Complex b) {
    ...
}`

</details>

#### 문제를 내 말로 읽어요

두 복소수 a,b를 받고 합을 Complex 값으로 반환해요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

real+imag×i의 합은 같은 성분끼리 더하는 componentwise addition이에요. C 구조체는 값으로 전달·반환할 수 있어요. 여기서는 멤버 이름을 real,imag로 정의해요.

#### 종이에 적을 첫 줄

`Complex result;`

#### 왜 이렇게 푸는지 함께 따라가요

`typedef struct { float real, imag; } Complex;
Complex complex_add(Complex a, Complex b) {
    Complex result;
    result.real = a.real + b.real;
    result.imag = a.imag + b.imag;
    return result;
}`

#### 완성 답과 검산

a=(1,2),b=(3,4)이면 result=(4,6), 즉 4+6i예요. 실수부와 허수부를 별도로 확인해요. 함수는 복사본을 받으므로 result 계산이 호출자의 a,b를 변경하지 않아요. 부동소수점 일반 입력은 반올림될 수 있어요.

#### 이 문제에서 조심할 점

real과 imag를 섞어 더하거나 지역 result의 주소를 반환하지 않아요.

#### 설명을 닫고 다시 해 봐요

1. Complex result;
2. 같은 성분끼리 합, 구조체 값 반환
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

#### 첫 줄

Complex result;

#### 떠올릴 개념·공식

같은 성분끼리 합, 구조체 값 반환

### P3. 구조체를 동적으로 만들고 반납

textbook-ch03-q12 · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0928_ArrayStructureList.html#p3)

1개의 정수와 최대 크기가 20인 문자열로 이루어진 구조체를 저장할 수 있도록 동적 메모리를 할당받고 여기에 정수 100과 문자열 “just testing”을 저장한 다음, 동적 메모리를 반납하는 프로그램을 작성하라.

<details><summary>교과서 원문 보기</summary>

3장 배열, 구조체, 포인터 · 12번 · PDF 2쪽

1개의 정수와 최대 크기가 20인 문자열로 이루어진 구조체를 저장할 수 있도록 동적 메모리를 할당받고 여기에 정수 100과 문자열 “just testing”을 저장한 다음, 동적 메모리를 반납하는 프로그램을 작성하라.

</details>

#### 문제를 내 말로 읽어요

구조체 하나를 heap에 만들고 100과 문자열을 저장한 뒤 반납해요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

동적 할당 dynamic allocation은 malloc(sizeof \*p), 실패는 NULL, 멤버 접근은 p-&gt;field, 해제는 free(p)예요. 최대 20문자를 보관하려고 종료 널을 포함한 21칸을 선택해요.

#### 종이에 적을 첫 줄

`struct Item { int number; char text[21]; };`

#### 왜 이렇게 푸는지 함께 따라가요

`#include <stdio.h>
#include <stdlib.h>
#include <string.h>
struct Item { int number; char text[21]; };
int main(void) {
    struct Item *p = malloc(sizeof *p);
    if (p == NULL) return 1;
    p->number = 100;
    strcpy(p->text, "just testing");
    printf("%d %s\n", p->number, p->text);
    free(p);
    return 0;
}`

#### 완성 답과 검산

just testing은 12문자라 종료 널까지 13칸으로 21칸 안에 들어가요. C 출력은 100 just testing이고 성공한 malloc 1회와 free 1회가 짝이에요. 문자열 한계가 널 포함 20칸이라는 해석에서도 이 예시는 20칸에 들어가요.

#### 이 문제에서 조심할 점

sizeof p는 포인터 크기여서 구조체 크기가 아니에요. free 뒤 p-&gt;number를 읽지 않아요.

#### 설명을 닫고 다시 해 봐요

1. struct Item { int number; char text[21]; };
2. malloc(sizeof \*p) → NULL 검사 → 저장 → free
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

#### 첫 줄

struct Item { int number; char text[21]; };

#### 떠올릴 개념·공식

malloc(sizeof \*p) → NULL 검사 → 저장 → free

### P4. 배열 접근·전체 방문의 복잡도

textbook-ch01-q17 · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0928_ArrayStructureList.html#p4)

배열에 정수가 들어 있다고 가정하고 다음의 작업의 최악, 최선의 시간복잡도를 빅오 표기법으로 말하라.

(1)

배열의 n번째 숫자를 화면에 출력한다.

(2)

배열안의 숫자 중에서 최소값을 찾는다.

(3)

배열의 모든 숫자를 더한다.

<details><summary>교과서 원문 보기</summary>

1장 자료구조와 알고리즘 · 17번 · 책 37쪽

배열에 정수가 들어 있다고 가정하고 다음의 작업의 최악, 최선의 시간복잡도를 빅오 표기법으로 말하라.

(1)

배열의 n번째 숫자를 화면에 출력한다.

(2)

배열안의 숫자 중에서 최소값을 찾는다.

(3)

배열의 모든 숫자를 더한다.

</details>

#### 문제를 내 말로 읽어요

배열 인덱스 접근, 최솟값 찾기, 합의 최선·최악 시간 복잡도를 각각 구해요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

배열은 random access라 주소=시작주소+인덱스×원소크기로 바로 찾아요. 정렬 등 추가 정보가 없는 임의의 배열에서 최솟값과 합은 모든 값을 봐야 해요. n은 여기서 전체 원소 수예요.

#### 종이에 적을 첫 줄

세 행 표에 접근 / 최소 / 합을 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

(1) n번째 원소 출력: 최선·최악 O(1)이에요. 유효 인덱스 접근과 정수 출력의 비용을 상수로 세어요. (2) 최소: 첫 원소를 후보로 놓고 나머지 n−1개를 비교하므로 최선·최악 O(n)이에요. (3) 합: n개를 읽어 누적하므로 최선·최악 O(n)이에요.

#### 완성 답과 검산

아직 읽지 않은 한 값을 더 작게 바꾸면 최소가 바뀌고, 어떤 값도 바꾸면 합이 바뀔 수 있어요. 그러므로 임의 배열에서 생략한 원소가 있는 정확한 알고리즘은 불가능해요. 이미 정렬됨 같은 추가 가정은 원문에 없어요.

#### 이 문제에서 조심할 점

최소가 첫 칸에 있어도 그 사실을 확인하려면 나머지를 읽어야 해요.

#### 설명을 닫고 다시 해 봐요

1. 세 행 표에 접근 / 최소 / 합을 적어요.
2. 접근 O(1), 최소·합 O(n), 최선=최악
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

#### 첫 줄

세 행 표에 접근 / 최소 / 합을 적어요.

#### 떠올릴 개념·공식

접근 O(1), 최소·합 O(n), 최선=최악

### P5. swap: 주소 전달과 값 전달

lecture-s03-p22-swap · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0928_ArrayStructureList.html#p5)

**강의 예제 기반 자체 출제** S3 p22

int a=1,b=2;에서 위 함수를 부르는 문장을 쓰고 각 대입 뒤의 (a,b,tmp)를 추적하세요. 매개변수가 int x,int y이고 값만 서로 바꾸는 함수라면 호출자의 a,b가 바뀌는지도 설명하세요.

`void swap(int *px, int *py)
{
    int tmp;
    tmp = *px;
    *px = *py;
    *py = tmp;
}`

<details><summary>강의 예제 보기</summary>

S3 p22 · Software_3_ArrayStructureList.pdf. 강의 코드의 해당 연산을 발췌해 들여쓰기를 정리했습니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

`void swap(int *px, int *py)
{
    int tmp;
    tmp = *px;
    *px = *py;
    *py = tmp;
}`

</details>

#### 문제를 내 말로 읽어요

int a=1,b=2;에서 위 함수를 부르는 문장을 쓰고 각 대입 뒤의 (a,b,tmp)를 추적하세요. 매개변수가 int x,int y이고 값만 서로 바꾸는 함수라면 호출자의 a,b가 바뀌는지도 설명하세요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “swap: 주소 전달과 값 전달”예요. 주소 연산자 &로 a,b의 위치를 넘겨요. 함수는 주소의 복사본 px,py를 받지만 역참조로 원래 객체에 접근해요. b에 tmp를 대입하면 2,1이 돼요. 값 전달 함수는 별도 지역 변수만 바꾸므로 호출자에게 반영되지 않아요.

#### 종이에 적을 첫 줄

swap(&a,&b); 다음 tmp=\*px에서 tmp=1을 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

1. 주소 연산자 &로 a,b의 위치를 넘겨요. 함수는 주소의 복사본 px,py를 받지만 역참조로 원래 객체에 접근해요.
2. 먼저 a의 값 1을 tmp에 보관해요. a에 b의 값 2를 대입해도 1은 tmp에 남아요.
3. b에 tmp를 대입하면 2,1이 돼요. 값 전달 함수는 별도 지역 변수만 바꾸므로 호출자에게 반영되지 않아요.

swap(&a,&b);. tmp=\*px 뒤 (1,2,1), \*px=\*py 뒤 (2,2,1), \*py=tmp 뒤 (2,1,1). 값 매개변수 x,y만 바꾸면 호출자의 a,b는 1,2 그대로다.

#### 완성 답과 검산

swap(&a,&b);. tmp=\*px 뒤 (1,2,1), \*px=\*py 뒤 (2,2,1), \*py=tmp 뒤 (2,1,1). 값 매개변수 x,y만 바꾸면 호출자의 a,b는 1,2 그대로다.

시작 조건에서 다시 추적한 결과가 위 답과 일치해요. b에 tmp를 대입하면 2,1이 돼요. 값 전달 함수는 별도 지역 변수만 바꾸므로 호출자에게 반영되지 않아요.

#### 이 문제에서 조심할 점

px=py는 주소 변수만 바꿔요. \*px=\*py와 의미가 달라요.

#### 설명을 닫고 다시 해 봐요

1. 주어진 시작 상태와 필요한 입력 조건을 적어요.
2. 첫 줄부터 연산 순서를 따라 답을 완성해요.
3. 경계 경우와 오류 경로를 확인해요.

**페이지 요약**

#### 첫 줄

swap(&a,&b); 다음 tmp=\*px에서 tmp=1을 적어요.

#### 떠올릴 개념·공식

주소 연산자 &로 a,b의 위치를 넘겨요. 함수는 주소의 복사본 px,py를 받지만 역참조로 원래 객체에 접근해요.

#### 검산

swap(&a,&b);. tmp=\*px 뒤 (1,2,1), \*px=\*py 뒤 (2,2,1), \*py=tmp 뒤 (2,1,1). 값 매개변수 x,y만 바꾸면 호출자의 a,b는 1,2 그대로다.

### P7. 역참조·후위 증가·이중 포인터 추적

아래는 배열 포인터와 이중 포인터를 다루는 코드예요. 각 문장 뒤 p가 가리키는 원소와 배열 값을 추적하고 x,y의 최종값을 쓰세요. \*p++와 (\*p)++가 바꾸는 대상이 어떻게 다른지, pp와 \*pp와 **pp가 각각 무엇인지 설명하세요. int 크기가4바이트일 때 p=a+1과 a의 바이트 간격도 쓰세요.

#### 문제를 내 말로 읽어요

아래는 배열 포인터와 이중 포인터를 다루는 코드예요. 각 문장 뒤 p가 가리키는 원소와 배열 값을 추적하고 x,y의 최종값을 쓰세요. \*p++와 (\*p)++가 바꾸는 대상이 어떻게 다른지, pp와 \*pp와 **pp가 각각 무엇인지 설명하세요. int 크기가4바이트일 때 p=a+1과 a의 바이트 간격도 쓰세요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

‘\*와 ++’는 연산 우선순위와 후위 증가(post-increment)의 단서예요. \*p++는 포인터를 이동하고 (\*p)++는 가리키는 값을 증가시켜요. ‘포인터의 주소’는 이중 포인터(double pointer)를 뜻하며 역참조 한 번마다 주소 연결을 한 단계 따라가요.

#### 종이에 쓰는 첫 줄

초기: p→a[0], pp→p, 배열[10,20,30]이라고 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

p=a는 첫 원소 주소이고 pp=&p는 포인터 변수 p의 주소예요.

\*p++는 \*(p++)이므로 첫 값10을 읽고 p만 다음 원소로 이동해요.

(\*p)++는 p가 가리키는20을 먼저 y에 넘기고 그 원소를21로 바꿔요. p는 이동하지 않아요.

\*pp는 현재 p이므로 **pp=40은 a[1]에40을 저장해요.

x=10,y=20이에요. x 대입 뒤 p는 a[1], 배열 [10,20,30]; y 대입 뒤 p는 계속 a[1], 배열 [10,21,30]; **pp=40 뒤 배열 [10,40,30]이에요. pp는 p의 주소, \*pp는 p의 값(현재 a[1]의 주소), **pp는 그 원소예요. 간격은4바이트예요.

#### 완성 답과 검산

x=10,y=20이에요. x 대입 뒤 p는 a[1], 배열 [10,20,30]; y 대입 뒤 p는 계속 a[1], 배열 [10,21,30]; **pp=40 뒤 배열 [10,40,30]이에요. pp는 p의 주소, \*pp는 p의 값(현재 a[1]의 주소), **pp는 그 원소예요. 간격은4바이트예요.

마지막에 \*pp=p=a+1이므로 **pp와 a[1]은 같은 객체예요. 두 이름 모두40을 나타내야 해요. p를 증가시킨 문장은 x 대입 한 번뿐이므로 최종 위치가 a[1]이라는 점도 따로 확인해요.

#### 이 문제에서 조심할 점

pp를 배열 원소의 주소와 혼동하지 않아요. 후위 증가가 어느 괄호 안 객체에 적용되는지 먼저 확인해요.

### P8. 포인터 초기화·void 포인터와 할당 방식

#### 문제를 내 말로 읽어요

char \*pc; \*pc='E';가 지역 코드에 있으면 왜 정상 출력값을 구하면 안 되나요? pc=NULL;만 추가하면 역참조가 안전해지나요? char c를 실제 저장 대상으로 써서 고치세요. void \*v=&c;에서 char \*q로 되돌려 쓰는 식도 쓰세요. 이어 고정 크기 buffer[100]과 실행 중 필요한 크기를 malloc으로 받는 방식을 비교하고, 할당 실패와 반납 시 확인할 일을 설명하세요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

‘초기화되지 않은 포인터’는 대상 객체와 유효성 확인의 단서예요. NULL은 대상 없음이고 void \*는 대상 타입 정보를 지정하지 않은 포인터 타입이에요. 둘은 다른 개념이에요. 동적 할당(dynamic allocation)은 실행 중 저장소를 요청하는 방식이며 성공 여부와 수명을 직접 관리해요.

#### 종이에 쓰는 첫 줄

pc가 어느 실제 char 객체를 가리키는지부터 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

선언한 포인터 변수만으로 저장 대상 char 객체가 생기지 않아요.

NULL은 미연결 상태를 표현하며 쓰기 가능한 메모리를 만들지 않아요.

실제 char c의 주소를 pc에 넣은 다음 쓰면 유효한 객체를 수정해요.

void \*는 특정 대상 타입을 지정하지 않은 주소 저장이고, 원래 대상이 char임을 아는 경우 char \*로 돌려 접근해요.

고정 용량과 실행 중 결정하는 크기를 비교하고, 동적 자원은 실패 검사와 반납 책임까지 정해요.

초기화되지 않은 pc를 역참조하면 미정의 동작이에요. NULL도 가리킬 객체가 없으므로 역참조할 수 없어요. char c; char \*pc=&c; \*pc='E';로 유효한 저장소를 연결할 수 있어요. char \*q=(char \*)v;로 원래 char 객체에 접근해요. 고정 배열은 정해진 용량의 부족·낭비 가능성이 있고 동적 할당은 실행 중 크기를 정해요. malloc 결과가 NULL인지 확인하고 사용 뒤 최초 할당 주소를 한 번 free하며 이후 접근하지 않아요.

#### 완성 답과 검산

초기화되지 않은 pc를 역참조하면 미정의 동작이에요. NULL도 가리킬 객체가 없으므로 역참조할 수 없어요. char c; char \*pc=&c; \*pc='E';로 유효한 저장소를 연결할 수 있어요. char \*q=(char \*)v;로 원래 char 객체에 접근해요. 고정 배열은 정해진 용량의 부족·낭비 가능성이 있고 동적 할당은 실행 중 크기를 정해요. malloc 결과가 NULL인지 확인하고 사용 뒤 최초 할당 주소를 한 번 free하며 이후 접근하지 않아요.

수정한 코드에서는 pc=&c, q=(char \*)v이고 v=&c이므로 두 포인터 모두 c에 연결돼요. c를 쓰면 그 객체만 바뀌어요. 할당 실패이면 저장 단계에 도달하지 않아야 하고 반납 뒤에는 객체 수명이 끝나므로 읽지 않는지 제어 흐름을 확인해요.

#### 이 문제에서 조심할 점

void \* 선언을 NULL 초기화와 같은 뜻으로 읽지 않아요. 캐스트만으로 잘못된 주소가 유효해지는 것도 아니에요.

**페이지 요약**

#### 떠올릴 개념·공식

‘초기화되지 않은 포인터’는 대상 객체와 유효성 확인의 단서예요. NULL은 대상 없음이고 void \*는 대상 타입 정보를 지정하지 않은 포인터 타입이에요. 둘은 다른 개념이에요. 동적 할당(dynamic allocation)은 실행 중 저장소를 요청하는 방식이며 성공 여부와 수명을 직접 관리해요.

#### 첫 줄

pc가 어느 실제 char 객체를 가리키는지부터 적어요.

#### 핵심 답

초기화되지 않은 pc를 역참조하면 미정의 동작이에요. NULL도 가리킬 객체가 없으므로 역참조할 수 없어요. char c; char \*pc=&c; \*pc='E';로 유효한 저장소를 연결할 수 있어요. char \*q=(char \*)v;로 원래 char 객체에 접근해요. 고정 배열은 정해진 용량의 부족·낭비 가능성이 있고 동적 할당은 실행 중 크기를 정해요. malloc 결과가 NULL인지 확인하고 사용 뒤 최초 할당 주소를 한 번 free하며 이후 접근하지 않아요.

### P9. sizeof·패딩과 배열 원소 수

lecture-s03-p30-sizeof-alignment-count · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0928_ArrayStructureList.html#p9)

**강의 예제 기반 자체 출제** S3 p30

구조체 struct AlignDepends { char c; int i; };를 봐요. 이 문제의 환경은 sizeof(char)=1, sizeof(int)=4, int 정렬4바이트이고 c 오프셋0, i 오프셋4, 구조체 크기8바이트예요. 왜 크기가1+4=5가 아닌지 설명하세요. int array[]={1,2,3,4,5};의 sizeof(array), sizeof(array[0]), 두 값의 비와 단위도 쓰세요. 이 값을 다른 C 환경에서도 무조건4·8이라고 할 수 있나요?

#### 문제를 내 말로 읽어요

구조체 struct AlignDepends { char c; int i; };를 봐요. 이 문제의 환경은 sizeof(char)=1, sizeof(int)=4, int 정렬4바이트이고 c 오프셋0, i 오프셋4, 구조체 크기8바이트예요. 왜 크기가1+4=5가 아닌지 설명하세요. int array[]={1,2,3,4,5};의 sizeof(array), sizeof(array[0]), 두 값의 비와 단위도 쓰세요. 이 값을 다른 C 환경에서도 무조건4·8이라고 할 수 있나요?

#### 이 문제를 봤을 때 떠올릴 개념과 공식

‘정렬’은 멤버 크기를 단순 합하지 말라는 단서예요. 패딩(padding)은 정렬 조건을 맞추는 빈 바이트도 객체 크기에 포함하는 규칙이에요. sizeof는 바이트 단위 크기이고, 실제 배열 객체 전체 크기를 원소 크기로 나누면 원소 수가 돼요.

#### 종이에 쓰는 첫 줄

c:0, 패딩:1~3, i:4~7이라고 배치를 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

문제에서 정한 배치 조건에 따라 c1바이트 뒤에 패딩3바이트를 넣어요.

i가 오프셋4~7을 사용하므로 객체 범위는0~7, 총8바이트예요.

원소5개×4바이트=20바이트이고 같은 단위끼리 나누면 원소 수5가 돼요.

고정 수치는 이 문제 환경의 조건이에요. C에서 sizeof(char)=1은 보장되지만 int4와 구조체8은 일반 보장이 아니에요.

c 다음 오프셋1~3에3바이트 패딩이 있어 i가4의 배수 오프셋에서 시작해요. 따라서 전체8바이트예요. array 전체20바이트, 원소 하나4바이트, 비20/4=5개예요. int 및 구조체 크기는 환경에 따라 달라 고정할 수 없고 sizeof(char)는 C에서 항상1이에요.

#### 완성 답과 검산

c 다음 오프셋1~3에3바이트 패딩이 있어 i가4의 배수 오프셋에서 시작해요. 따라서 전체8바이트예요. array 전체20바이트, 원소 하나4바이트, 비20/4=5개예요. int 및 구조체 크기는 환경에 따라 달라 고정할 수 없고 sizeof(char)는 C에서 항상1이에요.

0~7의8칸 중 c1칸+i4칸+패딩3칸=8칸으로 따로 세어요. 배열 원소 수는 초기화 값1,2,3,4,5를 직접 세어도5개여서 sizeof 비와 일치해요.

#### 이 문제에서 조심할 점

패딩으로 비워 둔 바이트는 malloc 후 free하지 않은 메모리 누수와 달라요. 배열이 포인터로 전달된 매개변수에서는 이 sizeof 비로 배열 길이를 구할 수 없어요.

문제를 내 말로 읽어요

강의의 struct AlignDepends { char c; int i; };를 봐요. 이 문제의 환경은 sizeof(char)=1, sizeof(int)=4, int 정렬4바이트이고 c 오프셋0, i 오프셋4, 구조체 크기8바이트예요. 왜 크기가1+4=5가 아닌지 설명하세요. int array[]={1,2,3,4,5};의 sizeof(array), sizeof(array[0]), 두 값의 비와 단위도 쓰세요. 이 값을 다른 C 환경에서도 무조건4·8이라고 할 수 있나요?

이 문제를 봤을 때 떠올릴 개념과 공식

‘정렬’은 멤버 크기를 단순 합하지 말라는 단서예요. 패딩(padding)은 정렬 조건을 맞추는 빈 바이트도 객체 크기에 포함하는 규칙이에요. sizeof는 바이트 단위 크기이고, 실제 배열 객체 전체 크기를 원소 크기로 나누면 원소 수가 돼요.

종이에 쓰는 첫 줄

c:0, 패딩:1~3, i:4~7이라고 배치를 적어요.

왜 이렇게 푸는지 함께 따라가요

문제에서 정한 배치 조건에 따라 c1바이트 뒤에 패딩3바이트를 넣어요.

i가 오프셋4~7을 사용하므로 객체 범위는0~7, 총8바이트예요.

원소5개×4바이트=20바이트이고 같은 단위끼리 나누면 원소 수5가 돼요.

고정 수치는 이 문제 환경의 조건이에요. C에서 sizeof(char)=1은 보장되지만 int4와 구조체8은 일반 보장이 아니에요.

c 다음 오프셋1~3에3바이트 패딩이 있어 i가4의 배수 오프셋에서 시작해요. 따라서 전체8바이트예요. array 전체20바이트, 원소 하나4바이트, 비20/4=5개예요. int 및 구조체 크기는 환경에 따라 달라 고정할 수 없고 sizeof(char)는 C에서 항상1이에요.

완성 답과 검산

c 다음 오프셋1~3에3바이트 패딩이 있어 i가4의 배수 오프셋에서 시작해요. 따라서 전체8바이트예요. array 전체20바이트, 원소 하나4바이트, 비20/4=5개예요. int 및 구조체 크기는 환경에 따라 달라 고정할 수 없고 sizeof(char)는 C에서 항상1이에요.

0~7의8칸 중 c1칸+i4칸+패딩3칸=8칸으로 따로 세어요. 배열 원소 수는 초기화 값1,2,3,4,5를 직접 세어도5개여서 sizeof 비와 일치해요.

이 문제에서 조심할 점

패딩으로 비워 둔 바이트는 malloc 후 free하지 않은 메모리 누수와 달라요. 배열이 포인터로 전달된 매개변수에서는 이 sizeof 비로 배열 길이를 구할 수 없어요.

설명을 닫고 다시 해 봐요

  1. 주어진 조건과 첫 상태를 적어요.
  2. 핵심 규칙을 떠올려 답을 다시 완성해요.
  3. 경계 조건과 보존되는 상태를 확인해요.

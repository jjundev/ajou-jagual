문제를 내 말로 읽어요

char *pc; *pc='E';가 지역 코드에 있으면 왜 정상 출력값을 구하면 안 되나요? pc=NULL;만 추가하면 역참조가 안전해지나요? char c를 실제 저장 대상으로 써서 고치세요. void *v=&c;에서 char *q로 되돌려 쓰는 식도 쓰세요. 이어 고정 크기 buffer[100]과 실행 중 필요한 크기를 malloc으로 받는 방식을 비교하고, 할당 실패와 반납 시 확인할 일을 설명하세요.

이 문제를 봤을 때 떠올릴 개념과 공식

‘초기화되지 않은 포인터’는 대상 객체와 유효성 확인의 단서예요. NULL은 대상 없음이고 void *는 대상 타입 정보를 지정하지 않은 포인터 타입이에요. 둘은 다른 개념이에요. 동적 할당(dynamic allocation)은 실행 중 저장소를 요청하는 방식이며 성공 여부와 수명을 직접 관리해요.

종이에 쓰는 첫 줄

pc가 어느 실제 char 객체를 가리키는지부터 적어요.

왜 이렇게 푸는지 함께 따라가요

선언한 포인터 변수만으로 저장 대상 char 객체가 생기지 않아요.

NULL은 미연결 상태를 표현하며 쓰기 가능한 메모리를 만들지 않아요.

실제 char c의 주소를 pc에 넣은 다음 쓰면 유효한 객체를 수정해요.

void *는 특정 대상 타입을 지정하지 않은 주소 저장이고, 원래 대상이 char임을 아는 경우 char *로 돌려 접근해요.

고정 용량과 실행 중 결정하는 크기를 비교하고, 동적 자원은 실패 검사와 반납 책임까지 정해요.

초기화되지 않은 pc를 역참조하면 미정의 동작이에요. NULL도 가리킬 객체가 없으므로 역참조할 수 없어요. char c; char *pc=&c; *pc='E';로 유효한 저장소를 연결할 수 있어요. char *q=(char *)v;로 원래 char 객체에 접근해요. 고정 배열은 정해진 용량의 부족·낭비 가능성이 있고 동적 할당은 실행 중 크기를 정해요. malloc 결과가 NULL인지 확인하고 사용 뒤 최초 할당 주소를 한 번 free하며 이후 접근하지 않아요.

수정한 코드에서는 pc=&c, q=(char *)v이고 v=&c이므로 두 포인터 모두 c에 연결돼요. c를 쓰면 그 객체만 바뀌어요. 할당 실패이면 저장 단계에 도달하지 않아야 하고 반납 뒤에는 객체 수명이 끝나므로 읽지 않는지 제어 흐름을 확인해요.

이 문제에서 조심할 점

void * 선언을 NULL 초기화와 같은 뜻으로 읽지 않아요. 캐스트만으로 잘못된 주소가 유효해지는 것도 아니에요.

문제를 내 말로 읽어요

네 배열의 전체 크기를 주어진 검산 환경의 바이트 수로 비교해요.

이 문제를 봤을 때 떠올릴 개념과 공식

sizeof는 byte 단위의 객체 크기예요. array 크기는 원소 수×sizeof(타입)이에요. 여기의 int=4,double=8,char=1,float=4는 현재 환경 조건이에요.

종이에 적을 첫 줄

array1=10×4=40바이트라고 적어요.

왜 이렇게 푸는지 함께 따라가요

array1=40, array2=80, array3=40, array4=40바이트예요. 최대는 (2) double array2[10]이에요.

완성 답과 검산

C sizeof 출력에서 40,80,40,40을 독립 확인해요. 현재 타입 크기 전제가 바뀌면 비교도 다시 해야 하므로 모든 C 구현에 8바이트 double을 단정하지 않아요.

이 문제에서 조심할 점

원소 개수만 비교하면 char[40]을 고르게 돼요.

설명을 닫고 다시 해 봐요

  1. array1=10×4=40바이트라고 적어요.
  2. 개수×타입 크기 → double[10] 80
  3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

첫 줄

array1=10×4=40바이트라고 적어요.

떠올릴 개념·공식

개수×타입 크기 → double[10] 80

검산

본문의 조건과 독립 추적을 함께 확인해요.

조건·구분과 확인

복소수를 구조체로 표현해보자. 복소수 a와 복소수 b를 받아서 a+b를 계산하는 함수를 작성해보자. 함수는 구조체를 반환할 수 있다. 알다시피 복소수는 real+imag*i와 같은 형태를 갖는다.

Complex complex_add(Complex a, Complex b) {
    ...
}

문제를 내 말로 읽어요

두 복소수 a,b를 받고 합을 Complex 값으로 반환해요.

이 문제를 봤을 때 떠올릴 개념과 공식

real+imag×i의 합은 같은 성분끼리 더하는 componentwise addition이에요. C 구조체는 값으로 전달·반환할 수 있어요. 여기서는 멤버 이름을 real,imag로 정의해요.

종이에 적을 첫 줄

Complex result;

왜 이렇게 푸는지 함께 따라가요

typedef struct { float real, imag; } Complex;
Complex complex_add(Complex a, Complex b) {
    Complex result;
    result.real = a.real + b.real;
    result.imag = a.imag + b.imag;
    return result;
}

완성 답과 검산

a=(1,2),b=(3,4)이면 result=(4,6), 즉 4+6i예요. 실수부와 허수부를 별도로 확인해요. 함수는 복사본을 받으므로 result 계산이 호출자의 a,b를 변경하지 않아요. 부동소수점 일반 입력은 반올림될 수 있어요.

이 문제에서 조심할 점

real과 imag를 섞어 더하거나 지역 result의 주소를 반환하지 않아요.

설명을 닫고 다시 해 봐요

  1. Complex result;
  2. 같은 성분끼리 합, 구조체 값 반환
  3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

첫 줄

Complex result;

떠올릴 개념·공식

같은 성분끼리 합, 구조체 값 반환

검산

본문의 조건과 독립 추적을 함께 확인해요.

조건·구분과 확인

  • result.real=a.real+b.real, result.imag=a.imag+b.imag를 값으로 반환해 (1,2)+(3,4)=(4,6)이 돼요. 복사본이므로 호출자 a,b는 그대로이고 지역 result의 주소를 반환하지 않아요.

1개의 정수와 최대 크기가 20인 문자열로 이루어진 구조체를 저장할 수 있도록 동적 메모리를 할당받고 여기에 정수 100과 문자열 “just testing”을 저장한 다음, 동적 메모리를 반납하는 프로그램을 작성하라.

문제를 내 말로 읽어요

구조체 하나를 heap에 만들고 100과 문자열을 저장한 뒤 반납해요.

이 문제를 봤을 때 떠올릴 개념과 공식

동적 할당 dynamic allocation은 malloc(sizeof *p), 실패는 NULL, 멤버 접근은 p->field, 해제는 free(p)예요. 최대 20문자를 보관하려고 종료 널을 포함한 21칸을 선택해요.

종이에 적을 첫 줄

struct Item { int number; char text[21]; };

왜 이렇게 푸는지 함께 따라가요

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
struct Item { int number; char text[21]; };
int main(void) {
    struct Item *p = malloc(sizeof *p);
    if (p == NULL) return 1;
    p->number = 100;
    strcpy(p->text, "just testing");
    printf("%d %s\n", p->number, p->text);
    free(p);
    return 0;
}

완성 답과 검산

just testing은 12문자라 종료 널까지 13칸으로 21칸 안에 들어가요. C 출력은 100 just testing이고 성공한 malloc 1회와 free 1회가 짝이에요. 문자열 한계가 널 포함 20칸이라는 해석에서도 이 예시는 20칸에 들어가요.

이 문제에서 조심할 점

sizeof p는 포인터 크기여서 구조체 크기가 아니에요. free 뒤 p->number를 읽지 않아요.

설명을 닫고 다시 해 봐요

  1. struct Item { int number; char text[21]; };
  2. malloc(sizeof *p) → NULL 검사 → 저장 → free
  3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

첫 줄

struct Item { int number; char text[21]; };

떠올릴 개념·공식

malloc(sizeof *p) → NULL 검사 → 저장 → free

검산

본문의 조건과 독립 추적을 함께 확인해요.

조건·구분과 확인

  • number=100·text="just testing"을 저장해요. 20문자와 종료 널을 위해 21칸을 고르고, sizeof p가 아닌 sizeof *p를 할당하며 free 뒤 접근하지 않아요.

P4. 배열 접근·전체 방문의 복잡도

배열에 정수가 들어 있다고 가정하고 다음의 작업의 최악, 최선의 시간복잡도를 빅오 표기법으로 말하라.

(1)

배열의 n번째 숫자를 화면에 출력한다.

(2)

배열안의 숫자 중에서 최소값을 찾는다.

(3)

배열의 모든 숫자를 더한다.

1장 자료구조와 알고리즘 · 17번 · 책 37쪽

배열에 정수가 들어 있다고 가정하고 다음의 작업의 최악, 최선의 시간복잡도를 빅오 표기법으로 말하라.

(1)

배열의 n번째 숫자를 화면에 출력한다.

(2)

배열안의 숫자 중에서 최소값을 찾는다.

(3)

배열의 모든 숫자를 더한다.

문제를 내 말로 읽어요

배열 인덱스 접근, 최솟값 찾기, 합의 최선·최악 시간 복잡도를 각각 구해요.

이 문제를 봤을 때 떠올릴 개념과 공식

배열은 random access라 주소=시작주소+인덱스×원소크기로 바로 찾아요. 정렬 등 추가 정보가 없는 임의의 배열에서 최솟값과 합은 모든 값을 봐야 해요. n은 여기서 전체 원소 수예요.

종이에 적을 첫 줄

세 행 표에 접근 / 최소 / 합을 적어요.

왜 이렇게 푸는지 함께 따라가요

(1) n번째 원소 출력: 최선·최악 O(1)이에요. 유효 인덱스 접근과 정수 출력의 비용을 상수로 세어요. (2) 최소: 첫 원소를 후보로 놓고 나머지 n−1개를 비교하므로 최선·최악 O(n)이에요. (3) 합: n개를 읽어 누적하므로 최선·최악 O(n)이에요.

완성 답과 검산

아직 읽지 않은 한 값을 더 작게 바꾸면 최소가 바뀌고, 어떤 값도 바꾸면 합이 바뀔 수 있어요. 그러므로 임의 배열에서 생략한 원소가 있는 정확한 알고리즘은 불가능해요. 이미 정렬됨 같은 추가 가정은 원문에 없어요.

이 문제에서 조심할 점

최소가 첫 칸에 있어도 그 사실을 확인하려면 나머지를 읽어야 해요.

설명을 닫고 다시 해 봐요

  1. 세 행 표에 접근 / 최소 / 합을 적어요.
  2. 접근 O(1), 최소·합 O(n), 최선=최악
  3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

첫 줄

세 행 표에 접근 / 최소 / 합을 적어요.

떠올릴 개념·공식

접근 O(1), 최소·합 O(n), 최선=최악

검산

본문의 조건과 독립 추적을 함께 확인해요.

조건·구분과 확인

  • 유효 인덱스 접근·정수 출력을 상수로 세고 정렬 정보가 없는 임의 배열을 가정해요. 읽지 않은 값이 최소나 합을 바꿀 수 있어 두 연산은 전부 방문해야 해요.

P5. swap: 주소 전달과 값 전달

lecture-s03-p22-swap · 원 문제 보기

강의 예제 기반 자체 출제 S3 p22

호출자(main)에 int a = 1, b = 2;가 선언되어 있고, 아래 포인터 매개변수 함수 swap으로 두 변수의 값을 교환하려고 해요.

void swap(int *px, int *py)
{
    int tmp;
    tmp = *px;
    *px = *py;
    *py = tmp;
}

구할 것

  1. (a) a와 b의 값을 바꾸기 위해 swap을 호출하는 문장을 쓰고, 함수 안의 세 대입문(tmp = *px;, *px = *py;, *py = tmp;) 실행 직후마다 (a, b, tmp)의 값을 순서대로 추적하세요.
  2. (b) 매개변수가 포인터가 아닌 void swap_val(int x, int y)처럼 값에 의한 호출(call by value)로 작성해 x와 y를 교환하면 호출자의 a, b가 바뀌는지를 이유와 함께 설명하세요.
강의 예제 보기

S3 p22 · Software_3_ArrayStructureList.pdf. 강의 코드의 해당 연산을 발췌해 들여쓰기를 정리했습니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

void swap(int *px, int *py)
{
    int tmp;
    tmp = *px;
    *px = *py;
    *py = tmp;
}

문제를 내 말로 읽어요

int a = 1, b = 2;의 주소를 넘기는 swap 함수에서 역참조 대입마다 (a, b, tmp)가 어떻게 바뀌는지 추적하고, 값 전달 함수와 왜 결과가 다른지 비교하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “swap: 주소 전달과 값 전달”이에요. 주소 연산자 &로 a, b의 주소를 넘기면 포인터 매개변수 px, py는 역참조 *px, *py를 통해 호출자의 원본 변수를 직접 수정해요. 반면 값 전달은 복사된 지역 변수만 바꿔요.

종이에 적을 첫 줄

swap(&a, &b); 호출 뒤 첫 대입 tmp = *px;에서 tmp = 1을 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) swap(&a, &b);로 호출하면 px = &a, py = &b가 돼요. 첫째 줄 tmp = *px;로 a의 값 1을 tmp에 보관해 (1, 2, 1)이 되고, 둘째 줄 *px = *py;로 a에 2를 대입해 (2, 2, 1)이 되며, 셋째 줄 *py = tmp;로 b에 1을 대입해 (2, 1, 1)이 돼요.

(b) void swap_val(int x, int y)처럼 값 매개변수로 받으면 함수 안의 별도 지역 변수 x, y만 서로 바뀌고 끝나므로 호출자 main의 a, b는 1, 2 그대로 남아요.

완성 답과 검산

(a) 세 단계 후 최종 (a, b) = (2, 1)이 되어 처음 값 (1, 2)가 손실 없이 교환되었음을 확인할 수 있어요.

(b) C 함수 인자 전달은 기본적으로 값 복사(call by value)이므로, 포인터 역참조 없이는 피호출 함수가 호출자 변수의 메모리 공간에 접근할 수 없어요.

이 문제에서 조심할 점

px = py는 주소 변수만 바꿔요. *px = *py와 의미가 달라요.

설명을 닫고 다시 해 봐요

  1. swap(&a, &b); 호출문과 세 대입 직후의 (a, b, tmp) 순서쌍을 적어요.
  2. 값 전달 함수가 왜 호출자의 a, b를 바꾸지 못하는지 설명해요.

첫 줄

swap(&a, &b); 다음 tmp = *px에서 tmp = 1을 적어요.

떠올릴 개념·공식

주소 연산자 &로 위치를 넘기면 *px, *py 역참조로 호출자의 원본 객체에 접근해요.

검산

(a) swap(&a,&b);, (1,2,1) → (2,2,1) → (2,1,1) (b) 값 전달은 지역 변수 x,y만 바꾸므로 a,b는 1,2 그대로다.

조건·구분과 확인

  • C는 포인터 주소도 값으로 복사하지만 역참조로 원본에 접근해요. px=py는 주소 변수만 바꾸므로 *px=*py와 달라요.

P6. 동적 구조체 배열의 두 원소

lecture-s03-p31-malloc-record · 원 문제 보기

강의 예제 기반 자체 출제 S3 p31

아래 코드는 struct Example 원소 2개 분량의 메모리를 동적으로 할당받아 값을 저장한 뒤 해제해요(할당은 성공했다고 가정해요).

struct Example { int number; char name[10]; };
struct Example *p;
p = (struct Example *)malloc(2*sizeof(struct Example));
if(p==NULL) { fprintf(stderr,"can't allocate memory\n"); exit(1); }
p->number=1;
strcpy(p->name,"Park");
(p+1)->number=2;
strcpy((p+1)->name,"Kim");
free(p);

구할 것

  1. (a) free(p); 직전 시점에 두 원소 p[0], p[1]에 저장된 필드 값을 쓰고, 포인터 연산 p + 1이 p로부터 몇 바이트 뒤 주소를 가리키는지 sizeof로 표현하세요.
  2. (b) 이 코드에 쓰인 함수들을 위해 필요한 표준 헤더 3개와 free에 넘겨야 할 주소를 쓰고, free(p); 이후 p->number를 읽으면 왜 안 되는지 설명하세요.
강의 예제 보기

S3 p31 · Software_3_ArrayStructureList.pdf. 강의 코드의 해당 연산을 발췌해 들여쓰기를 정리했습니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

struct Example { int number; char name[10]; };
struct Example *p;
p = (struct Example *)malloc(2*sizeof(struct Example));
if(p==NULL) { fprintf(stderr,"can't allocate memory\n"); exit(1); }
p->number=1;
strcpy(p->name,"Park");
(p+1)->number=2;
strcpy((p+1)->name,"Kim");
free(p);

문제를 내 말로 읽어요

malloc으로 구조체 2개 분량의 동적 배열을 할당해 p와 p + 1로 필드를 채웠을 때 각 원소의 값·포인터 바이트 간격·필요 헤더·free 규칙을 확인하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “동적 구조체 배열의 두 원소”예요. 포인터 덧셈 p + 1은 1바이트가 아니라 가리키는 원소 크기인 sizeof(struct Example)바이트만큼 이동하며, free(p)에는 최초 할당 주소를 넘기고 해제된 메모리는 다시 역참조하면 안 돼요.

종이에 적을 첫 줄

할당 크기 = 2 * sizeof(struct Example)와 p[0], p[1] 두 칸을 그려요.

왜 이렇게 푸는지 함께 따라가요

(a) p->는 첫 원소 p[0], (p+1)->는 두 번째 원소 p[1]을 가리키므로 p[0] = {1, "Park"}, p[1] = {2, "Kim"}이 저장돼요. 포인터 덧셈은 원소 크기 단위이므로 p + 1은 p보다 sizeof(struct Example)바이트 뒤 주소예요.

(b) malloc·free·exit는 stdlib.h, fprintf·stderr는 stdio.h, strcpy는 string.h가 선언해요. 해제할 때는 최초 할당 주소인 p를 free(p)에 넘겨야 하고, 해제 뒤에는 저장 공간의 수명이 끝났으므로 p->number를 역참조하면 미정의 동작이 돼요.

완성 답과 검산

(a) C에서 (p + 1)->number는 p[1].number와 완전히 같은 식이고, 두 원소 사이의 주소 차이는 원소 1개의 바이트 크기인 sizeof(struct Example)과 일치해요.

(b) free 뒤에도 포인터 변수 p가 자동으로 NULL이 되지는 않으므로(dangling pointer), 해제 뒤 p->number 접근이 위험하다는 점이 메모리 수명 규칙과 일치해요.

이 문제에서 조심할 점

free(p + 1)은 최초 할당 주소가 아니므로 사용할 수 없어요. 패딩 때문에 구조체 크기를 14바이트로 단정하지 마세요.

설명을 닫고 다시 해 봐요

  1. p[0]과 p[1]에 들어간 {number, name} 값과 p + 1의 이동 바이트를 적어요.
  2. malloc, fprintf, strcpy에 필요한 세 표준 헤더 이름을 적어요.
  3. free(p) 인자 규칙과 해제 후 역참조 금지 이유를 점검해요.

첫 줄

할당 크기 = 2 * sizeof(struct Example)와 p[0], p[1] 두 칸을 그려요.

떠올릴 개념·공식

p + 1은 sizeof(struct Example)바이트 뒤를 가리키고, 해제 뒤 메모리는 역참조할 수 없어요.

검산

(a) p[0]={1,"Park"}, p[1]={2,"Kim"}, sizeof(struct Example)바이트 뒤 (b) stdlib.h, stdio.h, string.h, free(p) 후 역참조 금지.

조건·구분과 확인

  • free에는 최초 할당 주소 p만 넘기고 p+1을 넘기지 않아요. 패딩 때문에 크기를 14로 단정하지 않고 free 뒤 p가 자동 NULL이 된다고 생각하지 않아요.

P7. 역참조·후위 증가·이중 포인터 추적

lecture-s03-p20-pointer-expression-double · 원 문제 보기

강의 예제 기반 자체 출제 S3 p20

아래 코드는 sizeof(int) == 4인 환경에서 포인터 p와 이중 포인터 pp로 배열 a를 조작해요.

int a[] = {10, 20, 30};
int *p = a;
int **pp = &p;
int x = *p++;
int y = (*p)++;
**pp = 40;

구할 것

  1. (a) int x = *p++;, int y = (*p)++;, **pp = 40; 각 문장 실행 직후 p가 가리키는 원소와 배열 a의 상태 및 최종 x, y 값을 쓰고, *p++와 (*p)++가 바꾸는 대상이 어떻게 다른지 설명하세요.
  2. (b) pp, *pp, **pp가 각각 무엇을 나타내는지 구별하고, p = a + 1일 때 a와 p의 바이트 간격을 쓰세요.
강의 예제 보기

S3 p20 · 추가 근거 p19,23,25,26 · Software_3_ArrayStructureList.pdf. 강의의 개념·그림·코드 연산을 바탕으로 조건과 질문을 새로 작성한 자체 출제예요. 제시 코드는 있는 경우 학습 확인용 자체 코드이며 강의 원문 발췌가 아니에요. 질문·입력 조건·검산은 자체 작성했어요.

int a[] = {10,20,30};
int *p = a;
int **pp = &p;
int x = *p++;
int y = (*p)++;
**pp = 40;

문제를 내 말로 읽어요

배열을 가리키는 포인터 p와 이중 포인터 pp에서 *p++, (*p)++, **pp = 40;이 실행될 때 포인터 위치와 배열 값이 어떻게 변하는지 추적하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

‘*와 ++’는 연산자 우선순위와 후위 증가의 단서예요. *p++는 *(p++)로서 현재 값을 읽고 포인터 p를 다음 원소로 옮기며, (*p)++는 포인터는 그대로 두고 가리키는 원소 값을 1 증가시켜요.

종이에 쓰는 첫 줄

초기 상태: p → a[0], pp → p, 배열 [10, 20, 30]이라고 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) int x = *p++;는 a[0] = 10을 x에 넣은 뒤 포인터 p만 a[1]로 이동시켜 배열은 [10, 20, 30]이에요. int y = (*p)++;는 현재 p가 가리키는 a[1] = 20을 y에 넣은 뒤 그 원소 값을 21로 증가시키고 p는 a[1]에 남아요(배열 [10, 21, 30]). 이어서 **pp = 40;은 *pp(= p)가 가리키는 a[1]에 40을 대입해 배열은 [10, 40, 30]이 돼요.

(b) pp는 포인터 변수 p의 주소, *pp는 p의 값(현재 a[1]의 주소), **pp는 그 주소에 있는 원소 a[1]이에요. int 크기가 4바이트이므로 p = a + 1과 a의 바이트 간격은 4바이트예요.

완성 답과 검산

(a) 포인터 p를 이동시킨 문장은 *p++ 한 번뿐이므로 마지막까지 p는 a[1]을 가리키고, **pp = 40이 a[1]을 덮어써 최종 배열이 [10, 40, 30]이 되는 것과 일치해요.

(b) *pp == p == a + 1이므로 **pp는 *(a + 1) == a[1]과 같은 객체이고, 원소 1개 간격은 1 × sizeof(int) = 4바이트예요.

이 문제에서 조심할 점

pp를 배열 원소의 주소와 혼동하지 않아요. 후위 증가가 어느 괄호 안 객체에 적용되는지 먼저 확인해요.

설명을 닫고 다시 해 봐요

  1. *p++와 (*p)++ 실행 직후의 x, y 값과 p의 위치 및 배열 값을 적어요.
  2. pp, *pp, **pp가 가리키는 대상과 a + 1의 바이트 간격을 적어요.

떠올릴 개념·공식

*p++는 포인터를 이동시키고 (*p)++는 가리키는 원소 값을 증가시켜요.

첫 줄

초기: p → a[0], pp → p, 배열 [10, 20, 30]이라고 적어요.

핵심 답

(a) x=10, y=20, [10,20,30] → [10,21,30] → [10,40,30](p는 a[1]) (b) pp는 p의 주소, *pp는 p의 값, **pp는 a[1], 간격 4바이트.

P8. 포인터 초기화·void 포인터와 할당 방식

lecture-s03-p27-pointer-safety-allocation · 원 문제 보기

강의 예제 기반 자체 출제 S3 p27

아래는 포인터 초기화, void * 형변환, 그리고 정적·동적 메모리 할당을 비교하기 위한 코드 조각이에요.

char *pc;
*pc = 'E';          /* 미초기화 역참조 */

char c;
void *v = &c;       /* 범용 포인터 저장 */
char buffer[100];   /* 고정 크기 정적 배열 */

구할 것

  1. (a) 지역 코드에서 char *pc; *pc = 'E';나 pc = NULL; *pc = 'E';를 실행하면 안 되는 이유를 설명하고, char c;를 실제 저장 대상으로 연결해 'E'를 대입하는 코드와 void *v = &c;에서 char *q로 형변환해 되돌려 받는 식을 쓰세요.
  2. (b) 고정 배열 buffer[100]과 실행 중 필요한 크기를 malloc으로 받는 방식을 비교하고, 동적 할당 직후와 반납 시 지켜야 할 안전 규칙을 설명하세요.
강의 예제 보기

S3 p27 · 추가 근거 p21,28,29 · Software_3_ArrayStructureList.pdf. 강의의 개념·그림·코드 연산을 바탕으로 조건과 질문을 새로 작성한 자체 출제예요. 제시 코드는 있는 경우 학습 확인용 자체 코드이며 강의 원문 발췌가 아니에요. 질문·입력 조건·검산은 자체 작성했어요.

문제를 내 말로 읽어요

초기화하지 않은 포인터나 NULL 포인터를 역참조하면 왜 위험한지, 유효한 변수 주소 연결과 void * 형변환을 어떻게 쓰는지, 그리고 고정 배열과 malloc 동적 할당의 관리 규칙을 묻는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

‘초기화되지 않은 포인터’는 유효한 대상 객체 연결의 단서예요. NULL은 가리키는 객체가 없다는 값이고, void *는 대상 타입을 지정하지 않은 주소 타입이므로 역참조 전에 원래 타입 포인터로 캐스트해야 해요. 동적 할당은 NULL 검사와 free 반납을 직접 책임져요.

종이에 쓰는 첫 줄

pc가 어느 실제 char 객체를 가리키는지(char c; char *pc = &c;)부터 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) 초기화되지 않은 pc를 역참조하면 쓰레기 주소에 쓰기를 시도해 미정의 동작이 되고, NULL도 가리키는 실제 객체가 없으므로 역참조할 수 없어요. 실제 변수 char c; char *pc = &c; *pc = 'E';로 유효한 저장소를 연결해야 하며, void *v = &c;에서는 char *q = (char *)v;로 형변환해 원래 char 객체에 접근해요.

(b) 고정 배열 buffer[100]은 정해진 용량 때문에 공간 부족이나 낭비가 생길 수 있지만, 동적 할당은 실행 중 필요한 크기를 정해요. malloc 호출 뒤에는 결과가 NULL인지 확인하고, 사용이 끝난 뒤 최초 할당 주소를 한 번 free하며 해제 이후에는 접근하지 않아요.

완성 답과 검산

(a) 수정한 코드에서 pc = &c이고 q = (char *)v = &c이므로 두 포인터 모두 유효한 지역 변수 c를 가리켜 안전하게 읽고 쓸 수 있어요.

(b) 할당 실패(NULL)일 때 역참조를 막고, 사용 후 free로 반납하고 재접근하지 않는 흐름이 동적 메모리 수명 주기와 정확히 일치해요.

이 문제에서 조심할 점

void * 선언을 NULL 초기화와 같은 뜻으로 읽지 않아요. 캐스트만으로 잘못된 주소가 유효해지는 것도 아니에요.

설명을 닫고 다시 해 봐요

  1. 미초기화·NULL 역참조가 불가능한 이유와 char c;를 연결하는 수정 코드를 적어요.
  2. void *v를 char *q로 되돌리는 형변환 식을 적어요.
  3. 고정 배열과 동적 할당의 차이 및 malloc·free 안전 규칙을 확인해요.

떠올릴 개념·공식

포인터는 유효한 저장소에 연결한 뒤에만 역참조할 수 있고, void *는 원래 포인터 타입으로 형변환해 사용해요.

첫 줄

pc가 어느 실제 char 객체를 가리키는지부터 적어요.

핵심 답

(a) 미초기화·NULL 역참조 불가, char c; char *pc=&c; *pc='E';, char *q=(char *)v; (b) 고정 배열은 용량 부족·낭비 가능, 동적 할당은 실행 중 크기 결정 및 NULL 확인·free 후 접근 금지.

조건·구분과 확인

  • void * 선언은 NULL 초기화가 아니며, 캐스트만으로 잘못된 주소가 유효해지지는 않아요.

P9. sizeof·패딩과 배열 원소 수

lecture-s03-p30-sizeof-alignment-count · 원 문제 보기

강의 예제 기반 자체 출제 S3 p30

sizeof(char) == 1, sizeof(int) == 4이고 int가 4바이트 경계에 정렬되는 환경에서 아래 구조체와 배열을 보아요(c의 오프셋은 0, i의 오프셋은 4, 구조체 전체 크기는 8바이트예요).

struct AlignDepends {
    char c;
    int i;
};
int array[] = {1, 2, 3, 4, 5};

구할 것

  1. (a) sizeof(struct AlignDepends)가 멤버 크기의 단순 합 1 + 4 = 5바이트가 아니라 8바이트가 되는 이유를 오프셋과 패딩(padding)으로 설명하세요.
  2. (b) sizeof(array), sizeof(array[0])의 값과 두 값의 비 sizeof(array) / sizeof(array[0])의 값·단위를 쓰고, 다른 C 환경에서도 int와 구조체 크기가 무조건 4·8바이트인지(반면 sizeof(char)는 어떠한지) 설명하세요.

문제를 내 말로 읽어요

구조체 struct AlignDepends의 크기가 메모리 정렬 패딩 때문에 8바이트가 되는 이유와, 배열에서 sizeof(array) / sizeof(array[0])으로 원소 개수를 구하는 원리 및 C 표준의 크기 보장 범위를 묻는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

‘정렬’은 구조체 멤버 크기를 단순 합산하지 말라는 단서예요. 패딩(padding)으로 비워 둔 바이트도 구조체 sizeof에 포함되며, 실제 배열 전체 바이트 크기를 한 원소 바이트 크기로 나누면 배열 원소 수가 돼요.

종이에 쓰는 첫 줄

c: 오프셋 0, 패딩: 오프셋 1~3, i: 오프셋 4~7이라고 메모리 배치를 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) 오프셋 0에 1바이트 c가 놓인 뒤, 4바이트 정렬을 따르는 int i가 4의 배수 오프셋에서 시작하도록 오프셋 1~3에 3바이트 패딩이 들어가요. i가 오프셋 4~7을 쓰므로 전체 크기는 8바이트예요.

(b) 원소 5개인 int array[] 전체는 5 × 4 = 20바이트이고 원소 하나 sizeof(array[0])은 4바이트이므로, 비는 20 / 4 = 5개예요. int와 구조체 크기는 실행 환경에 따라 달라 고정할 수 없지만, sizeof(char)는 C에서 항상 1바이트로 보장돼요.

완성 답과 검산

(a) 오프셋 0~7의 총 8칸을 c(1바이트) + 패딩(3바이트) + i(4바이트) = 8바이트로 합산해 검산할 수 있어요.

(b) 초기화 목록 {1, 2, 3, 4, 5}의 원소를 직접 세어도 5개여서 sizeof(array) / sizeof(array[0]) = 20 / 4 = 5와 일치해요.

이 문제에서 조심할 점

패딩으로 비워 둔 바이트는 malloc 후 free하지 않은 메모리 누수와 달라요. 배열이 포인터로 전달된 매개변수에서는 이 sizeof 비로 배열 길이를 구할 수 없어요.

설명을 닫고 다시 해 봐요

  1. c(오프셋 0), 패딩(1~3), i(4~7) 배치로 전체 8바이트가 되는 이유를 적어요.
  2. sizeof(array), sizeof(array[0]), 원소 수 20 / 4 = 5개를 구해요.
  3. 환경에 따라 달라지는 크기(int, 구조체)와 C가 항상 1로 보장하는 sizeof(char)를 구별해요.

떠올릴 개념·공식

패딩 바이트도 구조체 sizeof에 포함되며, 배열 전체 크기를 원소 크기로 나누면 원소 수가 돼요.

첫 줄

c: 0, 패딩: 1~3, i: 4~7이라고 배치를 적어요.

핵심 답

(a) 오프셋 1~3에 3바이트 패딩이 있어 전체 8바이트 (b) 전체 20바이트, 원소 4바이트, 비 20/4=5개, sizeof(char)만 항상 1 보장.

조건·구분과 확인

  • 배열이 포인터로 전달된 매개변수에서는 이 sizeof 비로 배열 길이를 구할 수 없으며, 정렬 패딩은 메모리 누수와 달라요.

# 배열 스택에서 top을 먼저 옮기는 이유

1008 수업 S5 p9–12의 배열 스택 push/pop 순서를 메모리 칸과 top 변화로 확인한다. 노트 절: s2-pushpop, s2-array.

**핵심 질문**: push는 왜 top을 먼저 올리고 저장하며, pop은 왜 값을 읽은 뒤 top을 내리는가? 순서를 바꾸면 무엇이 깨지는가?

입력: push할 값 x -99–99, 처음 요소 수 n 0–5(10, 20, 30, 40, 50), 연산 push/pop/보충 저장 후 증가. 사례: 빈 스택 push, 마지막 칸 채우기(x=-99), 가득 찬 push(overflow), pop, 빈 pop(underflow → exit(1)), 저장 후 증가 덮어쓰기, 빈 스택 저장 후 증가(stack[-1] 범위 밖).

원문 판단: 1008 수업은 S5 p10–12 의사코드로 설명했고(노트 s2-pushpop), C 구현 S5 p13–14는 노트의 다음 시간 예고 범위다. 의사코드와 같은 순서를 C 메모리로 보이기 위해 p13–14 원문 C를 사용하고 출처에 이를 밝힌다. MAX_STACK_SIZE 값 5, #include, main과 준비된 s는 보충. 저장 후 증가 한 줄은 노트의 덮어쓰기 경고를 확인하는 보충 오답 예제다.

C 의미: ++(s->top)의 결과가 인덱스이므로 저장 칸은 t+1. 후위 ++/--는 증가·감소 전 값을 인덱스로 쓴다. 저장과 top 갱신의 순서는 C가 정하지 않지만 결과가 같아 하나의 순서로 보이고 설명에 밝힌다. stack[-1] 저장은 정의되지 않은 동작이므로 실행하지 않고 그 단계에서 범위 밖 진단으로 멈춘다. exit(1)은 정의된 종료이며 PROGRAM_EXIT 진단으로 끝낸다. pop 뒤 stack[t]의 값은 지워지지 않으나 top 밖이다.

단순화: s->top은 첫 멤버가 아니라 해당 Cell을 직접 읽고 쓴다. is_full/is_empty 반환값은 조건에서 소비되어 설명으로 표시. stderr 출력은 관찰 단계 설명으로 표시.

독립 검산: compiler_unavailable. Python 표로 모든 값 복사·쓰기, 최종 스택, pop 반환값, 진단을 비교한다.

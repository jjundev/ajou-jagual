    <section id="s0"><h2>1. 리스트의 기능을 재사용하기</h2>
<article class="topic" id="s0-adapter"><h3>1. 위치와 선행 노드를 이어 주는 함수</h3><div class="tags"><span class="tag date">1008 수업</span><span class="tag slide">S4 p44, p47–48</span></div>
  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">줄에서 새 친구가 설 자리를 알려면 바로 앞 친구를 찾아요. 앞 친구를 찾는 작은 도우미가 있으면 이미 만든 끼워 넣는 일을 그대로 쓸 수 있어요.</p>
    <figure class="figure"><svg id="fig-s0-adapter" viewBox="0 0 500 130" role="img" aria-label="세 친구가 줄지어 있고 앞 친구 뒤에 새 친구가 들어가는 위치를 선으로 표시한 그림"><rect class="fig-ink" x="30" y="42" width="74" height="48" rx="6" fill="none"/><text class="fig-text" x="67" y="72" text-anchor="middle" font-size="13">첫째</text><path class="fig-ink" d="M105 66 H139" fill="none"/><path class="fig-ink" d="M132 60 L140 66 L132 72" fill="none"/><rect class="fig-ink" x="142" y="42" width="74" height="48" rx="6" fill="none"/><text class="fig-text" x="179" y="72" text-anchor="middle" font-size="13">둘째</text><path class="fig-accent" d="M217 66 H269" fill="none"/><path class="fig-accent" d="M262 60 L270 66 L262 72" fill="none"/><rect class="fig-accent" x="272" y="42" width="74" height="48" rx="6" fill="none"/><text class="fig-text" x="309" y="72" text-anchor="middle" font-size="13">새 친구</text><path class="fig-ink" d="M347 66 H381" fill="none"/><path class="fig-ink" d="M374 60 L382 66 L374 72" fill="none"/><rect class="fig-ink" x="384" y="42" width="74" height="48" rx="6" fill="none"/><text class="fig-text" x="421" y="72" text-anchor="middle" font-size="13">셋째</text></svg><figcaption>둘째를 찾으면 그 뒤에 새 친구를 놓을 수 있어요.</figcaption></figure>
  </div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span>
    <p>리스트 추상 데이터 타입(ADT)의 <code>add</code>와 <code>delete</code>는 위치(position)를 받지만, 연결 리스트(linked list)의 <code>insert_node</code>와 <code>remove_node</code>는 선행 노드 포인터를 받아요(S4 p44). <code>get_node_at</code>은 위치로 노드를 찾아 두 인터페이스를 이어 줘요. 교수는 이 작은 변환 함수를 두고 기존 함수를 재사용하자고 설명했어요.</p>
    <p>슬라이드 API의 위치는 0부터 세요. <code>position=0</code>은 첫 노드 앞에 넣는 뜻이고, <code>position=3</code>은 세 번째 노드 뒤에 넣는 뜻이에요. 그래서 구어체의 “세 번째 뒤”를 API 값 2로 읽으면 한 칸 어긋나요. 삽입 위치 <code>position</code>의 선행 노드는 <code>get_node_at(list, position-1)</code>로 찾아요.</p>
    <p>S4 p47 삽입 코드의 핵심 부분이에요. 아래는 원본의 나머지 줄을 생략한 발췌예요.</p>
    <pre><code class="language-c">/* … */
p = get_node_at(list, position-1);
insert_node(&amp;(list-&gt;head), p, node);
list-&gt;length++;
/* … */</code></pre>
    <p><code>position-1</code>이 음수이면 S4 p47의 <code>get_node_at</code>은 <code>NULL</code>을 돌려요. S4 p25의 <code>insert_node</code>는 빈 리스트이거나 선행 노드 <code>p</code>가 <code>NULL</code>일 때 헤드 포인터를 바꿔 앞에 삽입해요. 이 두 계약 덕분에 첫 위치도 같은 <code>add</code> 경로로 처리할 수 있어요. <code>length</code>와 헤드 포인터의 구조는 S4 p45–46을 배경으로 확인한 것이며, 그 쪽의 세부 구현을 이날 다시 강의했는지는 불확실해요.</p>
    <p>S4 p48의 삭제도 삭제 위치 <code>pos</code>보다 하나 앞의 노드를 구해 <code>remove_node</code>에 넘기려는 원리예요. 다만 원본 p48은 <code>pos=0</code>에서 <code>removed=NULL</code>을 넘기고, 원본 p28의 <code>remove_node</code>는 선행 노드가 <code>NULL</code>이면 첫 노드로 헤드를 옮긴 뒤 <code>free(removed)</code>를 해요. 이 조합은 첫 노드 메모리를 해제하지 못하므로 그대로 안전한 삭제 구현이라고 받아들이면 안 돼요. 개념상 첫 노드를 삭제할 때는 실제 첫 노드를 <code>removed</code>로 전달해야 해요. 이 경계 조건 설명은 두 슬라이드 코드를 대조한 구현 해설이며, 수업에서 수정 코드를 제시했다는 뜻은 아니에요.</p>
  </div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span><p>교수는 서로 맞지 않는 레고 블록 사이에 작은 연결 조각을 두는 비유로 <code>get_node_at</code>을 설명했어요. 이미 만든 AND 게이트를 이어 쓰듯 기능을 재사용하는 접근이에요.</p><blockquote>“있는 블록과 그 사이에 필요한 아주 마이너한 그런 함수를 만들어서” (1008 Part 01, 시간 미제공)</blockquote></div>
  <div class="layer warn"><span class="layer-title">꼭 기억해요</span><p>교수는 리스트 온라인 강의를 마치고 와야 한다고 강조했어요. 현재 다룬 여섯 챕터를 고르게 고려한다고 말했고, 연습문제도 풀어 보라고 했어요. 이는 출제 의도에 관한 발언이며 정확한 문항 수나 점수 배분의 확정 안내는 아니에요.</p><blockquote>“연습 문제 좀 풀어봤으면 좋겠어요.” (1008 Part 01, 시간 미제공)</blockquote><blockquote>“여러분들 강의 제대로 안 들었으면 안 돼요.” (1008 Part 01, 시간 미제공)</blockquote></div>
  <div class="sum" hidden><p class="sum-lead">위치를 선행 노드로 바꿔 기존 삽입·삭제 함수를 재사용해요.</p><p class="panel-label">용어</p><dl class="terms"><dt>get_node_at</dt><dd>위치로 노드를 찾아 선행 노드 포인터를 마련하는 함수예요.</dd><dt>선행 노드 포인터</dt><dd>삽입·삭제할 곳 바로 앞 노드를 가리키는 포인터예요.</dd></dl></div>

<article class="topic" id="s0-readable"><h3>2. 가독성과 모듈화</h3><div class="tags"><span class="tag date">1008 수업</span><span class="tag slide">S4 p44–48</span></div>
  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">여행 가방에 물건을 쓰임새대로 나눠 담으면 찾기 쉬워요. 다음 여행에서는 필요한 묶음을 다시 꺼내 쓰면 돼요.</p>
    <figure class="figure"><svg id="fig-s0-readable" viewBox="0 0 500 140" role="img" aria-label="큰 여행 가방 테두리 안에 세 개의 작은 꾸러미 테두리가 나뉘어 있는 그림"><rect class="fig-ink" x="36" y="34" width="428" height="90" rx="10" fill="none"/><path class="fig-ink" d="M208 34 V22 Q208 14 218 14 H282 Q292 14 292 22 V34" fill="none"/><rect class="fig-accent" x="58" y="56" width="112" height="47" rx="5" fill="none"/><rect class="fig-accent" x="194" y="56" width="112" height="47" rx="5" fill="none"/><rect class="fig-accent" x="330" y="56" width="112" height="47" rx="5" fill="none"/><text class="fig-text" x="114" y="85" text-anchor="middle" font-size="13">옷 꾸러미</text><text class="fig-text" x="250" y="85" text-anchor="middle" font-size="13">씻는 꾸러미</text><text class="fig-text" x="386" y="85" text-anchor="middle" font-size="13">책 꾸러미</text></svg><figcaption>같은 쓰임새의 물건끼리 모아 두면 다시 쓰기 쉬워요.</figcaption></figure>
  </div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p>가독성(readability)은 다른 사람이 코드의 흐름과 각 부분의 역할을 이해하기 쉬운 성질이에요. 재사용성(reusability)은 이미 만든 기능을 다른 곳에서도 쓸 수 있는 성질이에요. 모듈화는 한 역할을 함수로 감싸 각 부분이 맡은 일을 분명하게 하는 방법이에요.</p><p>S4 p44의 위치 기반 리스트 ADT와 노드 포인터 기반 연결 리스트 함수는 입력 방식이 달라요. <a href="#s0-adapter">위치와 선행 노드를 이어 주는 함수</a>처럼 작은 변환 함수를 두면 기존 연결 동작을 새로 작성할 필요가 줄어요. 교수는 여러 사람이 코드를 읽는 상황에서 함수의 역할이 보여야 한다고 강조했어요. S4 p45–46은 이 연결을 이해하기 위한 배경이지만, 이날 그 쪽을 조항별로 다시 설명했는지는 확인되지 않아요.</p></div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span><p>교수는 물건이 뒤섞인 여행 가방보다 용도별 꾸러미가 있는 여행 가방을 함수 구조에 비유했어요. 나중에 수영 준비가 필요하면 해당 꾸러미를 다시 꺼내 쓸 수 있다는 설명이에요.</p><blockquote>“가독성 있는 프로그램을 짤 줄 알아야 되고요.” (1008 Part 02, 시간 미제공)</blockquote><blockquote>“모듈화, 모듈화. function으로 감싸야 돼요.” (1008 Part 02, 시간 미제공)</blockquote></div>
  <div class="sum" hidden><p class="sum-lead">역할별로 함수를 나누면 읽기 쉽고 다시 쓰기 쉬워요.</p><p class="panel-label">용어</p><dl class="terms"><dt>가독성(readability)</dt><dd>코드의 흐름과 각 부분의 역할을 이해하기 쉬운 성질이에요.</dd><dt>재사용성(reusability)</dt><dd>이미 만든 기능을 다른 곳에서도 쓸 수 있는 성질이에요.</dd><dt>모듈화</dt><dd>한 역할을 함수로 감싸 각 부분의 일을 분명하게 하는 방법이에요.</dd></dl></div>

    <section id="s1"><h2>2. 스택의 규칙과 연산</h2>
<article class="topic" id="s1-lifo"><h3>1. 가장 최근에 들어온 것부터 꺼내기</h3><div class="tags"><span class="tag date">1008 수업</span><span class="tag slide">S5 p2–4</span></div>
  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">좁고 긴 통에 물건을 차곡차곡 넣으면 맨 위 물건부터 꺼낼 수 있어요.</p>
    <figure class="figure"><svg id="fig-s1-pile" viewBox="0 0 360 200" role="img" aria-label="테두리로 그린 긴 통 안에 세 물건이 쌓이고 위쪽 입구로 꺼내는 모습"><path class="fig-ink" d="M105 32 V174 H255 V32 M105 174 H255"/><rect class="fig-ink" x="125" y="133" width="110" height="33" rx="4"/><rect class="fig-ink" x="125" y="94" width="110" height="33" rx="4"/><rect class="fig-accent" x="125" y="55" width="110" height="33" rx="4"/><path class="fig-accent" d="M277 84 V42 M277 42 L270 52 M277 42 L284 52"/><text class="fig-text" x="160" y="156">첫째</text><text class="fig-text" x="160" y="117">둘째</text><text class="fig-text" x="160" y="78">셋째</text><text class="fig-muted" x="289" y="68">입구</text></svg><figcaption>마지막에 놓은 셋째 물건이 입구에 가장 가까워요.</figcaption></figure>
  </div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p>스택(stack)은 요소(element)를 쌓아 두는 자료구조예요. 아래쪽을 bottom, 위쪽을 top이라고 해요. 요소는 top에서만 추가하거나 제거해요. 따라서 가장 나중에 들어온 요소가 먼저 나가는 후입선출(LIFO, Last-In First-Out) 순서가 돼요.</p><p>예를 들어 아래부터 A, B, C가 있으면 B를 바로 꺼낼 수 없어요. 먼저 top의 C를 꺼내고 B를 꺼낸 다음, C를 다시 넣어야 해요. 리스트처럼 임의 위치를 직접 지정해 삭제하는 방식과 달라요.</p></div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span><p>교수님은 시험관 안에 블록을 차곡차곡 넣는 모습을 들어, 맨 위에서만 손댈 수 있다고 설명했어요. 책이나 상자처럼 쌓인 더미도 같은 직관을 줘요.</p><blockquote>“무조건 위에서만 삭제와 삽입 연산이 일어납니다.” <cite>(1008 Part 03, 시간 미제공)</cite></blockquote></div>
  <div class="sum" hidden><p class="sum-lead">스택은 top에서만 넣고 꺼내므로 가장 나중에 넣은 요소가 먼저 나와요.</p><p class="panel-label">용어</p><dl class="terms"><dt>후입선출(LIFO)</dt><dd>가장 나중에 들어온 요소가 먼저 나가는 순서예요.</dd><dt>top</dt><dd>요소를 넣고 꺼내는 스택의 위쪽이에요.</dd><dt>bottom</dt><dd>스택의 아래쪽이에요.</dd></dl></div>

  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">동전 지갑의 맨 위 동전을 더 넣거나 꺼낼 수 있어요. 꺼내지 않고 맨 위 동전이 무엇인지 보기만 할 수도 있어요.</p>

  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p>추상 데이터 타입(ADT)은 저장 대상과 허용 연산을 먼저 정한 설계예요. S5 p5의 스택 객체는 n개의 element형 요소로 이루어진 선형 리스트예요. 강의록의 기본 연산은 아래와 같고, 교수님은 필요한 연산을 이 목록에 더할 수 있다고 설명했어요.</p><ul><li><code>create()</code>: 새 스택을 생성해요.</li><li><code>is_empty(s)</code>: 비어 있는지 검사해요.</li><li><code>is_full(s)</code>: 가득 찼는지 검사해요.</li><li><code>push(s, e)</code>: 요소 e를 top에 추가해요.</li><li><code>pop(s)</code>: top의 요소를 제거하고 반환해요. 이때 꺼낸 요소를 이어서 처리할 수 있어요.</li><li><code>peek(s)</code>: top의 요소를 제거하지 않고 반환해요.</li></ul><p><code>push</code>와 <code>pop</code>은 조작 위치가 언제나 top이어서 위치나 선행 노드를 인자로 받지 않아요. <code>bottom</code>은 아래쪽을 가리키는 개념이지만 구현할 때 별도 변수로 반드시 둘 필요는 없어요.</p></div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span><p>교수님은 동전 지갑 안의 용수철 때문에 위에 놓인 동전부터 손이 닿는 모습으로 연산을 설명했어요. 음식 상자에서 위의 상자부터 꺼내는 비유도 들었어요. 삭제는 단순히 버리는 일이 아니라 꺼낸 뒤 처리하기 위한 시작일 수 있어요.</p><blockquote>“여러분들이 꼭 스택이라고 하는 자료구조를 실제로 디자인한다는 것을 염두에 두면서 이 수업을 들으세요.” <cite>(1008 Part 02, 시간 미제공)</cite></blockquote></div>
  <div class="sum" hidden><p class="sum-lead">push는 위에 넣고, pop은 꺼내며, peek는 그대로 두고 보기만 해요.</p><p class="panel-label">용어</p><dl class="terms"><dt>push</dt><dd>top에 새 요소를 추가해요.</dd><dt>pop</dt><dd>top의 요소를 제거하고 반환해요.</dd><dt>peek</dt><dd>top의 요소를 제거하지 않고 반환해요.</dd></dl></div>
</article>

  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p>함수가 다른 함수를 호출하면 시스템 스택에 활성 레코드(activation record)를 쌓아요. 활성 레코드에는 호출한 함수의 복귀 주소와 지역 변수 등이 들어가요. PC(program counter)는 실행 위치를 나타내며, 아래 PC 값은 슬라이드의 추적용 예시예요.</p><p>S5 p8의 <code>main</code>, <code>sub1</code>, <code>sub2</code> 함수 관계와 PC 그림을 단계별로 따라가요.</p><ol class="steps"><li><code>main</code>에서 <code>i=3</code>이고, 호출 지점은 <code>PC=20</code>이에요. 이 상태와 다음에 돌아올 주소를 보존하고 <code>sub1(i)</code>를 호출해요.</li><li><code>sub1</code>은 매개변수 <code>a=3</code>, 지역 변수 <code>j=5</code>인 상태로 실행돼요. <code>PC=150</code>에서 <code>sub2(j)</code>를 호출하며 자신의 상태와 복귀 주소를 그 위에 쌓아요.</li><li><code>sub2</code>는 매개변수 <code>b=5</code>로 실행돼요. 지금 활성 레코드의 순서는 아래부터 <code>main</code>, <code>sub1</code>, <code>sub2</code>예요.</li><li><code>sub2</code>가 끝나면 가장 위 레코드를 꺼내 <code>sub1</code>의 <code>PC=151</code>로 돌아가요. <code>a=3</code>과 <code>j=5</code>를 가진 <code>sub1</code>이 이어져요.</li><li><code>sub1</code>이 끝나면 그 레코드를 꺼내 <code>main</code>의 <code>PC=21</code>로 돌아가요. <code>i=3</code>인 <code>main</code>이 이어져요.</li></ol><p>이 흐름은 <code>main</code>이 <code>sub1</code>을, <code>sub1</code>이 <code>sub2</code>를 부른 중첩 호출이에요. 자기 자신을 부르는 재귀 호출은 아니에요. 재귀 호출도 각 호출에서 돌아올 곳을 쌓는 같은 원리를 써요.</p></div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span><p>교수님은 숲길에서 갈림길마다 되돌아올 이정표를 남기는 비유로 복귀 주소를 설명했어요. 이 예가 재귀가 아닌 중첩 호출이라고 구분했어요. (1008 Part 04, 시간 미제공)</p><blockquote>“이거 recursion / 순환 호출 아니거든요? 중첩된 함수들이 쭉 이어져 있는 거거든요.” <cite>(1008 Part 04, 시간 미제공)</cite></blockquote></div>
  <div class="sum" hidden><p class="sum-lead">함수는 활성 레코드에 돌아올 곳과 지역 변수를 보존해요.</p><p class="panel-label">용어</p><dl class="terms"><dt>활성 레코드(activation record)</dt><dd>호출마다 복귀 주소와 지역 변수 등을 담아 쌓는 기록</dd><dt>PC(program counter)</dt><dd>프로그램의 실행 위치를 나타내는 값</dd><dt>중첩 호출</dt><dd>서로 다른 함수가 차례로 다른 함수를 호출하는 흐름</dd></dl></div>

  <div class="sum" hidden><p class="sum-lead">배열 스택의 top은 현재 맨 위 요소의 인덱스를 가리켜요.</p><p class="panel-label">용어</p><dl class="terms"><dt>top</dt><dd>가장 최근에 넣은 요소의 인덱스</dd><dt>바텀(bottom)</dt><dd>첫 요소가 있는 쪽</dd><dt>MAX_STACK_SIZE</dt><dd>배열의 칸 수</dd></dl></div>

  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">새 물건을 넣기 전에 빈칸이 있는지 살펴요. 꺼낼 때는 물건이 있는지 먼저 보고, 맨 위 물건을 집은 뒤 자리를 한 칸 내려요.</p>

  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p>다음은 S5 p10–12의 <strong>의사코드</strong>를 순서로 풀어 쓴 것이에요. 완성된 C 함수 본문이 아니에요.</p><div class="table-wrap"><table><thead><tr><th>연산</th><th>의사코드 순서</th><th>오류</th></tr></thead><tbody><tr><td><code>push(S, x)</code></td><td><code>is_full(S)</code>을 먼저 검사해요. 공간이 있으면 <code>top + 1</code>로 위치를 올린 뒤 <code>stack[top]</code>에 <code>x</code>를 저장해요.</td><td>이미 찼으면 <code>overflow</code>예요.</td></tr><tr><td><code>pop(S)</code></td><td><code>is_empty(S)</code>를 먼저 검사해요. 요소가 있으면 <code>stack[top]</code>의 값을 읽고 <code>top - 1</code>로 위치를 내린 뒤 읽은 값을 반환해요.</td><td>비어 있으면 <code>underflow</code>예요.</td></tr></tbody></table></div><p><code>push</code>에서 기존 <code>stack[top]</code>에 먼저 쓰면 현재 맨 위 값을 덮어쓰기 해요. 반드시 증가 후 저장해요. <code>pop</code>에서는 먼저 값을 읽어 두어야 위치를 내린 뒤에도 그 값을 반환할 수 있어요.</p><ol class="steps"><li>빈 배열: <code>top=-1</code>.</li><li><code>push(A)</code>: 포화 여부 확인, <code>top=0</code>, <code>stack[0]=A</code>.</li><li><code>push(B)</code>: 포화 여부 확인, <code>top=1</code>, <code>stack[1]=B</code>.</li><li><code>pop()</code>: 공백 여부 확인, <code>B</code>를 읽음, <code>top=0</code>, <code>B</code> 반환. 이때 유효한 맨 위 요소는 <code>A</code>예요.</li></ol><p>각 연산은 검사와 인덱스 변경, 한 요소의 접근만 하므로 배열 기반 <code>push</code>와 <code>pop</code>의 시간복잡도는 $O(1)$이에요. 이는 슬라이드와 발화에 명시된 결과가 아닌 <strong>[슬라이드 외: 분석]</strong>이에요.</p></div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span><blockquote>“증가부터 하는 이유는 top이 맨 위의 요소를 가리키고 있기 때문이에요.” <cite>(1008 Part 05, 시간 미제공)</cite></blockquote><p>교수님은 공백과 포화를 먼저 확인하고 나서 값을 다루는 순서를 설명했어요. (1008 Part 05, 시간 미제공)</p></div>
  <div class="sum" hidden><p class="sum-lead">넣을 때는 검사 후 위치를 올려 저장하고, 꺼낼 때는 검사 후 읽어 위치를 내려요.</p><p class="panel-label">핵심 식</p><ul class="eq-list"><li><span class="eq-name">배열 기반 push·pop</span>$O(1)$</li></ul><p class="panel-label">용어</p><dl class="terms"><dt>overflow</dt><dd>가득 찬 스택에 넣으려 할 때의 오류</dd><dt>underflow</dt><dd>빈 스택에서 꺼내려 할 때의 오류</dd></dl></div>

  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p>실습 2는 <b>헤드 노드가 있는 원형 이중 연결 리스트</b>의 프로세스 노드를 <code>priority</code> 오름차순으로 옮기는 <b>삽입 정렬(insertion sort)</b>이에요. 왼쪽은 정렬된 영역, 오른쪽은 아직 처리하지 않은 영역이에요. 노드의 데이터를 바꾸는 대신 노드 자체를 분리해 맞는 위치에 다시 연결해요.</p><ol class="steps"><li>초기 PID 순서는 P1, P2, P3, P4이고 우선순위는 <code>3, 1, 4, 2</code>예요.   <div class="sum" hidden><p class="sum-lead">정렬된 영역에 노드를 하나씩 넣어 우선순위가 작은 것부터 놓아요.</p><p class="panel-label">핵심 식</p><ul class="eq-list"><li><span class="eq-name">최악 시간복잡도</span>$O(n^2)$</li></ul><p class="panel-label">용어</p><dl class="terms"><dt>삽입 정렬(insertion sort)</dt><dd>정렬된 영역의 알맞은 위치에 다음 항목을 넣는 방법</dd></dl></div>
</article>
<article class="topic" id="s3-move"><h3>2. 노드를 옮기기 전에 다음 대상을 저장하기</h3><div class="tags"><span class="tag date">1008 수업</span></div>
  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">줄에서 한 친구를 옮기기 전에 다음 친구가 누구인지 기억해 둬요. 그래야 자리가 바뀌어도 빠뜨리지 않고 계속할 수 있어요.</p><figure class="figure"><svg id="fig-save-next" viewBox="0 0 360 80" role="img" aria-label="세 개의 테두리 칸 가운데 칸에서 오른쪽 다음 칸으로 이어지는 선과 위쪽 기억 상자"><rect class="fig-ink" x="15" y="38" width="74" height="28"/><rect class="fig-accent" x="140" y="38" width="74" height="28"/><rect class="fig-ink" x="265" y="38" width="74" height="28"/><text class="fig-text" x="49" y="57">앞</text><text class="fig-text" x="166" y="57">지금</text><text class="fig-text" x="291" y="57">다음</text><path class="fig-ink" d="M214 52 H260 M253 46 L260 52 L253 58"/><rect class="fig-accent" x="257" y="3" width="88" height="25"/><text class="fig-text" x="269" y="21">기억해 둠</text><path class="fig-accent" d="M301 28 V37 M295 32 L301 38 L307 32"/></svg><figcaption>지금 자리를 바꾸기 전에 다음 자리를 기억해요.</figcaption></figure></div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p>제공된 <code>sort_by_priority</code>의 빈 부분에서 <code>current</code>를 옮기면 <code>current-&gt;next</code>가 새 삽입 위치에 맞게 바뀌어요. 그래서 다음 미정렬 노드를 <code>next_unsorted = current-&gt;next;</code>로 먼저 저장해야 해요. <code>position</code>은 이동 전 <code>current-&gt;prev</code>에서 시작해 왼쪽으로 탐색해요.</p><pre><code class="language-c">next_unsorted = current-&gt;next;
position = current-&gt;prev;
/* position-&gt;data.priority &gt; current-&gt;data.priority인 동안 왼쪽 탐색 */
detach_node(current);
insert_after(position, current);
current = next_unsorted;</code></pre><p>이 조각은 조교 설명과 스켈레톤을 연결한 핵심 순서예요. <code>detach_node</code>는 노드를 리스트에서 분리하지만 메모리를 해제하지 않아요. 이어 <code>insert_after</code>로 같은 노드를 재사용해요. 헤드에 닿으면 탐색을 멈추고 헤드 뒤에 넣을 수 있어요. 같은 <code>priority</code>는 엄격한 <code>&gt;</code> 비교를 쓰므로 앞선 노드의 순서가 보존돼요. 조교가 ‘삭제’라고 표현한 동작도 노드 자체의 해제가 아니라 연결의 분리와 재삽입이에요. (조교 Part 06, 시간 미제공)</p></div>
  <div class="sum" hidden><p class="sum-lead">현재 노드의 연결을 바꾸기 전에 다음 정렬 대상을 저장해요.</p><p class="panel-label">용어</p><dl class="terms"><dt>next_unsorted</dt><dd>이동 전에 기억해 둔 다음 미정렬 노드</dd><dt>position</dt><dd>현재 노드를 넣을 자리를 찾는 탐색 노드</dd></dl></div>
</article>
<article class="topic" id="s3-firstfit"><h3>3. 연속된 빈 공간에서 First-Fit 찾기</h3><div class="tags"><span class="tag date">1008 수업</span></div>
  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">빈 의자가 여러 곳에 나뉘어 있으면 긴 벤치가 필요한 손님은 앉지 못해요. 입구부터 살펴보고 처음 만나는 충분히 긴 벤치를 골라요.</p><figure class="figure"><svg id="fig-firstfit-gap" viewBox="0 0 360 75" role="img" aria-label="빈 자리 세 구간이 사람 자리를 사이에 두고 떨어져 있는 테두리 그림"><rect class="fig-accent" x="7" y="20" width="47" height="31"/><rect class="fig-ink" x="54" y="20" width="63" height="31"/><rect class="fig-accent" x="117" y="20" width="63" height="31"/><rect class="fig-ink" x="180" y="20" width="63" height="31"/><rect class="fig-accent" x="243" y="20" width="79" height="31"/><text class="fig-text" x="18" y="40">15</text><text class="fig-muted" x="74" y="40">사용</text><text class="fig-text" x="136" y="40">20</text><text class="fig-muted" x="200" y="40">사용</text><text class="fig-text" x="267" y="40">25</text></svg><figcaption>빈 자리가 나뉘어 있어 긴 자리 하나가 없어요.</figcaption></figure></div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p><b>First-Fit</b>은 리스트의 앞, 즉 낮은 주소부터 훑어 요청한 <code>size</code> 이상인 첫 <code>FREE_PID</code> 블록을 고르는 방식이에요. 빈 블록이 정확히 같으면 전체를 할당하고, 더 크면 할당 부분과 남는 빈 부분으로 분할해요.</p><p>과제 PDF p4의 빈 구간은 크기 <code>15</code>, <code>20</code>, <code>25</code>로 합계 60칸이에요. 그래도 연속된 최대 구간은 25칸이므로 <code>30</code>칸 요청은 실패해요. 총 빈칸은 충분하지만 연속 구간이 부족한 현상이 <b>외부 단편화(external fragmentation)</b>예요.</p><ol class="steps"><li>P3가 20칸을 요청하면 첫 15칸은 지나고 다음 20칸 전체를 받아요.</li><li>P4가 20칸을 요청하면 남은 구간 중 첫 충분한 25칸을 찾아요.</li><li>P4에 20칸을 할당하고 끝의 5칸은 빈 블록으로 남겨요. (과제 PDF p5–7)</li></ol></div>
  <div class="sum" hidden><p class="sum-lead">First-Fit은 앞에서부터 처음 만나는 충분히 큰 연속 빈 블록을 골라요.</p><p class="panel-label">용어</p><dl class="terms"><dt>First-Fit</dt><dd>앞에서부터 첫 적합 빈 블록을 고르는 방식</dd><dt>외부 단편화(external fragmentation)</dt><dd>빈칸의 합은 충분해도 연속된 빈 구간이 부족한 현상</dd></dl></div>
</article>
<article class="topic" id="s3-merge"><h3>4. 할당·분할·해제·병합 따라가기</h3><div class="tags"><span class="tag date">1008 수업</span></div>
  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">긴 자리를 조금만 빌려주고 남은 자리는 그대로 둬요. 빌린 자리를 돌려받으면 양옆의 빈 자리와 이어서 더 긴 자리로 만들어요.</p><figure class="figure"><svg id="fig-merge-space" viewBox="0 0 360 77" role="img" aria-label="세 개로 나뉜 테두리 빈 자리들이 아래에서 하나의 긴 테두리 자리로 합쳐진 모습"><rect class="fig-accent" x="10" y="9" width="98" height="27"/><rect class="fig-ink" x="108" y="9" width="100" height="27"/><rect class="fig-accent" x="208" y="9" width="142" height="27"/><text class="fig-text" x="42" y="28">빈 자리</text><text class="fig-text" x="135" y="28">돌려받음</text><text class="fig-text" x="253" y="28">빈 자리</text><rect class="fig-accent" x="10" y="47" width="340" height="27"/><text class="fig-text" x="148" y="66">긴 빈 자리</text></svg><figcaption>돌려받은 자리와 양옆 빈 자리가 이어져요.</figcaption></figure></div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p>과제의 <code>MemoryBlock</code>은 <code>start</code>(시작 주소), <code>size</code>(칸 수), <code>pid</code>(소유 프로세스), <code>prev</code>·<code>next</code>(이웃 블록)를 담아요. 실제 주소 구간은 <code>start</code>부터 <code>start + size - 1</code>까지예요. <code>FREE_PID</code>는 -1, <code>HEAD_PID</code>는 -2예요. 헤드 노드는 연결점이며 실제 메모리 블록으로 할당하거나 삭제하지 않아요. <code>merge_free_blocks</code>는 해제된 블록의 앞뒤가 빈 블록이면 인접 구간을 합쳐요.</p><p>다음 추적은 <b>과제 PDF p17의 <code>ALLOC 3 10</code></b>을 따르며 총 메모리는 100칸이에요.</p><ol class="steps"><li>처음: <code>[0–99] FREE</code>.</li><li><code>ALLOC 1 20</code>: <code>[0–19] P1 | [20–99] FREE</code>.</li><li><code>ALLOC 2 30</code>: <code>[0–19] P1 | [20–49] P2 | [50–99] FREE</code>.</li><li><code>ALLOC 3 10</code>: <code>[0–19] P1 | [20–49] P2 | [50–59] P3 | [60–99] FREE</code>.</li><li><code>FREE 2</code>: <code>[20–49] FREE</code>가 P1과 P3 사이에 생겨요.</li><li><code>FREE 1</code>: 앞의 빈 블록과 이어 <code>[0–49] FREE</code>가 돼요.</li><li><code>FREE 3</code>: 양옆의 빈 블록과 이어 <code>[0–99] FREE</code>가 돼요.</li></ol><p><small>조교 전사 Part 06(시간 미제공)은 P3 크기를 15칸으로 설명하지만 과제 PDF p17은 10칸이에요. 여기의 주소 계산은 PDF의 10칸만 적용했어요.</small></p></div>
  <div class="sum" hidden><p class="sum-lead">해제한 블록의 양옆이 비어 있으면 이어서 한 구간으로 만들어요.</p><p class="panel-label">용어</p><dl class="terms"><dt>merge_free_blocks</dt><dd>현재 빈 블록과 인접한 빈 블록을 합치는 함수</dd><dt>FREE_PID</dt><dd>빈 블록을 나타내는 값 -1</dd><dt>HEAD_PID</dt><dd>헤드 노드를 나타내는 값 -2</dd></dl></div>
</article>
<article class="topic" id="s3-requirements"><h3>5. 구현할 함수와 제출 조건</h3><div class="tags"><span class="tag date">1008 수업</span></div>
  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">빈 자리를 찾고 빌려주고 돌려받는 일을 나누어 맡아요. 한 일을 적은 종이와 실제로 만든 것도 함께 내요.</p><figure class="figure"><svg id="fig-assignment-flow" viewBox="0 0 360 76" role="img" aria-label="찾기, 빌려주기, 돌려받기, 설명하기의 네 테두리 칸이 차례로 이어진 그림"><rect class="fig-ink" x="5" y="17" width="72" height="38"/><rect class="fig-accent" x="98" y="17" width="72" height="38"/><rect class="fig-ink" x="191" y="17" width="72" height="38"/><rect class="fig-accent" x="284" y="17" width="72" height="38"/><text class="fig-text" x="23" y="41">찾기</text><text class="fig-text" x="110" y="41">빌려주기</text><text class="fig-text" x="203" y="41">돌려받기</text><text class="fig-text" x="296" y="41">설명하기</text><path class="fig-ink" d="M78 36 H95 M89 30 L95 36 L89 42 M171 36 H188 M182 30 L188 36 L182 42 M264 36 H281 M275 30 L281 36 L275 42"/></svg><figcaption>할 일을 나누고 결과까지 설명해요.</figcaption></figure></div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p>과제 2의 스켈레톤에서 학생이 채울 함수는 다섯 개예요. <code>find_first_fit</code>은 요청 크기 이상인 첫 빈 블록을, <code>find_process_block</code>은 PID의 블록을 찾아 없으면 <code>NULL</code>을 반환해요. <code>allocate_memory</code>는 중복 PID를 거절하고 First-Fit으로 할당·분할해요. <code>merge_free_blocks</code>는 이전·다음 빈 블록과 합쳐요. <code>release_memory</code>는 해당 PID의 블록을 빈 블록으로 바꾸고 병합해요.</p><p>성공·실패 반환은 <code>allocate_memory</code>와 <code>release_memory</code>에서 각각 1·0이에요. 과제 PDF p18의 실패 사례는 총 50칸에서 P1이 30칸을 쓴 뒤 다른 PID에 30칸을 요청한 경우, 없는 P7을 해제한 경우, 이미 할당된 P1에 다시 요청한 경우예요. 실패해도 리스트 상태를 유지해야 해요.</p><p>제공된 <code>FREE_PID</code>, <code>HEAD_PID</code>, <code>MAX_COMMANDS</code>, <code>COMMAND_LENGTH</code>, 구조체와 함수 형식은 수정하지 않아요. 양의 정수 입력을 전제로 하며 비양의 정수·실수의 별도 예외 처리는 요구하지 않아요. 헤드를 실제 블록으로 쓰거나 삭제하지 않고, 지정된 함수만 채우며 추가 함수를 만들지 않는 조건이에요. (과제 PDF p13, p19)</p><p>제출물은 <code>.c</code> 소스와 <b>PDF</b> 보고서예요. 마감은 과제 PDF p20 기준 <b>10월 28일에서 29일로 넘어가는 자정</b>이에요. 코드 분석은 제공 코드와 구현 코드를 모두 다루고 <b>2칼럼</b>으로 왼쪽에 코드, 오른쪽에 분석을 놓아요. 결과 화면 분석은 두 열이나 스크린샷 아래 설명 중 편한 형식으로 써도 된다고 조교가 정정했어요. PDF가 아닌 보고서는 PDF p20에서 보고서 미제출로 취급해요.</p><p>생성형 AI를 학습 참고로 쓰는 것은 허용되지만 제출 코드와 보고서는 본인이 직접 작성해야 해요. Mac에서 업로드한 C 파일의 한글이 깨지는 경우 보고서 마지막에 전체 소스를 덧붙여 달라는 것은 채점 편의를 위한 조교 요청이며 점수 요소는 아니에요. 조교는 시험 출제·채점에 관여하지 않아 시험 범위를 확답하지 않았어요. (조교 Part 07, 시간 미제공; 과제 PDF p20–21)</p></div>
  <div class="sum" hidden><p class="sum-lead">다섯 함수를 직접 구현하고 소스와 PDF 보고서를 기한 안에 제출해요.</p><p class="panel-label">용어</p><dl class="terms"><dt>find_first_fit</dt><dd>첫 적합 빈 블록을 찾는 함수</dd><dt>find_process_block</dt><dd>PID에 해당하는 블록을 찾는 함수</dd><dt>allocate_memory</dt><dd>메모리를 할당하고 필요하면 분할하는 함수</dd><dt>release_memory</dt><dd>PID의 메모리를 반납하고 병합하는 함수</dd></dl></div>

    (function () {

        if ((t === 'dark') === sysDark.matches) { delete root.dataset.theme; try { localStorage.removeItem(KEY); } catch (e) {} }
        else { root.dataset.theme = t; try { localStorage.setItem(KEY, t); } catch (e) { /* 저장 불가: 이번 방문에만 유지 */ } }

      });

      window.addEventListener('storage', (e) => {
        if (e.key !== KEY) return;

  <script id="panels-ui">
    (function () {
      const body = document.body;
      const layout = document.querySelector('.layout');
      const kind = body.dataset.panels;
      const panels = { left: document.getElementById('panel-left'), right: document.getElementById('panel-right') };
      const toggles = { left: document.getElementById('toggle-left'), right: document.getElementById('toggle-right') };
      const scrim = document.getElementById('panel-scrim');
      const blockers = [document.querySelector('.topbar'), document.querySelector('.content'), document.querySelector('.pager')];
      const wideMq = matchMedia('(min-width: 1024px)');
      const roomyMq = matchMedia('(min-width: 1280px)');
      const store = {
        get(k, d) { try { const v = localStorage.getItem(k); return v == null ? d : JSON.parse(v); } catch (e) { return d; } },
        set(k, v) { try { localStorage.setItem(k, JSON.stringify(v)); } catch (e) { /* 저장 불가: 이번 방문에만 유지 */ } }
      };
      const PREF = 'od-panels:' + kind;
      // 팩마다 문제·토픽 id가 p1, s1-…로 겹치므로 진행 기록은 기간별로 나눈다
      const RANGE = body.dataset.range || '';
      const ICON_TODO = '<svg viewBox="0 0 24 24"><circle cx="12" cy="12" r="9"/></svg>';
      const ICON_DONE = '<svg viewBox="0 0 24 24"><circle cx="12" cy="12" r="9"/><path d="M8 12.5l2.8 2.8L16 10"/></svg>';
      let overlay = null;

      // ---------- 열고 닫기 ----------
      function docked() {
        const pref = store.get(PREF, {});
        return { left: pref.left ?? true, right: pref.right ?? roomyMq.matches };
      }
      function sync() {
        const wide = wideMq.matches;
        const d = docked();
        ['left', 'right'].forEach((side) => {
          const open = wide ? d[side] : overlay === side;
          const p = panels[side];
          layout.dataset[side] = open ? 'open' : 'closed';
          p.classList.toggle('is-open', !wide && open);
          p.inert = !open;
          if (!wide && open) { p.setAttribute('role', 'dialog'); p.setAttribute('aria-modal', 'true'); }
          else { p.removeAttribute('role'); p.removeAttribute('aria-modal'); }
          toggles[side].setAttribute('aria-expanded', String(open));
        });
        const drawer = !wide && overlay !== null;
        scrim.classList.toggle('is-on', drawer);
        body.classList.toggle('drawer-open', drawer);
        blockers.forEach((el) => { el.inert = drawer; });
      }
      function openDrawer(side) {
        overlay = side;
        sync();
        requestAnimationFrame(() => panels[side].querySelector('[data-panel-close]').focus());
      }
      function closeDrawer(refocus) {
        if (overlay === null) return;
        const side = overlay;
        overlay = null;
        sync();
        if (refocus) toggles[side].focus();
      }
      function toggle(side) {
        if (wideMq.matches) {
          const d = docked();
          d[side] = !d[side];
          store.set(PREF, d);
          sync();
          if (d[side]) { const p = panels[side]; p.classList.remove('is-shown'); void p.offsetWidth; p.classList.add('is-shown'); }
        } else if (overlay === side) closeDrawer(true);
        else openDrawer(side);
      }

      toggles.left.addEventListener('click', () => toggle('left'));
      toggles.right.addEventListener('click', () => toggle('right'));
      scrim.addEventListener('click', () => closeDrawer(true));
      document.querySelectorAll('[data-panel-close]').forEach((b) => b.addEventListener('click', () => closeDrawer(true)));
      panels.left.addEventListener('click', (e) => { if (e.target.closest('.toc a')) closeDrawer(false); });
      document.addEventListener('keydown', (e) => { if (e.key === 'Escape' && overlay !== null) { e.preventDefault(); closeDrawer(true); } });

      // ---------- 패널 너비: 기본은 화면 폭에 맞춰 자동, 경계를 끌면 직접 조절 ----------
      const WIDTH = { left: { min: 220, max: 480, prop: '--panel-l-user' }, right: { min: 280, max: 720, prop: '--panel-r-user' } };
      function applyWidths() {
        const w = store.get(PREF + ':w', {});
        ['left', 'right'].forEach((side) => {
          if (w[side]) layout.style.setProperty(WIDTH[side].prop, w[side] + 'px');
          else layout.style.removeProperty(WIDTH[side].prop);
        });
      }
      function maxFor(side) {
        const other = side === 'left' ? panels.right : panels.left;
        const otherW = layout.dataset[side === 'left' ? 'right' : 'left'] === 'open' ? other.getBoundingClientRect().width : 0;
        return Math.max(WIDTH[side].min, Math.min(WIDTH[side].max, window.innerWidth - otherW - 400));
      }
      function setWidth(side, px, save) {
        const v = Math.round(Math.min(Math.max(px, WIDTH[side].min), maxFor(side)));
        layout.style.setProperty(WIDTH[side].prop, v + 'px');
        panels[side].querySelector('.panel-resize').setAttribute('aria-valuenow', String(v));
        if (save) { const w = store.get(PREF + ':w', {}); w[side] = v; store.set(PREF + ':w', w); }
      }
      function resetWidth(side) {
        const w = store.get(PREF + ':w', {});
        delete w[side];
        store.set(PREF + ':w', w);
        layout.style.removeProperty(WIDTH[side].prop);
      }
      document.querySelectorAll('.panel-resize').forEach((handle) => {
        const side = handle.dataset.side;
        const dir = side === 'left' ? 1 : -1;
        handle.setAttribute('aria-valuemin', String(WIDTH[side].min));
        handle.setAttribute('aria-valuemax', String(WIDTH[side].max));
        handle.addEventListener('pointerdown', (e) => {
          if (!wideMq.matches || e.button !== 0) return;
          e.preventDefault();
          const startX = e.clientX;
          const startW = panels[side].getBoundingClientRect().width;
          handle.setPointerCapture(e.pointerId);
          body.classList.add('is-resizing');
          const move = (ev) => setWidth(side, startW + dir * (ev.clientX - startX), false);
          const up = () => {
            handle.removeEventListener('pointermove', move);
            handle.removeEventListener('pointerup', up);
            handle.removeEventListener('pointercancel', up);
            body.classList.remove('is-resizing');
            setWidth(side, panels[side].getBoundingClientRect().width, true);
          };
          handle.addEventListener('pointermove', move);
          handle.addEventListener('pointerup', up);
          handle.addEventListener('pointercancel', up);
        });
        handle.addEventListener('dblclick', () => resetWidth(side));
        handle.addEventListener('keydown', (e) => {
          const step = e.shiftKey ? 64 : 16;
          const cur = panels[side].getBoundingClientRect().width;
          if (e.key === 'ArrowLeft' || e.key === 'ArrowRight') {
            e.preventDefault();
            e.stopPropagation();
            setWidth(side, cur + (e.key === 'ArrowRight' ? step : -step) * dir, true);
          } else if (e.key === 'Home') { e.preventDefault(); resetWidth(side); }
        });
      });
      applyWidths();
      const onMq = () => { overlay = null; sync(); };
      wideMq.addEventListener('change', onMq);
      roomyMq.addEventListener('change', onMq);

      // ---------- 목차의 진행 표시 ----------
      const progressN = document.getElementById('progress-n');
      const progressBar = document.getElementById('progress-bar');
      const progressTotal = document.getElementById('progress-total');
      function markToc(done, total, doneLabel) {
        panels.left.querySelectorAll('.toc-list a').forEach((a) => {

          if (!mark) {
            mark = document.createElement('span');
            mark.className = 'toc-mark';
            mark.setAttribute('aria-hidden', 'true');
            const state = document.createElement('span');
            state.className = 'sr-only toc-state';
            a.append(mark, state);
          }
          const isDone = done.has(id);
          mark.classList.toggle('is-done', isDone);
          mark.innerHTML = isDone ? ICON_DONE : ICON_TODO;
          a.querySelector('.toc-state').textContent = isDone ? ' (' + doneLabel + ')' : '';
        });
        progressN.textContent = String(done.size);
        progressTotal.textContent = String(total);
        progressBar.style.transform = 'scaleX(' + (total ? done.size / total : 0) + ')';
      }
      function revealCurrent() {
        const link = panels.left.querySelector('.toc-list a[aria-current="true"]');
        if (link && layout.dataset.left === 'open') link.scrollIntoView({ block: 'nearest' });
      }

      // ---------- 복습문제: 오른쪽 = 원문 · 힌트 · 풀이 ----------
      function setupReview() {

  <script id="pager-ui">
    (function () {
      const root = document.documentElement;
      const main = document.querySelector('main');
      const hero = main.querySelector('.hero');
      const screens = [hero].concat(Array.from(main.querySelectorAll(document.body.dataset.screens)));
      if (screens.length < 2) { root.classList.remove('js'); return; }
      screens.forEach((s) => s.classList.add('screen'));

      const last = screens.length - 1;
      const prevBtn = document.getElementById('pager-prev');
      const nextBtn = document.getElementById('pager-next');
      const count = document.getElementById('pager-count');
      const bar = document.getElementById('pager-bar');
      const status = document.getElementById('pager-status');
      const toc = document.querySelector('#panel-left .toc');
      const scroller = document.querySelector('.content');
      const titleOf = (s) => ((s.querySelector('h3') || s.querySelector('h1') || {}).textContent || '').trim();
      let cur = -1;

      // 목차: 섹션 링크 아래에 화면(토픽·카드) 목록을 붙인다
      const tocLinks = [];
      Array.from(toc.querySelectorAll(':scope > a')).forEach((a) => {
        const sec = document.getElementById(decodeURIComponent(a.getAttribute('href').slice(1)));
        const group = document.createElement('div');
        group.className = 'toc-group';
        a.replaceWith(group);
        group.appendChild(a);
        if (!sec) return;
        const list = document.createElement('ol');
        list.className = 'toc-list';
        screens.forEach((s, i) => {
          if (!sec.contains(s)) return;
          const li = document.createElement('li');
          const link = document.createElement('a');
          link.href = '#' + s.id;
          link.innerHTML = '<span class="toc-title"></span>';
          link.firstChild.textContent = titleOf(s);
          li.appendChild(link);
          list.appendChild(li);
          tocLinks[i] = link;
        });
        group.appendChild(list);
      });

      function indexFor(hash) {
        const id = decodeURIComponent((hash || '').replace(/^#/, ''));
        const el = id && document.getElementById(id);
        if (!el || !main.contains(el)) return { i: 0 };
        const i = screens.findIndex((s) => s.contains(el) || el.contains(s));
        return { i: Math.max(i, 0), target: i >= 0 && screens[i].contains(el) && screens[i] !== el ? el : null };
      }

      function render(i, target) {
        const dir = cur < 0 ? '' : i > cur ? 'enter-next' : 'enter-prev';
        if (i !== cur) {
          if (cur >= 0) screens[cur].classList.remove('is-current', 'enter-next', 'enter-prev');
          main.querySelectorAll(':scope > section.is-on').forEach((sec) => sec.classList.remove('is-on'));
          const s = screens[i];
          const sec = s.closest('section');
          if (sec) sec.classList.add('is-on');
          s.classList.add('is-current');
          if (dir) { s.classList.remove('enter-next', 'enter-prev'); void s.offsetWidth; s.classList.add(dir); }
          cur = i;
          document.body.classList.toggle('at-end', i === last);
          prevBtn.disabled = i === 0;
          nextBtn.textContent = i === 0 ? '시작하기' : i === last ? '처음으로' : '다음';
          count.textContent = i === 0 ? '' : i + ' / ' + last;
          bar.style.transform = 'scaleX(' + (i / last) + ')';
          status.textContent = i === 0 ? titleOf(s) : i + ' / ' + last + ', ' + titleOf(s);
          tocLinks.forEach((link, k) => link && link.setAttribute('aria-current', String(k === i)));
          document.dispatchEvent(new CustomEvent('od:screen', { detail: { index: i, screen: s } }));
        }
        if (target) target.scrollIntoView({ block: 'start' });
        else scroller.scrollTo(0, 0);
      }

      function go(i) {
        i = Math.min(Math.max(i, 0), last);
        if (i === cur) return;
        const url = i === 0 ? location.pathname + location.search : '#' + screens[i].id;
        history.pushState(null, '', url);
        render(i);
      }

      prevBtn.addEventListener('click', () => go(cur - 1));
      nextBtn.addEventListener('click', () => go(cur === last ? 0 : cur + 1));
      const fromUrl = () => { const r = indexFor(location.hash); render(r.i, r.target); };
      window.addEventListener('hashchange', fromUrl);
      window.addEventListener('popstate', fromUrl);

      document.addEventListener('keydown', (e) => {
        if (e.defaultPrevented || e.altKey || e.ctrlKey || e.metaKey || document.body.classList.contains('drawer-open')) return;
        if (e.target.closest('input, select, textarea, [contenteditable="true"]')) return;
        if (e.key === 'ArrowRight') { e.preventDefault(); go(cur + 1); }
        if (e.key === 'ArrowLeft') { e.preventDefault(); go(cur - 1); }
      });

      // 좌우로 밀어서 넘기기 (가로로 스크롤되는 영역은 제외)
      let sx = 0, sy = 0, skip = true;
      main.addEventListener('touchstart', (e) => {
        const t = e.touches[0];
        sx = t.clientX; sy = t.clientY;
        skip = e.touches.length > 1 || Boolean(e.target.closest('.widget, .katex-display, .table-wrap, pre, svg, input, details'));
      }, { passive: true });
      main.addEventListener('touchend', (e) => {
        if (skip) return;
        const t = e.changedTouches[0];
        const dx = t.clientX - sx, dy = t.clientY - sy;
        if (Math.abs(dx) > 64 && Math.abs(dx) > 2 * Math.abs(dy)) go(cur + (dx < 0 ? 1 : -1));
      }, { passive: true });

      fromUrl();
    })();
  </script>

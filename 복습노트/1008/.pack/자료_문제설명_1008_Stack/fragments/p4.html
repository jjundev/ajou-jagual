문제를 내 말로 읽어요

위치 정수 position을 받아 노드를 삽입하는 add 함수가 get_node_at(list, position - 1)로 선행 노드를 찾아 insert_node를 재사용하는 원리와 시간 복잡도를 묻는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

‘get_node_at으로 구한 선행 노드로 insert_node를 호출한다’는 단서는 인터페이스 어댑터(adapter)를 뜻해요. 사용자는 위치 position을 주고 insert_node는 선행 노드 주소 p를 원하므로 position - 1 위치 탐색으로 둘을 이어 줘요.

종이에 쓰는 첫 줄

position = 2 -> position - 1 = 1 -> 선행 노드 p = B를 먼저 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) position = 2는 현재 C의 자리이므로 바로 앞인 인덱스 1의 B를 찾아 insert_node(&(list->head), B, N)을 호출하고, 결과는 A -> B -> N -> C(length = 4)가 돼요. position = 0이면 get_node_at(list, -1) = NULL이므로 insert_node(&(list->head), NULL, N)을 호출해 N이 새 head가 돼요.

(b) 만약 get_node_at(list, position)을 호출하면 position = 2에서 C가 선행 노드가 되어 C 뒤에 들어가므로 한 칸 뒤로 밀려요. length 필드를 유지하므로 길이 조회는 O(1)이고, 선행 노드를 찾는 탐색 때문에 삽입의 최악 시간 복잡도는 O(n)(링크 갱신 자체는 O(1))이에요.

완성 답과 검산

(a) 결과 A -> B -> N -> C의 인덱스를 다시 세면 A:0, B:1, N:2, C:3이어서 요청한 position = 2에 N이 정확히 놓였어요.

(b) 잘못된 선행 노드 C 뒤에 넣으면 N의 인덱스가 3이 되어 한 칸 늦어진다는 사실이 바로 확인돼요.

이 문제에서 조심할 점

position번째 노드를 선행 노드라고 혼동하지 않아요. head 필드의 주소와 head가 가리키는 첫 노드의 주소도 구분해요.

설명을 닫고 다시 해 봐요

  1. position = 2와 position = 0에서 get_node_at(list, position - 1)의 반환값을 각각 구해요.
  2. insert_node에 전달되는 세 인자와 결과 체인을 적어요.
  3. 길이 조회 비용과 선행 노드 탐색을 포함한 삽입 비용을 비교해요.

떠올릴 개념·공식

위치 position 삽입의 선행 노드는 get_node_at(list, position - 1)이며, position = 0일 때는 NULL을 반환해 맨 앞 삽입으로 연결해요.

첫 줄

position = 2 -> position - 1 = 1 -> 선행 노드 p = B를 먼저 적어요.

핵심 답

(a) position = 2: p = B, A -> B -> N -> C(length = 4); position = 0: p = NULL, N이 새 head (b) position 그대로 전달 시 한 칸 뒤 삽입, 길이 조회 O(1), 탐색 포함 삽입 O(n)

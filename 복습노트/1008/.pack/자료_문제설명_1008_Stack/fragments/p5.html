문제를 내 말로 읽어요

main -> sub1 -> sub2 중첩 호출에서 시스템 스택에 쌓이는 호출 정보와 복귀 순서를 추적하고, 배열 스택의 포화·공백 경계 검사를 확인하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

‘호출했다가 돌아온다’는 말에서 시스템 스택(system stack)의 활성 레코드(activation record)와 후입선출(LIFO) 규칙을 떠올려요. 배열 스택에서는 인덱스 변경이나 배열 접근 전에 반드시 is_full·is_empty를 먼저 검사해야 해요.

종이에 쓰는 첫 줄

바닥: main(복귀 위치, i = 3) / 그 위: sub1(복귀 위치, a = 3, j = 5)을 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) main이 sub1을 부르고 sub1이 sub2를 부르므로 스택 아래부터 main(복귀 위치, i = 3), 그 위에 sub1(복귀 위치, a = 3, j = 5)이 쌓여요. sub2가 끝나면 맨 위의 sub1로, sub1이 끝나면 main으로 복귀해요. 지역 변수만 저장하면 돌아갈 코드 위치를 알 수 없으며, 가장 최근 호출·작업부터 되돌리는 LIFO 규칙이 함수 복귀와 undo에 공통으로 쓰여요.

(b) 용량 M = 3인 배열 스택에서 top = 2일 때의 push는 is_full을 먼저 검사해 거부해야 하고, top = -1일 때의 pop은 is_empty를 먼저 검사해 거부해야 해요. 먼저 검사하지 않으면 배열 범위(0..2) 밖 메모리에 접근하거나 실패한 연산이 기존 스택 상태를 훼손하기 때문이에요.

완성 답과 검산

(a) 호출 순서 main -> sub1 -> sub2와 복귀 순서 sub2 -> sub1 -> main이 정확히 역순(LIFO)을 이루어요.

(b) 용량 3의 유효 인덱스는 0..2이므로 top = 2에서 증가하면 3, top = -1에서 읽으면 -1이 되어 범위 밖임이 확인돼요.

이 문제에서 조심할 점

복귀 위치를 배열 인덱스나 실제 기계 주소로 계산하지 않아요. 이 문제는 개념 모형의 복귀 관계를 물어요.

설명을 닫고 다시 해 봐요

  1. sub2 실행 시점에 스택 아래부터 쌓인 호출 정보를 적어요.
  2. 복귀 순서와 LIFO·undo의 공통점을 정리해요.
  3. top = 2에서의 push와 top = -1에서의 pop이 먼저 검사할 조건을 적어요.

떠올릴 개념·공식

시스템 스택은 복귀 위치와 지역 상태를 함께 저장하며 가장 최근 호출부터 복귀(LIFO)해요.

첫 줄

바닥: main(복귀 위치, i = 3) / 그 위: sub1(복귀 위치, a = 3, j = 5)을 적어요.

핵심 답

(a) main 위에 sub1 저장, 복귀는 sub2 -> sub1 -> main(LIFO, undo와 동일) (b) top = 2 push는 is_full, top = -1 pop은 is_empty 선검사 및 상태 보존

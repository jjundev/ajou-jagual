문제를 내 말로 읽어요

초기 top = -1인 용량 3 배열 스택에서 push, peek, pop 연산 열을 단계별로 추적하고 peek과 pop의 차이를 설명하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “push·pop·peek의 순서 복원”이에요. top = -1은 공백 상태이고, push는 먼저 top을 1 올린 뒤 저장하며, pop은 현재 stack[top]을 꺼낸 뒤 top을 1 줄이고, peek은 top을 바꾸지 않고 읽기만 해요.

종이에 적을 첫 줄

초기 상태 top = -1, 빈 스택 []로 상태 표를 시작해요.

왜 이렇게 푸는지 함께 따라가요

(a) push(5)로 top = 0([5]), push(8)로 top = 1([5, 8])이 돼요. peek()은 8을 반환하고 top = 1을 유지해요. 첫 pop()은 8을 반환하고 top = 0([5])으로 줄여요. push(2)로 top = 1([5, 2])이 된 뒤 마지막 pop()은 2를 반환하고 top = 0이 되어 {5}가 남아요.

(b) peek()은 원소를 제거하지 않고 맨 위 값만 확인하므로 top을 변경하지 않아요. pop()에서 공백 검사 없이 top을 먼저 줄여 읽으면 꺼낼 원소가 아닌 그 아래 원소를 읽게 되고, 빈 스택(top == -1)에서는 배열 범위 밖 접근이 일어나요.

완성 답과 검산

(a) 총 push 3회, pop 2회가 실행되었으므로 최종 원소 개수는 1개({5})이고 마지막 top = 0과 일치해요.

(b) top = 0(원소 1개)일 때 top을 먼저 줄이면 stack[-1]을 읽게 되어 잘못된 접근임이 바로 확인돼요.

이 문제에서 조심할 점

peek에도 top--를 적용하면 단순 조회가 삭제로 바뀌어요.

설명을 닫고 다시 해 봐요

  1. 6개 연산을 순서대로 적고 매 단계의 top과 반환값을 채워요.
  2. peek()과 pop() 실행 후 top의 차이를 비교해요.
  3. top 감소와 배열 읽기의 순서가 바뀔 때 생기는 오류를 확인해요.

첫 줄

초기 상태 top = -1, 빈 스택 []로 상태 표를 시작해요.

떠올릴 개념·공식

push는 선증가 후 저장, pop은 선읽기 후 감소, peek은 top 유지예요.

검산

(a) top: 0, 1, 1, 0, 1, 0, 반환 8, 8, 2, 남은 스택 {5} (b) peek은 top 유지, 선감소 및 미검사는 범위 밖 접근 유발

문제를 내 말로 읽어요

길이 1인 리스트에서 첫 노드(pos = 0)를 삭제할 때 래퍼 함수가 잘못된 removed 인자를 넘겨 메모리 누수가 발생하는 원인을 찾고 삼항 연산자 식을 고치는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “ListType 삭제 래퍼의 메모리 누수 찾기”예요. pos = 0이면 pos - 1 = -1이므로 get_node_at은 NULL을 반환하고, 이때 실제 삭제되어 free되어야 할 대상은 호출 시점의 첫 노드인 list->head예요.

종이에 적을 첫 줄

pos = 0일 때 p = get_node_at(list, -1) = NULL을 먼저 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) pos = 0이면 p = NULL이므로 (p != NULL) ? p->link : NULL의 결과로 removed = NULL이 넘어가요. remove_node는 *phead를 다음 노드(NULL)로 바꾸고 래퍼는 list->length를 0으로 줄이지만, free(NULL)은 아무 메모리도 해제하지 않아 원래 첫 노드 A가 누수돼요.

(b) p == NULL일 때 해제할 노드는 *phead가 바뀌기 전의 첫 노드 list->head이므로, 세 번째 인자를 (p != NULL) ? p->link : list->head로 고쳐야 해요.

완성 답과 검산

(a) 수정 전 식에 p = NULL을 대입하면 removed = NULL이 되어 free(NULL)이 실행되고 노드 A의 주소를 잃어버림을 확인할 수 있어요.

(b) 수정 후 식에 p = NULL을 대입하면 removed = list->head(A)가 전달되어 *phead 갱신 뒤 free(A)가 정상 실행돼요.

이 문제에서 조심할 점

이 문제는 래퍼 코드의 결함을 찾는 문제예요. 코드를 몰래 고쳐 쓰거나 누수를 정상 동작으로 승인하지 않아요.

설명을 닫고 다시 해 봐요

  1. pos = 0일 때 get_node_at(list, pos - 1)의 반환값을 구해요.
  2. remove_node 내부에서 *phead 갱신과 free(removed)가 어떻게 실행되는지 추적해요.
  3. 삼항 연산자의 거짓 분기를 올바른 노드 포인터로 고쳐 적어요.

첫 줄

pos = 0일 때 p = get_node_at(list, -1) = NULL을 먼저 적어요.

떠올릴 개념·공식

선행 노드 p == NULL이면 삭제할 노드는 list->head예요.

검산

(a) p = NULL, removed = NULL로 첫 노드 A 누수 (b) (p != NULL) ? p->link : list->head

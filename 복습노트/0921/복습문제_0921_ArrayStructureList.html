P6. 하노이 코드의 매개변수 역할

강의 예제 기반 자체 출제 S2 p19

n >= 1개의 원판을 막대 from에서 보조 막대 tmp를 이용해 목표 막대 to로 옮기는 순환 함수예요.

void hanoi_tower(int n, char from, char tmp, char to)
{
    if(n==1) printf("원판1을%c에서%c으로옮긴다.\n",from,to);
    else {
        hanoi_tower(n-1,from,to,tmp);
        printf("원판%d을%c에서%c으로옮긴다.\n",n,from,to);
        hanoi_tower(n-1,tmp,from,to);
    }
}
  1. (a) hanoi_tower(3, 'A', 'B', 'C')를 호출했을 때 출력되는 원판 이동 7회를 순서대로 원판번호:출발→도착 형식으로 쓰세요.
  2. (b) 첫 번째 순환 호출 hanoi_tower(n-1, from, to, tmp)에서 to와 tmp의 인자 순서가 바뀌는 이유와, 최소 이동 횟수의 점화식 $T(n)$(기저 조건 T(1) 포함) 및 T(3) 값을 쓰세요.
강의 예제 보기

S2 p19 · Software_2_Recursion.pdf. 강의 코드의 해당 연산을 발췌해 들여쓰기를 정리했습니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

        printf("원판%d을%c에서%c으로옮긴다.\n",n,from,to);

    }
}
힌트 보기

가장 큰 원판을 A에서 C로 옮기기 전에 위의 2개를 B로 옮겨야 해요. 그래서 첫 호출의 도착 막대는 tmp(B)이고 보조 막대는 to(C)가 돼요.

풀이 보기
  1. (a) hanoi_tower(2, 'A', 'C', 'B')가 먼저 1:A→C, 2:A→B, 1:C→B를 출력해요. 이어서 원판 3을 옮기는 3:A→C를 출력한 뒤, hanoi_tower(2, 'B', 'A', 'C')가 1:B→A, 2:B→C, 1:A→C를 출력해요.
  2. (b) 가장 큰 원판 n을 from에서 to로 옮기려면 위의 n-1개를 먼저 보조 막대 tmp로 치워야 하므로, 첫 순환 호출에서는 tmp가 도착 막대, to가 보조 막대 역할을 맡아요. 위 n-1개 이동, 가장 큰 원판 1회, 다시 n-1개 이동이 필요하므로 T(1) = 1, T(n) = 2T(n-1) + 1 = 2^n - 1이고 T(3) = 7이에요.

정답: (a) 1:A→C, 2:A→B, 1:C→B, 3:A→C, 1:B→A, 2:B→C, 1:A→C (b) 가장 큰 원판을 to로 옮기기 전에 위 n-1개를 보조 막대 tmp로 옮겨야 하므로 tmp가 도착 막대, to가 보조 막대가 된다. T(1)=1, T(n)=2T(n-1)+1(일반식 2^n-1), T(3)=7.

from, tmp, to는 고정된 막대 이름이 아니라 현재 호출에서 맡은 역할이에요.

구조체 정의 본문 안에서는 아직 typedef 별칭 ListNode가 완성되기 전이므로 struct ListNode * 태그로 자기 자신에 대한 포인터를 선언해요.

풀이 보기
  1. (a) 구조체 정의 안에서는 태그를 써서 struct ListNode *link;로 선언해요. 포인터 p가 유효한 노드를 가리킬 때 화살표 연산자 ->로 데이터 필드는 p->data, 다음 노드 주소는 p->link로 접근해요.
  2. (b) 포인터는 고정된 크기의 주소만 저장하므로 구조체 크기가 유한하게 정해지지만, 같은 구조체를 값 멤버(struct ListNode link;)로 포함하면 자기 자신의 크기를 무한히 중첩해 포함해야 하므로 구조체 크기를 결정할 수 없어요.

정답: (a) struct ListNode *link;, 데이터 p->data, 다음 노드 p->link (b) 같은 구조체를 값으로 포함하면 자신의 크기를 무한히 포함해야 하므로 크기를 완성할 수 없다.

포인터 멤버를 선언했다고 해서 다음 노드가 자동으로 할당되지는 않아요.

P9. 배열 ADT와 행 우선 주소 계산

강의 예제 기반 자체 출제 S3 p3

배열 ADT는 <인덱스, 요소> 쌍의 집합을 객체로 정의하고 create(size), retrieve(A, i), store(A, i, item) 연산을 제공해요. C의 2차원 배열은 메모리에 행 우선(row-major) 순서로 연속 배치돼요.

int A[3][4]; /* 시작 주소 base = 1000, sizeof(int) = 4 */
  1. (a) 배열 ADT의 객체를 쓰고, create(6), store(A, 2, 7), retrieve(A, 2)가 각각 수행하는 일을 설명하세요.
  2. (b) 시작 주소가 1000이고 sizeof(int) == 4일 때 int A[3][4]에서 A[2][1]의 바이트 주소를 구하고, 인덱스 (2, 1)이 유효 범위 안에 있는지 확인하세요.
강의 예제 보기

S3 p3 · 추가 근거 p4,5 · Software_3_ArrayStructureList.pdf. 강의의 개념·그림·코드 연산을 바탕으로 조건과 질문을 새로 작성한 자체 출제예요. 제시 코드는 있는 경우 학습 확인용 자체 코드이며 강의 원문 발췌가 아니에요. 질문·입력 조건·검산은 자체 작성했어요.

힌트 보기

행 우선 배치에서 A[2][1] 앞의 원소 수는 2 × 4 + 1이에요.

풀이 보기
  1. (a) 배열 ADT의 객체는 <인덱스, 요소> 쌍의 집합이에요. create(6)은 6개 요소를 담는 배열을 생성하고, store(A, 2, 7)은 인덱스 2 위치에 값 7을 저장하며, retrieve(A, 2)는 인덱스 2 위치의 값 7을 반환해요.
  2. (b) 행 우선 배열 A[3][4]에서 한 행은 원소 4개이므로 A[2][1] 앞에는 앞선 두 행 2 × 4 = 8개와 현재 행 앞 1개를 합쳐 9개 원소가 있어요. 따라서 주소는 1000 + 9 × 4 = 1036이고, 0 <= 2 < 3, 0 <= 1 < 4이므로 유효한 인덱스예요.

정답: (a) 객체는 인덱스와 요소 쌍의 집합이며, create(6)은 6개 요소의 배열 생성, store는 2번 위치에 7 저장, retrieve는 그 위치의 7 반환이다. (b) C 행 우선 배열 A[2][1] 앞에는 2×4+1=9개 원소가 있어 주소는 1000+9×4=1036이며, 0<=2<3, 0<=1<4로 유효하다.

행 번호에 행 수 3을 곱하지 않고 한 행의 열 수 4를 곱해요. 범위를 벗어난 인덱스에 주소 공식을 적용해 유효한 접근이라고 하지 않아요.

P10. 두 표현의 다항식 덧셈과 남은 항 처리

강의 예제 기반 자체 출제 S3 p11

다항식 $A = 8x^3 + 7x + 1$과 $B = 10x^3 + 3x^2 + 1$을 두 가지 배열 표현으로 더해요. 방식 ①(가)은 최고차수 degree부터 상수항까지 모든 계수를 내림차순 배열 coef에 저장하고, 방식 ②(나)는 0이 아닌 항만 (coef, expon) 쌍 배열 terms에 내림차순으로 저장해요.

/* ① 모든 차수 배열 덧셈 루프 (초기 Apos=Bpos=Cpos=0, degree_a=A.degree, degree_b=B.degree) */
while( Apos<=A.degree && Bpos<=B.degree ){
    if( degree_a > degree_b ){ C.coef[Cpos++] = A.coef[Apos++]; degree_a--; }
    else if( degree_a == degree_b ){ C.coef[Cpos++] = A.coef[Apos++] + B.coef[Bpos++]; degree_a--; degree_b--; }
    else { C.coef[Cpos++] = B.coef[Bpos++]; degree_b--; }
}
/* ② 희소 항 배열 덧셈 루프 (terms[As..Ae]는 A, terms[Bs..Be]는 B) */
while( As <= Ae && Bs <= Be )
    switch(compare(terms[As].expon, terms[Bs].expon)){
    case '>': attach(terms[As].coef, terms[As].expon); As++; break;
    case '=': tempcoef = terms[As].coef + terms[Bs].coef;
              if( tempcoef ) attach(tempcoef, terms[As].expon);
              As++; Bs++; break;
    case '<': attach(terms[Bs].coef, terms[Bs].expon); Bs++; break;
    }
  1. (a) 방식 ①로 더한 결과 계수 배열 C.coef를 내림차순으로 쓰고, 루프 ①에서 차수가 큰 쪽 항만 C로 옮길 때 다른 쪽 인덱스는 그대로 두는 이유와 최고차수 $D$에 대한 시간 복잡도를 쓰세요.
  2. (b) 방식 ②의 루프 ②로 $A$와 $B$를 더할 때 매 비교 단계의 compare 결과·attach되는 (coef, expon) 쌍·전진 칸수(As, Bs)를 순서대로 쓰고, 한쪽 종료 후 남은 항 처리·동차항 합이 0일 때 처리·두 입력 항 수 $m, n$에 대한 시간 복잡도를 설명하세요.
강의 예제 보기

S3 p11 · 추가 근거 p7,8,9,10 · Software_3_ArrayStructureList.pdf. 강의의 개념·그림·코드 연산을 바탕으로 조건과 질문을 새로 작성한 자체 출제예요. 문제의 두 덧셈 루프는 S3 p8(①)과 p11(②)의 강의 코드를 발췌해 들여쓰기를 정리하고 설명 주석을 덧붙인 것이에요. 질문·입력 조건·검산은 자체 작성했어요.

힌트 보기

방식 ①에서 A의 계수는 [8, 0, 7, 1], B의 계수는 [10, 3, 0, 1]이고, 방식 ②에서 A는 [(8, 3), (7, 1), (1, 0)], B는 [(10, 3), (3, 2), (1, 0)]이에요.

풀이 보기
  1. (a) 같은 차수끼리 맞춘 계수 배열 [8, 0, 7, 1]과 [10, 3, 0, 1]을 더하면 내림차순 결과 계수는 [18, 3, 7, 2]($18x^3 + 3x^2 + 7x + 2$)예요. 루프 ①에서 차수가 높은 쪽 항만 출력했을 때 다른 쪽의 현재 항은 아직 비교·합산되지 않았으므로 인덱스를 유지해요. 배열 길이에 비례하므로 시간 복잡도는 O(D+1)이에요.
  2. (b) 루프 ②는 네 번 비교해요: 차수 3과 3은 '='라서 (18, 3)을 붙이고 As·Bs가 1·1칸 전진, 1과 2는 '<'라서 (3, 2)를 붙이고 1·2칸, 1과 0은 '>'라서 (7, 1)을 붙이고 2·2칸, 0과 0은 '='라서 (2, 0)을 붙이고 3·3칸 전진해 함께 끝나요. 한쪽이 먼저 끝나면 다른 쪽 남은 항을 그대로 복사하고, 동차항 합 tempcoef가 0이면 저장만 건너뛰고 양쪽 인덱스를 전진해요. 각 항을 한 번씩 지나가므로 시간 복잡도는 O(m+n)이에요.

정답: (a) 결과는 18x^3+3x^2+7x+2, 내림차순 계수 [18,3,7,2]이며, 높은 차수만 출력한 경우 다른 입력의 현재 항은 아직 처리하지 않았기 때문에 인덱스를 유지한다. 모든 차수 배열의 시간 복잡도는 O(D+1)이다. (b) 쌍 결과는 [(18,3),(3,2),(7,1),(2,0)]이며, ②는 네 번 비교해 =에서 (18,3)을 붙이고 As·Bs가 1·1칸, <에서 (3,2)를 붙이고 1·2칸, >에서 (7,1)을 붙이고 2·2칸, =에서 (2,0)을 붙이고 3·3칸이 되어 함께 끝난다(>에서는 A만, =에서는 양쪽, <에서는 B만 전진). 한쪽 종료 뒤 다른 쪽 남은 항을 복사하고, 합이 0인 항은 저장하지 않으며, 희소 병합의 시간 복잡도는 O(m+n)이다.

코드 줄 수가 길다고 더 높은 차수의 시간복잡도라고 판단하지 않아요. 최고차수 D와 0이 아닌 항의 수 m, n은 서로 다른 입력 크기예요.

P11. 구조체 대입과 비교 연산

강의 예제 기반 자체 출제 S3 p17

person 타입은 아래와 같이 선언되어 있으며, a와 b는 유효하게 초기화된 person 구조체 변수예요.

typedef struct person {
    char name[10];   // 문자 배열로 된 이름
    int age;         // 나이를 나타내는 정수값
    float height;    // 키를 나타내는 실수값
} person;
  1. (a) 구조체 대입 b = a;가 C에서 허용되는지, 이때 문자 배열 멤버 name도 함께 복사되는지, 그리고 대입 직후 b.age만 바꾸면 a.age도 바뀌는지 설명하세요.
  2. (b) 구조체 전체를 비교하는 if (a > b)가 C에서 허용되는지 답하고, 두 사람의 나이가 더 많은지를 비교하는 올바른 조건식을 쓰세요.
강의 예제 보기

S3 p17 · Software_3_ArrayStructureList.pdf. 강의의 개념·그림·코드 연산을 바탕으로 조건과 질문을 새로 작성한 자체 출제예요. 문제의 person 선언은 S3 p17의 강의 코드를 발췌해 들여쓰기를 정리한 것이에요. 질문·입력 조건·검산은 자체 작성했어요.

힌트 보기

b = a;는 같은 타입의 구조체 값 복사이고, 크기 비교는 특정 멤버를 직접 지정해야 해요.

풀이 보기
  1. (a) 같은 person 타입 사이의 대입 b = a;는 허용되며, 구조체 안에 들어 있는 문자 배열 멤버 name의 내용까지 포함한 모든 멤버 값이 별도 객체 b로 복사돼요. b와 a는 서로 다른 메모리 객체이므로 이후 b.age를 수정해도 a.age는 그대로 유지돼요.
  2. (b) C 언어는 구조체 전체에 대한 관계·동등 비교 연산(a > b, a == b)을 직접 지원하지 않으므로 컴파일 오류가 나요. 나이를 비교하려면 정수 멤버를 꺼내 a.age > b.age처럼 멤버별로 비교해야 해요.

정답: (a) 같은 person 타입의 b=a는 가능하고 멤버 값이 복사되어 name 배열의 내용도 복사된다. b와 a는 별도 객체이므로 b.age만 바꾸면 a.age는 유지된다. (b) 구조체 전체의 a>b는 C에서 허용되지 않으며 a.age>b.age로 나이를 비교한다.

구조체 대입이 가능하다고 해서 구조체 전체 비교 연산자 >나 ==까지 가능하다고 확대하지 마세요.

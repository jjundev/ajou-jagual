P6. 하노이 코드의 매개변수 역할

강의 예제 기반 자체 출제 S2 p19

n≥1이에요. hanoi_tower(3,'A','B','C')의 이동을 원판 번호와 출발·도착 막대로 쓰세요. 첫 번째 순환 호출에서 to와 tmp의 위치가 바뀌는 이유와 최소 이동 횟수의 점화식도 설명하세요.

void hanoi_tower(int n, char from, char tmp, char to)
{
    if(n==1) printf("원판1을%c에서%c으로옮긴다.\n",from,to);
    else {
        hanoi_tower(n-1,from,to,tmp);
        printf("원판%d을%c에서%c으로옮긴다.\n",n,from,to);
        hanoi_tower(n-1,tmp,from,to);
    }
}

힌트 보기

가장 큰 원판을 A에서 C로 옮기기 전에 위의 2개를 B로 옮겨야 해요. 그래서 첫 호출의 도착 막대는 tmp(B)이고 보조 막대는 to(C)가 돼요.

풀이 보기
  1. 가장 큰 원판을 A에서 C로 옮기기 전에 위의 2개를 B로 옮겨야 해요. 그래서 첫 호출의 도착 막대는 tmp(B)이고 보조 막대는 to(C)가 돼요.
  2. hanoi(2,A,C,B)는 1:A→C,2:A→B,1:C→B를 출력해요. 이어서 3:A→C를 출력해요.
  3. 마지막 hanoi(2,B,A,C)는 1:B→A,2:B→C,1:A→C를 출력해요.
  4. 위 n-1개 이동, 가장 큰 원판 1회, 위 n-1개 이동이 반드시 필요해요. 같은 전략으로 이 하한을 달성하므로 점화식은 최소 횟수예요.

정답: 1:A→C, 2:A→B, 1:C→B, 3:A→C, 1:B→A, 2:B→C, 1:A→C. T(1)=1, T(n)=2T(n-1)+1, T(3)=7.

P7. 계수 배열의 순서와 공간 낭비

강의 예제 기반 자체 출제 S3 p7

MAX_DEGREE는 6 이상이에요. 이 구조체는 계수를 차수가 높은 항부터 내림차순으로 저장해요. 곧 coef[i]는 x^(degree−i)의 계수예요. 이 규칙으로 a가 나타내는 다항식과 coef[4]의 차수를 쓰세요. 1000차 항과 상수항만 있는 다항식을 이 방식과 (계수,차수) 쌍 방식으로 저장할 때 필요한 유효 항목 수를 비교하세요.

typedef struct {
    int degree;
    float coef[MAX_DEGREE];
} polynomial;
polynomial a = {5,{10,0,0,0,6,3}};
강의 예제 보기

S3 p7 · Software_3_ArrayStructureList.pdf. 강의 코드의 해당 연산을 발췌해 들여쓰기를 정리했습니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

힌트 보기

degree=5이므로 인덱스 i의 차수는 5-i예요. coef[0]은 5차, coef[4]는 1차, coef[5]는 상수항이에요.

풀이 보기
  1. degree=5이므로 인덱스 i의 차수는 5-i예요. coef[0]은 5차, coef[4]는 1차, coef[5]는 상수항이에요.
  2. 0인 계수도 자리를 차지하므로 x^4,x^3,x² 항이 없다는 사실을 배열에 남겨요.
  3. 1000차부터 0차까지는 총 1001개예요. 쌍 표현은 0이 아닌 두 항만 저장하지만 각 항의 차수도 별도로 저장해야 해요.

정답: 10x^5+6x+3, coef[4]는 1차 항. 모든 차수 배열은 1001개 계수, 쌍 방식은 2개 항(계수와 차수 각각 2개)을 저장한다.

이 구조체에서는 coef[0]이 상수항이 아니에요. 저장 규칙을 먼저 확인하세요.

풀이 보기
  1. ADT는 가능한 객체와 연산의 의미를 먼저 정하고 물리 주소 계산과 구별해요.
  2. store 뒤 같은 인덱스 retrieve 결과는 저장한 7이에요.
  3. 앞선 두 행에 8개, 현재 행 앞에 1개가 있으므로 총 9개 원소를 건너뛰어요.
  4. 9개에 원소 크기 4바이트를 곱해 시작 주소에 더해요.

정답: 객체는 인덱스와 요소 쌍의 집합이에요. create(6)은 6개 요소의 배열 생성, store는 2번 위치에 7 저장, retrieve는 그 위치의 7 반환이에요. C 행 우선 배열 A[2][1]의 앞에는 2×4+1=9개 원소가 있어 주소는 1000+9×4=1036이에요. 0≤2<3, 0≤1<4로 유효해요.

행 번호에 행 수 3을 곱하지 않아요. 한 행의 열 수 4를 곱해요. 범위를 벗어난 인덱스에 주소 공식을 적용해 유효한 접근이라고 하지 않아요.

P10. 두 표현의 다항식 덧셈과 남은 항 처리

강의 예제 기반 자체 출제 S3 p11 · 추가 근거 p7,8,9,10

A=8x^3+7x+1, B=10x^3+3x^2+1을 두 저장 방식으로 더하려고 해요. (가) 모든 차수 방식은 최고 차수 degree와, 0을 포함한 모든 계수를 차수가 높은 항부터 내림차순으로 담은 배열 coef를 저장해요. (나) 희소 방식은 0이 아닌 항만 (계수,차수) 쌍으로 차수가 높은 항부터 저장해요.

(가)의 결과 계수를 내림차순으로 쓰고, 아래 ①에서 차수가 높은 쪽 항만 C로 옮길 때 왜 다른 쪽 인덱스는 그대로인지 설명하세요. (나)의 두 입력을 아래 ②로 더할 때 비교가 일어날 때마다 compare 결과, attach로 붙는 쌍, 그 비교를 처리한 직후 As와 Bs가 각자 입력의 첫 항에서 몇 칸 전진했는지를 순서대로 쓰세요. 한쪽이 먼저 끝날 때, 같은 차수의 계수 합이 0일 때 처리와 두 방식의 시간복잡도를 최고 차수 D 및 두 입력의 항 수 m,n으로 설명하세요.

/* ① (가) 방식의 덧셈 루프. Apos, Bpos, Cpos는 처음에 0이고, degree_a, degree_b는 처음에 A.degree, B.degree예요. */
while( Apos<=A.degree && Bpos<=B.degree ){
    if( degree_a > degree_b ){
        C.coef[Cpos++]= A.coef[Apos++];
        degree_a--;
    }
    else if( degree_a == degree_b ){
        C.coef[Cpos++]=A.coef[Apos++]+B.coef[Bpos++];
        degree_a--; degree_b--;
    }
    else {
        C.coef[Cpos++]= B.coef[Bpos++];
        degree_b--;
    }
}

/* ② (나) 방식의 덧셈 루프. terms[As..Ae]가 A, terms[Bs..Be]가 B의 항이고,
   compare는 두 차수를 비교해 '>', '=', '<'를 돌려줘요.
   attach(c,e)는 결과 끝에 (c,e) 쌍을 하나 추가해요. */
while( As <= Ae && Bs <= Be )
    switch(compare(terms[As].expon,terms[Bs].expon)){
    case '>':
        attach(terms[As].coef, terms[As].expon);
        As++;
        break;
    case '=':
        tempcoef = terms[As].coef + terms[Bs].coef;
        if( tempcoef )
            attach(tempcoef,terms[As].expon);
        As++; Bs++;
        break;
    case '<':
        attach(terms[Bs].coef, terms[Bs].expon);
        Bs++;
        break;
    }
강의 예제 보기

S3 p11 · 추가 근거 p7,8,9,10 · Software_3_ArrayStructureList.pdf. 강의의 개념·그림·코드 연산을 바탕으로 조건과 질문을 새로 작성한 자체 출제예요. 문제의 두 덧셈 루프는 S3 p8(①)과 p11(②)의 강의 코드를 발췌해 들여쓰기를 정리하고 설명 주석을 덧붙인 것이에요. 질문·입력 조건·검산은 자체 작성했어요.

힌트 보기

A의 계수 [8,0,7,1], B의 계수 [10,3,0,1]이라고 적어요.

풀이 보기
  1. 계수 배열은 같은 차수끼리 맞추므로 [8,0,7,1]+[10,3,0,1]을 써요.
  2. 각 자리 합으로 [18,3,7,2]를 얻어요. 차수가 높은 입력만 처리했다면 다른 쪽 항은 아직 기다려요.
  3. 희소 방식은 현재 차수를 비교해 큰 쪽을 복사하고, 같으면 계수를 합쳐 양쪽을 전진해요.
  4. 차수 3과 3은 =라서 (18,3)을 붙이고 둘 다 전진해요(1·1칸). 1과 2는 <라서 (3,2)를 붙이고 Bs만(1·2칸), 1과 0은 >라서 (7,1)을 붙이고 As만(2·2칸), 0과 0은 =라서 (2,0)을 붙이고 둘 다 전진해요(3·3칸).
  5. while이 끝나면 남은 입력을 복사해 누락을 막고, 같은 차수 합이0이면 저장만 건너뛰되 양쪽 입력은 전진해요.
  6. 각 입력 위치가 한 번씩 전진하므로 길이에 비례해요. 배열 길이는 D+1, 희소 입력 길이는 m+n이에요.

정답: 결과는 18x^3+3x^2+7x+2, 내림차순 계수 [18,3,7,2], 쌍 [(18,3),(3,2),(7,1),(2,0)]이에요. ②는 네 번 비교해요: =에서 (18,3)을 붙이고 As·Bs가 1·1칸, <에서 (3,2)를 붙이고 1·2칸, >에서 (7,1)을 붙이고 2·2칸, =에서 (2,0)을 붙이고 3·3칸이 되어 두 입력이 함께 끝나요. >에서는 A만, =에서는 양쪽, <에서는 B만 전진해요. 높은 차수만 출력한 경우 다른 입력의 현재 항은 아직 처리하지 않았기 때문이에요. 한쪽 종료 뒤 다른 쪽 남은 항을 복사해요. 희소 방식은 합이 0인 항을 저장하지 않아요. 모든 차수 배열은 O(D+1), 희소 병합은 O(m+n)이에요.

코드 줄 수가 길다고 더 높은 차수의 시간복잡도라고 판단하지 않아요. 두 표현의 D와 m,n은 서로 다른 입력 크기예요.

P11. 구조체 대입과 비교 연산

강의 예제 기반 자체 출제 S3 p17

person 타입은 아래처럼 선언되어 있어요.

typedef struct person {
    char name[10];   // 문자 배열로 된 이름
    int age;         // 나이를 나타내는 정수값
    float height;    // 키를 나타내는 실수값
} person;

a와 b가 유효하게 초기화된 person일 때 b=a;와 if(a>b)는 각각 가능한가요? b=a; 뒤 b.age를 바꾸면 a.age도 바뀌나요? 나이가 더 많은지를 비교하는 올바른 조건을 쓰고 배열 멤버도 대입 때 복사되는지 설명하세요.

강의 예제 보기

S3 p17 · Software_3_ArrayStructureList.pdf. 강의의 개념·그림·코드 연산을 바탕으로 조건과 질문을 새로 작성한 자체 출제예요. 문제의 person 선언은 S3 p17의 강의 코드를 발췌해 들여쓰기를 정리한 것이에요. 질문·입력 조건·검산은 자체 작성했어요.

힌트 보기

b=a: 같은 타입의 구조체 값 복사라고 적어요.

풀이 보기
  1. b=a는 같은 구조체 타입의 값을 별도 객체로 대입해요.
  2. 구조체 안의 배열 멤버도 이 구조체 대입에 포함돼요. 배열만 단독으로 b.name=a.name이라고 대입하는 것과 달라요.
  3. 두 객체는 같은 주소가 아니므로 b.age 수정은 a.age를 바꾸지 않아요.
  4. 비교 기준이 나이이면 정수 멤버 a.age와 b.age를 비교해요.

정답: 같은 person 타입의 b=a는 가능하고 멤버 값이 복사되어 name 배열의 내용도 복사돼요. b와 a는 별도 객체이므로 b.age만 바꾸면 a.age는 유지돼요. 구조체 전체의 a>b는 C에서 허용되지 않으며 a.age>b.age로 나이를 비교해요.

구조체 대입 가능을 구조체 > 비교 가능으로 확대하지 않아요. 배열 멤버가 있다는 이유로 구조체 대입 전체가 금지된다고 하지 않아요.

### P1. 2차원 배열의 바이트 수

textbook-ch03-q01 · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0921_ArrayStructureList.html#p1)

int a[10][20]에서 배열이 차지하는 메모리 공간의 크기는 얼마인가? int형은 4바이트라고 하자.

#### 문제를 내 말로 읽어요

10행 20열의 int 배열 전체 바이트 수를 구해요. int=4바이트는 문제에서 정한 값이에요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

“배열이 차지하는 공간”은 원소 개수×원소 한 개의 크기예요. 배열은 같은 타입 원소를 연속 배치하므로 별도 행 포인터 10개가 붙는 것이 아니에요.

#### 종이에 적을 첫 줄

원소 수=10×20=200을 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

200×4=800바이트, 정답 (4)예요. 각 행이 20×4=80바이트이고 10행을 합쳐도 800이에요.

#### 완성 답과 검산

두 방식 200원소×4와 10행×80이 같아요. 실제 C 검산에서도 sizeof(int)==4인 환경의 sizeof a가 800이에요.

#### 이 문제에서 조심할 점

10+20으로 원소 수를 세거나 int**의 저장 크기와 섞지 않아요.

#### 설명을 닫고 다시 해 봐요

1. 원소 수=10×20=200을 적어요.
2. 행×열×int 크기 = 800
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

#### 떠올릴 개념·공식

### P2. 배열에 2의 거듭제곱 저장

textbook-ch03-q04 · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0921_ArrayStructureList.html#p2)

크기가 10인 배열 two[]를 선언하고 여기에 2의 제곱 값들을 저장해보자. 즉 배열의 첫 번째 요소에는 2⁰을 저장하고 두 번째 요소에는 2¹값을 저장한다. 마지막 요소에는 2⁹값을 저장한다. for 루프를 이용하여 two[] 배열의 전체 요소의 값을 출력하는 프로그램을 작성하라.

크기가 10인 배열 two[]를 선언하고 여기에 2의 제곱 값들을 저장해보자. 즉 배열의 첫 번째 요소에는 2⁰을 저장하고 두 번째 요소에는 2¹값을 저장한다. 마지막 요소에는 2⁹값을 저장한다. for 루프를 이용하여 two[] 배열의 전체 요소의 값을 출력하는 프로그램을 작성하라.

#### 문제를 내 말로 읽어요

two[0]부터 two[9]까지 2⁰..2⁹를 저장하고 출력해요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

“이전 값의 두 배”라는 점화식 two[i]=2×two[i−1]로 거듭제곱 power를 만들 수 있어요. C의 ^는 거듭제곱이 아니라 XOR이므로 쓰지 않아요.

#### 종이에 적을 첫 줄

`int two[10];
two[0] = 1;`

#### 왜 이렇게 푸는지 함께 따라가요

`#include <stdio.h>
int main(void) {
    int two[10];
    two[0] = 1;
    for (int i=1; i<10; ++i) two[i] = 2*two[i-1];
    for (int i=0; i<10; ++i) printf("%d%s", two[i], i==9?"\n":" ");
    return 0;
}`

#### 완성 답과 검산

출력은 1 2 4 8 16 32 64 128 256 512예요. 귀납적으로 첫 원소 2⁰이고 직전 2ⁱ⁻¹의 두 배가 2ⁱ예요. 독립 정수 거듭제곱과 C 출력 모두 대조해요.

#### 이 문제에서 조심할 점

i=0부터 직전 원소를 읽으면 two[−1]로 배열 범위를 벗어나요.

#### 설명을 닫고 다시 해 봐요

1. int two[10]; two[0] = 1;
2. two[0]=1, 이전 원소×2
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

#### 첫 줄

int two[10]; two[0] = 1;

#### 떠올릴 개념·공식

two[0]=1, 이전 원소×2

### P4. typedef로 complex 만들기

textbook-ch03-q06 · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0921_ArrayStructureList.html#p4)

C언어의 typedef을 이용하여 complex라고 하는 새로운 자료형을 정의하라. complex 자료형은 구조체로서 float형인 real 변수와 역시 float형인 imaginary 변수를 갖는다. complex 자료형으로 변수 c1과 c2를 선언하여보라.

#### 문제를 내 말로 읽어요

실수부와 허수부를 갖는 타입 complex를 만들고 두 변수를 선언해요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

typedef는 새로운 표현을 발명하는 것이 아니라 기존 타입에 이름 alias를 붙여요. real과 imaginary는 float, c1과 c2는 이 두 필드를 갖는 객체예요.

#### 종이에 적을 첫 줄

typedef struct { 로 시작해요.

#### 왜 이렇게 푸는지 함께 따라가요

`typedef struct {
    float real;
    float imaginary;
} complex;
complex c1, c2;`

#### 완성 답과 검산

complex c1,c2는 각각 두 float 멤버를 가진 변수를 만들어요. C 컴파일에서 c1.real=1.0f, c2.imaginary=2.0f 접근이 가능해요. typedef 선언만으로는 c1,c2 객체가 생기지 않으므로 별도 선언을 확인해요.

#### 이 문제에서 조심할 점

complex를 구조체 태그와 변수 이름으로 혼동하지 않아요.

#### 설명을 닫고 다시 해 봐요

1. typedef struct { 로 시작해요.
2. typedef 별명 뒤 변수 c1,c2 선언
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

### P5. 행렬 예제를 C 배열과 세 쌍으로 표현하기

lecture-s03-p14-sparse-triples · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0921_ArrayStructureList.html#p5)

**강의 예제 기반 자체 출제** S3 p14

아래 코드는 3×3 행렬 A를 C 배열로 쓴 것이에요. 0부터 시작하는 (행,열,값)으로 0이 아닌 원소를 행 우선 순서대로 나열하세요. 9개 값 저장과 세 정수로 된 7개 항 저장 중 이 예제에서 어느 쪽이 적은 정수를 쓰는지 비교하고, 희소 표현이 언제 유리한지도 설명하세요.

`/* 3×3 행렬 A */
int A[3][3]={{2,3,0},{8,9,1},{7,0,5}};`

#### 문제를 내 말로 읽어요

코드는 3×3 행렬 A를 C 배열로 쓴 것이에요. 0부터 시작하는 (행,열,값)으로 0이 아닌 원소를 행 우선 순서대로 나열하세요. 9개 값 저장과 세 정수로 된 7개 항 저장 중 이 예제에서 어느 쪽이 적은 정수를 쓰는지 비교하고, 희소 표현이 언제 유리한지도 설명하세요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “행렬 예제를 C 배열과 세 쌍으로 표현하기”예요. 행 0에서 2,3을 기록하고 0은 빼요. 행 1에는 세 값이 모두 있고 행 2에는 첫 칸과 끝 칸이 있어요. 0이 조금 있다고 희소 표현이 항상 작은 것은 아니에요. t가 충분히 작아야 주소 정보의 추가 비용을 상쇄해요.

#### 종이에 적을 첫 줄

행 0, 열 0의 값 2를 (0,0,2)로 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

1. 행 0에서 2,3을 기록하고 0은 빼요. 행 1에는 세 값이 모두 있고 행 2에는 첫 칸과 끝 칸이 있어요.
2. 값만 저장하는 배열과 달리 삼중항에는 각 값의 행과 열도 들어가요. 따라서 7×3=21개 정수예요.
3. 0이 조금 있다고 희소 표현이 항상 작은 것은 아니에요. t가 충분히 작아야 주소 정보의 추가 비용을 상쇄해요.

(0,0,2),(0,1,3),(1,0,8),(1,1,9),(1,2,1),(2,0,7),(2,2,5). 전체 배열 9개, 삼중항 21개 정수이므로 A에서는 전체 배열이 작다. 행렬 크기 부가정보를 제외하면 3t&lt;행수×열수일 때 삼중항이 작다.

#### 완성 답과 검산

(0,0,2),(0,1,3),(1,0,8),(1,1,9),(1,2,1),(2,0,7),(2,2,5). 전체 배열 9개, 삼중항 21개 정수이므로 A에서는 전체 배열이 작다. 행렬 크기 부가정보를 제외하면 3t&lt;행수×열수일 때 삼중항이 작다.

시작 조건에서 다시 추적한 결과가 위 답과 일치해요. 0이 조금 있다고 희소 표현이 항상 작은 것은 아니에요. t가 충분히 작아야 주소 정보의 추가 비용을 상쇄해요.

#### 이 문제에서 조심할 점

항 개수 7개와 저장하는 정수 개수 21개를 혼동하지 마세요.

#### 설명을 닫고 다시 해 봐요

1. 주어진 시작 상태와 필요한 입력 조건을 적어요.
2. 첫 줄부터 연산 순서를 따라 답을 완성해요.
3. 경계 경우와 오류 경로를 확인해요.

**페이지 요약**

#### 첫 줄

행 0, 열 0의 값 2를 (0,0,2)로 적어요.

#### 떠올릴 개념·공식

‘객체와 연산’은 추상 자료형(ADT)의 단서예요. ADT는 무엇을 저장하고 어떤 작업을 할지 정의해요. ‘C의 2차원 배열’은 행 우선(row-major) 연속 배치의 단서예요. 열 수가 C일 때 A[r][c] 앞에는 rC+c개 원소가 있고 원소 크기를 곱하면 바이트 간격이 돼요.

#### 종이에 쓰는 첫 줄

A[2][1] 앞의 원소 수 = 2×4+1이라고 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

ADT는 가능한 객체와 연산의 의미를 먼저 정하고 물리 주소 계산과 구별해요.

store 뒤 같은 인덱스 retrieve 결과는 저장한 7이에요.

앞선 두 행에 8개, 현재 행 앞에 1개가 있으므로 총 9개 원소를 건너뛰어요.

9개에 원소 크기 4바이트를 곱해 시작 주소에 더해요.

객체는 인덱스와 요소 쌍의 집합이에요. create(6)은 6개 요소의 배열 생성, store는 2번 위치에 7 저장, retrieve는 그 위치의 7 반환이에요. C 행 우선 배열 A[2][1]의 앞에는 2×4+1=9개 원소가 있어 주소는 1000+9×4=1036이에요. 0≤2&lt;3, 0≤1&lt;4로 유효해요.

#### 완성 답과 검산

객체는 인덱스와 요소 쌍의 집합이에요. create(6)은 6개 요소의 배열 생성, store는 2번 위치에 7 저장, retrieve는 그 위치의 7 반환이에요. C 행 우선 배열 A[2][1]의 앞에는 2×4+1=9개 원소가 있어 주소는 1000+9×4=1036이에요. 0≤2&lt;3, 0≤1&lt;4로 유효해요.

A[0][0]=1000, 다음 행 A[1][0]=1016, A[2][0]=1032에서 한 원소 더 가면 1036이에요. 행 단위 계산과 원소 단위 계산이 일치해요.

#### 이 문제에서 조심할 점

행 번호에 행 수 3을 곱하지 않아요. 한 행의 열 수 4를 곱해요. 범위를 벗어난 인덱스에 주소 공식을 적용해 유효한 접근이라고 하지 않아요.

1. 주어진 조건과 첫 상태를 적어요.
2. 핵심 규칙을 떠올려 답을 다시 완성해요.
3. 경계 조건과 보존되는 상태를 확인해요.

### P10. 두 표현의 다항식 덧셈과 남은 항 처리

lecture-s03-p11-polynomial-add-merge · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0921_ArrayStructureList.html#p10)

**강의 예제 기반 자체 출제** S3 p11 · 추가 근거 p7,8,9,10

A=8x^3+7x+1, B=10x^3+3x^2+1을 두 저장 방식으로 더하려고 해요. (가) 모든 차수 방식은 최고 차수 degree와, 0을 포함한 모든 계수를 차수가 높은 항부터 내림차순으로 담은 배열 coef를 저장해요. (나) 희소 방식은 0이 아닌 항만 (계수,차수) 쌍으로 차수가 높은 항부터 저장해요.

(가)의 결과 계수를 내림차순으로 쓰고, 아래 ①에서 차수가 높은 쪽 항만 C로 옮길 때 왜 다른 쪽 인덱스는 그대로인지 설명하세요. 아래 ②의 &gt;, =, &lt; 분기에서 어느 입력 인덱스를 전진시키는지와 출력 쌍을 쓰세요. 한쪽이 먼저 끝날 때, 같은 차수의 계수 합이 0일 때 처리와 두 방식의 시간복잡도를 최고 차수 D 및 두 입력의 항 수 m,n으로 설명하세요.

`/* ① (가) 방식의 덧셈 루프. degree_a, degree_b는 처음에 A.degree, B.degree예요. */
while( Apos<=A.degree && Bpos<=B.degree ){
    if( degree_a > degree_b ){
        C.coef[Cpos++]= A.coef[Apos++];
        degree_a--;
    }
    else if( degree_a == degree_b ){
        C.coef[Cpos++]=A.coef[Apos++]+B.coef[Bpos++];
        degree_a--; degree_b--;
    }
    else {
        C.coef[Cpos++]= B.coef[Bpos++];
        degree_b--;
    }
}

/* ② (나) 방식의 덧셈 루프. terms[As..Ae]가 A, terms[Bs..Be]가 B의 항이고,
   compare는 두 차수를 비교해 '>', '=', '<'를 돌려줘요.
   attach(c,e)는 결과 끝에 (c,e) 쌍을 하나 추가해요. */
while( As <= Ae && Bs <= Be )
    switch(compare(terms[As].expon,terms[Bs].expon)){
    case '>':
        attach(terms[As].coef, terms[As].expon);
        As++;
        break;
    case '=':
        tempcoef = terms[As].coef + terms[Bs].coef;
        if( tempcoef )
            attach(tempcoef,terms[As].expon);
        As++; Bs++;
        break;
    case '<':
        attach(terms[Bs].coef, terms[Bs].expon);
        Bs++;
        break;
    }`

#### 문제를 내 말로 읽어요

A=8x^3+7x+1, B=10x^3+3x^2+1을 (가) 0을 포함한 모든 계수를 내림차순으로 담는 방식과 (나) 0이 아닌 항만 (계수,차수) 쌍으로 담는 방식으로 더해요. (가)의 결과 계수를 내림차순으로 쓰고, 덧셈 루프 ①에서 차수가 높은 쪽 항만 옮길 때 왜 다른 쪽 인덱스는 그대로인지 설명하세요. (나)를 합치는 루프 ②의 &gt;,=,&lt; 분기에서 어느 입력 인덱스를 전진시키는지와 출력 쌍을 쓰세요. 한쪽이 먼저 끝날 때, 같은 차수의 계수 합이 0일 때 처리와 두 방식의 시간복잡도를 최고 차수 D 및 두 입력의 항 수 m,n으로 설명하세요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

‘정렬된 차수 두 묶음’은 병합(merge)의 단서예요. 차수가 큰 항부터 확정하면 뒤에서 같은 차수보다 큰 항이 새로 나타나지 않아요. 같을 때 양쪽을 소비하고 나머지 분기에서는 한쪽만 소비해요. 입력 포인터가 후퇴하지 않아 총 전진 수로 시간복잡도를 셀 수 있어요.

#### 종이에 쓰는 첫 줄

A의 계수 [8,0,7,1], B의 계수 [10,3,0,1]이라고 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

계수 배열은 같은 차수끼리 맞추므로 [8,0,7,1]+[10,3,0,1]을 써요.

각 자리 합으로 [18,3,7,2]를 얻어요. 차수가 높은 입력만 처리했다면 다른 쪽 항은 아직 기다려요.

희소 방식은 현재 차수를 비교해 큰 쪽을 복사하고, 같으면 계수를 합쳐 양쪽을 전진해요.

차수3은 18, 차수2는 B의3, 차수1은 A의7, 차수0은 합2를 저장해요.

while이 끝나면 남은 입력을 복사해 누락을 막고, 같은 차수 합이0이면 저장만 건너뛰되 양쪽 입력은 전진해요.

각 입력 위치가 한 번씩 전진하므로 길이에 비례해요. 배열 길이는 D+1, 희소 입력 길이는 m+n이에요.

결과는 18x^3+3x^2+7x+2, 내림차순 계수 [18,3,7,2], 쌍 [(18,3),(3,2),(7,1),(2,0)]이에요. &gt;에서는 A만, =에서는 양쪽, &lt;에서는 B만 전진해요. 높은 차수만 출력한 경우 다른 입력의 현재 항은 아직 처리하지 않았기 때문이에요. 한쪽 종료 뒤 다른 쪽 남은 항을 복사해요. 희소 방식은 합이 0인 항을 저장하지 않아요. 모든 차수 배열은 O(D+1), 희소 병합은 O(m+n)이에요.

#### 완성 답과 검산

결과는 18x^3+3x^2+7x+2, 내림차순 계수 [18,3,7,2], 쌍 [(18,3),(3,2),(7,1),(2,0)]이에요. &gt;에서는 A만, =에서는 양쪽, &lt;에서는 B만 전진해요. 높은 차수만 출력한 경우 다른 입력의 현재 항은 아직 처리하지 않았기 때문이에요. 한쪽 종료 뒤 다른 쪽 남은 항을 복사해요. 희소 방식은 합이 0인 항을 저장하지 않아요. 모든 차수 배열은 O(D+1), 희소 병합은 O(m+n)이에요.

x=1을 대입하면 A=16, B=14, 결과=30으로 일치해요. 계수별 직접 덧셈이 희소 병합 출력과도 같아요. 별도 경계로 A=x, B=-x이면 출력 항이 없고, A=x^2+x+1, B=x^2이면 마지막 x와1을 나머지 복사해야 해요.

#### 이 문제에서 조심할 점

코드 줄 수가 길다고 더 높은 차수의 시간복잡도라고 판단하지 않아요. 두 표현의 D와 m,n은 서로 다른 입력 크기예요.

1. 주어진 조건과 첫 상태를 적어요.
2. 핵심 규칙을 떠올려 답을 다시 완성해요.
3. 경계 조건과 보존되는 상태를 확인해요.

### P11. 구조체 대입과 비교 연산

#### 문제를 내 말로 읽어요

person 타입은 char name[10], int age, float height 멤버를 가진 typedef 구조체예요. a와 b가 유효하게 초기화된 person일 때 b=a;와 if(a&gt;b)는 각각 가능한가요? b=a; 뒤 b.age를 바꾸면 a.age도 바뀌나요? 나이가 더 많은지를 비교하는 올바른 조건을 쓰고 배열 멤버도 대입 때 복사되는지 설명하세요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

‘대입’은 값 복사, ‘나이가 많음’은 비교할 특정 멤버의 선택을 요구해요. C는 같은 구조체 타입의 대입을 지원하지만 구조체 전체에 순서 관계 &gt;를 정의하지 않아요. 자료가 포인터 멤버를 가지면 가리키는 객체 복사와 구별해야 하지만 이 문제의 멤버는 문자 배열과 수 값이에요.

#### 종이에 쓰는 첫 줄

b=a: 같은 타입의 구조체 값 복사라고 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

b=a는 같은 구조체 타입의 값을 별도 객체로 대입해요.

구조체 안의 배열 멤버도 이 구조체 대입에 포함돼요. 배열만 단독으로 b.name=a.name이라고 대입하는 것과 달라요.

두 객체는 같은 주소가 아니므로 b.age 수정은 a.age를 바꾸지 않아요.

비교 기준이 나이이면 정수 멤버 a.age와 b.age를 비교해요.

같은 person 타입의 b=a는 가능하고 멤버 값이 복사되어 name 배열의 내용도 복사돼요. b와 a는 별도 객체이므로 b.age만 바꾸면 a.age는 유지돼요. 구조체 전체의 a&gt;b는 C에서 허용되지 않으며 a.age&gt;b.age로 나이를 비교해요.

#### 완성 답과 검산

같은 person 타입의 b=a는 가능하고 멤버 값이 복사되어 name 배열의 내용도 복사돼요. b와 a는 별도 객체이므로 b.age만 바꾸면 a.age는 유지돼요. 구조체 전체의 a&gt;b는 C에서 허용되지 않으며 a.age&gt;b.age로 나이를 비교해요.

a.age=20, b=a 뒤 b.age=21이라고 손으로 추적하면 a.age는20, b.age는21이에요. 따라서 a.age&gt;b.age는 거짓이에요. 구조체 통째 비교는 값을 계산할 문제가 아니라 컴파일 단계에서 허용되지 않는 표현이에요.

#### 이 문제에서 조심할 점

구조체 대입 가능을 구조체 &gt; 비교 가능으로 확대하지 않아요. 배열 멤버가 있다는 이유로 구조체 대입 전체가 금지된다고 하지 않아요.

#### 설명을 닫고 다시 해 봐요

1. 주어진 조건과 첫 상태를 적어요.
2. 핵심 규칙을 떠올려 답을 다시 완성해요.
3. 경계 조건과 보존되는 상태를 확인해요.

**페이지 요약**

#### 떠올릴 개념·공식

‘대입’은 값 복사, ‘나이가 많음’은 비교할 특정 멤버의 선택을 요구해요. C는 같은 구조체 타입의 대입을 지원하지만 구조체 전체에 순서 관계 &gt;를 정의하지 않아요. 자료가 포인터 멤버를 가지면 가리키는 객체 복사와 구별해야 하지만 이 문제의 멤버는 문자 배열과 수 값이에요.

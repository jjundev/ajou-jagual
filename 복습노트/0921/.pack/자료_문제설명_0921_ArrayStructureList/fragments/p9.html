문제를 내 말로 읽어요

배열 ADT의 객체를 설명하고 create(6), store(A,2,7), retrieve(A,2)가 하는 일을 쓰세요. 이어 int A[3][4]의 시작 주소를 1000, int 크기를 4바이트로 가정할 때 A[2][1]의 주소를 구하고 인덱스 범위가 유효한지 확인하세요.

이 문제를 봤을 때 떠올릴 개념과 공식

‘객체와 연산’은 추상 자료형(ADT)의 단서예요. ADT는 무엇을 저장하고 어떤 작업을 할지 정의해요. ‘C의 2차원 배열’은 행 우선(row-major) 연속 배치의 단서예요. 열 수가 C일 때 A[r][c] 앞에는 rC+c개 원소가 있고 원소 크기를 곱하면 바이트 간격이 돼요.

종이에 쓰는 첫 줄

A[2][1] 앞의 원소 수 = 2×4+1이라고 적어요.

왜 이렇게 푸는지 함께 따라가요

ADT는 가능한 객체와 연산의 의미를 먼저 정하고 물리 주소 계산과 구별해요.

store 뒤 같은 인덱스 retrieve 결과는 저장한 7이에요.

앞선 두 행에 8개, 현재 행 앞에 1개가 있으므로 총 9개 원소를 건너뛰어요.

9개에 원소 크기 4바이트를 곱해 시작 주소에 더해요.

객체는 인덱스와 요소 쌍의 집합이에요. create(6)은 6개 요소의 배열 생성, store는 2번 위치에 7 저장, retrieve는 그 위치의 7 반환이에요. C 행 우선 배열 A[2][1]의 앞에는 2×4+1=9개 원소가 있어 주소는 1000+9×4=1036이에요. 0≤2<3, 0≤1<4로 유효해요.

완성 답과 검산

객체는 인덱스와 요소 쌍의 집합이에요. create(6)은 6개 요소의 배열 생성, store는 2번 위치에 7 저장, retrieve는 그 위치의 7 반환이에요. C 행 우선 배열 A[2][1]의 앞에는 2×4+1=9개 원소가 있어 주소는 1000+9×4=1036이에요. 0≤2<3, 0≤1<4로 유효해요.

A[0][0]=1000, 다음 행 A[1][0]=1016, A[2][0]=1032에서 한 원소 더 가면 1036이에요. 행 단위 계산과 원소 단위 계산이 일치해요.

이 문제에서 조심할 점

행 번호에 행 수 3을 곱하지 않아요. 한 행의 열 수 4를 곱해요. 범위를 벗어난 인덱스에 주소 공식을 적용해 유효한 접근이라고 하지 않아요.

설명을 닫고 다시 해 봐요

  1. 주어진 조건과 첫 상태를 적어요.
  2. 핵심 규칙을 떠올려 답을 다시 완성해요.
  3. 경계 조건과 보존되는 상태를 확인해요.

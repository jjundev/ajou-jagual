문제를 내 말로 읽어요

배열 추상 자료형(ADT)의 객체와 create·store·retrieve 연산의 의미를 정리하고, 행 우선으로 배치된 2차원 배열 int A[3][4]에서 A[2][1]의 메모리 주소를 계산하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

‘객체와 연산’은 추상 자료형(ADT)의 단서이고, ‘C의 2차원 배열’은 행 우선(row-major) 연속 배치의 단서예요. 열 수가 C일 때 A[r][c] 앞에는 r × C + c개 원소가 놓이므로 시작 주소 base에 (r × C + c) × sizeof(Element)를 더하면 바이트 주소가 돼요.

종이에 쓰는 첫 줄

A[2][1] 앞의 원소 수 = 2 × 4 + 1 = 9라고 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) 배열 ADT의 객체는 <인덱스, 요소> 쌍의 집합이에요. create(6)은 6개 요소를 담는 배열을 생성하고, store(A, 2, 7)은 인덱스 2 위치에 7을 저장하며, retrieve(A, 2)는 그 위치에 저장된 7을 반환해요.

(b) int A[3][4]는 한 행에 4개 원소가 있으므로 A[2][1] 앞에는 행 0과 행 1의 2 × 4 = 8개와 행 2의 첫 원소 1개를 합쳐 총 9개 원소가 있어요. 원소 하나가 4바이트이므로 주소는 1000 + 9 × 4 = 1036이고, 0 <= 2 < 3, 0 <= 1 < 4이므로 유효한 인덱스예요.

완성 답과 검산

(a) 인덱스 2에 store(A, 2, 7)을 수행한 직후 같은 인덱스 2를 retrieve(A, 2)로 읽으면 방금 저장한 7이 나오는 것이 배열 ADT의 정의와 일치해요.

(b) 행 시작 주소를 차례로 적으면 A[0][0] = 1000, A[1][0] = 1016, A[2][0] = 1032이고, 여기서 한 칸(4바이트) 더 가면 A[2][1] = 1036이 되어 공식 결과와 일치해요.

이 문제에서 조심할 점

행 번호에 행 수 3을 곱하지 않고 한 행의 열 수 4를 곱해요. 범위를 벗어난 인덱스에 주소 공식을 적용해 유효한 접근이라고 하지 않아요.

설명을 닫고 다시 해 봐요

  1. 배열 ADT의 객체(<인덱스, 요소> 쌍)와 세 연산의 역할을 적어요.
  2. A[2][1] 앞의 원소 수 2 × 4 + 1 = 9와 바이트 주소 1036을 계산해요.
  3. 행·열 인덱스가 0 <= r < 3, 0 <= c < 4 범위 안인지 확인해요.

떠올릴 개념·공식

배열 ADT는 <인덱스, 요소> 쌍의 집합이고, 2차원 행 우선 배열 A[r][c] 앞에는 r × 열수 + c개 원소가 있어요.

첫 줄

A[2][1] 앞의 원소 수 = 2 × 4 + 1 = 9라고 적어요.

핵심 답

(a) 객체는 인덱스와 요소 쌍의 집합, create(6)은 6개 요소 생성, store는 2번에 7 저장, retrieve는 7 반환 (b) 주소 1000 + 9×4 = 1036, 0<=2<3·0<=1<4로 유효.

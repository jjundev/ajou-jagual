### P5. 행렬 예제를 C 배열과 세 쌍으로 표현하기

**강의 예제 기반 자체 출제** S3 p14

아래 코드는 `3 × 3` 행렬 `A`를 C 2차원 배열로 초기화한 것이에요.

```c
/* 3×3 행렬 A */
int A[3][3] = {{2, 3, 0}, {8, 9, 1}, {7, 0, 5}};
```

- (a) 인덱스가 `0`부터 시작할 때, `A`에서 `0`이 아닌 원소를 `(행, 열, 값)` 삼중항으로 행 우선(row-major) 순서대로 나열하세요.
- (b) 행렬 `A`를 2차원 배열 전체(`9`개 칸)로 저장할 때와 삼중항(`7`개 항)으로 저장할 때 필요한 정수 개수를 비교하고, 행렬 크기 부가정보를 제외할 때 `m × n` 행렬(`0`이 아닌 항 `t`개)에서 삼중항 표현이 더 적은 정수를 쓰는 조건을 쓰세요.

<details><summary>강의 예제 보기</summary>

S3 p14 · Software_3_ArrayStructureList.pdf. 그림의 행렬 A를 C 초기화식으로 옮긴 자체 작성 코드이며 강의 원문 C 코드는 아닙니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

```c
/* 강의의 행렬 A를 C 초기화식으로 옮긴 자체 작성 코드 */

```

</details>

<details><summary>힌트 보기</summary>

행 `0`에서 `2, 3`을 기록하고 `0`은 빼요. 삼중항 하나는 `(행, 열, 값)` 세 정수를 저장해요.

</details>

<details><summary>풀이 보기</summary>

- (a) 행 `0`에서 `(0, 0, 2)`, `(0, 1, 3)`을 기록하고 `0`은 건너뛰어요. 행 `1`에는 세 값이 모두 있으므로 `(1, 0, 8)`, `(1, 1, 9)`, `(1, 2, 1)`을, 행 `2`에는 첫 칸과 끝 칸인 `(2, 0, 7)`, `(2, 2, 5)`를 기록해요.
- (b) 값만 저장하는 2차원 배열 `A[3][3]`은 `9`개 정수를 쓰지만, 삼중항 배열은 각 항마다 행·열·값 `3`개 정수를 쓰므로 `7 × 3 = 21`개 정수를 써요. 따라서 `A`에서는 전체 배열이 더 작고, 일반적으로 `3t < 행수 × 열수`(`3t < m × n`)일 때 삼중항이 더 작아요.

**정답:** (a) `(0,0,2), (0,1,3), (1,0,8), (1,1,9), (1,2,1), (2,0,7), (2,2,5)` (b) 전체 배열 `9`개, 삼중항 `21`개 정수이므로 `A`에서는 전체 배열이 작다. 행렬 크기 부가정보를 제외하면 `3t < 행수×열수`일 때 삼중항이 작다.

항 개수 `7`개와 저장하는 정수 개수 `21`개를 혼동하지 마세요.

</details>

### P6. 하노이 코드의 매개변수 역할

**강의 예제 기반 자체 출제** S2 p19

`n >= 1`개의 원판을 막대 `from`에서 보조 막대 `tmp`를 이용해 목표 막대 `to`로 옮기는 순환 함수예요.

```c
void hanoi_tower(int n, char from, char tmp, char to)
{
    if(n==1) printf("원판1을%c에서%c으로옮긴다.\n",from,to);
    else {
        hanoi_tower(n-1,from,to,tmp);
        printf("원판%d을%c에서%c으로옮긴다.\n",n,from,to);
        hanoi_tower(n-1,tmp,from,to);
    }
}
```

- (a) `hanoi_tower(3, 'A', 'B', 'C')`를 호출했을 때 출력되는 원판 이동 `7`회를 순서대로 `원판번호:출발→도착` 형식으로 쓰세요.
- (b) 첫 번째 순환 호출 `hanoi_tower(n-1, from, to, tmp)`에서 `to`와 `tmp`의 인자 순서가 바뀌는 이유와, 최소 이동 횟수의 점화식 $T(n)$(기저 조건 `T(1)` 포함) 및 `T(3)` 값을 쓰세요.

<details><summary>강의 예제 보기</summary>

S2 p19 · Software_2_Recursion.pdf. 강의 코드의 해당 연산을 발췌해 들여쓰기를 정리했습니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

```c
void hanoi_tower(int n, char from, char tmp, char to)
{
    if(n==1) printf("원판1을%c에서%c으로옮긴다.\n",from,to);
    else {
        hanoi_tower(n-1,from,to,tmp);
        printf("원판%d을%c에서%c으로옮긴다.\n",n,from,to);
        hanoi_tower(n-1,tmp,from,to);
    }
}
```

</details>

<details><summary>힌트 보기</summary>

가장 큰 원판을 `A`에서 `C`로 옮기기 전에 위의 `2`개를 `B`로 옮겨야 해요. 그래서 첫 호출의 도착 막대는 `tmp`(`B`)이고 보조 막대는 `to`(`C`)가 돼요.

</details>

<details><summary>풀이 보기</summary>

- (a) `hanoi_tower(2, 'A', 'C', 'B')`가 먼저 `1:A→C`, `2:A→B`, `1:C→B`를 출력해요. 이어서 원판 `3`을 옮기는 `3:A→C`를 출력한 뒤, `hanoi_tower(2, 'B', 'A', 'C')`가 `1:B→A`, `2:B→C`, `1:A→C`를 출력해요.
- (b) 가장 큰 원판 `n`을 `from`에서 `to`로 옮기려면 위의 `n-1`개를 먼저 보조 막대 `tmp`로 치워야 하므로, 첫 순환 호출에서는 `tmp`가 도착 막대, `to`가 보조 막대 역할을 맡아요. 위 `n-1`개 이동, 가장 큰 원판 `1`회, 다시 `n-1`개 이동이 필요하므로 `T(1) = 1`, `T(n) = 2T(n-1) + 1 = 2^n - 1`이고 `T(3) = 7`이에요.

**정답:** (a) `1:A→C, 2:A→B, 1:C→B, 3:A→C, 1:B→A, 2:B→C, 1:A→C` (b) 가장 큰 원판을 `to`로 옮기기 전에 위 `n-1`개를 보조 막대 `tmp`로 옮겨야 하므로 `tmp`가 도착 막대, `to`가 보조 막대가 된다. `T(1)=1`, `T(n)=2T(n-1)+1`(일반식 `2^n-1`), `T(3)=7`.

`from`, `tmp`, `to`는 고정된 막대 이름이 아니라 현재 호출에서 맡은 역할이에요.

</details>

### P7. 계수 배열의 순서와 공간 낭비

**강의 예제 기반 자체 출제** S3 p7

`MAX_DEGREE`는 `6` 이상인 상수예요. 아래 구조체는 다항식의 계수를 최고차항부터 내림차순으로 저장하므로 `coef[i]`는 $x^{\text{degree}-i}$의 계수예요.

```c
typedef struct {
    int degree;
    float coef[MAX_DEGREE];
} polynomial;

```

- (b) $1000$차 항과 상수항만 있는 다항식(예: $10x^{1000} + 3$)을 이 방식(모든 차수의 계수 배열)과 `(계수, 차수)` 쌍 배열 방식으로 저장할 때 필요한 유효 항목 수를 비교하세요.

<details><summary>강의 예제 보기</summary>

</details>

<details><summary>풀이 보기</summary>

- (a) `a.degree = 5`이므로 인덱스 `i`의 차수는 `5 - i`예요. `coef[0] = 10`은 $x^5$, `coef[1..3] = 0`은 $x^4, x^3, x^2$, `coef[4] = 6`은 $x^1$(`1`차 항), `coef[5] = 3`은 상수항이므로 다항식은 $10x^5 + 6x + 3$이에요.
- (b) 모든 차수의 계수를 저장하는 방식은 `1000`차부터 `0`차까지 총 `1001`개 계수(그중 `999`개가 `0`)를 저장하지만, `(계수, 차수)` 쌍 방식은 `0`이 아닌 `2`개 항(계수와 차수 각각 `2`개씩)만 저장해요.

**정답:** (a) `10x^5+6x+3`, `coef[4]`는 `1`차 항 (b) 모든 차수 배열은 `1001`개 계수, 쌍 방식은 `2`개 항(계수와 차수 각각 `2`개)을 저장한다.

이 구조체에서는 `coef[0]`이 상수항이 아니에요. 내림차순 저장 규칙을 먼저 확인하세요.

</details>

### P8. 자체 참조 구조체의 링크 타입

**강의 예제 기반 자체 출제** S3 p18

아래는 문자열 데이터와 다음 노드를 가리키는 링크 필드를 가진 자체 참조 구조체 `ListNode` 정의예요.

```c
typedef struct ListNode {
    char data[10];
    /* link 필드를 선언하세요 */
} ListNode;
```

- (a) 주석 자리에 들어갈 `link` 필드 선언문을 복원하고, 유효한 노드를 가리키는 포인터 `ListNode *p`에서 데이터와 다음 노드 주소에 접근하는 식을 각각 쓰세요.
- (b) `link`를 포인터가 아닌 `struct ListNode link;`처럼 구조체 값 멤버로 선언할 수 없는 이유를 설명하세요.

<details><summary>강의 예제 보기</summary>

S3 p18 · Software_3_ArrayStructureList.pdf. 강의 코드의 해당 연산을 발췌해 들여쓰기를 정리했습니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

```c
typedef struct ListNode {
    char data[10];
    struct ListNode *link;
} ListNode;
```

</details>

<details><summary>힌트 보기</summary>

구조체 정의 본문 안에서는 아직 `typedef` 별칭 `ListNode`가 완성되기 전이므로 `struct ListNode *` 태그로 자기 자신에 대한 포인터를 선언해요.

</details>

<details><summary>풀이 보기</summary>

- (a) 구조체 정의 안에서는 태그를 써서 `struct ListNode *link;`로 선언해요. 포인터 `p`가 유효한 노드를 가리킬 때 화살표 연산자 `->`로 데이터 필드는 `p->data`, 다음 노드 주소는 `p->link`로 접근해요.
- (b) 포인터는 고정된 크기의 주소만 저장하므로 구조체 크기가 유한하게 정해지지만, 같은 구조체를 값 멤버(`struct ListNode link;`)로 포함하면 자기 자신의 크기를 무한히 중첩해 포함해야 하므로 구조체 크기를 결정할 수 없어요.

**정답:** (a) `struct ListNode *link;`, 데이터 `p->data`, 다음 노드 `p->link` (b) 같은 구조체를 값으로 포함하면 자신의 크기를 무한히 포함해야 하므로 크기를 완성할 수 없다.

포인터 멤버를 선언했다고 해서 다음 노드가 자동으로 할당되지는 않아요.

</details>

### P9. 배열 ADT와 행 우선 주소 계산

**강의 예제 기반 자체 출제** S3 p3

배열 ADT는 `<인덱스, 요소>` 쌍의 집합을 객체로 정의하고 `create(size)`, `retrieve(A, i)`, `store(A, i, item)` 연산을 제공해요. C의 2차원 배열은 메모리에 행 우선(row-major) 순서로 연속 배치돼요.

```c
int A[3][4]; /* 시작 주소 base = 1000, sizeof(int) = 4 */
```

- (a) 배열 ADT의 객체를 쓰고, `create(6)`, `store(A, 2, 7)`, `retrieve(A, 2)`가 각각 수행하는 일을 설명하세요.
- (b) 시작 주소가 `1000`이고 `sizeof(int) == 4`일 때 `int A[3][4]`에서 `A[2][1]`의 바이트 주소를 구하고, 인덱스 `(2, 1)`이 유효 범위 안에 있는지 확인하세요.

<details><summary>강의 예제 보기</summary>

S3 p3 · 추가 근거 p4,5 · Software_3_ArrayStructureList.pdf. 강의의 개념·그림·코드 연산을 바탕으로 조건과 질문을 새로 작성한 자체 출제예요. 제시 코드는 있는 경우 학습 확인용 자체 코드이며 강의 원문 발췌가 아니에요. 질문·입력 조건·검산은 자체 작성했어요.

</details>

<details><summary>힌트 보기</summary>

행 우선 배치에서 `A[2][1]` 앞의 원소 수는 `2 × 4 + 1`이에요.

</details>

<details><summary>풀이 보기</summary>

- (a) 배열 ADT의 객체는 `<인덱스, 요소>` 쌍의 집합이에요. `create(6)`은 `6`개 요소를 담는 배열을 생성하고, `store(A, 2, 7)`은 인덱스 `2` 위치에 값 `7`을 저장하며, `retrieve(A, 2)`는 인덱스 `2` 위치의 값 `7`을 반환해요.
- (b) 행 우선 배열 `A[3][4]`에서 한 행은 원소 `4`개이므로 `A[2][1]` 앞에는 앞선 두 행 `2 × 4 = 8`개와 현재 행 앞 `1`개를 합쳐 `9`개 원소가 있어요. 따라서 주소는 `1000 + 9 × 4 = 1036`이고, `0 <= 2 < 3`, `0 <= 1 < 4`이므로 유효한 인덱스예요.

**정답:** (a) 객체는 인덱스와 요소 쌍의 집합이며, `create(6)`은 `6`개 요소의 배열 생성, `store`는 `2`번 위치에 `7` 저장, `retrieve`는 그 위치의 `7` 반환이다. (b) C 행 우선 배열 `A[2][1]` 앞에는 `2×4+1=9`개 원소가 있어 주소는 `1000+9×4=1036`이며, `0<=2<3`, `0<=1<4`로 유효하다.

행 번호에 행 수 `3`을 곱하지 않고 한 행의 열 수 `4`를 곱해요. 범위를 벗어난 인덱스에 주소 공식을 적용해 유효한 접근이라고 하지 않아요.

</details>

### P10. 두 표현의 다항식 덧셈과 남은 항 처리

**강의 예제 기반 자체 출제** S3 p11

다항식 $A = 8x^3 + 7x + 1$과 $B = 10x^3 + 3x^2 + 1$을 두 가지 배열 표현으로 더해요. 방식 ①(가)은 최고차수 `degree`부터 상수항까지 모든 계수를 내림차순 배열 `coef`에 저장하고, 방식 ②(나)는 `0`이 아닌 항만 `(coef, expon)` 쌍 배열 `terms`에 내림차순으로 저장해요.

```c
/* ① 모든 차수 배열 덧셈 루프 (초기 Apos=Bpos=Cpos=0, degree_a=A.degree, degree_b=B.degree) */
while( Apos<=A.degree && Bpos<=B.degree ){
    if( degree_a > degree_b ){ C.coef[Cpos++] = A.coef[Apos++]; degree_a--; }
    else if( degree_a == degree_b ){ C.coef[Cpos++] = A.coef[Apos++] + B.coef[Bpos++]; degree_a--; degree_b--; }
    else { C.coef[Cpos++] = B.coef[Bpos++]; degree_b--; }
}
/* ② 희소 항 배열 덧셈 루프 (terms[As..Ae]는 A, terms[Bs..Be]는 B) */
while( As <= Ae && Bs <= Be )
    switch(compare(terms[As].expon, terms[Bs].expon)){
    case '>': attach(terms[As].coef, terms[As].expon); As++; break;
    case '=': tempcoef = terms[As].coef + terms[Bs].coef;
              if( tempcoef ) attach(tempcoef, terms[As].expon);
              As++; Bs++; break;
    case '<': attach(terms[Bs].coef, terms[Bs].expon); Bs++; break;
    }
```

- (a) 방식 ①로 더한 결과 계수 배열 `C.coef`를 내림차순으로 쓰고, 루프 ①에서 차수가 큰 쪽 항만 `C`로 옮길 때 다른 쪽 인덱스는 그대로 두는 이유와 최고차수 $D$에 대한 시간 복잡도를 쓰세요.
- (b) 방식 ②의 루프 ②로 $A$와 $B$를 더할 때 매 비교 단계의 `compare` 결과·`attach`되는 `(coef, expon)` 쌍·전진 칸수(`As`, `Bs`)를 순서대로 쓰고, 한쪽 종료 후 남은 항 처리·동차항 합이 `0`일 때 처리·두 입력 항 수 $m, n$에 대한 시간 복잡도를 설명하세요.

<details><summary>강의 예제 보기</summary>

S3 p11 · 추가 근거 p7,8,9,10 · Software_3_ArrayStructureList.pdf. 강의의 개념·그림·코드 연산을 바탕으로 조건과 질문을 새로 작성한 자체 출제예요. 문제의 두 덧셈 루프는 S3 p8(①)과 p11(②)의 강의 코드를 발췌해 들여쓰기를 정리하고 설명 주석을 덧붙인 것이에요. 질문·입력 조건·검산은 자체 작성했어요.

</details>

<details><summary>힌트 보기</summary>

방식 ①에서 `A`의 계수는 `[8, 0, 7, 1]`, `B`의 계수는 `[10, 3, 0, 1]`이고, 방식 ②에서 `A`는 `[(8, 3), (7, 1), (1, 0)]`, `B`는 `[(10, 3), (3, 2), (1, 0)]`이에요.

</details>

<details><summary>풀이 보기</summary>

- (a) 같은 차수끼리 맞춘 계수 배열 `[8, 0, 7, 1]`과 `[10, 3, 0, 1]`을 더하면 내림차순 결과 계수는 `[18, 3, 7, 2]`($18x^3 + 3x^2 + 7x + 2$)예요. 루프 ①에서 차수가 높은 쪽 항만 출력했을 때 다른 쪽의 현재 항은 아직 비교·합산되지 않았으므로 인덱스를 유지해요. 배열 길이에 비례하므로 시간 복잡도는 `O(D+1)`이에요.
- (b) 루프 ②는 네 번 비교해요: 차수 `3`과 `3`은 `'='`라서 `(18, 3)`을 붙이고 `As·Bs`가 `1·1`칸 전진, `1`과 `2`는 `'<'`라서 `(3, 2)`를 붙이고 `1·2`칸, `1`과 `0`은 `'>'`라서 `(7, 1)`을 붙이고 `2·2`칸, `0`과 `0`은 `'='`라서 `(2, 0)`을 붙이고 `3·3`칸 전진해 함께 끝나요. 한쪽이 먼저 끝나면 다른 쪽 남은 항을 그대로 복사하고, 동차항 합 `tempcoef`가 `0`이면 저장만 건너뛰고 양쪽 인덱스를 전진해요. 각 항을 한 번씩 지나가므로 시간 복잡도는 `O(m+n)`이에요.

**정답:** (a) 결과는 `18x^3+3x^2+7x+2`, 내림차순 계수 `[18,3,7,2]`이며, 높은 차수만 출력한 경우 다른 입력의 현재 항은 아직 처리하지 않았기 때문에 인덱스를 유지한다. 모든 차수 배열의 시간 복잡도는 `O(D+1)`이다. (b) 쌍 결과는 `[(18,3),(3,2),(7,1),(2,0)]`이며, ②는 네 번 비교해 `=`에서 `(18,3)`을 붙이고 `As·Bs`가 `1·1`칸, `<`에서 `(3,2)`를 붙이고 `1·2`칸, `>`에서 `(7,1)`을 붙이고 `2·2`칸, `=`에서 `(2,0)`을 붙이고 `3·3`칸이 되어 함께 끝난다(`>`에서는 `A`만, `=`에서는 양쪽, `<`에서는 `B`만 전진). 한쪽 종료 뒤 다른 쪽 남은 항을 복사하고, 합이 `0`인 항은 저장하지 않으며, 희소 병합의 시간 복잡도는 `O(m+n)`이다.

코드 줄 수가 길다고 더 높은 차수의 시간복잡도라고 판단하지 않아요. 최고차수 `D`와 `0`이 아닌 항의 수 `m, n`은 서로 다른 입력 크기예요.

</details>

### P11. 구조체 대입과 비교 연산

**강의 예제 기반 자체 출제** S3 p17

`person` 타입은 아래와 같이 선언되어 있으며, `a`와 `b`는 유효하게 초기화된 `person` 구조체 변수예요.

```c
typedef struct person {
    char name[10];   // 문자 배열로 된 이름
    int age;         // 나이를 나타내는 정수값
    float height;    // 키를 나타내는 실수값
} person;
```

- (a) 구조체 대입 `b = a;`가 C에서 허용되는지, 이때 문자 배열 멤버 `name`도 함께 복사되는지, 그리고 대입 직후 `b.age`만 바꾸면 `a.age`도 바뀌는지 설명하세요.
- (b) 구조체 전체를 비교하는 `if (a > b)`가 C에서 허용되는지 답하고, 두 사람의 나이가 더 많은지를 비교하는 올바른 조건식을 쓰세요.

<details><summary>강의 예제 보기</summary>

S3 p17 · Software_3_ArrayStructureList.pdf. 강의의 개념·그림·코드 연산을 바탕으로 조건과 질문을 새로 작성한 자체 출제예요. 문제의 person 선언은 S3 p17의 강의 코드를 발췌해 들여쓰기를 정리한 것이에요. 질문·입력 조건·검산은 자체 작성했어요.

</details>

<details><summary>힌트 보기</summary>

`b = a;`는 같은 타입의 구조체 값 복사이고, 크기 비교는 특정 멤버를 직접 지정해야 해요.

</details>

<details><summary>풀이 보기</summary>

- (a) 같은 `person` 타입 사이의 대입 `b = a;`는 허용되며, 구조체 안에 들어 있는 문자 배열 멤버 `name`의 내용까지 포함한 모든 멤버 값이 별도 객체 `b`로 복사돼요. `b`와 `a`는 서로 다른 메모리 객체이므로 이후 `b.age`를 수정해도 `a.age`는 그대로 유지돼요.
- (b) C 언어는 구조체 전체에 대한 관계·동등 비교 연산(`a > b`, `a == b`)을 직접 지원하지 않으므로 컴파일 오류가 나요. 나이를 비교하려면 정수 멤버를 꺼내 `a.age > b.age`처럼 멤버별로 비교해야 해요.

**정답:** (a) 같은 `person` 타입의 `b=a`는 가능하고 멤버 값이 복사되어 `name` 배열의 내용도 복사된다. `b`와 `a`는 별도 객체이므로 `b.age`만 바꾸면 `a.age`는 유지된다. (b) 구조체 전체의 `a>b`는 C에서 허용되지 않으며 `a.age>b.age`로 나이를 비교한다.

구조체 대입이 가능하다고 해서 구조체 전체 비교 연산자 `>`나 `==`까지 가능하다고 확대하지 마세요.

</details>

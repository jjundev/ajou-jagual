이 문제를 봤을 때 떠올릴 개념과 공식

“배열이 차지하는 공간”은 원소 개수×원소 한 개의 크기예요. 배열은 같은 타입 원소를 연속 배치하므로 별도 행 포인터 10개가 붙는 것이 아니에요.

원소 수=10×20=200을 적어요.

왜 이렇게 푸는지 함께 따라가요

200×4=800바이트, 정답 (4)예요. 각 행이 20×4=80바이트이고 10행을 합쳐도 800이에요.

완성 답과 검산

두 방식 200원소×4와 10행×80이 같아요. 실제 C 검산에서도 sizeof(int)==4인 환경의 sizeof a가 800이에요.

10+20으로 원소 수를 세거나 int**의 저장 크기와 섞지 않아요.

설명을 닫고 다시 해 봐요

  1. 원소 수=10×20=200을 적어요.
  2. 행×열×int 크기 = 800
  3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

이 문제를 봤을 때 떠올릴 개념과 공식

“이전 값의 두 배”라는 점화식 two[i]=2×two[i−1]로 거듭제곱 power를 만들 수 있어요. C의 ^는 거듭제곱이 아니라 XOR이므로 쓰지 않아요.

종이에 적을 첫 줄

int two[10];
two[0] = 1;

왜 이렇게 푸는지 함께 따라가요

int main(void) {
    int two[10];
    two[0] = 1;
    for (int i=1; i<10; ++i) two[i] = 2*two[i-1];
    for (int i=0; i<10; ++i) printf("%d%s", two[i], i==9?"\n":" ");
    return 0;
}

출력은 1 2 4 8 16 32 64 128 256 512예요. 귀납적으로 첫 원소 2⁰이고 직전 2ⁱ⁻¹의 두 배가 2ⁱ예요. 독립 정수 거듭제곱과 C 출력 모두 대조해요.

이 문제에서 조심할 점

i=0부터 직전 원소를 읽으면 two[−1]로 배열 범위를 벗어나요.

설명을 닫고 다시 해 봐요

  1. int two[10]; two[0] = 1;
  2. two[0]=1, 이전 원소×2
  3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

첫 줄

P5. 행렬 예제를 C 배열과 세 쌍으로 표현하기

lecture-s03-p14-sparse-triples · 원 문제 보기

강의 예제 기반 자체 출제 S3 p14

아래 코드는 3 × 3 행렬 A를 C 2차원 배열로 초기화한 것이에요.

/* 3×3 행렬 A */
int A[3][3] = {{2, 3, 0}, {8, 9, 1}, {7, 0, 5}};

구할 것

  1. (a) 인덱스가 0부터 시작할 때, A에서 0이 아닌 원소를 (행, 열, 값) 삼중항으로 행 우선(row-major) 순서대로 나열하세요.
  2. (b) 행렬 A를 2차원 배열 전체(9개 칸)로 저장할 때와 삼중항(7개 항)으로 저장할 때 필요한 정수 개수를 비교하고, 행렬 크기 부가정보를 제외할 때 m × n 행렬(0이 아닌 항 t개)에서 삼중항 표현이 더 적은 정수를 쓰는 조건을 쓰세요.
강의 예제 보기

S3 p14 · Software_3_ArrayStructureList.pdf. 그림의 행렬 A를 C 초기화식으로 옮긴 자체 작성 코드이며 강의 원문 C 코드는 아닙니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

/* 강의의 행렬 A를 C 초기화식으로 옮긴 자체 작성 코드 */
int A[3][3]={{2,3,0},{8,9,1},{7,0,5}};

문제를 내 말로 읽어요

3 × 3 행렬 A에서 0이 아닌 원소만 골라 행 우선 순서의 (행, 열, 값) 삼중항으로 적고, 2차원 전체 배열과 삼중항 표현 중 어느 쪽이 정수를 덜 쓰는지 비교하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “행렬 예제를 C 배열과 세 쌍으로 표현하기”예요. 희소 행렬의 삼중항 표현은 0이 아닌 항 t개만 (row, col, value) 세 정수로 저장하므로 총 3t개의 정수를 써요. 따라서 3t < m × n일 때만 전체 배열보다 공간을 아껴요.

종이에 적을 첫 줄

행 0, 열 0의 값 2를 (0, 0, 2)로 적으며 행 우선 추적을 시작해요.

왜 이렇게 푸는지 함께 따라가요

(a) 행 0에서 (0, 0, 2), (0, 1, 3)을 기록하고 0은 빼요. 행 1에는 세 값이 모두 있으므로 (1, 0, 8), (1, 1, 9), (1, 2, 1)을 기록하고, 행 2에는 첫 칸과 끝 칸인 (2, 0, 7), (2, 2, 5)를 기록해요.

(b) 값만 저장하는 A[3][3]은 9개 정수를 쓰지만, 삼중항 표현은 7개 항마다 (행, 열, 값) 3개 정수가 필요해 7 × 3 = 21개 정수를 써요. 따라서 이 예제에서는 전체 배열이 더 작고, 행렬 크기 부가정보를 제외하면 3t < 행수 × 열수일 때 삼중항이 더 작아요.

완성 답과 검산

(a) 나열한 삼중항 7개의 개수가 전체 9칸 중 0인 두 칸((0, 2), (2, 1))을 뺀 9 - 2 = 7개와 일치하고, 행 번호 0 → 1 → 2 및 같은 행 안 열 번호가 오름차순이에요.

(b) t = 7, m × n = 9를 부등식 3t < m × n에 대입하면 21 < 9가 거짓이므로 전체 배열(9개)이 삼중항(21개)보다 작다는 결론과 일치해요.

이 문제에서 조심할 점

항 개수 7개와 실제 저장하는 정수 개수 21개를 혼동하지 마세요.

설명을 닫고 다시 해 봐요

  1. 행 0, 1, 2 순서로 0이 아닌 칸의 (행, 열, 값)을 적어요.
  2. 전체 배열 정수 개수 9와 삼중항 정수 개수 3t = 21을 비교해요.
  3. 삼중항이 유리해지는 조건 부등식 3t < 행수 × 열수를 확인해요.

첫 줄

행 0, 열 0의 값 2를 (0, 0, 2)로 적어요.

떠올릴 개념·공식

삼중항 t개는 3t개 정수를 쓰므로 3t < 행수 × 열수일 때만 전체 배열보다 작아요.

검산

(a) (0,0,2), (0,1,3), (1,0,8), (1,1,9), (1,2,1), (2,0,7), (2,2,5) (b) 전체 배열 9개 vs 삼중항 21개, 조건 3t < 행수×열수.

조건·구분과 확인

  • 3t<행수×열수는 행렬 크기 부가정보를 제외한 비교이며, 이 예는 9개 정수와 21개 정수라 전체 배열이 더 작아요.

P6. 하노이 코드의 매개변수 역할

lecture-s02-p19-hanoi · 원 문제 보기

강의 예제 기반 자체 출제 S2 p19

n >= 1개의 원판을 막대 from에서 보조 막대 tmp를 이용해 목표 막대 to로 옮기는 순환 함수예요.

void hanoi_tower(int n, char from, char tmp, char to)
{
    if(n==1) printf("원판1을%c에서%c으로옮긴다.\n",from,to);
    else {
        hanoi_tower(n-1,from,to,tmp);
        printf("원판%d을%c에서%c으로옮긴다.\n",n,from,to);
        hanoi_tower(n-1,tmp,from,to);
    }
}

구할 것

  1. (a) hanoi_tower(3, 'A', 'B', 'C')를 호출했을 때 출력되는 원판 이동 7회를 순서대로 원판번호:출발→도착 형식으로 쓰세요.
  2. (b) 첫 번째 순환 호출 hanoi_tower(n-1, from, to, tmp)에서 to와 tmp의 인자 순서가 바뀌는 이유와, 최소 이동 횟수의 점화식 $T(n)$(기저 조건 T(1) 포함) 및 T(3) 값을 쓰세요.
강의 예제 보기

S2 p19 · Software_2_Recursion.pdf. 강의 코드의 해당 연산을 발췌해 들여쓰기를 정리했습니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

void hanoi_tower(int n, char from, char tmp, char to)
{
    if(n==1) printf("원판1을%c에서%c으로옮긴다.\n",from,to);
    else {
        hanoi_tower(n-1,from,to,tmp);
        printf("원판%d을%c에서%c으로옮긴다.\n",n,from,to);
        hanoi_tower(n-1,tmp,from,to);
    }
}

문제를 내 말로 읽어요

원판 3개를 막대 A에서 C로 옮기는 hanoi_tower(3, 'A', 'B', 'C')의 이동 순서 7번을 추적하고, 순환 호출에서 막대 역할이 바뀌는 이유와 최소 이동 횟수 점화식을 구하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “하노이 코드의 매개변수 역할”이에요. 가장 큰 원판 n을 from에서 to로 옮기려면 위의 n-1개를 먼저 보조 막대 tmp로 옮겨야 하므로, 첫 순환 호출의 도착 막대는 tmp가 되고 최소 이동 횟수는 T(n) = 2T(n-1) + 1 = 2^n - 1을 따라요.

종이에 적을 첫 줄

가장 큰 원판 3을 A→C로 옮기기 전후로 hanoi_tower(2, 'A', 'C', 'B')와 hanoi_tower(2, 'B', 'A', 'C')를 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) 첫 호출 hanoi_tower(2, 'A', 'C', 'B')가 위 2개 원판을 B로 옮기며 1:A→C, 2:A→B, 1:C→B를 출력해요. 이어서 원판 3을 옮기는 3:A→C를 출력하고, 두 번째 호출 hanoi_tower(2, 'B', 'A', 'C')가 1:B→A, 2:B→C, 1:A→C를 출력해요.

(b) 가장 큰 원판을 to로 옮기기 전에 위 n-1개를 보조 막대 tmp에 모아 두어야 하므로 첫 순환 호출에서는 tmp가 도착 막대, to가 보조 막대 역할을 맡아요. 위 n-1개 이동, 가장 큰 원판 1회, 다시 위 n-1개 이동이 필요하므로 T(1) = 1, T(n) = 2T(n-1) + 1(일반식 $2^n - 1$)이며 T(3) = 7이에요.

완성 답과 검산

(a) 총 출력 줄 수는 3 + 1 + 3 = 7줄이고, 가운데 4번째 이동이 3:A→C이며 원판 1이 홀수 번째(1, 3, 5, 7번째)마다 이동하므로 규칙과 일치해요.

(b) 점화식에 대입하면 T(1) = 1, T(2) = 2(1) + 1 = 3, T(3) = 2(3) + 1 = 7로 일반식 $2^3 - 1 = 7$과 일치해요.

이 문제에서 조심할 점

from, tmp, to는 고정된 막대 이름이 아니라 현재 호출에서 맡은 역할이에요.

설명을 닫고 다시 해 봐요

  1. n = 3 호출을 n = 2 앞뒤 호출과 원판 3 이동으로 나누어 7줄을 적어요.
  2. 첫 순환 호출에서 왜 to와 tmp 자리가 바뀌는지 설명해요.
  3. 점화식 T(n) = 2T(n-1) + 1로 T(3) = 7을 검산해요.

첫 줄

맨 큰 원판 3을 A→C로 옮기려면 위 2개를 A→B로 먼저 옮겨요.

떠올릴 개념·공식

첫 순환 호출은 도착 막대가 tmp이고, 이동 횟수는 T(n) = 2T(n-1) + 1 = 2^n - 1이에요.

검산

(a) 1:A→C, 2:A→B, 1:C→B, 3:A→C, 1:B→A, 2:B→C, 1:A→C (b) T(1)=1, T(n)=2T(n-1)+1, T(3)=7.

조건·구분과 확인

  • n≥1에서 from·tmp·to는 고정된 막대 이름이 아니라 현재 호출의 출발·임시·도착 역할이에요.

P7. 계수 배열의 순서와 공간 낭비

lecture-s03-p7-polynomial · 원 문제 보기

강의 예제 기반 자체 출제 S3 p7

MAX_DEGREE는 6 이상인 상수예요. 아래 구조체는 다항식의 계수를 최고차항부터 내림차순으로 저장하므로 coef[i]는 $x^{\text{degree}-i}$의 계수예요.

typedef struct {
    int degree;
    float coef[MAX_DEGREE];
} polynomial;
polynomial a = {5, {10, 0, 0, 0, 6, 3}};

구할 것

  1. (a) 위 저장 규칙에 따라 구조체 변수 a가 나타내는 다항식과 a.coef[4]에 해당하는 항의 차수를 쓰세요.
  2. (b) $1000$차 항과 상수항만 있는 다항식(예: $10x^{1000} + 3$)을 이 방식(모든 차수의 계수 배열)과 (계수, 차수) 쌍 배열 방식으로 저장할 때 필요한 유효 항목 수를 비교하세요.
강의 예제 보기

S3 p7 · Software_3_ArrayStructureList.pdf. 강의 코드의 해당 연산을 발췌해 들여쓰기를 정리했습니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

typedef struct {
    int degree;
    float coef[MAX_DEGREE];
} polynomial;
polynomial a = {5,{10,0,0,0,6,3}};

문제를 내 말로 읽어요

최고차항부터 내림차순으로 계수를 저장하는 polynomial 구조체에서 배열 인덱스와 항의 차수를 대응시키고, 희소 다항식을 저장할 때 두 표현 방식의 공간 효율을 비교하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “계수 배열의 순서와 공간 낭비”예요. coef[i]가 $x^{\text{degree}-i}$의 계수이므로 인덱스 i의 차수는 degree - i예요. 최고차수가 $D$일 때 모든 차수 배열은 D + 1칸을 쓰지만, 쌍 배열 방식은 0이 아닌 항의 개수만큼만 저장해요.

종이에 적을 첫 줄

a.degree = 5이므로 인덱스 i의 차수는 5 - i라고 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) degree = 5이고 coef = {10, 0, 0, 0, 6, 3}이므로 coef[0] = 10은 5차항, coef[1..3] = 0은 4, 3, 2차항, coef[4] = 6은 5 - 4 = 1차항, coef[5] = 3은 상수항이에요. 따라서 다항식은 10x^5 + 6x + 3이고 coef[4]는 1차 항이에요.

(b) 1000차 항과 상수항만 있는 다항식을 모든 차수 계수 배열로 저장하면 1000차부터 0차까지 총 1001개 계수를 저장해야 해요. 반면 (계수, 차수) 쌍 방식은 0이 아닌 2개 항(계수와 차수 각각 2개)만 저장해요.

완성 답과 검산

(a) 배열 원소 개수 6개는 degree + 1 = 5 + 1 = 6과 일치하고, i = 4를 degree - i에 넣으면 차수 1이 나와요.

(b) $10x^{1000} + 3$에서 중간 999개 차수의 계수는 모두 0이므로 1001 - 999 = 2개 항만 0이 아니라는 점이 두 표현의 항목 수 차이와 일치해요.

이 문제에서 조심할 점

이 구조체에서는 coef[0]이 상수항이 아니라 최고차항(x^degree)의 계수예요.

설명을 닫고 다시 해 봐요

  1. coef[i]의 차수 공식 degree - i에 i = 0, 4, 5를 대입해 다항식을 적어요.
  2. 1000차 희소 다항식에서 모든 차수 배열이 쓰는 칸 수 1001을 구해요.
  3. (계수, 차수) 쌍 배열이 저장하는 항 수 2개와 비교해요.

첫 줄

인덱스 i의 차수는 degree - i = 5 - i라고 적어요.

떠올릴 개념·공식

coef[0]은 5차, coef[4]는 1차, coef[5]는 상수항이며 모든 차수 배열은 degree + 1칸을 써요.

검산

(a) 10x^5+6x+3, coef[4]는 1차 항 (b) 모든 차수 배열 1001개 계수 vs 쌍 방식 2개 항.

조건·구분과 확인

  • 예제 MAX_DEGREE는 6 이상이며, 쌍 방식의 2개 항은 계수 2개와 차수 2개를 함께 저장한다는 뜻이에요.

P8. 자체 참조 구조체의 링크 타입

lecture-s03-p18-self-reference · 원 문제 보기

강의 예제 기반 자체 출제 S3 p18

아래는 문자열 데이터와 다음 노드를 가리키는 링크 필드를 가진 자체 참조 구조체 ListNode 정의예요.

typedef struct ListNode {
    char data[10];
    /* link 필드를 선언하세요 */
} ListNode;

구할 것

  1. (a) 주석 자리에 들어갈 link 필드 선언문을 복원하고, 유효한 노드를 가리키는 포인터 ListNode *p에서 데이터와 다음 노드 주소에 접근하는 식을 각각 쓰세요.
  2. (b) link를 포인터가 아닌 struct ListNode link;처럼 구조체 값 멤버로 선언할 수 없는 이유를 설명하세요.
강의 예제 보기

S3 p18 · Software_3_ArrayStructureList.pdf. 강의 코드의 해당 연산을 발췌해 들여쓰기를 정리했습니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

typedef struct ListNode {
    char data[10];
    struct ListNode *link;
} ListNode;

문제를 내 말로 읽어요

연결 리스트 노드를 만드는 자체 참조 구조체 ListNode에서 다음 노드를 가리키는 link 멤버의 자료형과 포인터 접근 식을 쓰고, 왜 포인터가 아닌 구조체 값으로는 선언할 수 없는지 알아보는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “자체 참조 구조체의 링크 타입”이에요. 구조체 정의 내부에서는 아직 typedef 이름 ListNode가 완성되지 않았으므로 태그 struct ListNode *link;로 자기 자신을 가리키는 포인터를 선언하고, 구조체 포인터 p에서는 -> 연산자로 멤버에 접근해요.

종이에 적을 첫 줄

struct ListNode *link;처럼 다음 노드의 주소를 담는 포인터 필드를 먼저 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) 구조체 정의 안에서는 태그 이름 struct ListNode를 써서 struct ListNode *link;로 선언해요. 유효한 노드를 가리키는 ListNode *p에서 데이터 멤버는 p->data, 다음 노드를 가리키는 포인터 멤버는 p->link로 읽어요.

(b) 포인터는 다른 노드의 주소만 보관하므로 크기가 일정(예: 4 또는 8바이트)하지만, struct ListNode link;처럼 같은 구조체를 값으로 포함하면 자기 자신 안에 똑같은 구조체가 무한히 중첩되어 전체 크기를 결정할 수 없어요.

완성 답과 검산

(a) (*p).data와 p->data, (*p).link와 p->link는 서로 동치이며, p->link의 타입이 struct ListNode *이므로 다음 노드의 주소를 담을 수 있어요.

(b) 만약 값 멤버를 허용한다면 sizeof(ListNode) = 10 + sizeof(ListNode)라는 모순된 방정식이 되어 유한한 바이트 크기가 존재하지 않음을 바로 확인할 수 있어요.

이 문제에서 조심할 점

포인터 멤버를 선언했다고 해서 다음 노드가 자동으로 할당되지는 않아요.

설명을 닫고 다시 해 봐요

  1. 구조체 태그를 사용한 struct ListNode *link; 선언과 p->data, p->link 식을 적어요.
  2. 자기 자신을 값 멤버로 넣을 때 바이트 크기가 왜 무한해지는지 설명해요.

첫 줄

struct ListNode *link;처럼 주소를 저장하는 필드를 선언해요.

떠올릴 개념·공식

구조체 내부에서는 struct ListNode * 태그를 쓰고, 포인터 p는 p->data, p->link로 접근해요.

검산

(a) struct ListNode *link;, p->data, p->link (b) 값 포함 시 무한 중첩으로 크기 결정 불가.

조건·구분과 확인

  • p는 유효한 노드를 가리킨다고 가정해요. link 포인터 멤버를 선언해도 다음 노드가 자동으로 할당되지는 않아요.

P9. 배열 ADT와 행 우선 주소 계산

lecture-s03-p3-array-adt-address · 원 문제 보기

강의 예제 기반 자체 출제 S3 p3

배열 ADT는 <인덱스, 요소> 쌍의 집합을 객체로 정의하고 create(size), retrieve(A, i), store(A, i, item) 연산을 제공해요. C의 2차원 배열은 메모리에 행 우선(row-major) 순서로 연속 배치돼요.

int A[3][4]; /* 시작 주소 base = 1000, sizeof(int) = 4 */

구할 것

  1. (a) 배열 ADT의 객체를 쓰고, create(6), store(A, 2, 7), retrieve(A, 2)가 각각 수행하는 일을 설명하세요.
  2. (b) 시작 주소가 1000이고 sizeof(int) == 4일 때 int A[3][4]에서 A[2][1]의 바이트 주소를 구하고, 인덱스 (2, 1)이 유효 범위 안에 있는지 확인하세요.
강의 예제 보기

S3 p3 · 추가 근거 p4,5 · Software_3_ArrayStructureList.pdf. 강의의 개념·그림·코드 연산을 바탕으로 조건과 질문을 새로 작성한 자체 출제예요. 제시 코드는 있는 경우 학습 확인용 자체 코드이며 강의 원문 발췌가 아니에요. 질문·입력 조건·검산은 자체 작성했어요.

문제를 내 말로 읽어요

배열 추상 자료형(ADT)의 객체와 create·store·retrieve 연산의 의미를 정리하고, 행 우선으로 배치된 2차원 배열 int A[3][4]에서 A[2][1]의 메모리 주소를 계산하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

‘객체와 연산’은 추상 자료형(ADT)의 단서이고, ‘C의 2차원 배열’은 행 우선(row-major) 연속 배치의 단서예요. 열 수가 C일 때 A[r][c] 앞에는 r × C + c개 원소가 놓이므로 시작 주소 base에 (r × C + c) × sizeof(Element)를 더하면 바이트 주소가 돼요.

종이에 쓰는 첫 줄

A[2][1] 앞의 원소 수 = 2 × 4 + 1 = 9라고 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) 배열 ADT의 객체는 <인덱스, 요소> 쌍의 집합이에요. create(6)은 6개 요소를 담는 배열을 생성하고, store(A, 2, 7)은 인덱스 2 위치에 7을 저장하며, retrieve(A, 2)는 그 위치에 저장된 7을 반환해요.

(b) int A[3][4]는 한 행에 4개 원소가 있으므로 A[2][1] 앞에는 행 0과 행 1의 2 × 4 = 8개와 행 2의 첫 원소 1개를 합쳐 총 9개 원소가 있어요. 원소 하나가 4바이트이므로 주소는 1000 + 9 × 4 = 1036이고, 0 <= 2 < 3, 0 <= 1 < 4이므로 유효한 인덱스예요.

완성 답과 검산

(a) 인덱스 2에 store(A, 2, 7)을 수행한 직후 같은 인덱스 2를 retrieve(A, 2)로 읽으면 방금 저장한 7이 나오는 것이 배열 ADT의 정의와 일치해요.

(b) 행 시작 주소를 차례로 적으면 A[0][0] = 1000, A[1][0] = 1016, A[2][0] = 1032이고, 여기서 한 칸(4바이트) 더 가면 A[2][1] = 1036이 되어 공식 결과와 일치해요.

이 문제에서 조심할 점

행 번호에 행 수 3을 곱하지 않고 한 행의 열 수 4를 곱해요. 범위를 벗어난 인덱스에 주소 공식을 적용해 유효한 접근이라고 하지 않아요.

설명을 닫고 다시 해 봐요

  1. 배열 ADT의 객체(<인덱스, 요소> 쌍)와 세 연산의 역할을 적어요.
  2. A[2][1] 앞의 원소 수 2 × 4 + 1 = 9와 바이트 주소 1036을 계산해요.
  3. 행·열 인덱스가 0 <= r < 3, 0 <= c < 4 범위 안인지 확인해요.

떠올릴 개념·공식

배열 ADT는 <인덱스, 요소> 쌍의 집합이고, 2차원 행 우선 배열 A[r][c] 앞에는 r × 열수 + c개 원소가 있어요.

첫 줄

A[2][1] 앞의 원소 수 = 2 × 4 + 1 = 9라고 적어요.

핵심 답

(a) 객체는 인덱스와 요소 쌍의 집합, create(6)은 6개 요소 생성, store는 2번에 7 저장, retrieve는 7 반환 (b) 주소 1000 + 9×4 = 1036, 0<=2<3·0<=1<4로 유효.

P10. 두 표현의 다항식 덧셈과 남은 항 처리

lecture-s03-p11-polynomial-add-merge · 원 문제 보기

강의 예제 기반 자체 출제 S3 p11

다항식 $A = 8x^3 + 7x + 1$과 $B = 10x^3 + 3x^2 + 1$을 두 가지 배열 표현으로 더해요. 방식 ①(가)은 최고차수 degree부터 상수항까지 모든 계수를 내림차순 배열 coef에 저장하고, 방식 ②(나)는 0이 아닌 항만 (coef, expon) 쌍 배열 terms에 내림차순으로 저장해요.

/* ① 모든 차수 배열 덧셈 루프 (초기 Apos=Bpos=Cpos=0, degree_a=A.degree, degree_b=B.degree) */
while( Apos<=A.degree && Bpos<=B.degree ){
    if( degree_a > degree_b ){ C.coef[Cpos++] = A.coef[Apos++]; degree_a--; }
    else if( degree_a == degree_b ){ C.coef[Cpos++] = A.coef[Apos++] + B.coef[Bpos++]; degree_a--; degree_b--; }
    else { C.coef[Cpos++] = B.coef[Bpos++]; degree_b--; }
}
/* ② 희소 항 배열 덧셈 루프 (terms[As..Ae]는 A, terms[Bs..Be]는 B) */
while( As <= Ae && Bs <= Be )
    switch(compare(terms[As].expon, terms[Bs].expon)){
    case '>': attach(terms[As].coef, terms[As].expon); As++; break;
    case '=': tempcoef = terms[As].coef + terms[Bs].coef;
              if( tempcoef ) attach(tempcoef, terms[As].expon);
              As++; Bs++; break;
    case '<': attach(terms[Bs].coef, terms[Bs].expon); Bs++; break;
    }

구할 것

  1. (a) 방식 ①로 더한 결과 계수 배열 C.coef를 내림차순으로 쓰고, 루프 ①에서 차수가 큰 쪽 항만 C로 옮길 때 다른 쪽 인덱스는 그대로 두는 이유와 최고차수 $D$에 대한 시간 복잡도를 쓰세요.
  2. (b) 방식 ②의 루프 ②로 $A$와 $B$를 더할 때 매 비교 단계의 compare 결과·attach되는 (coef, expon) 쌍·전진 칸수(As, Bs)를 순서대로 쓰고, 한쪽 종료 후 남은 항 처리·동차항 합이 0일 때 처리·두 입력 항 수 $m, n$에 대한 시간 복잡도를 설명하세요.
강의 예제 보기

S3 p11 · 추가 근거 p7,8,9,10 · Software_3_ArrayStructureList.pdf. 강의의 개념·그림·코드 연산을 바탕으로 조건과 질문을 새로 작성한 자체 출제예요. 문제의 두 덧셈 루프는 S3 p8(①)과 p11(②)의 강의 코드를 발췌해 들여쓰기를 정리하고 설명 주석을 덧붙인 것이에요. 질문·입력 조건·검산은 자체 작성했어요.

문제를 내 말로 읽어요

두 다항식 $A = 8x^3 + 7x + 1$과 $B = 10x^3 + 3x^2 + 1$을 모든 차수 계수 배열 방식(①)과 희소 항 쌍 배열 방식(②)으로 더하며, 각 루프의 인덱스 이동·예외 처리·시간 복잡도를 비교하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

‘내림차순으로 정렬된 두 항 배열’은 병합(merge)의 단서예요. 차수가 큰 항을 먼저 결과에 복사하면 그쪽 인덱스만 전진하고, 차수가 같을 때만 두 계수를 더해 양쪽 인덱스를 함께 전진해요. 입력 포인터가 후퇴하지 않으므로 배열 길이에 비례하는 선형 시간이 걸려요.

종이에 쓰는 첫 줄

방식 ①의 계수 배열 A = [8, 0, 7, 1], B = [10, 3, 0, 1]과 방식 ②의 항 배열 A = [(8, 3), (7, 1), (1, 0)], B = [(10, 3), (3, 2), (1, 0)]을 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) 방식 ①은 같은 차수 자리끼리 맞춰 [8, 0, 7, 1] + [10, 3, 0, 1] = [18, 3, 7, 2]($18x^3 + 3x^2 + 7x + 2$)를 얻어요. 루프 ①에서 높은 차수 쪽 항만 결과로 옮겼을 때 다른 입력의 현재 항은 아직 비교·합산되지 않았으므로 인덱스를 그대로 두어요. 최고차수 $D$에 대해 총 $D + 1$칸을 순회하므로 시간 복잡도는 O(D+1)이에요.

(b) 방식 ②의 루프 ②는 네 번 비교해요: 차수 3과 3은 =이므로 (18, 3)을 붙이고 As·Bs가 1·1칸, 1과 2는 <이므로 (3, 2)를 붙이고 1·2칸, 1과 0은 >이므로 (7, 1)을 붙이고 2·2칸, 0과 0은 =이므로 (2, 0)을 붙이고 3·3칸 전진해 함께 끝나요(>에서는 A만, =에서는 양쪽, <에서는 B만 전진). 한쪽이 먼저 끝나면 남은 입력의 항들을 뒤에 그대로 복사하고, 같은 차수 계수 합이 0이면 저장하지 않되 양쪽 인덱스는 전진해요. 두 입력 항 수 $m, n$에 대해 시간 복잡도는 O(m+n)이에요.

완성 답과 검산

(a) $x = 1$을 대입하면 $A(1) = 16$, $B(1) = 14$이고 결과 다항식 $18x^3 + 3x^2 + 7x + 2$에 $x = 1$을 대입한 값도 $18 + 3 + 7 + 2 = 30$으로 일치해요.

(b) 네 번의 비교에서 전진한 총 칸수는 As가 1 + 0 + 1 + 1 = 3칸, Bs가 1 + 1 + 0 + 1 = 3칸으로 두 입력의 항 개수(각 3개)와 정확히 맞아떨어져요.

이 문제에서 조심할 점

코드 줄 수가 길다고 더 높은 차수의 시간복잡도라고 판단하지 않아요. 두 표현의 D와 m, n은 서로 다른 입력 크기예요.

설명을 닫고 다시 해 봐요

  1. 방식 ①의 결과 계수 배열 [18, 3, 7, 2]와 O(D+1) 복잡도를 적어요.
  2. 방식 ②의 4회 비교에서 compare 결과, attach 쌍, As·Bs 전진 칸수를 표로 적어요.
  3. 한쪽 조기 종료 시 나머지 복사와 계수 합 0 상쇄 처리 및 O(m+n)을 확인해요.

떠올릴 개념·공식

차수가 큰 쪽만 소비하고 같을 때만 양쪽을 합산·소비하는 병합(merge) 구조로 선형 시간에 덧셈해요.

첫 줄

A의 계수 [8, 0, 7, 1], B의 계수 [10, 3, 0, 1]이라고 적어요.

핵심 답

(a) 18x^3+3x^2+7x+2, 계수 [18,3,7,2], 시간 복잡도 O(D+1) (b) 쌍 [(18,3),(3,2),(7,1),(2,0)], 비교 4회(= → < → > → =), 남은 항 복사·합 0 미저장, 시간 복잡도 O(m+n).

조건·구분과 확인

  • 합 0을 저장하지 않아도 양쪽 인덱스는 전진해요. O(D+1)의 D는 최고차수, O(m+n)의 m,n은 입력 항 수라 서로 다른 척도예요.

P11. 구조체 대입과 비교 연산

lecture-s03-p17-struct-assignment-comparison · 원 문제 보기

강의 예제 기반 자체 출제 S3 p17

person 타입은 아래와 같이 선언되어 있으며, a와 b는 유효하게 초기화된 person 구조체 변수예요.

typedef struct person {
    char name[10];   // 문자 배열로 된 이름
    int age;         // 나이를 나타내는 정수값
    float height;    // 키를 나타내는 실수값
} person;

구할 것

  1. (a) 구조체 대입 b = a;가 C에서 허용되는지, 이때 문자 배열 멤버 name도 함께 복사되는지, 그리고 대입 직후 b.age만 바꾸면 a.age도 바뀌는지 설명하세요.
  2. (b) 구조체 전체를 비교하는 if (a > b)가 C에서 허용되는지 답하고, 두 사람의 나이가 더 많은지를 비교하는 올바른 조건식을 쓰세요.
강의 예제 보기

S3 p17 · Software_3_ArrayStructureList.pdf. 강의의 개념·그림·코드 연산을 바탕으로 조건과 질문을 새로 작성한 자체 출제예요. 문제의 person 선언은 S3 p17의 강의 코드를 발췌해 들여쓰기를 정리한 것이에요. 질문·입력 조건·검산은 자체 작성했어요.

문제를 내 말로 읽어요

person 구조체에서 변수 간 대입 b = a;가 배열 멤버까지 복사하는지, 복사 뒤 한쪽 멤버만 수정할 때 다른 쪽이 영향을 받는지, 그리고 구조체 비교 연산을 어떻게 써야 하는지 묻는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

‘구조체 대입’은 모든 멤버의 값 복사이고, ‘나이가 더 많음’은 비교할 특정 멤버의 선택을 뜻해요. C는 같은 구조체 타입의 통째 대입 b = a;를 지원하지만 구조체 전체에 대한 비교 연산자(>, ==)는 정의하지 않아요.

종이에 쓰는 첫 줄

b = a: 같은 타입의 구조체 값 복사(내부 배열 멤버 포함), a > b: 구조체 전체 비교 불가라고 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) 같은 person 타입끼리의 b = a; 대입은 가능하며, 구조체 안의 문자 배열 멤버 name까지 모든 멤버 값이 별도 객체 b로 복사돼요. 두 객체는 서로 다른 메모리 공간을 쓰므로 대입 뒤 b.age만 바꿔도 a.age는 원래 값 그대로 유지돼요.

(b) 구조체 전체를 비교하는 if (a > b)는 C에서 허용되지 않아 컴파일 오류가 나요. 나이가 더 많은지 비교하려면 정수 멤버를 직접 지정해 a.age > b.age로 비교해야 해요.

완성 답과 검산

(a) 예를 들어 a.age = 20일 때 b = a; 뒤 b.age = 21;을 실행하면 a.age는 20, b.age는 21로 서로 독립임을 확인할 수 있어요.

(b) a.age와 b.age는 모두 int 타입이므로 a.age > b.age는 int끼리의 유효한 관계 연산식이 돼요.

이 문제에서 조심할 점

구조체 대입 가능을 구조체 > 비교 가능으로 확대하지 않아요. 배열 멤버가 있다는 이유로 구조체 대입 전체가 금지된다고 하지 않아요.

설명을 닫고 다시 해 봐요

  1. b = a; 실행 시 name 배열 복사와 b.age 수정의 독립성을 적어요.
  2. a > b가 왜 불가능한지와 올바른 나이 비교 식 a.age > b.age를 적어요.

떠올릴 개념·공식

C는 같은 구조체 타입의 값 대입(b = a)을 허용하지만 구조체 전체 비교(a > b)는 허용하지 않아요.

첫 줄

b = a: 같은 타입의 구조체 값 복사라고 적어요.

핵심 답

(a) b=a 가능, name 배열도 복사되며 b.age 수정 시 a.age는 유지됨 (b) a>b 불가, a.age>b.age로 비교.

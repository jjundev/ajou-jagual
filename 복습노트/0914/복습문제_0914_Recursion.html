i가 정해지면 j는 몇 번 도나요? j가 0이 아니라 i에서 시작해요.

풀이 보기
  1. 안쪽 k 루프: k = 0 … 29, 대입 30번이에요.
  2. 가운데 j 루프: j = i … n−1, 모두 $n - i$번 돌아요. 그래서 i마다 대입은 $30(n - i)$번이에요.

P6. 자연수 ADT의 연산 계약

아래는 자연수 추상 데이터 타입(ADT) Nat_No의 일부 연산을 정의한 수학적 유사코드예요.

Nat_No
zero() ::= return 0;
sub(x,y) ::= if(x<y) return 0;
             else return x-y;
add(x,y) ::= if((x+y)<=INT_MAX) return x+y;
             else return INT_MAX;
  1. (a) Nat_No의 객체 범위를 쓰고, sub(3, 5), sub(5, 3), add(INT_MAX, 1)의 반환 결과를 각각 구하세요.

자연수 범위 밖의 음수가 나오지 않도록 sub는 작은 수에서 큰 수를 뺄 때 0을 반환해요.

풀이 보기
  1. (a) 객체 범위는 0..INT_MAX예요. sub(3, 5)는 3 < 5이므로 0, sub(5, 3)은 5 - 3 = 2, add(INT_MAX, 1)은 수학적 합이 상한을 넘으므로 INT_MAX를 반환해요.
  2. (b) ADT는 객체와 연산 계약(인터페이스)만 공개하고 내부 구현 표현을 숨기므로 사용자는 내부 표현을 몰라도 돼요. C의 signed int에서는 x + y가 INT_MAX를 넘는 순간 오버플로(미정의 동작)가 일어나므로, 덧셈 전에 x > INT_MAX - y를 먼저 검사해야 해요.
  3. 수업과의 연결: 자판기 비유처럼 추상 데이터 타입(ADT)이 무엇을 하는지(계약)와 어떻게 구현하는지를 분리한다는 내용과 이어져요.

정답: (a) 객체 범위: 0..INT_MAX, 결과: 0, 2, INT_MAX (b) ADT는 객체와 연산 계약을 제공하고 내부 표현을 숨기기 때문이며, C에서는 x + y 자체가 오버플로할 수 있으므로 x > INT_MAX - y를 먼저 검사해야 한다.

위 유사코드를 그대로 C의 정수 연산이라고 간주해 INT_MAX + 1을 실행하지 마세요.

강의 예제 기반 자체 출제 S2 p4

아래 순환 함수 factorial(n)에서 n은 0 이상의 정수이고, 계산 결과는 int 범위에 들어간다고 가정해요.

int factorial(int n)
{
    if(n <= 1) return 1;
    else return n * factorial(n-1);
}
  1. (a) factorial(3)을 실행할 때 호출 순서와 반환값 순서를 차례로 쓰고, factorial(0)의 반환값도 구하세요.
  2. (b) 이 함수에서 순환을 멈추는 종료 조건과 호출마다 문제 크기가 줄어드는 부분을 찾아 설명하세요.

힌트 보기

먼저 종료 조건 n <= 1을 표시해요. factorial(3)은 아직 곱셈을 끝내지 못하고 factorial(2)를 기다려요.

풀이 보기
  1. (a) factorial(3)은 factorial(2)를, factorial(2)는 factorial(1)을 차례로 호출하므로 호출 인자 순서는 3 → 2 → 1이에요. factorial(1)이 1을 반환하면 역순으로 2 * 1 = 2, 3 * 2 = 6이 계산되어 반환값 순서는 1 → 2 → 6이고, factorial(0)은 0 <= 1을 만족해 1을 반환해요.
  2. (b) 종료 조건은 n <= 1일 때 1을 반환하는 기저 분기이며, 순환 호출 인자 n - 1이 매 호출마다 문제 크기를 1씩 줄여 결국 종료 조건에 도달하게 해요.
  3. 수업과의 연결: 순환 알고리즘의 두 필수 조건(종료 조건과 문제 크기 감소) 및 factorial(3)의 스택 호출·반환 추적과 이어져요.

정답: (a) 호출 순서: 3 → 2 → 1, 반환값 순서: 1 → 2 → 6, factorial(0) = 1 (b) n <= 1이 종료 조건이고 n - 1로 문제 크기가 줄어든다.

호출하는 순간 3 * 2 * 1이 한 번에 계산된다고 생각하지 마세요. 아직 끝나지 않은 곱셈이 각 호출에 남아 있어요.

풀이 보기

원문 그대로라면 k는 0에서 변하지 않아요. n≥2일 때 i=1,j=0에서 넷째 루프에 진입하면 k<30이 계속 참이에요. 배열 경계 이탈과 signed int 오버플로 등 미정의 동작 위험이 있어 정상 종료하는 유한 T(n)을 줄 수 없어요. 아래 T(n)은 문제에 명시한 넷째 증가식만 k++로 보정한 조건에서의 대입 횟수예요.

  1. 넷째 루프: k가 0부터 29까지 돌아요. 한 번 들어가면 대입이 30번이에요.
  2. 셋째 루프 for(p=0; j<i; j++): 둘째 루프가 막 시작해 j = 0일 때, j를 0 → 1 → … → i로 올리며 i번 돌아요. j = i가 되면 멈춰요.
  3. 그다음 둘째 루프가 j를 더 올려도 j > i라서 셋째 루프는 다시 돌지 않아요. 그래서 i마다 대입은 $30 \cdot i$번이에요.
  4. i별로 세면: i = 0 → 0번, i = 1 → 30번, i = 2 → 60번, …, i = n−1 → $30(n-1)$번
  5. 모두 더해요. $$30\,(0 + 1 + 2 + \cdots + (n-1)) = 30 \cdot \frac{n(n-1)}{2}$$ 그래서 $T(n) = 30n(n-1)/2$예요. n = 3이면 0 + 30 + 60 = 90 = 30·3·2/2로 맞아요.
  6. 빅오: $T(n) = 15n^2 - 15n$에서 최고차항 $n^2$만 남기고 계수 15를 떼면 $O(n^2)$예요. 루프가 네 겹이어도 $O(n^4)$가 아니에요.
  7. 수업과의 연결: 0914 수업 S1 p29에서 알고리즘 C의 대입 연산을 루프 횟수로 센 방법 그대로예요. 교수님이 루프 개수만 보지 말고 "얼마나 가는지"도 보라고 했어요(40:35).

정답: $T(n) = 30n(n-1)/2$, 빅오 표기법 $O(n^2)$

  1. 넷째 루프: k = 1 … 29, 대입 29번이에요. k<30이지만 1부터 시작해서 하나 적어요.
  2. 셋째 루프 for(p=1; j<=i; j++): 둘째 루프가 막 시작해 j = 1일 때, j를 1 → 2 → … → i로 올리며 i번 돌아요. j = i + 1이 되면 멈춰요.

#### 문제를 내 말로 읽어요

대입문 실행 횟수만 세어요. n은 비음수 정수이고 배열의 유효한 접근 범위를 가정해요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

j가 i부터 시작하므로 각 i의 j 반복 횟수는 n−i예요. k는 입력과 무관한 상수 30번이에요. 중첩 개수만 보고 n³이라고 판단하지 않아요.

#### 종이에 적을 첫 줄

i=0일 때 j는 n번, i=1일 때 n−1번이라고 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

T(n)=30×[n+(n−1)+…+1]=30n(n+1)/2예요. 상수와 낮은 차수를 지우면 O(n²), 더 정확한 성장률은 Θ(n²)이에요. 합 공식은 앞뒤 항을 짝지으면 각 쌍의 합이 n+1인 데서 나와요.

#### 완성 답과 검산

n=3이면 j 횟수는 3+2+1=6이라 대입은 180번이에요. n=0에서는 0번, n=1에서는 30번으로 공식과 맞아요. 별도 반복문으로 n=0..20의 횟수를 확인해요.

#### 이 문제에서 조심할 점

변형 카드의 k 상수와 아래 기출 원문 30을 구별해요. 답은 현재 카드의 상수로 계산해요.

#### 설명을 닫고 다시 해 봐요

1. i=0일 때 j는 n번, i=1일 때 n−1번이라고 적어요.
2. 상수×삼각수, O(n²)
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

상수×삼각수, O(n²)

#### 검산

### P2. 자기 자신을 다시 부르는 기법

2018-mid-c102-q1 · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0914_Recursion-%EB%AC%B8%EC%A0%9C.pdf#page=2)

함수가 수행 도중에 자기 자신을 다시 호출하여 문제를 해결하는 기법을 ( )이라고 해요. 빈칸을 채워 보세요.

#### 문제를 내 말로 읽어요

함수가 자기 자신을 호출한다는 설명에 맞는 이름을 쓰는 문제예요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

“자기 자신을 다시 호출”은 recursion, 수업 용어로 순환(재귀)이에요. 일반 반복 iteration은 루프를 돌지만 별도의 자기 호출을 만들지 않아요.

#### 종이에 적을 첫 줄

빈칸에 순환(recursion)을 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

답은 순환, 또는 동의어 재귀예요. 예를 들어 factorial(3)이 factorial(2)를 호출하면 작은 문제의 답을 받아 현재 답을 만들어요. 올바른 순환은 즉시 답을 주는 바닥 조건과 그 조건으로 다가가는 감소를 함께 가져요.

#### 완성 답과 검산

반복문만 있는 sum은 자기 호출이 없어요. 반대로 함수 안의 자기 호출은 루프가 없어도 순환이에요. 이 차이로 용어를 확인해요.

#### 이 문제에서 조심할 점

함수 이름을 두 번 썼다고 항상 실행 중 자기 호출은 아니에요. 실제 호출 관계를 보아요.

#### 설명을 닫고 다시 해 봐요

1. 빈칸에 순환(recursion)을 적어요.
2. 자기 호출 = 순환/재귀
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

#### 첫 줄

빈칸에 순환(recursion)을 적어요.

#### 떠올릴 개념·공식

자기 호출 = 순환/재귀

#### 검산

본문의 조건과 독립 추적을 함께 확인해요.

#### 조건·구분과 확인

- 올바른 순환에는 즉시 답을 주는 바닥 조건과 그 조건으로 다가가는 문제 크기 감소가 필요해요.
- 반복문은 자기 호출을 만들지 않으므로 함수 이름 반복이 아니라 실제 실행 중 호출 관계를 확인해요.

### P3. 성장률이 작은 순서

textbook-ch01-q12 · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0914_Recursion-%EB%AC%B8%EC%A0%9C.pdf#page=3)

다음의 빅오표기법들을 수행시간이 적게 걸리는 것부터 나열하라.

O(1) O(n) O(log n) O(n²) O(n log n) O(n!) O(2ⁿ)

<details><summary>교과서 원문 보기</summary>

1장 자료구조와 알고리즘 · 12번 · 책 37쪽

다음의 빅오표기법들을 수행시간이 적게 걸리는 것부터 나열하라.

O(1) O(n) O(log n) O(n²) O(n log n) O(n!) O(2ⁿ)

</details>

#### 문제를 내 말로 읽어요

입력 크기 n이 충분히 커질 때의 대표 성장률을 작은 순서로 나열해요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

Big O는 점근 상한 표기예요. 여기서는 문제에서 제시한 대표 함수들의 성장률 비교를 요구해요. log의 밑은 1보다 큰 고정 상수이며 순서를 바꾸지 않아요.

#### 종이에 적을 첫 줄

상수 1과 log n을 먼저 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

O(1), O(log n), O(n), O(n log n), O(n²), O(2ⁿ), O(n!) 순서예요. log n/n→0이고 log n&lt;n인 충분히 큰 n에서 n log n&lt;n²이에요. 지수는 어떤 고정 차수 다항식보다 커지고, n!/2ⁿ는 뒤쪽 인수들의 곱이 계속 커져 발산해요.

#### 완성 답과 검산

n=16에서 1,4,16,64,256,65536,20922789888000 순서예요. 이 예는 직관 확인이고 전체 점근 순서는 앞의 성장률 논증이 근거예요. 실제 초 단위 시간은 상수·하드웨어에 따라 달라요.

#### 이 문제에서 조심할 점

작은 n의 한 번 비교를 일반 증명으로 삼지 않아요. O(n²) 클래스는 O(n)도 포함하므로 여기서는 대표 성장 함수 비교라는 관례로 읽어요.

#### 설명을 닫고 다시 해 봐요

1. 상수 1과 log n을 먼저 적어요.
2. 1&lt;log n&lt;n&lt;n log n&lt;n²&lt;2ⁿ&lt;n!
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

#### 첫 줄

상수 1과 log n을 먼저 적어요.

#### 떠올릴 개념·공식

1&lt;log n&lt;n&lt;n log n&lt;n²&lt;2ⁿ&lt;n!

#### 검산

본문의 조건과 독립 추적을 함께 확인해요.

#### 조건·구분과 확인

- 충분히 큰 n에서 대표 성장 함수를 비교하며 로그 밑은 1보다 큰 고정 상수예요.
- O(n²)는 O(n)도 포함하므로 표는 대표 함수 비교로 읽고, 실제 초 단위 시간은 상수·하드웨어에도 달려 있어요.

### P5. 줄어들지 않는 순환 호출

textbook-ch02-q05 · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0914_Recursion-%EB%AC%B8%EC%A0%9C.pdf#page=5)

다음의 순환호출 함수에서 잘못된 점은 무엇인가?

`int recursive(int n)
{
    if( n==1 ) return 0;
    return n*recursive(n);
}`

<details><summary>교과서 원문 보기</summary>

2장 순환 · 05번 · 책 63쪽

다음의 순환호출 함수에서 잘못된 점은 무엇인가?

`int recursive(int n)
{
    if( n==1 ) return 0;
    return n*recursive(n);
}`

</details>

#### 문제를 내 말로 읽어요

잘못된 순환 함수의 결함을 찾는 문제예요. 정상 반환값을 요구하는 문제가 아니에요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

“잘못된 점”과 recursive(n)은 종료를 위한 감소가 없는 단서예요. 바닥 조건 n==1은 있지만 n이 변하지 않으면 그 조건에 가까워지지 않아요.

#### 종이에 적을 첫 줄

n=2에서 2×recursive(2)를 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

2→2→2…가 반복되어 결과를 얻지 못해요. n=1에서는 0을 반환하지만 n&gt;1은 종료 조건에 도달하지 않아요. 결함은 인자를 줄이지 않는 자기 호출이에요. 팩토리얼 의도라면 recursive(n−1)와 바닥값 1이 함께 필요하지만 이는 수정안이지 원문 답이 아니에요.

#### 완성 답과 검산

인자가 동일하다는 정적 추적이 모든 n≠1에서 동일 상황 반복을 보여 줘요. 시스템 자원 한계나 signed overflow에 따른 실제 동작을 정상 결과로 예측하지 않아요.

#### 이 문제에서 조심할 점

바닥 조건이 존재한다는 것만으로 종료를 보장하지 않아요.

#### 설명을 닫고 다시 해 봐요

1. n=2에서 2×recursive(2)를 적어요.
2. 같은 n 재호출 → 감소 없음
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

#### 첫 줄

n=2에서 2×recursive(2)를 적어요.

#### 떠올릴 개념·공식

같은 n 재호출 → 감소 없음

#### 검산

본문의 조건과 독립 추적을 함께 확인해요.

#### 조건·구분과 확인

- n=1은 0을 반환하지만 n≠1은 같은 n을 다시 호출해 바닥 조건에 다가가지 않아요.

### P6. 자연수 ADT의 연산 계약

lecture-s01-p24-nat-no · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0914_Recursion-%EB%AC%B8%EC%A0%9C.pdf#page=6)

**강의 예제 기반 자체 출제** S1 p24

아래는 자연수 추상 데이터 타입(ADT) `Nat_No`의 일부 연산을 정의한 수학적 유사코드예요.

`Nat_No
zero() ::= return 0;
sub(x,y) ::= if(x<y) return 0;
             else return x-y;
add(x,y) ::= if((x+y)<=INT_MAX) return x+y;
             else return INT_MAX;`

#### 구할 것

- (a) `Nat_No`의 객체 범위를 쓰고, `sub(3, 5)`, `sub(5, 3)`, `add(INT_MAX, 1)`의 반환 결과를 각각 구하세요.
- (b) ADT 사용자가 내부 표현을 몰라도 되는 이유와, `add(x, y)`를 C의 `signed int` 코드로 옮길 때 `x + y`를 바로 계산하지 않고 먼저 검사해야 하는 이유·조건식을 설명하세요.

<details><summary>강의 예제 보기</summary>

S1 p24 · Software_1_자료구조및알고리즘.pdf. 강의 코드의 해당 연산을 발췌해 들여쓰기를 정리했습니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

`Nat_No
zero() ::= return 0;
sub(x,y) ::= if(x<y) return 0;
             else return x-y;
add(x,y) ::= if((x+y)<=INT_MAX) return x+y;
             else return INT_MAX;`

</details>

#### 문제를 내 말로 읽어요

자연수 ADT `Nat_No`의 객체 범위와 `sub`·`add` 연산 결과를 구하고, 정보 은닉 이유와 C의 `signed int` 오버플로 사전 검사 조건을 설명하는 문제예요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “자연수 ADT의 연산 계약”이에요. 자연수 범위 밖의 음수가 나오지 않도록 `sub`는 작은 수에서 큰 수를 뺄 때 `0`을 반환하고, `add`는 합이 상한을 넘으면 `INT_MAX`로 포화시켜요. C의 `signed int` 오버플로는 미정의 동작이므로 `x + y`를 계산하기 전에 `INT_MAX - y`와 비교해요.

#### 종이에 적을 첫 줄

`sub(3, 5)`: `3 < 5`이므로 `0`이에요.

#### 왜 이렇게 푸는지 함께 따라가요

(a) `Nat_No`의 객체 범위는 `0..INT_MAX`예요. 정의에 따라 `sub(3, 5)`는 `3 < 5`이므로 `0`, `sub(5, 3)`은 `5 - 3 = 2`, `add(INT_MAX, 1)`은 수학적 합이 `INT_MAX`를 넘으므로 `INT_MAX`를 반환해요.

(b) ADT는 객체와 연산의 계약(무엇을 하는가)만 제공하고 내부 표현(어떻게 구현하는가)을 숨기므로 사용자는 내부 표현을 몰라도 돼요. 또한 C에서 `signed int`로 `x + y`를 바로 계산하면 오버플로가 먼저 발생할 수 있으므로, `x, y >= 0`일 때 안전한 `x > INT_MAX - y`를 먼저 검사해야 해요.

#### 완성 답과 검산

(a) `0`, `2`, `INT_MAX` 모두 자연수 객체 범위 `0..INT_MAX` 안에 속하며 각 분기 조건과 일치해요.

(b) `x = INT_MAX`, `y = 1`을 `x > INT_MAX - y`에 대입하면 `INT_MAX > INT_MAX - 1`이 되어 오버플로 없이 상한 초과를 판별할 수 있어요.

#### 이 문제에서 조심할 점

위 유사코드를 그대로 C의 정수 연산이라고 간주해 `INT_MAX + 1`을 실행하지 마세요.

#### 설명을 닫고 다시 해 봐요

1. `Nat_No`의 객체 범위와 세 연산 호출 결과를 차례로 적어요.
2. ADT의 인터페이스(계약)와 내부 구현 분리를 설명해요.
3. 오버플로 없이 상한 초과를 검사하는 부등식을 적어 봐요.

**페이지 요약**

#### 첫 줄

`sub(3, 5)`: `3 < 5`이므로 `0`이에요.

#### 떠올릴 개념·공식

자연수 ADT는 `0..INT_MAX` 범위와 연산 계약을 정의하며, C 구현 시 `x > INT_MAX - y`로 오버플로를 예방해요.

#### 검산

(a) 범위 `0..INT_MAX`, 결과 `0`, `2`, `INT_MAX` (b) ADT는 표현을 숨기며 C에서는 `x > INT_MAX - y`를 먼저 검사함.

#### 조건·구분과 확인

- x,y≥0일 때 x&gt;INT_MAX-y를 먼저 검사하며, signed int의 x+y 오버플로를 실제로 실행하지 않아요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “같은 n²를 계산하는 세 알고리즘”이에요. 루프 제어를 제외하고 기본 연산(대입·덧셈·곱셈) 횟수 $T(n)$을 입력 크기 $n$의 함수로 나타낸 뒤, 최고차항의 차수로 빅오($O(1)$, $O(n)$, $O(n^2)$)를 판정해요.

#### 종이에 적을 첫 줄

`A`의 곱셈 `1`회 + 대입 `1`회 = `2`회부터 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

(a) `A`는 곱셈 `1`회와 대입 `1`회로 총 `2`회이므로 $O(1)$이에요. `B`는 초기 대입 `1`회와 `n`번 반복되는 덧셈·대입 각 `1`회로 총 $2n + 1$회이므로 $O(n)$이고, `C`는 초기 대입 `1`회와 $n^2$번 반복되는 덧셈·대입 각 `1`회로 총 $2n^2 + 1$회이므로 $O(n^2)$이에요.

(b) 세 알고리즘 모두 $n^2$을 반환하지만, $n$이 커질 때 총 연산 횟수가 상수($O(1)$), 일차($O(n)$), 이차($O(n^2)$)로 다르게 증가하므로 실행 시간이 같다고 할 수 없어요.

(a) $n = 1$을 대입하면 `A`는 `2`회, `B`는 $2(1)+1 = 3$회, `C`는 $2(1)^2+1 = 3$회이고, $n = 10$이면 각각 `2`회, `21`회, `201`회로 식과 일치해요.

(b) $n = 100$일 때 연산 수가 `2`회, `201`회, `20001`회로 벌어져 증가율 차이를 바로 확인할 수 있어요.

#### 이 문제에서 조심할 점

문제에서 제외한 루프 제어 연산을 일부 알고리즘에만 더하지 마세요.

#### 설명을 닫고 다시 해 봐요

1. `A`, `B`, `C`에서 초기 대입과 반복 본문 연산 횟수를 분리해 세어요.
2. 각 $T(n)$에서 상수 계수와 낮은 차수 항을 지워 빅오 표기를 적어요.
3. 결과값이 같아도 복잡도가 다르면 실행 시간이 다른 이유를 정리해요.

**페이지 요약**

#### 첫 줄

`A`의 곱셈 `1`회 + 대입 `1`회 = `2`회부터 적어요.

#### 떠올릴 개념·공식

기본 연산 횟수 $T(n)$의 최고차항으로 빅오($O(1), O(n), O(n^2)$)를 판정해요.

#### 검산

(a) `A`: `2`회, $O(1)$ / `B`: $2n+1$회, $O(n)$ / `C`: $2n^2+1$회, $O(n^2)$ (b) 연산 증가율이 달라 실행 시간도 다름.

#### 조건·구분과 확인

- n≥1이고 루프 제어는 제외하며 대입·덧셈·곱셈을 각각 1회로 동일하게 세어요.

### P8. 팩토리얼의 호출과 반환을 분리하기

lecture-s02-p4-factorial · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0914_Recursion-%EB%AC%B8%EC%A0%9C.pdf#page=8)

**강의 예제 기반 자체 출제** S2 p4

아래 순환 함수 `factorial(n)`에서 `n`은 `0` 이상의 정수이고, 계산 결과는 `int` 범위에 들어간다고 가정해요.

`int factorial(int n)
{
    if(n <= 1) return 1;
    else return n * factorial(n-1);
}`

#### 구할 것

- (a) `factorial(3)`을 실행할 때 호출 순서와 반환값 순서를 차례로 쓰고, `factorial(0)`의 반환값도 구하세요.
- (b) 이 함수에서 순환을 멈추는 종료 조건과 호출마다 문제 크기가 줄어드는 부분을 찾아 설명하세요.

<details><summary>강의 예제 보기</summary>

S2 p4 · Software_2_Recursion.pdf. 강의 코드의 해당 연산을 발췌해 들여쓰기를 정리했습니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

`int factorial(int n)
{
    if(n <= 1) return 1;
    else return n * factorial(n-1);
}`

</details>

#### 문제를 내 말로 읽어요

순환 함수 `factorial(3)`의 호출 순서와 반환 순서를 분리해 추적하고, 종료 조건과 문제 크기가 줄어드는 식을 찾는 문제예요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “팩토리얼의 호출과 반환을 분리하기”예요. 순환 함수는 종료 조건(기저 조건)에 도달할 때까지 더 작은 인자(`n - 1`)로 자기 자신을 호출하며 내려가고, 기저 조건에서 값이 반환되면 역순으로 곱셈을 마무리해요.

#### 종이에 적을 첫 줄

`factorial(3) = 3 * factorial(2)`라고 적고 하위 호출을 따라가요.

#### 왜 이렇게 푸는지 함께 따라가요

(a) `factorial(3)`은 `factorial(2)`를 부르고, `factorial(2)`는 `factorial(1)`을 부르므로 호출 인자 순서는 `3 → 2 → 1`이에요. `factorial(1)`이 종료 조건을 만나 `1`을 반환하면 `factorial(2)`가 `2 * 1 = 2`를, `factorial(3)`이 `3 * 2 = 6`을 반환하므로 반환값 순서는 `1 → 2 → 6`이에요. `factorial(0)`은 처음부터 `0 <= 1`이 참이므로 `1`을 반환해요.

(b) 순환을 멈추는 종료 조건은 `if (n <= 1) return 1;`의 `n <= 1`이고, 순환 호출의 인자 `n - 1`이 호출마다 문제 크기를 `1`씩 줄여 결국 종료 조건에 도달하게 해요.

#### 완성 답과 검산

(a) 호출 순서 `3 → 2 → 1`과 반환 순서 `1 → 2 → 6`이 스택의 후입선출(LIFO) 순서와 일치하며, $3! = 6$, $0! = 1$과도 맞아요.

(b) 정수 $n \ge 2$에서 매번 `n - 1`을 전달하면 유한 번 뒤에 반드시 `n == 1`이 되어 `n <= 1` 조건에 도달함을 확인해요.

#### 이 문제에서 조심할 점

호출하는 순간 `3 * 2 * 1`이 한 번에 계산된다고 생각하지 마세요. 아직 끝나지 않은 곱셈이 각 호출에 남아 있어요.

#### 설명을 닫고 다시 해 봐요

1. `factorial(3)`의 호출 순서와 반환값 순서를 화살표로 나누어 적어요.
2. `factorial(0)`이 어느 분기로 들어가 무엇을 반환하는지 확인해요.
3. 종료 조건과 문제 크기를 줄이는 식을 코드에서 찾아 적어요.

**페이지 요약**

#### 첫 줄

`factorial(3) = 3 * factorial(2)`라고 적고 하위 호출을 따라가요.

#### 떠올릴 개념·공식

순환은 종료 조건(`n <= 1`)과 문제 크기 감소(`n - 1`)로 구성되며 호출 역순으로 반환돼요.

#### 검산

(a) 호출 `3 → 2 → 1`, 반환 `1 → 2 → 6`, `factorial(0) = 1` (b) 종료 조건 `n <= 1`, 크기 감소 `n - 1`.

#### 조건·구분과 확인

- 입력은 0 이상의 정수이고 계산 결과가 int 범위에 든다는 가정에서 추적해요.

### P9. 네 겹 루프의 시간 복잡도

2019-mid-q9 · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0914_Recursion-%EB%AC%B8%EC%A0%9C.pdf#page=9)

다음 코드의 시간 복잡도를 n에 대한 함수 T(n)으로 표현하고, 빅오 표기법으로도 써 보세요.

`int i, j, p, k, n;

for(i=0; i<n; i++){
    for(j=0; j<n; j++){
        for(p=0; j<i; j++){
            for(k=0; k<30; i++){
                buffer[i][j] = 0;
            }
        }
    }
}`

넷째 루프의 `i++`만 `k++`의 오타로 가정해 풀어요. 셋째 루프의 `j<i; j++`는 그대로 두어요. 원문 그대로의 동작과 이 조건부 답은 풀이에서 구분해요.

> "다음의 코드의 시간 복잡도를 n에 대한 함수 T(n)으로 표현하고 빅오 표기법 (4점)"

`int i, j, p, k, n;

for(i=0; i<n; i++){
    for(j=0; j<n; j++){
        for(p=0; j<i; j++){
            for(k=0; k<30; i++){
                buffer[i][j] = 0;
            }
        }
    }
}`

</details>

#### 문제를 내 말로 읽어요

원문 넷째 루프는 i++인데 k&lt;30을 검사해요. 현재 리뷰는 k++로 보는 가정을 별도로 명시했어요. 두 경우를 나눠요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

종료 조건을 검사하는 k가 변하는지 먼저 확인해요. 원문의 결함과 수정 가정의 시간 복잡도를 같은 답으로 취급할 수 없어요. 원 코드 실행은 정상적인 T(n) 계산 대상이 아니에요.

#### 종이에 적을 첫 줄

원문: i=1,j=0,k=0에서 넷째 루프 진입이라고 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

원문 그대로라면 k=0이 계속되어 k&lt;30이 항상 참이에요. i만 증가해 배열 밖 접근이나 정수 범위 초과에 이르므로 정상 종료와 유한한 T(n)을 보장하지 않아요. n≤1은 대입 0번이지만 n≥2의 정상 빅오 답은 정할 수 없어요. **리뷰가 명시한 k++ 가정에서만** j가 0..i−1로 증가하고 k가 30번 돌아 T(n)=30n(n−1)/2, O(n²)이에요. 셋째 루프의 j 증감은 그대로 두어요.

#### 완성 답과 검산

수정 가정 n=4의 i별 횟수는 0,30,60,90으로 180번이에요. 원문은 k가 변하지 않는다는 정적 제어흐름 분석으로 결함을 확인하며 실제 위험 코드는 실행하지 않아요. 이 180을 원문 실행 결과라고 쓰지 않아요.

#### 이 문제에서 조심할 점

문제은행의 의도된 답을 원문의 정상 실행값으로 승인하지 않아요. 이 해설은 결함과 조건부 답을 설명하는 것이며 원 코드가 정상 종료한다는 주장은 하지 않아요. 검산은 명시한 k++ 보정 조건에만 적용해요.

#### 설명을 닫고 다시 해 봐요

1. 원문: i=1,j=0,k=0에서 넷째 루프 진입이라고 적어요.
2. 원문 정상 복잡도 없음; k++ 가정만 O(n²)
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

#### 떠올릴 개념·공식

원문 정상 복잡도 없음; k++ 가정만 O(n²)

#### 검산

#### 조건·구분과 확인

- 원문은 k=0이 변하지 않아 n≥2에서 정상 종료·유한 T(n)을 보장하지 못하고, n≤1은 대입 0번이에요.
- 넷째 i++만 k++로 고친 가정에서 셋째의 j 증감을 유지하면 T(n)=30n(n-1)/2예요. n=4의 180번은 보정한 경우에만 해당해요.

#### 문제를 내 말로 읽어요

p가 등장하지만 실제로 바뀌는 변수는 j예요. k=1에서 29번 대입해요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

for문의 변수 이름보다 조건과 증감식을 읽어요. j≤i 동안 j++하므로 각 i에서 j=1..i를 한 번 훑어요. 바깥 j 루프는 그 뒤 j=i+2에서 계속되지만 j≤i가 거짓이라 대입을 추가하지 않아요.

#### 종이에 적을 첫 줄

i=1일 때 안쪽 j=1에서 한 번 진입한다고 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

i=1..n−1의 안쪽 실행 횟수는 1+2+…+(n−1)예요. 각 실행에 k는 1..29라 29번이므로 T(n)=29n(n−1)/2, O(n²)예요. p는 1에서 변하지 않아도 j가 증가하므로 이 루프의 종료를 막지 않아요.

#### 완성 답과 검산

n=4에서 i별 대입 횟수는 29,58,87, 합 174이에요. n=1은 0번이에요. 별도 제어흐름 시뮬레이션과 공식이 일치해요.

#### 이 문제에서 조심할 점

네 겹이라고 n⁴이 아니에요. k=1이므로 k&lt;30는 29번이에요. 원문의 대입값 1과 설명의 0 차이는 횟수를 바꾸지 않아요.

#### 설명을 닫고 다시 해 봐요

1. i=1일 때 안쪽 j=1에서 한 번 진입한다고 적어요.
2. j 증감 추적, (k끝−1)×삼각수
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

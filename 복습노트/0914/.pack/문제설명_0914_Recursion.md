### P1. 함수 foo는 무엇을 할까요

2019-mid-q8 · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0914_Recursion.html#p1)

#### 주어진 조건

아래에 함수 foo의 코드가 있어요. 이 함수를 호출하면 무엇을 하는 함수인지 답해 보세요.

함수 foo는 ( ) 함수이다.

`int foo (int x, int y){
    if (x % y == 0) return y;
    else
        return foo(y, x % y);
}`

#### 기출 원문

2019 중간 8번 · 2점 · 출제자 미상

> "아래에는 함수 foo에 대한 코드가 있으며 이 함수를 호출(사용)하였을 때 무엇을 하는 함수인지에 대해서 답을 하시오. 함수 foo는 ( ) 함수이다. (2점)"

`int foo (int x, int y){
    if (x % y == 0) return y;
    else
        return foo(y, x % y);
}`

#### 문제를 내 말로 읽어요

코드가 어떤 문제를 푸는지 이름이 아니라 인자 변화로 판단해요. 입력은 양의 정수 x,y로 두어요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

x%y라는 “나머지”와 (y,x%y) 호출은 Euclidean algorithm의 단서예요. x=qy+r일 때 x,y의 공약수 집합은 y,r의 공약수 집합과 같아요. y&gt;0일 때 0≤r&lt;y예요.

#### 종이에 적을 첫 줄

foo(48,18)에서 나머지 12를 첫 줄에 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

(48,18)→(18,12)→(12,6)에서 나머지가 0이 되어 6을 반환해요. 공약수 d가 x,y를 나누면 x−qy=r도 나누고, 반대로 y,r을 나누면 qy+r=x도 나눠요. 그래서 매 호출의 최대공약수가 같아요. 나머지가 양의 이전 y보다 작아 종료해요.

#### 완성 답과 검산

48의 약수와 18의 약수 중 공통 최대는 6이에요. 순서를 바꾼 foo(18,48)도 (48,18)로 이어져 6이에요. 따라서 답은 최대공약수 GCD예요.

#### 이 문제에서 조심할 점

원 함수는 y=0에서 %0이므로 정의되지 않아요. 양의 입력 조건 없이 모든 정수에 안전하다고 쓰지 않아요.

#### 설명을 닫고 다시 해 봐요

1. foo(48,18)에서 나머지 12를 첫 줄에 적어요.
2. 나머지로 줄이는 유클리드 호제법
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

#### 첫 줄

foo(48,18)에서 나머지 12를 첫 줄에 적어요.

#### 떠올릴 개념·공식

나머지로 줄이는 유클리드 호제법

#### 검산

### P2. 네 겹 루프의 시간 복잡도

2019-mid-q9 · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0914_Recursion.html#p2)

#### 주어진 조건

다음 코드의 시간 복잡도를 n에 대한 함수 T(n)으로 표현하고, 빅오 표기법으로도 써 보세요.

`int i, j, p, k, n;

for(i=0; i<n; i++){
    for(j=0; j<n; j++){
        for(p=0; j<i; j++){
            for(k=0; k<30; i++){
                buffer[i][j] = 0;
            }
        }
    }
}`

넷째 루프의 `i++`는 `k++`의 오타로 보고 풀어요.

#### 기출 원문

2019 중간 9번 · 4점 · 출제자 미상

> "다음의 코드의 시간 복잡도를 n에 대한 함수 T(n)으로 표현하고 빅오 표기법 (4점)"

`int i, j, p, k, n;

for(i=0; i<n; i++){
    for(j=0; j<n; j++){
        for(p=0; j<i; j++){
            for(k=0; k<30; i++){
                buffer[i][j] = 0;
            }
        }
    }
}`

#### 문제를 내 말로 읽어요

원문 넷째 루프는 i++인데 k&lt;30을 검사해요. 현재 리뷰는 k++로 보는 가정을 별도로 명시했어요. 두 경우를 나눠요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

종료 조건을 검사하는 k가 변하는지 먼저 확인해요. 원문의 결함과 수정 가정의 시간 복잡도를 같은 답으로 취급할 수 없어요. 원 코드 실행은 정상적인 T(n) 계산 대상이 아니에요.

#### 종이에 적을 첫 줄

원문: i=1,j=0,k=0에서 넷째 루프 진입이라고 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

원문 그대로라면 k=0이 계속되어 k&lt;30이 항상 참이에요. i만 증가해 배열 밖 접근이나 정수 범위 초과에 이르므로 정상 종료와 유한한 T(n)을 보장하지 않아요. n≤1은 대입 0번이지만 n≥2의 정상 빅오 답은 정할 수 없어요. **리뷰가 명시한 k++ 가정에서만** j가 0..i−1로 증가하고 k가 30번 돌아 T(n)=30n(n−1)/2, O(n²)이에요. 셋째 루프의 j 증감은 그대로 두어요.

#### 완성 답과 검산

수정 가정 n=4의 i별 횟수는 0,30,60,90으로 180번이에요. 원문은 k가 변하지 않는다는 정적 제어흐름 분석으로 결함을 확인하며 실제 위험 코드는 실행하지 않아요. 이 180을 원문 실행 결과라고 쓰지 않아요.

#### 이 문제에서 조심할 점

문제은행의 의도된 답을 원문의 정상 실행값으로 승인하지 않아요. 이 해설은 결함과 조건부 답을 설명하는 것이며 원 코드의 정상 실행 검증은 보류 상태예요.

#### 설명을 닫고 다시 해 봐요

1. 원문: i=1,j=0,k=0에서 넷째 루프 진입이라고 적어요.
2. 원문 정상 복잡도 없음; k++ 가정만 O(n²)
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

#### 첫 줄

원문: i=1,j=0,k=0에서 넷째 루프 진입이라고 적어요.

#### 떠올릴 개념·공식

원문 정상 복잡도 없음; k++ 가정만 O(n²)

#### 검산

본문의 조건과 독립 추적을 함께 확인해요.

for(i=0; i<n; i++){
    for(j=i; j<n; j++){
        for(k=0; k<30; k++){
            buffer[i][j] = 0;
        }
    }
}`

#### 문제를 내 말로 읽어요

대입문 실행 횟수만 세어요. n은 비음수 정수이고 배열의 유효한 접근 범위를 가정해요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

j가 i부터 시작하므로 각 i의 j 반복 횟수는 n−i예요. k는 입력과 무관한 상수 30번이에요. 중첩 개수만 보고 n³이라고 판단하지 않아요.

#### 종이에 적을 첫 줄

#### 왜 이렇게 푸는지 함께 따라가요

T(n)=30×[n+(n−1)+…+1]=30n(n+1)/2예요. 상수와 낮은 차수를 지우면 O(n²), 더 정확한 성장률은 Θ(n²)이에요. 합 공식은 앞뒤 항을 짝지으면 각 쌍의 합이 n+1인 데서 나와요.

#### 완성 답과 검산

n=3이면 j 횟수는 3+2+1=6이라 대입은 180번이에요. n=0에서는 0번, n=1에서는 30번으로 공식과 맞아요. 별도 반복문으로 n=0..20의 횟수를 확인해요.

#### 이 문제에서 조심할 점

변형 카드의 k 상수와 아래 기출 원문 30을 구별해요. 답은 현재 카드의 상수로 계산해요.

#### 설명을 닫고 다시 해 봐요

1. i=0일 때 j는 n번, i=1일 때 n−1번이라고 적어요.
2. 상수×삼각수, O(n²)
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

#### 첫 줄

#### 떠올릴 개념·공식

### P4. 최대공약수를 순환 함수로

2018-mid-c024-q15 · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0914_Recursion.html#p4)

#### 주어진 조건

임의의 두 양의 정수의 최대 공약수를 구해 주는 gcd를 순환 함수로 구현해 보세요. (main 함수에서 임의의 두 양의 정수를 입력받아요.)

`#include <stdio.h>
int gcd(int i, int j){

}
int main(){
    int i, j;
    printf("임의의 두 양의 정수 입력:");
    scanf("%d %d", &i, &j);
    printf("gcd:%d\n", gcd(i, j));
    return 0;
}`

#### 기출 원문

2018 중간 15번 · 5점 · 출제자 미상

> "임의의 두 양의 정수의 최대 공약수를 구해주는 gcd를 순환 함수로 구현하시오. ( main함수에서 임의의 두 양의 정수를 입력 ) [5 points]"

`#include <stdio.h>
int gcd(int i, int j){

}
int main(){
    int i, j;
    printf("임의의 두 양의 정수 입력:");
    scanf("%d %d", &i, &j);
    printf("gcd:%d\n", gcd(i, j));
    return 0;
}`

#### 문제를 내 말로 읽어요

빈 gcd 본문을 채워 양의 두 정수의 최대공약수를 반환해요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

“순환 함수”와 “최대공약수”에서 gcd(i,j)=gcd(j,i%j)를 떠올려요. %를 계산하기 전에 j=0을 검사해야 나눗셈 오류 없이 종료해요.

#### 종이에 적을 첫 줄

`if (j == 0) return i;`

#### 왜 이렇게 푸는지 함께 따라가요

`int gcd(int i, int j) {
    if (j == 0) return i;
    return gcd(j, i % j);
}`

#### 완성 답과 검산

gcd(48,18)→(18,12)→(12,6)→(6,0)→6이에요. 반환값은 추가 계산 없이 위 호출로 전달돼요. 공약수 집합 보존과 두 번째 인자의 감소가 정확성과 종료를 증명해요. 입력 변환 성공과 양의 int 범위를 가정해요.

#### 이 문제에서 조심할 점

if 앞에서 i%j를 계산하면 마지막 호출에서 %0을 하게 돼요. “0이 모든 수를 나눈다”가 아니라 모든 양의 수가 0을 나눈다는 뜻이에요.

#### 설명을 닫고 다시 해 봐요

1. if (j == 0) return i;
2. j=0 종료, 아니면 gcd(j,i%j)
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

#### 첫 줄

if (j == 0) return i;

#### 떠올릴 개념·공식

j=0 종료, 아니면 gcd(j,i%j)

#### 검산

### P5. 자기 자신을 다시 부르는 기법

2018-mid-c102-q1 · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0914_Recursion.html#p5)

#### 주어진 조건

함수가 수행 도중에 자기 자신을 다시 호출하여 문제를 해결하는 기법을 ( )이라고 해요. 빈칸을 채워 보세요.

#### 기출 원문

2018 중간 1번 · 2점 · 출제자 미상

> "1. 함수가 수행 도중에 자기 자신을 다시 호출하여 문제를 해결하는 기법을 ( ) 이라고 한다. [2 points]"

#### 문제를 내 말로 읽어요

함수가 자기 자신을 호출한다는 설명에 맞는 이름을 쓰는 문제예요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

“자기 자신을 다시 호출”은 recursion, 수업 용어로 순환(재귀)이에요. 일반 반복 iteration은 루프를 돌지만 별도의 자기 호출을 만들지 않아요.

#### 종이에 적을 첫 줄

빈칸에 순환(recursion)을 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

답은 순환, 또는 동의어 재귀예요. 예를 들어 factorial(3)이 factorial(2)를 호출하면 작은 문제의 답을 받아 현재 답을 만들어요. 올바른 순환은 즉시 답을 주는 바닥 조건과 그 조건으로 다가가는 감소를 함께 가져요.

#### 완성 답과 검산

반복문만 있는 sum은 자기 호출이 없어요. 반대로 함수 안의 자기 호출은 루프가 없어도 순환이에요. 이 차이로 용어를 확인해요.

#### 이 문제에서 조심할 점

textbook-ch02-q01 · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0914_Recursion.html#p11)

#### 주어진 조건

팩토리얼을 계산하는 순환호출 함수 factorial에서 매개 변수로 5를 주었다면 최대 몇 개의 factorial 함수의 활성 레코드가 동시에 존재할 수 있는가?

#### 기출 원문

2장 순환 · 01번 · 책 63쪽

팩토리얼을 계산하는 순환호출 함수 factorial에서 매개 변수로 5를 주었다면 최대 몇 개의 factorial 함수의 활성 레코드가 동시에 존재할 수 있는가?

#### 문제를 내 말로 읽어요

factorial(5) 실행 중 동시에 살아 있는 호출 기록의 최대 수를 세어요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

“동시에”는 활성 레코드 activation record와 호출 스택의 깊이를 묻는 단서예요. 강의록 factorial은 n≤1이면 반환하므로 factorial(0)을 추가로 부르지 않아요.

#### 종이에 적을 첫 줄

호출 줄에 5→4→3→2→1을 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

5개의 factorial 호출이 살아 있는 순간이 최대예요. 5,4,3,2의 호출은 곱셈 결과를 기다리고 1의 호출이 바닥 답 1을 결정해요. 이후 복귀하면서 1,2,6,24,120을 전달하고 기록을 하나씩 없애요.

#### 완성 답과 검산

바닥 n≤1 코드와 대조하면 입력 1은 깊이 1, 입력 2는 깊이 2예요. 입력 5의 깊이는 5예요. main의 기록은 factorial의 기록이 아니므로 세지 않아요.

#### 이 문제에서 조심할 점

n=0을 바닥으로 삼는 다른 구현의 깊이 6을 현재 강의 코드에 섞지 않아요.

#### 설명을 닫고 다시 해 봐요

1. 호출 줄에 5→4→3→2→1을 적어요.
2. 강의 바닥 1 → 최대 5개
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

#### 첫 줄

호출 줄에 5→4→3→2→1을 적어요.

#### 떠올릴 개념·공식

강의 바닥 1 → 최대 5개

### P12. 줄어들지 않는 순환 호출

textbook-ch02-q05 · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0914_Recursion.html#p12)

#### 주어진 조건

다음의 순환호출 함수에서 잘못된 점은 무엇인가?

`int recursive(int n)
{
    if( n==1 ) return 0;
    return n*recursive(n);
}`

#### 기출 원문

2장 순환 · 05번 · 책 63쪽

다음의 순환호출 함수에서 잘못된 점은 무엇인가?

`int recursive(int n)
{
    if( n==1 ) return 0;
    return n*recursive(n);
}`

#### 문제를 내 말로 읽어요

잘못된 순환 함수의 결함을 찾는 문제예요. 정상 반환값을 요구하는 문제가 아니에요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

“잘못된 점”과 recursive(n)은 종료를 위한 감소가 없는 단서예요. 바닥 조건 n==1은 있지만 n이 변하지 않으면 그 조건에 가까워지지 않아요.

#### 종이에 적을 첫 줄

n=2에서 2×recursive(2)를 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

2→2→2…가 반복되어 결과를 얻지 못해요. n=1에서는 0을 반환하지만 n&gt;1은 종료 조건에 도달하지 않아요. 결함은 인자를 줄이지 않는 자기 호출이에요. 팩토리얼 의도라면 recursive(n−1)와 바닥값 1이 함께 필요하지만 이는 수정안이지 원문 답이 아니에요.

#### 완성 답과 검산

인자가 동일하다는 정적 추적이 모든 n≠1에서 동일 상황 반복을 보여 줘요. 시스템 자원 한계나 signed overflow에 따른 실제 동작을 정상 결과로 예측하지 않아요.

#### 이 문제에서 조심할 점

바닥 조건이 존재한다는 것만으로 종료를 보장하지 않아요.

#### 설명을 닫고 다시 해 봐요

1. n=2에서 2×recursive(2)를 적어요.
2. 같은 n 재호출 → 감소 없음
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

#### 첫 줄

n=2에서 2×recursive(2)를 적어요.

#### 떠올릴 개념·공식

같은 n 재호출 → 감소 없음

#### 검산

본문의 조건과 독립 추적을 함께 확인해요.

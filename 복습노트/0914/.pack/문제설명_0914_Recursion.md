### P2. 자기 자신을 다시 부르는 기법

#### 문제를 내 말로 읽어요

함수가 자기 자신을 호출한다는 설명에 맞는 이름을 쓰는 문제예요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

“자기 자신을 다시 호출”은 recursion, 수업 용어로 순환(재귀)이에요. 일반 반복 iteration은 루프를 돌지만 별도의 자기 호출을 만들지 않아요.

#### 종이에 적을 첫 줄

빈칸에 순환(recursion)을 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

답은 순환, 또는 동의어 재귀예요. 예를 들어 factorial(3)이 factorial(2)를 호출하면 작은 문제의 답을 받아 현재 답을 만들어요. 올바른 순환은 즉시 답을 주는 바닥 조건과 그 조건으로 다가가는 감소를 함께 가져요.

#### 완성 답과 검산

반복문만 있는 sum은 자기 호출이 없어요. 반대로 함수 안의 자기 호출은 루프가 없어도 순환이에요. 이 차이로 용어를 확인해요.

#### 이 문제에서 조심할 점

함수 이름을 두 번 썼다고 항상 실행 중 자기 호출은 아니에요. 실제 호출 관계를 보아요.

#### 설명을 닫고 다시 해 봐요

1. 빈칸에 순환(recursion)을 적어요.
2. 자기 호출 = 순환/재귀
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

#### 첫 줄

빈칸에 순환(recursion)을 적어요.

#### 떠올릴 개념·공식

자기 호출 = 순환/재귀

### P3. 성장률이 작은 순서

textbook-ch01-q12 · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0914_Recursion.html#p3)

다음의 빅오표기법들을 수행시간이 적게 걸리는 것부터 나열하라.

O(1) O(n) O(log n) O(n²) O(n log n) O(n!) O(2ⁿ)

<details><summary>교과서 원문 보기</summary>

1장 자료구조와 알고리즘 · 12번 · 책 37쪽

다음의 빅오표기법들을 수행시간이 적게 걸리는 것부터 나열하라.

O(1) O(n) O(log n) O(n²) O(n log n) O(n!) O(2ⁿ)

</details>

#### 문제를 내 말로 읽어요

입력 크기 n이 충분히 커질 때의 대표 성장률을 작은 순서로 나열해요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

Big O는 점근 상한 표기예요. 여기서는 문제에서 제시한 대표 함수들의 성장률 비교를 요구해요. log의 밑은 1보다 큰 고정 상수이며 순서를 바꾸지 않아요.

#### 종이에 적을 첫 줄

상수 1과 log n을 먼저 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

O(1), O(log n), O(n), O(n log n), O(n²), O(2ⁿ), O(n!) 순서예요. log n/n→0이고 log n&lt;n인 충분히 큰 n에서 n log n&lt;n²이에요. 지수는 어떤 고정 차수 다항식보다 커지고, n!/2ⁿ는 뒤쪽 인수들의 곱이 계속 커져 발산해요.

#### 완성 답과 검산

n=16에서 1,4,16,64,256,65536,20922789888000 순서예요. 이 예는 직관 확인이고 전체 점근 순서는 앞의 성장률 논증이 근거예요. 실제 초 단위 시간은 상수·하드웨어에 따라 달라요.

#### 이 문제에서 조심할 점

작은 n의 한 번 비교를 일반 증명으로 삼지 않아요. O(n²) 클래스는 O(n)도 포함하므로 여기서는 대표 성장 함수 비교라는 관례로 읽어요.

#### 설명을 닫고 다시 해 봐요

1. 상수 1과 log n을 먼저 적어요.
2. 1&lt;log n&lt;n&lt;n log n&lt;n²&lt;2ⁿ&lt;n!
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

#### 첫 줄

상수 1과 log n을 먼저 적어요.

#### 떠올릴 개념·공식

1&lt;log n&lt;n&lt;n log n&lt;n²&lt;2ⁿ&lt;n!

#### 검산

본문의 조건과 독립 추적을 함께 확인해요.

### P5. 줄어들지 않는 순환 호출

textbook-ch02-q05 · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0914_Recursion.html#p5)

다음의 순환호출 함수에서 잘못된 점은 무엇인가?

`int recursive(int n)
{
    if( n==1 ) return 0;
    return n*recursive(n);
}`

<details><summary>교과서 원문 보기</summary>

2장 순환 · 05번 · 책 63쪽

다음의 순환호출 함수에서 잘못된 점은 무엇인가?

`int recursive(int n)
{
    if( n==1 ) return 0;
    return n*recursive(n);
}`

</details>

#### 문제를 내 말로 읽어요

잘못된 순환 함수의 결함을 찾는 문제예요. 정상 반환값을 요구하는 문제가 아니에요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

“잘못된 점”과 recursive(n)은 종료를 위한 감소가 없는 단서예요. 바닥 조건 n==1은 있지만 n이 변하지 않으면 그 조건에 가까워지지 않아요.

#### 종이에 적을 첫 줄

n=2에서 2×recursive(2)를 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

2→2→2…가 반복되어 결과를 얻지 못해요. n=1에서는 0을 반환하지만 n&gt;1은 종료 조건에 도달하지 않아요. 결함은 인자를 줄이지 않는 자기 호출이에요. 팩토리얼 의도라면 recursive(n−1)와 바닥값 1이 함께 필요하지만 이는 수정안이지 원문 답이 아니에요.

#### 완성 답과 검산

인자가 동일하다는 정적 추적이 모든 n≠1에서 동일 상황 반복을 보여 줘요. 시스템 자원 한계나 signed overflow에 따른 실제 동작을 정상 결과로 예측하지 않아요.

#### 이 문제에서 조심할 점

바닥 조건이 존재한다는 것만으로 종료를 보장하지 않아요.

#### 설명을 닫고 다시 해 봐요

1. n=2에서 2×recursive(2)를 적어요.
2. 같은 n 재호출 → 감소 없음
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

#### 첫 줄

n=2에서 2×recursive(2)를 적어요.

#### 떠올릴 개념·공식

같은 n 재호출 → 감소 없음

### P9. 네 겹 루프의 시간 복잡도

#### 이 문제를 봤을 때 떠올릴 개념과 공식

1. 원문: i=1,j=0,k=0에서 넷째 루프 진입이라고 적어요.

### P10. 1부터 시작하는 네 겹 루프

unk-final-ltk-q1 · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0914_Recursion.html#p10)

다음 코드의 시간 복잡도를 n에 대한 함수 T(n)으로 써 보세요. 또한 빅오 표기법으로 써 보세요. (시간 복잡도를 구할 때 `buffer[i][j] = 0;`의 대입 연산만 고려해요.)

`int i, j, p, k, n;
for(i=1; i<n; i++){
    for(j=1; j<n; j++){
        for(p=1; j<=i; j++){
            for(k=1; k<30; k++){
                buffer[i][j] = 1;
            }
        }
    }
}`

(코드의 `= 1`은 원문 그대로예요. 대입 횟수만 세요)

#### 문제를 내 말로 읽어요

p가 등장하지만 실제로 바뀌는 변수는 j예요. k=1에서 29번 대입해요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

for문의 변수 이름보다 조건과 증감식을 읽어요. j≤i 동안 j++하므로 각 i에서 j=1..i를 한 번 훑어요. 바깥 j 루프는 그 뒤 j=i+2에서 계속되지만 j≤i가 거짓이라 대입을 추가하지 않아요.

#### 종이에 적을 첫 줄

i=1일 때 안쪽 j=1에서 한 번 진입한다고 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

i=1..n−1의 안쪽 실행 횟수는 1+2+…+(n−1)예요. 각 실행에 k는 1..29라 29번이므로 T(n)=29n(n−1)/2, O(n²)예요. p는 1에서 변하지 않아도 j가 증가하므로 이 루프의 종료를 막지 않아요.

#### 완성 답과 검산

n=4에서 i별 대입 횟수는 29,58,87, 합 174이에요. n=1은 0번이에요. 별도 제어흐름 시뮬레이션과 공식이 일치해요.

#### 이 문제에서 조심할 점

네 겹이라고 n⁴이 아니에요. k=1이므로 k&lt;30는 29번이에요. 원문의 대입값 1과 설명의 0 차이는 횟수를 바꾸지 않아요.

#### 설명을 닫고 다시 해 봐요

1. i=1일 때 안쪽 j=1에서 한 번 진입한다고 적어요.
2. j 증감 추적, (k끝−1)×삼각수
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

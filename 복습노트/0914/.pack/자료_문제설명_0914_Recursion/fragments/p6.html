문제를 내 말로 읽어요

자연수 ADT Nat_No의 객체 범위와 sub·add 연산 결과를 구하고, 정보 은닉 이유와 C의 signed int 오버플로 사전 검사 조건을 설명하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “자연수 ADT의 연산 계약”이에요. 자연수 범위 밖의 음수가 나오지 않도록 sub는 작은 수에서 큰 수를 뺄 때 0을 반환하고, add는 합이 상한을 넘으면 INT_MAX로 포화시켜요. C의 signed int 오버플로는 미정의 동작이므로 x + y를 계산하기 전에 INT_MAX - y와 비교해요.

종이에 적을 첫 줄

sub(3, 5): 3 < 5이므로 0이에요.

왜 이렇게 푸는지 함께 따라가요

(a) Nat_No의 객체 범위는 0..INT_MAX예요. 정의에 따라 sub(3, 5)는 3 < 5이므로 0, sub(5, 3)은 5 - 3 = 2, add(INT_MAX, 1)은 수학적 합이 INT_MAX를 넘으므로 INT_MAX를 반환해요.

(b) ADT는 객체와 연산의 계약(무엇을 하는가)만 제공하고 내부 표현(어떻게 구현하는가)을 숨기므로 사용자는 내부 표현을 몰라도 돼요. 또한 C에서 signed int로 x + y를 바로 계산하면 오버플로가 먼저 발생할 수 있으므로, x, y >= 0일 때 안전한 x > INT_MAX - y를 먼저 검사해야 해요.

완성 답과 검산

(a) 0, 2, INT_MAX 모두 자연수 객체 범위 0..INT_MAX 안에 속하며 각 분기 조건과 일치해요.

(b) x = INT_MAX, y = 1을 x > INT_MAX - y에 대입하면 INT_MAX > INT_MAX - 1이 되어 오버플로 없이 상한 초과를 판별할 수 있어요.

이 문제에서 조심할 점

위 유사코드를 그대로 C의 정수 연산이라고 간주해 INT_MAX + 1을 실행하지 마세요.

설명을 닫고 다시 해 봐요

  1. Nat_No의 객체 범위와 세 연산 호출 결과를 차례로 적어요.
  2. ADT의 인터페이스(계약)와 내부 구현 분리를 설명해요.
  3. 오버플로 없이 상한 초과를 검사하는 부등식을 적어 봐요.

첫 줄

sub(3, 5): 3 < 5이므로 0이에요.

떠올릴 개념·공식

자연수 ADT는 0..INT_MAX 범위와 연산 계약을 정의하며, C 구현 시 x > INT_MAX - y로 오버플로를 예방해요.

검산

(a) 범위 0..INT_MAX, 결과 0, 2, INT_MAX (b) ADT는 표현을 숨기며 C에서는 x > INT_MAX - y를 먼저 검사함.

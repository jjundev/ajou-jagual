Q1. 합쳐지는 작업 흐름을 담는 자료구조

프로젝트에서 B의 산출물이 A로 가고, A가 그것을 가공해 C로 넘겨요. 갈라졌던 작업이 나중에 다시 합쳐지기도 해요.

이런 관계를 트리 대신 그래프로 표현하는 까닭으로 알맞은 것을 고르세요.

  1. 트리와 그래프는 전혀 다른 구조라 트리에서는 정점·간선이라는 말을 쓸 수 없어서예요.
  2. 트리는 상하·포함 관계만 담아, 다시 합쳐지며 생기는 고리(사이클)를 표현할 수 없어서예요.
  3. 그래프에는 사이클이 생기지 않아서 작업 흐름이 무한히 도는 일을 막아 주기 때문이에요.
  4. 그래프는 루트 하나에서 모든 가지가 아래로 뻗어 나가는 모양이라 흐름을 따라가기 쉬워서예요.
힌트 보기

트리가 표현할 수 있는 관계의 종류를 먼저 떠올리고, 작업이 다시 합쳐질 때 어떤 모양이 생기는지 보세요.

풀이 보기
  1. "트리와 그래프를 별개의 구조로 봄" — 트리도 그래프의 일종이고, 트리에서도 간선(edge)과 노드(vertex)라는 말을 썼어요.
  2. 맞아요. 사이클이 생길 수밖에 없는 구조가 필요할 때 그래프를 써요.
  3. "그래프에는 사이클이 없다고 봄" — 반대예요. 그래프는 사이클을 담을 수 있는 구조이고, 그래서 소프트웨어에서는 무한 루프를 경계해야 해요.
  4. "그래프를 루트에서 가지가 뻗는 트리 모양으로 봄" — 루트에서 가지만 뻗는 모양은 트리예요. 지도처럼 어느 정점을 들어 올려도 트리가 되지 않는 관계가 그래프예요.

정답: B

Q2. 모든 간선을 한 번씩 지나 돌아오기

무방향 그래프 V = {A, B, C, D}, E = {(A, B), (B, C), (C, D), (D, A), (A, C)}가 있어요.

한 정점에서 출발해 모든 간선을 딱 한 번씩 지나 출발 정점으로 돌아올 수 있을까요? 판단과 이유를 함께 고르세요.

  1. 돌아올 수 있어요. 간선이 5개로 정점 수 4보다 많아서 충분히 한 바퀴 돌 수 있어요.
  2. 돌아올 수 있어요. 차수가 짝수인 B나 D에서 출발하면 모든 간선을 지나 돌아와요.
  3. 돌아올 수 없어요. A와 C의 차수가 3(홀수)이라 지나갈 때 들어오고 나가는 간선을 짝지을 수 없어요.
  4. 돌아올 수 없어요. 간선의 총수 5가 홀수라서 짝을 맞출 수 없기 때문이에요.
힌트 보기

정점 A, B, C, D마다 붙은 간선 수를 하나씩 세어 보세요.

풀이 보기
  1. "간선이 많으면 한붓그리기가 된다고 봄" — 간선이 많고 적음으로는 판정하지 못해요. 정점마다 붙은 간선 수가 짝수인지 봐야 해요.
  2. "짝수 차수 정점 하나만 있으면 된다고 봄" — 출발점 하나가 아니라 모든 정점의 차수가 짝수여야 해요. A와 C는 차수가 3이에요.
  3. 맞아요. A는 B, D, C와, C는 B, D, A와 이어져 차수가 3이에요. 홀수 차수 정점이 있으면 출발점으로 돌아오는 길이 없어요.
  4. "간선 총수의 홀짝으로 판단함" — 결론은 같지만 이유가 달라요. 판정은 정점마다 붙은 간선 수로 해요. 삼각형처럼 간선 3개여도 모든 차수가 2라 돌아올 수 있어요.

정답: C

Q3. 꺾쇠괄호 간선 읽기

방향 그래프의 간선 집합이 E = {<0, 1>, <1, 2>, <2, 0>}이에요.

이 그래프에 대한 설명으로 맞는 것을 고르세요.

  1. 0에서 1로 가는 간선은 있지만, 1에서 0으로 바로 가는 간선은 없어요.
  2. <0, 1>과 <1, 0>은 같은 간선이라 1에서 0으로도 바로 갈 수 있어요.
  3. 1에서 0으로도 가려면 이 그래프에 무방향 간선 (0, 1)을 하나 더 넣으면 돼요.
  4. 꺾쇠괄호로 쓴 간선에는 거리·요금 같은 값을 붙일 수 없어요.
힌트 보기

꺾쇠괄호 안의 두 정점 중 어느 쪽이 출발이고 어느 쪽이 도착인지부터 정해 보세요.

풀이 보기
  1. 맞아요. 방향 간선은 $\langle 0, 1\rangle \ne \langle 1, 0\rangle$이라 E에 없는 $\langle 1, 0\rangle$은 없는 간선이에요.
  2. "방향 간선도 순서를 무시함" — 순서를 무시해도 되는 건 소괄호로 쓰는 무방향 간선 $(A, B) = (B, A)$뿐이에요.
  3. "한 그래프에 방향·무방향 간선을 섞음" — 수업에서는 한 그래프 안에 방향 간선과 무방향 간선을 섞어 쓰지 않아요. 필요하면 방향 간선 $\langle 1, 0\rangle$을 따로 넣어요.
  4. "방향 간선은 데이터를 못 가진다고 봄" — 정점과 간선은 모두 데이터를 가질 수 있어요. 슬라이드에도 $\langle A, B\rangle$에 1200이 붙은 예가 있어요.

정답: A

Q4. 간선 집합에서 차수 세기

무방향 그래프 V = {0, 1, 2, 3, 4}, E = {(0, 1), (0, 2), (1, 2), (1, 3), (1, 4), (3, 4)}가 있어요.

정점 1의 차수는 얼마일까요?

  1. 3
  2. 6
  3. 8
  4. 4
힌트 보기

간선 집합에서 1이 들어 있는 쌍을 앞자리·뒷자리 가리지 말고 모두 찾아보세요.

풀이 보기
  1. "1이 앞자리에 온 간선만 셈" — (1, 2), (1, 3), (1, 4)만 센 값이에요. (0, 1)도 (1, 0)과 같은 간선이라 1에 붙어 있어요.
  2. "정점의 차수를 그래프의 간선 수로 봄" — 6은 그래프 전체의 간선 수예요. 차수는 그 정점에 연결된 인접 정점의 개수예요.
  3. "무방향 간선 하나를 두 번 셈" — 무방향 간선 하나를 양 끝에서 두 번 센 값이에요. 정점 1 입장에서는 간선 하나가 이웃 하나예요.
  4. 맞아요. 1의 인접 정점은 0, 2, 3, 4로 네 개예요.

정답: D

Q5. 정점 나열 0, 2, 3, 0

무방향 그래프 G의 간선 집합이 E = {(1, 2), (2, 3), (0, 3), (0, 2), (0, 1)}이에요.

G에서 정점을 0, 2, 3, 0 차례로 늘어놓았어요. 이 나열에 대한 설명으로 맞는 것을 고르세요.

  1. 사이클이고, 정점을 4개 적었으니 경로의 길이는 4예요.
  2. 출발 정점 0으로 돌아오는 사이클이고, 경로의 길이는 3이에요.
  3. 0이 두 번 나와서 경로라고 할 수 없어요.
  4. E에는 (3, 0)이 없고 (0, 3)만 있어서 3에서 0으로는 갈 수 없어요.
힌트 보기

이웃한 두 정점마다 E에 그 간선이 있는지 보고, 첫 정점과 마지막 정점을 비교해 보세요.

풀이 보기
  1. "경로의 길이를 정점 수로 셈" — 경로의 길이는 정점 수가 아니라 사용한 간선 수예요. (0, 2), (2, 3), (3, 0) 세 개예요.
  2. 맞아요. 세 간선이 모두 E에 있고, 시작과 끝이 같은 0이라 사이클이에요. 길이는 간선 3개라 3이에요.
  3. "시작·끝 정점이 같으면 경로가 될 수 없다고 봄" — 시작 정점과 끝 정점만 같고 중간 정점은 겹치지 않으니, 단순 경로의 시작과 끝이 같은 사이클이에요.
  4. "무방향 간선도 순서가 다르면 다른 간선으로 봄" — 무방향 간선은 $(0, 3) = (3, 0)$이라 같은 간선이에요. 3에서 0으로도 갈 수 있어요.

정답: B

Q6. 한 줄로 이어진 네 정점

무방향 그래프 V = {0, 1, 2, 3}, E = {(0, 1), (1, 2), (2, 3)}가 있어요.

이 그래프에 대한 설명으로 맞는 것을 고르세요.

  1. 건너서라도 모든 정점에 닿으니 연결 그래프이지만, 완전 그래프는 아니에요.
  2. 건너 건너 모든 정점에 닿을 수 있으니 완전 그래프예요.
  3. 0과 3이 간선으로 직접 이어지지 않았으니 연결 그래프도 될 수 없어요.
  4. 연결 그래프이고, 완전 그래프가 되려면 간선이 모두 4 × 3 = 12개여야 해요.
힌트 보기

0과 3처럼 멀리 떨어진 두 정점을 골라, 간선으로 바로 이어졌는지와 건너서라도 닿는지를 따로 확인해 보세요.

풀이 보기
  1. 맞아요. 0에서 3까지 1, 2를 거쳐 가요. 하지만 (0, 2), (0, 3), (1, 3)이 없어 모든 쌍이 직접 이어지지는 않았어요.
  2. "건너 건너 닿으면 완전 그래프라고 봄" — 건너 건너 닿는 것은 연결 그래프의 조건이에요. 완전 그래프는 모든 정점 쌍이 간선으로 직접 이어져야 해요.
  3. "연결 그래프도 모든 쌍이 직접 이어져야 한다고 봄" — 연결 그래프는 직접 이어지지 않아도 다른 정점을 거쳐 경로가 있으면 돼요.
  4. "무방향 간선을 두 번 세어 n(n-1)로 셈" — 무방향 간선 하나를 양 끝에서 두 번 센 값이에요. 정점 4개 완전 그래프의 간선은 $4 \cdot 3 / 2 = 6$개예요.

정답: A

Q7. 정점 6개 완전 그래프의 간선

정점이 6개인 무방향 완전 그래프에는 간선이 몇 개 있을까요?

  1. 30개
  2. 5개
  3. 15개
  4. 36개
힌트 보기

정점 하나가 간선으로 바로 이어지는 상대가 몇 개인지 먼저 세어 보세요.

풀이 보기
  1. "무방향 간선을 양 끝에서 두 번 셈" — 정점마다 5개씩 세면 30이지만, 간선 하나를 양 끝에서 두 번 센 값이라 2로 나눠야 해요.
  2. "건너 건너 닿으면 완전 그래프라고 봄" — 한 줄로 이어 건너 건너 닿게 하는 데 드는 간선 수예요. 그건 연결 그래프의 모습이에요.

Q8. insert_edge 뒤의 adjacent(0)

방향 그래프 g에 정점 0, 1, 2를 넣은 뒤 insert_edge(g,0,1), insert_edge(g,0,2)를 차례로 불렀어요.

이어서 adjacent(0)을 부르면 무엇을 돌려줄까요?

  1. 정수 2, 정점 0에 붙은 간선의 개수
  2. 빈 리스트, 두 간선 모두 0으로 들어오는 간선이라서
  3. 정점 0, 1, 2가 든 리스트, 그래프의 정점 전체라서
  4. 정점 1, 2가 든 리스트, 0에서 나가는 간선의 도착점이라서
힌트 보기

insert_edge(g,u,v)에서 u와 v 가운데 어느 쪽이 소스인지 먼저 확인해 보세요.

풀이 보기
  1. "adjacent(v)가 차수를 돌려준다고 봄" — adjacent(v)는 개수가 아니라 v에 인접한 정점들의 리스트를 돌려줘요.
  2. "insert_edge의 u를 도착, v를 출발로 거꾸로 읽음" — insert_edge(g,u,v)에서 u가 소스, v가 데스티네이션이라 두 간선은 0에서 나가는 간선이에요.
  3. "adjacent(v)가 그래프의 정점 전체를 돌려준다고 봄" — 인접 정점은 간선 하나로 직접 이어진 정점이에요. 0 자신과 그래프 전체가 아니에요.
  4. 맞아요. 0에서 1, 0에서 2로 가는 간선이 있어서 0에 인접한 정점은 1과 2예요.

정답: D

Q9. 대칭이 깨진 인접 행렬

정점 0~3인 그래프의 인접 행렬이에요. 맨 왼쪽 수가 행, 맨 위 수가 열이에요.

   0 1 2 3
0  0 1 0 0
1  0 0 1 1
2  1 0 0 0
3  0 0 1 0

이 행렬이 나타내는 그래프에 대한 설명으로 맞는 것을 고르세요.

  1. 무방향 그래프이고, 1행 3열이 1이니 간선 (1, 3)이 있어요.
  2. 방향 그래프이고, 간선 <1, 3>은 있지만 <3, 1>은 없어요.
  3. 방향 그래프이고, M[3][2] = 1은 2에서 3으로 가는 간선 <2, 3>이에요.
  4. 대각선이 모두 0이니 이 그래프에는 사이클이 하나도 없어요.
힌트 보기

M[1][3]과 M[3][1]처럼 대각선을 사이에 둔 두 칸을 짝지어 비교해 보세요.

풀이 보기
  1. "1이 있으면 대칭과 상관없이 무방향으로 봄" — 무방향이면 $M[i][j] = M[j][i]$로 대칭이어야 해요. M[1][3]은 1인데 M[3][1]은 0이라 대칭이 깨져 있어요.
  2. 맞아요. 행이 출발, 열이 도착이라 M[1][3] = 1은 $\langle 1, 3\rangle$, M[3][1] = 0이라 $\langle 3, 1\rangle$은 없어요.
  3. "행을 도착, 열을 출발로 거꾸로 읽음" — 행이 출발, 열이 도착이에요. M[3][2] = 1은 3에서 2로 가는 $\langle 3, 2\rangle$예요.
  4. "대각선 칸을 사이클 여부로 봄" — 대각선 칸은 자기 자신으로 가는 간선이에요. 0→1→2→0처럼 여러 정점을 거쳐 도는 사이클은 대각선과 상관없어요.

정답: B

Q10. 헤드 노드에서 읽는 인접 리스트

무방향 그래프를 인접 리스트로 나타냈어요. 맨 왼쪽이 정점마다 둔 헤드 노드예요.

0 → 2 → 3 → NULL
1 → NULL
2 → 0 → 3 → NULL
3 → 0 → 2 → NULL

이 리스트를 읽은 설명으로 맞는 것을 고르세요.

  1. 간선은 (0, 2), (0, 3), (2, 3) 세 개이고, 정점 1에는 간선이 없어요.
  2. 헤드 노드 말고 노드가 6개이니 간선도 6개예요.
  3. 헤드 1이 곧바로 NULL이니 정점 1은 그래프에 없는 정점이에요.
  4. 0의 리스트가 2 → 3 순서이니 0에서 3으로 가려면 꼭 2를 거쳐야 해요.
힌트 보기

헤드 노드 하나씩, 그 정점과 직접 이어진 정점이 무엇인지 적어 보세요.

풀이 보기
  1. 맞아요. 무방향 간선 하나가 두 리스트에 한 번씩 나와 노드 6개가 간선 3개예요. 1의 헤드는 곧바로 NULL이에요.
  2. "무방향 간선이 두 리스트에 나타나는 것을 잊음" — 무방향 간선 (i, j)는 i의 리스트와 j의 리스트에 한 번씩, 두 번 나타나요. 간선은 3개예요.
  3. "간선이 없는 정점은 그래프에서 빠진다고 봄" — 간선이 없어도 정점은 그래프에 있어요. 강의 G2의 정점 3처럼 갈 길이 없는 정점일 뿐이에요.
  4. "리스트 노드 순서를 경로로 읽음" — 리스트의 화살표는 노드를 잇는 링크일 뿐 경로가 아니에요. 3도 0의 리스트에 있으니 0과 3은 직접 이어져 있어요.

정답: A

Q11. 갈림길 앞의 깊이 우선 탐색

정점 0에서 출발했어요. 0과 이어진 정점 1, 2 가운데 1로 갔고, 1에서는 처음 보는 정점 3으로 더 갈 수 있어요.

깊이 우선 탐색(DFS)이 다음에 할 일과, 이 움직임을 보고 떠올릴 자료구조를 고르세요.

  1. 0과 이어진 2를 먼저 다 본 뒤 3으로 내려가요. 떠올릴 자료구조는 스택이에요.
  2. 3으로 먼저 내려가고, 막히면 가장 먼저 지나친 갈림길로 돌아가요. 떠올릴 자료구조는 큐예요.
  3. 0으로 돌아가 2를 본 뒤 다시 3으로 와요. 떠올릴 자료구조는 스택이에요.
  4. 3으로 먼저 내려가고, 막히면 가장 가까운 갈림길로 돌아와요. 떠올릴 자료구조는 스택이에요.
힌트 보기

미로에서 한 방향으로 갈 수 있을 때까지 가는 사람을 떠올리고, 막혔을 때 어느 갈림길로 돌아가는지 생각해 보세요.

풀이 보기
  1. "DFS를 가까운 범위부터 넓게 보는 방법으로 봄" — 가까운 범위를 먼저 다 보고 한 단계 내려가는 것은 BFS의 움직임이에요.
  2. "되돌아갈 갈림길을 먼저 지나친 순서로 고름" — DFS는 막히면 가장 가까운(가장 최근) 갈림길로 돌아와요. 나중에 넣은 것을 먼저 꺼내는 스택이에요.
  3. "갈 곳이 남아도 매번 출발점으로 돌아온다고 봄" — DFS는 더 갈 수 있는 동안에는 돌아가지 않아요. 막혔을 때만 갈림길로 돌아와요.
  4. 맞아요. 한 방향으로 갈 수 있을 때까지 가고, 막히면 가장 최근 갈림길로 돌아오니 스택을 떠올려요.

정답: D

Q12. 방문 검사 조건을 지우면

DFS 의사코드에서 if (u가 아직 방문되지 않았으면) 줄을 지우고, 인접 정점 u마다 무조건 depth_first_search(u)를 부르게 바꿨어요.

depth_first_search(v)
    v를 방문되었다고 표시;
    for all u ∈ (v에 인접한 정점) do
        depth_first_search(u)

무방향 그래프 E = {(0, 1), (1, 2), (2, 0)}에서 depth_first_search(0)을 부르면 어떤 일이 생길까요?

  1. 방문 표시 배열에 1을 적어 두니 같은 정점은 한 번만 처리돼요.
  2. for문이 인접 정점을 다 돌면 끝나니 탐색은 끝나고 방문 순서만 바뀌어요.
  3. 0이 1을 부르고 1이 다시 0을 부르는 식으로 호출이 끝없이 이어져요.
  4. 조건문이 사라져 재귀가 반복문으로 바뀌므로 너비 우선 탐색(BFS)처럼 돌아요.
힌트 보기

0이 1을 부른 뒤, 1의 인접 정점 목록에 누가 들어 있는지 보세요.

풀이 보기
  1. "표시만 하면 검사 없이도 재호출이 막힌다고 봄" — 표시는 남지만 그 값을 읽는 조건을 지웠으니 표시가 호출을 막지 못해요.
  2. "사이클이 있어도 반복은 언젠가 끝난다고 봄" — for문이 끝나기 전에 재귀 호출이 다시 같은 정점들을 불러서, 사이클을 따라 끝없이 돌아요.
  3. 맞아요. 무방향이라 1의 인접 정점에 0이 있어요. 방문 검사가 없으니 0과 1이 서로를 계속 다시 불러요.
  4. "방문 검사 조건이 재귀 여부를 정한다고 봄" — 재귀 호출은 그대로 남아 있어요. 조건문은 재귀 여부가 아니라 이미 방문한 정점을 거르는 역할이에요.

정답: C

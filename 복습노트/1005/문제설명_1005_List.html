6장 연결 리스트 I · 07번 · 책 216쪽

다음과 같은 연결 리스트에 아래와 같은 코드를 실행한다고 하자. 실행이 끝난 후에 포인터 p가 가리키는 노드는 어떤 노드인가?

data link

for(p=list->head; p->link!= NULL; p=p->link)
    ;

문제를 내 말로 읽어요

A→B→C→D→NULL에서 for 종료 후 p가 가리키는 노드를 구해요. 빈 리스트는 그림의 조건이 아니에요.

이 문제를 봤을 때 떠올릴 개념과 공식

조건은 p!=NULL이 아니라 p->link!=NULL이에요. 현재 노드의 다음 주소가 없을 때 현재 노드에서 멈춰요. 빈 본문 뒤 세미콜론도 반복문 본문이에요.

종이에 적을 첫 줄

p=A, A.link=B≠NULL을 적어요.

왜 이렇게 푸는지 함께 따라가요

A에서 조건 참→B, B에서 참→C, C에서 참→D, D에서는 link=NULL이라 거짓이에요. 따라서 답은 D 노드예요. p를 NULL까지 이동시키지 않아요.

완성 답과 검산

각 검사 시점의 p는 A,B,C,D로 네 번이고 이동은 세 번이에요. 한 노드인 경우 첫 조건이 거짓으로 그 노드에서 멈추는 규칙도 같아요.

이 문제에서 조심할 점

head=NULL일 때 이 코드의 p->link는 UB예요. 주어진 비어 있지 않은 그림에서만 계산해요.

설명을 닫고 다시 해 봐요

  1. p=A, A.link=B≠NULL을 적어요.
  2. 다음 링크 검사 → 마지막 D에서 정지
  3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

첫 줄

p=A, A.link=B≠NULL을 적어요.

떠올릴 개념·공식

다음 링크 검사 → 마지막 D에서 정지

검산

본문의 조건과 독립 추적을 함께 확인해요.

조건·구분과 확인

  • 비어 있지 않은 리스트에서 p->link!=NULL을 검사하므로 마지막 D에 남아요. head==NULL에는 p->link 역참조를 적용할 수 없어요.

6장 연결 리스트 I · 10번 · 책 217쪽

다음과 같이 단순 연결 리스트의 노드들의 개수를 계산하는 프로그램을 작성해보자.

노드의 개수 : 3 [Enter↵]
노드 #1 데이터 : 5 [Enter↵]
노드 #2 데이터 : 6 [Enter↵]
노드 #3 데이터 : 7 [Enter↵]
연결 리스트 노드의 개수 = 3

문제를 내 말로 읽어요

입력 노드들을 연결하고 head에서 출발해 실제 노드 수를 세는 프로그램을 만들어요.

이 문제를 봤을 때 떠올릴 개념과 공식

linked list traversal은 link를 따라 NULL까지 방문하는 것이에요. 입력으로 받은 n을 그대로 결과로 쓰는 대신 실제 연결 구조를 세어야 해요. count는 방문한 노드 수예요.

종이에 적을 첫 줄

int count = 0;

왜 이렇게 푸는지 함께 따라가요

#include <stdio.h>
#include <stdlib.h>
typedef struct Node { int data; struct Node *link; } Node;
int count_nodes(const Node *head) {
    int count=0;
    for (const Node *p=head; p!=NULL; p=p->link) ++count;
    return count;
}
int main(void) {
    int n, value, ok=1;
    Node *head=NULL, *tail=NULL;
    printf("노드의 개수 : ");
    if (scanf("%d", &n)!=1 || n<0 || n>10000) return 1;
    for (int i=0; i<n; ++i) {
        printf("노드 #%d 데이터 : ", i+1);
        if (scanf("%d", &value)!=1) { ok=0; break; }
        Node *node=malloc(sizeof *node);
        if (node==NULL) { ok=0; break; }
        node->data=value; node->link=NULL;
        if (tail) tail->link=node; else head=node;
        tail=node;
    }
    if (ok) printf("연결 리스트 노드의 개수 = %d\n", count_nodes(head));
    while (head) { Node *next=head->link; free(head); head=next; }
    return ok?0:1;
}

완성 답과 검산

입력 3,5,6,7로 5→6→7→NULL이 만들어져 count는 0→1→2→3이에요. 빈 입력 n=0에서는 0이에요. count가 이미 방문한 접두 노드 수라는 불변식으로 acyclic 리스트의 정확성을 확인해요. 10000 제한은 검산 프로그램의 입력 보호 선택이에요.

이 문제에서 조심할 점

마지막 노드도 세어야 하므로 조건을 p->link!=NULL로 쓰지 않아요. 순환 링크를 가진 구조는 이 단순 리스트 전제 밖이에요.

설명을 닫고 다시 해 봐요

  1. int count = 0;
  2. head부터 p!=NULL 동안 한 노드당 +1
  3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

첫 줄

int count = 0;

떠올릴 개념·공식

head부터 p!=NULL 동안 한 노드당 +1

검산

본문의 조건과 독립 추적을 함께 확인해요.

조건·구분과 확인

  • 비순환 단순 리스트를 실제로 순회해 마지막 노드까지 세고 빈 리스트는 0이에요. 입력 n을 그대로 반환하지 않고, p->link!=NULL로 마지막을 빼먹지 않아요.

P3. 두 연결 리스트를 이어 붙일 때

lecture-s04-p31-concat · 원 문제 보기

강의 예제 기반 자체 출제 S4 p31

서로 노드를 공유하지 않는 두 단순 연결 리스트 head1 = A -> B -> NULL, head2 = C -> D -> NULL에 대해 아래 concat 함수를 호출해요.

ListNode *concat(ListNode *head1,ListNode *head2)
{
    ListNode *p;
    if(head1==NULL) return head2;
    else if(head2==NULL) return head1;
    else {
        p=head1;
        while(p->link!=NULL) p=p->link;
        p->link=head2;
        return head1;
    }
}

구할 것

  1. (a) concat(head1, head2) 실행 시 포인터 p가 이동을 멈추는 노드, 새로 연결되는 링크 대입식(p->link = head2), 반환 포인터 및 결과 체인을 쓰세요.
  2. (b) head1 == NULL일 때의 반환값과, 반복 조건을 while (p != NULL)로 잘못 썼을 때 생기는 오류 및 첫 리스트 길이 $m$에 대한 시간 복잡도를 설명하세요.
강의 예제 보기

S4 p31 · Software_4_List.pdf. 강의 코드의 해당 연산을 발췌해 들여쓰기를 정리했습니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

ListNode *concat(ListNode *head1,ListNode *head2)
{
    ListNode *p;
    if(head1==NULL) return head2;
    else if(head2==NULL) return head1;
    else {
        p=head1;
        while(p->link!=NULL) p=p->link;
        p->link=head2;
        return head1;
    }
}

문제를 내 말로 읽어요

두 단순 연결 리스트 head1 = A -> B -> NULL과 head2 = C -> D -> NULL을 concat으로 이어 붙일 때 마지막 노드 탐색 조건과 시간 복잡도를 확인하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “두 연결 리스트를 이어 붙일 때”예요. 첫 리스트의 마지막 노드 p(p->link == NULL)를 찾아 p->link = head2로 연결하며, 마지막 노드에서 멈추려면 반복 조건이 p->link != NULL이어야 해요.

종이에 적을 첫 줄

p = head1 = A에서 시작해 p->link != NULL을 검사해요.

왜 이렇게 푸는지 함께 따라가요

(a) p = A에서 A->link = B != NULL이므로 p = B로 이동하고, B->link == NULL에서 루프를 멈춰요. 이어서 B->link = C(p->link = head2)를 대입하고 head1 = A를 반환하므로 결과 체인은 A -> B -> C -> D -> NULL이에요.

(b) head1 == NULL이면 첫 if문에서 곧바로 head2를 반환해요. 만약 반복 조건을 while (p != NULL)로 쓰면 루프가 끝날 때 p == NULL이 되어 p->link = head2에서 널 포인터 역참조 오류가 발생해요. 첫 리스트의 길이 $m$만큼 순회해 꼬리를 찾으므로 시간 복잡도는 $O(m)$이에요.

완성 답과 검산

(a) A -> B의 마지막 노드 B의 link만 C로 바뀌고 나머지 링크는 보존되어 4개 노드가 순서대로 연결돼요.

(b) 두 번째 리스트의 길이 $n$과 무관하게 첫 리스트의 마지막 노드에 head2 포인터만 대입하므로 시간 복잡도는 $O(m)$이에요.

이 문제에서 조심할 점

단순 이어 붙이기는 정렬 병합이 아니며 두 리스트를 값 순으로 섞지 않아요.

설명을 닫고 다시 해 봐요

  1. while (p->link != NULL)이 멈추는 노드 p와 연결 대입식을 적어요.
  2. head1 == NULL일 때의 반환값과 while (p != NULL)의 오류 원인을 설명해요.
  3. 첫 리스트 길이 $m$에 대한 시간 복잡도를 확인해요.

첫 줄

p = head1 = A에서 시작해 p->link != NULL을 검사해요.

떠올릴 개념·공식

마지막 노드에서 멈추려면 while (p->link != NULL)로 이동한 뒤 p->link = head2를 대입해요.

검산

(a) p = B에서 멈추고 B->link = C, 반환 A, 체인 A -> B -> C -> D -> NULL (b) head1 == NULL이면 head2 반환, while (p != NULL)은 널 역참조 오류, 시간 복잡도 $O(m)$

조건·구분과 확인

  • 두 입력은 노드를 공유하지 않는 단순 리스트라는 전제이며, concat은 정렬 병합이 아닌 순서 그대로의 이어 붙이기예요.

P4. 역순 코드의 세 포인터

lecture-s04-p32-reverse · 원 문제 보기

강의 예제 기반 자체 출제 S4 p32

단순 연결 리스트 head = A -> B -> C -> NULL에 대해 아래 reverse(head) 함수를 호출해요.

ListNode *reverse(ListNode *head)
{
    ListNode *p,*q,*r;
    p=head; q=NULL;
    while(p!=NULL) {
        r=q;
        q=p;
        p=p->link;
        q->link=r;
    }
    return q;
}

구할 것

  1. (a) while 루프 1~3회차가 끝난 직후마다 포인터 (r, q, p)가 가리키는 노드와 이미 역순으로 뒤집힌 부분 체인(q부터 시작하는 체인)을 쓰세요.
  2. (b) 루프 안에서 q = p; p = p->link; 전에 q->link = r;를 먼저 실행하면 안 되는 이유와, 공백 리스트(head == NULL) 입력 시 반환값을 설명하세요.
강의 예제 보기

S4 p32 · Software_4_List.pdf. 강의 코드의 해당 연산을 발췌해 들여쓰기를 정리했습니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

ListNode *reverse(ListNode *head)
{
    ListNode *p,*q,*r;
    p=head; q=NULL;
    while(p!=NULL) {
        r=q;
        q=p;
        p=p->link;
        q->link=r;
    }
    return q;
}

문제를 내 말로 읽어요

세 포인터 r, q, p를 한 칸씩 밀며 링크 방향을 뒤집는 reverse 함수를 1~3회차까지 추적하고 대입 순서의 이유를 확인하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “역순 코드의 세 포인터”예요. p는 아직 뒤집지 않은 앞부분, q는 현재 뒤집을 노드, r은 이미 뒤집힌 리스트의 첫 노드를 가리키며, 반드시 p = p->link로 다음 노드를 먼저 대피시킨 뒤 q->link = r로 방향을 뒤집어야 해요.

종이에 적을 첫 줄

루프 진입 전 초기 상태 p = A, q = NULL을 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) 1회차 종료 시 (r, q, p) = (NULL, A, B)이고 뒤집힌 부분은 A -> NULL이에요. 2회차 종료 시 (r, q, p) = (A, B, C)이고 뒤집힌 부분은 B -> A -> NULL이에요. 3회차 종료 시 (r, q, p) = (B, C, NULL)이고 뒤집힌 부분은 C -> B -> A -> NULL이 되어 루프가 끝나고 q = C를 반환해요.

(b) 만약 q = p; p = p->link; 전에 q->link = r;를 먼저 실행하면, q와 p가 같은 노드를 가리킬 때 그 노드의 link가 r로 덮어써져 원래 다음 노드로 가는 주소를 잃어버려요. 공백 리스트(head == NULL) 입력 시에는 루프를 건너뛰고 초기값 q = NULL을 그대로 반환해요.

완성 답과 검산

(a) 3회 반복 후 p == NULL이 되어 모든 노드가 소비되었고, 반환된 q = C부터 따라가면 C -> B -> A -> NULL로 역순이 완성돼요.

(b) 1회차에서 q = p(A) 직후 q->link = r(NULL)을 먼저 하면 A->link = NULL이 되어 p = p->link가 B 대신 NULL이 됨을 대입으로 확인할 수 있어요.

이 문제에서 조심할 점

원래 head 변수가 자동으로 새 첫 노드를 가리키는 것은 아니므로 호출자가 반환값을 받아야 해요.

설명을 닫고 다시 해 봐요

  1. 1~3회차 종료 시점마다 (r, q, p)와 q부터 시작하는 체인을 표로 적어요.
  2. q->link = r을 p = p->link보다 먼저 실행할 때 1회차에서 생기는 일을 추적해요.
  3. head == NULL일 때의 반환값을 확인해요.

첫 줄

루프 진입 전 초기 상태 p = A, q = NULL을 적어요.

떠올릴 개념·공식

r = q; q = p; p = p->link;로 포인터를 먼저 한 칸씩 전진시킨 뒤 q->link = r;로 링크를 뒤집어요.

검산

(a) 1회 (NULL, A, B), 2회 (A, B, C), 3회 (B, C, NULL), 최종 C -> B -> A -> NULL (b) q->link = r을 먼저 하면 다음 노드 주소 손실, 공백 입력 반환 NULL

조건·구분과 확인

  • 호출자의 head가 자동으로 바뀌지 않으므로 head=reverse(head)로 반환된 새 첫 노드를 받아야 해요.

P5. 연결 리스트 삽입의 세 경우

lecture-s04-p25-insert-node · 원 문제 보기

강의 예제 기반 자체 출제 S4 p25

새로 동적 할당한 노드 new_node = N을 단순 연결 리스트에 삽입하는 아래 insert_node 함수를 세 가지 독립적인 상황에서 호출해요.

void insert_node(ListNode **phead,ListNode *p,ListNode *new_node)
{
    if(*phead==NULL) {
        new_node->link=NULL;
        *phead=new_node;
    } else if(p==NULL) {
        new_node->link=*phead;
        *phead=new_node;
    } else {
        new_node->link=p->link;
        p->link=new_node;
    }
}

구할 것

  1. (a) 공백 리스트(*phead == NULL), A -> B -> NULL에서 맨 앞 삽입(p == NULL), 같은 리스트에서 중간 삽입(p == A) 세 경우 각각에 대해 실행되는 링크 대입과 결과 체인을 쓰세요.
  2. (b) 마지막 분기(else)에서 두 대입문 new_node->link = p->link;와 p->link = new_node;의 순서를 바꾸면 뒷부분 노드를 잃어버리는 이유와, 매개변수로 이중 포인터 ListNode **phead를 쓰는 이유를 설명하세요.

문제를 내 말로 읽어요

단순 연결 리스트의 insert_node에서 공백·맨 앞·중간 삽입 세 경우의 결과를 구하고, 대입 순서와 이중 포인터 ListNode **phead의 역할을 확인하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “연결 리스트 삽입의 세 경우”예요. *phead == NULL(공백), p == NULL(맨 앞), p != NULL(선행 노드 p 뒤)로 분기하며, 중간 삽입에서는 new_node->link = p->link를 먼저 연결해야 뒷노드를 잃지 않아요.

종이에 적을 첫 줄

세 경우를 *phead == NULL / p == NULL / p == A로 나누어 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) ① 공백 리스트(*phead == NULL): N->link = NULL; *phead = N;으로 N -> NULL이 돼요. ② 맨 앞 삽입(p == NULL): N->link = A; *phead = N;으로 N -> A -> B -> NULL이 돼요. ③ 중간 삽입(p == A): N->link = B; A->link = N;으로 A -> N -> B -> NULL이 돼요.

(b) 중간 삽입에서 p->link = new_node;를 먼저 실행하면 p->link가 N으로 덮어써져 다음 줄 new_node->link = p->link;가 N->link = N(자기 순환)이 되고 원래 뒷노드 B를 잃어버려요. 또한 공백·맨 앞 삽입에서는 호출자의 head 포인터 변수 값을 새 노드로 바꿔야 하므로 이중 포인터 ListNode **phead를 받아요.

완성 답과 검산

(a) 세 경우 모두 새 노드 N의 link가 기존 후속 노드(NULL, A, B)를 먼저 가리킨 뒤 앞쪽 포인터(*phead 또는 A->link)가 N으로 갱신돼요.

(b) 단일 포인터 ListNode *head로 받으면 함수 지역 매개변수만 바뀌고 호출자의 head는 갱신되지 않음을 확인할 수 있어요.

이 문제에서 조심할 점

p == NULL은 리스트가 비어 있다는 뜻이 아니라 선행 노드가 없어 맨 앞에 삽입한다는 뜻이에요.

설명을 닫고 다시 해 봐요

  1. 공백, p == NULL, p == A 세 경우의 결과 체인을 각각 적어요.
  2. 중간 삽입의 두 대입문 순서를 바꾸면 N->link가 무엇이 되는지 확인해요.
  3. ListNode **phead 이중 포인터가 필요한 분기를 짚어 봐요.

첫 줄

세 경우를 *phead == NULL / p == NULL / p == A로 나누어 적어요.

떠올릴 개념·공식

새 노드의 link를 먼저 이어 준 뒤 앞 포인터(*phead 또는 p->link)를 새 노드로 바꿔요.

검산

(a) 공백: N -> NULL, p == NULL: N -> A -> B -> NULL, p == A: A -> N -> B -> NULL (b) 순서 역전 시 B 유실, 호출자 head 변경을 위해 ListNode **phead 사용

조건·구분과 확인

  • p==NULL은 리스트 공백이 아니라 선행 노드가 없어 맨 앞에 넣는다는 뜻이에요.

P6. 삭제할 노드를 해제하기 전의 연결

lecture-s04-p28-remove-node · 원 문제 보기

강의 예제 기반 자체 출제 S4 p28

각 노드를 malloc으로 할당한 단순 연결 리스트 head = A -> B -> C -> NULL에서 아래 remove_node 함수를 호출해요.

void remove_node(ListNode **phead,ListNode *p,ListNode *removed)
{
    if(p==NULL) *phead=(*phead)->link;
    else p->link=removed->link;
    free(removed);
}

  1. (a) 중간 노드 B를 삭제할 때와 맨 앞 노드 A를 삭제할 때 각각 전달할 (p, removed) 인자와 삭제 후 체인을 쓰고, 노드가 A 하나뿐인 리스트에서 A를 삭제한 뒤 head 값을 쓰세요.
  2. (b) p == NULL(맨 앞 삭제) 분기가 따로 필요한 이유와, 링크 갱신 전에 free(removed)를 먼저 호출하면 안 되는 이유를 설명하세요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “삭제할 노드를 해제하기 전의 연결”이에요. p는 삭제 대상 removed의 직전 노드(맨 앞 삭제는 p == NULL)이며, removed->link를 앞쪽에 이어 준 뒤에야 free(removed)를 호출할 수 있어요.

종이에 적을 첫 줄

B 삭제는 (p = A, removed = B), A 삭제는 (p = NULL, removed = A)로 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) 중간 노드 B를 삭제할 때는 p = A, removed = B를 전달해 A->link = B->link(C)가 되어 A -> C -> NULL이 돼요. 맨 앞 노드 A를 삭제할 때는 p = NULL, removed = A를 전달해 *phead = A->link(B)가 되어 B -> C -> NULL이 돼요. 노드가 A 하나뿐이면 *phead = A->link = NULL이 되어 head = NULL이 돼요.

(b) 맨 앞 노드는 선행 노드 p가 없으므로 p->link 대신 시작 포인터 *phead를 바꿔야 해 p == NULL 분기가 따로 필요해요. 또한 링크를 잇기 전에 free(removed)를 먼저 호출하면 이미 해제된 메모리의 removed->link를 읽는 오류가 발생해요.

완성 답과 검산

(a) 두 삭제 모두 삭제 대상 노드를 우회해 앞뒤를 연결한 뒤 free(removed)로 정확히 1개 노드를 해제해요.

(b) 단일 노드 A(link = NULL)에서 p == NULL 분기를 실행하면 *phead = NULL이 되어 공백 불변식이 성립해요.

이 문제에서 조심할 점

단순 연결 리스트에서는 삭제 대상 포인터 removed만으로는 직전 노드 p의 link를 고칠 수 없어 선행 노드 포인터 p가 함께 필요해요.

설명을 닫고 다시 해 봐요

  1. B 삭제와 A 삭제에서 (p, removed)와 결과 체인을 적어요.
  2. 단일 노드 삭제 후 head가 무엇이 되는지 확인해요.
  3. p == NULL 분기와 free(removed) 호출 순서의 이유를 설명해요.

첫 줄

B 삭제는 (p = A, removed = B), A 삭제는 (p = NULL, removed = A)로 적어요.

떠올릴 개념·공식

선행 노드 p(또는 *phead)의 링크를 removed->link로 먼저 우회시킨 뒤 free(removed)를 호출해요.

검산

(a) B 삭제: (A, B) → A -> C -> NULL, A 삭제: (NULL, A) → B -> C -> NULL, 단일 삭제 후 head = NULL (b) 맨 앞은 *phead 갱신 필요, free 선행 시 해제 메모리 접근 오류

P7. 꼬리를 head로 두는 원형 리스트

lecture-s04-p35-circular-last · 원 문제 보기

강의 예제 기반 자체 출제 S4 p35

head가 마지막(꼬리) 노드를 가리키고 head->link가 첫 노드를 가리키는 원형 연결 리스트(현재 A -> B -> A, head = B)에 새 노드 N을 삽입해요.

void insert_last(ListNode **phead,ListNode *node)
{
    if(*phead==NULL) {
        *phead=node; node->link=node;
    } else {
        node->link=(*phead)->link;
        (*phead)->link=node;
        *phead=node;
    }
}

구할 것

  1. (a) insert_last(&head, N) 실행 후 각 노드의 link(A->link, B->link, N->link)와 head 및 첫 노드를 쓰세요.
  2. (b) 마지막 줄 *phead = node;를 생략하면 논리적으로 어떤 위치 삽입이 되는지 쓰고, head가 꼬리 노드를 가리키게 설계할 때 맨 앞(insert_first)·맨 뒤(insert_last) 삽입이 모두 $O(1)$이 되는 이유를 설명하세요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “꼬리를 head로 두는 원형 리스트”예요. 이 구조에서 꼬리는 head이고 첫 노드는 head->link이므로, 새 노드를 head와 head->link 사이에 끼운 뒤 head를 새 노드로 옮기면 맨 뒤 삽입이 돼요.

종이에 적을 첫 줄

초기 상태에서 꼬리 head = B, 첫 노드 head->link = A임을 표시해요.

왜 이렇게 푸는지 함께 따라가요

(a) node->link = (*phead)->link로 N->link = A를 연결하고, (*phead)->link = node로 B->link = N을 연결한 뒤, *phead = node로 head = N으로 바꿔요. 따라서 A->link = B, B->link = N, N->link = A이고, head = N, 첫 노드는 A예요.

(b) 마지막 *phead = node;를 생략하면 head = B가 그대로 남아 첫 노드(head->link)가 N이 되므로 맨 앞 삽입(insert_first)이 돼요. head가 꼬리 노드를 가리키면 꼬리(head)와 첫 노드(head->link)를 모두 순회 없이 즉시 알 수 있어 맨 앞·맨 뒤 삽입이 모두 $O(1)$에 수행돼요.

완성 답과 검산

(a) 첫 노드 head->link = N->link = A부터 따라가면 A -> B -> N -> A로 순환하며 새 꼬리가 N으로 일치해요.

(b) 만약 head가 첫 노드를 가리켰다면 마지막 노드의 link를 고치기 위해 리스트 끝까지 $O(n)$ 순회가 필요했을 거예요.

이 문제에서 조심할 점

이 구현에서 head를 첫 노드라고 해석하면 모든 결과가 한 칸씩 어긋나요.

설명을 닫고 다시 해 봐요

  1. insert_last(&head, N)의 세 대입문을 따라 각 노드의 link와 head를 적어요.
  2. 마지막 줄 *phead = node; 유무가 insert_first와 insert_last를 어떻게 가르는지 비교해요.
  3. 꼬리를 가리키는 head가 양끝 삽입을 $O(1)$로 만드는 이유를 설명해요.

첫 줄

초기 상태에서 꼬리 head = B, 첫 노드 head->link = A임을 표시해요.

떠올릴 개념·공식

원형 리스트에서 head가 꼬리를 가리키면 첫 노드는 head->link이므로 양끝 삽입이 모두 $O(1)$이에요.

검산

(a) A->link = B, B->link = N, N->link = A, head = N, 첫 노드 A (b) *phead = node 생략 시 insert_first, 양끝 모두 $O(1)$

이중 원형 연결 리스트에서 before = A와 오른쪽 이웃 B 사이에 새 노드 N을 삽입·삭제할 때의 링크 대입문과 대입 순서를 확인하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “이중 연결 리스트의 삽입과 삭제”예요. dinsert_node에서는 새 노드의 양쪽 링크를 먼저 설정한 뒤 before->rlink->llink = new_node를 before->rlink = new_node보다 먼저 실행해야 기존 오른쪽 노드 B의 주소를 잃지 않아요.

종이에 적을 첫 줄

before = A의 현재 오른쪽 이웃이 before->rlink = B임을 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) 4개 대입문이 순서대로 실행되면 N->llink = A, N->rlink = B, B->llink = N, A->rlink = N이 되어 A <-> N <-> B가 완성돼요. 삽입한 N을 다시 삭제할 때는 N->llink->rlink = N->rlink;(A->rlink = B)와 N->rlink->llink = N->llink;(B->llink = A)로 양옆을 연결한 뒤 free(N)을 호출해요.

(b) 만약 before->rlink = new_node;를 먼저 실행하면 before->rlink가 B가 아니라 N을 가리키게 되어, 다음 문장 before->rlink->llink = new_node;가 N->llink = N으로 바뀌고 원래 오른쪽 노드 B의 llink는 갱신되지 않아요.

완성 답과 검산

(a) 삽입 후 A->rlink->llink == A(N->llink == A)와 B->llink->rlink == B(N->rlink == B)가 모두 성립하며, 삭제 후에는 다시 A->rlink == B, B->llink == A로 복원돼요.

(b) 역순 실행 시 B->llink가 여전히 옛 값 A를 가리켜 역방향 순회가 깨짐을 확인할 수 있어요.

이 문제에서 조심할 점

새 노드 자신의 두 링크만 설정해서는 기존 양옆 노드가 새 노드를 가리키지 않아요.

설명을 닫고 다시 해 봐요

  1. dinsert_node(A, N)의 4개 대입문 결과를 순서대로 적어요.
  2. 마지막 두 대입문 순서를 바꾸면 어느 링크가 잘못되는지 확인해요.
  3. N을 삭제할 때 양옆을 이어 주는 두 대입문을 적어요.

첫 줄

before = A의 현재 오른쪽 이웃이 before->rlink = B임을 적어요.

떠올릴 개념·공식

새 노드의 llink, rlink를 먼저 정한 뒤 before->rlink->llink = new_node 후 before->rlink = new_node 순서로 갱신해요.

검산

(a) N->llink = A, N->rlink = B, B->llink = N, A->rlink = N; 삭제: N->llink->rlink = N->rlink; N->rlink->llink = N->llink; (b) 순서 역전 시 N->llink = N이 되고 B->llink 미갱신

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “방문 순서와 탐색의 반환값”이에요. 방문(traversal)은 현재 노드를 처리한 뒤 p->link로 넘어가고, 탐색(search)은 값 x와 일치하는 노드의 주소(ListNode *)를 반환하며 실패 시 NULL을 반환해요.

종이에 쓰는 첫 줄

첫 호출에서 p = A(p != NULL)이므로 10->을 출력한 뒤 B로 이동해요.

왜 이렇게 푸는지 함께 따라가요

(a) display_recur(head)는 현재 노드의 data를 출력한 뒤 p->link로 재귀 호출하므로 10->20->30->을 출력해요. search(head, 20)은 B->data == 20에서 일치하므로 정수 20이 아니라 노드 B의 주소(ListNode *)를 반환하고, search(head, 99)는 끝까지 일치하는 노드가 없어 NULL을 반환해요.

(b) 두 함수 모두 지역 포인터 p만 이동할 뿐 노드의 link나 호출자의 head를 수정하지 않으므로 원래 리스트가 그대로 유지돼요. 공백 리스트(head == NULL)에서는 display_recur가 출력 없이 종료하고 search는 NULL을 반환하며, 재귀 호출마다 p->link로 이동해 남은 노드 수가 1씩 줄어들다가 유한 리스트의 끝 NULL에 도달하므로 유한 번 만에 종료해요.

완성 답과 검산

(a) 출력 노드 수는 3개(10->20->30->)이며, search(head, 20)이 반환한 포인터를 역참조하면 data == 20임을 확인할 수 있어요.

(b) 함수 내부에 p->link = ... 같은 쓰기 문장이 없으므로 원본 체인은 불변이에요.

이 문제에서 조심할 점

search의 반환 타입은 ListNode *이므로 정수 20이 아니에요. 재귀 인자를 p->link 대신 p로 주면 무한 재귀에 빠져요.

  1. display_recur(head)의 출력 문자열과 search의 성공·실패 반환값을 적어요.
  2. 호출 후 원본 head와 링크가 바뀌지 않는 이유를 설명해요.
  3. 공백 입력 시 동작과 재귀 종료 근거를 점검해요.

떠올릴 개념·공식

재귀 방문은 p->data 출력 후 p->link로 호출해 NULL에서 멈추고, search는 일치 노드의 주소(ListNode *) 또는 NULL을 반환해요.

핵심 답

P10. 헤드 포인터와 헤드 노드의 공백 표현

lecture-s04-p37-sentinel-empty-model · 원 문제 보기

강의 예제 기반 자체 출제 S4 p37

연결 리스트의 공백 상태 표현과 ListType 래퍼 구조체 및 하위 노드 함수의 인터페이스는 아래와 같아요.

typedef struct { ListNode *head; int length; } ListType;
void insert_node(ListNode **phead, ListNode *p, ListNode *new_node); // p 뒤에 삽입 (p==NULL이면 맨 앞)
void remove_node(ListNode **phead, ListNode *p, ListNode *removed);  // p 다음의 removed 삭제 (p==NULL이면 맨 앞)

구할 것

  1. (a) 데이터 노드가 하나도 없을 때 ① 헤드 노드 없는 단순·원형 연결 리스트의 head 값, ② 헤드 노드 H가 있는 이중 원형 연결 리스트의 H->llink·H->rlink 값, ③ 헤드 노드 없는 공백 ListType의 head·length 값을 각각 쓰고, 헤드 포인터와 헤드 노드(H)의 차이 및 H->rlink·H->llink가 가리키는 대상을 설명하세요.
  2. (b) ListType에서 get_length의 시간 복잡도가 $O(1)$인 이유와 삽입·삭제 시 length를 함께 갱신해야 하는 이유를 쓰고, 위치를 받는 add(list, pos, x)·delete(list, pos)가 하위 함수 insert_node·remove_node를 재사용하는 방법을 설명하세요.
강의 예제 보기

S4 p37 · 추가 근거 p33,34,35,36,45,46,44,47,48 · Software_4_List.pdf. 강의 개념·그림을 근거로 질문을 직접 작성했습니다. 문제의 ListType 선언은 S4 p45의 강의 코드를 옮긴 것이고, 나머지는 강의 원문 코드의 전사가 아닙니다. 질문·입력 조건·검산은 자체 작성했어요.

문제를 내 말로 읽어요

헤드 노드가 없는 연결 리스트와 헤드 노드 H가 있는 이중 원형 리스트, 그리고 ListType 구조체의 공백 표현과 하위 함수 재사용 원리를 비교하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “헤드 포인터와 헤드 노드의 공백 표현”이에요. 헤드 포인터는 시작 주소를 담는 포인터 변수이고, 헤드 노드 H는 경계 처리를 단순화하는 더미(센티널) 노드여서 공백일 때 H->llink = H, H->rlink = H로 자기 자신을 가리켜요.

종이에 쓰는 첫 줄

헤드 노드 없음: head = NULL / 헤드 노드 H 있음: H->llink = H, H->rlink = H.

왜 이렇게 푸는지 함께 따라가요

(a) 데이터 노드가 하나도 없을 때 ① 헤드 노드 없는 단순·원형 리스트는 head = NULL, ② 헤드 노드 H가 있는 이중 원형 리스트는 H->llink = H, H->rlink = H, ③ 공백 ListType은 head = NULL, length = 0이에요. 헤드 포인터는 주소 변수이고 H는 실제 데이터가 아닌 더미 노드로, 리스트가 비어 있지 않으면 H->rlink는 첫 데이터 노드, H->llink는 마지막 데이터 노드를 가리켜요.

(b) ListType의 get_length는 노드를 순회하지 않고 저장된 length를 바로 반환하므로 $O(1)$이며, 실제 노드 수와 일치하도록 삽입·삭제 때마다 length를 증감해야 해요. 위치를 받는 add·delete는 위치 인덱스를 선행 노드 포인터 p(와 삭제 대상 removed)로 변환한 뒤 insert_node·remove_node를 호출해 기존 연결 함수를 재사용해요.

완성 답과 검산

(a) 공백 이중 원형 리스트에서 H->llink = H, H->rlink = H이면 첫 노드를 before = H 뒤에 넣을 때도 일반 dinsert_node(H, new_node)가 예외 분기 없이 그대로 성립해요.

(b) pos == 0이면 p = NULL을, pos > 0이면 pos - 1번째 노드의 주소를 p로 넘기면 insert_node·remove_node의 계약과 정확히 맞물려요.

이 문제에서 조심할 점

모든 공백 연결 리스트의 head가 NULL이라고 일반화하지 않아요. 헤드 노드 유무에 따라 공백 조건이 달라져요.

설명을 닫고 다시 해 봐요

  1. 세 연결 구조의 공백 상태(head, H->llink/rlink, length)를 각각 적어요.
  2. 헤드 포인터와 헤드 노드 H의 차이 및 H->rlink·H->llink가 가리키는 대상을 설명해요.
  3. ListType의 $O(1)$ 길이 조회 이유와 insert_node·remove_node 재사용 방법을 정리해요.

떠올릴 개념·공식

헤드 노드 없는 공백은 head = NULL, 헤드 노드 H가 있는 이중 원형 공백은 H->llink = H, H->rlink = H예요.

첫 줄

헤드 노드 없음: head = NULL / 헤드 노드 H 있음: H->llink = H, H->rlink = H.

핵심 답

(a) 단순·원형 공백 head = NULL, 이중 원형 공백 H->llink = H, H->rlink = H, ListType 공백 head = NULL, length = 0 (b) get_length는 length 즉시 반환으로 $O(1)$, 위치를 노드 포인터로 변환해 insert_node·remove_node 재사용

조건·구분과 확인

  • 헤드 포인터는 주소 변수이고 H는 데이터 없는 노드예요. 비공백 H->rlink는 첫 노드·H->llink는 마지막 노드이며, 저장된 length는 삽입·삭제 때 갱신해야 해요.

P11. 연결 다항식의 지수 비교와 포인터 이동

각 노드가 (계수 coef, 지수 expon)을 지수 내림차순으로 저장하는 두 연결 다항식 A, B를 포인터 p, q로 순회하며 더해요.

A (p): (3, 12) -> (2, 8) -> (1, 0) -> NULL
B (q): (8, 12) -> (-3, 10) -> (10, 6) -> NULL

지수 내림차순으로 연결된 두 다항식 A와 B를 포인터 p, q로 비교하며 더하는 과정과 선형 병합 시간 복잡도를 구하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “연결 다항식의 지수 비교와 포인터 이동”이에요. 두 항의 지수가 같으면 계수를 더하고 p, q를 모두 전진시키며, 한쪽 지수가 더 크면 그 항만 결과에 붙이고 해당 포인터만 전진시켜요.

p = (3, 12), q = (8, 12): 지수가 12로 같으므로 (11, 12)를 붙이고 p, q 모두 이동해요.

왜 이렇게 푸는지 함께 따라가요

(a) ① 지수 12 == 12: (11, 12)를 추가하고 p, q 모두 이동해요. ② 지수 8 < 10: (-3, 10)을 추가하고 q만 이동해요. ③ 지수 8 > 6: (2, 8)을 추가하고 p만 이동해요. ④ 지수 0 < 6: (10, 6)을 추가하고 q만 이동해 B가 끝나요. ⑤ 남은 A의 (1, 0)을 복사해 최종 다항식은 $11x^{12} - 3x^{10} + 2x^8 + 10x^6 + 1$이에요.

(b) 같은 지수의 계수 합이 0이면 결과 다항식에 항을 붙이지 않지만 두 입력 항은 모두 소비했으므로 p, q를 둘 다 다음 노드로 이동해요. 매 비교마다 적어도 한 포인터가 전진해 각 항을 한 번씩만 처리하므로 전체 시간 복잡도는 $O(m + n)$이에요.

완성 답과 검산

(a) 지수별로 검산하면 $12$차($3+8=11$), $10$차($-3$), $8$차($2$), $6$차($10$), $0$차($1$)로 내림차순 5개 항이 정확히 일치해요.

(b) 입력 항 총 $3 + 3 = 6$개가 후퇴 없이 한 번씩만 소비되므로 선형 시간 $O(m + n)$이 성립해요.

이 문제에서 조심할 점

계수가 큰 쪽이 아니라 지수가 큰 쪽을 먼저 선택하며, 한쪽 리스트가 끝났다고 다른 쪽에 남은 항을 버리지 않아요.

설명을 닫고 다시 해 봐요

  1. 4번의 지수 비교 단계마다 추가되는 항과 이동하는 포인터(p 또는 q)를 적어요.
  2. B가 끝난 뒤 남은 A의 항 처리와 최종 다항식을 적어요.
  3. 계수 합이 0일 때의 포인터 이동과 시간 복잡도 $O(m + n)$을 확인해요.

떠올릴 개념·공식

높은 지수 항을 먼저 결과에 붙이고 해당 포인터를 전진시키며, 지수가 같으면 계수를 더하고 p, q를 함께 전진시켜요.

첫 줄

p = (3, 12), q = (8, 12): 지수가 12로 같으므로 (11, 12)를 붙이고 p, q 모두 이동해요.

핵심 답

(a) (11, 12)(p,q) → (-3, 10)(q) → (2, 8)(p) → (10, 6)(q) → (1, 0) 복사, $11x^{12} - 3x^{10} + 2x^8 + 10x^6 + 1$ (b) 계수 합 0이면 미추가 후 p, q 모두 이동, 시간 복잡도 $O(m + n)$

조건·구분과 확인

  • O(m+n)은 결과 리스트의 마지막 포인터를 유지해 항 추가가 O(1)이라는 조건에서 성립해요.

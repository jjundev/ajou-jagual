문제를 내 말로 읽어요

단순 연결 리스트의 remove_node에서 중간 노드와 맨 앞 노드를 삭제할 때의 인자·체인을 구하고, p == NULL 분기와 free 호출 순서의 이유를 확인하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “삭제할 노드를 해제하기 전의 연결”이에요. p는 삭제 대상 removed의 직전 노드(맨 앞 삭제는 p == NULL)이며, removed->link를 앞쪽에 이어 준 뒤에야 free(removed)를 호출할 수 있어요.

종이에 적을 첫 줄

B 삭제는 (p = A, removed = B), A 삭제는 (p = NULL, removed = A)로 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) 중간 노드 B를 삭제할 때는 p = A, removed = B를 전달해 A->link = B->link(C)가 되어 A -> C -> NULL이 돼요. 맨 앞 노드 A를 삭제할 때는 p = NULL, removed = A를 전달해 *phead = A->link(B)가 되어 B -> C -> NULL이 돼요. 노드가 A 하나뿐이면 *phead = A->link = NULL이 되어 head = NULL이 돼요.

(b) 맨 앞 노드는 선행 노드 p가 없으므로 p->link 대신 시작 포인터 *phead를 바꿔야 해 p == NULL 분기가 따로 필요해요. 또한 링크를 잇기 전에 free(removed)를 먼저 호출하면 이미 해제된 메모리의 removed->link를 읽는 오류가 발생해요.

완성 답과 검산

(a) 두 삭제 모두 삭제 대상 노드를 우회해 앞뒤를 연결한 뒤 free(removed)로 정확히 1개 노드를 해제해요.

(b) 단일 노드 A(link = NULL)에서 p == NULL 분기를 실행하면 *phead = NULL이 되어 공백 불변식이 성립해요.

이 문제에서 조심할 점

단순 연결 리스트에서는 삭제 대상 포인터 removed만으로는 직전 노드 p의 link를 고칠 수 없어 선행 노드 포인터 p가 함께 필요해요.

설명을 닫고 다시 해 봐요

  1. B 삭제와 A 삭제에서 (p, removed)와 결과 체인을 적어요.
  2. 단일 노드 삭제 후 head가 무엇이 되는지 확인해요.
  3. p == NULL 분기와 free(removed) 호출 순서의 이유를 설명해요.

첫 줄

B 삭제는 (p = A, removed = B), A 삭제는 (p = NULL, removed = A)로 적어요.

떠올릴 개념·공식

선행 노드 p(또는 *phead)의 링크를 removed->link로 먼저 우회시킨 뒤 free(removed)를 호출해요.

검산

(a) B 삭제: (A, B) → A -> C -> NULL, A 삭제: (NULL, A) → B -> C -> NULL, 단일 삭제 후 head = NULL (b) 맨 앞은 *phead 갱신 필요, free 선행 시 해제 메모리 접근 오류

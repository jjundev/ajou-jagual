문제를 내 말로 읽어요

세 포인터 r, q, p를 한 칸씩 밀며 링크 방향을 뒤집는 reverse 함수를 1~3회차까지 추적하고 대입 순서의 이유를 확인하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “역순 코드의 세 포인터”예요. p는 아직 뒤집지 않은 앞부분, q는 현재 뒤집을 노드, r은 이미 뒤집힌 리스트의 첫 노드를 가리키며, 반드시 p = p->link로 다음 노드를 먼저 대피시킨 뒤 q->link = r로 방향을 뒤집어야 해요.

종이에 적을 첫 줄

루프 진입 전 초기 상태 p = A, q = NULL을 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) 1회차 종료 시 (r, q, p) = (NULL, A, B)이고 뒤집힌 부분은 A -> NULL이에요. 2회차 종료 시 (r, q, p) = (A, B, C)이고 뒤집힌 부분은 B -> A -> NULL이에요. 3회차 종료 시 (r, q, p) = (B, C, NULL)이고 뒤집힌 부분은 C -> B -> A -> NULL이 되어 루프가 끝나고 q = C를 반환해요.

(b) 만약 q = p; p = p->link; 전에 q->link = r;를 먼저 실행하면, q와 p가 같은 노드를 가리킬 때 그 노드의 link가 r로 덮어써져 원래 다음 노드로 가는 주소를 잃어버려요. 공백 리스트(head == NULL) 입력 시에는 루프를 건너뛰고 초기값 q = NULL을 그대로 반환해요.

완성 답과 검산

(a) 3회 반복 후 p == NULL이 되어 모든 노드가 소비되었고, 반환된 q = C부터 따라가면 C -> B -> A -> NULL로 역순이 완성돼요.

(b) 1회차에서 q = p(A) 직후 q->link = r(NULL)을 먼저 하면 A->link = NULL이 되어 p = p->link가 B 대신 NULL이 됨을 대입으로 확인할 수 있어요.

이 문제에서 조심할 점

원래 head 변수가 자동으로 새 첫 노드를 가리키는 것은 아니므로 호출자가 반환값을 받아야 해요.

설명을 닫고 다시 해 봐요

  1. 1~3회차 종료 시점마다 (r, q, p)와 q부터 시작하는 체인을 표로 적어요.
  2. q->link = r을 p = p->link보다 먼저 실행할 때 1회차에서 생기는 일을 추적해요.
  3. head == NULL일 때의 반환값을 확인해요.

첫 줄

루프 진입 전 초기 상태 p = A, q = NULL을 적어요.

떠올릴 개념·공식

r = q; q = p; p = p->link;로 포인터를 먼저 한 칸씩 전진시킨 뒤 q->link = r;로 링크를 뒤집어요.

검산

(a) 1회 (NULL, A, B), 2회 (A, B, C), 3회 (B, C, NULL), 최종 C -> B -> A -> NULL (b) q->link = r을 먼저 하면 다음 노드 주소 손실, 공백 입력 반환 NULL

조건·구분과 확인

  • 호출자의 head가 자동으로 바뀌지 않으므로 head=reverse(head)로 반환된 새 첫 노드를 받아야 해요.

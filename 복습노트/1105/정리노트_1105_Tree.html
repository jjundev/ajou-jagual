이진 탐색 트리 — 5살도 이해하는 정리노트

1. 찾기 좋게 정리한 트리

레코드·필드·고유 키

1105 수업S7 p18
쉽게 말하면

친구 한 명의 정보를 한 장의 카드에 모아 두면 찾기 편해요.

이름이 같은 친구도 있으니, 서로 겹치지 않는 번호로 카드를 구별해요.

정확히 말하면

탐색(search)은 전화번호부·사전·일정처럼 여러 데이터가 모인 곳에서 원하는 항목을 찾는 일이에요. 데이터가 많아질수록 찾는 시간이 중요해지므로, 탐색에 알맞게 데이터를 조직해요.

특정 목표를 찾는 탐색(search)은 목적 없이 살펴보는 둘러보기(browsing)와 구별해요. 교수님이 회상한 0부터 100 사이의 77 찾기는, 정렬된 범위에서 비교할 때마다 후보를 절반씩 줄이는 이진 탐색의 예예요. 후보 수가 $n$개라면 이 조건에서 탐색 횟수는 $O(\log n)$ 규모가 돼요. 임의의 이진 탐색 트리까지 같은 최악 성능을 보장한다는 뜻은 아니에요.

레코드(record)
하나의 대상에 관한 정보를 묶은 단위예요. 학생 정보 표에서는 학생 한 명의 정보가 들어 있는 한 행이 학생 레코드예요.
필드(field)
레코드를 이루는 각각의 정보 항목이에요. 이름, 학번, 학과, 학년, 평점, 이수학점, 수강 정보와 전화번호가 필드의 예예요.
고유 키(primary key)
레코드를 다른 레코드와 겹치지 않게 식별하기 위해 선택한 필드예요. 이 수업에서는 하나의 필드가 학생 한 명을 대표하는 경우로 설명해요.
후보 필드학생을 구별하는 데 쓸 수 있는 조건
이름동명이인이 있을 수 있으므로 이름만으로 고유성을 보장할 수 없어요.
학번해당 학교의 학생 관리 범위에서 학생마다 서로 다른 학번을 부여한다는 조건으로 학생 레코드를 식별해요.
전화번호관리 대상 모두에게 번호가 있고 서로 공유하거나 중복하지 않는다는 조건을 확인해야 후보로 쓸 수 있어요. 전화번호라는 이유만으로 고유한 것은 아니에요.

교수님은 학번과 전화번호를 고유 키의 예로 들었어요. 핵심은 필드의 이름이 아니라, 실제 관리하는 레코드들에서 값이 겹치지 않는다는 조건이에요. 탐색할 때 비교하는 키는 그 레코드를 찾는 기준이 돼요.

파일과 데이터베이스로 연결해 생각해요

교수님은 CSV 파일의 행·항목을 데이터베이스(database, DB)의 테이블과 연결해서 설명했어요. 파일을 읽고 내용을 해석하는 입출력(I/O)에도 시간이 들고, CPU의 계산 시간과 입출력 시간은 달라요. 앞서 배운 큐의 대기 버퍼도 그 시간 차이와 연결해 회상했어요.

SQL은 DB에 조건을 전달해 결과를 요청하는 언어예요. “소득이 1억 이상이고 이름이 A로 시작하는 사람”을 요청하는 예를 들었고, SQL 문법이나 DB 내부 알고리즘을 새로 유도한 것은 아니에요. DB의 데이터 구성과 접근 역할을 CPU와 메모리 사이의 캐시에 비유했지만, DB 자체가 단순한 캐시라는 정의도 아니에요. 파일보다 DB가 어떤 조건에서도 항상 빠르다는 보장으로 읽지 않아요.

계산 시간과 응답 시간을 함께 봐요

응답 시간(response time)은 사용자가 결과를 볼 때까지 기다리는 시간이에요. 교수님은 탐색 계산만 아니라 데이터를 가져오는 시간과 사용자가 결과를 보는 방식도 함께 고려해야 한다는 경험을 소개했어요. 연구나 디버깅에서 막히면 지금의 코드만 복잡하게 만들기 전에 초기 조건·경계 조건을 다시 확인하는 태도와도 연결했어요.

“요 하나의 행을 레코드라고 얘기를 합니다.”

(1105 Part 04 · 시각 미제공)

“이름은 안 됩니다. 왜? 중복일 수가 있어서 고유하지 않습니다.”

(1105 Part 04 · 시각 미제공)

교수님의 당시 검색 연구 경험담에서는 Michael Jordan에 관한 문서가 야구와 농구 중 어느 문맥인지를 구별하는 사례가 나왔어요. 문서의 낱말을 보는 bag-of-words와 문서 사이의 하이퍼링크(hyperlink)에 가중치를 두는 방식을 대비했어요. 또 모든 결과를 기다리지 않고 첫 화면의 결과를 먼저 보여 주며 나머지를 가져오는 발상을 소개했어요. 이는 교수님의 회고이며, 현재 검색 엔진 전체의 구현이나 검증된 역사적 사실을 설명하는 주장은 아니에요.

문제의 한 부분에만 매달리기보다 초기 조건과 경계 조건까지 한 발짝 물러나 살펴보라는 교훈을 강조했어요. 도구의 답도 성실하지만 검토가 필요한 초년 연구자의 결과처럼 직접 확인하고 요구와 다른 점을 짚어야 한다고 비유했어요.

“한 발짝 뒤에서 보면 내가 집중해 있던 문제를 풀기 위해서는 바운더리 컨디션을 봐야 된다”

(1105 Part 03 · 시각 미제공)

정보 한 묶음은 레코드, 각각의 항목은 필드이고, 고유 키는 레코드를 겹치지 않게 구별해요.

용어

탐색(search)
많은 데이터에서 원하는 항목을 찾는 일이에요. 데이터가 많을수록 효율적인 구성이 필요해요.
레코드(record)
학생 한 명의 이름·학번·학과·학년·평점·이수학점·수강 정보·전화번호처럼 한 대상의 정보를 묶은 한 행이에요.
필드(field)
레코드 안의 이름이나 학번 같은 개별 정보 항목이에요.
고유 키(primary key)
실제 관리 범위에서 값이 겹치지 않아 레코드를 식별하는 필드예요. 탐색 키는 레코드를 찾는 비교 기준이에요.
고유성의 조건
이름은 동명이인 때문에 보장되지 않아요. 학번은 학교의 학생 관리 범위에서 서로 다르게 부여한다는 조건으로 사용해요. 전화번호는 모두에게 있고 공유·중복되지 않는지 확인해야 해요.
목표와 후보 범위
탐색(search)은 목표가 있고 둘러보기(browsing)는 목적 없이 살펴봐요. 정렬된 0–100 범위의 77 찾기처럼 후보를 절반씩 줄일 때는 $O(\log n)$ 규모예요. 일반 이진 탐색 트리의 최악 보장은 아니에요.
CSV·DB·SQL 배경
파일의 행·항목을 DB 테이블과 연결했어요. 파일을 읽고 해석하는 I/O 시간과 CPU 계산 시간의 차이는 큐의 대기 버퍼를 회상하는 배경이에요. SQL은 조건을 전달해 결과를 요청하며, 소득 1억 이상·이름 A로 시작하는 사람을 예로 들었어요. 문법·내부 알고리즘은 유도하지 않았어요.
캐시 비유의 범위
DB의 데이터 구성·접근 역할을 CPU와 메모리 사이의 캐시에 빗댔어요. DB가 단순 캐시이거나 파일보다 항상 빠르다는 뜻은 아니에요.
응답 시간과 연구 회고
사용자가 결과를 볼 때까지 기다리는 시간도 고려해요. 교수님은 bag-of-words·하이퍼링크 가중치의 문맥 판별 사례와 첫 화면 결과를 먼저 보이며 나머지를 가져오는 발상을 소개했어요. 당시 경험담이며 현재 검색 엔진 구현이나 검증된 역사로 일반화하지 않아요.
문제 해결과 검토
막히면 초기·경계 조건을 다시 살펴봐요. 도구의 결과도 성실한 초년 연구자의 답처럼 직접 검토하고 요구와 다른 점을 확인해요.

이진 탐색 트리의 네 가지 조건

1105 수업S7 p18–19
쉽게 말하면

물건을 가운데 기준보다 작은 것은 왼쪽에, 큰 것은 오른쪽에 나눠 놓아요.

나눠 놓은 자리 안에서도 같은 약속을 지켜야 원하는 물건을 찾기 쉬워요.

정확히 말하면

이진 탐색 트리(binary search tree)는 탐색 작업을 효율적으로 하기 위해 키의 크기 관계를 유지하는 이진 트리예요. 이진 트리라는 기본 조건 때문에 각 노드의 자식 수는 최대 둘이에요. 여기에 다음 네 조건을 함께 지켜요.

  1. 모든 원소의 키는 유일해요. 같은 키를 가진 노드가 두 개 존재하지 않아요.
  2. 왼쪽 서브트리의 모든 키는 현재 루트의 키보다 작아요. 왼쪽 자식 하나만 비교하는 조건이 아니에요.
  3. 오른쪽 서브트리의 모든 키는 현재 루트의 키보다 커요. 여러 단계 아래의 자손도 모두 포함해요.
  4. 왼쪽과 오른쪽 서브트리도 각각 이진 탐색 트리예요. 각 서브트리를 새로운 트리로 보아 같은 조건을 재귀적으로 적용해요.

왼쪽 서브트리의 임의의 키를 $k_L$, 현재 루트의 키를 $k_V$, 오른쪽 서브트리의 임의의 키를 $k_R$라고 쓰면, 양쪽에 해당 원소가 있을 때 다음 관계를 만족해요.

$$k_L \lt k_V \lt k_R$$

슬라이드 19쪽에는 등호가 포함되어 있지만, 교수님은 이 수업에서 키가 유일하므로 등호를 지우라고 정정했어요. 따라서 이 노트에서는 엄격한 부등호를 써요. 다른 중복 허용 규칙을 이 정의와 섞으면 안 돼요.

19쪽 예제에서 루트는 18이에요. 왼쪽 서브트리의 7, 3, 12는 모두 18보다 작고, 오른쪽 서브트리의 26, 31, 27은 모두 18보다 커요. 특히 27은 31의 왼쪽 자식이면서 26의 오른쪽 서브트리에 속하므로, 31보다 작고 26보다 커야 해요. 더 위의 조상인 18보다도 커야 해요.

서브트리 안에서도 확인해요. 7의 왼쪽 3은 7보다 작고 오른쪽 12는 7보다 커요. 26의 오른쪽 서브트리에는 26보다 큰 31과 27이 있어요. 31의 왼쪽 27은 31보다 작아요. 26의 왼쪽처럼 빈 서브트리에는 조건을 위반할 키가 없으므로 조건을 만족해요. 이런 식으로 모든 노드와 그 아래 전체를 확인해야 해요.

이 예제는 모든 내부 노드가 두 자식을 갖는 트리도, 마지막 층을 왼쪽부터 빠짐없이 채우는 완전 이진 트리도 아니에요. 이진 탐색 트리의 판정 기준은 그런 모양이 아니라 자식 수와 전체 키의 순서 조건이에요.

교수님 말씀
“여기에서 =을 빼세요. 왜냐하면 유니크하다라고 했기 때문에”

(1105 Part 04 · 시각 미제공)

“26의 왼쪽 서브트리는 널이기 때문에 만족합니다. 없으면 만족하는 거예요, 그냥.”

(1105 Part 04 · 시각 미제공)

자식이 최대 둘인 트리에서, 모든 키가 유일하고 모든 자손이 각 조상의 크기 조건을 지켜야 해요.

핵심 식

  • 왼쪽의 임의의 키·현재 루트·오른쪽의 임의의 키$$k_L \lt k_V \lt k_R$$

용어

이진 탐색 트리(binary search tree)
탐색을 위해 키의 크기 관계를 유지해요. 자식 수는 최대 둘이며 모든 원소의 키는 유일해요.
왼쪽 서브트리·오른쪽 서브트리
왼쪽의 모든 키는 루트보다 작고 오른쪽의 모든 키는 루트보다 커요. 직접 자식뿐 아니라 모든 자손에 적용해요.
재귀적인 정의
양쪽 서브트리도 같은 조건을 만족해야 해요. 빈 서브트리는 위반할 키가 없으므로 조건을 만족해요.
예제의 전체 조건
18의 왼쪽은 3·7·12, 오른쪽은 26·27·31이에요. 27은 31보다 작고 26과 18보다 커야 해요. 7·26·31을 새 루트로 보아도 조건이 유지돼요.
등호와 모양 주의
교수님이 슬라이드의 등호를 지웠으므로 엄격한 부등호를 써요. 두 자식을 모두 갖추거나 완전 이진 트리 모양일 필요는 없어요.

중위 순회가 오름차순이 되는 이유

1105 수업S7 p19
쉽게 말하면

작은 물건들을 먼저 꺼내고, 가운데 물건을 꺼낸 뒤 큰 물건들을 꺼내면 크기순으로 나와요.

책상을 쓰는 사람이 쉽게 찾도록, 정리하는 사람이 먼저 자리를 잘 정해 두는 거예요.

정확히 말하면

중위 순회(inorder traversal)는 LVR, 즉 왼쪽 서브트리 순회(L), 현재 노드 방문(V), 오른쪽 서브트리 순회(R) 순서예요. 방문은 현재 노드의 키를 출력하는 동작으로 생각하면 돼요. 서브트리에도 같은 순서를 재귀적으로 적용해요.

이진 탐색 트리의 네 가지 조건 때문에 왼쪽의 모든 키는 현재 키보다 작고, 오른쪽의 모든 키는 현재 키보다 커요. 각 서브트리도 같은 조건을 만족하므로 그 안에서도 작은 키부터 출력돼요. 따라서 왼쪽 전체를 출력한 뒤 현재 키, 오른쪽 전체를 출력하면 전체 결과도 오름차순이에요. 아무 이진 트리에나 중위 순회를 한다고 정렬되는 것은 아니에요.

  2. k가 현재 키와 같으면 성공하고 현재 노드의 포인터를 반환해요.

    struct TreeNode *left, *right;

TreeNode *search(TreeNode *node, int key)

    if (key == node->key)

    if (key < node->key)

삽입(insert)은 이진 탐색 트리의 키 순서와 유일성을 유지하면서 새 노드를 연결하는 일이에요. 먼저 새 키를 탐색해요. 같은 키를 찾으면 중복이므로 삽입을 중단하고, 없다면 탐색이 끝난 빈 링크에 연결해요. 완전 이진 트리처럼 단순히 앞쪽의 빈자리를 채우는 연산이 아니에요.

C로 옮긴 예시예요. 필요한 TreeNode 선언을 함께 적었어요. 호출자는 유효한 루트 포인터 변수의 주소를 첫 인수로 전달해요. 둘째 인수 z는 트리와 별개로 준비한 새 노드이며, z != NULL이고 두 자식 링크가 NULL이어야 해요. 이 함수는 메모리를 할당하거나 해제하지 않아요.

#include <stddef.h>
typedef struct TreeNode {
    int key;
    struct TreeNode *left, *right;
} TreeNode;
int insert_node(TreeNode **root, TreeNode *z)
{
    TreeNode *p = NULL;
    TreeNode *t = *root;
    while (t != NULL) {
        if (z->key == t->key)
            return 0;
        p = t;
        if (z->key < p->key)
            t = p->left;
        else
            t = p->right;
    }
    if (p == NULL)
        *root = z;
    else if (z->key < p->key)
        p->left = z;
    else
        p->right = z;
    return 1;
}

호출 형태는 insert_node(&root, &new_node)예요. 빈 트리에서 호출자의 root도 바뀌어야 하므로 포인터의 주소를 받아 *root에 대입해요. 반환값 1은 연결 성공, 0은 중복으로 중단했다는 뜻으로 이 C 예시에 명시한 계약이에요. 원문 의사코드의 return;과 달리 상태 정수를 돌려주며, 노드 주소를 반환하는 탐색 함수와도 구별해요. 중복으로 연결하지 않은 z는 호출자에게 남아요.

이 삽입 의사코드는 반복문이에요. 탐색 과정을 이용한다는 말은 같은 크기 비교로 경로를 찾는다는 뜻이며, 앞의 재귀 탐색 함수를 따로 한 번 호출한 뒤 처음부터 다시 내려가야 한다는 뜻은 아니에요.

높이 $h$는 루트부터 가장 깊은 노드까지 세는 레벨 수예요. 이 수업에서는 루트 높이를 1로 세고, 빈 트리 높이는 0이에요. 노드가 $n$개인 트리에서 탐색·삽입·삭제의 최악 상한은 모두 $O(h)$예요.

  • 탐색은 목표가 있을 경로 하나만 따라 내려가요.
  • 삽입은 그 경로에서 중복 여부와 빈자리를 찾고 링크를 연결해요.
  • 삭제는 대상을 찾고, 두 자식이면 대체 후보까지 찾아 원래 자리를 정리해요. 경로 탐색과 연결 처리의 합도 $O(h)$예요.
모양·상황높이·방문 길이연산 비용
균형적인 트리높이가 $\Theta(\log n)$이에요.가장 깊은 경로까지 가는 연산의 최악 상한은 $O(\log n)$이에요.
경사 트리한쪽으로만 이어지면 $h=n$이에요.최악 비용은 $O(n)$으로 순차 탐색과 같아요.
루트에서 즉시 성공한 탐색현재 키 하나만 확인해요.그 한 번의 질의는 $O(1)$이에요.

이진 트리에는 높이 $h$까지 최대 $2^h-1$개의 노드가 들어가요. 따라서 $n\ge 1$일 때 가능한 최소 높이는 다음과 같아요.

$$h_{\min}=\left\lceil\log_2(n+1)\right\rceil$$

마지막 층을 왼쪽부터 채운 완전 이진 트리는 이 최소 높이를 달성해요. 모든 층이 찬 포화 이진 트리는 $n=2^h-1$이라서 $h=\log_2(n+1)$이 정확해요. 임의의 균형적인 트리 높이가 항상 최소 높이와 정확히 같다는 뜻은 아니에요. 균형적인 높이의 점근적 크기는 $\Theta(\log n)$이에요.

그림의 4를 루트로 한 트리와 1부터 7까지 오른쪽으로 이어진 트리는 둘 다 이진 탐색 트리예요. 키의 순서 규칙만으로 균형을 보장하지 않아요. 일반 이진 탐색 트리의 최악은 $O(n)$이며, 항상 빠르다고 단정할 수 없어요.

강의록의 “최선의 경우”는 균형적으로 만들어진 좋은 모양을 가리켜요. 한 질의가 루트에서 바로 끝나는 최선 $O(1)$과 구별해요. 연산에서 방문한 노드 수에 비례해 시간이 걸린다는 사실은 두 설명 모두에 적용돼요.

교수님 말씀
“탐색, insert, delete, 이런 연산의 시간 복잡도는 트리의 높이를 h라고 했을 때 h에 비례” (1105 Part 07, 시각 미제공)
“노드가 4개인데 높이가 4예요.” (1105 Part 07, 시각 미제공)

교수님은 오른쪽으로 이어진 1·2·3·4도 순서 조건을 만족하지만 순차 탐색만큼 길어질 수 있다고 설명하셨어요. 좋은 모양을 유지하도록 추가 관리할 수 있다는 방향도 소개하셨어요. 일반 이진 탐색 트리가 스스로 균형을 맞춘다는 뜻은 아니에요.

교수님은 자신의 연구 경험을 통해, 막힌 지점만 고치기보다 한 발짝 물러나 문제를 다시 보라고 말씀하셨어요. 같은 테스트를 여러 번 실행해 서로 다른 구간을 얻고 시간 동기를 맞춰 조합한 사례, 신호의 수치 대신 파형 그림을 입력한 사례를 드셨어요. 이는 교수님의 해당 경험에서 나온 접근법이며, 임의의 실시간 데이터를 항상 복원하거나 모든 분석의 성능을 높인다는 일반 보장은 아니에요.

“프로그래밍은 어디까지나 아이디어와 프랙티스입니다.” (1105 Part 07, 시각 미제공)

농구 경기를 보고 쉬워 보이는 것과 직접 슛을 넣는 일이 다르듯, 설명을 이해한 뒤에는 직접 구현하며 연습해야 한다고 강조하셨어요.

꼭 기억해요
“우리는 이거를 최악의 경우로 얘기하지 않는다, 트리에 한해서.” (1105 Part 07, 시각 미제공)

이 발언은 균형을 관리해 좋은 성능을 얻자는 취지로 이해해요. 수학적인 최악 분석은 생략하지 않아요. 일반 이진 탐색 트리는 최악 $O(n)$이고, 높이를 $O(\log n)$으로 보장하려면 추가적인 균형 유지 규칙이 필요해요.

연산 비용은 높이에 비례하며, 일반 이진 탐색 트리의 최악은 경사 모양에서 선형으로 늘어나요.

핵심 식

  • 탐색·삽입·삭제의 최악 상한$$O(h)$$
  • 가능한 최소 높이, n은 1 이상$$h_{\min}=\left\lceil\log_2(n+1)\right\rceil$$
  • 균형적인 높이와 연산 상한$$h=\Theta(\log n),\qquad O(\log n)$$
  • 경사 높이와 최악 비용$$h=n,\qquad O(n)$$
  • 루트에서 바로 성공하는 질의$$O(1)$$
  • 높이는 루트부터 가장 깊은 노드까지의 레벨 수예요. 루트만 있으면 1, 빈 트리는 0이에요.
  • 탐색은 경로 하나를 방문해요. 삽입의 탐색·연결, 삭제의 대상·후보 탐색과 재연결을 합쳐도 높이에 비례해요.
  • 높이 h까지 최대 $2^h-1$개를 담아요. 완전 이진 트리는 최소 높이를 달성하고, 포화 이진 트리는 $n=2^h-1$ 및 $h=\log_2(n+1)$이에요. 임의의 균형 트리가 정확히 최소 높이라는 뜻은 아니에요.
  • 같은 일곱 키도 세 층 또는 일곱 층으로 만들 수 있어요. 이진 탐색 트리의 순서 조건은 균형을 보장하지 않아요.
  • 강의록의 좋은 모양에 대한 “최선”과 한 질의의 루트 성공 $O(1)$은 달라요.
  • “트리는 최악으로 얘기하지 않는다”를 분석 규칙으로 쓰지 않아요. 최악 $O(\log n)$ 보장에는 추가 균형 유지 규칙이 필요해요.
  • 교수님 경험의 교훈: 막히면 한 발짝 물러나 구간 수집 방식이나 데이터 표현을 다시 생각해 봐요. 반복 테스트의 구간 조합과 파형 그림 입력은 해당 경험의 사례이며, 모든 데이터의 복원·성능 향상 보장이 아니에요.
  • “프로그래밍은 어디까지나 아이디어와 프랙티스입니다.” 설명 이해와 직접 구현은 달라서 코딩 연습이 필요해요.

탐색·삽입·삭제를 할 때는 각 서브트리의 순서 조건을 지켜요. 트리의 모양은 연산 비용을 결정해요.

개념·연산기억할 규칙예시·주의
고유 키레코드는 한 대상의 데이터 묶음이고, 필드는 그 안의 항목이에요. 고유 키는 레코드를 유일하게 구별해요.학번은 학생을 구별해요. 이름은 중복될 수 있어요.
이진 탐색 트리키는 유일해요. 왼쪽 서브트리의 모든 키는 루트보다 작고, 오른쪽 서브트리의 모든 키는 루트보다 커요. 두 서브트리에도 같은 규칙을 적용해요.이 수업에서는 등호를 빼요. 바로 옆 자식만 비교해서는 전체 트리를 판정할 수 없어요.
중위 순회왼쪽 서브트리, 현재 노드, 오른쪽 서브트리의 순서인 LVR로 방문해요. 이진 탐색 트리에서는 오름차순이 나와요.강의 예시 출력은 3, 7, 12, 18, 26, 27, 31이에요. 설명에서 생략해도 NULL을 확인하는 재귀 바닥 조건은 필요해요.
탐색키가 같으면 현재 노드를 반환해요. 목표가 작으면 왼쪽, 크면 오른쪽만 탐색해요. NULL을 만나면 실패로 NULL을 반환해요.12는 18, 7, 12를 비교해 찾고, 20은 18, 26을 비교한 뒤 빈 왼쪽 링크에서 실패해요. 링크 표현의 반환값은 노드 포인터예요.
삽입중복 키면 중단해요. 탐색에 실패한 빈 위치에 새 노드를 붙여요. t는 현재 노드이고, p는 직전 부모를 보존해요.9는 18, 7, 12를 비교한 뒤 12의 왼쪽에 붙여요. 빈 트리에서는 새 노드가 루트가 돼요. NULL 반환만으로 부모 위치를 얻는 것은 아니에요.
삭제: 자식 0개단말 노드를 가리키던 부모의 자식 링크를 NULL로 바꿔요.루트 하나뿐인 트리를 지우면 루트 포인터도 NULL이 돼요.
삭제: 자식 1개대상의 부모가 대상의 유일한 자식 서브트리를 직접 가리키게 해요.대상만 제거해요. 아래 서브트리까지 잃으면 데이터 손실이 생겨요. 대상이 루트면 유일한 자식이 새 루트가 돼요.
삭제: 자식 2개왼쪽 서브트리의 최댓값 또는 오른쪽 서브트리의 최솟값으로 대체해요. 대체한 노드의 원래 자리도 삭제·재연결해 중복을 남기지 않아요.강의의 두 자식 삭제 그림에서는 12 또는 22가 후보예요. 오른쪽 최솟값 노드는 왼쪽 자식이 없고, 왼쪽 최댓값 노드는 오른쪽 자식이 없어서 원래 자리 정리는 자식 0개 또는 1개 삭제로 끝나요.
공통 시간복잡도탐색·삽입·삭제는 높이 $h$에 따라 $O(h)$가 걸려요.균형적인 모양이면 높이가 $\Theta(\log n)$이므로 연산의 최악 상한은 $O(\log n)$이에요.
경사 트리한쪽으로만 이어지면 높이가 $n$이어서 일반 이진 탐색 트리의 최악 비용은 $O(n)$이에요.1, 2, 3, 4가 오른쪽으로만 이어져도 올바른 이진 탐색 트리예요. 단일 탐색이 루트에서 바로 성공하면 $O(1)$이에요.

두 자식 삭제에서 대체 노드의 원래 자리를 정리하는 설명과 루트 삭제의 연결 처리는 구현을 위한 보완이에요. 수업에서는 삭제의 세 경우와 순서 보존 원리를 그림으로 설명했어요.

Q1. 고유 키로 쓸 필드

학생 레코드에는 이름·학번·학과·학년·전화번호 같은 필드가 있어요. 이 가운데 어떤 필드를 고유 키(primary key)로 쓸 수 있는지 정하는 기준으로 알맞은 것을 고르세요.

  1. 학번·전화번호처럼 '번호'가 붙은 필드면 값이 저절로 겹치지 않으니 고유 키로 써요.
  2. 관리하는 레코드들 사이에서 그 필드의 값이 서로 겹치지 않아야 고유 키로 써요.
  3. 사람을 부르는 이름이 레코드를 가장 잘 대표하니 이름을 고유 키로 써요.
  4. 크기를 비교할 수 있는 필드면 값이 겹쳐도 고유 키로 써요.
풀이 보기
  1. "번호 필드면 저절로 고유하다" — 필드 이름이 아니라 실제 값이 겹치는지가 기준이에요. 전화번호도 공유·중복이 없는지 확인해야 해요.
  2. 고유 키는 레코드 하나를 다른 레코드와 구별해야 해요. 그래서 학번은 되고, 동명이인이 있는 이름은 안 돼요.
  3. "이름이 레코드를 대표한다" — 이름은 같은 사람이 있을 수 있어 고유하지 않아요. 교수님이 이름은 안 된다고 짚었어요.
  4. "비교만 되면 키가 된다" — 이진 탐색 트리의 키는 비교 기준이면서 유일해야 해요. 값이 겹치면 고유 키가 될 수 없어요.

정답: B

Q2. 이 트리의 판정

다음 트리가 이진 탐색 트리인지 판단한 것으로 알맞은 것을 고르세요.

  1. 이진 탐색 트리예요. 45는 바로 위 부모 25보다 크니 25의 오른쪽에 있어도 돼요.
  2. 이진 탐색 트리가 될 수 없어요. 자식 60과 45가 부모보다 커서 조건을 어겨요.
  3. 이진 탐색 트리가 될 수 없어요. 45가 40의 왼쪽 서브트리에 있는데 40보다 커요.
  4. 이진 탐색 트리예요. 마지막 층이 왼쪽부터 채워진 완전 이진 트리 모양이에요.
풀이 보기
  1. "바로 위 부모와만 비교하면 된다" — 크기 조건은 바로 위 부모만이 아니라 모든 조상에 걸려요. 45는 40의 왼쪽 서브트리에 있으니 40보다 작아야 해요.
  2. "자식은 부모보다 항상 작아야 한다" — 오른쪽 자식은 부모보다 커야 해요. 자식이 부모보다 큰 것 자체는 문제가 되지 않아요.
  3. 왼쪽 서브트리의 모든 키는 루트 40보다 작아야 해요. 45 하나가 이 조건을 깨요.
  4. "완전 이진 트리 모양이면 이진 탐색 트리다" — 판정 기준은 모양이 아니라 키의 순서 조건이에요. 모양이 좋아도 45가 순서를 깨요.

Q3. ? 자리에 둘 키

다음 이진 탐색 트리에서 ? 자리(60의 오른쪽 자식)에 새 키를 둘 때, 그 키가 지켜야 할 조건으로 알맞은 것을 고르세요.

  1. 60보다 크고 80보다 작아야 해요.
  2. 60보다 크기만 하면 돼요.
  3. 60 이상 80 이하면 돼요.
  4. 자식은 부모보다 작아야 하니 60보다 작아야 해요.
풀이 보기
  1. ?는 60의 오른쪽이라 60보다 크고, 80의 왼쪽 서브트리에 있어 80보다 작아야 해요. 50보다 큰 것은 60보다 크면 저절로 맞아요.
  2. "바로 위 부모와만 비교한다" — ?는 80의 왼쪽 서브트리에도 속해요. 90처럼 80보다 큰 키를 두면 80의 조건을 깨요.
  3. "슬라이드 식의 등호를 그대로 쓴다" — 키는 유일해서 60이나 80과 같은 키는 둘 수 없어요. 교수님이 등호를 지우라고 했어요.
  4. "자식은 부모보다 항상 작다" — 오른쪽 자식은 부모보다 커야 해요. 부모보다 작은 키는 왼쪽에 와요.

Q4. 등호를 지운 식

슬라이드 19쪽 식 key(왼쪽서브트리) ≤ key(루트노드) ≤ key(오른쪽서브트리)에서 교수님은 등호를 지우라고 했어요. 그 까닭으로 알맞은 것을 고르세요.

  1. 같은 키는 오른쪽 서브트리에 하나 더 두기로 했기 때문이에요.
  2. 같은 키를 넣으면 기존 노드를 새 노드로 바꿔 끼우기 때문이에요.
  3. 슬라이드 식이 잘못이라 어떤 이진 탐색 트리도 중복 키를 둘 수 없기 때문이에요.
  4. 이 수업의 정의는 모든 키가 유일해서 같은 키가 두 번 나올 수 없기 때문이에요.
풀이 보기
  1. "중복 허용 규칙을 이 정의에 섞는다" — 이 수업의 정의에서는 같은 키를 어느 쪽에도 두지 않아요. 중복을 허용하는 규칙을 이 정의와 섞으면 안 돼요.
  2. "중복 삽입은 기존 노드를 교체한다" — 같은 키를 만나면 insert_node는 return;으로 연결을 바꾸지 않고 끝나요. 교체하지 않아요.
  3. "등호 표기 자체가 오류다" — 중복 키를 허용하는 이진 탐색 트리도 고급 자료구조에 있어서 슬라이드에 등호가 있어요. 지운 까닭은 이 수업의 정의 때문이에요.
  4. 첫 조건이 '모든 원소의 키는 유일하다'예요. 같은 키가 없으니 등호가 성립할 일이 없어요.

Q6. 오른쪽을 건너뛰는 근거

이진 탐색 트리에서 키를 찾다가, 찾는 키가 현재 노드의 키보다 작으면 왼쪽 서브트리로만 내려가요. 오른쪽 서브트리를 살펴보지 않아도 되는 까닭으로 알맞은 것을 고르세요.

  1. 트리가 균형 잡혀 있을 때만 오른쪽을 건너뛸 수 있고, 경사 트리라면 양쪽을 다 봐야 해요.
  2. 오른쪽 서브트리의 키는 모두 현재 키보다 커서, 더 작은 목표 키가 그쪽에 있을 수 없어요.
  3. 오른쪽 자식 하나만 현재 키보다 크고, 그 아래 자손은 나중에 다시 확인해요.
  4. 어느 키를 찾든 높이만큼 비교하면 끝나므로 오른쪽까지 볼 시간이 없어요.
풀이 보기
  1. "한쪽만 따라가려면 균형이 필요하다" — 경사 트리도 순서 조건을 지키는 이진 탐색 트리예요. 모양과 상관없이 한쪽만 따라가고, 모양은 비교 횟수만 바꿔요.
  2. 순서 조건이 오른쪽 서브트리 전체에 걸리므로 오른쪽은 후보에서 통째로 빠져요.
  3. "크기 조건이 직접 자식에만 걸린다" — 오른쪽 서브트리의 모든 자손이 현재 키보다 커요. 다시 확인할 필요가 없어요.
  4. "탐색은 늘 높이만큼 비교한다" — 높이만큼 비교하는 것은 최악의 경우예요. 19쪽 트리에서 12는 높이 4보다 적은 3번 비교로 찾았어요.

Q7. search의 두 반환

슬라이드 20쪽의 탐색 의사코드예요.

search(x, k)
if x=NULL
    then return NULL;
if k=x->key
    then return x;
else if k<x->key
    then return search(x->left, k);
else return search(x->right, k);

이 코드의 동작을 바르게 설명한 것을 고르세요.

  1. x가 NULL이면 바로 NULL을 돌려주고, 키가 같으면 그 노드의 주소 x를 돌려줘요.
  2. 키가 같으면 그 노드의 배열 인덱스 번호(예: 5)를 정수로 돌려줘요.
  3. 끝내 못 찾으면 새 노드를 붙일 부모 노드의 주소를 돌려줘요.
  4. x->key를 먼저 비교하고, 키가 다를 때만 x가 NULL인지 확인해요.
풀이 보기
  1. 빈 서브트리에 닿으면 실패, 같은 키를 만나면 성공이에요. 반환형이 TreeNode *라 성공 결과는 노드 주소예요.
  2. "노드 주소 대신 배열 인덱스를 돌려준다" — return x는 노드를 가리키는 포인터예요. 수업 중 말한 5번은 배열 표현을 가정한 설명이에요.
  3. "실패한 탐색이 부모 주소를 알려 준다" — 실패하면 NULL만 돌아와요. 부모 주소가 필요해서 insert_node는 p를 따로 들고 내려가요.
  4. "키 비교가 NULL 검사보다 먼저다" — x가 NULL일 때 x->key를 읽으면 안 돼요. 그래서 NULL 검사가 첫 줄에 있어요.

정답: A

Q8. 35가 붙는 자리

다음 이진 탐색 트리에 키 35를 삽입해요. 새 노드가 연결되는 자리로 알맞은 것을 고르세요.

  1. 20의 왼쪽 자식 자리예요. 마지막 층의 맨 왼쪽 빈자리부터 채워요.
  2. 80의 오른쪽 자식 자리예요. 현재 키보다 작으면 오른쪽으로 내려가요.
  3. 40의 왼쪽 자식 자리예요. 왼쪽, 오른쪽, 왼쪽으로 내려간 끝이 비어 있어요.
  4. 30의 오른쪽 자리에 끼우고, 원래 있던 40을 35의 오른쪽 자식으로 내려요.
풀이 보기
  1. "완전 이진 트리처럼 다음 빈자리에 넣는다" — 그렇게 넣으면 35가 20의 왼쪽에 와서 순서가 깨져요. 이진 탐색 트리는 비교로 자리를 찾아요.
  2. "작으면 오른쪽으로 간다" — 작으면 왼쪽, 크면 오른쪽이에요. 방향을 뒤집으면 35가 50보다 큰 쪽에 놓여요.
  3. 35는 50보다 작고 30보다 크고 40보다 작아요. 탐색이 실패한 빈 링크가 새 노드의 자리예요.
  4. "비교 경로 중간에 새 노드를 끼워 넣는다" — 삽입은 기존 링크를 바꾸지 않고, 탐색이 끝난 빈 링크에만 새 노드를 연결해요.

정답: C

Q9. 반복이 끝난 뒤의 p

슬라이드 21쪽 insert_node(T,z)의 앞부분이에요.

p←NULL;
t←root;
while t≠NULL do
{
    if (z->key = t->key) return;
    p←t;
    if z->key < p->key
        then t←p->left;
        else t←p->right;
}

반복문이 끝난 직후 p가 맡는 역할로 알맞은 것을 고르세요.

  1. p는 새 노드 z를 담으려고 메모리에 할당해 둔 공간이에요.
  2. p가 NULL이면 트리가 비었다고 알리기만 하고 삽입 없이 끝나요.
  3. p는 search 함수가 실패하며 돌려준 NULL을 받아 둔 값이에요.
  4. p는 t가 NULL로 내려가기 직전의 노드라서, z를 연결할 부모예요.
풀이 보기
  1. "p 선언이 새 노드 할당이다" — p는 이미 트리에 있는 노드를 가리킬 뿐이에요. 새 노드는 z로 따로 받아요.
  2. "빈 트리면 삽입하지 않는다" — p가 NULL이면 트리가 비어 있던 것이고, root←z로 z가 루트가 돼요.
  3. "search의 NULL 반환으로 부모를 얻는다" — 이 반복문은 search를 부르지 않고 직접 내려가요. NULL만으로는 부모를 알 수 없어서 p를 따로 기억해요.
  4. p←t로 한 칸 뒤를 따라가므로, t가 빈자리에 닿으면 p는 그 빈 링크를 가진 노드예요.

정답: D

Q10. 단말 노드 30 삭제

다음 이진 탐색 트리를 링크로 표현했어요. 단말 노드 30을 삭제할 때 바꾸는 것으로 알맞은 것을 고르세요.

  1. 부모 20의 오른쪽 링크를 NULL로 바꿔요.
  2. 30의 왼쪽·오른쪽 링크만 NULL로 바꾸고, 20의 링크는 그대로 둬요.
  3. 30보다 뒤에 있는 노드들을 한 칸씩 앞으로 당겨 빈자리를 메워요.

Q11. 자식 하나인 65 삭제

다음 이진 탐색 트리에서 자식이 하나뿐인 65를 삭제해요. 삭제 처리로 알맞은 것을 고르세요.

  1. 65를 가지째 잘라 내므로 그 아래 80과 72도 트리에서 빠져요.
  2. 40의 오른쪽 링크가 80을 가리키게 바꿔요. 72는 80의 왼쪽에 그대로 남아요.
  3. 80만 40의 오른쪽에 붙이고, 80 아래의 72는 따로 떼어 버려요.
  4. 배열 표현이라면 80이 있던 7번 칸 값만 65의 3번 칸으로 옮기면 끝나요.
풀이 보기
  1. "자식이 있어도 가지째 자른다" — 자식까지 사라지면 데이터 손실이에요. 남은 서브트리는 부모에 이어 붙여요.
  2. 80 서브트리의 키는 모두 40보다 커서 40의 오른쪽에 이어 붙여도 순서 조건이 유지돼요.
  3. "유일한 자식 노드만 옮기고 그 아래는 버린다" — 이어 붙이는 것은 자식 노드 하나가 아니라 그 서브트리 전체예요. 72도 보존해요.
  4. "배열에서도 칸 하나만 옮기면 된다" — 배열에서는 서브트리 전체가 한 레벨 올라가요. 14번 칸의 72도 6번 칸으로 옮겨야 해요.

Q12. 50 자리의 후보

다음 이진 탐색 트리에서 자식이 둘인 루트 50을 삭제해요. 50 자리에 올려도 순서 조건이 유지되는 키 두 개로 알맞은 것을 고르세요.

  1. 25 또는 75예요. 바로 아래 자식 가운데 하나를 올려요.
  2. 12 또는 90이에요. 왼쪽은 가장 작은 값, 오른쪽은 가장 큰 값을 올려요.
  3. 44 또는 62예요. 왼쪽 서브트리의 최댓값과 오른쪽 서브트리의 최솟값이에요.
  4. 38 또는 62예요. 왼쪽 자식에서 오른쪽으로 한 칸만 가면 최댓값이에요.
풀이 보기
  1. "두 자식 중 하나를 그대로 올린다" — 25를 올리면 원래 오른쪽 38 서브트리와 75 서브트리가 함께 25의 오른쪽에 붙어야 해서 자식이 셋이 돼요.
  2. "값이 극단인 노드가 가장 힘센 후보다" — 12를 올리면 25·38 같은 키가 그보다 큰데 왼쪽에 남아요. 왼쪽은 최댓값, 오른쪽은 최솟값을 올려요.
  3. 44는 남은 왼쪽 키보다 크고 62는 남은 오른쪽 키보다 작아요. 어느 쪽을 올려도 순서가 지켜져요.
  4. "오른쪽 끝까지 가지 않고 한 칸에서 멈춘다" — 38의 오른쪽에 44가 더 있어요. 38을 올리면 44가 새 루트보다 큰데 왼쪽에 남아요.

Q13. 올린 62의 옛자리

다음 이진 탐색 트리에서 루트 50을 지우면서 오른쪽 서브트리의 최솟값 62를 50 자리로 올렸어요. 그다음 원래 62가 있던 자리를 처리하는 방법으로 알맞은 것을 고르세요.

  1. 원래 62 노드는 그대로 둬요. 값만 위로 복사했으니 고칠 곳이 없어요.
  2. 원래 62를 지우면서 그 오른쪽 자식 68도 함께 지워요.
  3. 68을 새 루트 62의 오른쪽 자식 자리로 함께 올려 붙여요.
  4. 75의 왼쪽 링크가 68을 가리키게 해서 원래 62 자리를 정리해요.
풀이 보기
  1. "후보의 원래 자리를 남겨 둬도 된다" — 그러면 62가 두 번 나와 키의 유일성이 깨져요. 원래 자리는 지워야 해요.
  2. "후보를 지울 때 그 자식도 버린다" — 68은 지울 키가 아니에요. 후보에게 자식이 있으면 후보의 부모에게 이어 붙여요.
  3. "후보의 자식을 후보와 함께 옮긴다" — 새 루트 62의 오른쪽에는 75 서브트리가 그대로 있어야 해요. 68은 원래 후보의 부모 75가 이어받아요.
  4. 오른쪽 최솟값 62에는 왼쪽 자식이 없고 오른쪽 자식 68만 있어요. 68은 75보다 작으니 75의 왼쪽에 붙어요.

Q14. 다섯 키를 차례로 넣은 트리

빈 이진 탐색 트리에 키 10, 20, 30, 40, 50을 이 순서대로 삽입했어요. 이 트리에서 50을 찾는 비용을 바르게 설명한 것을 고르세요.

  1. 오른쪽으로만 이어진 높이 5의 경사 트리라서 5번 비교해요. 순차 탐색과 같아요.
  2. 이진 탐색 트리는 늘 $O(\log n)$이니 3번 안에 찾아요.
  3. 트리는 최악으로 따지지 않는다고 했으니 이 경우도 $O(\log n)$으로 봐요.
  4. 노드가 5개면 넣는 순서와 상관없이 높이가 같아서 비교 횟수도 같아요.
풀이 보기
  1. 비용은 높이 $h$에 비례해요. 경사 트리는 $h=n$이라 최악 $O(n)$이에요.
  2. "이진 탐색 트리는 모양과 상관없이 $O(\log n)$이다" — 순서 조건은 균형을 보장하지 않아요. $O(\log n)$은 균형 잡힌 모양일 때예요.
  3. "'최악으로 얘기하지 않는다'를 분석 규칙으로 쓴다" — 그 말은 균형을 관리하자는 취지예요. 이 트리의 실제 비용은 높이만큼인 5번이에요.
  4. "노드 수가 같으면 높이도 같다" — 같은 다섯 키도 30을 먼저 넣으면 높이 3이 돼요. 높이는 넣는 순서에 따라 달라요.

정답: A

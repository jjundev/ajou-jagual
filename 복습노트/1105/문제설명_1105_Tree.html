핵심 조건과 구할 것

한 이진 탐색 트리(BST)에서 13, 16, 5를 차례대로 누적 삭제한 뒤의 최종 트리를 그려요.

  • 앞 단계의 결과 트리가 다음 삭제의 출발점이에요(원래 그림으로 돌아가지 않아요).
  • 마지막 5는 자식이 둘이라 후계자(6)와 선행자(3) 두 가지 답이 모두 가능해요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제 단서꺼낼 도구·공식이 문제에 쓰는 이유와 조건
BST에서 순차 삭제자식 수(0·1·2개)별 삭제 규칙 (정리노트)13(0개)·16(1개)·5(2개)를 만날 때마다 연결 바꿈 방식이 달라져요.
자식이 2개인 5오른쪽 최솟값(successor) 또는 왼쪽 최댓값(predecessor) (정리노트)왼쪽 전체 < 대체 키 < 오른쪽 전체인 BST 순서를 깨지 않는 유일한 두 후보예요.
후보 이동 후 남은 가지후보의 원래 자리 1자식/0자식 삭제 (정리노트)후계자 6의 오른쪽 자식 7을 부모 10의 왼쪽에 붙여야 키 유실과 중복이 없어요.

종이에 쓰는 실제 첫 줄

1단계(13 삭제): 15 → 5 → 12 → 13 (left=NULL, right=NULL → 단말)
⇒ 12.right = NULL

  • 중위 순회(inorder) 검산: 두 트리 모두 왼쪽→현재→오른쪽 순으로 읽으면 3 6 7 10 12 15 18 20 23으로 오름차순이 정확히 일치해요.

  3. 선행자 3으로 바꿀 때 6과 7의 위치가 왜 변하지 않는지 설명해 보세요.

떠올릴 개념·공식

자식 0개(NULL)·1개(유일 자식 연결)·2개(후계자/선행자 대체 후 후보 자리 정리).

검산

이 문제를 봤을 때 떠올릴 개념과 공식

문제 단서꺼낼 도구·공식이 문제에 쓰는 이유와 조건
높이(height)루트를 레벨 1로 세는 최대 깊이 (정리노트)일반 BST의 높이는 $\lceil\log_2(n+1)\rceil \le h \le n$ 범위에서 입력 순서에 따라 변해요.

크기가 $n$인 BST 표에서 비어 있는 삽입연산의 평균 시간복잡도와 최악 시간복잡도를 채워요.

  • 첫 열 제목이 “삭제연산알고리즘”으로 인쇄되어 있지만 실제 두 행은 탐색연산(이미 채워짐)과 삽입연산이므로, 원문 오기를 그대로 두고 삽입연산의 두 빈칸만 구해요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제 단서꺼낼 도구·공식이 문제에 쓰는 이유와 조건
BST 삽입 연산높이 $h$ 하강 비교 $O(h)$ + 링크 연결 $O(1)$ (정리노트)한 갈래만 따라 빈 링크까지 내려가 붙이므로 삽입 시간은 트리 높이 $h$에 비례해요.
평균의 시간복잡도무작위 순서·유일 키 삽입 모형의 기대 높이 $O(\log n)$ (정리노트)서로 다른 $n$개 키가 무작위 순열로 들어올 때 평균 경로 길이가 로그 수준이에요(모든 트리에 대한 보장은 아님).
최악의 시간복잡도한쪽 경사 트리(skewed tree) $h = n$정렬된 키를 연속 삽입해 일렬로 매달리면 새 최댓값 삽입 시 $n$개를 모두 비교해요.

종이에 쓰는 실제 첫 줄

삽입 시간 = 빈자리까지 비교(O(h)) + 새 링크 연결(O(1)) = O(h)
⇒ h의 평균과 최악만 결정하면 두 빈칸이 바로 나와요.

왜 이렇게 푸는지 함께 따라가요

빈칸트리 높이 $h$ 가정비교 횟수와 시간복잡도
삽입연산 평균서로 다른 키 무작위 순서 → 기대 높이 $\Theta(\log n)$ $O(\log n)$
삽입연산 최악오름차순/내림차순 삽입 → 경사 트리 $h = n$ $O(n)$

이미 인쇄된 탐색연산 행(평균 $O(\log n)$, 최악 $O(n)$)과 구조가 같은 이유는 탐색과 삽입 모두 루트에서 한 갈래를 따라 $O(h)$만큼 비교하기 때문이에요.

완성 답과 검산

완성 답: 삽입연산 평균 $O(\log n)$, 최악 $O(n)$ (교과서 공식 정답 미제공으로 자체 검산한 답이에요).

  • 최악 경계 검산: 1 → 2 → 3처럼 오른쪽으로만 $n$개가 이어진 경사 트리에 n+1을 삽입하면 1, 2, ..., n을 전부 비교한 뒤 붙으므로 정확히 $n$번 비교(O(n))가 발생해요.
  • 경계값($n=0$) 검산: 빈 트리($n=0$)에 첫 노드를 삽입할 때는 비교 없이 $O(1)$에 끝나므로, 표의 $O(\log n)$·$O(n)$은 $n$이 커질 때의 점근적 평균·최악 상한을 뜻해요.

실수하면 답이 이렇게 망가져요

평균 $O(\log n)$을 “어떤 BST든 항상 $O(\log n)$”으로 읽으면: 1, 2, ..., 1000처럼 정렬된 데이터를 그대로 넣으면 높이가 1000인 일렬 트리가 되어 삽입 비용이 $O(n)$으로 치솟아요.

제목 오기 “삭제연산알고리즘”을 보고 삭제 행을 억지로 추가하면: 문제 표에는 탐색행과 삽입행 두 줄만 있고 삭제행 빈칸이 없으므로 없는 칸을 만들어 답하면 문제 조건과 어긋나요.

해설을 가리고 스스로 확인해요

  1. BST 삽입에서 노드 연결 자체는 $O(1)$인데도 전체 시간이 $O(h)$가 되는 이유를 말해 보세요.
  2. 최악 시간 $O(n)$이 실제로 나타나는 입력 키 순서 예시(n=4)를 적어 보세요.

떠올릴 개념·공식

삽입 = 탐색 하강 $O(h)$ + 연결 $O(1)$ = $O(h)$. 무작위 입력 평균 $O(\log n)$, 경사 트리 최악 $O(n)$.

첫 줄

삽입 시간 = O(h) + O(1) = O(h)에서 높이 $h$의 평균·최악을 대입.

핵심 답

삽입연산 평균 $O(\log n)$, 최악 $O(n)$ (원문 제목 ‘삭제연산알고리즘’ 오타는 보존, 삽입행만 작성).

검산

(c) TreeNode *search(x, k)키 비교 분기 + NULL 종료 + 포인터 반환 (정리노트)성공 시 반환하는 값은 배열 인덱스가 아니라 찾은 노드의 메모리 주소(TreeNode *)예요.

종이에 쓰는 실제 첫 줄

(a) 학생 1명 전체 = 레코드,  속성 1개 = 필드,  중복 없음 = 학번(고유 키)
(b) 20은 18의 왼쪽 서브트리 ⇒ 20 < 18 조건 검사
(c) 12 탐색: 12 < 18 → 왼쪽 7  /  20 탐색: 20 > 18 → 오른쪽 26

왜 이렇게 푸는지 함께 따라가요

(a) 자료 구조 용어와 고유 키
  • 학생 한 명의 자료 전체(학번·이름·학과 묶음) = 레코드(record), 그 안의 속성 하나 = 필드(field).
  • 고유 키 = 학번: 학번은 학생마다 서로 다르므로 레코드를 유일하게 구별하지만, 이름은 동명이인이 있어 고유 키로 쓸 수 없어요.
(b) 별도 트리의 BST 여부와 키 7 중복
  • BST가 아니에요: 20은 부모 7보다는 크지만(20 > 7), 루트 18의 왼쪽 서브트리에 있으므로 허용 범위 (7, 18)을 벗어나 20 < 18 조건을 위반해요.
  • 중복 7 불가: 문제 조건에서 BST는 키 중복을 허용하지 않고 엄격한 부등호(<, >)로만 분기하므로 같은 키를 둘 수 없어요.
(c) 12·20 탐색 추적과 반환값 의미
탐색 키방문·비교한 노드 키 순서종료 지점과 이유반환값
1218 → 7 → 1212 == 12 일치 (성공)키 12 노드의 주소(TreeNode *)
2018 → 2626.left == NULL 만남 (실패)NULL

성공 반환값은 포인터형 TreeNode *(연결된 노드의 메모리 주소)이므로 정수 배열 인덱스라고 부를 수 없어요(연결 구조라 배열 인덱스 자체가 존재하지 않아요).

완성 답과 검산

(a) 검산: 전체(레코드) ⊃ 부분(필드)의 포함 관계가 맞고, 동명이인 예시(예: 두 학생 모두 이름이 ‘김철수’)에서는 이름만으로 한 명을 고를 수 없지만 학번은 유일해요.

(b) 검산: 해당 트리를 중위 순회하면 7, 20, 18 순서로 20 > 18 역전이 바로 보이고, 중복 허용 시 k < x->key와 k > x->key 어디로도 보낼 수 없어요.

(c) 검산: 20 탐색 시 26.left가 NULL이므로 search(NULL, 20)에서 if x=NULL이 즉시 참이 되어 키 비교 없이 NULL을 반환해요(비교 키는 18, 26 2개뿐). search 함수 선언 반환형이 TreeNode *이므로 반환값도 반드시 주소 또는 NULL이에요.

실수하면 답이 이렇게 망가져요

(b)에서 부모 7만 보고 20 > 7이라 통과시키면: 이후 20을 탐색할 때 루트 18에서 20 > 18이므로 오른쪽(NULL)으로 가 버려 트리 안에 있는 20을 찾지 못해요.

(c)의 실패 탐색 비교 키에 NULL을 포함해 18, 26, NULL로 적으면: NULL은 노드가 아니므로 x->key를 읽을 수 없고 키 비교 횟수에 들어가지 않아요.

해설을 가리고 스스로 확인해요

  1. 만약 동명이인이 없더라도 “규정상 이름이 같을 수 있다”면 고유 키로 쓸 수 없는 이유를 말해 보세요.
  2. (b)의 20을 루트 18부터 탐색할 때 왜 찾지 못하는지 경로를 따라 확인해 보세요.
  3. (c)에서 반환형 TreeNode *를 보고 배열 인덱스가 아님을 바로 판단하는 근거 한 가지를 들어 보세요.

첫 줄

핵심 답

검산

P12. 삽입의 부모·현재 노드와 경계

lecture-s07-p21-insert-boundaries · 원 문제 보기

강의 예제 기반 자체 출제 S7 p21

다음 트리에서 키 중복을 허용하지 않아요. 새 노드 z의 두 자식 링크는 NULL이에요. 아래 절차는 새 노드를 기존 트리에 연결하는 연산만 다뤄요.

p = NULL, t = root로 시작해요. p는 직전에 지난 부모이고 t는 현재 노드예요. t가 NULL이 아니면 같은 키가 있는지 먼저 검사하고, 같으면 연결하지 않고 종료해요. 다르면 p = t로 옮긴 뒤 새 키가 p의 키보다 작으면 t = p->left, 크면 t = p->right로 내려가요.

반복이 끝났을 때 p == NULL이면 root = z예요. 그렇지 않으면 새 키가 작을 때 p->left = z, 클 때 p->right = z로 연결해요. 이 조건의 =는 상태 변경을 뜻하며, 같음을 확인하는 조건은 ==로 적었어요.

구할 것

  1. (a) 키 9를 넣을 때 반복 시작마다 (p, t)의 키 또는 NULL을 쓰세요. 반복이 끝났을 때 값과 바꾸는 링크도 쓰세요.
  2. (b) (a)의 결과에 새 9를 다시 넣으면 노드 수와 링크는 어떻게 되나요?
  3. (c) (a)와 별도로, 처음부터 빈 트리에 키 9를 넣으면 반복 횟수와 root 값은 무엇인가요?
강의 예제 보기

S7 p21 · 삽입 원문 의사코드

원문의 의사코드예요. =는 같음을 비교하고 ←는 값을 바꾸는 표시예요. C 대입식으로 읽지 않아요.

insert_node(T,z)

p←NULL;
t←root;
while t≠NULL do                 // 빈자리 찾기
{
    if (z->key = t->key) return;
    p←t;
    if z->key < p->key
        then t←p->left;
        else t←p->right;
}
if p=NULL
    then root←z;// 트리가 비어있음
else if z->key < p->key // insert
    then p->left←z
    else p->right←z

추가 근거: S7 p18–19의 레코드·키와 이진 탐색 트리 조건, S7 p20의 탐색 트리 그림이에요.

핵심 조건과 구할 것

반복문 삽입 절차 insert_node(T, z)에서 부모 포인터 p와 현재 포인터 t를 추적해 (a) 키 9 삽입 추적, (b) 중복 9 재삽입 결과, (c) 빈 트리 경계 삽입을 구해요.

  • 새 노드 z의 두 자식 링크는 NULL이며, =는 대입·==는 비교로 읽어요(노드 연결 연산만 다룸).

이 문제를 봤을 때 떠올릴 개념과 공식

소문항·단서꺼낼 도구·공식이 문제에 쓰는 이유와 조건
(a) 반복 시작마다 (p, t) 추적p(직전 부모)가 t(현재 노드)를 한 칸 뒤따르는 불변식 (정리노트)t가 NULL에 도달해 루프가 끝나도 p가 마지막 노드를 기억하므로 p->left/right = z를 연결할 수 있어요.
(b) 같은 키 9 다시 삽입루프 선두 중복 검사(z->key == t->key → 즉시 return)p = t나 링크 연결문까지 내려가지 않고 종료하므로 트리가 그대로 보존돼요.
(c) 빈 트리에 9 삽입t = root = NULL 경계 조건(while 0회 + p == NULL 분기)반복 본문이 한 번도 돌지 않아 p == NULL이 유지되고 root = z가 실행돼요.

종이에 쓰는 실제 첫 줄

(a) while 진입 전: p = NULL,  t = root(18)  ⇒  첫 반복 시작 (p, t) = (NULL, 18)
9 != 18 이고 9 < 18  ⇒  p = 18,  t = 18->left(7)

왜 이렇게 푸는지 함께 따라가요

(a) 키 9 삽입 시 (p, t) 변화와 최종 연결
반복 구분시작 시 (p, t)루프 내 판정과 포인터 갱신
1회차 본문 시작(NULL, 18)9 != 18, 9 < 18 → p = 18, t = 7
2회차 본문 시작(18, 7)9 != 7, 9 > 7 → p = 7, t = 12
3회차 본문 시작(7, 12)9 != 12, 9 < 12 → p = 12, t = NULL
종료(탈출)(12, NULL)t == NULL이므로 본문 실행 없이 while 종료

반복 본문은 3회 실행되고, 종료 시 p는 키 12 노드, t는 NULL이에요. 9 < 12이므로 p->left = z(12의 왼쪽 링크)에 z(키 9)를 연결해요.

(b) (a)의 트리에 9를 다시 삽입한 경우

(NULL, 18) → (18, 7) → (7, 12) → (12, 9) 순서로 내려가 4회차 시작에서 z->key == t->key(9 == 9)가 참이 되어 즉시 return해요. 루프 뒤의 연결 코드에 도달하지 않으므로 노드 수는 8개로 유지되고 모든 링크는 변하지 않아요.

(c) 처음부터 빈 트리(root == NULL)에 9를 삽입한 경우

시작부터 p = NULL, t = root = NULL이므로 while (t != NULL) 조건이 거짓이에요. 따라서 반복 횟수는 0회이고, if (p == NULL) 분기를 타서 root = z(키 9 노드의 주소, 양쪽 자식 NULL)가 돼요.

완성 답과 검산

(a) 검산: (NULL, 18), (18, 7), (7, 12) 3쌍 뒤 종료 (12, NULL)이에요. 새 키 9는 경로상 7 < 9 < 12 < 18 범위에 딱 맞으므로 12.left = 9 연결 후 중위 순회가 3 7 9 12 18 26 27 31(8개 오름차순)이 돼요.

(b) 검산: 중복 검사가 루프 맨 앞줄(p = t보다 위)에 있으므로 p도, 어떤 링크도 바뀌지 않고 노드 8개(3, 7, 9, 12, 18, 26, 27, 31)가 보존돼요.

(c) 검산: 경계값 $n=0$(빈 트리)을 대입하면 t == NULL이라 본문 0회 실행 후 p == NULL이므로 root = z로 노드 1개 트리가 완성돼요(root 변수의 값은 정수 9가 아니라 노드 z의 주소).

실수하면 답이 이렇게 망가져요

종료 상태 (12, NULL)까지 본문 실행 횟수에 넣어 4회로 세면: t == NULL일 때는 while 조건이 거짓이라 본문에 들어가지 않아요. 만약 들어간다면 t->key에서 널 포인터 역참조 오류가 나요.

(c)의 root 값을 “정수 9”라고만 적으면: root는 TreeNode * 포인터이므로 정수 키 9를 저장한 새 노드의 주소를 가리킨다고 구분해 적어야 정확해요.

해설을 가리고 스스로 확인해요

  1. 9 대신 28을 삽입한다면 반복 시작마다 (p, t) 쌍이 몇 번 나오고 어느 노드의 어느 링크가 바뀌는지 적어 보세요.
  2. 만약 코드에서 if (z->key == t->key) return;이 p = t 아래로 내려가면 (b)에서 p 값은 어떻게 달라질까요?
  3. 빈 트리($n=0$)일 때 p == NULL 조건을 빼먹고 바로 p->left = z를 실행하면 어떤 오류가 생길지 말해 보세요.

핵심 답

검산

(a) 7<9<12<18 및 중위 8개 오름차순, (b) p=t 전 종료, (c) $n=0$에서 t=NULL 0회 확인.

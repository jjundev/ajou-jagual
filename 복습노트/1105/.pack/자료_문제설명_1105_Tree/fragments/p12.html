핵심 조건과 구할 것

반복문 삽입 절차 insert_node(T, z)에서 부모 포인터 p와 현재 포인터 t를 추적해 (a) 키 9 삽입 추적, (b) 중복 9 재삽입 결과, (c) 빈 트리 경계 삽입을 구해요.

  • 새 노드 z의 두 자식 링크는 NULL이며, =는 대입·==는 비교로 읽어요(노드 연결 연산만 다룸).

이 문제를 봤을 때 떠올릴 개념과 공식

소문항·단서꺼낼 도구·공식이 문제에 쓰는 이유와 조건
(a) 반복 시작마다 (p, t) 추적p(직전 부모)가 t(현재 노드)를 한 칸 뒤따르는 불변식 (정리노트)t가 NULL에 도달해 루프가 끝나도 p가 마지막 노드를 기억하므로 p->left/right = z를 연결할 수 있어요.
(b) 같은 키 9 다시 삽입루프 선두 중복 검사(z->key == t->key → 즉시 return)p = t나 링크 연결문까지 내려가지 않고 종료하므로 트리가 그대로 보존돼요.
(c) 빈 트리에 9 삽입t = root = NULL 경계 조건(while 0회 + p == NULL 분기)반복 본문이 한 번도 돌지 않아 p == NULL이 유지되고 root = z가 실행돼요.

종이에 쓰는 실제 첫 줄

(a) while 진입 전: p = NULL,  t = root(18)  ⇒  첫 반복 시작 (p, t) = (NULL, 18)
9 != 18 이고 9 < 18  ⇒  p = 18,  t = 18->left(7)

왜 이렇게 푸는지 함께 따라가요

(a) 키 9 삽입 시 (p, t) 변화와 최종 연결
반복 구분시작 시 (p, t)루프 내 판정과 포인터 갱신
1회차 본문 시작(NULL, 18)9 != 18, 9 < 18 → p = 18, t = 7
2회차 본문 시작(18, 7)9 != 7, 9 > 7 → p = 7, t = 12
3회차 본문 시작(7, 12)9 != 12, 9 < 12 → p = 12, t = NULL
종료(탈출)(12, NULL)t == NULL이므로 본문 실행 없이 while 종료

반복 본문은 3회 실행되고, 종료 시 p는 키 12 노드, t는 NULL이에요. 9 < 12이므로 p->left = z(12의 왼쪽 링크)에 z(키 9)를 연결해요.

(b) (a)의 트리에 9를 다시 삽입한 경우

(NULL, 18) → (18, 7) → (7, 12) → (12, 9) 순서로 내려가 4회차 시작에서 z->key == t->key(9 == 9)가 참이 되어 즉시 return해요. 루프 뒤의 연결 코드에 도달하지 않으므로 노드 수는 8개로 유지되고 모든 링크는 변하지 않아요.

(c) 처음부터 빈 트리(root == NULL)에 9를 삽입한 경우

시작부터 p = NULL, t = root = NULL이므로 while (t != NULL) 조건이 거짓이에요. 따라서 반복 횟수는 0회이고, if (p == NULL) 분기를 타서 root = z(키 9 노드의 주소, 양쪽 자식 NULL)가 돼요.

완성 답과 검산

(a) 검산: (NULL, 18), (18, 7), (7, 12) 3쌍 뒤 종료 (12, NULL)이에요. 새 키 9는 경로상 7 < 9 < 12 < 18 범위에 딱 맞으므로 12.left = 9 연결 후 중위 순회가 3 7 9 12 18 26 27 31(8개 오름차순)이 돼요.

(b) 검산: 중복 검사가 루프 맨 앞줄(p = t보다 위)에 있으므로 p도, 어떤 링크도 바뀌지 않고 노드 8개(3, 7, 9, 12, 18, 26, 27, 31)가 보존돼요.

(c) 검산: 경계값 $n=0$(빈 트리)을 대입하면 t == NULL이라 본문 0회 실행 후 p == NULL이므로 root = z로 노드 1개 트리가 완성돼요(root 변수의 값은 정수 9가 아니라 노드 z의 주소).

실수하면 답이 이렇게 망가져요

종료 상태 (12, NULL)까지 본문 실행 횟수에 넣어 4회로 세면: t == NULL일 때는 while 조건이 거짓이라 본문에 들어가지 않아요. 만약 들어간다면 t->key에서 널 포인터 역참조 오류가 나요.

(c)의 root 값을 “정수 9”라고만 적으면: root는 TreeNode * 포인터이므로 정수 키 9를 저장한 새 노드의 주소를 가리킨다고 구분해 적어야 정확해요.

해설을 가리고 스스로 확인해요

  1. 9 대신 28을 삽입한다면 반복 시작마다 (p, t) 쌍이 몇 번 나오고 어느 노드의 어느 링크가 바뀌는지 적어 보세요.
  2. 만약 코드에서 if (z->key == t->key) return;이 p = t 아래로 내려가면 (b)에서 p 값은 어떻게 달라질까요?
  3. 빈 트리($n=0$)일 때 p == NULL 조건을 빼먹고 바로 p->left = z를 실행하면 어떤 오류가 생길지 말해 보세요.

떠올릴 개념·공식

p(직전 부모)·t(현재 노드) 불변식, 중복 시 즉시 return, 빈 트리(p==NULL) 시 root=z.

첫 줄

(p, t) = (NULL, 18)에서 9 < 18이므로 p=18, t=7로 하강.

핵심 답

(a) 시작 (NULL,18),(18,7),(7,12)(3회), 종료 (12,NULL), 12.left = z / (b) 8개·링크 불변 / (c) 0회, root = z(키 9 노드 주소).

검산

(a) 7<9<12<18 및 중위 8개 오름차순, (b) p=t 전 종료, (c) $n=0$에서 t=NULL 0회 확인.

무엇을 구하는 문제인가요?

현재 노드와 직전 부모를 구별하며 삽입 과정을 추적해요. 첫 삽입, 중복 키, 처음부터 빈 트리라는 세 경우를 따로 판단해요.

이 문제를 봤을 때 떠올릴 개념과 공식

“반복 시작마다 (p, t)”는 키 비교 결과만이 아니라 두 포인터의 상태를 함께 적으라는 단서예요. t는 이번에 검사할 현재 노드, p는 직전에 지나온 부모예요. 처음에는 부모가 없어서 p = NULL이고 현재 노드는 t = root예요.

현재 키와 다르면 p = t를 먼저 실행하고, 비교 결과에 따라 t를 다음 자식으로 옮겨요. 따라서 빈 링크에 도착했을 때 t == NULL이고 p에는 연결할 부모가 남아요. 이 관계가 반복 중 유지되는 불변식이에요.

같은 키를 만나면 부모 이동이나 마지막 링크 변경 전에 종료해요. 빈 트리는 처음부터 현재 노드가 없어 반복 본문을 한 번도 실행하지 않아요. 문제는 노드 연결을 묻고 있으므로 메모리 할당·해제 여부를 추가로 가정하지 않아요.

종이에 적을 첫 줄

초기 상태: (p, t) = (NULL, 18)
9와 18은 다르고 9 < 18이에요.
p를 18로 옮긴 뒤 t를 18의 왼쪽인 7로 옮겨요.

왜 이렇게 푸는지 함께 따라가요

(a) 새 키 9와 같은 키가 있는지 먼저 확인하고, 없으면 부모를 기억한 뒤 한 가지를 내려가요.

반복 시작/종료(p, t)의 키비교와 이동
첫 본문 시작(NULL, 18)9 < 18이므로 p=18, t=7로 옮겨요.
둘째 본문 시작(18, 7)9 > 7이므로 p=7, t=12로 옮겨요.
셋째 본문 시작(7, 12)9 < 12이므로 p=12, t=NULL로 옮겨요.
반복 종료(12, NULL)t == NULL이므로 본문을 더 실행하지 않아요.

본문은 3번 실행됐어요. 종료 쌍은 넷째 본문의 시작이 아니라 조건이 거짓이 된 상태예요. p가 키 12 노드를 가리키고 9 < 12이므로 p->left = z를 실행해 12의 왼쪽에 9를 연결해요.

(b) (a)의 삽입으로 기존 7개가 8개가 됐어요. 새 9를 다시 넣으면 18, 7, 12, 9를 차례로 비교해요. 마지막 기존 9에서 키가 같으므로 즉시 종료해요.

마지막 연결 문장에 도달하지 않으므로 새 노드는 붙지 않아요. 노드 수는 8개이고 모든 자식 링크는 변하지 않아요.

(c) 처음부터 빈 트리이면 root == NULL이에요. 초기 p와 t가 모두 NULL이므로 반복 조건이 처음부터 거짓이에요. 본문 실행은 0회예요.

반복 뒤에도 p == NULL이어서 root = z로 새 노드를 루트에 연결해요. root는 키 9인 새 노드의 주소이고 두 자식 링크는 NULL이에요.

완성 답과 검산

(a) 완성 추적은 (NULL, 18), (18, 7), (7, 12), 종료 (12, NULL)이에요. 별도 추적도 본문 실행 3회와 같은 종료 쌍을 얻었어요. 독립 C11 검산용 번역에서는 원문의 삽입 절차를 감싸고, 연결했으면 1·중복으로 연결하지 않았으면 0을 반환하는 상태 규약을 추가했어요. 이 1·0은 원문 의사코드의 반환값 계약이 아니에요. 그 검산용 규약으로 삽입 성공과 바뀐 링크를 확인했어요.

insert9=1
parent12.left=9

새 키가 지나온 범위도 확인해요. 7 < 9 < 12 < 18이므로 12의 왼쪽에 연결해도 조상들의 키 조건을 모두 지켜요. 다른 링크는 바꿀 필요가 없어요.

(b) 별도 검산에서 중복 시도 전후 노드 수는 모두 8개였고 링크도 같았어요. C11 결과의 0은 검산용 번역이 추가한 상태 표시로, 새 노드를 연결하지 않았다는 뜻이에요. 원문의 return;이 정수 0을 반환한다는 뜻은 아니에요.

duplicate9=0

같은 키 검사에서 바로 반환하므로 마지막 연결문을 실행하지 않는다는 절차와 일치해요. 중복 시도 때문에 노드 수를 9개로 세지 않아요.

(c) 별도 추적은 빈 트리에서 반복 본문을 0회 실행하고 root만 바꿨어요. C11 실행도 새 루트의 키 9를 확인했어요. 출력의 empty_insert=1은 검산용 번역의 “연결 성공” 상태이며, 원문 의사코드가 정수 1을 반환한다고 해석하지 않아요.

empty_insert=1 root=9

출력의 root=9는 루트 주소에 있는 노드의 키를 보여 준 표시예요. 실제 root 변수에는 정수 키가 아니라 새 노드의 주소가 들어 있어요.

헷갈리기 쉬운 지점

종료 쌍 (12, NULL)을 넷째 반복 실행으로 세지 않아요. p와 t를 동시에 다음 자식으로 옮기면 빈자리의 부모를 잃어요. 중복이면 연결 전에 끝나며, 빈 트리에서는 본문 실행 없이 루트만 바꿔요. 원문의 의사코드 =는 비교, ←는 상태 변경이라는 표기도 구별해요.

설명을 닫고 다시 풀어요

  1. 새 9를 넣을 때 세 번의 본문 시작 쌍과 종료 쌍을 나눠 적으세요.
  2. 중복 9에서 어느 검사로 끝나는지 설명하고 노드 수를 세어 보세요.
  3. 빈 트리의 초기 쌍, 본문 실행 횟수, 마지막 루트 변경을 적으세요.

떠올릴 개념·공식

p는 직전 부모, t는 현재 노드예요. p=t뒤 t만 다음 자식으로 옮겨요.

첫 줄·삽입 답

본문 시작은 (NULL, 18), (18, 7), (7, 12)예요. 본문 3회 뒤 종료 (12, NULL)에서 12의 왼쪽에 9를 연결해요.

중복·빈 트리

중복 9는 같은 키 검사에서 종료해 8개와 링크를 유지해요. 처음부터 빈 트리이면 본문은 0회, root는 새 키 9 노드의 주소가 돼요.

검산·주의

C11 결과와 별도 추적이 일치해요. 출력의 1·0은 검산용 번역에 추가한 연결 성공·중복 상태이며 원문 의사코드의 반환 계약이 아니에요. 종료 쌍을 추가 반복으로 세지 않고, 키·주소를 구별해요. 연결 연산 밖의 할당·해제는 가정하지 않아요. 의사코드 =는 비교, ←는 변경이에요.

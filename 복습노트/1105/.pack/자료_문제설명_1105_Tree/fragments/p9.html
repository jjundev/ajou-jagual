핵심 조건과 구할 것

크기가 $n$인 BST 표에서 비어 있는 삽입연산의 평균 시간복잡도와 최악 시간복잡도를 채워요.

  • 첫 열 제목이 “삭제연산알고리즘”으로 인쇄되어 있지만 실제 두 행은 탐색연산(이미 채워짐)과 삽입연산이므로, 원문 오기를 그대로 두고 삽입연산의 두 빈칸만 구해요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제 단서꺼낼 도구·공식이 문제에 쓰는 이유와 조건
BST 삽입 연산높이 $h$ 하강 비교 $O(h)$ + 링크 연결 $O(1)$ (정리노트)한 갈래만 따라 빈 링크까지 내려가 붙이므로 삽입 시간은 트리 높이 $h$에 비례해요.
평균의 시간복잡도무작위 순서·유일 키 삽입 모형의 기대 높이 $O(\log n)$ (정리노트)서로 다른 $n$개 키가 무작위 순열로 들어올 때 평균 경로 길이가 로그 수준이에요(모든 트리에 대한 보장은 아님).
최악의 시간복잡도한쪽 경사 트리(skewed tree) $h = n$정렬된 키를 연속 삽입해 일렬로 매달리면 새 최댓값 삽입 시 $n$개를 모두 비교해요.

종이에 쓰는 실제 첫 줄

삽입 시간 = 빈자리까지 비교(O(h)) + 새 링크 연결(O(1)) = O(h)
⇒ h의 평균과 최악만 결정하면 두 빈칸이 바로 나와요.

왜 이렇게 푸는지 함께 따라가요

빈칸트리 높이 $h$ 가정비교 횟수와 시간복잡도
삽입연산 평균서로 다른 키 무작위 순서 → 기대 높이 $\Theta(\log n)$ $O(\log n)$
삽입연산 최악오름차순/내림차순 삽입 → 경사 트리 $h = n$ $O(n)$

이미 인쇄된 탐색연산 행(평균 $O(\log n)$, 최악 $O(n)$)과 구조가 같은 이유는 탐색과 삽입 모두 루트에서 한 갈래를 따라 $O(h)$만큼 비교하기 때문이에요.

완성 답과 검산

완성 답: 삽입연산 평균 $O(\log n)$, 최악 $O(n)$ (교과서 공식 정답 미제공으로 자체 검산한 답이에요).

  • 최악 경계 검산: 1 → 2 → 3처럼 오른쪽으로만 $n$개가 이어진 경사 트리에 n+1을 삽입하면 1, 2, ..., n을 전부 비교한 뒤 붙으므로 정확히 $n$번 비교(O(n))가 발생해요.
  • 경계값($n=0$) 검산: 빈 트리($n=0$)에 첫 노드를 삽입할 때는 비교 없이 $O(1)$에 끝나므로, 표의 $O(\log n)$·$O(n)$은 $n$이 커질 때의 점근적 평균·최악 상한을 뜻해요.

실수하면 답이 이렇게 망가져요

평균 $O(\log n)$을 “어떤 BST든 항상 $O(\log n)$”으로 읽으면: 1, 2, ..., 1000처럼 정렬된 데이터를 그대로 넣으면 높이가 1000인 일렬 트리가 되어 삽입 비용이 $O(n)$으로 치솟아요.

제목 오기 “삭제연산알고리즘”을 보고 삭제 행을 억지로 추가하면: 문제 표에는 탐색행과 삽입행 두 줄만 있고 삭제행 빈칸이 없으므로 없는 칸을 만들어 답하면 문제 조건과 어긋나요.

해설을 가리고 스스로 확인해요

  1. BST 삽입에서 노드 연결 자체는 $O(1)$인데도 전체 시간이 $O(h)$가 되는 이유를 말해 보세요.
  2. 최악 시간 $O(n)$이 실제로 나타나는 입력 키 순서 예시(n=4)를 적어 보세요.

떠올릴 개념·공식

삽입 = 탐색 하강 $O(h)$ + 연결 $O(1)$ = $O(h)$. 무작위 입력 평균 $O(\log n)$, 경사 트리 최악 $O(n)$.

첫 줄

삽입 시간 = O(h) + O(1) = O(h)에서 높이 $h$의 평균·최악을 대입.

핵심 답

삽입연산 평균 $O(\log n)$, 최악 $O(n)$ (원문 제목 ‘삭제연산알고리즘’ 오타는 보존, 삽입행만 작성).

검산

경사 트리 1→2→…→n에 n+1 삽입 시 $n$번 비교 확인. 교과서 공식 정답 미제공.

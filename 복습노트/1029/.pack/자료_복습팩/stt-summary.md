## 1. 과제 예고와 트리 도입 (Part 01 앞)

**핵심 내용**
- 스택·큐는 "심플하고 개념적인" 자료구조였고, 트리부터는 "본격적인 자료구조"로 들어간다. [슬라이드 외]
- 트리(Tree): 계층적인 구조를 나타내는 자료구조. 나무를 거꾸로 뒤집은 모양이라 뿌리 = 루트(root), 나뭇잎 = 리프(leaf), 나뭇가지 = 브랜치(branch) 라는 용어를 그대로 쓴다. (S7 p2)
- 트리를 만든 이유: 현실 세계를 모델링하다 보면 **계층적·조직적·포함 관계**를 동시에 표현해야 하는 문제가 많다.
  - 같은 레벨끼리는 형제 관계, 아래에서 루트 쪽으로 올라가는 방향으로는 포함 관계가 느껴진다.
- 응용 분야 (S7 p2): 계층적인 조직 표현(대표이사–총무부–전산팀…), 파일 시스템, 인공지능의 결정 트리(decision tree).
- 트리는 부모–자식(parent–child) 관계의 노드(node)들로 이루어진다.

**비유와 일화**
- **가계도(family tree)**: 할아버지·할머니 아래 큰아버지·고모·아빠·삼촌이 한 레벨에 있다 = 형제. 나는 아빠 밑. 루트부터 레벨 1, 2, 3 으로 단계를 표현하고, 나 ⊂ 아빠 ⊂ 할아버지 식의 포함 관계가 생긴다. "얘가 갑자기 여기에 포함이 되지 않습니다."
- **파일 시스템**: 탐색기에서 C 드라이브를 열면 디렉토리 안에 디렉토리, 또는 파일이 쭉 나온다. 트리를 옆으로 눕힌 모양이고 C 가 루트, 맨 끝의 파일이 리프다.
- **결정 트리**: "온도가 25도보다 높은가 → 바람이 부는가 → 비가 오는가 → 테니스를 치러 나간다/안 나간다." 딥러닝 이전, 1970년대부터 나온 AI 알고리즘 중 심플하지만 많이 쓰인 것이 결정 트리이며 트리 구조를 쓴다. [슬라이드 외] 뉴럴 네트워크는 원래 레이어가 하나였고 딥러닝은 레이어를 깊게(deep) 쌓은 것이라는 곁가지 설명, 알파고 이전 체스 대전 일화.

## 2. 트리의 용어 (Part 01 중간–끝, Part 02 앞)

**핵심 내용** (S7 p3, 예시 트리 A–J)
- 앞 자료구조의 용어와 대비: 스택은 `top`, 큐는 `front`·`rear`(교수님은 tail·head 도 함께 언급). 트리는 용어가 훨씬 많다: node, root, subtree, terminal node, non-terminal node, parent, child, sibling, level, height (+ degree).
- **노드(node)**: 트리의 구성 요소. 그림의 동그라미이며 데이터를 품는다(이 노드는 A, 이 노드는 H).
- **루트(root)**: 부모가 없는 가장 위 레벨의 노드. 예시에서 A 하나.
- **서브트리(subtree)**: 하나의 노드와 그 노드의 자손들로 이루어진 트리. 루트 A 를 잘라내면 나무 세 개(B·C·D 를 루트로 하는)가 생기고, 각각이 또 하나의 트리다 → "정의가 리커시브(recursive)합니다." [재귀적 정의 강조는 슬라이드 외]
  - 노드 하나만 남아도 서브트리, **공백(아무것도 없음)도 서브트리**다. [슬라이드 외]
- **단말 노드(terminal node)**: 자식이 없는 노드(E, F, G, H, I, J). = **리프 노드(leaf node)**. "터미널 노드는 곧 리프 노드입니다."
- **비단말 노드(non-terminal node)**: 적어도 하나의 자식을 가지는 노드(A, B, C, D) = 리프를 제외한 나머지.
- **부모·자식·형제·조상·자손**: 인간 가계도와 동일. 형제(sibling)는 교수님 설명으로 "같은 레벨에 있는 노드"(→ 말실수 정정 참고).
- **레벨(level)**: 루트를 1로 해서 각 층에 붙인 번호(레벨 1, 2, 3). 트리를 그릴 때 레벨을 맞춰 그려야 한다.
- **높이(height)**: 트리의 **최대 레벨**. 대다수 리프가 있는 곳이 아니라 가장 깊은(긴) 리프까지 잰다. 예시 트리는 레벨 3 까지이므로 높이 3.
- **차수(degree)**: 노드가 가지고 있는 자식 노드의 개수. 예시에서 노드마다 자식이 3, 3, 1, 2개로 다른데, 트리의 차수는 그중 **최댓값(max)** → 차수 3 인 트리. [트리 차수 = max 는 슬라이드 외]
- 용어를 많이 배우는 이유: 이 용어를 다 써서 앞으로 알고리즘을 생각해야 한다. 그래서 트리를 스택·큐보다 어려워할 수 있다.

**비유와 일화**
- **터미널 = 고속버스 터미널, 종점**: 더 이상 뻗어나갈 수 없는 끝 노드.
- **나무 높이 재기**: 잎이 듬성한 나무를 뒤집었을 때 높이는 가장 길게 뻗은 가지 끝까지 잰다.
- 형제 설명 중 "어 이거 사촌 아니에요? 네, 그래도 같은 레벨에 있으면 시블링 노드" (자문자답).

**학생과의 대화**
- 없음. 교수님이 "아니, 서브트리 아니고요, 얘 리프 노드들인데요?", "이거 사촌 아니에요?" 같은 예상 질문을 스스로 던지고 답했다.

**강조 발언**
- "이제 굉장히 중요한 용어 두 개가 나옵니다. 레벨." (Part 01 끝, 레벨·높이 설명 직전)
- "트리를 그릴 때 아무렇게나 삐죽삐죽 그릴 수 없고요, 레벨을 맞춰서 그리셔야 돼요." (Part 01 끝)

- "이렇게 용어를 많이 배운 이유는 뭐냐면 이 용어를 다 써서 앞으로 알고리즘을 생각해야 된다는 겁니다." (Part 02 앞)

## 3. 이진 트리의 정의 (Part 02 앞–중간)

**핵심 내용** (S7 p4)
- **이진 트리(binary tree)**: 모든 노드가 **2개 이하**의 서브트리를 가지는 트리. 가장 쉬운 트리지만 "엄청 강력한 트리". 루트 기준으로 왼쪽 서브트리, 오른쪽 서브트리라 부른다.
  - 슬라이드 문구는 "모든 노드가 2개의 서브트리를 가지고 있는 트리 / 서브트리는 공집합일 수 있다"이고, 교수님은 이를 "자식이 0개, 1개, 2개 모두 가능, 3개는 불허"로 풀었다.
  - 자식이 하나 더 있으면 3진 트리(ternary tree). [슬라이드 외]
- 서브트리는 공집합일 수 있다.
- 노드에는 최대 2개의 자식 → 모든 노드의 차수가 2 이하 → **구현하기 편리**.
- **서브트리 간에 순서가 존재**: 왼쪽 서브트리가 오른쪽 서브트리보다 우선한다.
- 이진 모델링의 의도: 현실 세계를 단순화(simplify)해서 0/1, yes/no, 왼쪽/오른쪽으로 모델링하겠다는 것. 표현 안 되는 경우도 있지만 대부분 이진 트리로 모델링한다. [슬라이드 외]

**비유와 일화**
- **디지털 0과 1**: 아날로그 세상을 전기 신호의 넣고/끊고로 디지털화하듯, 자료구조 모델링도 이진을 쓴다.
- **if–else**: if–else 는 사실 이진 분기이고, else if 가 여러 개여도 중첩(nested)하면 전부 0과 1로 표현할 수 있다.
- **가계도는 왼쪽부터 그린다**: 큰아버지, 둘째 큰아버지, 아빠 순으로 왼쪽부터 그리듯 왼쪽 서브트리가 우선.

**학생과의 대화**
- 없음.

**강조 발언**
- "이진 트리는 무조건 자식의 개수가 2개 이하를 개런티(guarantee)해야 됩니다." (Part 02 앞)

🕳️ 미룬 유도: 서브트리 간 순서(왼쪽 우선)의 의미 — "어 이게 어떤 말인지는 뒤에서 봅시다." (Part 02 중간) → 완전 이진 트리 채우는 순서·순회(S7 p7, p9)에서 이어짐.

## 4. 이진 트리의 성질: 간선 수, 노드 수, 높이 (Part 02 중간–끝, Part 03 앞)

**핵심 내용** (S7 p5–p6)
- **간선 수**: 노드가 $n$개이면 간선(edge)은 $n-1$개.
  - 추적: 그림의 노드 7개 → 간선 6개, $7-1=6$.
  - 노드 하나를 연결 없이 빼 두면 그건 더 이상 그 트리의 노드가 아니다(나무가 공중에 떠 있을 수 없다).
- **높이 $h$ 인 이진 트리의 노드 수**: 최소 $h$개, 최대 $2^h-1$개.
  - 최소 $h$개: 레벨마다 노드가 하나뿐인 "삐쩍 마른" 트리 = **경사 트리(skewed tree)**. 노드 3개가 레벨 1·2·3 에 하나씩. 스택·큐 같은 선형처럼 보이지만 오른쪽 서브트리가 공백일 뿐 자식 2개 이하라 이진 트리다.
  - 최대 $2^h-1$개: 레벨마다 꽉 찬 트리. 레벨 $i$ 의 노드 수는 $2^{i-1}$(1, 2, 4, 8, …)이고, 합하면
    $$\sum_{i=1}^{h} 2^{i-1} = 2^h - 1$$
    예: 높이 3 → 노드 7개.
- **노드 $n$개인 이진 트리의 높이**: 최대 $n$(경사 트리), 최소는 아래 식 (S7 p6).
  $$n = 2^h - 1 \;\Rightarrow\; 2^h = n+1 \;\Rightarrow\; h = \lceil \log_2(n+1) \rceil$$
  (슬라이드 표기: `h =upper_bound { log2 (n + 1) }`). 교수님: 양변에 로그를 씌워 $h$ 를 왼편에 두고 upper bound 값을 만든다.
- 높이가 알고리즘 퍼포먼스를 좌지우지하므로 **높이를 낮게 만드는 것이 핵심**. 노드 7개로 트리를 만들어야 한다면 경사 트리보다 꽉 찬 트리로 만드는 게 중요하다. [슬라이드 외 강조; 근거인 $O(h)$ 는 S7 p25 에서 나올 예정]

**비유와 일화**
- **못생긴 트리 vs 예쁜 트리**: 경사 트리는 "기껏 만들었는데 경사가 져 있어서 알고리즘 퍼포먼스에 도움이 안 되는" 못생긴 트리. 꽉 찬 트리는 **아름드리나무**처럼 풍성해서 예쁜 트리.
- 자료구조를 쓰는 이유: "누구는 100분이 걸리는 걸 나는 10분 만에 끝내려고" 좋은 알고리즘을 만들기 위해서.

**학생과의 대화**
- 없음. "아니, 뭐 하나 빼면 안 돼요?", "어 이거 이게 뭔 트리예요? 스택이나 큐 같은데" 등은 교수님 자문자답.

**강조 발언**
- "여러분들한테 어 어떤 트리 구조가 주어졌을 때 내가 노드의 개수가 7개인데 어떤 트리 구조를 만들어야 된다라고 하면 얘보다는 요렇게 만드는 게 굉장히 중요합니다." (Part 02 끝)
- "나무의 높이가 너무 중요해요. 이게 알고리즘의 퍼포먼스를 좌지우지합니다. 그래서 높이를 어떻게든 낮게 만드는... 게 엄청 중요하거든요" (Part 02 끝 → Part 03 맨 앞)
- "upper bound 얘를 넘어가지 않도록 하는 h를 만드는 게 굉장히 중요합니다." (Part 03 앞)
- "트리에서 가장 중요한 터미놀로지가 뭐냐라고 한다면 높이입니다. 높이를 작게 만드는 게 엄청 중요해요." (Part 03 앞)

🕳️ 미룬 유도: 왜 성능을 높이로 재는가 — "어 왜 근데 높이로 하지? 그건 뒤에 설명을 하고" (Part 02 끝). "자 그래서 요게 왜 중요한지 이제 살펴볼 거예요." (Part 03 앞) → 이진 탐색 트리 분석 $O(h)$, 최선 $O(\log_2 n)$, 최악 $O(n)$ (S7 p25) 에서 다룰 내용.

## 5. 이진 트리의 분류: 포화·완전·기타 (Part 03 앞–중간)

**핵심 내용** (S7 p7)
- 경사 트리도 이진 트리다(못생겼을 뿐).
- **포화 이진 트리(full binary tree)**: 각 레벨에 노드가 꽉 차 있는 이진 트리. 같은 노드 수에서 높이가 가장 낮다. 더 채우려면 다음 레벨로 가야 하고 그 순간 full 이 아니게 된다.
- **완전 이진 트리(complete binary tree)**: 높이가 $h$ 일 때 레벨 1 ~ $h-1$ 은 꽉 차 있고, 마지막 레벨 $h$ 는 **왼쪽부터 오른쪽으로 순서대로** 채워진 이진 트리. 데이터 개수가 포화 개수로 딱 떨어지지 않으니 "full 로 가는 과정에 있는 트리"다.
  - 추적: G 까지 찬 상태에서 H 가 들어오면 왼쪽 자식부터 → 왼쪽 자식의 왼쪽 자식, 그다음 왼쪽 자식의 오른쪽 자식 순. … 그다음 K 는 **E 의 오른쪽 자식**으로 들어간다. (번호로 K=11, E=5, $11 = 2\cdot5+1$)
- **기타 이진 트리**: 자식이 2개 이하라 이진 트리는 맞지만 왼쪽부터 채우지 않은 트리. 트리에서 필요한 데이터를 꺼내 쓰면(노드가 없어지면) 중간 과정에서 이런 모양, 나아가 경사 트리도 생길 수 있다. 그래도 이진 트리를 쓰겠다면 이진 조건은 만족해야 한다. [슬라이드 외]
- 구현은 결국 **배열(array) 아니면 연결 리스트(linked list)**. "더는 없어요." (S7 p8 예고)

**비유와 일화**
- 없음(개념 설명 위주).

**학생과의 대화**
- 없음. "이거 왼쪽 자식부터 안 채웠어요? 네, 안 채우긴 했어요"는 자문자답.

**강조 발언**
- "우리는 역시 이거를 뭘로 구현하겠어요? 배열(array) 아니면 링크드 리스트(linked list)로 구현합니다. 더는 없어요, 항상 없어요." (Part 03 중간)

## 용어·코드 목록

**용어 (한국어 / 영어)**
- 트리 / tree, 계층적 구조, 포함 관계
- 노드 / node, 간선 / edge
- 루트 / root, 리프 노드 / leaf node, 브랜치 / branch
- 서브트리 / subtree, 재귀적 정의 / recursive
- 단말 노드 / terminal node (= 리프 노드), 비단말 노드 / non-terminal node
- 부모 / parent, 자식 / child, 형제 / sibling, 조상 노드, 자손 노드
- 레벨 / level, 높이 / height, 차수 / degree
- 이진 트리 / binary tree, 3진 트리 / ternary tree, 왼쪽 서브트리, 오른쪽 서브트리
- 경사 트리 / skewed tree (경사 이진 트리)
- 포화 이진 트리 / full binary tree
- 완전 이진 트리 / complete binary tree
- 기타 이진 트리
- 결정 트리 / decision tree, 가계도 / family tree, 파일 시스템
- upper bound
- 배열 / array, 연결 리스트 / linked list (구현 수단 예고)
- (비교용) 스택 `top`, 큐 `front`·`rear`

**식 (TeX)**
- 간선 수: $e = n - 1$
- 높이 $h$ 이진 트리의 노드 수: $h \le n \le 2^h - 1$
- 레벨 $i$ 의 최대 노드 수: $2^{i-1}$, $\sum_{i=1}^{h} 2^{i-1} = 2^h - 1$
- $n = 2^h - 1 \Rightarrow 2^h = n + 1 \Rightarrow h = \lceil \log_2(n+1) \rceil$ (슬라이드: `h =upper_bound { log2 (n + 1) }`)
- $n$ 노드 이진 트리 높이: 최대 $n$, 최소 $\lceil \log_2(n+1) \rceil$
- 예: 높이 3 → 최대 노드 7, 노드 7 → 간선 6

문제를 내 말로 읽어요

리스트 ADT의 연산 계약만으로 6단계 연산의 리스트 상태와 length를 추적하고 조회·삭제·교체 연산의 의미를 확인하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “리스트 ADT의 연산 계약과 순서”예요. 추상 자료형(ADT)에서 add는 기존 원소를 뒤로 밀며 length를 1 늘리고, delete는 원소를 지우고 뒤 원소를 당기며 length를 1 줄이고, replace는 해당 위치 값만 바꿔 length를 유지해요.

종이에 쓰는 첫 줄

초기 상태 L = [], length = 0을 적고 첫 연산 add_tail(A)부터 적용해요.

왜 이렇게 푸는지 함께 따라가요

(a) 공백 리스트에서 순서대로 실행하면 add_tail(A) → [A](length = 1), add_tail(B) → [A, B](2), add(2, C) → [A, B, C](3), add(1, D) → 위치 1의 B와 C가 뒤로 밀려 [A, D, B, C](4), delete(2) → 위치 2의 B가 삭제되어 [A, D, C](3), replace(1, E) → 위치 1의 D가 E로 바뀌어 [A, E, C](3)이 돼요.

(b) 최종 [A, E, C]에서 get_entry(1) = E, get_length() = 3이에요. 여기서 delete(0)을 한 번 더 실행하면 위치 0의 A가 삭제되면서 뒤의 E, C 2개 원소가 앞으로 한 칸씩 당겨져요. add는 원소를 끼워 넣어 length를 1 늘리지만, replace는 기존 위치 값만 교체하므로 length를 바꾸지 않아요.

완성 답과 검산

(a) 삽입 계열 연산(add_tail, add)이 4회, 삭제(delete)가 1회, 교체(replace)가 1회이므로 최종 길이는 0 + 4 - 1 = 3이고 원소는 [A, E, C]로 일치해요.

(b) 길이 3인 리스트 [A, E, C]에서 인덱스 0을 지우면 남은 3 - 0 - 1 = 2개 원소(E, C)가 앞으로 이동함을 확인할 수 있어요.

이 문제에서 조심할 점

add(1, D)를 기존 B를 없애는 대치로 읽지 않아요. 원소가 같아도 순서가 다르면 같은 리스트가 아니에요.

설명을 닫고 다시 해 봐요

  1. 6개 연산을 순서대로 적용하며 매 단계 리스트와 length를 적어요.
  2. 최종 리스트에서 get_entry(1), get_length()와 delete(0)의 이동 원소 수를 구해요.
  3. add와 replace가 length에 미치는 차이를 비교해요.

떠올릴 개념·공식

리스트 ADT에서 add는 끼워 넣기(length + 1), delete는 당기기(length - 1), replace는 제자리 값 교체(length 유지)예요.

첫 줄

초기 상태 L = [], length = 0을 적고 첫 연산 add_tail(A)부터 적용해요.

핵심 답

(a) [A](1) → [A, B](2) → [A, B, C](3) → [A, D, B, C](4) → [A, D, C](3) → [A, E, C](3) (b) get_entry(1) = E, get_length() = 3, delete(0) 시 2개 이동, add는 길이 1 증가·replace는 길이 유지

문제를 내 말로 읽어요

배열에 이전 값이 남아 있을 때 init(&L) 직후와 포화 상태에서 상태 검사·조회 결과를 구하고, 구조체 포인터 &L을 전달하는 이유를 묻는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “초기화와 논리적 길이”예요. 배열 리스트의 유효 원소 범위는 0 .. L->length - 1이므로 L->length = 0만 대입하면 이전 배열 값과 무관하게 공백 리스트가 돼요.

종이에 쓰는 첫 줄

init(&L) 직후 L.length = 0이므로 유효 인덱스 범위는 비어 있어요.

왜 이렇게 푸는지 함께 따라가요

(a) init(&L) 직후 L.length = 0이므로 is_empty(&L) = 1, is_full(&L) = 0이고 논리적 리스트는 []예요. 원소 3개를 채워 L.length == 3(MAX_LIST_SIZE)이 되면 is_empty(&L) = 0, is_full(&L) = 1이며, 유효 인덱스가 0..2이므로 get_entry(&L, 2)는 L.list[2]를 반환하고 get_entry(&L, 3)은 pos >= L->length여서 위치 오류가 나요.

(b) 모든 연산이 유효 원소를 0 .. L->length - 1 범위로만 다루므로 길이 밖의 이전 값 {7, 8, 9}는 읽히지 않아 0으로 지울 필요가 없어요. 또한 C는 인자를 값으로 전달하므로 구조체 주소(&L)를 넘겨야 함수가 호출자의 원본 구조체 L을 직접 수정할 수 있고 구조체 전체 복사 비용도 아낄 수 있어요.

완성 답과 검산

(a) MAX_LIST_SIZE = 3에 대해 length = 0이면 0 == 0(참 1), 0 == 3(거짓 0)이고, length = 3이면 3 == 0(거짓 0), 3 == 3(참 1)이며 인덱스 3은 pos < length를 위반해요.

(b) 값 전달(ArrayListType L)로 init(L)을 호출하면 복사본의 length만 0이 되고 main의 원본 L.length는 바뀌지 않음을 확인할 수 있어요.

이 문제에서 조심할 점

배열에 이전 값이 남아 있다는 이유로 리스트가 비어 있지 않다고 판단하지 않아요.

설명을 닫고 다시 해 봐요

  1. length = 0과 length = 3일 때 is_empty, is_full 반환값을 각각 적어요.
  2. length = 3에서 get_entry(&L, 2)와 get_entry(&L, 3)의 차이를 확인해요.
  3. 배열을 0으로 지우지 않는 이유와 &L 포인터 전달 이유를 한 문장씩 정리해요.

떠올릴 개념·공식

유효 원소는 0 .. length - 1로만 정의되며, 원본 구조체 수정과 복사 비용 절감을 위해 ArrayListType *L(&L)을 전달해요.

첫 줄

init(&L) 직후 L.length = 0이므로 유효 인덱스 범위는 비어 있어요.

핵심 답

(a) 직후 length = 0, is_empty = 1, is_full = 0, []; length == 3일 때 is_empty = 0, is_full = 1, get_entry(&L, 2) 정상 반환, get_entry(&L, 3) 위치 오류 (b) 0..length-1만 유효하므로 0 초기화 불필요, 원본 수정·복사 절감을 위해 &L 전달

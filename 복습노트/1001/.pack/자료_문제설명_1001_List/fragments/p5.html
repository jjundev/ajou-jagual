문제를 내 말로 읽어요

메모리 주소와 link가 주어진 단순 연결 리스트에서 방문 순서를 읽고, 특정 노드 뒤 삽입과 노드 삭제 시 바꿔야 할 링크를 구하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “주소로 읽는 연결 리스트의 순서”예요. 연결 표현에서 논리적 순서는 물리 주소의 크기가 아니라 head부터 따라가는 link가 결정하며, 선행 노드 p를 알 때 삽입·삭제 링크 변경은 $O(1)$이에요.

종이에 쓰는 첫 줄

head = 300에서 시작해 300 → 100 → 400 → 200 → NULL 순서로 화살표를 따라가요.

왜 이렇게 푸는지 함께 따라가요

(a) head = 300부터 각 노드의 link를 따라가면 (300, 10) → (100, 20) → (400, 30) → (200, 40) 순서로 방문하고 200의 link = NULL에서 끝나요. 연결 표현은 연속된 메모리 배치나 고정 용량 제약이 없고 선행 노드를 알 때 원소 이동 없이 $O(1)$에 삽입·삭제할 수 있는 장점이 있지만, link 저장 공간이 추가로 들고 $k$번째 위치를 찾으려면 head부터 순차 탐색해야 해 $O(n)$이 걸리는 단점이 있어요.

(b) p(주소 100) 뒤에 주소 500(data = 25)인 new_node를 넣으려면, 기존 p->link(400)를 잃지 않도록 먼저 new_node->link = p->link(주소 500의 link = 400)를 연결한 뒤 p->link = new_node(주소 100의 link = 500)로 바꿔요. 초기 상태에서 노드 400을 삭제할 때는 선행 노드 p(주소 100)의 link를 삭제 노드의 다음 주소인 200으로 바꿔요(p->link = 200).

완성 답과 검산

(a) 주소 크기순(100, 200, 300, 400)이 아니라 link 체인(300 → 100 → 400 → 200)을 따라 읽으면 데이터 10 → 20 → 30 → 40이 빠짐없이 한 번씩 방문돼요.

(b) 삽입 후 체인은 300 → 100 → 500 → 400 → 200 → NULL이 되고, 초기 상태에서 노드 400 삭제 후 체인은 300 → 100 → 200 → NULL이 되어 뒷부분 노드가 끊기지 않아요.

이 문제에서 조심할 점

삽입 시 p->link = new_node를 먼저 실행하면 원래 p->link(주소 400)가 덮어써져 뒷부분 체인을 잃어버려요.

설명을 닫고 다시 해 봐요

  1. head = 300부터 NULL까지 방문하는 (주소, data) 쌍을 순서대로 적어요.
  2. 배열 리스트와 연결 표현의 공간·탐색·삽입·삭제 특성을 비교해요.
  3. p = 100 뒤 500 삽입과 노드 400 삭제에서 바꿀 link 대입식을 적어요.

떠올릴 개념·공식

연결 리스트는 head에서 link를 따라 순서를 읽으며, 삽입은 new_node->link = p->link 후 p->link = new_node 순서로 연결해요.

첫 줄

head = 300에서 시작해 300 → 100 → 400 → 200 → NULL 순서로 화살표를 따라가요.

핵심 답

(a) (300, 10) → (100, 20) → (400, 30) → (200, 40), 선행 노드 알 때 삽입·삭제 $O(1)$이나 추가 링크 공간 및 탐색 $O(n)$ 소요 (b) 삽입: 500의 link = 400 후 100의 link = 500; 삭제: 100의 link = 200

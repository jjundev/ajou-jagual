문제를 내 말로 읽어요

배열 리스트 {10, 20, 30, 40}에서 인덱스 1의 원소를 꺼내고 뒤 원소들을 앞으로 당기는 과정을 추적하며 삽입과 복사 방향이 반대인 이유를 확인하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “배열 리스트 삭제의 경계와 반환”이에요. 삭제할 원소 L->list[position]을 먼저 item에 보관한 뒤, i = position부터 length - 2까지 앞에서 뒤로(i++) 한 칸씩 당겨요.

종이에 적을 첫 줄

item = L->list[1] = 20을 먼저 보관하고 i = 1부터 복사를 시작해요.

왜 이렇게 푸는지 함께 따라가요

(a) 먼저 삭제 대상 item = L->list[1] = 20을 보관해요. 그다음 i = 1, 2에서 L->list[1] = L->list[2](30), L->list[2] = L->list[3](40)을 복사하고 L->length를 3으로 줄여 20을 반환해요. 최종 유효 원소는 L.list[0..2] = {10, 30, 40}, length = 3이에요.

(b) add는 원소를 오른쪽으로 밀어야 하므로 아직 읽지 않은 뒤 원소를 덮어쓰지 않으려 뒤에서 앞으로(i--) 복사하고, delete는 item을 따로 보관해 비워진 앞자리(position)부터 차례로 채우므로 앞에서 뒤로(i++) 복사해요. 삭제는 실제 원소가 있는 0 .. length - 1만 가능하므로 position == length는 불가능하며, 이동 횟수는 n - k - 1회로 맨 끝 삭제는 $O(1)$, 맨 앞 삭제는 $O(n)$이에요.

완성 답과 검산

(a) n = 4, k = 1에서 이동 횟수는 4 - 1 - 1 = 2회(30, 40)이고, length = 3이므로 인덱스 0..2의 {10, 30, 40}만 유효 원소로 남아요.

(b) 맨 끝 원소 삭제(k = n - 1)를 n - k - 1에 대입하면 0회($O(1)$), 맨 앞 원소 삭제(k = 0)를 대입하면 n - 1회($O(n)$)가 되어 복잡도와 일치해요.

이 문제에서 조심할 점

삽입에서 허용된 position == length를 삭제에도 허용하면 유효 범위 밖 원소를 읽게 돼요.

설명을 닫고 다시 해 봐요

  1. item 보관 후 i = 1, 2에서 L->list[i] = L->list[i+1] 결과를 적어요.
  2. add(i--)와 delete(i++)의 복사 방향이 반대인 이유를 비교해요.
  3. 삭제 유효 범위 0 .. length - 1과 이동 횟수 n - k - 1을 확인해요.

첫 줄

item = L->list[1] = 20을 먼저 보관하고 i = 1부터 복사를 시작해요.

떠올릴 개념·공식

삭제는 item을 보관한 뒤 i = position .. length - 2를 순방향(i++)으로 당기며 이동 횟수는 n - k - 1회예요.

검산

(a) 반환값 20, list[0..2] = {10, 30, 40}, length = 3 (b) add는 i--, delete는 i++, 이동 횟수 n - k - 1회(최선 $O(1)$, 최악 $O(n)$)

조건·구분과 확인

  • 삭제 유효 위치는 0..length-1이라 position==length는 허용되지 않아요. 삽입의 끝 경계와 구별해요.

### P1. 배열 리스트 삽입의 이동 방향

**강의 예제 기반 자체 출제** S4 p11

용량은 충분하고 list={10,20,30,40}, length=4예요. add(L,1,99)의 배열 이동 순서와 최종 유효 원소·length를 쓰세요. 반복 방향을 앞에서 뒤로 바꾸면 왜 원소가 손실되는지, 맨 끝 삽입의 position 범위도 설명하세요. 길이 n에서 position=k일 때 이동 횟수와 최선·최악 시간복잡도도 구하세요.

```c
void add(ArrayListType *L, int position, element item)
{
    if(!is_full(L) && position>=0 && position<=L->length) {
        int i;
        for(i=L->length-1;i>=position;i--)
            L->list[i+1]=L->list[i];
        L->list[position]=item;
        L->length++;
    }
}
```

4. 삽입 위치는 0부터 length까지예요. length 자리에 추가할 때는 기존 원소 이동이 없어요.
5. 반복 인덱스의 처음과 끝을 세면 이동 횟수가 나와요. 위치가 끝이면 이동이 없고 처음이면 길이에 비례해요.

**정답:** 40을 4번,30을 3번,20을 2번 위치로 이동. 결과 {10,99,20,30,40}, length=5. 앞에서 뒤로 복사하면 아직 읽지 않은 원소를 덮어쓴다. 맨 끝 삽입 position=length도 유효하다. 이동 횟수 n-k, 맨 끝 삽입은 O(1), 맨 앞 삽입은 O(n).

length를 먼저 늘린 뒤 이동 범위를 잡거나 position&lt;length로만 검사하면 경계 처리가 달라져요.

### P2. 배열 리스트 삭제의 경계와 반환

**강의 예제 기반 자체 출제** S4 p12

error는 실행을 종료해요. list={10,20,30,40}, length=4에서 delete(L,1)의 반환값·복사 순서·유효 원소를 쓰세요. 삭제 뒤 배열의 마지막 칸을 0으로 만들지 않아도 되는 이유와 position=length가 불가능한 이유도 설명하세요. 길이 n에서 position=k일 때 이동 횟수와 최선·최악 시간복잡도도 구하세요.

```c
element delete(ArrayListType *L, int position)
{
    int i; element item;
    if(position<0 || position>=L->length) error("위치오류");
    item=L->list[position];
    for(i=position;i<L->length-1;i++)
        L->list[i]=L->list[i+1];
    L->length--;
    return item;
}
```

### P3. 리스트 ADT의 연산 계약과 순서

**강의 예제 기반 자체 출제** S4 p5 · 추가 근거 p2,3,4,6

리스트 ADT의 연산은 다음과 같아요. 위치는 0부터 셉니다. add_tail(x)는 리스트 끝에 x를 추가해요. add(pos,x)는 0≤pos≤길이인 pos 위치에 x를 넣고 원래 그 위치부터 있던 항목을 한 칸씩 뒤로 밀어요(pos가 길이와 같으면 끝에 추가돼요). delete(pos)는 pos 위치의 항목을 지우고 뒤 항목을 한 칸씩 당겨요. replace(pos,x)는 pos 위치의 항목을 x로 바꿔요. get_entry(pos)는 pos 위치의 항목을, get_length()는 항목 수를 돌려줘요.

빈 리스트에 add_tail(A), add_tail(B), add(2,C), add(1,D), delete(2), replace(1,E)를 차례로 적용하세요. 각 단계의 리스트와 길이, 마지막 get_entry(1)과 get_length()의 값을 쓰세요. add와 replace가 길이에 미치는 차이, \[A,E,C\]와 \[E,A,C\]가 서로 다른 리스트인 이유, 이 결과를 구하는 데 배열·연결 구현을 알아야 하는지도 설명하세요.

</details>

<details><summary>힌트 보기</summary>

초기 상태: L=\[\], 길이=0.

</details>

<details><summary>풀이 보기</summary>

1. 처음 상태를 빈 리스트와 길이 0으로 적어요.
2. 끝 추가 두 번 뒤 \[A,B\]가 돼요. 위치2에 C를 넣으면 \[A,B,C\]예요.
3. 위치1 삽입은 B를 덮지 않으므로 \[A,D,B,C\], 길이 4예요.
4. 위치2의 B를 삭제해 \[A,D,C\], 위치1만 E로 바꿔 \[A,E,C\]예요.
5. 객체는 순서 있는 모임, 연산은 그 객체를 바꾸거나 조회하는 계약이므로 저장 구현 없이 판단해요.

**정답:** \[A\](1), \[A,B\](2), \[A,B,C\](3), \[A,D,B,C\](4), \[A,D,C\](3), \[A,E,C\](3). get_entry(1)=E, get_length()=3. add는 기존 항목을 보존하며 길이를 1 늘리고 replace는 값만 바꿔 길이를 유지합니다. 위치별 순서가 다르면 다른 리스트이며 ADT 계약만으로 결과를 정할 수 있습니다.

add(1,D)를 기존 B를 없애는 대치로 읽지 않아요. 원소가 같아도 순서가 다르면 같은 리스트가 아니에요.

</details>

### P4. 초기화와 논리적 길이

**강의 예제 기반 자체 출제** S4 p9 · 추가 근거 p10

MAX_LIST_SIZE=3이며 배열 세 칸에 이전 값 {7,8,9}가 남아 있어요. 아래 init을 호출한 직후 length, is_empty, is_full의 반환값과 논리적인 리스트를 쓰세요. 모든 칸을 0으로 지우지 않아도 되는 이유를 설명하고, 별도로 length=3인 유효 상태에서 is_empty와 is_full도 구하세요.

```c
void init(ArrayListType *L)
{
    L->length = 0;
}
int is_empty(ArrayListType *L)
{
    return L->length == 0;
}
int is_full(ArrayListType *L)
{
    return L->length == MAX_LIST_SIZE;
}
```

### P5. 주소로 읽는 연결 리스트의 순서

**강의 예제 기반 자체 출제** S4 p18 · 추가 근거 p7,8,13,14,15,16,17

노드 A는 주소300에 data=10,link=100, B는 주소100에 data=20,link=500, C는 주소500에 data=30,link=NULL을 저장하고 head=300이에요(주소는 설명용 표식이며 실제 C 주소가 아닙니다). 논리적 원소 순서와 마지막 링크를 쓰고, head·data·link의 역할을 구별하세요. 원형 리스트라면 C의 link가 무엇인지, 이중 연결 리스트라면 어떤 링크가 추가되는지도 쓰세요. 배열과 달리 물리적 주소순 정렬이나 연속 배치가 필요 없는 이유와, 선행 노드 위치를 이미 알 때 연결 삽입 비용과 그 위치를 처음부터 찾는 비용을 구분하세요. 마지막으로 별도 임시 포인터 없이 N.link=A.link와 A.link=N 두 대입만 사용해 A→C→NULL 사이에 독립된 새 노드 N을 넣을 때, N의 link와 A의 link 중 어느 것을 먼저 연결해야 하는지 쓰고 순서를 뒤집었을 때 C로 가는 길이 어떻게 되는지 설명하세요(두 링크 대입의 순서만 묻습니다). 배열의 고정 용량과 연결 노드의 동적 증가를 비교하고, 연결 리스트도 메모리 할당 실패로 더 늘릴 수 없는 경우가 있는지 설명하세요.

head=300 → A(data10) → link100.

<details><summary>풀이 보기</summary>

1. head의 300에서 A를 읽고 link 100으로 B, link 500으로 C를 찾아가요.
2. 주소를 오름차순으로 정렬하는 것이 아니라 link 값을 따라 순서를 읽어요.
3. 단순 리스트는 마지막 link가 NULL이고 원형은 첫 노드의 주소 300을 저장해요.
4. 헤드 포인터는 노드 전체가 아니라 시작 주소를 담는 변수예요. 이중 연결은 앞뒤 링크를 두어요.
5. 알고 있는 위치에서 연결을 바꾸는 일과 그 위치까지 이동하는 일을 나누어 비용을 말해요.
6. A와 C 사이에 넣을 때는 먼저 N이 C를 가리키게 한 다음 A가 N을 가리키게 해요. 반대로 바꾸면 기존 A.link의 C 주소가 사라져 N의 링크를 채울 근거를 잃어요.

**정답:** 논리 순서는10→20→30이며 마지막 link=NULL입니다. head는 첫 노드의 주소를 담는 별도 포인터, data는 값,link는 다음 노드 주소입니다. 첫 노드를 head로 두는 원형 구조에서 C.link=300입니다. 이중 연결은 선행 노드 링크가 추가됩니다. 연결은 주소를 따라가므로 주소의 크기·연속성은 순서를 결정하지 않습니다. 유효 선행 노드를 알면 링크 변경 O(1), 일반적인 위치 탐색은 최악 O(n)입니다. 삽입은 N.link를 기존 A.link(C)에 먼저 연결한 뒤 A.link를 N으로 바꿉니다. 반대 순서 뒤 N.link=A.link를 적용하면 N이 자신을 가리키고 C로 가는 기존 연결을 잃습니다. 고정 배열은 정해진 용량에 제한되며 연결 노드는 필요할 때 할당해 늘릴 수 있지만, 사용 가능한 메모리와 할당 성공에 제한돼요.

마지막 data가 NULL이라고 쓰지 않아요. NULL인 것은 link예요. 탐색까지 포함한 임의 위치 삽입을 항상 O(1)이라 하지 않아요.

</details>

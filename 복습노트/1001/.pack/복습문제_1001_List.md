### P1. 배열 리스트 삽입의 이동 방향

**강의 예제 기반 자체 출제** S4 p11

배열 용량은 충분하고 초기 상태는 `L.list = {10, 20, 30, 40}`, `L.length = 4`예요.

```c
void add(ArrayListType *L, int position, element item)
{
    if(!is_full(L) && position>=0 && position<=L->length) {
        int i;
        for(i=L->length-1;i>=position;i--)
            L->list[i+1]=L->list[i];
        L->list[position]=item;
        L->length++;
    }
}
```

- (a) `add(&L, 1, 25)`를 실행할 때 루프 변수 `i`의 변화 순서와 원소 이동 대입식(`L->list[i+1] = L->list[i]`), 실행 후 유효 원소 `L.list[0..4]`와 `L.length`를 쓰세요. 또한 반복 방향을 앞에서 뒤(`i++`)로 바꾸면 왜 원소가 손실되는지 설명하세요.
- (b) 길이 `n`인 배열 리스트의 `position = k`(`0 <= k <= n`)에 삽입할 때 원소 이동 횟수를 쓰고, 최선(맨 끝 삽입, `position = n`)과 최악(맨 앞 삽입, `position = 0`)의 이동 횟수 및 시간 복잡도를 구하세요.

<details><summary>강의 예제 보기</summary>

S4 p11 · Software_4_List.pdf. 강의 코드의 해당 연산을 발췌해 들여쓰기를 정리했습니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

```c
void add(ArrayListType *L, int position, element item)
{
    if(!is_full(L) && position>=0 && position<=L->length) {
        int i;
        for(i=L->length-1;i>=position;i--)
            L->list[i+1]=L->list[i];
        L->list[position]=item;
        L->length++;
    }
}
```

</details>

<details><summary>힌트 보기</summary>

삽입 위치 `1`부터 기존 마지막 인덱스 `3`까지 세 원소를 뒤에서 앞으로(`i = 3, 2, 1`) 한 칸씩 오른쪽으로 옮겨야 덮어쓰기가 발생하지 않아요.

</details>

<details><summary>풀이 보기</summary>

- (a) `i = 3, 2, 1` 순서로 `L->list[4] = L->list[3]`(`40`), `L->list[3] = L->list[2]`(`30`), `L->list[2] = L->list[1]`(`20`)을 실행한 뒤 `L->list[1] = 25`를 대입하고 `L->length`를 `5`로 늘려요. 최종 유효 원소는 `{10, 25, 20, 30, 40}`, `length = 5`예요. 만약 `i = 1`부터 앞으로 복사하면 아직 읽지 않은 `list[2]`(`30`)가 `20`으로 덮어써져 원래 원소가 손실돼요.
- (b) 인덱스 `k`부터 `n - 1`까지 옮기므로 이동 횟수는 `n - k`회예요. 맨 끝 삽입(`position = n`)은 이동 횟수 `0`회로 최선 $O(1)$이고, 맨 앞 삽입(`position = 0`)은 `n`개 원소를 모두 옮기므로 이동 횟수 `n`회로 최악 $O(n)$이에요.

**정답:** (a) `i = 3, 2, 1` 순으로 `list[4]=40, list[3]=30, list[2]=20` 이동 후 `list[1]=25` 저장, 최종 `list[0..4] = {10, 25, 20, 30, 40}`, `length = 5` (앞에서 뒤로 복사하면 아직 읽지 않은 원소를 덮어쓴다) (b) 이동 횟수 `n - k`회, 최선(맨 끝 삽입, `position = n`) `0`회로 $O(1)$, 최악(맨 앞 삽입, `position = 0`) `n`회로 $O(n)$

`length`를 먼저 늘린 뒤 이동 범위를 잡거나 `position < length`로만 검사하면 맨 끝 삽입 경계가 달라져요.

</details>

### P2. 배열 리스트 삭제의 경계와 반환

**강의 예제 기반 자체 출제** S4 p12

`error`는 실행을 즉시 종료해요. 초기 상태는 `L.list = {10, 20, 30, 40}`, `L.length = 4`예요.

```c
element delete(ArrayListType *L, int position)
{
    int i; element item;
    if(position<0 || position>=L->length) error("위치오류");
    item=L->list[position];
    for(i=position;i<L->length-1;i++)
        L->list[i]=L->list[i+1];
    L->length--;
    return item;
}
```

- (a) `delete(&L, 1)`을 실행할 때 반환값 `item`, 루프 변수 `i`의 이동 대입식(`L->list[i] = L->list[i+1]`), 실행 후 유효 원소 `L.list[0..2]`와 `L.length`를 쓰세요.
- (b) 삽입(`add`)은 뒤에서 앞으로(`i--`), 삭제(`delete`)는 앞에서 뒤로(`i++`) 복사 방향이 반대인 이유와, 삭제에서 `position == L->length`가 불가능한 이유 및 최선·최악 시간 복잡도를 설명하세요.

<details><summary>강의 예제 보기</summary>

S4 p12 · Software_4_List.pdf. 강의 코드의 해당 연산을 발췌해 들여쓰기를 정리했습니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

```c
element delete(ArrayListType *L, int position)
{
    int i; element item;
    if(position<0 || position>=L->length) error("위치오류");
    item=L->list[position];
    for(i=position;i<L->length-1;i++)
        L->list[i]=L->list[i+1];
    L->length--;
    return item;
}
```

</details>

<details><summary>힌트 보기</summary>

이동 전에 삭제 대상 `L->list[1] = 20`을 `item`에 먼저 보관한 뒤, 빈자리 `position`부터 앞에서 뒤로(`i++`) 당겨 와요.

</details>

<details><summary>풀이 보기</summary>

- (a) 먼저 `item = L->list[1] = 20`을 보관해요. 이어서 `i = 1, 2` 순서로 `L->list[1] = L->list[2]`(`30`), `L->list[2] = L->list[3]`(`40`)을 복사하고 `L->length`를 `3`으로 줄인 뒤 `20`을 반환해요. 유효 원소는 `L.list[0..2] = {10, 30, 40}`이에요(인덱스 `3`은 논리적 길이 밖이므로 `0`으로 지울 필요가 없어요).
- (b) `add`는 오른쪽으로 밀어야 하므로 뒤에서부터(`i--`) 복사해야 아직 읽지 않은 원소를 덮어쓰지 않고, `delete`는 이미 `item`에 보관한 삭제 위치(왼쪽 빈자리)부터 차례로 채워야 하므로 앞에서 뒤로(`i++`) 복사해요. 또한 삭제는 실제 원소가 들어 있는 `0 .. length - 1`만 유효하므로 `position == length`는 삭제할 원소가 없어 불가능하며, 길이 `n`에서 `position = k` 삭제의 이동 횟수는 `n - k - 1`회로 맨 끝 삭제는 $O(1)$, 맨 앞 삭제는 $O(n)$이에요.

**정답:** (a) 반환값 `item = 20`, `i = 1, 2`에서 `list[1]=30, list[2]=40` 복사, 최종 유효 원소 `list[0..2] = {10, 30, 40}`, `length = 3` (b) `add`는 오른쪽으로 밀 때 뒤 원소 덮어쓰기를 막으려 `i--`로 복사하고, `delete`는 보관 후 비워진 앞자리부터 채우려 `i++`로 복사한다. 삭제 유효 범위는 `0..length-1`뿐이며 이동 횟수는 `n - k - 1`회(최선 맨 끝 삭제 $O(1)$, 최악 맨 앞 삭제 $O(n)$)이다.

삽입에서 허용된 `position == length`를 삭제에도 허용하면 유효 범위 밖 원소를 읽게 돼요.

</details>

### P3. 리스트 ADT의 연산 계약과 순서

**강의 예제 기반 자체 출제** S4 p5

위치를 `0`부터 세는 리스트 ADT의 연산 계약이 아래와 같고, 초기 리스트는 공백(`[]`, `length = 0`)이에요.

```c
add_tail(x)    : 리스트 맨 끝에 x 추가 (length 1 증가)
add(pos, x)    : 0 <= pos <= length 위치에 x 삽입, 기존 원소는 뒤로 한 칸 이동 (length 1 증가)
delete(pos)    : pos 위치 원소를 삭제하고 뒤 원소를 앞으로 한 칸 이동 (length 1 감소)
replace(pos, x): pos 위치 원소 값을 x로 교체 (length 유지)
get_entry(pos) : pos 위치 원소 반환 / get_length() : 현재 원소 수(length) 반환
```

- (a) 빈 리스트에 `add_tail(A)`, `add_tail(B)`, `add(2, C)`, `add(1, D)`, `delete(2)`, `replace(1, E)`를 순서대로 실행할 때 각 단계 직후의 리스트 상태와 `length`를 쓰세요.
- (b) 최종 상태에서 `get_entry(1)`과 `get_length()`의 반환값을 쓰고, 여기서 `delete(0)`을 한 번 더 실행할 때 앞으로 당겨지는 원소 개수 및 `add`와 `replace`가 `length`에 미치는 차이를 설명하세요.

<details><summary>강의 예제 보기</summary>

S4 p5 · 추가 근거 p2,3,4,6 · Software_4_List.pdf. 강의 개념·그림을 근거로 질문을 직접 작성했습니다. 강의 원문 코드의 전사가 아닙니다. 질문·입력 조건·검산은 자체 작성했어요.

</details>

<details><summary>힌트 보기</summary>

초기 상태는 `L = []`, `length = 0`이며 `add(1, D)`는 위치 `1`의 `B`를 지우지 않고 한 칸 뒤로 밀어요.

</details>

<details><summary>풀이 보기</summary>

- (a) 초기 `[]`(`length = 0`)에서 차례로 실행하면 `add_tail(A)` → `[A]`(`1`), `add_tail(B)` → `[A, B]`(`2`), `add(2, C)` → `[A, B, C]`(`3`), `add(1, D)` → `[A, D, B, C]`(`4`), `delete(2)` → `[A, D, C]`(`3`), `replace(1, E)` → `[A, E, C]`(`3`)이 돼요.
- (b) 최종 리스트 `[A, E, C]`에서 `get_entry(1) = E`, `get_length() = 3`이에요. 여기서 `delete(0)`을 추가 실행하면 맨 앞 `A`가 지워지고 뒤의 `E, C` `2`개 원소가 앞으로 한 칸씩 당겨져요. `add`는 기존 원소를 밀어내며 `length`를 `1` 늘리고, `replace`는 해당 위치 값만 덮어써 `length`를 그대로 유지해요.

**정답:** (a) `[A]`(`1`) → `[A, B]`(`2`) → `[A, B, C]`(`3`) → `[A, D, B, C]`(`4`) → `[A, D, C]`(`3`) → `[A, E, C]`(`3`) (b) `get_entry(1) = E`, `get_length() = 3`, `delete(0)` 추가 실행 시 앞으로 당겨지는 원소는 `2`개(`E, C`)이며, `add`는 `length`를 `1` 늘리고 `replace`는 값만 교체해 `length`를 유지한다.

`add(1, D)`를 기존 `B`를 없애는 대치로 읽지 않아요. 원소가 같아도 순서가 다르면 같은 리스트가 아니에요.

</details>

### P4. 초기화와 논리적 길이

**강의 예제 기반 자체 출제** S4 p9

`MAX_LIST_SIZE = 3`인 배열 리스트 `L`의 배열 세 칸에 이전 값 `{7, 8, 9}`가 남아 있고, 조회 연산 `get_entry(L, pos)`는 `pos < 0 || pos >= L->length`일 때 위치 오류를 내요.

```c
void init(ArrayListType *L)
{
    L->length = 0;
}
int is_empty(ArrayListType *L)
{
    return L->length == 0;
}
int is_full(ArrayListType *L)
{
    return L->length == MAX_LIST_SIZE;
}
```

- (a) `init(&L)` 호출 직후 `L.length`, `is_empty(&L)`, `is_full(&L)`의 값과 논리적 리스트 상태를 쓰고, 원소 3개를 채워 `L.length == 3`이 된 상태에서 `is_empty(&L)`, `is_full(&L)` 반환값 및 `get_entry(&L, 2)`·`get_entry(&L, 3)` 호출 결과를 쓰세요.
- (b) `init`에서 배열 칸을 일일이 `0`으로 지우지 않아도 되는 이유와, `main`에서 구조체 값(`ArrayListType L`)이 아닌 주소(`&L`)를 넘기는 이유를 설명하세요.

<details><summary>강의 예제 보기</summary>

S4 p9 · 추가 근거 p10 · Software_4_List.pdf. 강의 예제의 해당 코드를 발췌했습니다. 질문과 입력 조건은 자체 출제이며 주변 선언·입출력은 생략했습니다. 질문·입력 조건·검산은 자체 작성했어요.

```c
void init(ArrayListType *L)
{
    L->length = 0;
}
int is_empty(ArrayListType *L)
{
    return L->length == 0;
}
int is_full(ArrayListType *L)
{
    return L->length == MAX_LIST_SIZE;
}
```

</details>

<details><summary>힌트 보기</summary>

`init(&L)` 직후 `L.length = 0`이므로 유효 인덱스(`0 .. length - 1`)는 하나도 없어요.

</details>

<details><summary>풀이 보기</summary>

- (a) `init(&L)` 직후 `L.length = 0`, `is_empty(&L) = 1`, `is_full(&L) = 0`이고 유효 인덱스가 없으므로 논리적 리스트는 `[]`예요. `L.length == 3`일 때는 `is_empty(&L) = 0`, `is_full(&L) = 1`이며, 유효 인덱스 범위가 `0..2`이므로 `get_entry(&L, 2)`는 `L.list[2]`를 반환하고 `get_entry(&L, 3)`은 위치 오류가 발생해요.
- (b) 논리적 리스트의 유효 원소 범위는 `0`부터 `L->length - 1`까지로만 판단하므로 범위 밖의 이전 값 `{7, 8, 9}`는 원소로 읽히지 않아 `0`으로 지울 필요가 없어요. 또한 C 함수는 인자를 값으로 복사해 전달하므로 구조체 주소(`&L`)를 넘겨야 함수 안에서 원본 구조체 `L`의 `length`나 `list`를 직접 수정할 수 있고 큰 구조체 복사 비용도 줄일 수 있어요.

**정답:** (a) `init(&L)` 직후 `length = 0`, `is_empty(&L) = 1`, `is_full(&L) = 0`, 논리적 리스트 `[]`; `length == 3`일 때 `is_empty(&L) = 0`, `is_full(&L) = 1`, `get_entry(&L, 2)`는 `L.list[2]` 반환, `get_entry(&L, 3)`은 위치 오류 (b) 유효 원소는 `0..length-1` 범위로만 구분하므로 이전 값을 `0`으로 지울 필요가 없고, 원본 구조체 `L`을 직접 수정하고 복사 비용을 줄이기 위해 주소(`&L`)를 전달한다.

배열에 이전 값이 남아 있다는 이유로 리스트가 비어 있지 않다고 판단하지 않아요.

</details>

### P5. 주소로 읽는 연결 리스트의 순서

**강의 예제 기반 자체 출제** S4 p18

단순 연결 리스트의 초기 메모리 상태가 아래와 같아요(주소 숫자는 설명용 표식이에요).

```c
head = 300, p = 100
300:[data=10 | link=100] -> 100:[data=20 | link=400] -> 400:[data=30 | link=200] -> 200:[data=40 | link=NULL]
```

- (a) `head`부터 `NULL`까지 링크를 따라 방문하는 노드의 `(주소, data)` 순서와, 배열 리스트 대비 연결 표현의 장단점(메모리 배치·용량, 선행 노드를 알 때의 삽입·삭제 비용 vs $k$번째 위치 탐색 비용)을 쓰세요.
- (b) 주소 `500`(`data = 25`)인 새 노드 `new_node`를 `p`(주소 `100`) 뒤에 삽입할 때 바꿀 링크 대입 순서와, 초기 상태에서 노드 `400`을 삭제할 때 바꿀 링크를 쓰세요.

<details><summary>풀이 보기</summary>

- (a) `head = 300`에서 시작해 `link`를 따라가면 `(300, 10) → (100, 20) → (400, 30) → (200, 40)` 순서로 방문하고 마지막 `link = NULL`에서 멈춰요. 연결 표현은 연속된 메모리 공간이나 고정 용량이 필요 없고 선행 노드를 알면 원소 이동 없이 링크만 바꿔 $O(1)$에 삽입·삭제할 수 있지만, 포인터 저장 공간이 추가로 들고 $k$번째 위치를 찾으려면 `head`부터 순차 탐색해야 하므로 $O(n)$이 걸려요.
- (b) `p`(주소 `100`) 뒤에 주소 `500`(`new_node`)을 삽입할 때는 기존 뒷노드 주소(`400`)를 잃지 않도록 먼저 `new_node->link = p->link`(주소 `500`의 `link = 400`)를 연결한 뒤 `p->link = new_node`(주소 `100`의 `link = 500`)로 바꿔요. 초기 상태에서 노드 `400`을 삭제할 때는 선행 노드 `p`(주소 `100`)의 `link`를 삭제 노드의 다음 주소인 `200`으로 바꿔(`p->link = 200`) 노드 `400`을 건너뛰게 해요.

**정답:** (a) 방문 순서 `(300, 10) → (100, 20) → (400, 30) → (200, 40)`; 연결 표현은 연속 배치·고정 용량 제약 없이 선행 노드를 알 때 링크 변경만으로 $O(1)$ 삽입·삭제가 가능하나, 추가 링크 공간이 필요하고 위치 탐색에 $O(n)$이 걸린다. (b) 삽입: `new_node->link = 400`(`p->link`) 먼저 연결 후 `p->link = 500`으로 변경; 초기 상태에서 노드 `400` 삭제: 선행 노드 `100`(`p`)의 `link`를 `200`으로 변경(`p->link = 200`).

삽입 시 `p->link = new_node`를 먼저 실행하면 원래 `p->link`(주소 `400`)가 덮어써져 뒷부분 체인을 잃어버려요.

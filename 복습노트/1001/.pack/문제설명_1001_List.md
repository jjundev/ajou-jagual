### P1. 배열 리스트 삽입의 이동 방향

lecture-s04-p11-array-insert · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_1001_List.html#p1)

**강의 예제 기반 자체 출제** S4 p11

용량은 충분하고 list={10,20,30,40}, length=4예요. add(L,1,99)의 배열 이동 순서와 최종 유효 원소·length를 쓰세요. 반복 방향을 앞에서 뒤로 바꾸면 왜 원소가 손실되는지, 맨 끝 삽입의 position 범위도 설명하세요. 길이 n에서 position=k일 때 이동 횟수와 최선·최악 시간복잡도도 구하세요.

`void add(ArrayListType *L, int position, element item)
{
    if(!is_full(L) && position>=0 && position<=L->length) {
        int i;
        for(i=L->length-1;i>=position;i--)
            L->list[i+1]=L->list[i];
        L->list[position]=item;
        L->length++;
    }
}`

#### 문제를 내 말로 읽어요

용량은 충분하고 list={10,20,30,40}, length=4예요. add(L,1,99)의 배열 이동 순서와 최종 유효 원소·length를 쓰세요. 반복 방향을 앞에서 뒤로 바꾸면 왜 원소가 손실되는지, 맨 끝 삽입의 position 범위도 설명하세요. 길이 n에서 position=k일 때 이동 횟수와 최선·최악 시간복잡도도 구하세요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “배열 리스트 삽입의 이동 방향”예요. 삽입 위치 1부터 기존 끝 3까지 세 원소를 오른쪽으로 옮겨야 해요. 반복 인덱스의 처음과 끝을 세면 이동 횟수가 나와요. 위치가 끝이면 이동이 없고 처음이면 길이에 비례해요.

#### 종이에 적을 첫 줄

i=length-1=3에서 list[4]=list[3]부터 실행해요.

#### 왜 이렇게 푸는지 함께 따라가요

1. 삽입 위치 1부터 기존 끝 3까지 세 원소를 오른쪽으로 옮겨야 해요.
2. i=3,2,1 순으로 복사하면 원래 값이 읽히기 전에 덮이지 않아요. 복사를 끝낸 뒤 1번에 99를 저장해요.
3. 반대로 i=1부터 시작하면 2번의 30을 20으로 덮고 다음 복사에서도 20이 전파돼요.
4. 삽입 위치는 0부터 length까지예요. length 자리에 추가할 때는 기존 원소 이동이 없어요.
5. 반복 인덱스의 처음과 끝을 세면 이동 횟수가 나와요. 위치가 끝이면 이동이 없고 처음이면 길이에 비례해요.

40을 4번,30을 3번,20을 2번 위치로 이동. 결과 {10,99,20,30,40}, length=5. 앞에서 뒤로 복사하면 아직 읽지 않은 원소를 덮어쓴다. 맨 끝 삽입 position=length도 유효하다. 이동 횟수 n-k, 맨 끝 삽입은 O(1), 맨 앞 삽입은 O(n).

#### 완성 답과 검산

40을 4번,30을 3번,20을 2번 위치로 이동. 결과 {10,99,20,30,40}, length=5. 앞에서 뒤로 복사하면 아직 읽지 않은 원소를 덮어쓴다. 맨 끝 삽입 position=length도 유효하다. 이동 횟수 n-k, 맨 끝 삽입은 O(1), 맨 앞 삽입은 O(n).

시작 조건에서 다시 추적한 결과가 위 답과 일치해요. 반복 인덱스의 처음과 끝을 세면 이동 횟수가 나와요. 위치가 끝이면 이동이 없고 처음이면 길이에 비례해요.

#### 이 문제에서 조심할 점

length를 먼저 늘린 뒤 이동 범위를 잡거나 position&lt;length로만 검사하면 경계 처리가 달라져요.

#### 설명을 닫고 다시 해 봐요

1. 주어진 시작 상태와 필요한 입력 조건을 적어요.
2. 첫 줄부터 연산 순서를 따라 답을 완성해요.
3. 경계 경우와 오류 경로를 확인해요.

**페이지 요약**

#### 첫 줄

i=length-1=3에서 list[4]=list[3]부터 실행해요.

#### 떠올릴 개념·공식

삽입 위치 1부터 기존 끝 3까지 세 원소를 오른쪽으로 옮겨야 해요.

#### 검산

### P2. 배열 리스트 삭제의 경계와 반환

lecture-s04-p12-array-delete · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_1001_List.html#p2)

**강의 예제 기반 자체 출제** S4 p12

error는 실행을 종료해요. list={10,20,30,40}, length=4에서 delete(L,1)의 반환값·복사 순서·유효 원소를 쓰세요. 삭제 뒤 배열의 마지막 칸을 0으로 만들지 않아도 되는 이유와 position=length가 불가능한 이유도 설명하세요. 길이 n에서 position=k일 때 이동 횟수와 최선·최악 시간복잡도도 구하세요.

`element delete(ArrayListType *L, int position)
{
    int i; element item;
    if(position<0 || position>=L->length) error("위치오류");
    item=L->list[position];
    for(i=position;i<L->length-1;i++)
        L->list[i]=L->list[i+1];
    L->length--;
    return item;
}`

### P3. 리스트 ADT의 연산 계약과 순서

#### 문제를 내 말로 읽어요

빈 리스트에 강의 사용 예의 add_tail(A), add_tail(B), add(2,C), add(1,D), delete(2), replace(1,E)를 차례로 적용하세요(위치는 0부터 셉니다). 각 단계의 리스트와 길이, 마지막 get_entry(1)과 get_length()의 값을 쓰세요. add와 replace가 길이에 미치는 차이, [A,E,C]와 [E,A,C]가 서로 다른 리스트인 이유, 이 결과를 구하는 데 배열·연결 구현을 알아야 하는지도 설명하세요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

‘리스트 ADT’와 연산 이름이 단서예요. 추상 자료형(abstract data type)은 객체와 허용 연산의 뜻을 정해요. add는 끼워 넣기, replace는 기존 자리의 값 바꾸기이며 구현의 대입문을 추측할 필요가 없어요.

#### 종이에 쓰는 첫 줄

초기 상태: L=[], 길이=0.

#### 왜 이렇게 푸는지 함께 따라가요

처음 상태를 빈 리스트와 길이 0으로 적어요.

끝 추가 두 번 뒤 [A,B]가 돼요. 위치2에 C를 넣으면 [A,B,C]예요.

위치1 삽입은 B를 덮지 않으므로 [A,D,B,C], 길이 4예요.

위치2의 B를 삭제해 [A,D,C], 위치1만 E로 바꿔 [A,E,C]예요.

객체는 순서 있는 모임, 연산은 그 객체를 바꾸거나 조회하는 계약이므로 저장 구현 없이 판단해요.

`[A](1)`, `[A,B](2)`, `[A,B,C](3)`, `[A,D,B,C](4)`, `[A,D,C](3)`, `[A,E,C](3)`. get_entry(1)=E, get_length()=3. add는 기존 항목을 보존하며 길이를 1 늘리고 replace는 값만 바꿔 길이를 유지합니다. 위치별 순서가 다르면 다른 리스트이며 ADT 계약만으로 결과를 정할 수 있습니다.

#### 완성 답과 검산

`[A](1)`, `[A,B](2)`, `[A,B,C](3)`, `[A,D,B,C](4)`, `[A,D,C](3)`, `[A,E,C](3)`. get_entry(1)=E, get_length()=3. add는 기존 항목을 보존하며 길이를 1 늘리고 replace는 값만 바꿔 길이를 유지합니다. 위치별 순서가 다르면 다른 리스트이며 ADT 계약만으로 결과를 정할 수 있습니다.

삽입4번, 삭제1번이므로 마지막 길이는0+4−1=3이에요. replace와 조회는 길이를 바꾸지 않아요. 마지막 인덱스1은 E이며 나머지A,C의 상대 순서가 보존돼요.

#### 이 문제에서 조심할 점

add(1,D)를 기존 B를 없애는 대치로 읽지 않아요. 원소가 같아도 순서가 다르면 같은 리스트가 아니에요.

#### 설명을 닫고 다시 해 봐요

1. 주어진 조건과 첫 상태를 적어요.
2. 핵심 규칙을 떠올려 답을 다시 완성해요.
3. 경계 조건과 보존되는 상태를 확인해요.

**페이지 요약**

#### 떠올릴 개념·공식

‘리스트 ADT’와 연산 이름이 단서예요. 추상 자료형(abstract data type)은 객체와 허용 연산의 뜻을 정해요. add는 끼워 넣기, replace는 기존 자리의 값 바꾸기이며 구현의 대입문을 추측할 필요가 없어요.

#### 첫 줄

초기 상태: L=[], 길이=0.

#### 핵심 답

`[A](1)`, `[A,B](2)`, `[A,B,C](3)`, `[A,D,B,C](4)`, `[A,D,C](3)`, `[A,E,C](3)`. get_entry(1)=E, get_length()=3. add는 기존 항목을 보존하며 길이를 1 늘리고 replace는 값만 바꿔 길이를 유지합니다. 위치별 순서가 다르면 다른 리스트이며 ADT 계약만으로 결과를 정할 수 있습니다.

### P5. 주소로 읽는 연결 리스트의 순서

lecture-s04-p18-linked-representation · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_1001_List.html#p5)

#### 문제를 내 말로 읽어요

노드 A는 주소300에 data=10,link=100, B는 주소100에 data=20,link=500, C는 주소500에 data=30,link=NULL을 저장하고 head=300이에요(주소는 설명용 표식이며 실제 C 주소가 아닙니다). 논리적 원소 순서와 마지막 링크를 쓰고, head·data·link의 역할을 구별하세요. 원형 리스트라면 C의 link가 무엇인지, 이중 연결 리스트라면 어떤 링크가 추가되는지도 쓰세요. 배열과 달리 물리적 주소순 정렬이나 연속 배치가 필요 없는 이유와, 선행 노드 위치를 이미 알 때 연결 삽입 비용과 그 위치를 처음부터 찾는 비용을 구분하세요. 마지막으로 별도 임시 포인터 없이 N.link=A.link와 A.link=N 두 대입만 사용해 A→C→NULL 사이에 독립된 새 노드 N을 넣을 때, N의 link와 A의 link 중 어느 것을 먼저 연결해야 하는지 쓰고 순서를 뒤집었을 때 C로 가는 길이 어떻게 되는지 설명하세요(그림의 링크 변경만 묻습니다). 배열의 고정 용량과 연결 노드의 동적 증가를 비교하고, 연결 리스트도 메모리 할당 실패로 더 늘릴 수 없는 경우가 있는지 설명하세요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

‘주소와 link가 따로 주어짐’은 연결 표현(linked representation)의 단서예요. 노드는 데이터와 주소의 쌍이며 link가 논리적 다음 원소를 정해요. 상수 시간 삽입은 선행 노드를 이미 알고 있다는 조건이 필요해요.

#### 종이에 쓰는 첫 줄

head=300 → A(data10) → link100.

#### 왜 이렇게 푸는지 함께 따라가요

head의 300에서 A를 읽고 link 100으로 B, link 500으로 C를 찾아가요.

주소를 오름차순으로 정렬하는 것이 아니라 link 값을 따라 순서를 읽어요.

단순 리스트는 마지막 link가 NULL이고 원형은 첫 노드의 주소 300을 저장해요.

헤드 포인터는 노드 전체가 아니라 시작 주소를 담는 변수예요. 이중 연결은 앞뒤 링크를 두어요.

알고 있는 위치에서 연결을 바꾸는 일과 그 위치까지 이동하는 일을 나누어 비용을 말해요.

별도 그림 A→C에서 먼저 N이 C를 가리키게 한 다음 A가 N을 가리키게 해요. 반대로 바꾸면 기존 A.link의 C 주소가 사라져 N의 링크를 채울 근거를 잃어요.

논리 순서는10→20→30이며 마지막 link=NULL입니다. head는 첫 노드의 주소를 담는 별도 포인터, data는 값,link는 다음 노드 주소입니다. 첫 노드를 head로 두는 원형 구조에서 C.link=300입니다. 이중 연결은 선행 노드 링크가 추가됩니다. 연결은 주소를 따라가므로 주소의 크기·연속성은 순서를 결정하지 않습니다. 유효 선행 노드를 알면 링크 변경 O(1), 일반적인 위치 탐색은 최악 O(n)입니다. 삽입은 N.link를 기존 A.link(C)에 먼저 연결한 뒤 A.link를 N으로 바꿉니다. 반대 순서 뒤 N.link=A.link를 적용하면 N이 자신을 가리키고 C로 가는 기존 연결을 잃습니다. 고정 배열은 정해진 용량에 제한되며 연결 노드는 필요할 때 할당해 늘릴 수 있지만, 사용 가능한 메모리와 할당 성공에 제한돼요.

#### 완성 답과 검산

논리 순서는10→20→30이며 마지막 link=NULL입니다. head는 첫 노드의 주소를 담는 별도 포인터, data는 값,link는 다음 노드 주소입니다. 첫 노드를 head로 두는 원형 구조에서 C.link=300입니다. 이중 연결은 선행 노드 링크가 추가됩니다. 연결은 주소를 따라가므로 주소의 크기·연속성은 순서를 결정하지 않습니다. 유효 선행 노드를 알면 링크 변경 O(1), 일반적인 위치 탐색은 최악 O(n)입니다. 삽입은 N.link를 기존 A.link(C)에 먼저 연결한 뒤 A.link를 N으로 바꿉니다. 반대 순서 뒤 N.link=A.link를 적용하면 N이 자신을 가리키고 C로 가는 기존 연결을 잃습니다. 고정 배열은 정해진 용량에 제한되며 연결 노드는 필요할 때 할당해 늘릴 수 있지만, 사용 가능한 메모리와 할당 성공에 제한돼요.

방문 주소는 300, 100, 500, NULL이에요. 주어진 노드를 정확히 한 번씩 방문하며 얻는 값은 10, 20, 30이에요. 주소 크기순으로 읽으면 20, 10, 30이 되어 link 관계와 모순돼요. 올바른 삽입 순서는 A→N→C→NULL이고, 같은 대입의 역순은 A→N→N…이므로 원래 C에 도달하지 못해요. 동적 연결이라고 무한히 늘어나는 것은 아니며 할당 실패 경로가 필요해요.

#### 이 문제에서 조심할 점

마지막 data가 NULL이라고 쓰지 않아요. NULL인 것은 link예요. 탐색까지 포함한 임의 위치 삽입을 항상 O(1)이라 하지 않아요.

1. 주어진 조건과 첫 상태를 적어요.
2. 핵심 규칙을 떠올려 답을 다시 완성해요.
3. 경계 조건과 보존되는 상태를 확인해요.

### P1. 배열 리스트 삽입의 이동 방향

lecture-s04-p11-array-insert · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_1001_List.html#p1)

**강의 예제 기반 자체 출제** S4 p11

배열 용량은 충분하고 초기 상태는 `L.list = {10, 20, 30, 40}`, `L.length = 4`예요.

`void add(ArrayListType *L, int position, element item)
{
    if(!is_full(L) && position>=0 && position<=L->length) {
        int i;
        for(i=L->length-1;i>=position;i--)
            L->list[i+1]=L->list[i];
        L->list[position]=item;
        L->length++;
    }
}`

#### 구할 것

- (a) `add(&L, 1, 25)`를 실행할 때 루프 변수 `i`의 변화 순서와 원소 이동 대입식(`L->list[i+1] = L->list[i]`), 실행 후 유효 원소 `L.list[0..4]`와 `L.length`를 쓰세요. 또한 반복 방향을 앞에서 뒤(`i++`)로 바꾸면 왜 원소가 손실되는지 설명하세요.
- (b) 길이 `n`인 배열 리스트의 `position = k`(`0 <= k <= n`)에 삽입할 때 원소 이동 횟수를 쓰고, 최선(맨 끝 삽입, `position = n`)과 최악(맨 앞 삽입, `position = 0`)의 이동 횟수 및 시간 복잡도를 구하세요.

<details><summary>강의 예제 보기</summary>

S4 p11 · Software_4_List.pdf. 강의 코드의 해당 연산을 발췌해 들여쓰기를 정리했습니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

`void add(ArrayListType *L, int position, element item)
{
    if(!is_full(L) && position>=0 && position<=L->length) {
        int i;
        for(i=L->length-1;i>=position;i--)
            L->list[i+1]=L->list[i];
        L->list[position]=item;
        L->length++;
    }
}`

</details>

#### 문제를 내 말로 읽어요

배열 리스트 `{10, 20, 30, 40}`의 인덱스 `1`에 `25`를 끼워 넣을 때 뒤에서 앞으로 원소를 옮기는 과정과 삽입 위치에 따른 시간 복잡도를 구하는 문제예요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “배열 리스트 삽입의 이동 방향”이에요. 삽입 위치 `position`부터 기존 마지막 원소 `length - 1`까지 뒤에서 앞으로(`i--`) 한 칸씩 오른쪽으로 복사해야 아직 읽지 않은 원소를 덮어쓰지 않아요.

#### 종이에 적을 첫 줄

`i = L->length - 1 = 3`에서 `L->list[4] = L->list[3]`부터 역순으로 실행해요.

#### 왜 이렇게 푸는지 함께 따라가요

(a) `i = 3, 2, 1` 순서로 `L->list[4] = L->list[3]`(`40`), `L->list[3] = L->list[2]`(`30`), `L->list[2] = L->list[1]`(`20`)을 차례로 이동한 뒤 `L->list[1] = 25`를 저장하고 `L->length`를 `5`로 늘려요. 따라서 최종 유효 원소는 `{10, 25, 20, 30, 40}`, `length = 5`예요. 만약 앞에서 뒤(`i++`)로 복사하면 `list[2]`의 `30`이 먼저 `20`으로 덮어써져 원래 값을 잃게 돼요.

(b) 길이 `n`인 리스트의 `position = k`에 삽입할 때 인덱스 `k .. n - 1`의 원소를 옮기므로 이동 횟수는 `n - k`회예요. 맨 끝 삽입(`position = n`)은 이동 횟수 `0`회로 최선 $O(1)$이고, 맨 앞 삽입(`position = 0`)은 `n`회 이동하므로 최악 $O(n)$이에요.

#### 완성 답과 검산

(a) `n = 4`, `k = 1`에서 이동 횟수는 `4 - 1 = 3`회(`40, 30, 20`)이고, 기존 세 원소가 한 칸씩 밀린 자리에 `25`가 들어가 원소 `5`개가 모두 보존돼요.

(b) `k = n`을 `n - k`에 대입하면 `0`회($O(1)$), `k = 0`을 대입하면 `n`회($O(n)$)로 최선·최악 이동 횟수 공식과 일치해요.

#### 이 문제에서 조심할 점

`length`를 먼저 늘린 뒤 이동 범위를 잡거나 `position < length`로만 검사하면 맨 끝 삽입 경계가 달라져요.

#### 설명을 닫고 다시 해 봐요

1. `i = 3, 2, 1`에 대해 `L->list[i+1] = L->list[i]` 대입 결과를 차례로 적어요.
2. 앞에서 뒤로 복사할 때 덮어써지는 원소를 직접 확인해요.
3. `position = k`일 때 이동 횟수 `n - k`로 최선과 최악 복잡도를 계산해요.

**페이지 요약**

#### 첫 줄

`i = L->length - 1 = 3`에서 `L->list[4] = L->list[3]`부터 역순으로 실행해요.

#### 떠올릴 개념·공식

배열 리스트 삽입은 `i = length - 1`부터 `position`까지 역방향(`i--`)으로 복사하며 이동 횟수는 `n - k`회예요.

#### 검산

(a) `i = 3, 2, 1` 이동 후 `list[0..4] = {10, 25, 20, 30, 40}`, `length = 5` (b) 이동 횟수 `n - k`회, 최선 $O(1)$, 최악 $O(n)$

### P2. 배열 리스트 삭제의 경계와 반환

lecture-s04-p12-array-delete · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_1001_List.html#p2)

**강의 예제 기반 자체 출제** S4 p12

`error`는 실행을 즉시 종료해요. 초기 상태는 `L.list = {10, 20, 30, 40}`, `L.length = 4`예요.

`element delete(ArrayListType *L, int position)
{
    int i; element item;
    if(position<0 || position>=L->length) error("위치오류");
    item=L->list[position];
    for(i=position;i<L->length-1;i++)
        L->list[i]=L->list[i+1];
    L->length--;
    return item;
}`

#### 구할 것

- (a) `delete(&L, 1)`을 실행할 때 반환값 `item`, 루프 변수 `i`의 이동 대입식(`L->list[i] = L->list[i+1]`), 실행 후 유효 원소 `L.list[0..2]`와 `L.length`를 쓰세요.
- (b) 삽입(`add`)은 뒤에서 앞으로(`i--`), 삭제(`delete`)는 앞에서 뒤로(`i++`) 복사 방향이 반대인 이유와, 삭제에서 `position == L->length`가 불가능한 이유 및 최선·최악 시간 복잡도를 설명하세요.

<details><summary>강의 예제 보기</summary>

S4 p12 · Software_4_List.pdf. 강의 코드의 해당 연산을 발췌해 들여쓰기를 정리했습니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

`element delete(ArrayListType *L, int position)
{
    int i; element item;
    if(position<0 || position>=L->length) error("위치오류");
    item=L->list[position];
    for(i=position;i<L->length-1;i++)
        L->list[i]=L->list[i+1];
    L->length--;
    return item;
}`

</details>

#### 문제를 내 말로 읽어요

배열 리스트 `{10, 20, 30, 40}`에서 인덱스 `1`의 원소를 꺼내고 뒤 원소들을 앞으로 당기는 과정을 추적하며 삽입과 복사 방향이 반대인 이유를 확인하는 문제예요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “배열 리스트 삭제의 경계와 반환”이에요. 삭제할 원소 `L->list[position]`을 먼저 `item`에 보관한 뒤, `i = position`부터 `length - 2`까지 앞에서 뒤로(`i++`) 한 칸씩 당겨요.

#### 종이에 적을 첫 줄

`item = L->list[1] = 20`을 먼저 보관하고 `i = 1`부터 복사를 시작해요.

#### 왜 이렇게 푸는지 함께 따라가요

(a) 먼저 삭제 대상 `item = L->list[1] = 20`을 보관해요. 그다음 `i = 1, 2`에서 `L->list[1] = L->list[2]`(`30`), `L->list[2] = L->list[3]`(`40`)을 복사하고 `L->length`를 `3`으로 줄여 `20`을 반환해요. 최종 유효 원소는 `L.list[0..2] = {10, 30, 40}`, `length = 3`이에요.

(b) `add`는 원소를 오른쪽으로 밀어야 하므로 아직 읽지 않은 뒤 원소를 덮어쓰지 않으려 뒤에서 앞으로(`i--`) 복사하고, `delete`는 `item`을 따로 보관해 비워진 앞자리(`position`)부터 차례로 채우므로 앞에서 뒤로(`i++`) 복사해요. 삭제는 실제 원소가 있는 `0 .. length - 1`만 가능하므로 `position == length`는 불가능하며, 이동 횟수는 `n - k - 1`회로 맨 끝 삭제는 $O(1)$, 맨 앞 삭제는 $O(n)$이에요.

#### 완성 답과 검산

(a) `n = 4`, `k = 1`에서 이동 횟수는 `4 - 1 - 1 = 2`회(`30, 40`)이고, `length = 3`이므로 인덱스 `0..2`의 `{10, 30, 40}`만 유효 원소로 남아요.

(b) 맨 끝 원소 삭제(`k = n - 1`)를 `n - k - 1`에 대입하면 `0`회($O(1)$), 맨 앞 원소 삭제(`k = 0`)를 대입하면 `n - 1`회($O(n)$)가 되어 복잡도와 일치해요.

#### 이 문제에서 조심할 점

삽입에서 허용된 `position == length`를 삭제에도 허용하면 유효 범위 밖 원소를 읽게 돼요.

#### 설명을 닫고 다시 해 봐요

1. `item` 보관 후 `i = 1, 2`에서 `L->list[i] = L->list[i+1]` 결과를 적어요.
2. `add`(`i--`)와 `delete`(`i++`)의 복사 방향이 반대인 이유를 비교해요.
3. 삭제 유효 범위 `0 .. length - 1`과 이동 횟수 `n - k - 1`을 확인해요.

**페이지 요약**

#### 첫 줄

`item = L->list[1] = 20`을 먼저 보관하고 `i = 1`부터 복사를 시작해요.

#### 떠올릴 개념·공식

삭제는 `item`을 보관한 뒤 `i = position .. length - 2`를 순방향(`i++`)으로 당기며 이동 횟수는 `n - k - 1`회예요.

#### 검산

(a) 반환값 `20`, `list[0..2] = {10, 30, 40}`, `length = 3` (b) `add`는 `i--`, `delete`는 `i++`, 이동 횟수 `n - k - 1`회(최선 $O(1)$, 최악 $O(n)$)

### P3. 리스트 ADT의 연산 계약과 순서

lecture-s04-p5-list-adt-contract · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_1001_List.html#p3)

**강의 예제 기반 자체 출제** S4 p5

위치를 `0`부터 세는 리스트 ADT의 연산 계약이 아래와 같고, 초기 리스트는 공백(`[]`, `length = 0`)이에요.

`add_tail(x)    : 리스트 맨 끝에 x 추가 (length 1 증가)
add(pos, x)    : 0 <= pos <= length 위치에 x 삽입, 기존 원소는 뒤로 한 칸 이동 (length 1 증가)
delete(pos)    : pos 위치 원소를 삭제하고 뒤 원소를 앞으로 한 칸 이동 (length 1 감소)
replace(pos, x): pos 위치 원소 값을 x로 교체 (length 유지)
get_entry(pos) : pos 위치 원소 반환 / get_length() : 현재 원소 수(length) 반환`

#### 구할 것

- (a) 빈 리스트에 `add_tail(A)`, `add_tail(B)`, `add(2, C)`, `add(1, D)`, `delete(2)`, `replace(1, E)`를 순서대로 실행할 때 각 단계 직후의 리스트 상태와 `length`를 쓰세요.
- (b) 최종 상태에서 `get_entry(1)`과 `get_length()`의 반환값을 쓰고, 여기서 `delete(0)`을 한 번 더 실행할 때 앞으로 당겨지는 원소 개수 및 `add`와 `replace`가 `length`에 미치는 차이를 설명하세요.

<details><summary>강의 예제 보기</summary>

S4 p5 · 추가 근거 p2,3,4,6 · Software_4_List.pdf. 강의 개념·그림을 근거로 질문을 직접 작성했습니다. 강의 원문 코드의 전사가 아닙니다. 질문·입력 조건·검산은 자체 작성했어요.

</details>

#### 문제를 내 말로 읽어요

리스트 ADT의 연산 계약만으로 6단계 연산의 리스트 상태와 `length`를 추적하고 조회·삭제·교체 연산의 의미를 확인하는 문제예요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “리스트 ADT의 연산 계약과 순서”예요. 추상 자료형(ADT)에서 `add`는 기존 원소를 뒤로 밀며 `length`를 `1` 늘리고, `delete`는 원소를 지우고 뒤 원소를 당기며 `length`를 `1` 줄이고, `replace`는 해당 위치 값만 바꿔 `length`를 유지해요.

#### 종이에 쓰는 첫 줄

초기 상태 `L = []`, `length = 0`을 적고 첫 연산 `add_tail(A)`부터 적용해요.

#### 왜 이렇게 푸는지 함께 따라가요

(a) 공백 리스트에서 순서대로 실행하면 `add_tail(A)` → `[A]`(`length = 1`), `add_tail(B)` → `[A, B]`(`2`), `add(2, C)` → `[A, B, C]`(`3`), `add(1, D)` → 위치 `1`의 `B`와 `C`가 뒤로 밀려 `[A, D, B, C]`(`4`), `delete(2)` → 위치 `2`의 `B`가 삭제되어 `[A, D, C]`(`3`), `replace(1, E)` → 위치 `1`의 `D`가 `E`로 바뀌어 `[A, E, C]`(`3`)이 돼요.

(b) 최종 `[A, E, C]`에서 `get_entry(1) = E`, `get_length() = 3`이에요. 여기서 `delete(0)`을 한 번 더 실행하면 위치 `0`의 `A`가 삭제되면서 뒤의 `E, C` `2`개 원소가 앞으로 한 칸씩 당겨져요. `add`는 원소를 끼워 넣어 `length`를 `1` 늘리지만, `replace`는 기존 위치 값만 교체하므로 `length`를 바꾸지 않아요.

#### 완성 답과 검산

(a) 삽입 계열 연산(`add_tail`, `add`)이 `4`회, 삭제(`delete`)가 `1`회, 교체(`replace`)가 `1`회이므로 최종 길이는 `0 + 4 - 1 = 3`이고 원소는 `[A, E, C]`로 일치해요.

(b) 길이 `3`인 리스트 `[A, E, C]`에서 인덱스 `0`을 지우면 남은 `3 - 0 - 1 = 2`개 원소(`E, C`)가 앞으로 이동함을 확인할 수 있어요.

#### 이 문제에서 조심할 점

`add(1, D)`를 기존 `B`를 없애는 대치로 읽지 않아요. 원소가 같아도 순서가 다르면 같은 리스트가 아니에요.

#### 설명을 닫고 다시 해 봐요

1. 6개 연산을 순서대로 적용하며 매 단계 리스트와 `length`를 적어요.
2. 최종 리스트에서 `get_entry(1)`, `get_length()`와 `delete(0)`의 이동 원소 수를 구해요.
3. `add`와 `replace`가 `length`에 미치는 차이를 비교해요.

**페이지 요약**

#### 떠올릴 개념·공식

리스트 ADT에서 `add`는 끼워 넣기(`length + 1`), `delete`는 당기기(`length - 1`), `replace`는 제자리 값 교체(`length` 유지)예요.

#### 첫 줄

초기 상태 `L = []`, `length = 0`을 적고 첫 연산 `add_tail(A)`부터 적용해요.

#### 핵심 답

(a) `[A](1) → [A, B](2) → [A, B, C](3) → [A, D, B, C](4) → [A, D, C](3) → [A, E, C](3)` (b) `get_entry(1) = E`, `get_length() = 3`, `delete(0)` 시 `2`개 이동, `add`는 길이 `1` 증가·`replace`는 길이 유지

### P4. 초기화와 논리적 길이

lecture-s04-p9-array-list-state · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_1001_List.html#p4)

**강의 예제 기반 자체 출제** S4 p9

`MAX_LIST_SIZE = 3`인 배열 리스트 `L`의 배열 세 칸에 이전 값 `{7, 8, 9}`가 남아 있고, 조회 연산 `get_entry(L, pos)`는 `pos < 0 || pos >= L->length`일 때 위치 오류를 내요.

`void init(ArrayListType *L)
{
    L->length = 0;
}
int is_empty(ArrayListType *L)
{
    return L->length == 0;
}
int is_full(ArrayListType *L)
{
    return L->length == MAX_LIST_SIZE;
}`

#### 구할 것

- (a) `init(&L)` 호출 직후 `L.length`, `is_empty(&L)`, `is_full(&L)`의 값과 논리적 리스트 상태를 쓰고, 원소 3개를 채워 `L.length == 3`이 된 상태에서 `is_empty(&L)`, `is_full(&L)` 반환값 및 `get_entry(&L, 2)`·`get_entry(&L, 3)` 호출 결과를 쓰세요.
- (b) `init`에서 배열 칸을 일일이 `0`으로 지우지 않아도 되는 이유와, `main`에서 구조체 값(`ArrayListType L`)이 아닌 주소(`&L`)를 넘기는 이유를 설명하세요.

<details><summary>강의 예제 보기</summary>

S4 p9 · 추가 근거 p10 · Software_4_List.pdf. 강의 예제의 해당 코드를 발췌했습니다. 질문과 입력 조건은 자체 출제이며 주변 선언·입출력은 생략했습니다. 질문·입력 조건·검산은 자체 작성했어요.

`void init(ArrayListType *L)
{
    L->length = 0;
}
int is_empty(ArrayListType *L)
{
    return L->length == 0;
}
int is_full(ArrayListType *L)
{
    return L->length == MAX_LIST_SIZE;
}`

</details>

#### 문제를 내 말로 읽어요

배열에 이전 값이 남아 있을 때 `init(&L)` 직후와 포화 상태에서 상태 검사·조회 결과를 구하고, 구조체 포인터 `&L`을 전달하는 이유를 묻는 문제예요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “초기화와 논리적 길이”예요. 배열 리스트의 유효 원소 범위는 `0 .. L->length - 1`이므로 `L->length = 0`만 대입하면 이전 배열 값과 무관하게 공백 리스트가 돼요.

#### 종이에 쓰는 첫 줄

`init(&L)` 직후 `L.length = 0`이므로 유효 인덱스 범위는 비어 있어요.

#### 왜 이렇게 푸는지 함께 따라가요

(a) `init(&L)` 직후 `L.length = 0`이므로 `is_empty(&L) = 1`, `is_full(&L) = 0`이고 논리적 리스트는 `[]`예요. 원소 3개를 채워 `L.length == 3`(`MAX_LIST_SIZE`)이 되면 `is_empty(&L) = 0`, `is_full(&L) = 1`이며, 유효 인덱스가 `0..2`이므로 `get_entry(&L, 2)`는 `L.list[2]`를 반환하고 `get_entry(&L, 3)`은 `pos >= L->length`여서 위치 오류가 나요.

(b) 모든 연산이 유효 원소를 `0 .. L->length - 1` 범위로만 다루므로 길이 밖의 이전 값 `{7, 8, 9}`는 읽히지 않아 `0`으로 지울 필요가 없어요. 또한 C는 인자를 값으로 전달하므로 구조체 주소(`&L`)를 넘겨야 함수가 호출자의 원본 구조체 `L`을 직접 수정할 수 있고 구조체 전체 복사 비용도 아낄 수 있어요.

#### 완성 답과 검산

(a) `MAX_LIST_SIZE = 3`에 대해 `length = 0`이면 `0 == 0`(참 `1`), `0 == 3`(거짓 `0`)이고, `length = 3`이면 `3 == 0`(거짓 `0`), `3 == 3`(참 `1`)이며 인덱스 `3`은 `pos < length`를 위반해요.

(b) 값 전달(`ArrayListType L`)로 `init(L)`을 호출하면 복사본의 `length`만 `0`이 되고 `main`의 원본 `L.length`는 바뀌지 않음을 확인할 수 있어요.

#### 이 문제에서 조심할 점

배열에 이전 값이 남아 있다는 이유로 리스트가 비어 있지 않다고 판단하지 않아요.

#### 설명을 닫고 다시 해 봐요

1. `length = 0`과 `length = 3`일 때 `is_empty`, `is_full` 반환값을 각각 적어요.
2. `length = 3`에서 `get_entry(&L, 2)`와 `get_entry(&L, 3)`의 차이를 확인해요.
3. 배열을 `0`으로 지우지 않는 이유와 `&L` 포인터 전달 이유를 한 문장씩 정리해요.

**페이지 요약**

#### 떠올릴 개념·공식

유효 원소는 `0 .. length - 1`로만 정의되며, 원본 구조체 수정과 복사 비용 절감을 위해 `ArrayListType *L`(`&L`)을 전달해요.

#### 첫 줄

`init(&L)` 직후 `L.length = 0`이므로 유효 인덱스 범위는 비어 있어요.

#### 핵심 답

(a) 직후 `length = 0, is_empty = 1, is_full = 0, []`; `length == 3`일 때 `is_empty = 0, is_full = 1`, `get_entry(&L, 2)` 정상 반환, `get_entry(&L, 3)` 위치 오류 (b) `0..length-1`만 유효하므로 `0` 초기화 불필요, 원본 수정·복사 절감을 위해 `&L` 전달

### P5. 주소로 읽는 연결 리스트의 순서

lecture-s04-p18-linked-representation · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_1001_List.html#p5)

**강의 예제 기반 자체 출제** S4 p18

단순 연결 리스트의 초기 메모리 상태가 아래와 같아요(주소 숫자는 설명용 표식이에요).

`head = 300, p = 100
300:[data=10 | link=100] -> 100:[data=20 | link=400] -> 400:[data=30 | link=200] -> 200:[data=40 | link=NULL]`

#### 구할 것

- (a) `head`부터 `NULL`까지 링크를 따라 방문하는 노드의 `(주소, data)` 순서와, 배열 리스트 대비 연결 표현의 장단점(메모리 배치·용량, 선행 노드를 알 때의 삽입·삭제 비용 vs $k$번째 위치 탐색 비용)을 쓰세요.
- (b) 주소 `500`(`data = 25`)인 새 노드 `new_node`를 `p`(주소 `100`) 뒤에 삽입할 때 바꿀 링크 대입 순서와, 초기 상태에서 노드 `400`을 삭제할 때 바꿀 링크를 쓰세요.

<details><summary>강의 예제 보기</summary>

S4 p18 · 추가 근거 p7,8,13,14,15,16,17 · Software_4_List.pdf. 강의 개념·그림을 근거로 질문을 직접 작성했습니다. 강의 원문 코드의 전사가 아닙니다. 질문·입력 조건·검산은 자체 작성했어요.

</details>

#### 문제를 내 말로 읽어요

메모리 주소와 `link`가 주어진 단순 연결 리스트에서 방문 순서를 읽고, 특정 노드 뒤 삽입과 노드 삭제 시 바꿔야 할 링크를 구하는 문제예요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “주소로 읽는 연결 리스트의 순서”예요. 연결 표현에서 논리적 순서는 물리 주소의 크기가 아니라 `head`부터 따라가는 `link`가 결정하며, 선행 노드 `p`를 알 때 삽입·삭제 링크 변경은 $O(1)$이에요.

#### 종이에 쓰는 첫 줄

`head = 300`에서 시작해 `300 → 100 → 400 → 200 → NULL` 순서로 화살표를 따라가요.

#### 왜 이렇게 푸는지 함께 따라가요

(a) `head = 300`부터 각 노드의 `link`를 따라가면 `(300, 10) → (100, 20) → (400, 30) → (200, 40)` 순서로 방문하고 `200`의 `link = NULL`에서 끝나요. 연결 표현은 연속된 메모리 배치나 고정 용량 제약이 없고 선행 노드를 알 때 원소 이동 없이 $O(1)$에 삽입·삭제할 수 있는 장점이 있지만, `link` 저장 공간이 추가로 들고 $k$번째 위치를 찾으려면 `head`부터 순차 탐색해야 해 $O(n)$이 걸리는 단점이 있어요.

(b) `p`(주소 `100`) 뒤에 주소 `500`(`data = 25`)인 `new_node`를 넣으려면, 기존 `p->link`(`400`)를 잃지 않도록 먼저 `new_node->link = p->link`(주소 `500`의 `link = 400`)를 연결한 뒤 `p->link = new_node`(주소 `100`의 `link = 500`)로 바꿔요. 초기 상태에서 노드 `400`을 삭제할 때는 선행 노드 `p`(주소 `100`)의 `link`를 삭제 노드의 다음 주소인 `200`으로 바꿔요(`p->link = 200`).

#### 완성 답과 검산

(a) 주소 크기순(`100, 200, 300, 400`)이 아니라 `link` 체인(`300 → 100 → 400 → 200`)을 따라 읽으면 데이터 `10 → 20 → 30 → 40`이 빠짐없이 한 번씩 방문돼요.

(b) 삽입 후 체인은 `300 → 100 → 500 → 400 → 200 → NULL`이 되고, 초기 상태에서 노드 `400` 삭제 후 체인은 `300 → 100 → 200 → NULL`이 되어 뒷부분 노드가 끊기지 않아요.

#### 이 문제에서 조심할 점

삽입 시 `p->link = new_node`를 먼저 실행하면 원래 `p->link`(주소 `400`)가 덮어써져 뒷부분 체인을 잃어버려요.

#### 설명을 닫고 다시 해 봐요

1. `head = 300`부터 `NULL`까지 방문하는 `(주소, data)` 쌍을 순서대로 적어요.
2. 배열 리스트와 연결 표현의 공간·탐색·삽입·삭제 특성을 비교해요.
3. `p = 100` 뒤 `500` 삽입과 노드 `400` 삭제에서 바꿀 `link` 대입식을 적어요.

**페이지 요약**

#### 떠올릴 개념·공식

연결 리스트는 `head`에서 `link`를 따라 순서를 읽으며, 삽입은 `new_node->link = p->link` 후 `p->link = new_node` 순서로 연결해요.

#### 첫 줄

`head = 300`에서 시작해 `300 → 100 → 400 → 200 → NULL` 순서로 화살표를 따라가요.

#### 핵심 답

(a) `(300, 10) → (100, 20) → (400, 30) → (200, 40)`, 선행 노드 알 때 삽입·삭제 $O(1)$이나 추가 링크 공간 및 탐색 $O(n)$ 소요 (b) 삽입: `500`의 `link = 400` 후 `100`의 `link = 500`; 삭제: `100`의 `link = 200`

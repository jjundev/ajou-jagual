## 1. 포화·완전 이진 트리 복습과 배열 표현법 (Part 01)

**핵심 내용**

- 복습(S7 p7): 포화 이진 트리(full binary tree)는 마지막 레벨까지 리프가 꽉 찬 트리다. 완전 이진 트리(complete binary tree)는 "풀 바이너리 트리로 가는 과정에 있는 트리"로, 마지막 레벨을 뺀 나머지가 포화 상태이고 마지막 레벨은 왼쪽부터 채워진다. 둘 다 아니어도 조건을 만족하면 그냥 이진 트리다.
- 트리도 스택·큐·리스트처럼 array 아니면 linked list로 구현해야 하므로 "표현에 대한 약속"을 정한다.
- **배열 표현법**(S7 p8): 모든 이진 트리를 포화 이진 트리로 가정하고, 각 자리에 번호를 붙여 그 번호를 배열 인덱스로 쓴다.
  - 번호는 위에서 아래로, 같은 레벨은 왼쪽에서 오른쪽으로 매긴다. 루트가 1, 왼쪽 자식 2, 오른쪽 자식 3, 다음 레벨 4~7, 8~15 순이다.
  - 0번 인덱스는 쓰지 않는다. 루트를 1번으로 가정하기 때문이다(학생이 물을 법한 질문을 교수님이 스스로 던지고 답함).
  - 완전 이진 트리 예: 1:A, 2:B, 3:C, 4:D …. 7번은 비어 있고, 나중에 G가 들어오면 7번에 들어간다.
  - 경사 이진 트리(skewed tree) 예: 1:A, 2:B, 3 빈칸, 4:C, 5~7 빈칸, 8:D. **빈칸을 당기지 않는다.** 자리가 고정이라, 당기면 8번 노드가 5번 자리로 가 버리기 때문이다. 희소행렬처럼 다른 표현법을 쓰지 않고 비워 둔다.
- 노드 i의 부모·자식 인덱스:
  - 부모: $\lfloor i/2 \rfloor$. 예: $5/2 = 2.5 \to 2$, $8/2 = 4$.
  - 왼쪽 자식: $2i$. 오른쪽 자식: $2i+1$. 예: 1의 오른쪽 자식은 $3$이다. 2의 오른쪽 자식 자리 5가 비어 있으면 "오른쪽 자식은 NULL"이다.
  - 부모를 거듭 따라 올라가면(recursive) 루트까지 찾을 수 있다.
- 이렇게 자리를 매기는 이유는 부모와 자식을 찾기 쉽게 하려는 것이다. 그리고 트리는 왼쪽·오른쪽 갈래에 따라 전혀 다른 데이터를 만나게 되므로 이것이 중요하다. 선형 자료구조(스택: top→bottom, 큐: front→rear)는 인덱스를 쫓다 보면 언젠가 모든 데이터를 만난다. 트리는 왼쪽으로 가면 오른쪽 데이터를 못 만날 수도 있다. [슬라이드 외]

**강조 발언**

- "요 array만 보고서도 여러분들이 '이게 바이너리 트리다', 그림을 그려라, 트리 그림을 그려 봐라, 그럼 그릴 수 있어야 돼요." (Part 01)
- "1번에 A, 2번에 B, 그리고 3번은 없으니까 통과, 4번에 C, 5, 6, 7 통과, 그다음에 8번에 D 해서 이렇게 그릴 수 있어야 되는 거예요." (Part 01)

**학생과의 대화**

- 실제 학생 발언은 없다. "어, 0번은 왜 안 써요?"는 교수님의 자문자답이다(Part 01).

## 2. 트리에서 높이가 중요한 이유와 링크 표현법 (Part 02)

**핵심 내용**

- 부모와 자식을 따라 루트로 올라가거나 리프로 내려가는 과정이 빨라야 한다. 트리는 그러려고 만든 자료구조다.
  - 데이터가 4개뿐인 높이 4 경사 트리는 최악의 경우 4번 찾아야 한다. 노드가 6개여도 균형 잡힌 트리는 1~3번 만에 찾을 수 있다.
- **링크 표현법**(S7 p8): 포인터로 부모가 자식을 직접 가리킨다. 교수님은 이를 "더블 링크", "llink, rlink"라고 불렀고, 슬라이드 코드의 필드 이름은 `left`, `right`다. 인덱스가 없고, 루트부터 조건에 따라 left나 right로 내려간다. 자식이 없으면 NULL이다. 경사 트리는 left 링크만 이어지고 right는 계속 NULL이다(교수님은 이 예를 "완전 이진 트리"라고 불렀다. 말실수 정정 참고).

```c
Typedef struct TreeNode {
int data;
struct TreeNode *left, *right;
} TreeNode; 
```

- 언제 무엇을 쓰나 [슬라이드 외]
  - 트리가 레벨 3 정도 안에서만 움직이고 커지지 않으면 배열이 단순해서 낫다.
  - 입력에 따라 깊이가 10, 20으로 동적으로 늘어나는 상황이라면, 배열을 크게 잡아 두기보다 링크 표현법으로 노드를 생성하면서 연결한다.

**강조 발언**

- "사실은 페어런트와 차일드를 얼마나 빨리 찾아 나가느냐가 굉장히 중요합니다. 제가 높이가 중요하다고 했잖아요?" (Part 02)

🕳️ 미룬 유도: 노드가 더 많아도 1~2번 만에 찾을 수 있는 이유는 "요게 이제 뒤에 설명을 해 줄 건데"라며 미뤘다(Part 02). BST(S7 p18–25)에서 다룰 내용이다.

## 3. 순회의 개념: VLR · LVR · LRV와 재귀적 추상화 (Part 02)

**핵심 내용**

- 순회(traversal)는 트리의 노드들을 **체계적으로** 방문하는 연산이다(S7 p9). traverse는 '배회하다'라는 뜻이다. 타깃 없이 브라우징하듯 무엇이 있는지 훑어본다. 내장(built-in) 함수는 아니다.
  - "체계적"이란 반드시 규칙이 있고 그 규칙을 따른다는 뜻이다. 아무 순서(A→F→C→B …)로 다 볼 수도 있지만, 그것은 순회가 아니다.
  - 스택·큐의 순회는 선형 방법이다(top→bottom, front→rear).
- 이진 트리의 기본 순회 3가지:
  - 전위(preorder) = **VLR**
  - 중위(inorder) = **LVR**
  - 후위(postorder) = **LRV**
  - 스택 단원의 전위/중위/후위 표기(prefix/infix/postfix)와 같은 구조다.
- V는 vertex다. 교수님이 학교 다닐 때는 트리의 동그라미를 노드가 아니라 vertex라고 불렀다고 한다. 여기서는 "루트"의 의미로 보면 된다. L은 left subtree, R은 right subtree다.
- **L과 R의 순서는 바뀌지 않는다.** 항상 left가 우선이다. 세 순회는 루트를 언제 방문하느냐로만 갈린다.
- "모두 내부적으로 Stack 구조를 이용"(S7 p9). 트리는 배열·링크로 표현하는데 왜 스택을 쓰는지는 뒤(Part 04)에서 설명했다. 재귀 호출이 쌓이는 내부 스택을 말한다.
- 재귀적 추상화 [슬라이드 외]
  - 모든 이진 트리는 머릿속에서 "루트(V) + 왼쪽 서브트리(L) + 오른쪽 서브트리(R)"로 추상화된다.
  - L을 다시 쪼개면 V, L, R이 되고, 이렇게 계속 내려간다. empty(NULL)도 서브트리 조건을 만족한다.
  - 루트 자체는 NULL일 수 없다. 루트에서 끊어진 것은 트리가 아니라 나뭇가지다.

**비유와 일화**

- 루트가 없는 트리는 "나뭇가지에 불과"하다. 루트로부터 연결돼야 트리가 된다(Part 02).

**강조 발언**

- "여기에 이제 체계적으로라는 말이 중요한데요" (Part 02)
- "근데 여기서 주의할 게 L, R의 순서는 바뀌지 않습니다. 그래서 항상 레프트가 우선순위가 있다고 얘기를 하는 거예요." (Part 02)

🕳️ 미룬 유도: 슬라이드 S7 p9 하단의 "DFS (Depth First Search) vs. BFS (Breadth First Search)"는 수업에서 언급하지 않았다.

## 4. 전위 순회(VLR): 목차 출력과 재귀의 두 조건 (Part 03–04)

**핵심 내용**

- 예: 책 목차 트리(S7 p10). 루트는 '자료구조'이고 아래에 "1. 자료구조와 알고리즘이란?"(1.1, 1.2), "2. 기초적인 자료구조"(2.1 스택, 2.2 큐, 2.3 리스트), "3. 고급자료구조"(3.1 트리, 3.2 그래프)가 있다. 응용 분야는 구조화된 문서 출력이다.
  - 이 트리는 이진 트리가 아니다. 이를 이진 트리로 바꿔 생각하는 방법도 있다고만 말했다("얘가 V가 되고요, 얘가 L이 되고요, 나머지가 R").
- **추적**(빨간 번호 = 방문 순서)
  1. 자료구조(V)를 방문한다 → 1
  2. L로 재귀해 들어간다. "1. 자료구조와 알고리즘이란?"(V) → 2. 여기서 끝나지 않고 다시 L로 재귀한다.
  3. 1.1(V) → 3. 1.1의 L은 NULL, R은 NULL이다. 바닥을 쳤으니 돌아온다.
  4. 1.2 → 4
  5. 오른쪽으로 넘어가 "2. 기초적인 자료구조" → 5. "아직 6번은 못 가요." 다시 L로 재귀한다.
  6. 2.1 → 6, 2.2 → 7, 2.3 → 8
  7. "3. 고급자료구조" → 9, 3.1 → 10, 3.2 → 11
  - 결과: 순서대로 찍으면 공부할 챕터 순서가 나온다.
  - 주의: "VLR이니까 2, 3, 4가 한 번에 찍히겠거니" 생각하면 안 된다. V를 방문한 다음 L이나 R로 가는 순간 무조건 재귀로 내려가고, NULL로 바닥을 쳐야 올라온다.
- **슬라이드 코드**(S7 p10)

```c
// 전위순회
preorder( TreeNode *root ){ 
if ( root ){ 
printf("%d", root->data );
// 노드방문
preorder( root->left );// 왼쪽서브트리순회
preorder( root->right );// 오른쪽서브트리순회
} 
} 
```

- "방문"이 출력만 뜻하지는 않는다. 계산 등 "방문해서 할 일"을 한다. 이 프로그램에서는 목차를 찍는 게 목적이다. [슬라이드 외]
- 자기 자신을 두 번 호출한다(V, L, R이므로). 그동안 본 재귀는 대개 한 번 호출했지만, 피보나치처럼 두 번, 필요하면 세 번도 가능하다.
- **재귀 함수의 두 조건**(2장 복습) [슬라이드 외]
  - (1) 바닥을 치는 **종결 조건**. 여기서는 `root`가 NULL인 경우다. if문에 들어가지 않고 그냥 나간다.
  - (2) 종결 조건으로 가는 **수렴**. 서브셋이 작아져야 하며, 한 칸씩 작아질 필요는 없다. 여기서는 left·right로 내려가는 것이 수렴이다. 트리는 높이가 유한하므로 언젠가 끝난다. "-1, 나누기 2 이런 거 안 보이잖아요."
  - 레벨을 따라 내려가면 후보 셋이 해당 서브트리로 국한된다. n개로 시작했어도 n−m개로 줄어든다(Part 04 첫머리).
- 재귀 호출을 하는 순간 내부 스택이 호출을 차곡차곡 쌓아 준다(Part 04). 이것이 "모두 내부적으로 Stack 구조를 이용"의 뜻이다.
- 트리, 힙, 그래프는 모두 재귀 함수를 쓴다. 재귀를 쓰지 않으면 구현이 훨씬 어렵다.
- LVR, LRV 코드는 `printf` 줄의 위치만 옮기면 된다("LVR은 얘가 올라가고 얘가 가운데로 오겠죠. 그러고 끝.").
- 시간복잡도: 수업에서 O 표기는 쓰지 않았다. [슬라이드 외·보충] 각 노드를 한 번씩 방문하므로 $O(n)$이다.

**비유와 일화**

- "인간이 더 위대한 거죠. 우리는 이게 바닥인지 알잖아요. 근데 컴퓨터는 바닥이라는 걸 확인해야 바닥인지 압니다." 이것이 NULL 종결 조건의 의미다(Part 03).
- 재귀는 "필요악"처럼 느껴지지만, 그 효과가 드러나는 자료구조를 만나면 반드시 필요한 개념으로 느껴진다(Part 03).

## 5. 중위 순회(LVR): 수식 트리 a*b + c/d (Part 04)

**핵심 내용**

- 예: 수식 `a*b + c/d`의 트리(S7 p11). 루트 `+`, 왼쪽 `*`(a, b), 오른쪽 `/`(c, d).
- **추적**(내부 스택이 기억한다. "내가? 아니 내부 스택이.")
  1. `+`(V)를 스택에 기억하고 L로 간다.
  2. `*`를 기억하고 L로 간다.
  3. a에서 다시 L로 가면 NULL이다. 올라와서 a를 찍는다 → 1
  4. a의 R은 NULL이다. 바닥을 치고 올라오면 LVR 한 세트가 완성된다.
  5. `*`를 찍는다 → 2
  6. R로 가서 b의 L은 NULL, b를 찍고 → 3, R은 NULL이다.
  7. `+`를 찍는다 → 4
  8. 오른쪽 서브트리: `/`를 스택에 저장하고 L로 간다. c → 5, `/` → 6, d → 7
  - 출력: `a * b + c / d`. 중위 순회를 하면 익숙한 중위 표기법으로 출력된다.
- **슬라이드 코드**(S7 p11)

```c
// 중위순회
inorder( TreeNode *root ){ 
if ( root ){ 
inorder( root->left );// 왼쪽서브트리순회
printf("%d", root->data );
// 노드방문
inorder( root->right );// 오른쪽서브트리순회
} 
} 
```

- L과 R은 link를 따라가는 역할만 하고, 실제 일(출력, 계산)은 항상 V에서 한다. [슬라이드 외]
- 그림으로는 "L, V, R" 하고 끝내도 되지만, 컴퓨터로는 반드시 NULL 조건을 만나 리턴돼야 한다. 그래프로 넘어가면 사이클(closed loop)이 있어서, 바닥 조건을 명확히 하지 않으면 매우 헷갈린다. [슬라이드 외]

**비유와 일화**

- 나뭇가지끼리 붙어 closed loop가 생긴 나무는 이상하다. 트리에는 사이클이 없지만 그래프에는 있다(Part 04).

**강조 발언**

- "근데 엄밀히 얘기하면 틀리는 겁니다. 왜? 바닥을 치지 않았습니다." (Part 04)
- "자, L, L, L 바닥 찍고 V, R 바닥 찍고 올라와서 하나의 서브트리 완성. 이렇게 설명해야지 맞아요." (Part 04)
- "이걸 왜 강조하냐면요, … 그래프로 넘어가게 되면 … 사이클 같은 게 있기 때문에 엄청 헷갈려요." (Part 04)

## 6. 후위 순회(LRV): 디렉토리 용량 계산 (Part 04–05)

**핵심 내용**

- 예: 디렉토리 용량 계산(S7 p12). '내 문서' 아래에 음악, 그림(정지영상, 동영상) 등이 있다. 탐색기의 디렉토리는 계층·포함 관계를 가진 트리 구조다(C: → Program Files …).
  - 폴더 하나만 봐서는 용량을 모른다. 속성에서 보이는 용량도 LRV 순으로 방문하면서 값을 기억해야 나온다.
- **추적**(전사 기준. 그림 세부는 확인할 수 없다)
  1. L로 내려가 다시 L로 가면 없으니 리턴한다.
  2. R로 가도 없다. 그다음 V에서 용량 **50KB**를 기억한다.
  3. 오른쪽 서브트리를 L, R, V로 돌아 **200KB**를 더해 **250**이 된다.
  4. R로 내려가 L, R, V로 **500**이 되도록 더한다.
  5. 마지막으로 루트 V에서 합산해 총량을 출력한다.
- **슬라이드 코드**(S7 p12)

```c
// 후위순회
postorder( TreeNode *root ){
if ( root ){
postorder( root->left );// 왼쪽서브트리순회
postorder( root->right );// 오른쪽서브트리순회
printf("%d", root->data );  // 노드방문
}
}
```

- 지금까지는 "계산은 안 했어요, 찍기만 했지". 실제 계산은 7절(evaluate)에서 다룬다.

## 7. 레벨 순회(Level-order): 큐 사용, 표준이 아닌 이유 (Part 05)

**핵심 내용**

- 1, 2, 3, … 매긴 자리 순서대로 방문하는 방법이다(S7 p13). 위에서 아래로, 왼쪽에서 오른쪽으로 간다.
- **표준 순회 방법이 아니다.** 트리의 장점을 살리기 어렵기 때문이다. [슬라이드 외 설명]
  - 트리에서는 높이가 가장 중요하다. 가장 높은 곳에 가려면 가지 하나만 타면 되지, 전부 훑을 이유가 없다.
  - 왼쪽 서브트리로 가는 순간 오른쪽 서브트리의 데이터는 후보 셋에서 빠진다. 타깃을 찾을 때는 이렇게 드릴다운하는 편이 훨씬 효과적이다.
  - 큐를 쓰는 순간 선형 자료구조이고 sequential search다. 복잡도 측면에서 이득이 없다. 그래도 편하면 쓸 수 있다는 것을 보여 주는 것이다.
- **큐 추적**(수식 트리 `a*b + c/d`)
  1. `+`를 넣는다.
  2. `+`를 꺼내고 자식 `*`, `/`를 넣는다(insert).
  3. `*`를 꺼내고 a, b를 넣는다.
  4. `/`를 꺼내고 c, d를 넣는다.
  5. a, b, c, d를 차례로 꺼낸다.
  - 방문 순서: `+ * / a b c d`
- 이것으로 "순회 방법 네 가지"를 마쳤다.
- 시간복잡도: 수업에서 O 표기는 쓰지 않았다. [슬라이드 외·보충] 레벨 순회도 모든 노드를 방문하므로 $O(n)$이다. 교수님이 말한 "이득 없음"은 탐색에 쓸 때 후보를 줄이지 못한다는 뜻이다.

**비유와 일화**

- **업다운 게임**: 0~100 사이 수를 맞힐 때 50을 부르고 "다운"이면 51~100이 한 번에 날아간다. 후보 셋(candidate set)이 반으로 준다. 다음엔 25를 불러야 효과적이다. 100, 99, 98 …처럼 부르면 sequential search이고, 답이 0이면 100번을 찾아야 한다(Part 05). 이진 탐색 트리의 탐색 효율을 미리 보여 주는 비유다.

**강조 발언**

- "트리는 높이라고 하는 terminology가 제일 중요하다고 그랬어요." (Part 05)

🕳️ 미룬 유도: "만약에 내가 어떤 타깃(target)을 찾겠다, 바로 이어서 나오겠지만"(Part 05). 타깃 탐색(BST 탐색, S7 p20)은 이번 시간에 하지 않았다.

## 8. [일화] 수식 트리 → 시스템 프로그래밍 → 예지보전·가상 센서 (Part 05–07)

수식 트리를 소개하다가 흐른 긴 여담이다. 개념과 이어지는 부분만 적는다.

- 메모리에 C 프로그램이 어떻게 탑재되는지(어셈블러, 링커, 로더)는 컴퓨터시스템프로그래밍이나 마이크로컴퓨터설계에서 배운다. 수식 트리, 중위→후위 변환, 계산은 그 과정과 이어진다(Part 07 복귀 발언: "중위 표기법이 후위 표기법으로 바뀌고 그거를 계산하고 이런 과정들을 스택에서 봤었잖아요?").
- 예지보전(predictive maintenance): 병이 나기 전에 언제 날지 맞히듯, 고장 전에 예측해서 유지보수하는 기술이다. 협동로봇은 출시 전 스펙 테스트를 하지만 현장 용도(치킨 튀기기, 카매트 글루건, 유해 화학약품, 왁스 칠)를 모두 테스트할 수는 없다. 그래서 출시 후 데이터로 예측한다.
- 가상 센서(virtual sensor): 온도 센서를 붙이지 않고 전류(current)와 온도의 상관관계를 딥러닝으로 학습시킨다. 그러면 AI 모델이 "온도 센서인 척" 동작한다(Part 07).
- 강조 표현이 들어간 여담 발언(목록 완결용)
  - "컴퓨터시스템프로그래밍이 그 부분을 메꿔 주고 있기 때문에 여러분들이 꼭 배워야 된다고 생각하지는 않는데" (Part 05)
  - "가장 민감한 환경 변수가 온도거든요. 기판의 온도가 되게 중요하거든요." (Part 05)

## 9. 이진 트리의 응용 1: 수식 트리 (Part 05, 07)

**핵심 내용**

- 수식 트리(expression tree)는 산술식을 트리 형태로 표현한 것이다(S7 p14).
  - 비단말 노드(non-terminal node)는 연산자(operator)다.
  - 단말 노드(terminal node, 리프)는 피연산자(operand)다. "주로가 아니라 100%" 피연산자만 온다.
- 슬라이드 표 (S7 p14):

| 수식 | 전위순회 | 중위순회 | 후위순회 |
|---|---|---|---|
| a + b | + a b | a + b | a b + |
| a - (b × c) | - a × b c | a - b × c | a b c × - |
| (a < b) or (c < d) | or < a b < c d | a < b or c < d | a b < c d < or |

- **교수님 추적**
  - `a + b` 전위: V, L, R → `+ a b`
  - `(a < b) or (c < d)` 중위: L(`a < b`) → V(`or`) → R(`c < d`)
  - `a - (b × c)` 후위:
    1. L: a를 찍는다.
    2. R 서브트리에서 L: b, R: c, V: ×를 찍는다.
    3. 마지막으로 V: `-`를 찍는다.
    - 결과: `a b c × -`
- 스택 단원의 전위/중위/후위 표기법과 "이어져 있는 연장선"이다.

**강조 발언**

- "여러분들 이거 진작에 알았으면 우리 시험 볼 때 이 페이지 마지막 거 맞았을 텐데. 훨씬 쉽게 풀었을 텐데, 그렇죠? 네. 이어져 있는 연장선이에요." (Part 07)

## 10. 수식 트리 계산: evaluate (Part 07)

**핵심 내용**

- 후위 순회를 사용한다(S7 p15). 서브트리의 값을 순환 호출로 계산하고, 비단말 노드를 방문할 때 양쪽 서브트리의 값에 저장된 연산자를 적용한다. 방문만 하는 게 아니라 실제로 계산한다.
- **슬라이드 의사코드**(S7 p15)

```c
evaluate(exp)
if exp = NULL
then return 0;
else x←evaluate(exp->left);
y←evaluate(exp->right);
op←exp->data;
return (x op y);
```

- 종결 조건은 `exp = NULL`이다. 수렴은 `exp->left`와 `exp->right`로 가는 것이므로 재귀가 제대로 동작한다. 왼쪽, 오른쪽, 그다음 연산자 순서이므로 LRV, 곧 후위 순회다.
- **추적**(교수님 예)
  1. L로 내려가 더 없으면 x = 3이다.
  2. R로 가서 y = 2다.
  3. 노드의 연산자를 적용한다. 교수님은 "곱하기를 찍게 되는 거예요. 그래서 더하기, 3 + 2"라고 말해 연산자가 섞였다. 말실수 정정 참고.
- 시간복잡도: 수업에서 언급하지 않았다. [슬라이드 외·보충] 노드마다 한 번 계산하므로 $O(n)$이다.

**강조 발언**

- "이게 재귀 호출(recursive call)의 효과예요. 트리는 무조건 재귀 호출(recursive call)을 이용합니다." (Part 07)

## 11. 이진 트리 연산: 노드 개수 get_node_count (Part 07)

**핵심 내용**

- 순회하면서 동시에 노드 개수를 센다(S7 p16). 각 서브트리에 대해 순환 호출한 다음, 반환되는 값에 1(자기 자신)을 더해 반환한다.

```c
int get_node_count(TreeNode *node)
{
int count=0;
if( node != NULL )
count = 1 + get_node_count(node->left)+ 
get_node_count(node->right);
return count;
}
```

- **추적**(슬라이드 그림의 수 1, 1, 3, 1, 2, 6)
  1. 리프는 left·right가 NULL이라 0을 받고 1을 반환한다.
  2. 리프 둘을 자식으로 둔 노드는 $1 + 1 + 1 = 3$이다.
  3. 자식이 하나인 노드는 $1 + 0 + 1 = 2$다.
  4. 루트는 $3 + 2 + 1 = 6$이다.
- 더하려면 원하는 값을 리턴해 줘야 한다. 빠져나오는 이유는 NULL이기 때문이다.
- 시간복잡도: 언급하지 않았다. [슬라이드 외·보충] $O(n)$이다.

## 12. 이진 트리 연산: 높이 get_height (Part 07)

**핵심 내용**

- 높이는 가장 높은 가지까지의 높이다. "무성한 가지"가 아니라 가장 위로 뻗은 가지가 기준이다(S7 p17).
- left와 right를 재귀로 따라간 뒤, 더하지 않고 `max`로 둘 중 큰 값을 골라 **+1**(루트 자신의 높이)을 해서 반환한다.

```c
int get_height(TreeNode *node)
{
int height=0;
if( node != NULL )
height = 1 + max(get_height(node->left), 
get_height(node->right));
return height;
}
```

- 왼쪽에서 x, 오른쪽에서 y가 리턴되면 $\max(x, y) + 1$이다. +1을 하는 이유는 "루트 때문에요. 루트의 높이도 더해줘야죠."
- 반복문이 필요 없다. 내부 스택이 모든 것을 관리해 연산하는 것이 트리의 장점이다.
- 시간복잡도: 언급하지 않았다. [슬라이드 외·보충] $O(n)$이다.

- 재귀 / 순환 호출 (recursive call, recursion), 종결 조건, 수렴, 내부 스택, 바닥을 친다
- 큐 (queue), 선형 자료구조, sequential search, 후보 셋 (candidate set), 드릴다운 (drill-down)
- 수식 트리 (expression tree), 연산자 (operator), 피연산자 (operand), 중위 표기법, 후위 표기법
- 노드 개수, 높이 (height), 사이클 / closed loop (그래프와 대비)
- 이진 탐색 트리 (binary search tree, 예고)

**식**

- 부모: $\lfloor i/2 \rfloor$, 왼쪽 자식: $2i$, 오른쪽 자식: $2i+1$ (루트 = 1, 0번 미사용)
- 노드 개수: $\text{count}(T) = 1 + \text{count}(L) + \text{count}(R)$, $\text{count}(\text{NULL}) = 0$
- 높이: $h(T) = 1 + \max(h(L), h(R))$, $h(\text{NULL}) = 0$
- 예: $5/2 = 2.5 \to 2$, $8/2 = 4$, $3 + 2 + 1 = 6$

**한 줄 코드 조각(슬라이드 표기 그대로)**

- `struct TreeNode *left, *right;`
- `printf("%d", root->data );`
- `preorder( root->left );// 왼쪽서브트리순회`
- `inorder( root->right );// 오른쪽서브트리순회`
- `postorder( root->left );// 왼쪽서브트리순회`
- `if exp = NULL then return 0;`
- `return (x op y);`
- `count = 1 + get_node_count(node->left)+ get_node_count(node->right);`
- `height = 1 + max(get_height(node->left), get_height(node->right));`

## 시험·과제 언급

- "여러분들 이거 진작에 알았으면 우리 시험 볼 때 이 페이지 마지막 거 맞았을 텐데. 훨씬 쉽게 풀었을 텐데, 그렇죠? 네. 이어져 있는 연장선이에요." (Part 07)
  - 이미 치른 시험(중간고사로 보임)에 수식의 전위·중위·후위 표기 문제가 있었고, 그 문제가 수식 트리 순회(S7 p14)로 쉽게 풀린다는 취지다.
- 앞으로의 시험 범위, 출제 방식, 과제, 실습에 대한 언급은 없다.

핵심 조건과 구할 것

노드 8개 이진 트리 그림을 보고 (1) 0~19번 1차원 배열, (2) 전위, (3) 후위, (4) 중위 순회 결과를 구해요.

D는 오른쪽 자식 E만, F와 G는 왼쪽 자식만 있어요. 원문 모범답안의 [12]=F는 G의 왼쪽 자리이므로 H의 오기예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제 단서꺼낼 도구·공식이유와 조건
0~19번 1차원 배열 배열 표현법: 루트 1, 왼쪽 $2i$, 오른쪽 $2i+1$ 0번은 비우고, 부모 $i$의 반 $\lfloor i/2 \rfloor$ 로 역산하며 없는 자식은 빈칸으로 둬요(정리노트).
전위·후위·중위 순회 VLR / LRV / LVR 셋 다 왼쪽(L)을 오른쪽(R)보다 먼저 돌고, 루트(V)를 찍는 순서만 앞·뒤·가운데로 달라져요(정리노트).

종이에 쓰는 실제 첫 줄

[1] = A  →  왼쪽 B = 2×1 = 2,  오른쪽 F = 2×1+1 = 3

왜 이렇게 푸는지 함께 따라가요

(1) 1차원 배열 인덱스 계산
부모(인덱스)왼쪽 자식 ( $2i$ )오른쪽 자식 ( $2i+1$ )
A(1)B → 2F → 3
B(2)C → 4D → 5
F(3)G → 6없음 (7 빈칸)
C(4)없음 (8 빈칸)없음 (9 빈칸)
D(5)없음 (10 빈칸)E → 11
G(6)H → 12없음 (13 빈칸)

따라서 [1]=A, [2]=B, [3]=F, [4]=C, [5]=D, [6]=G, [11]=E, [12]=H이고 0번과 나머지 칸은 빈칸이에요. 원본 모범답안은 [12]=F로 적혀 있지만 F는 이미 [3]에 있고 [12]는 G(6)의 왼쪽 자리이므로 H가 맞아요.

(2) 전위 순회 (VLR: 루트 → 왼쪽 → 오른쪽)

루트 A를 먼저 찍고, 왼쪽 B 서브트리(B, C, D, E)를 끝낸 뒤 오른쪽 F 서브트리(F, G, H)를 돌아요 → A, B, C, D, E, F, G, H.

(3) 후위 순회 (LRV: 왼쪽 → 오른쪽 → 루트)

B 서브트리는 C → (E, D) → B, F 서브트리는 (H, G) → F, 마지막에 루트 A를 찍어요 → C, E, D, B, H, G, F, A.

(4) 중위 순회 (LVR: 왼쪽 → 루트 → 오른쪽)

B 서브트리는 C → B → (D, E), 이어서 A, F 서브트리는 (H, G) → F예요 → C, B, D, E, A, H, G, F.

완성 답과 검산

(1) 완성 답: [1]=A, [2]=B, [3]=F, [4]=C, [5]=D, [6]=G, [11]=E, [12]=H (나머지 빈칸). 부모 역산 $\lfloor 11/2 \rfloor = 5$ (D, 홀수=오른쪽 E), $\lfloor 12/2 \rfloor = 6$ (G, 짝수=왼쪽 H)이 그림과 일치하고 채워진 칸 8개도 노드 수와 같아요. (원본 모범답안 [12]=F는 오기.)

(2) 완성 답: A, B, C, D, E, F, G, H. 맨 앞이 루트 A이고, 바로 뒤 4개(B, C, D, E)가 왼쪽 서브트리 크기와 같아요.

(3) 완성 답: C, E, D, B, H, G, F, A. 맨 끝이 루트 A이고, 바로 앞 3개(H, G, F)가 오른쪽 서브트리 크기와 같아요.

(4) 완성 답: C, B, D, E, A, H, G, F. 루트 A 왼쪽에 B 서브트리 4개, 오른쪽에 F 서브트리 3개가 정확히 나뉘어요.

실수하면 답이 이렇게 망가져요

외자식 E를 습관적으로 10번에 넣으면: $\lfloor 10/2 \rfloor = 5$ 의 짝수 인덱스라 D의 왼쪽 자식이 되어 그림(오른쪽 자식)과 어긋나요. D의 왼쪽은 10번 빈칸으로 비워 둬야 11번이 나와요.

중위에서 D 서브트리를 E, D로 적으면: D의 왼쪽이 비어 있으므로 L(없음)→V(D)→R(E) 순서대로 D, E가 맞아요.

해설을 가리고 스스로 확인해요

  1. 자식이 하나뿐인 노드(D, F, G)를 보면 → 왼쪽( $2i$ )인지 오른쪽( $2i+1$ )인지 먼저 동그라미 치고 빈칸 번호를 건너뛴다.
  2. 세 순회를 적을 때 → A 아래 왼쪽(4개)·오른쪽(3개) 서브트리를 괄호로 묶어 V의 자리만 앞·뒤·가운데로 옮긴다.
  3. 배열을 다 채운 뒤 → 가장 큰 두 번호 11, 12에 $\lfloor i/2 \rfloor$ 를 적용해 그림의 부모·좌우와 맞는지 검산한다.

떠올릴 개념·공식

배열 표현법(0 비움, 루트 1, L $2i$, R $2i+1$), 순회 3종(VLR·LRV·LVR).

첫 줄

[1]=A → B=2, F=3부터 부모 번호에 $2i, 2i+1$ 을 적용해요.

핵심 답

(1) [1]A [2]B [3]F [4]C [5]D [6]G [11]E [12]H (2) ABCDEFGH (3) CEDBHGFA (4) CBDEAHGF.

검산

$\lfloor 11/2 \rfloor=5$ (E=R), $\lfloor 12/2 \rfloor=6$ (H=L). 원본 [12]=F는 오기예요.

후위순회: F, D, E, G, R, T, S, N, P, M, K, H
중위순회: D, F, G, E, H, R, T, N, S, M, P, K

후위순회: F, D, E, G, R, T, S, N, P, M, K, H
중위순회: D, F, G, E, H, R, T, N, S, M, P, K"

핵심 조건과 구할 것

12노드의 후위순회와 중위순회 문자열을 만족하는 이진 트리 하나를 그려요. 원본(2021 모의 1회·이태권 기말)에 공식 답은 없어요.

이 문제를 봤을 때 떠올릴 개념과 공식

두 순회로 트리를 되살리는 절차는 순회 정의(S7 p9~p12)에서 끌어낸 수업 밖 보충 방법이에요.

문제 단서꺼낼 도구·공식이유와 조건
후위순회 (LRV) 맨 끝 글자 = 현재 서브트리 루트 LRV는 왼쪽·오른쪽을 다 돈 맨 마지막에 루트 V를 찍어요(정리노트).
중위순회 (LVR) 루트 기준 왼쪽 | 루트 | 오른쪽 분할 중위에서 센 왼쪽 노드 개수 $k$ 만큼 후위 앞부분을 잘라 왼쪽 서브트리에 줘요(정리노트).

종이에 쓰는 실제 첫 줄

후위 끝 = H  →  루트 H
중위 분할: [D, F, G, E] | H | [R, T, N, S, M, P, K]   (왼쪽 4개, 오른쪽 7개)

왜 이렇게 푸는지 함께 따라가요

후위 끝에서 루트를 뽑고, 중위에서 왼쪽 개수 $k$ 를 세어 후위 앞 $k$ 개를 왼쪽으로 떼어 내는 분할을 표로 따라가요.

서브트리 후위루트중위 분할 (왼쪽 | 루트 | 오른쪽)확정된 자식
F D E G R T S N P M K HHD F G E (4) | H | R T N S M P K (7)L: G, R: K
F D E GGD F (2) | G | E (1)L: D, R: E
F DD없음 | D | F (1)L: -, R: F
R T S N P M KKR T N S M P (6) | K | 없음L: M, R: -
R T S N P MMR T N S (4) | M | P (1)L: N, R: P
R T S NNR T (2) | N | S (1)L: T, R: S
R TTR (1) | T | 없음L: R, R: -

1개만 남은 E, F, P, S, R은 모두 단말 노드예요. D는 중위가 D, F이므로 F가 D의 오른쪽 자식이고, K는 중위의 맨 끝이라 오른쪽 자식이 없어요.

완성 답과 검산

완성 답: 루트 H — H(G, K), G(D, E), D(-, F), K(M, -), M(N, P), N(T, S), T(R, -) (층별 순서: H / G K / D E M / F N P / T S / R). 원본에 공식 답은 없어요.

  • 노드 수 보존: 루트 1 + 왼쪽 4 + 오른쪽 7 = 12노드로 입력 길이와 같아요.
  • 후위 재순회 검산: G 서브트리(F, D, E, G) + K 서브트리(R, T, S, N, P, M, K) + H = F, D, E, G, R, T, S, N, P, M, K, H로 입력과 12글자 모두 일치해요.
  • 중위 재순회 검산: 그림의 x좌표를 왼쪽부터 읽으면 D, F, G, E, H, R, T, N, S, M, P, K로 입력과 일치해요.

실수하면 답이 이렇게 망가져요

후위 첫 글자 F를 루트로 잡으면: 전위와 반대로 읽은 것이며, F로 중위를 자르면 왼쪽 1개(D)·오른쪽 10개가 되어 후위 분할이 성립하지 않아요.

중위 D, F에서 F를 D의 왼쪽에 두면: LVR 순회 결과가 F, D로 뒤집혀 입력(D, F)과 충돌해요.

해설을 가리고 스스로 확인해요

  1. 후위+중위 복원을 보면 → 후위 맨 끝으로 루트를 먼저 확정하고 중위에서 왼쪽 개수 $k$ 를 센다.
  2. 후위에서 왼쪽 덩어리를 뗄 때 → 앞에서 $k$ 개를 잘라 왼쪽에, 나머지(맨 끝 제외)를 오른쪽에 넘긴다.
  3. 트리를 그린 뒤 → 아래에서 위로 후위 순회를 다시 적어 입력 12글자와 대조한다.

떠올릴 개념·공식

후위 LRV 끝 = 루트, 중위 LVR로 왼쪽(k) | 루트 | 오른쪽 분할(보충 방법).

첫 줄

후위 끝 H → 루트 H, 중위 [D F G E] | H | [R T N S M P K] (4개 / 7개).

핵심 답

레벨 순서 H / G K / D E M / F N P / T S / R (유일한 트리, 공식 답 미기재).

검산

노드 1+4+7=12개, 그림 x좌표 중위와 재순회 후위가 입력과 12글자 일치.

핵심 조건과 구할 것

13노드의 중위·후위 순회로 트리를 복원해 1~40번 1차원 배열에 채워요(트리는 제출하지 않고 배열만 적어요).

이 문제를 봤을 때 떠올릴 개념과 공식

문제 단서꺼낼 도구·공식이유와 조건
후위에 P 2회, F 0회 두 순회의 글자 집합 비교 같은 트리이므로 노드 13개 집합이 일치해야 해요. 덩어리 경계로 어느 P가 F인지 확정해요.

문제 단서꺼낼 도구·공식이유와 조건
머리말 ‘전위’ vs 줄 이름표 ‘중위·후위’ 줄 이름표·모범답안 기준 일치 확인 머리말대로 읽으면 D가 루트인 전혀 다른 트리가 성립하므로 줄 이름표를 기준으로 풀어야 해요.

종이에 쓰는 실제 첫 줄

후위 끝 = A  →  루트 A

머리말(“전위”)만 보고 첫 줄을 전위로 읽으면: D가 루트인 길쭉한 다른 트리가 하나 나와 두 줄 이름표·원본 모범답안과 전혀 다른 답이 돼요.

핵심 조건과 구할 것

컴퓨터 디렉토리 폴더의 용량 계산에 가장 알맞은 이진 트리 순회 이름 하나를 빈칸에 적어요.

이 문제를 봤을 때 떠올릴 개념과 공식

‘디렉토리 폴더의 용량 계산’이라는 단서에서 후위 순회(postorder traversal, LRV) 응용을 떠올려요. 폴더 용량은 하위 폴더 용량을 모두 구해 합친 뒤에야 자기 파일 크기를 더해 확정할 수 있으므로, 자식(L·R)을 먼저 끝내고 루트(V)를 마지막에 처리하는 순서가 맞아요(S7 p12, 정리노트).

종이에 쓰는 실제 첫 줄

용량(현재 폴더) = 용량(왼쪽 하위) + 용량(오른쪽 하위) + 자기 파일 크기  →  L, R 먼저, V 나중

왜 이렇게 푸는지 함께 따라가요

  • 전위 순회(VLR): 현재 폴더(V)를 먼저 방문하므로 하위 폴더(L, R) 용량을 아직 모르는 상태라 계산할 수 없어요.
  • 중위 순회(LVR): 왼쪽(L)만 구한 뒤 오른쪽(R)을 보기 전에 현재 폴더(V)를 처리하므로 합산이 끝나지 않아요.
  • 후위 순회(LRV): 왼쪽·오른쪽 하위 폴더 용량을 모두 반환받은 뒤 마지막에 자기 파일 크기를 더해 루트 용량을 확정해요 → 정답: 후위 순회.

완성 답과 검산

완성 답: 후위 순회 (postorder traversal, LRV).

구체적 수치로 확인해요. 왼쪽 하위 폴더가 50 KB, 오른쪽이 150 KB, 현재 폴더 자체 파일이 50 KB라면, 자식을 먼저 돌아 50과 150을 모은 뒤 루트에서 50 + 150 + 50 = 250 KB를 한 번에 계산할 수 있어요. 2018 중간 3번 원본 답(“후위 순회”) 및 S7 p12 예시와 일치해요.

실수하면 답이 이렇게 망가져요

“상위 폴더부터 열어 본다”는 탐색 순서에 끌려 전위를 적으면: 폴더를 여는 시점(V)에는 하위 폴더 용량이 아직 계산되지 않아 값을 구할 수 없어요. 계산이 완료되어 돌아오는 순서는 LRV예요.

해설을 가리고 스스로 확인해요

  1. 트리 응용 문제를 보면 → “부모 값을 구할 때 자식의 반환값이 먼저 필요한가?”를 물어 LRV(후위) vs VLR(전위)를 즉시 가른다.

떠올릴 개념·공식

후위 순회(LRV): 왼쪽·오른쪽 자식을 먼저 계산하고 마지막에 루트 합산(S7 p12).

첫 줄

용량(현재) = 용량(L) + 용량(R) + 자기 크기 → 자식 먼저, 루트 나중.

핵심 답

후위 순회 (원본 답·S7 p12 일치).

검산

하위 50KB + 150KB를 먼저 모아야 상위에서 + 50KB = 250KB 확정 가능.

이 문제를 봤을 때 떠올릴 개념과 공식

‘자손보다 루트를 먼저 방문’이라는 단서에서 S7 p9의 표준 순회 3종을 떠올려요. 전위(VLR)·중위(LVR)·후위(LRV)는 모두 왼쪽(L)을 오른쪽(R)보다 먼저 방문하고 루트(V)의 위치만 달라지므로, V가 맨 앞인 전위 순회(preorder traversal)가 정의와 일치해요(정리노트, 전위 순회).

종이에 쓰는 실제 첫 줄

표준 순회 3종: VLR (루트 먼저) / LVR (루트 가운데) / LRV (루트 나중)

  • 중위 순회(LVR): 왼쪽 자손을 루트보다 먼저 방문해요.
  • 후위 순회(LRV): 모든 자손을 루트보다 먼저 방문해요.

완성 답과 검산

완성 답: 전위 순회 (preorder traversal, VLR).

최소 트리 A(B, C)($n=3$)에 대입하면 전위는 A, B, C(루트 A가 맨 앞), 중위는 B, A, C(B가 먼저), 후위는 B, C, A(B, C가 먼저)이므로 조건을 만족하는 것은 전위뿐이에요. 2017 중간 5번 모범답안(“전위순회/preorder traversal”) 및 S7 p9와 일치해요.

실수하면 답이 이렇게 망가져요

“루트부터 위층에서 훑는다”는 느낌으로 레벨 순회를 적으면: 레벨 순회는 큐를 쓰는 별도 순회로 슬라이드에서 표준 순회가 아니라고 구분하고, 문제의 문구(“자손노드보다 루트노드를 먼저 방문”)는 S7 p9의 전위 순회 정의 그대로예요.

해설을 가리고 스스로 확인해요

  1. 순회 정의 빈칸을 보면 → V가 L, R의 앞·중간·뒤 중 어디에 오는지부터 적어 VLR·LVR·LRV를 구분한다.

떠올릴 개념·공식

표준 순회 3종 중 루트(V)를 자손(L, R)보다 먼저 찍는 것은 VLR(전위).

핵심 답

검산

  2. C 서브트리(LVR): 왼쪽 E → 루트 C → 오른쪽 F = E, C, F.
  3. 합치기: D B + A + E C F = D B A E C F (정답 ④).

보기별 소거 판정

  • ① A B D C E F: 루트 A가 맨 앞이므로 전위 순회(VLR) 결과라 소거해요.

완성 답과 검산

완성 답: ④ D B A E C F (교과서 인쇄 정답 미기재).

실수하면 답이 이렇게 망가져요

D가 B의 왼쪽 자식임을 놓치고 B, D로 적으면: 오른쪽 자식처럼 읽은 실수로, 중위(LVR)에서는 왼쪽 D가 B보다 먼저 나와야 해요.

③(D B E C F A)을 후위로 착각하고 고민하면: A가 맨 끝에 있어 후위처럼 보이지만, 오른쪽 덩어리가 LVR(E C F) 그대로라 후위도 아니에요.

해설을 가리고 스스로 확인해요

  1. 중위 순회 객관식을 보면 → 루트 앞뒤에 올 왼쪽·오른쪽 서브트리 노드 수부터 세어 루트 위치가 틀린 선지를 즉시 지운다.
  2. 외자식 노드(B)를 만나면 → 가지가 왼쪽인지 오른쪽인지 확인해 L-V인지 V-R인지 확정한다.

떠올릴 개념·공식

중위 LVR: 루트 앞에 왼쪽 서브트리(2개), 뒤에 오른쪽 서브트리(3개).

첫 줄

중위(A) = 중위(B) + A + 중위(C).

핵심 답

④ D B A E C F (① 전위, ② 레벨, ③ 불일치. 인쇄 정답 없음).

검산

A가 3번째 자리인 선지는 ④뿐이고, D B | A | E C F 모두 LVR과 일치.

완성 답: ④ A B / C * D * E + (교과서 인쇄 정답 미기재).

실수하면 답이 이렇게 망가져요

②(A / B * C * D + E)처럼 익숙한 수식 모양을 고르면: 연산자가 가운데 오는 것은 중위(LVR)이고, 후위(LRV)는 항상 피연산자 뒤에 연산자가 와야 해요.

두 *의 깊이를 섞어 D를 C보다 먼저 붙이면: 아래 *의 오른쪽이 C, 위 *의 오른쪽이 D이므로 가장 깊은 서브트리부터 올라와야 순서가 안 뒤집혀요.

해설을 가리고 스스로 확인해요

  1. 수식 트리의 후위 순회 선지를 보면 → 문자열 맨 끝이 트리의 루트 연산자(+)인지부터 확인해 전위·중위 선지를 즉시 지운다.
  2. 연산자가 여러 층 겹치면 → 가장 깊은 단말 쌍(A, B)의 부모부터 A B op 덩어리로 치환하며 위로 올라간다.

떠올릴 개념·공식

수식 트리 후위(LRV) = 왼쪽 + 오른쪽 + 연산자(후위 표기).

첫 줄

가장 깊은 /부터 A B /로 묶어 위로 한 층씩 합쳐요.

핵심 답

④ A B / C * D * E + (① 전위, ② 중위, ③ 불일치).

검산

후위를 괄호식으로 복원하면 ((((A/B)*C)*D)+E)로 그림과 일치.

완성 답: 8 (교과서 인쇄 정답 미기재).

  • 함수 성질 검산: 단말 집합 {4, 2, 8, 6}의 최댓값 $\max\{4, 2, 8, 6\} = 8$ 과 같아요.
  • 경계값·변형 검산: 루트 3을 9로 바꿔 대입해도 else 분기가 p->data를 참조하지 않으므로 max(4, 8) = 8이 불변이에요. 빈 트리 mystery(NULL)은 첫 if에서 0을 반환하며, NULL을 먼저 검사한 뒤 자식을 읽으므로 정의되지 않은 동작도 없어요.

“트리 전체의 최댓값”이라고 단정하면: 이 트리에서는 최댓값 8이 마침 단말에 있어 답이 같지만, 루트가 9인 트리에서는 내부 노드 값을 비교하지 않으므로 9가 아니라 8이 나와 틀려요.

NULL→0, 단말→data, 내부 노드→max(left, right) (자기 data 미사용).

첫 줄

핵심 답

8 (= 단말 노드 값의 최댓값, 인쇄 정답 없음).

검산

P11. 수식 트리의 레벨 순회와 큐

lecture-s07-p13-level-order · 원 문제 보기

강의 예제 기반 자체 출제 S7 p13

수식 a * b + c / d를 나타내는 이진 트리가 있어요. 루트는 +이고, +의 왼쪽 자식은 *, 오른쪽 자식은 /예요. *의 왼쪽·오른쪽 자식은 a, b이고, /의 왼쪽·오른쪽 자식은 c, d예요.

레벨 순회는 큐로 돌아요. 먼저 큐에 루트를 넣어요. 큐 앞에서 노드 하나를 꺼내 방문하고, 그 노드의 왼쪽 자식과 오른쪽 자식을 차례로 큐 뒤에 넣어요(없는 자식은 넣지 않아요). 큐가 빌 때까지 이것을 되풀이해요.

전위 순회는 VLR(루트 → 왼쪽 → 오른쪽), 중위 순회는 LVR, 후위 순회는 LRV 순서로 방문해요.

  2. (b) *를 꺼내 방문하고 그 자식을 큐에 넣은 직후, 큐의 내용을 앞에서 뒤 순서로 적어 보세요.
  3. (c) 같은 트리의 전위·중위·후위 순회 결과를 각각 적어 보세요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제 단서꺼낼 도구·공식이유와 조건
(a)(b) 레벨 순회 + 큐 FIFO 큐: 1개 dequeue·방문 → L·R 자식 enqueue 먼저 들어간 위층 노드가 먼저 나와 층별·좌→우 순서를 보장해요(표준 순회 아님, 정리노트).
(c) 수식 트리 + 세 순회 VLR(전위) / LVR(중위) / LRV(후위) 비단말은 연산자, 단말은 피연산자이므로 세 순회가 전위·중위·후위 표기가 돼요(정리노트).

(b) * 처리 직후 큐 상태

표의 셋째 행처럼 *를 꺼낼 때 큐 맨 앞에는 같은 층의 /가 남아 있고, *의 왼쪽·오른쪽 자식 a, b가 뒤에 추가돼요. 따라서 큐(앞 → 뒤)는 [/ a b]예요.

(c) 전위·중위·후위 순회
  • 전위(VLR): + → 왼쪽(* a b) → 오른쪽(/ c d) = + * a b / c d
  • 중위(LVR): 왼쪽(a * b) → + → 오른쪽(c / d) = a * b + c / d
  • 후위(LRV): 왼쪽(a b *) → 오른쪽(c d /) → + = a b * c d / +

완성 답과 검산

(a) 완성 답: + * / a b c d. 층별 노드 수 1(+) + 2(*, /) + 4(a, b, c, d) = 7이 방문 길이 및 S7 p13 번호(1~7)와 일치해요.

(b) 완성 답: [/ a b]. 큐 길이 보존 검산: 직전 큐 [* /](길이 2)에서 * 1개를 빼고 자식 2개(a, b)를 넣었으므로 길이는 $2 - 1 + 2 = 3$ 이 되어야 맞고 S7 p13 그림과도 같아요.

(c) 완성 답: 전위 + * a b / c d, 중위 a * b + c / d, 후위 a b * c d / +. 후위를 괄호식으로 읽으면 (a*b) + (c/d)로 원래 수식의 연산 우선순위와 일치해요.

실수하면 답이 이렇게 망가져요

*를 꺼낼 때 같은 층의 /도 함께 빠진다고 착각하면: 한 번에 1개만 dequeue하므로 /는 큐 맨 앞에 남고, 그래서 a, b보다 먼저 /가 방문돼요.

큐(FIFO) 대신 방금 넣은 a, b를 먼저 꺼내면(LIFO): 방문 순서가 + * a b / c d가 되어 층 순서가 깨지고 전위 순회처럼 흘러가요.

해설을 가리고 스스로 확인해요

  1. 레벨 순회 큐 문제를 보면 → 꺼낸 1개, 추가할 자식(L→R), 남은 큐 3칸 표를 먼저 그린다.
  2. 중간 시점의 큐를 구한 뒤 → 직전 큐 길이에서 -1 + 자식 수를 계산해 현재 큐 원소 개수가 맞는지 검증한다.

떠올릴 개념·공식

레벨 순회=큐(FIFO, 표준 순회 아님). 수식 트리의 VLR/LVR/LRV=전위/중위/후위 표기.

첫 줄

초기 큐 [+]에서 시작해 1개씩 꺼내 방문하고 L·R 자식을 뒤에 넣어요.

핵심 답

(a) + * / a b c d (b) [/ a b] (c) 전위 + * a b / c d, 중위 a * b + c / d, 후위 a b * c d / +.

검산

(a) 층별 1+2+4=7, (b) 큐 길이 2−1+2=3, (c) 후위 복원 (a*b)+(c/d).

P12. 노드 개수와 높이를 재귀로 구하기

이진 트리 노드 TreeNode와 두 함수 get_node_count, get_height가 아래처럼 정의돼 있어요. max는 C 표준 함수가 아니어서 함께 정의했어요. 빈 자리는 NULL이에요.

typedef struct TreeNode {
    char data;
    struct TreeNode *left, *right;
} TreeNode;

int max(int a, int b) { return a > b ? a : b; }

int get_node_count(TreeNode *node)
{
    int count=0;
    if( node != NULL )
        count = 1 + get_node_count(node->left)+
                get_node_count(node->right);
    return count;
}

int get_height(TreeNode *node)
{
    int height=0;
    if( node != NULL )
        height = 1 + max(get_height(node->left),
                         get_height(node->right));
    return height;
}

트리는 노드 6개예요. 루트 R의 왼쪽 자식은 X, 오른쪽 자식은 Y예요. X의 왼쪽·오른쪽 자식은 L1, L2이고, Y는 왼쪽 자식 L3만 있어요.

  2. (b) get_height를 루트 R에서 부르면 얼마를 돌려주나요?
  3. (c) get_height에서 max(...)에 1을 더하는 이유를 한 문장으로 적어 보세요.

(a) get_node_count 상향식 계산

완성 답과 검산

(a) 완성 답: X = 3, Y = 2, R = 6. 전체 노드 수 직접 세기(R, X, Y, L1, L2, L3 = 6개) 및 1 + X(3) + Y(2) = 6과 일치해요(S7 p16 그림의 반환 패턴과 동일).

(b) 완성 답: 3. 루트에서 단말까지 가장 긴 경로 R → X → L1의 노드 개수가 3개이므로 높이 3과 일치해요.

(c) 완성 답: 1은 현재 노드 자신이 차지하는 한 층이에요. 경계값 대입 검산: 만약 1 +를 지우면 단말 노드 1개(L1)에서도 max(0, 0) = 0이 되어, 모든 트리의 높이가 0으로 무너져요. 두 함수 모두 node != NULL을 먼저 검사하고 지역 변수를 0으로 초기화하므로 NULL 역참조가 없어요.

실수하면 답이 이렇게 망가져요

높이도 개수처럼 양쪽을 더하면(1 + h(L) + h(R)): R에서 1 + 2 + 2 = 5가 되어 실제 층 수(3)가 아니라 노드 개수 식과 섞여 버려요.

Y의 오른쪽 자식이 비어 있는데 NULL을 1로 보거나 Y를 1로 세면: Y는 자신(1) + L3(1) + NULL(0) = 2예요.

해설을 가리고 스스로 확인해요

  1. get_node_count와 get_height가 함께 나오면 → 양쪽 재귀 결과를 +로 합치는지 max로 고르는지부터 표시하고 단말(1)에서 위로 채운다.
  2. 재귀 코드의 + 1 의미를 물으면 → + 1을 지웠을 때 단말 노드(NULL 두 개)에서 얼마가 반환되는지 대입해 확인한다.

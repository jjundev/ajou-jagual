Q3. 0번 칸을 비우는 까닭

배열 표현법에서는 배열의 0번 칸을 쓰지 않아요. 수업에서 말한 까닭으로 알맞은 것을 고르세요.

  1. 0번 칸에 빈칸 위치를 모아 두고 따로 관리해야 해서
  2. 루트를 1번으로 약속해야 부모·자식 번호 규칙이 맞아서
  3. 0번을 루트의 부모 자리로 남겨 두고 위로 올라갈 때 써서
  4. 칸이 0번부터 있으니 루트는 원래 0번이고, 1번은 시험용 약속이라서
힌트 보기

작은 트리에서 루트를 0번과 1번에 각각 두고 부모·자식 번호 규칙이 어떻게 적용되는지 살펴보세요.

풀이 보기
  1. "빈칸은 다른 표현으로 따로 모아 관리한다" — 빈칸은 희소행렬처럼 다른 방식으로 관리하지 않고 제자리에 그냥 비워 둬요. 0번에 따로 모으는 약속은 없어요.
  2. 루트를 1번으로 가정하기 때문에 0번은 쓰지 않아요. 루트가 1번이어야 왼쪽 자식 $2i$, 오른쪽 자식 $2i+1$, 부모 $\lfloor i/2 \rfloor$가 그대로 맞아요.
  3. "부모를 따라 올라가다 닿을 0번 자리가 필요하다" — 루트 1번에서 $\lfloor 1/2 \rfloor = 0$이 나오는 것은 부모가 없다는 뜻일 뿐이에요. 0번 칸에 무엇을 담아 두지는 않아요.
  4. "배열 칸이 0번부터 있으니 루트도 0번에 둔다" — 수업 약속 자체가 루트 1번, 0번 미사용이에요. 0~19번 칸을 준 기출도 [1]=A부터 채우는 것이 정답이에요.

정답: B

Q4. 빈칸을 그대로 두는 까닭

오른쪽으로만 A–B–C가 이어진 경사 이진 트리를 배열에 담으면 A·B·C가 1·3·7번에 들어가고 2번과 4~6번은 빈칸이 돼요. 빈칸을 앞으로 당겨 채우지 않는 까닭으로 알맞은 것을 고르세요.

  1. 빈칸은 희소행렬처럼 따로 압축해 담는 것이 약속이라서
  2. 새 노드가 들어올 때 빈칸을 한꺼번에 당기기로 해서
  3. 칸 번호가 곧 부모·자식 관계라서 당기면 관계가 틀어져서
  4. 경사 트리는 노드가 적어서 빈칸이 있어도 칸 낭비가 없어서
힌트 보기

B를 빈 2번 칸으로 옮겼다고 가정하고, 그 번호가 A의 어느 자식 자리를 가리키는지 확인해 보세요.

풀이 보기
  1. "빈칸은 다른 표현법으로 압축해 담는다" — 수업에서는 희소행렬 같은 다른 표현법을 쓰지 않고 빈칸을 그대로 비워 둔다고 했어요.
  2. "빈칸은 나중에 노드가 들어올 때 정리한다" — 새 노드는 자기 번호 칸에 들어갈 뿐이에요. 완전 이진 트리 예에서도 G는 비어 있던 7번에 들어가고, 당기는 일은 없어요.
  3. 빈칸을 당겨 A·B·C를 1·2·3번에 두면 2번은 A의 왼쪽 자식 자리, 3번은 A의 오른쪽 자식 자리예요. A의 오른쪽 자식이던 B는 왼쪽 자식으로, B의 오른쪽 자식이던 C는 A의 자식으로 읽혀 관계가 틀어져요.
  4. "경사 트리를 배열에 담아도 칸이 낭비되지 않는다" — 칸 낭비는 실제로 생겨요. 노드 3개에 7칸을 쓰니까요. 그래도 부모·자식 관계를 지키려고 비워 두는 거예요.

정답: C

Q5. 왼쪽으로만 이어진 트리의 링크

왼쪽으로만 A–B–C–D가 이어진 트리를 링크 표현법(struct TreeNode *left, *right;)으로 담았어요. 이 트리와 링크를 바르게 설명한 것을 고르세요.

  1. 경사 이진 트리이고, left 링크만 이어지며 right는 모두 NULL이에요
  2. 완전 이진 트리이고, left 링크만 이어지며 right는 모두 NULL이에요
  3. 경사 이진 트리이고, 빈 자리 3번·5~7번도 NULL 노드로 만들어 둬요
  4. 경사 이진 트리이고, 노드마다 자식 번호 $2i$를 계산해 내려가요
힌트 보기

B의 두 포인터를 하나씩 짚어 실제로 어느 방향에 다음 노드가 있는지 확인해 보세요.

풀이 보기
  1. 한쪽으로만 이어진 트리는 경사 이진 트리예요. 가리킬 자식이 없는 링크는 NULL이라 right는 모두 NULL이고, D는 left도 NULL이에요.
  2. "왼쪽으로만 이어진 트리를 완전 이진 트리라 부른다" — 수업 중 말실수였어요. 완전 이진 트리는 마지막 층만 왼쪽부터 채워지는 중인 트리라, 왼쪽으로만 이어진 이 트리는 경사 이진 트리예요.
  3. "링크 표현에도 배열처럼 빈 번호 자리를 채워 둔다" — 링크 표현법에는 번호(인덱스)가 없어요. 없는 자식은 링크 값이 NULL일 뿐, 빈 노드를 따로 만들지 않아요.
  4. "링크 표현법도 번호 계산으로 자식을 찾는다" — 번호 계산은 배열 표현법의 규칙이에요. 링크 표현법은 루트에서 left나 right 포인터를 따라 내려가요.

정답: A

Q6. 세 순회를 가르는 기준

전위(VLR)·중위(LVR)·후위(LRV) 순회를 바르게 설명한 것을 고르세요.

  1. 후위(LRV)는 루트를 자손 노드보다 먼저 방문하는 순회예요
  2. 순회 종류에 따라 L과 R의 방문 순서도 서로 바뀌어요
  3. 전위(VLR)는 루트 다음 같은 층 노드를 모두 찍고 아래층으로 가요
  4. 루트 V를 방문하는 때만 다르고, L은 늘 R보다 먼저예요
힌트 보기

VLR·LVR·LRV를 나란히 쓰고 V가 놓인 위치에 각각 동그라미를 쳐 보세요.

풀이 보기
  1. "루트를 먼저 방문하는 순회를 후위로 착각한다" — 자손보다 루트를 먼저 방문하는 것은 전위(VLR)예요. 후위는 루트를 맨 나중에 방문해요.
  2. "순회마다 L·R 순서도 바뀐다" — 교수님이 L, R의 순서는 바뀌지 않는다고 짚었어요. 세 순회 모두 레프트가 우선이에요.
  3. "VLR이면 2, 3, 4번이 한 번에 찍힌다" — 전위는 V를 찍고 L로 가는 순간 재귀로 끝까지 내려가요. 층마다 차례로 찍는 것은 레벨 순회예요.
  4. VLR·LVR·LRV에서 바뀌는 것은 V의 자리뿐이에요. 루트를 먼저 찍으면 전위, 가운데면 중위, 맨 끝이면 후위예요.

정답: D

Q7. 순회가 쓰는 스택

슬라이드는 전위·중위·후위 순회가 “모두 내부적으로 Stack 구조를 이용”한다고 적어요. 트리는 배열이나 링크로 담는데, 여기서 말하는 스택은 무엇일까요?

  1. 트리 노드를 스택에 옮겨 담은 뒤 pop 하면서 차례로 찍는 것
  2. 재귀 호출이 쌓이며 돌아올 노드를 기억해 주는 내부 스택
  3. 지나온 노드를 프로그래머가 직접 push 해 두는 배열 스택
  4. 다음에 들를 노드를 줄 세워 두는 큐를 스택이라 부른 것
힌트 보기

왼쪽 가지로 내려갔다 돌아왔을 때, 어느 노드에서 순회를 이어갈지 어떻게 기억하는지 생각해 보세요.

풀이 보기
  1. "순회하려면 트리를 스택에 옮겨 담는다" — 트리는 배열이나 링크로 담은 그대로예요. 순회하려고 노드를 스택으로 옮기지 않아요.
  2. 순회 함수가 자기 자신을 부를 때마다 호출이 내부 스택에 쌓여요. NULL로 바닥을 치면 쌓인 반대 순서로 돌아와 다음 일을 이어 가요.
  3. "지나온 노드는 프로그래머가 기억해 두어야 한다" — 슬라이드 코드에는 push가 없어요. 교수님 말대로 기억하는 것은 프로그래머가 아니라 내부 스택이에요.
  4. "세 순회의 스택과 레벨 순회의 큐를 같은 것으로 본다" — 큐는 레벨 순회에서 따로 쓰는 구조예요. 전위·중위·후위는 재귀 호출의 내부 스택을 써요.

Q8. 전위 순회 방문 순서

아래 이진 트리를 전위 순회(VLR)로 돌며 노드를 찍어요. 찍히는 순서를 쉼표로 이어 써 보세요.

힌트 보기

A에서 출발해 어느 가지로 먼저 내려갈지 그림에 표시해 보세요.

풀이 보기
  1. VLR은 V(루트)를 먼저 찍고, L로 내려간 뒤, 그다음 R로 가요.

  4. A의 R로 가 C를 찍어요. C의 L은 NULL이고 R인 F를 찍어요.

Q10. 폴더 용량을 재는 순회

탐색기에서 폴더 속성을 열면 그 폴더 아래 모든 파일을 더한 용량이 나와요. 이 값을 트리 순회로 구한다면 어떤 순회가 왜 알맞을까요?

  1. 전위(VLR) — 위 폴더부터 열어 보는 순서와 같아서
  2. 어느 순회든 — 폴더 하나의 속성만 보면 용량이 바로 나와서
  3. 후위(LRV) — 아래 폴더 용량을 다 구한 뒤에야 위 폴더 합을 내서
  4. 레벨 순회 — 위층부터 한 층씩 재야 빠짐없이 셀 수 있어서
힌트 보기

상위 폴더의 합계를 내기 전에 어떤 값이 준비돼야 하는지 생각해 보세요.

풀이 보기
  1. "폴더를 위에서부터 여니까 루트를 먼저 방문한다" — 위 폴더를 먼저 들르면 그때는 아래 폴더 용량을 아직 몰라서 합을 낼 수 없어요.
  2. "폴더 하나만 보면 용량을 알 수 있다" — 폴더 하나만 봐서는 용량을 몰라요. 속성의 용량도 아래 폴더를 다 돌며 값을 기억해야 나오는 값이에요.
  3. LRV는 L과 R을 모두 방문한 뒤 V를 방문해요. 그래서 V에 왔을 때 아래 폴더 값을 모두 더할 수 있어요.
  4. "빠짐없이 세려면 층마다 도는 레벨 순회가 필요하다" — 네 순회 모두 모든 노드를 한 번씩 방문해요. 레벨 순회는 위 폴더를 먼저 들러서 그때 합을 낼 수 없어요.

정답: C

Q11. 레벨 순회와 표준 순회

레벨 순회는 큐를 써서 위층부터 한 층씩 방문해요. 교수님은 이것을 표준 순회 방법에서 뺐어요. 그 까닭으로 알맞은 것을 고르세요.

  1. 가지를 골라 내려가며 후보를 줄이는 트리의 장점을 못 살려서
  2. 아래층의 일부 노드를 건너뛰어서 모든 노드를 방문하지 못해서
  3. 순회는 내부 스택을 써야 하는데, 큐를 써서 순회의 규칙을 어겨서
  4. 노드 수보다 훨씬 많이 방문하게 되어서 순회 자체가 느려져서
힌트 보기

가지를 따라 내려가는 방문과 한 층씩 도는 방문이 다음에 볼 노드를 어떻게 고르는지 비교해 보세요.

풀이 보기

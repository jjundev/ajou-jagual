문제를 내 말로 읽어요

변환한 후위식의 계산에 필요한 push와 pop 횟수를 세어요. 최종 결과를 스택에 남긴다는 조건을 꼭 읽어요.

이 문제를 봤을 때 떠올릴 개념과 공식

후위식 postfix evaluation에서 피연산자 하나는 push 1회, 이항 연산자 하나는 pop 2회와 결과 push 1회예요. 괄호나 변환용 연산자 스택 횟수는 계산 스택 횟수에 포함하지 않아요.

후위식 5 6 * 4 2 / + 1 −를 적어요.

왜 이렇게 푸는지 함께 따라가요

가장 나중에 열린 괄호를 가장 먼저 닫아야 하므로 LIFO인 stack을 떠올려요. 열린 괄호를 미해결 상태로 저장해요.

종이에 적을 첫 줄

왜 이렇게 푸는지 함께 따라가요

여는 괄호는 push, 닫는 괄호는 top과 종류를 비교하고 pop해요. 닫는 순간 빈 스택이거나 종류가 다르면 실패, 전체 후 남아 있어도 실패예요. 예 ([ ])에서 ]는 가장 최근 [와 짝이고 마지막 )는 (와 짝이에요.

완성 답과 검산

이 문제에서 조심할 점

여는/닫는 개수만 같아도 종류와 순서가 틀릴 수 있어요.

설명을 닫고 다시 해 봐요

  1. 빈칸에 스택(stack)을 적어요.
  2. 최근 열린 괄호 먼저 닫기 → 스택
  3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

첫 줄

빈칸에 스택(stack)을 적어요.

떠올릴 개념·공식

P7. 배열 스택의 전위·후위 연산

lecture-s05-p14-stack-c · 원 문제 보기

강의 예제 기반 자체 출제 S5 p14

아래 세 줄은 구조체 포인터 s를 받는 배열 스택 함수 push, pop, peek의 정상 경로 핵심 문장이에요.

/* push의 정상 경로 */
s->stack[++(s->top)] = item;
/* pop의 정상 경로 */
return s->stack[(s->top)--];
/* peek의 정상 경로 */
return s->stack[s->top];

구할 것

  1. (a) 초기 공백 상태가 s->top = -1일 때, push에서는 전위 증가 연산자 ++(s->top)을 쓰고 pop에서는 후위 감소 연산자 (s->top)--를 쓰는 이유를 설명하세요.
  2. (b) 만약 두 식을 각각 s->stack[(s->top)++] = item;과 return s->stack[--(s->top)];으로 잘못 바꾸면, 초기 s->top = -1에서의 첫 push와 원소 1개인 s->top = 0에서의 첫 pop이 각각 접근하는 배열 인덱스와 발생하는 문제를 쓰세요(오류 동작을 정상 출력값으로 계산하지 마세요).
강의 예제 보기

/* peek의 정상 경로 */

문제를 내 말로 읽어요

배열 스택의 push와 pop에서 각각 전위 증가(++top)와 후위 감소(top--)를 쓰는 이유와, 이를 반대로 썼을 때 생기는 범위 밖 접근 오류를 확인하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “배열 스택의 전위·후위 연산”예요. 전위 ++는 식의 평가값이 증가 후의 값이고 후위 --는 식의 평가값이 감소 전의 값이며, 공백 스택의 s->top = -1에서 유효 인덱스는 0부터 시작해요.

종이에 적을 첫 줄

전위 ++의 식 값은 증가 후 값, 후위 --의 식 값은 감소 전 값이라고 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) 초기 공백 상태 s->top = -1에서 첫 원소는 인덱스 0에 들어가야 하므로, push는 ++(s->top)으로 먼저 1 올린 위치에 저장해요. 반대로 pop은 현재 맨 위 위치 s->top의 값을 먼저 꺼낸 뒤 인덱스를 줄여야 하므로 (s->top)--를 써요.

(b) 만약 push에 (s->top)++를 쓰면 초기 s->top = -1에서 증가 전 인덱스 -1에 쓰게 되고, pop에 --(s->top)을 쓰면 s->top = 0에서 감소 후 인덱스 -1을 읽게 되어 둘 다 배열 범위 밖 접근(미정의 동작)을 일으켜요.

완성 답과 검산

(a) s->top = -1에서 ++(s->top)은 0을 평가하고 s->top = 0에서 (s->top)--는 0을 평가한 뒤 -1로 돌아오므로 첫 push 후 첫 pop이 같은 칸 stack[0]을 가리켜요.

(b) 바꾼 식에 각각 s->top = -1과 s->top = 0을 대입하면 두 경우 모두 s->stack[-1]에 접근함이 즉시 확인돼요.

이 문제에서 조심할 점

후위 연산이 문장 전체가 끝날 때까지 값을 안 바꾼다는 식으로 설명하지 마세요. 식의 평가값과 변수 갱신을 구별해요.

설명을 닫고 다시 해 봐요

  1. s->top = -1에서 정상 push가 쓰는 인덱스와 갱신 후 s->top을 적어요.
  2. s->top = 0에서 정상 pop이 읽는 인덱스와 갱신 후 s->top을 적어요.
  3. top++와 --top으로 바꿨을 때 각각 접근하는 잘못된 인덱스를 적어요.

첫 줄

전위 ++의 식 값은 증가 후 값, 후위 --의 식 값은 감소 전 값이라고 적어요.

떠올릴 개념·공식

push는 ++(s->top)으로 선증가 후 저장, pop은 (s->top)--로 선읽기 후 감소해요.

검산

(a) push는 올린 인덱스에 저장, pop은 현재 인덱스를 읽은 뒤 감소 (b) top++와 --top 모두 인덱스 -1 범위 밖 접근

조건·구분과 확인

  • 후위 연산은 식의 평가값이 갱신 전 값이라는 뜻이지, 문장 전체가 끝날 때까지 변수 갱신을 안 한다는 뜻은 아니에요.

P8. 연결 스택의 두 링크 갱신

강의 예제 기반 자체 출제 S5 p17

연결된 스택(linked stack)에서 push와 pop의 정상 경로 핵심 문장은 아래와 같아요.

/* push: 동적 할당 성공 뒤 */
temp->item = item;
temp->link = s->top;
s->top = temp;

/* pop: 비어 있지 않을 때 */
StackNode *temp = s->top;

s->top = s->top->link;

  2. (b) push에서 temp->link = s->top;과 s->top = temp;의 순서를 뒤집었을 때 생기는 문제와, pop에서 free(temp);를 item 복사 및 s->top 갱신보다 먼저 실행했을 때 생기는 문제를 각각 설명하세요.

문제를 내 말로 읽어요

연결된 스택에서 새 노드 N을 push하고 바로 pop할 때 포인터 변화를 추적하고, 링크 대입 순서나 free 순서를 어겼을 때 생기는 오류를 설명하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “연결 스택의 두 링크 갱신”예요. push에서는 temp->link = s->top;으로 기존 연결을 먼저 이어 준 뒤 s->top = temp;로 바꾸고, pop에서는 값과 다음 노드 주소를 먼저 꺼낸 뒤 마지막에 free(temp);를 호출해요.

종이에 적을 첫 줄

기존 s->top = A(A -> B -> NULL)와 새 노드 N을 따로 그려요.

왜 이렇게 푸는지 함께 따라가요

(a) N을 push하면 N->link = A, s->top = N이 되어 체인은 N -> A -> B -> NULL이 돼요. 이어서 pop하면 temp = N의 값을 item에 보관하고 s->top을 A로 옮긴 뒤 N을 free해요.

(b) push에서 s->top = temp;를 먼저 실행하면 temp->link = s->top;이 N->link = N 자기 참조가 되어 기존 A -> B 체인을 잃어버려요. pop에서 free(temp);를 먼저 실행하면 해제된 메모리의 temp->item이나 temp->link를 읽는 해제 후 접근(use-after-free) 오류가 발생해요.

완성 답과 검산

(a) A -> B -> NULL에 N을 push했다가 바로 pop하면 원래 상태인 s->top = A(A -> B -> NULL)로 정확히 복원되고 N만 반납돼요.

(b) 반납 전 지역 변수 item에 값을 복사해 두었기 때문에 free(temp) 뒤에도 안전하게 return item;을 수행할 수 있어요.

이 문제에서 조심할 점

free(temp)가 s->top까지 자동 갱신해 주지는 않아요.

설명을 닫고 다시 해 봐요

  1. push의 두 링크 대입문을 순서대로 따라가며 체인을 그려요.
  2. pop에서 s->top 이동과 free(temp) 뒤 남는 노드를 적어요.
  3. 대입 순서나 free 순서를 뒤집었을 때 깨지는 포인터를 확인해요.

첫 줄

기존 s->top = A(A -> B -> NULL)와 새 노드 N을 따로 그려요.

떠올릴 개념·공식

temp->link = s->top;을 먼저 수행해 기존 리스트를 보존하고, pop에서는 값·포인터 갱신 후 free(temp)를 호출해요.

검산

(a) push 후 N -> A -> B -> NULL, pop 후 s->top = A, N 해제 (b) 순서 역전 시 N->link = N 자기 참조, 조기 free 시 해제 후 접근

    case '/': push(&s,op1/op2); break;
    }
}

문제를 내 말로 읽어요

후위 표기식 계산 코드로 "82/3-"를 문자별로 추적하고, pop한 두 피연산자의 순서와 한 자리 숫자 입력 계약의 한계를 설명하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “후위식 계산 코드의 입력 계약”예요. 숫자 문자는 ch - '0'으로 정수로 바꿔 push하고, 연산자에서는 먼저 꺼낸 값이 오른쪽 피연산자(op2), 나중에 꺼낸 값이 왼쪽 피연산자(op1)가 돼요.

종이에 적을 첫 줄

첫 문자 '8'을 읽으면 스택 [8]부터 시작해요.

왜 이렇게 푸는지 함께 따라가요

(a) '8'과 '2'를 차례로 넣으면 [8] -> [8, 2]가 돼요. '/'에서 op2 = 2, op1 = 8을 꺼내 8 / 2 = 4를 넣어 [4]가 되고, '3'을 넣어 [4, 3]이 된 뒤 '-'에서 op2 = 3, op1 = 4를 꺼내 4 - 3 = 1을 넣어 최종 스택 [1], 결과 1을 얻어요.

(b) 나중에 들어간 오른쪽 피연산자가 스택 맨 위에 있으므로 첫 pop이 op2여야 뺄셈·나눗셈에서 op1 - op2, op1 / op2 순서가 맞아요. 또한 코드는 한 문자씩 ch - '0'을 수행할 뿐 여러 자리 숫자를 묶거나 공백을 건너뛰는 처리가 없어 "12 3+"는 지원하지 않아요.

완성 답과 검산

(a) 후위식 "82/3-"는 중위식 (8 / 2) - 3 = 4 - 3 = 1과 같아 스택 추적 결과 1과 일치해요.

(b) 만약 op1과 op2를 바꾸면 '/'에서 2 / 8 = 0이 계산되어 전혀 다른 값이 나오고, "12 3+"에서는 '1', '2', ' '가 각각 별도 숫자로 push됨을 확인할 수 있어요.

이 문제에서 조심할 점

표시된 switch는 뺄셈·나눗셈 부분만 보여 줘요. 전체 eval에는 +와 * 처리도 있어요.

설명을 닫고 다시 해 봐요

  1. "82/3-"의 5개 문자를 순서대로 따라가며 스택 상태를 적어요.
  2. op2 = pop(&s); op1 = pop(&s); 순서가 중요한 연산자를 적어요.
  3. "12 3+"가 입력될 때 if 조건문에서 공백과 두 자리 수가 어떻게 처리되는지 확인해요.

첫 줄

첫 문자 '8'을 읽으면 스택 [8]부터 시작해요.

떠올릴 개념·공식

숫자 문자는 ch - '0'으로 변환해 push하고, 연산자에서는 먼저 꺼낸 값이 오른쪽 피연산자 op2예요.

검산

(a) [8] -> [8, 2] -> [4] -> [4, 3] -> [1], 결과 1 (b) 첫 pop이 오른쪽 피연산자 op2, 다자리 수·공백 미지원

조건·구분과 확인

  • 표시된 switch는 뺄셈·나눗셈 부분만이고 전체 eval에는 +와 * 처리도 있어요.

# 연결 스택 push: 무엇을 먼저 연결할까?

1012 수업(Software_5 Stack p16·17, 정리노트 `s0-node / s0-linkedpush`)의 코드를 메모리 저장 공간 변화로 확인한다.

## 핵심 질문
새 노드를 맨 앞에 붙일 때 temp->link = s->top과 s->top = temp 중 무엇을 먼저 해야 기존 노드를 잃지 않는가?

## 학습자에게 남길 것
새 노드의 link에 기존 top 주소를 먼저 적고, 그다음 top을 새 노드로 옮깁니다. top부터 바꾸면 기존 노드의 주소를 담은 곳이 사라집니다.

## 입력과 사례
- 입력: 넣을 값(-99..99), 시작 노드 수(0..3), 연결 순서(link 먼저 (강의) / top 먼저 (오류 예))
- preset: C→B→A 위에 D 넣기, top부터 바꾸면?, 빈 스택에 넣기, 빈 스택 + top 먼저, C와 같은 값 30 넣기, 경계 값 -99
- 주소는 기호(&s, &D 등)이며 실제 번지·ABI 배치를 주장하지 않는다.

## 출처와 보충
- 강의 코드: `자료구조_강의록_2026/Software_5_Stack.pdf` p16, p17 (sha256 `235bf69c42564fed…`). 강의 원문 소스는 provenance.supplement=false, 비교용 오류 예는 true.
- 단순화·보충: 노드 A~C(값 10, 20, 30)는 앞선 push 결과로 가정하고 시작 상태로 제공(source.c는 실제 push로 생성). 노드 이름표 A~D와 &A 같은 주소는 기호이며 C 식별자·실제 번지가 아님. malloc 성공을 가정해 실패 분기는 실행하지 않음. temp->link처럼 첫 멤버가 아닌 필드 쓰기는 temp 읽기와 link Cell 쓰기로 나눠 저작. top 먼저 모드는 비교용 오류 예이며 UB가 아니라 정의된 동작(누수·자기 순환)이라 진단 없이 끝까지 실행.
- 검산용 `source.c`는 강의 코드를 보존하고 시작 상태를 실제 함수 호출로 만드는 main을 덧붙인 완전 프로그램이다.

# 연결 스택 pop: 보관하고, 옮기고, 해제하기

1012 수업(Software_5 Stack p16·18, 정리노트 `s0-node / s0-linkedpop`)의 코드를 메모리 저장 공간 변화로 확인한다.

## 핵심 질문
pop에서 값 보관, top 이동, free의 순서를 바꾸면 어디서 무엇이 사용 불가가 되는가?

## 학습자에게 남길 것
temp로 기존 첫 노드를 잡고, 값을 item에 복사하고, top을 다음 노드로 옮긴 뒤에 free합니다. free한 노드와 그 노드를 가리키던 포인터는 다시 읽을 수 없습니다.

## 입력과 사례
- 입력: 맨 위 노드 값(-99..99), 시작 노드 수(0..3), 처리 순서(강의 순서 / 해제 후 읽기 (오류 예) / 먼저 해제 (오류 예))
- preset: C→B→A에서 꺼내기, 노드 하나에서 꺼내기, 빈 스택에서 꺼내면?, free 뒤에 값을 읽으면?, top을 옮기기 전에 free하면?, 경계 값 -99 꺼내기
- 주소는 기호(&s, &D 등)이며 실제 번지·ABI 배치를 주장하지 않는다.

## 출처와 보충
- 강의 코드: `자료구조_강의록_2026/Software_5_Stack.pdf` p16, p18 (sha256 `235bf69c42564fed…`). 강의 원문 소스는 provenance.supplement=false, 비교용 오류 예는 true.
- 단순화·보충: is_empty(top == NULL)는 p18이 호출만 하고 싣지 않아 보충. 노드 A, B(10, 20)와 맨 위 노드 값(입력)은 앞선 push 결과로 가정. s->top->link는 s->top 읽기 + 노드 link Cell 읽기로 나눠 저작. exit(1)은 프로그램 종료 관찰 단계로 표시(진단 아님). 두 오류 예는 비교용 보충이며 해제 후 포인터 값을 읽는 지점에서 실행하지 않고 중단.
- 검산용 `source.c`는 강의 코드를 보존하고 시작 상태를 실제 함수 호출로 만드는 main을 덧붙인 완전 프로그램이다.

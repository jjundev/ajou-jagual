문제를 내 말로 읽어요

후위 표기식 계산 코드로 "82/3-"를 문자별로 추적하고, pop한 두 피연산자의 순서와 한 자리 숫자 입력 계약의 한계를 설명하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “후위식 계산 코드의 입력 계약”예요. 숫자 문자는 ch - '0'으로 정수로 바꿔 push하고, 연산자에서는 먼저 꺼낸 값이 오른쪽 피연산자(op2), 나중에 꺼낸 값이 왼쪽 피연산자(op1)가 돼요.

종이에 적을 첫 줄

첫 문자 '8'을 읽으면 스택 [8]부터 시작해요.

왜 이렇게 푸는지 함께 따라가요

(a) '8'과 '2'를 차례로 넣으면 [8] -> [8, 2]가 돼요. '/'에서 op2 = 2, op1 = 8을 꺼내 8 / 2 = 4를 넣어 [4]가 되고, '3'을 넣어 [4, 3]이 된 뒤 '-'에서 op2 = 3, op1 = 4를 꺼내 4 - 3 = 1을 넣어 최종 스택 [1], 결과 1을 얻어요.

(b) 나중에 들어간 오른쪽 피연산자가 스택 맨 위에 있으므로 첫 pop이 op2여야 뺄셈·나눗셈에서 op1 - op2, op1 / op2 순서가 맞아요. 또한 코드는 한 문자씩 ch - '0'을 수행할 뿐 여러 자리 숫자를 묶거나 공백을 건너뛰는 처리가 없어 "12 3+"는 지원하지 않아요.

완성 답과 검산

(a) 후위식 "82/3-"는 중위식 (8 / 2) - 3 = 4 - 3 = 1과 같아 스택 추적 결과 1과 일치해요.

(b) 만약 op1과 op2를 바꾸면 '/'에서 2 / 8 = 0이 계산되어 전혀 다른 값이 나오고, "12 3+"에서는 '1', '2', ' '가 각각 별도 숫자로 push됨을 확인할 수 있어요.

이 문제에서 조심할 점

표시된 switch는 뺄셈·나눗셈 부분만 보여 줘요. 전체 eval에는 +와 * 처리도 있어요.

설명을 닫고 다시 해 봐요

  1. "82/3-"의 5개 문자를 순서대로 따라가며 스택 상태를 적어요.
  2. op2 = pop(&s); op1 = pop(&s); 순서가 중요한 연산자를 적어요.
  3. "12 3+"가 입력될 때 if 조건문에서 공백과 두 자리 수가 어떻게 처리되는지 확인해요.

첫 줄

첫 문자 '8'을 읽으면 스택 [8]부터 시작해요.

떠올릴 개념·공식

숫자 문자는 ch - '0'으로 변환해 push하고, 연산자에서는 먼저 꺼낸 값이 오른쪽 피연산자 op2예요.

검산

(a) [8] -> [8, 2] -> [4] -> [4, 3] -> [1], 결과 1 (b) 첫 pop이 오른쪽 피연산자 op2, 다자리 수·공백 미지원

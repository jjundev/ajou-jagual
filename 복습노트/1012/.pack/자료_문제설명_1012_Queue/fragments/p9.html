문제를 내 말로 읽어요

강의 eval의 일부예요. 피연산자는 한 자리 숫자, 공백 없는 올바른 식만 입력한다고 가정해요. exp="82/3-"를 문자별 스택으로 추적하세요. op1과 op2를 바꾸면 왜 틀리는지, "12 3+"를 그대로 처리할 수 없는 이유도 설명하세요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “후위식 계산 코드의 입력 계약”예요. 숫자 문자는 ch-'0'으로 정수로 바꿔요. 문자 8과 2를 차례로 넣어요. 이 예제는 일반 수식 파서가 아니에요. 공백 건너뛰기와 여러 자리 수 토큰화가 없으므로 입력 계약을 벗어난 식을 정상 계산하지 않아요.

종이에 적을 첫 줄

토큰 8을 읽으면 스택 [8]부터 시작해요.

왜 이렇게 푸는지 함께 따라가요

  1. 숫자 문자는 ch-'0'으로 정수로 바꿔요. 문자 8과 2를 차례로 넣어요.
  2. /에서 op2=2,op1=8이므로 8/2=4를 넣어요. 3을 넣은 뒤 -에서 4-3=1을 넣어요.
  3. 뺄셈과 나눗셈은 교환법칙이 없어서 pop 순서를 뒤집으면 결과가 달라져요.
  4. 이 예제는 일반 수식 파서가 아니에요. 공백 건너뛰기와 여러 자리 수 토큰화가 없으므로 입력 계약을 벗어난 식을 정상 계산하지 않아요.

[8]→[8,2]→[4]→[4,3]→[1], 결과 1. 먼저 꺼낸 값은 오른쪽 피연산자다. 코드는 숫자 여러 자리를 묶지 않고 공백도 숫자로 취급하므로 "12 3+"는 지원하지 않는다.

완성 답과 검산

[8]→[8,2]→[4]→[4,3]→[1], 결과 1. 먼저 꺼낸 값은 오른쪽 피연산자다. 코드는 숫자 여러 자리를 묶지 않고 공백도 숫자로 취급하므로 "12 3+"는 지원하지 않는다.

시작 조건에서 다시 추적한 결과가 위 답과 일치해요. 이 예제는 일반 수식 파서가 아니에요. 공백 건너뛰기와 여러 자리 수 토큰화가 없으므로 입력 계약을 벗어난 식을 정상 계산하지 않아요.

이 문제에서 조심할 점

표시된 switch는 뺄셈·나눗셈 부분만 발췌했어요. 강의 전체에는 +와 * 처리도 있어요.

설명을 닫고 다시 해 봐요

  1. 주어진 시작 상태와 필요한 입력 조건을 적어요.
  2. 첫 줄부터 연산 순서를 따라 답을 완성해요.
  3. 경계 경우와 오류 경로를 확인해요.

    <section id="s0"><h2>1. 스택을 C로 구현하기</h2>
<article class="topic" id="s0-array"><h3>배열·top을 함께 묶고 초기화하기</h3><div class="tags"><span class="tag date">1012 수업</span><span class="tag slide">S5 p11–13</span></div>
  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">그릇과 그릇의 맨 위 자리를 알려 주는 표를 한 가방에 넣어 함께 가져가요.</p><figure class="figure"><svg id="fig-array-bag" viewBox="0 0 340 118" role="img" aria-label="그릇 세 칸과 맨 위 자리를 가리키는 표가 한 테두리 안에 있는 그림"><rect class="fig-ink" x="12" y="12" width="316" height="94" rx="8"/><rect class="fig-accent" x="36" y="37" width="52" height="45"/><rect class="fig-accent" x="88" y="37" width="52" height="45"/><rect class="fig-accent" x="140" y="37" width="52" height="45"/><text class="fig-text" x="47" y="64">그릇</text><text class="fig-text" x="99" y="64">그릇</text><text class="fig-text" x="151" y="64">그릇</text><rect class="fig-ink" x="222" y="37" width="76" height="45"/><text class="fig-text" x="229" y="64">자리표</text></svg><figcaption>함께 들고 다니면 어느 표가 어느 그릇의 것인지 헷갈리지 않아요.</figcaption></figure></div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p>배열 스택은 값 저장 공간과 맨 위 원소의 인덱스인 <code>top</code>을 <code>StackType</code> 구조체로 묶어요. 스택마다 두 값이 짝을 이루므로 여러 스택을 만들 때도 서로 섞이지 않아요. 배열 인덱스가 0부터 시작하므로 <code>top</code>을 <code>-1</code>로 초기화하면 비어 있음을 뜻해요. 배열 칸의 기존 비트값을 모두 지울 필요는 없고, <code>top</code>까지만 유효한 원소로 다뤄요.</p><pre><code class="language-c">typedef int element;
typedef struct {
    element stack[MAX_STACK_SIZE];
    int top;
} StackType;

// 스택초기화함수
void init(StackType *s)
{
    s-&gt;top = -1;
}
// 공백상태검출함수
int is_empty(StackType *s)
{
    return (s-&gt;top == -1);
}
// 포화상태검출함수
int is_full(StackType *s)
{
    return (s-&gt;top == (MAX_STACK_SIZE-1));
}</code></pre><p>크기가 5라면 유효 인덱스는 0부터 4예요. <code>top == 4</code>이면 꽉 찼고, <code>top == -1</code>이면 비었어요. 저장 가능한 원소 수는 미리 정한 배열 크기로 제한돼요.</p></div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span><blockquote>“철가방같이 1층, 2층, 3층으로 해서 서로 다른 데이터 타입으로도 함께 다닐 수 있는 걸”</blockquote><p>(1012 Part 01) 교수님은 구조체를 철가방에 빗대며 배열과 <code>top</code>을 한 묶음으로 관리하는 이유를 강조했어요.</p></div>
  <div class="sum" hidden><p class="sum-lead">배열과 top을 묶고 top을 -1로 두면 빈 스택이에요.</p><p class="panel-label">용어</p><dl class="terms"><dt>StackType</dt><dd>배열과 top을 함께 담는 스택 구조체</dd><dt>top</dt><dd>현재 맨 위 원소의 인덱스</dd></dl></div>
</article>
<article class="topic" id="s0-pushpop"><h3>push·pop·peek의 C 코드</h3><div class="tags"><span class="tag date">1012 수업</span><span class="tag slide">S5 p11–14</span></div>
  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">새 접시는 맨 위에 얹고, 꺼낼 때도 맨 위 접시부터 들어요. 살짝 보기만 할 때는 접시를 그대로 둬요.</p><figure class="figure"><svg id="fig-array-ops" viewBox="0 0 340 130" role="img" aria-label="접시 두 장이 포개져 있고 위 접시로 올라가는 선과 내려오는 선이 있는 그림"><rect class="fig-ink" x="106" y="88" width="128" height="25" rx="8"/><rect class="fig-accent" x="106" y="62" width="128" height="25" rx="8"/><path class="fig-ink" d="M73 100 L73 42 L94 42 M94 42 L86 35 M94 42 L86 49"/><path class="fig-accent" d="M263 40 L263 101 L244 101 M244 101 L252 94 M244 101 L252 108"/><text class="fig-text" x="26" y="28">얹기</text><text class="fig-text" x="261" y="28">꺼내기</text></svg><figcaption>두 동작 모두 맨 위에서 일어나요.</figcaption></figure></div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p><code>push</code>는 먼저 포화를 검사하고, 빈 칸을 만들기 위해 <code>top</code>을 <strong>증가부터</strong> 시킨 다음 값을 써요. <code>pop</code>은 먼저 공백을 검사하고, 현재 <code>top</code>의 값을 반환할 표현식을 평가하면서 <code>top</code>을 감소시켜요. 호출자가 반환값을 받는 시점에는 감소가 끝나 있어요. <code>peek</code>는 같은 값을 읽되 <code>top</code>을 바꾸지 않아요.</p><pre><code class="language-c">// 삽입함수
void push(StackType *s, element item)
{
    if( is_full(s) ) {
        fprintf(stderr,"스택포화에러\n");
        return;
    }
    else s-&gt;stack[++(s-&gt;top)] = item;
}
// 삭제함수
element pop(StackType *s)
{
    if( is_empty(s) ) {
        fprintf(stderr, "스택공백에러\n");
        exit(1);
    }
    else return s-&gt;stack[(s-&gt;top)--];
}</code></pre><pre><code class="language-c">// 피크함수
element peek(StackType *s)
{
    if( is_empty(s) ) {
        fprintf(stderr, "스택공백에러\n");
        exit(1);
    }
    else return s-&gt;stack[s-&gt;top];
}</code></pre><p>예를 들어 <code>top = 1</code>, 원소가 <code>[7, 9]</code>라면 다음처럼 변해요.</p><ol class="steps"><li><code>push(4)</code>: <code>top</code>을 2로 증가시킨 뒤 인덱스 2에 4를 써요. 상태는 <code>[7, 9, 4]</code>예요.</li><li><code>peek()</code>: 4를 읽고 <code>top = 2</code>는 유지해요.</li><li><code>pop()</code>: 인덱스 2의 4를 반환값으로 정하고 <code>top</code>을 1로 줄여요. 호출자는 4를 받고 유효 상태는 <code>[7, 9]</code>예요.</li></ol><p>포화된 배열의 <code>push</code>는 오류를 출력하고 그 함수에서 돌아가요. 빈 스택의 <code>pop</code>·<code>peek</code>에 있는 <code>exit(1)</code>은 반복문만 빠져나오는 명령이 아니라 <strong>프로세스 전체를 종료</strong>해요.</p></div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span><blockquote>“증가부터 하고 써라.”</blockquote><p>(1012 Part 02) 앞의 <code>++</code>는 칸을 옮긴 뒤 그 칸에 저장한다는 강조예요. 수업 중 <code>exit(1)</code>을 “루프 구조를 빠져나오는” 것으로 설명했지만, 실제 C에서는 프로그램 실행을 종료해요.</p></div>
  <div class="sum" hidden><p class="sum-lead">push는 top을 올리고 쓰며 pop은 현재 값을 읽고 top을 내려요.</p><p class="panel-label">용어</p><dl class="terms"><dt>peek</dt><dd>맨 위 값을 제거하지 않고 읽는 연산</dd><dt>top</dt><dd>현재 맨 위 원소의 인덱스</dd></dl></div>
</article>
<article class="topic" id="s0-choice"><h3>입력 크기에 맞춰 구현 고르기</h3><div class="tags"><span class="tag date">1012 수업</span><span class="tag slide">S5 p15</span></div>
  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">손님 수가 정해져 있으면 정해진 의자를 놓으면 돼요. 얼마나 올지 모르면 손님이 올 때마다 의자를 더 놓는 방법이 편해요.</p><figure class="figure"><svg id="fig-choice" viewBox="0 0 340 115" role="img" aria-label="왼쪽에는 테두리로 고정된 세 칸, 오른쪽에는 선으로 이어진 세 칸과 다음 칸을 붙일 공간이 있는 그림"><rect class="fig-ink" x="15" y="38" width="126" height="45"/><path class="fig-ink" d="M57 38 L57 83 M99 38 L99 83"/><rect class="fig-accent" x="188" y="38" width="36" height="45"/><rect class="fig-accent" x="247" y="38" width="36" height="45"/><path class="fig-accent" d="M224 60 L247 60 M243 55 L247 60 L243 65 M283 60 L317 60 M312 55 L317 60 L312 65"/><text class="fig-text" x="23" y="28">정해진 자리</text><text class="fig-text" x="187" y="28">늘어나는 자리</text></svg><figcaption>들어올 양을 예상할 수 있는지가 선택의 기준이에요.</figcaption></figure></div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p><strong>배열</strong> 스택은 미리 정한 용량까지 연속된 공간을 써요. 예를 들어 입력이 언제나 <strong>100명</strong> 미만이라면 그 상한을 반영해 배열 크기를 정할 수 있어요. 반대로 실제 <strong>입력</strong>이 시험 때보다 훨씬 커질 수 있다면 고정 배열은 포화될 수 있어요. <strong>연결 스택</strong>은 원소마다 노드를 동적으로 할당하므로 미리 정한 배열 용량에 묶이지 않아요. 다만 사용 가능한 메모리까지 무한한 것은 아니며, 포인터와 할당 관리가 필요해요.</p><p>두 구현 모두 마지막에 넣은 값을 먼저 꺼내는 스택이에요. 교수님은 실제 입력 상한을 가늠하기 어려운 시험 문제에서 배열 크기를 작게 잡아 실패한 사례를 들었어요. 재귀(recursion)의 내부 호출 스택이 반드시 연결 스택이라는 뜻은 아니에요. 이 수업의 구현 선택 기준은 <em>문제의 입력 규모를 알고 있는가</em>예요.</p></div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span><blockquote>“입력 자체가 어떤 얼마나 커질지 얼마나 작을지 가늠하기 어려운 모델 조건”</blockquote><p>(1012 Part 02) 실제 데이터 양을 보고 저장 공간을 정하라는 취지예요.</p></div>
  <div class="sum" hidden><p class="sum-lead">입력 상한을 알면 배열, 가늠하기 어려우면 연결 스택을 고려해요.</p><p class="panel-label">용어</p><dl class="terms"><dt>배열 스택</dt><dd>고정 용량 배열로 구현한 스택</dd><dt>연결 스택</dt><dd>노드를 동적으로 연결해 구현한 스택</dd></dl></div>
</article>
<article class="topic" id="s0-node"><h3>노드와 top의 의미</h3><div class="tags"><span class="tag date">1012 수업</span><span class="tag slide">S5 p15–16</span></div>
  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">집의 방 하나를 가리키는 게 아니라 집 전체의 주소를 가리켜요. 그 집에는 물건과 다음 집 주소가 함께 있어요.</p><figure class="figure"><svg id="fig-node-top" viewBox="0 0 340 112" role="img" aria-label="맨 앞 주소를 나타내는 선이 값과 다음 주소가 함께 있는 첫 번째 노드 테두리로 향하고, 그 노드가 두 번째 노드로 이어지는 그림"><text class="fig-text" x="8" y="59">맨 앞</text><path class="fig-accent" d="M52 55 L91 55 M85 49 L91 55 L85 61"/><rect class="fig-ink" x="93" y="30" width="100" height="50"/><path class="fig-ink" d="M145 30 L145 80"/><text class="fig-text" x="103" y="60">값</text><text class="fig-text" x="150" y="60">다음</text><path class="fig-accent" d="M193 55 L233 55 M227 49 L233 55 L227 61"/><rect class="fig-ink" x="235" y="30" width="88" height="50"/><text class="fig-text" x="247" y="60">다음 집</text></svg><figcaption>맨 앞 표시는 첫 번째 집의 시작 주소를 기억해요.</figcaption></figure></div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p>각 <code>StackNode</code>는 저장할 <code>item</code>과 다음 노드를 가리키는 <code>link</code>를 가져요. <code>LinkedStackType</code>은 첫 노드의 주소인 <code>top</code>을 가져요. <code>top</code>은 <code>item</code> 필드만 가리키는 것이 아니라 노드 구조체 전체의 시작 주소를 가리켜요. 노드가 없다면 <code>top = NULL</code>이고 마지막 노드의 <code>link = NULL</code>이에요.</p><pre><code class="language-c">typedef int element;
typedef struct StackNode {
    element item;
    struct StackNode *link;
} StackNode;
typedef struct {
    StackNode *top;
} LinkedStackType;</code></pre><p>강의록 S5 p16의 typedef 별칭은 <code>StackeNode</code>로 인쇄되어 있어요. 바로 아래의 <code>StackNode *top</code> 및 다음 쪽 코드와 맞도록 여기서는 <code>StackNode</code>로 고쳤어요. 연결 스택의 초기 상태에서는 <code>top</code>을 <code>NULL</code>로 두어요.</p></div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span><blockquote>“방을 가리키는 게 아니고요, 101호를 가리키는 거”</blockquote><p>(1012 Part 02) 포인터가 노드의 개별 필드가 아닌 노드 시작 주소를 담는다는 비유예요.</p></div>
  <div class="sum" hidden><p class="sum-lead">top은 첫 StackNode의 시작 주소를 가리켜요.</p><p class="panel-label">용어</p><dl class="terms"><dt>StackNode</dt><dd>값과 다음 노드 주소를 담은 구조체</dd><dt>LinkedStackType</dt><dd>첫 노드 주소 top을 담은 구조체</dd><dt>NULL</dt><dd>가리키는 노드가 없음을 나타내는 포인터 값</dd></dl></div>
</article>
<article class="topic" id="s0-linkedpush"><h3>새 노드를 먼저 연결한 뒤 top 바꾸기</h3><div class="tags"><span class="tag date">1012 수업</span><span class="tag slide">S5 p17</span></div>
  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">새 집에 다음 집의 주소를 먼저 적어요. 그다음 맨 앞 표지판을 새 집으로 옮기면 기존 집을 잃지 않아요.</p><figure class="figure"><svg id="fig-linked-push" viewBox="0 0 340 125" role="img" aria-label="새 노드 테두리에서 기존 첫 노드로 향하는 선과, 맨 앞 표지에서 새 노드로 향하는 선을 그린 그림"><text class="fig-text" x="13" y="29">맨 앞 표지</text><path class="fig-accent" d="M71 33 L71 55 L93 55 M87 49 L93 55 L87 61"/><rect class="fig-accent" x="95" y="43" width="84" height="46"/><text class="fig-text" x="109" y="71">새 집</text><path class="fig-ink" d="M179 66 L231 66 M225 60 L231 66 L225 72"/><rect class="fig-ink" x="233" y="43" width="92" height="46"/><text class="fig-text" x="245" y="71">기존 집</text><text class="fig-muted" x="101" y="112">주소를 잇고 표지를 옮겨요</text></svg><figcaption>연결을 먼저 만들면 앞자리를 바꿔도 뒤가 이어져요.</figcaption></figure></div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p><code>malloc</code>으로 <code>StackNode</code> 크기의 메모리를 요청해요. 실패하면 <code>NULL</code>이므로 오류를 출력하고 돌아가요. 성공하면 값을 적고 <code>temp-&gt;link = s-&gt;top;</code>으로 기존 첫 노드를 연결한 다음, <code>s-&gt;top = temp;</code>로 새 노드를 맨 앞에 둬요. 순서를 바꾸면 기존 첫 노드의 주소를 잃어버릴 수 있어요.</p><pre><code class="language-c">// 삽입함수
void push(LinkedStackType *s, element item)
{
    StackNode *temp=(StackNode *)malloc(sizeof(StackNode));
    if( temp == NULL ){
        fprintf(stderr, "메모리할당에러\n");
        return;
    }
    else{
        temp-&gt;item = item;
        temp-&gt;link = s-&gt;top;
        s-&gt;top = temp;
    }
}</code></pre><ol class="steps"><li>처음에는 <code>top → C → B → A → NULL</code>이에요.</li><li>새 노드 <code>D</code>의 <code>link</code>에 기존 <code>top</code> 주소를 넣어요. <code>D → C → B → A → NULL</code> 연결이 생겨요.</li><li><code>top</code>을 <code>D</code>로 옮겨요. 최종 상태는 <code>top → D → C → B → A → NULL</code>이에요.</li></ol><p>맨 앞 노드만 연결하므로 새 노드를 연결하는 포인터 변경은 일정한 단계로 끝나요.</p></div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span><blockquote>“top부터 바꾸면 낙동강 오리알 된다 그랬어요.”</blockquote><p>(1012 Part 02) 새 노드가 기존 첫 노드를 가리키기 전에 <code>top</code>을 덮어쓰면 기존 연결을 잃는다는 뜻이에요.</p></div>
  <div class="sum" hidden><p class="sum-lead">새 노드를 기존 top에 연결한 뒤 top을 새 노드로 바꿔요.</p><p class="panel-label">용어</p><dl class="terms"><dt>malloc</dt><dd>새 노드에 쓸 메모리를 요청하는 함수</dd><dt>top</dt><dd>현재 첫 노드의 주소</dd></dl></div>

<article class="topic" id="s0-linkedpop"><h3>값을 보관하고 노드를 반납하기</h3><div class="tags"><span class="tag date">1012 수업</span><span class="tag slide">S5 p18</span></div>
  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">맨 앞 집의 물건과 다음 집 주소를 기억해요. 표지판을 다음 집으로 옮긴 뒤 빈 집을 치워요.</p><figure class="figure"><svg id="fig-linked-pop" viewBox="0 0 340 120" role="img" aria-label="맨 앞 표지가 첫 번째 노드에서 두 번째 노드로 옮겨지고 첫 번째 노드는 테두리로 표시된 그림"><text class="fig-text" x="14" y="25">맨 앞 표지</text><path class="fig-accent" d="M63 29 L63 47 L217 47 M211 41 L217 47 L211 53"/><rect class="fig-ink" x="67" y="64" width="95" height="40"/><text class="fig-muted" x="79" y="89">치울 집</text><rect class="fig-ink" x="219" y="64" width="97" height="40"/><text class="fig-text" x="231" y="89">다음 집</text><path class="fig-ink" d="M162 84 L219 84 M213 78 L219 84 L213 90"/></svg><figcaption>값을 꺼낼 때 집의 자리는 다음 집으로 넘겨요.</figcaption></figure></div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p>비어 있으면 <code>exit(1)</code>로 프로세스를 종료해요. 비어 있지 않으면 기존 첫 노드를 <code>temp</code>로 보관하고 그 노드의 값을 <code>item</code>에 복사해요. 그다음 <code>s-&gt;top = s-&gt;top-&gt;link;</code>로 다음 노드를 첫 노드로 만들어요. 마지막으로 <code>free(temp);</code>를 호출한 뒤 <code>return item;</code>으로 저장한 값을 돌려줘요. 해제한 노드의 필드를 다시 읽으면 안 돼요.</p><pre><code class="language-c">// 삭제함수
element pop(LinkedStackType *s)
{
    if( is_empty(s) ) {
        fprintf(stderr, "스택이비어있음\n");
        exit(1);
    }
    else{
        StackNode *temp=s-&gt;top;
        int item = temp-&gt;item;
        s-&gt;top = s-&gt;top-&gt;link;
        free(temp);
        return item;
    }
}</code></pre><p>여기서 <code>is_empty</code>는 연결 스택의 <code>top == NULL</code>을 검사해야 해요. S5 p18은 그 구현을 함께 싣지 않았어요.</p><ol class="steps"><li>처음은 <code>top → C → B → A → NULL</code>이고 <code>temp</code>와 <code>item</code>에 첫 노드 주소와 값 C를 각각 보관해요.</li><li><code>top</code>을 B로 옮기면 유효한 연결은 <code>top → B → A → NULL</code>이에요.</li><li>C 노드의 메모리를 반납하고 보관한 값 C를 반환해요.</li></ol><p>첫 노드만 다루므로 첫 노드를 옮기고 해제하는 순서를 지켜요.</p></div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span><blockquote>“얘를 return 받고 얘도 free시켜”</blockquote><p>(1012 Part 02–03) 반환할 값은 해제 전에 별도 변수에 보관해야 해요.</p></div>
  <div class="sum" hidden><p class="sum-lead">첫 노드 값을 보관하고 top을 옮긴 뒤 기존 노드를 해제해요.</p><p class="panel-label">용어</p><dl class="terms"><dt>free</dt><dd>동적으로 할당한 노드 메모리를 반납하는 함수</dd><dt>temp</dt><dd>해제할 기존 첫 노드를 잠시 가리키는 포인터</dd></dl></div>

  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">열린 문을 차곡차곡 기억해요. 닫는 문이 나오면 방금 기억한 문과 짝이 맞는지 봐요.</p><figure class="figure"><svg id="fig-matching" viewBox="0 0 340 140" role="img" aria-label="열린 문 둘이 세로로 쌓이고 맨 위 문을 먼저 꺼내 오른쪽의 닫는 문과 짝을 맞추는 그림"><text class="fig-text" x="26" y="24">기억한 문</text><rect class="fig-ink" x="28" y="83" width="105" height="35"/><text class="fig-text" x="42" y="106">먼저 연 문</text><rect class="fig-accent" x="28" y="46" width="105" height="35"/><text class="fig-text" x="40" y="69">나중 문</text><path class="fig-accent" d="M135 63 L216 63 M210 57 L216 63 L210 69"/><rect class="fig-ink" x="220" y="46" width="95" height="35"/><text class="fig-text" x="232" y="69">닫는 문</text></svg><figcaption>마지막에 열었던 문을 먼저 살펴요.</figcaption></figure></div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p><code>check_matching</code>은 문자열을 왼쪽부터 읽어요. <code>(</code>, <code>[</code>, <code>{</code>이면 <code>push</code>하고, 닫는 괄호이면 스택이 <strong>비어</strong> 있는지 먼저 확인해요. 비었다면 짝 없는 닫는 괄호라 즉시 실패해요. 아니면 <code>open_ch</code>를 꺼내 현재 닫는 괄호와 종류를 맞춰요. 끝까지 읽은 뒤에도 스택이 비어 있지 않으면 열린 괄호가 남았으므로 실패해요.</p>
<ol class="steps"><li>입력이 끝날 때까지 다음 글자를 읽어요.</li><li>왼쪽 괄호라면 스택에 넣어요.</li><li>오른쪽 괄호라면 빈 스택인지 검사하고, 비지 않았다면 꺼낸 open_ch와 종류를 비교해요. 비었거나 짝이 다르면 오류예요.</li><li>입력이 끝나면 스택이 비었는지 검사해 남은 왼쪽 괄호가 있으면 오류, 없으면 성공이에요.</li></ol>
<p>이 절차는 S5 p22의 의사코드를 읽기 쉽게 풀어쓴 것이에요. 강의록에는 마지막 <code>case</code>가 <code>']'</code>로 한 번 더 적혀 있지만, 오른쪽 중괄호 <code>'}'</code>가 맞아요.</p>
<ol class="steps"><li><code>if((i==0)&amp;&amp;(j==0)</code>: 첫 두 <code>(</code>을 쌓고, <code>i==0</code>의 <code>)</code>로 하나를 꺼내요. <code>j==0</code>을 여는 <code>(</code>을 쌓았다가 닫아도 맨 처음 <code>(</code> 하나가 남아 실패해요.</li><li><code>{ A[(i+1)]=0; }</code>: <code>{</code>, <code>[</code>, <code>(</code>을 차례로 쌓아요. <code>)</code>, <code>]</code>, <code>}</code>가 역순으로 각각 매칭되고 빈 스택으로 끝나 성공해요.</li></ol><p>문자열을 한 글자씩 읽고 열린 괄호를 스택에 기억해요.</p></div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span><blockquote>“왼쪽 괄호가 나오면 무조건 push를 합니다.”</blockquote><p>(1012 Part 03) 닫는 괄호는 직전에 열린 짝과 비교해요.</p></div>
  <div class="sum" hidden><p class="sum-lead">닫는 괄호를 읽을 때 스택이 비거나 짝이 다르면 실패해요.</p><p class="panel-label">용어</p><dl class="terms"><dt>check_matching</dt><dd>스택으로 괄호 짝을 확인하는 알고리즘</dd><dt>open_ch</dt><dd>스택에서 꺼낸 왼쪽 괄호</dd></dl></div>

  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">같은 계산도 말하는 순서를 다르게 적을 수 있어요. 먼저 해야 할 계산은 언제나 먼저 끝내야 해요.</p><figure class="figure"><svg id="fig-notation" viewBox="0 0 340 140" role="img" aria-label="두 수의 순서를 유지하면서 계산 표시를 앞, 사이, 뒤에 두는 세 가지 줄의 그림"><text class="fig-text" x="22" y="32">앞</text><text class="fig-text" x="22" y="68">사이</text><text class="fig-text" x="22" y="104">뒤</text><rect class="fig-accent" x="79" y="13" width="73" height="26"/><text class="fig-text" x="87" y="32">계산 표시</text><text class="fig-text" x="176" y="32">첫 수   다음 수</text><text class="fig-text" x="84" y="68">첫 수</text><rect class="fig-accent" x="154" y="49" width="73" height="26"/><text class="fig-text" x="162" y="68">계산 표시</text><text class="fig-text" x="245" y="68">다음 수</text><text class="fig-text" x="84" y="104">첫 수   다음 수</text><rect class="fig-accent" x="234" y="85" width="73" height="26"/><text class="fig-text" x="242" y="104">계산 표시</text></svg><figcaption>표시의 위치가 달라도 계산 뜻은 같아요.</figcaption></figure></div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p><strong>중위</strong> 표기는 연산자를 피연산자 사이에, <strong>전위</strong> 표기는 앞에, <strong>후위</strong> 표기는 뒤에 적어요. 예를 들어 중위 <code>2+3*4</code>는 전위 <code>+ 2 * 3 4</code>, 후위 <code>2 3 4 * +</code>예요. 곱셈을 먼저 계산하므로 <code>2 3 + 4 *</code>로 바꾸면 다른 뜻이 돼요.</p><ol class="steps"><li>후위 <code>2 3 4 * +</code>에서 <code>3 4 *</code>를 계산해 12를 얻어요.</li><li><code>2 12 +</code>를 계산하면 <strong>14</strong>예요.</li></ol><p>강의록은 <code>2+3*4</code>를 후위식으로 바꿔 스택으로 계산하는 절차를 소개해요. 이는 이 장의 <em>수식 처리 알고리즘</em>이며 모든 컴파일러나 CPU가 실제로 반드시 후위 문자열로 바꾼다는 뜻은 아니에요.</p></div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span><blockquote>“연산자 우선순위까지 고려해서 위치를 바꿔 줘야 됩니다.”</blockquote><p>(1012 Part 04) 표시 위치만 바꾸면 계산 의미가 달라질 수 있어요.</p></div>
  <div class="sum" hidden><p class="sum-lead">2+3*4는 후위 2 3 4 * +로 바꾸며 결과는 14예요.</p><p class="panel-label">용어</p><dl class="terms"><dt>중위</dt><dd>연산자가 두 피연산자 사이에 있는 표기</dd><dt>후위</dt><dd>연산자가 해당 피연산자 뒤에 있는 표기</dd><dt>전위</dt><dd>연산자가 해당 피연산자 앞에 있는 표기</dd></dl></div>

<article class="topic" id="s1-eval"><h3>후위식에서 피연산자 순서 지키기</h3><div class="tags"><span class="tag date">1012 수업</span><span class="tag slide">S5 p24–26</span></div>
  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">숫자를 차곡차곡 쌓아 두었다가 계산 표시가 나오면 위의 둘을 꺼내요. 두 번째로 꺼낸 수가 계산의 앞자리에 와요.</p><figure class="figure"><svg id="fig-eval" viewBox="0 0 340 140" role="img" aria-label="수 둘이 세로로 쌓여 있고 위 수가 먼저 오른쪽 자리로, 아래 수가 다음에 왼쪽 자리로 옮겨지는 그림"><rect class="fig-ink" x="22" y="83" width="75" height="34"/><text class="fig-text" x="35" y="106">아래 수</text><rect class="fig-accent" x="22" y="46" width="75" height="34"/><text class="fig-text" x="35" y="69">위 수</text><path class="fig-accent" d="M99 63 L234 63 L234 82 M228 76 L234 82 L240 76"/><path class="fig-ink" d="M99 100 L133 100 M127 94 L133 100 L127 106"/><rect class="fig-ink" x="139" y="83" width="74" height="34"/><text class="fig-text" x="151" y="106">앞자리</text><rect class="fig-accent" x="237" y="83" width="82" height="34"/><text class="fig-text" x="249" y="106">뒷자리</text></svg><figcaption>나누기와 빼기는 두 수의 자리를 바꾸면 답이 달라져요.</figcaption></figure></div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p>후위식은 피연산자이면 쌓고, 연산자이면 두 값을 꺼내 계산 결과를 다시 쌓아요. 먼저 꺼낸 값이 <code>second</code>, 다음이 <code>first</code>이므로 계산은 <code>first op second</code>예요. 특히 <code>8 / 2</code>와 <code>4 - 3</code>을 뒤집지 않도록 해요. 수업의 식 <code>8 2 / 3 - 3 2 * +</code>를 따라가요.</p>
<ol class="steps"><li><code>8</code>을 쌓아요: <code>[8]</code>.</li><li><code>2</code>를 쌓아요: <code>[8, 2]</code>.</li><li><code>/</code>: 2를 <code>second</code>, 8을 <code>first</code>로 꺼내 <code>8 / 2 = 4</code>를 쌓아요: <code>[4]</code>.</li><li><code>3</code>을 쌓아요: <code>[4, 3]</code>.</li><li><code>-</code>: <code>4 - 3 = 1</code>을 쌓아요: <code>[1]</code>.</li><li><code>3</code>, <code>2</code>를 차례로 쌓아요: <code>[1, 3, 2]</code>.</li><li><code>*</code>: <code>3 * 2 = 6</code>을 쌓아요: <code>[1, 6]</code>.</li><li><code>+</code>: <code>1 + 6 = 7</code>을 쌓아요: <code>[7]</code>.</li></ol><p>마지막 한 값 <strong>7</strong>이 결과예요. 연산자 앞에 값이 두 개보다 적거나 끝에 값이 여러 개 남으면 정상적인 이항 연산식이 아니에요. 각 토큰을 왼쪽부터 차례대로 처리해요.</p></div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span><blockquote>“먼저 꺼내는 애가 어떻게 돼요? 두 번째 연산자가 됩니다.”</blockquote><p>(1012 Part 04) 연산 순서가 중요한 나눗셈과 뺄셈에서 확인해야 해요.</p></div>
  <div class="sum" hidden><p class="sum-lead">먼저 꺼낸 수가 second이고 다음 수가 first라서 결과는 7이에요.</p><p class="panel-label">용어</p><dl class="terms"><dt>second</dt><dd>먼저 꺼낸 오른쪽 피연산자</dd><dt>first</dt><dd>나중에 꺼낸 왼쪽 피연산자</dd></dl></div>
</article>
<article class="topic" id="s1-evalcode"><h3>문자를 숫자로 바꾸는 C 코드</h3><div class="tags"><span class="tag date">1012 수업</span><span class="tag slide">S5 p27</span></div>
  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">종이에 적힌 숫자 모양을 계산할 수 있는 숫자로 바꿔요. 계산한 답은 다시 쌓아 두어요.</p><figure class="figure"><svg id="fig-evalcode" viewBox="0 0 340 140" role="img" aria-label="숫자로 적힌 글자 모양이 계산할 수 있는 값으로 바뀌고 아래의 계산 자리로 내려가는 그림"><rect class="fig-ink" x="18" y="29" width="91" height="44"/><text class="fig-text" x="37" y="57">글자</text><path class="fig-accent" d="M110 51 L170 51 M164 45 L170 51 L164 57"/><rect class="fig-accent" x="174" y="29" width="91" height="44"/><text class="fig-text" x="193" y="57">숫자 값</text><path class="fig-ink" d="M218 75 L218 101 M212 95 L218 101 L224 95"/><text class="fig-muted" x="159" y="125">계산 자리로 가요</text></svg><figcaption>읽은 글자를 수로 바꾼 뒤 계산해요.</figcaption></figure></div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p>강의록의 <code>eval</code>은 문자열을 한 글자씩 읽어요. 이 예시는 한 자리 숫자만 다루므로 <code>value = ch - '0';</code>으로 숫자 문자를 정수 값으로 바꿔요. 연산자이면 <code>op2 = pop(&amp;s);</code>로 오른쪽 값을 먼저 꺼내고 <code>op1 = pop(&amp;s);</code>로 왼쪽 값을 꺼내요. 각 연산 결과를 다시 쌓은 뒤 마지막 값을 반환해요.</p>
<pre><code class="language-c">// 후위표기수식계산함수
int eval(char exp[])
{
    int op1, op2, value, i=0;
    int len = strlen(exp);
    char ch;
    StackType s;
    init(&amp;s);
    for( i=0; i&lt;len; i++){
        ch = exp[i];
        if( ch != '+' &amp;&amp; ch != '-' &amp;&amp; ch != '*' &amp;&amp; ch != '/' ){
            value = ch - '0';
            push(&amp;s, value);
        }
        else{
            op2 = pop(&amp;s);
            op1 = pop(&amp;s);
            switch(ch){
                case '+': push(&amp;s,op1+op2); break;
                case '-': push(&amp;s,op1-op2); break;
                case '*': push(&amp;s,op1*op2); break;
                case '/': push(&amp;s,op1/op2); break;
            }
        }
    }
    return pop(&amp;s);
}</code></pre><p>슬라이드의 함수 선언에는 반환형이 생략되어 있어요. 실제 C 코드로 사용하려면 <code>int eval(char exp[])</code>처럼 반환형을 명시해야 해요. 이 예시에는 공백·다자리 수·잘못된 문자·0으로 나누기 검사가 없으므로 그런 입력까지 처리하는 일반 계산기로 보아서는 안 돼요.</p></div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span><blockquote>“character로 들어왔을 거거든요, string에서. 근데 수치잖아요, 계산해야 되니까.”</blockquote><p>(1012 Part 04) 문자와 정수 값을 구분해야 한다는 설명이에요.</p></div>
  <div class="sum" hidden><p class="sum-lead">숫자 문자는 0 문자를 빼서 한 자리 정수로 만들어요.</p><p class="panel-label">용어</p><dl class="terms"><dt>eval</dt><dd>한 자리 후위식의 계산 함수</dd><dt>op2</dt><dd>먼저 꺼낸 오른쪽 피연산자</dd><dt>op1</dt><dd>나중에 꺼낸 왼쪽 피연산자</dd></dl></div>
</article>
<article class="topic" id="s1-convert"><h3>우선순위와 괄호로 중위식을 바꾸기</h3><div class="tags"><span class="tag date">1012 수업</span><span class="tag slide">S5 p28–36</span></div>
  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">숫자나 글자는 그대로 읽은 순서에 놓아요. 계산 표시는 차례를 살펴 잠깐 기다리게 해요.</p><figure class="figure"><svg id="fig-convert" viewBox="0 0 340 140" role="img" aria-label="글자는 곧장 출력 쪽으로 향하고 계산 표시는 잠시 세로 스택에서 기다리는 그림"><rect class="fig-ink" x="15" y="50" width="77" height="40"/><text class="fig-text" x="27" y="76">읽기</text><path class="fig-ink" d="M93 62 L199 62 M193 56 L199 62 L193 68"/><rect class="fig-ink" x="204" y="47" width="114" height="46"/><text class="fig-text" x="223" y="75">글자 출력</text><path class="fig-accent" d="M53 91 L53 119 L127 119 M121 113 L127 119 L121 125"/><rect class="fig-accent" x="131" y="103" width="91" height="31"/><text class="fig-text" x="142" y="124">차례 대기</text></svg><figcaption>글자의 순서는 지키고 계산 차례만 정해요.</figcaption></figure></div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p>중위식을 후위식으로 바꿀 때 <strong>피연산자</strong>는 바로 출력해요. 연산자만 스택에 보관해요. 새 연산자보다 스택 위 연산자의 우선순위가 <strong>높거나 같</strong>으면 그 연산자를 먼저 꺼내 출력해요. 같을 때도 꺼내는 것은 이 수업의 이항 <code>+</code>, <code>-</code>, <code>*</code>, <code>/</code>를 왼쪽부터 계산하기 위해서예요. <code>peek</code>으로 스택 위 연산자를 확인해요.</p><p>예를 들어 <code>A+B*C</code>는 A를 출력하고 +를 쌓은 뒤 B를 출력해요. *는 +보다 우선순위가 높으므로 쌓아요. C를 출력하고 끝에 *와 +를 꺼내 <code>A B C * +</code>가 돼요. 반대로 <code>(A+B)*C</code>는 괄호가 A+B를 먼저 묶어요.</p>
<ol class="steps"><li><code>(</code>: 스택 <code>[(]</code>, 출력은 비어요.</li><li><code>A</code>: 스택 <code>[(]</code>, 출력 <code>A</code>.</li><li><code>+</code>: 스택 <code>[(, +]</code>, 출력 <code>A</code>.</li><li><code>B</code>: 스택 <code>[(, +]</code>, 출력 <code>A B</code>.</li><li><code>)</code>: +를 꺼내 출력하고 (는 버려요. 스택 <code>[]</code>, 출력 <code>A B +</code>.</li><li><code>*</code>: 스택 <code>[*]</code>, 출력 <code>A B +</code>.</li><li><code>C</code>: 스택 <code>[*]</code>, 출력 <code>A B + C</code>.</li><li>끝: *를 꺼내 출력해 최종 <code>A B + C *</code>예요.</li></ol><p>왼쪽 괄호는 밖의 연산자가 안쪽으로 끼어들지 못하게 경계를 만들고, 오른쪽 괄호를 만나면 그 경계까지 꺼내요. 괄호 자체는 출력하지 않아요.</p></div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span><blockquote>“높거나 같아도 나와야 됩니다.”</blockquote><p>(1012 Part 05) 같은 우선순위의 왼쪽 결합 연산자는 먼저 나온 것을 먼저 처리해요.</p></div>
  <div class="sum" hidden><p class="sum-lead">피연산자는 바로 출력하고 연산자는 우선순위에 따라 꺼내요.</p><p class="panel-label">용어</p><dl class="terms"><dt>peek</dt><dd>스택 위 연산자를 제거하지 않고 확인하는 연산</dd><dt>피연산자</dt><dd>계산을 받는 값 또는 이름</dd></dl></div>
</article>

  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">읽을 것이 끝나도 기다리는 계산 표시가 남을 수 있어요. 남은 것을 맨 위부터 차례로 내보내요.</p><figure class="figure"><svg id="fig-convertalgo" viewBox="0 0 340 140" role="img" aria-label="기다리던 계산 표시 두 개가 세로 스택에서 위부터 순서대로 출력되는 그림"><rect class="fig-ink" x="37" y="82" width="95" height="35"/><text class="fig-text" x="53" y="105">먼저 둠</text><rect class="fig-accent" x="37" y="45" width="95" height="35"/><text class="fig-text" x="53" y="68">나중 둠</text><path class="fig-accent" d="M133 61 L230 61 M224 55 L230 61 L224 67"/><rect class="fig-ink" x="235" y="43" width="87" height="40"/><text class="fig-text" x="251" y="69">출력</text></svg><figcaption>마지막에 남은 것까지 모두 내보내야 해요.</figcaption></figure></div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p><code>infix_to_postfix</code>는 입력을 끝까지 읽고도 스택이 <code>empty</code>가 아닐 수 있음을 고려해요. 피연산자를 즉시 <strong>출력</strong>하고, 연산자를 읽으면 더 높거나 같은 우선순위의 연산자를 먼저 출력한 뒤 새 연산자를 쌓아요. <strong>왼쪽 괄호</strong>는 쌓고 오른쪽 괄호를 읽으면 왼쪽 괄호가 나올 때까지 연산자를 출력해요. 입력이 끝나면 남은 연산자를 모두 꺼내요.</p>
<ol class="steps"><li>다음 문자가 피연산자면 바로 출력해요.</li><li>연산자면 스택이 비지 않았고 왼쪽 괄호 경계가 아니며 peek의 우선순위가 높거나 같은 동안 꺼내 출력한 다음 새 연산자를 넣어요.</li><li>왼쪽 괄호는 넣고, 오른쪽 괄호는 왼쪽 괄호까지 꺼내되 괄호는 출력하지 않아요.</li><li>입력을 다 읽으면 스택이 empty가 될 때까지 남은 연산자를 꺼내 출력해요.</li></ol><p>강의록 S5 p37의 의사코드에 생략된, <code>peek(s)</code> 전에 공백을 확인하는 단계를 명시했어요. 정상적인 입력이라면 마지막에 왼쪽 괄호가 남지 않아요. 예를 들어 <code>A+B*C</code>를 C까지 읽었을 때 출력은 <code>A B C</code>, 스택은 아래부터 <code>[+, *]</code>예요. 끝에서 *와 +를 차례로 꺼내 <code>A B C * +</code>로 마쳐요.</p></div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span><blockquote>“몇 개가 남아 있든 얘 빼 주고 바닥까지 다”</blockquote><p>(1012 Part 05) 마지막 출력 단계에서 연산자를 하나만 꺼내고 멈추면 식이 불완전해져요.</p></div>
  <div class="sum" hidden><p class="sum-lead">입력이 끝나면 스택의 남은 연산자 전부를 출력해요.</p><p class="panel-label">용어</p><dl class="terms"><dt>infix_to_postfix</dt><dd>중위 표기를 후위 표기로 바꾸는 절차</dd><dt>empty</dt><dd>스택에 원소가 없는 상태</dd></dl></div>

  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p>강의록의 미로는 벽을 1, 갈 수 있는 칸을 0으로 나타내요. 현재 위치를 <strong>방문</strong> 처리하고 아직 방문하지 않았으며 갈 수 있는 이웃 위치를 스택에 쌓아요. 그다음 맨 위 후보를 꺼내 현재 위치로 삼아요. 후보가 없으면 실패하고 <strong>출구</strong>에 도달하면 성공해요. 방문 표시는 같은 칸을 다시 후보로 넣어 무한히 돌지 않게 해요.</p><p>수업에서 갈림길에 <strong>리본</strong>을 묶는 비유로 설명한 추적이에요. 교수님은 한쪽 벽만 따라가다 섬처럼 떨어진 벽 때문에 같은 자리를 반복했던 미로 공원 경험도 들었어요. 아래 스택은 <em>아직 조사하지 않은 후보</em>를 아래부터 위 순서로 적은 것이며, 로봇이 실제로 걸은 모든 칸의 경로 기록은 아니에요.</p>
<ol class="steps"><li>시작 <code>(1, 0)</code>에서 <code>(1, 1)</code>을 쌓았다 꺼내 이동해요. 후보 스택은 <code>[]</code>예요.</li><li><code>(1, 1)</code>에서 <code>(2, 1)</code>을 먼저, <code>(1, 2)</code>를 나중에 쌓아요. 스택 <code>[(2, 1), (1, 2)]</code>에서 <code>(1, 2)</code>를 꺼내요.</li><li><code>(1, 2)</code>에서 <code>(1, 3)</code>을 쌓았다 꺼내요. 남은 후보는 <code>[(2, 1)]</code>이에요.</li><li><code>(1, 3)</code>에서 <code>(2, 3)</code>을 먼저, <code>(1, 4)</code>를 나중에 쌓아요. 스택 <code>[(2, 1), (2, 3), (1, 4)]</code>에서 <code>(1, 4)</code>를 꺼내요.</li><li><code>(1, 4)</code>는 막다른 길이라 새 후보가 없어요. 남은 스택의 위 <code>(2, 3)</code>을 꺼내며 스택은 <code>[(2, 1)]</code>이에요. 그림의 이 이동은 후보 선택을 압축해 나타낸 것이고, 실제 되돌아가는 걸음은 따로 기록해야 해요.</li><li><code>(2, 3)</code>에서 <code>(3, 3)</code>을 쌓았다 꺼내요. 스택은 <code>[(2, 1)]</code>이에요.</li><li><code>(3, 3)</code>에서 <code>(4, 3)</code>을 먼저, <code>(3, 4)</code>를 나중에 쌓고 <code>(3, 4)</code>로 이동해요. 스택은 <code>[(2, 1), (4, 3)]</code>이에요.</li><li><code>(3, 4)</code>에서 <code>(3, 5)</code>를 쌓았다 꺼내 <strong>출구</strong>에 도달해요. <code>(2, 1)</code>과 <code>(4, 3)</code>은 후보로 남아 있어도 탐색은 끝나요.</li></ol><p>후보 스택은 다음 탐색 대상을 고를 뿐, <code>(1, 4)</code>에서 <code>(2, 3)</code>까지의 물리적 이동 경로를 자동으로 알려 주지는 않아요.</p></div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span><blockquote>“먼저 처리하고 싶은 애가 top에 올라오게 push를 해야 됩니다.”</blockquote><p>(1012 Part 06) 다음에 먼저 볼 후보를 나중에 넣는다는 뜻이에요.</p></div>
  <div class="sum" hidden><p class="sum-lead">스택에는 다음 후보가 남고 출구에 닿으면 후보가 남아도 끝나요.</p><p class="panel-label">용어</p><dl class="terms"><dt>방문</dt><dd>이미 조사한 칸임을 표시하는 것</dd><dt>출구</dt><dd>탐색이 성공하는 목표 위치</dd></dl></div>

    <section id="s2"><h2>3. 큐가 필요한 이유와 구조</h2>
<article class="topic" id="s2-fifo"><h3>먼저 들어온 것을 먼저 꺼내기</h3><div class="tags"><span class="tag date">1012 수업</span><span class="tag slide">S6 p2–3</span></div>
  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">줄을 선 순서대로 차례가 와요.</p><figure class="figure"><svg id="fig-s2-fifo" viewBox="0 0 430 125" role="img" aria-label="세 사람이 줄을 서고 맨 앞 사람이 먼저 나가는 모습"><rect class="fig-ink" x="26" y="35" width="88" height="54" rx="8"/><rect class="fig-ink" x="152" y="35" width="88" height="54" rx="8"/><rect class="fig-ink" x="278" y="35" width="88" height="54" rx="8"/><text class="fig-text" x="70" y="67" text-anchor="middle">첫째</text><text class="fig-text" x="196" y="67" text-anchor="middle">둘째</text><text class="fig-text" x="322" y="67" text-anchor="middle">셋째</text><path class="fig-accent" d="M137 62h-15m-6-6-6 6 6 6M263 62h-15m-6-6-6 6 6 6"/><text class="fig-muted" x="70" y="112" text-anchor="middle">먼저 나가요</text></svg><figcaption>앞에서 기다린 사람이 먼저 나가요.</figcaption></figure></div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p>큐(queue)는 선입선출(FIFO: First-In First-Out) 자료구조예요. 먼저 들어온 요소가 먼저 나가요. 스택과 달리 삽입과 삭제가 양 끝에서 일어나요. 전단(front)에서 꺼내고 후단(rear)에 넣어요.</p><p>큐 추상 데이터 타입(ADT)의 연산은 <code>create()</code> 생성, <code>init(q)</code> 초기화, <code>is_empty(q)</code> 공백 검사, <code>is_full(q)</code> 포화 검사, <code>enqueue(q, e)</code> 후단 삽입, <code>dequeue(q)</code> 전단 요소 반환과 삭제, <code>peek(q)</code> 전단 요소를 삭제하지 않고 반환하기예요. 삽입·삭제 위치를 호출자가 따로 지정하지 않아요.</p><ol class="steps"><li>빈 큐에 A를 enqueue하면 대기 순서는 A예요.</li><li>B를 enqueue하면 대기 순서는 A, B예요.</li><li>dequeue하면 A를 꺼내고 B가 앞에 남아요.</li><li>peek하면 B를 읽고 큐의 내용은 그대로예요.</li></ol></div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span><p>매표소 대기열과 빨대 안의 음료를 비유로 들었어요. 빨대에 먼저 들어온 것이 먼저 입에 닿듯 큐도 순서를 지켜요. “순서, 들어온 순서를 유지하는 게 매우 중요한 자료구조입니다.” (1012 Part 06, 시각 미제공)</p></div>
  <div class="sum" hidden><p class="sum-lead">큐는 먼저 들어온 요소를 앞에서 먼저 꺼내요.</p><p class="panel-label">용어</p><dl class="terms"><dt>선입선출(FIFO: First-In First-Out)</dt><dd>먼저 들어온 요소가 먼저 나가는 순서예요.</dd><dt>enqueue</dt><dd>큐의 후단에 요소를 넣어요.</dd><dt>dequeue</dt><dd>큐의 전단 요소를 꺼내요.</dd></dl></div>
</article>

<article class="topic" id="s2-buffer"><h3>생산자와 소비자 사이에서 기다리기</h3><div class="tags"><span class="tag date">1012 수업</span><span class="tag slide">S6 p4</span></div>
  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">보내는 쪽이 빠르고 받는 쪽이 느리면, 보낸 것을 줄 세워 잠시 기다리게 해요.</p><figure class="figure"><svg id="fig-s2-buffer" viewBox="0 0 460 130" role="img" aria-label="보내는 사람과 받는 사람 사이에 세 물건이 줄지어 기다리는 모습"><rect class="fig-ink" x="12" y="39" width="86" height="50" rx="8"/><text class="fig-text" x="55" y="69" text-anchor="middle">보내요</text><rect class="fig-accent" x="144" y="29" width="180" height="70" rx="8"/><rect class="fig-ink" x="157" y="43" width="42" height="42" rx="5"/><rect class="fig-ink" x="209" y="43" width="42" height="42" rx="5"/><rect class="fig-ink" x="261" y="43" width="42" height="42" rx="5"/><rect class="fig-ink" x="366" y="39" width="82" height="50" rx="8"/><text class="fig-text" x="407" y="69" text-anchor="middle">받아요</text><path class="fig-accent" d="M104 64h29m-7-6 7 6-7 6M329 64h25m-7-6 7 6-7 6"/><text class="fig-muted" x="234" y="120" text-anchor="middle">기다리는 자리</text></svg><figcaption>중간에 기다리는 자리를 만들어요.</figcaption></figure></div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p>생산자(producer)는 데이터를 만들고 소비자(consumer)는 데이터를 처리해요. 생산자가 더 빠르거나 두 쪽의 속도가 다르면, 중간의 버퍼(buffer)가 데이터를 순서대로 보관해요. 큐는 이 버퍼를 구현하기 좋은 자료구조예요. 프린터는 컴퓨터가 보낸 출력 작업을 물리적으로 인쇄하는 데 시간이 걸려요. 인쇄 대기열은 먼저 요청된 작업부터 처리해요. 통신 패킷의 대기열도 응용 사례예요.</p><p>시뮬레이션(simulation)은 실제 상황을 소프트웨어로 모의실험하는 일이에요. 공항에서는 항공기 이착륙과 연착에 따른 대기를, 은행에서는 시간대별 고객 대기와 행원 수를 모델링할 수 있어요. 교수는 은행의 점심시간 인력을 줄였을 때 고객 평균 대기시간이 어떻게 바뀔지 시험하는 예를 들었어요. 이 수업은 사례의 목적을 설명했으며 구체적인 시뮬레이션 코드는 다루지 않았어요.</p></div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span><p>컴퓨터가 명령을 보내는 속도와 프린터가 종이를 찍는 속도의 차이를 비교했어요. 은행주가 적은 인력으로 대기시간을 관리하려고 여러 인력 배치를 모의실험하는 사례도 들었어요. “둘 사이에 속도 차이가 클 때 잠깐 데이터가 순서대로 머물러야 될 자리가 필요해요.” (1012 Part 07, 시각 미제공)</p></div>
  <div class="sum" hidden><p class="sum-lead">속도가 다른 두 작업 사이에서 큐가 데이터를 순서대로 기다리게 해요.</p><p class="panel-label">용어</p><dl class="terms"><dt>생산자(producer)</dt><dd>데이터를 만들어요.</dd><dt>소비자(consumer)</dt><dd>데이터를 처리해요.</dd><dt>버퍼(buffer)</dt><dd>처리 전 데이터를 순서대로 보관해요.</dd></dl></div>
</article>

<article class="topic" id="s2-linear"><h3>선형 배열에서 빈자리를 못 쓰는 문제</h3><div class="tags"><span class="tag date">1012 수업</span><span class="tag slide">S6 p5</span></div>
  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">긴 의자의 앞자리가 비어도 새 사람이 끝자리 뒤에만 서면 자리가 없다고 느껴져요.</p><figure class="figure"><svg id="fig-s2-linear" viewBox="0 0 460 140" role="img" aria-label="여섯 칸 중 앞의 두 칸은 비고 뒤의 네 칸에 사람이 있어 맨 끝 뒤에는 자리가 없는 모습"><rect class="fig-ink" x="16" y="38" width="62" height="60"/><rect class="fig-ink" x="78" y="38" width="62" height="60"/><rect class="fig-ink" x="140" y="38" width="62" height="60"/><rect class="fig-ink" x="202" y="38" width="62" height="60"/><rect class="fig-ink" x="264" y="38" width="62" height="60"/><rect class="fig-ink" x="326" y="38" width="62" height="60"/><text class="fig-muted" x="47" y="74" text-anchor="middle">빈칸</text><text class="fig-muted" x="109" y="74" text-anchor="middle">빈칸</text><text class="fig-text" x="171" y="74" text-anchor="middle">가</text><text class="fig-text" x="233" y="74" text-anchor="middle">나</text><text class="fig-text" x="295" y="74" text-anchor="middle">다</text><text class="fig-text" x="357" y="74" text-anchor="middle">라</text><path class="fig-danger" d="M399 68h27m-7-7 7 7-7 7"/><text class="fig-muted" x="231" y="126" text-anchor="middle">앞은 비었지만 끝은 막혔어요</text></svg><figcaption>앞쪽의 빈자리를 다시 쓸 방법이 필요해요.</figcaption></figure></div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p>선형 큐(linear queue)는 배열을 일직선의 대기열로 사용해요. 앞에서 꺼낼 때마다 앞 인덱스만 옮기는 방식은 삭제 때 요소를 옮기지 않아도 되지만, 뒤 인덱스가 배열 끝에 닿으면 앞쪽에 빈 칸이 있어도 새 요소를 삽입할 수 없어요. 대기 중인 요소들을 앞쪽으로 당기는 대이동을 하면 빈 칸을 재사용할 수 있지만 그만큼 복사 작업이 들어요. 매번 삭제나 삽입에서 반드시 대이동이 생긴다는 뜻은 아니에요.</p><ol class="steps"><li>여섯 칸에 A, B, C, D, E, F를 차례로 넣어요.</li><li>A, B를 꺼내면 앞 두 칸은 비지만 뒤 인덱스는 끝에 있어요.</li><li>그대로 뒤에 G를 넣으려 하면 자리가 없어요.</li><li>남은 C, D, E, F를 앞쪽으로 당기면 빈 칸을 되찾아요.</li></ol><p>원형 큐(circular queue)는 배열 끝 다음을 처음으로 이어지는 자리처럼 생각해, 앞에서 비운 칸을 다시 쓰는 개념이에요. 이번 수업에서는 개념을 소개했고 실제 순환 갱신식은 다루지 않았어요.</p></div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span><p>“선형 큐는 문제점이 많아서 사용하지 않습니다.” (1012 Part 07, 시각 미제공) 이어서 배열 자체를 버리는 것이 아니라 배열을 원처럼 보아 빈 칸을 재사용하는 구상을 설명했어요.</p></div>
  <div class="sum" hidden><p class="sum-lead">선형 큐는 앞 칸이 비어도 뒤 인덱스가 끝에 이르면 삽입할 수 없어요.</p><p class="panel-label">용어</p><dl class="terms"><dt>선형 큐(linear queue)</dt><dd>배열을 일직선의 대기열로 사용해요.</dd><dt>원형 큐(circular queue)</dt><dd>배열 끝 다음을 처음으로 이어지는 자리처럼 생각해요.</dd></dl></div>

<article class="topic" id="s2-structure"><h3>front와 rear가 가리키는 자리</h3><div class="tags"><span class="tag date">1012 수업</span><span class="tag slide">S6 p5–7</span></div>

  <div class="layer formal"><span class="layer-title">정확히 말하면</span><p>원형 큐(circular queue)는 배열의 위치가 끝에서 처음으로 이어진다고 보는 개념이에요. 수업에서 <code>rear</code>는 마지막 요소의 인덱스, <code>front</code>는 첫번째 요소 하나 앞의 인덱스로 정의했어요. 두 변수가 큐의 전단과 후단을 관리하므로 모든 요소를 옮길 필요가 없어요. <code>head</code>, <code>tail</code>이라는 변수 이름을 쓰기도 한다고 했어요.</p><ol class="steps"><li>수업 그림은 <code>front = 0</code>, <code>rear = 2</code>이고 A는 1번, B는 2번 칸에 있어요.</li><li>C를 넣으면 C가 3번 칸에 놓이고 <code>rear = 3</code>이 돼요.</li><li>A를 꺼내면 <code>front = 1</code>이 되고 B, C가 남아요.</li></ol><p>(전사본의 <code>front = 2</code> 발언은 제작 과정에서 강의록 그림을 기준으로 <code>front = 1</code>로 바로잡았어요.)</p><p>강의에서는 왜 <code>front</code>를 첫번째 요소 하나 앞에 두는지 설명을 미뤘어요. 공백·포화 조건과 인덱스를 순환시키는 계산식은 다음 범위예요.</p></div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span><p>원형 식탁의 빈자리에 새 사람이 앉는 모습으로 배열의 자리 재사용을 설명했어요. “front는 실제 첫 번째 element보다 하나 앞을 가리키게 만들어 놨어요. 이 이유는 뒤에서 볼게요.” (1012 Part 07, 시각 미제공) 끝에서 “다음 시간에 여기서부터 다시 할게요?”라고 말했어요. (1012 Part 08, 시각 미제공)</p></div>

        // 조각의 <div class="sum" hidden> 을 오른쪽 패널로 옮긴다. 없으면 안내 문구만 보인다.
        const box = panels.right.querySelector('.sums');
        const sums = {};
        topics.forEach((t) => {
          const el = t.querySelector(':scope > .sum');
          if (!el) return;
          el.hidden = true;
          box.appendChild(el);
          sums[t.id] = el;
        });
        const sub = document.getElementById('sum-for');
        const empty = document.getElementById('sum-empty');
        document.addEventListener('od:screen', (e) => {
          const s = e.detail.screen;
          const key = s.matches('article.topic') ? s.id : 'intro';
          Object.keys(sums).forEach((id) => { sums[id].hidden = id !== key; });
          empty.hidden = Boolean(sums[key]);
          sub.textContent = key === 'intro' ? '전체 흐름' : ((s.querySelector('h3') || {}).textContent || '').trim();
          if (s.matches('article.topic') && !read.has(s.id)) { read.add(s.id); store.set(KEY, Array.from(read)); }
          panels.right.querySelector('.panel-inner').scrollTop = 0;
          markToc(read, topics.length, '읽음');
          revealCurrent();
        });
      }

      if (kind === 'review') setupReview();
      if (kind === 'note') setupNote();
      sync();
    })();

  <script id="pager-ui">
    (function () {
      const root = document.documentElement;
      const main = document.querySelector('main');
      const hero = main.querySelector('.hero');
      const screens = [hero].concat(Array.from(main.querySelectorAll(document.body.dataset.screens)));
      if (screens.length < 2) { root.classList.remove('js'); return; }
      screens.forEach((s) => s.classList.add('screen'));

      const last = screens.length - 1;
      const prevBtn = document.getElementById('pager-prev');
      const nextBtn = document.getElementById('pager-next');
      const count = document.getElementById('pager-count');
      const bar = document.getElementById('pager-bar');
      const status = document.getElementById('pager-status');
      const toc = document.querySelector('#panel-left .toc');
      const scroller = document.querySelector('.content');
      const titleOf = (s) => ((s.querySelector('h3') || s.querySelector('h1') || {}).textContent || '').trim();
      let cur = -1;

      // 목차: 섹션 링크 아래에 화면(토픽·카드) 목록을 붙인다
      const tocLinks = [];
      Array.from(toc.querySelectorAll(':scope > a')).forEach((a) => {
        const sec = document.getElementById(decodeURIComponent(a.getAttribute('href').slice(1)));
        const group = document.createElement('div');
        group.className = 'toc-group';
        a.replaceWith(group);
        group.appendChild(a);
        if (!sec) return;
        const list = document.createElement('ol');
        list.className = 'toc-list';
        screens.forEach((s, i) => {
          if (!sec.contains(s)) return;
          const li = document.createElement('li');
          const link = document.createElement('a');
          link.href = '#' + s.id;
          link.innerHTML = '<span class="toc-title"></span>';
          link.firstChild.textContent = titleOf(s);
          li.appendChild(link);
          list.appendChild(li);
          tocLinks[i] = link;
        });
        group.appendChild(list);
      });

      function indexFor(hash) {
        const id = decodeURIComponent((hash || '').replace(/^#/, ''));
        const el = id && document.getElementById(id);
        if (!el || !main.contains(el)) return { i: 0 };
        const i = screens.findIndex((s) => s.contains(el) || el.contains(s));
        return { i: Math.max(i, 0), target: i >= 0 && screens[i].contains(el) && screens[i] !== el ? el : null };
      }

      function render(i, target) {
        const dir = cur < 0 ? '' : i > cur ? 'enter-next' : 'enter-prev';
        if (i !== cur) {
          if (cur >= 0) screens[cur].classList.remove('is-current', 'enter-next', 'enter-prev');
          main.querySelectorAll(':scope > section.is-on').forEach((sec) => sec.classList.remove('is-on'));
          const s = screens[i];
          const sec = s.closest('section');
          if (sec) sec.classList.add('is-on');
          s.classList.add('is-current');
          if (dir) { s.classList.remove('enter-next', 'enter-prev'); void s.offsetWidth; s.classList.add(dir); }
          cur = i;
          document.body.classList.toggle('at-end', i === last);
          prevBtn.disabled = i === 0;
          nextBtn.textContent = i === 0 ? '시작하기' : i === last ? '처음으로' : '다음';
          count.textContent = i === 0 ? '' : i + ' / ' + last;
          bar.style.transform = 'scaleX(' + (i / last) + ')';
          status.textContent = i === 0 ? titleOf(s) : i + ' / ' + last + ', ' + titleOf(s);
          tocLinks.forEach((link, k) => link && link.setAttribute('aria-current', String(k === i)));
          document.dispatchEvent(new CustomEvent('od:screen', { detail: { index: i, screen: s } }));
        }
        if (target) target.scrollIntoView({ block: 'start' });
        else scroller.scrollTo(0, 0);
      }

      function go(i) {
        i = Math.min(Math.max(i, 0), last);
        if (i === cur) return;
        const url = i === 0 ? location.pathname + location.search : '#' + screens[i].id;
        history.pushState(null, '', url);
        render(i);
      }

      prevBtn.addEventListener('click', () => go(cur - 1));
      nextBtn.addEventListener('click', () => go(cur === last ? 0 : cur + 1));
      const fromUrl = () => { const r = indexFor(location.hash); render(r.i, r.target); };
      window.addEventListener('hashchange', fromUrl);
      window.addEventListener('popstate', fromUrl);

      document.addEventListener('keydown', (e) => {
        if (e.defaultPrevented || e.altKey || e.ctrlKey || e.metaKey || document.body.classList.contains('drawer-open')) return;
        if (e.target.closest('input, select, textarea, [contenteditable="true"]')) return;
        if (e.key === 'ArrowRight') { e.preventDefault(); go(cur + 1); }
        if (e.key === 'ArrowLeft') { e.preventDefault(); go(cur - 1); }
      });

      // 좌우로 밀어서 넘기기 (가로로 스크롤되는 영역은 제외)
      let sx = 0, sy = 0, skip = true;
      main.addEventListener('touchstart', (e) => {
        const t = e.touches[0];
        sx = t.clientX; sy = t.clientY;
        skip = e.touches.length > 1 || Boolean(e.target.closest('.widget, .katex-display, .table-wrap, pre, svg, input, details'));
      }, { passive: true });
      main.addEventListener('touchend', (e) => {
        if (skip) return;
        const t = e.changedTouches[0];
        const dx = t.clientX - sx, dy = t.clientY - sy;
        if (Math.abs(dx) > 64 && Math.abs(dx) > 2 * Math.abs(dy)) go(cur + (dx < 0 ? 1 : -1));
      }, { passive: true });

      fromUrl();
    })();
  </script>

1. 스택을 C로 구현하기

배열·top을 함께 묶고 초기화하기

1012 수업S5 p11–13
쉽게 말하면

그릇과 그릇의 맨 위 자리를 알려 주는 표를 한 가방에 넣어 함께 가져가요.

정확히 말하면

배열 스택은 값 저장 공간과 맨 위 원소의 인덱스인 top을 StackType 구조체로 묶어요. 스택마다 두 값이 짝을 이루므로 여러 스택을 만들 때도 서로 섞이지 않아요. 배열 인덱스가 0부터 시작하므로 top을 -1로 초기화하면 비어 있음을 뜻해요. 배열 칸의 기존 비트값을 모두 지울 필요는 없고, top까지만 유효한 원소로 다뤄요.

typedef int element;
typedef struct {
    element stack[MAX_STACK_SIZE];
    int top;
} StackType;

// 스택초기화함수
void init(StackType *s)
{
    s->top = -1;
}
// 공백상태검출함수
int is_empty(StackType *s)
{
    return (s->top == -1);
}
// 포화상태검출함수
int is_full(StackType *s)
{
    return (s->top == (MAX_STACK_SIZE-1));
}

크기가 5라면 유효 인덱스는 0부터 4예요. top == 4이면 꽉 찼고, top == -1이면 비었어요. 저장 가능한 원소 수는 미리 정한 배열 크기로 제한돼요.

교수님 말씀
“철가방같이 1층, 2층, 3층으로 해서 서로 다른 데이터 타입으로도 함께 다닐 수 있는 걸”

교수님은 구조체를 철가방에 빗대며 배열과 top을 한 묶음으로 관리하는 이유를 강조했어요.

배열과 top을 묶고 top을 -1로 두면 빈 스택이에요.

용어

StackType
배열과 top을 함께 담는 스택 구조체
top
현재 맨 위 원소의 인덱스

조건·구분과 확인

  • 배열은 지우지 않아도 0..top만 유효해요. 포화는 top==MAX_STACK_SIZE-1이고 용량은 배열 크기로 제한돼요.

push·pop·peek의 C 코드

1012 수업S5 p11–14
쉽게 말하면

새 접시는 맨 위에 얹고, 꺼낼 때도 맨 위 접시부터 들어요. 살짝 보기만 할 때는 접시를 그대로 둬요.

정확히 말하면

push는 먼저 포화를 검사하고, 빈 칸을 만들기 위해 top을 증가부터 시킨 다음 값을 써요. pop은 먼저 공백을 검사하고, 현재 top의 값을 반환할 표현식을 평가하면서 top을 감소시켜요. 호출자가 반환값을 받는 시점에는 감소가 끝나 있어요. peek는 같은 값을 읽되 top을 바꾸지 않아요.

// 삽입함수
void push(StackType *s, element item)
{
    if( is_full(s) ) {
        fprintf(stderr,"스택포화에러\n");
        return;
    }
    else s->stack[++(s->top)] = item;
}
// 삭제함수
element pop(StackType *s)
{
    if( is_empty(s) ) {
        fprintf(stderr, "스택공백에러\n");
        exit(1);
    }
    else return s->stack[(s->top)--];
}
// 피크함수
element peek(StackType *s)
{
    if( is_empty(s) ) {
        fprintf(stderr, "스택공백에러\n");
        exit(1);
    }
    else return s->stack[s->top];
}

예를 들어 top = 1, 원소가 [7, 9]라면 다음처럼 변해요.

  1. push(4): top을 2로 증가시킨 뒤 인덱스 2에 4를 써요. 상태는 [7, 9, 4]예요.
  2. peek(): 4를 읽고 top = 2는 유지해요.
  3. pop(): 인덱스 2의 4를 반환값으로 정하고 top을 1로 줄여요. 호출자는 4를 받고 유효 상태는 [7, 9]예요.

포화된 배열의 push는 오류를 출력하고 그 함수에서 돌아가요. 빈 스택의 pop·peek에 있는 exit(1)은 반복문만 빠져나오는 명령이 아니라 프로세스 전체를 종료해요.

top이 바뀌는 시점과 저장·꺼내는 인덱스를 배열 스택: ++top과 top--의 위치에서 한 단계씩 확인해 보세요.

교수님 말씀
“증가부터 하고 써라.”

앞의 ++는 칸을 옮긴 뒤 그 칸에 저장한다는 강조예요. 수업 중 exit(1)을 “루프 구조를 빠져나오는” 것으로 설명했지만, 실제 C에서는 프로그램 실행을 종료해요.

push는 top을 올리고 쓰며 pop은 현재 값을 읽고 top을 내려요.

용어

peek
맨 위 값을 제거하지 않고 읽는 연산
top
현재 맨 위 원소의 인덱스

조건·구분과 확인

  • 포화 push는 오류 후 함수에서 돌아오고, 공백 pop·peek의 exit(1)은 루프가 아니라 프로세스를 종료해요. 검사 후에만 인덱스와 값을 다뤄요.

입력 크기에 맞춰 구현 고르기

1012 수업S5 p15
쉽게 말하면

손님 수가 정해져 있으면 정해진 의자를 놓으면 돼요. 얼마나 올지 모르면 손님이 올 때마다 의자를 더 놓는 방법이 편해요.

정확히 말하면

배열 스택은 미리 정한 용량까지 연속된 공간을 써요. 예를 들어 입력이 언제나 100명 미만이라면 그 상한을 반영해 배열 크기를 정할 수 있어요. 반대로 실제 입력이 시험 때보다 훨씬 커질 수 있다면 고정 배열은 포화될 수 있어요. 연결 스택은 원소마다 노드를 동적으로 할당하므로 미리 정한 배열 용량에 묶이지 않아요. 다만 사용 가능한 메모리까지 무한한 것은 아니며, 포인터와 할당 관리가 필요해요.

두 구현 모두 마지막에 넣은 값을 먼저 꺼내는 스택이에요. 교수님은 실제 입력 상한을 가늠하기 어려운 시험 문제에서 배열 크기를 작게 잡아 실패한 사례를 들었어요. 재귀(recursion)의 내부 호출 스택이 반드시 연결 스택이라는 뜻은 아니에요. 이 수업의 구현 선택 기준은 문제의 입력 규모를 알고 있는가예요.

실제 데이터 양을 보고 저장 공간을 정하라는 취지예요.

입력 상한을 알면 배열, 가늠하기 어려우면 연결 스택을 고려해요.

노드와 top의 의미

1012 수업S5 p15–16
쉽게 말하면

집의 방 하나를 가리키는 게 아니라 집 전체의 주소를 가리켜요. 그 집에는 물건과 다음 집 주소가 함께 있어요.

정확히 말하면

각 StackNode는 저장할 item과 다음 노드를 가리키는 link를 가져요. LinkedStackType은 첫 노드의 주소인 top을 가져요. top은 item 필드만 가리키는 것이 아니라 노드 구조체 전체의 시작 주소를 가리켜요. 노드가 없다면 top = NULL이고 마지막 노드의 link = NULL이에요.

typedef int element;
typedef struct StackNode {
    element item;
    struct StackNode *link;
} StackNode;
typedef struct {
    StackNode *top;
} LinkedStackType;

강의록 S5 p16의 typedef 별칭은 StackeNode로 인쇄되어 있어요. 바로 아래의 StackNode *top 및 다음 쪽 코드와 맞도록 여기서는 StackNode로 고쳤어요. 연결 스택의 초기 상태에서는 top을 NULL로 두어요.

교수님 말씀
“방을 가리키는 게 아니고요, 101호를 가리키는 거”

포인터가 노드의 개별 필드가 아닌 노드 시작 주소를 담는다는 비유예요.

top은 첫 StackNode의 시작 주소를 가리켜요.

용어

StackNode
값과 다음 노드 주소를 담은 구조체
LinkedStackType
첫 노드 주소 top을 담은 구조체
NULL
가리키는 노드가 없음을 나타내는 포인터 값

조건·구분과 확인

  • 초기 top은 NULL이고 마지막 노드 link도 NULL이에요. 슬라이드 별칭 StackeNode는 후속 코드와 맞춰 StackNode로 바로잡았어요.

새 노드를 먼저 연결한 뒤 top 바꾸기

1012 수업S5 p17
쉽게 말하면

새 집에 다음 집의 주소를 먼저 적어요. 그다음 맨 앞 표지판을 새 집으로 옮기면 기존 집을 잃지 않아요.

정확히 말하면

malloc으로 StackNode 크기의 메모리를 요청해요. 실패하면 NULL이므로 오류를 출력하고 돌아가요. 성공하면 값을 적고 temp->link = s->top;으로 기존 첫 노드를 연결한 다음, s->top = temp;로 새 노드를 맨 앞에 둬요. 순서를 바꾸면 기존 첫 노드의 주소를 잃어버릴 수 있어요.

// 삽입함수
void push(LinkedStackType *s, element item)
{
    StackNode *temp=(StackNode *)malloc(sizeof(StackNode));
    if( temp == NULL ){
        fprintf(stderr, "메모리할당에러\n");
        return;
    }
    else{
        temp->item = item;
        temp->link = s->top;
        s->top = temp;
    }
}
  1. 처음에는 top → C → B → A → NULL이에요.
  2. 새 노드 D의 link에 기존 top 주소를 넣어요. D → C → B → A → NULL 연결이 생겨요.
  3. top을 D로 옮겨요. 최종 상태는 top → D → C → B → A → NULL이에요.

맨 앞 노드만 연결하므로 새 노드를 연결하는 포인터 변경은 일정한 단계로 끝나요.

link와 top을 바꾸는 순서에 따라 노드가 어떻게 이어지는지 연결 스택 push: 무엇을 먼저 연결할까?에서 한 단계씩 확인해 보세요.

교수님 말씀
“top부터 바꾸면 낙동강 오리알 된다 그랬어요.”

새 노드가 기존 첫 노드를 가리키기 전에 top을 덮어쓰면 기존 연결을 잃는다는 뜻이에요.

새 노드를 기존 top에 연결한 뒤 top을 새 노드로 바꿔요.

용어

malloc
새 노드에 쓸 메모리를 요청하는 함수
top
현재 첫 노드의 주소

조건·구분과 확인

  • malloc이 NULL이면 오류 후 돌아오고 성공하면 item 저장 → temp->link=s->top → s->top=temp 순서예요. top을 먼저 덮으면 기존 연결을 잃을 수 있어요.

값을 보관하고 노드를 반납하기

1012 수업S5 p18
쉽게 말하면

맨 앞 집의 물건과 다음 집 주소를 기억해요. 표지판을 다음 집으로 옮긴 뒤 빈 집을 치워요.

정확히 말하면

비어 있으면 exit(1)로 프로세스를 종료해요. 비어 있지 않으면 기존 첫 노드를 temp로 보관하고 그 노드의 값을 item에 복사해요. 그다음 s->top = s->top->link;로 다음 노드를 첫 노드로 만들어요. 마지막으로 free(temp);를 호출한 뒤 return item;으로 저장한 값을 돌려줘요. 해제한 노드의 필드를 다시 읽으면 안 돼요.

// 삭제함수
element pop(LinkedStackType *s)
{
    if( is_empty(s) ) {
        fprintf(stderr, "스택이비어있음\n");
        exit(1);
    }
    else{
        StackNode *temp=s->top;
        int item = temp->item;
        s->top = s->top->link;
        free(temp);
        return item;
    }
}

여기서 is_empty는 연결 스택의 top == NULL을 검사해야 해요. S5 p18은 그 구현을 함께 싣지 않았어요.

  1. 처음은 top → C → B → A → NULL이고 temp와 item에 첫 노드 주소와 값 C를 각각 보관해요.
  2. top을 B로 옮기면 유효한 연결은 top → B → A → NULL이에요.
  3. C 노드의 메모리를 반납하고 보관한 값 C를 반환해요.

첫 노드만 다루므로 첫 노드를 옮기고 해제하는 순서를 지켜요.

값 보관·top 이동·free 순서와 해제 뒤 포인터의 상태를 연결 스택 pop: 보관하고, 옮기고, 해제하기에서 한 단계씩 확인해 보세요.

교수님 말씀
“얘를 return 받고 얘도 free시켜”

반환할 값은 해제 전에 별도 변수에 보관해야 해요.

첫 노드 값을 보관하고 top을 옮긴 뒤 기존 노드를 해제해요.

용어

free
동적으로 할당한 노드 메모리를 반납하는 함수
temp
해제할 기존 첫 노드를 잠시 가리키는 포인터

조건·구분과 확인

  • 연결 스택 공백은 top==NULL이며 비면 exit(1)로 종료해요. temp·item에 보관 → top 이동 → free(temp) → item 반환 순서로 해제 뒤 필드를 읽지 않아요.

2. 스택으로 문제 풀기

괄호의 개수·순서·포함 관계

1012 수업S5 p19–20
쉽게 말하면

문을 열었으면 나중에 닫아야 해요. 안쪽 문부터 닫아야 바깥 문도 제대로 닫을 수 있어요.

정확히 말하면

괄호 검사에는 세 조건이 있어요. 왼쪽과 오른쪽 괄호의 개수가 같아야 하고, 같은 종류의 왼쪽 괄호가 오른쪽보다 먼저 나와야 하며, 여러 쌍은 교차하지 않고 포함 관계를 이뤄야 해요. 가장 최근에 연 왼쪽 괄호부터 닫는 매칭이므로 스택을 써요.

  1. a(b): 열고 닫는 순서가 맞아요.
  2. (a(b): 마지막에 왼쪽 괄호 하나가 남아요.
  3. a(b)c): 마지막 오른쪽 괄호에 맞출 왼쪽 괄호가 없어요.
  4. a{b(c[d]e}f): }를 읽을 때 가장 최근의 (와 종류가 달라요.

같은 수만 세는 것으로는 마지막 사례의 잘못된 포함 관계를 발견할 수 없어요.

교수님 말씀
“괄호 사이에는 포함 관계만 존재합니다.”

교수님은 수가 맞아도 교차해서 닫으면 오류라고 강조했어요.

괄호는 가장 최근에 연 것부터 같은 종류로 닫아야 해요.

용어

매칭
오른쪽 괄호와 가장 최근 왼쪽 괄호의 짝 확인

조건·구분과 확인

  • 개수가 같고 같은 종류의 왼쪽이 먼저 나오며 쌍은 교차 없이 포함돼야 해요. 개수만 세면 잘못된 포함 관계를 놓쳐요.

괄호 검사 알고리즘과 실패 지점

정확히 말하면

중위 표기는 연산자를 피연산자 사이에, 전위 표기는 앞에, 후위 표기는 뒤에 적어요. 예를 들어 중위 2+3*4는 전위 + 2 * 3 4, 후위 2 3 4 * +예요. 곱셈을 먼저 계산하므로 2 3 + 4 *로 바꾸면 다른 뜻이 돼요.

  2. 2 12 +를 계산하면 14예요.

강의록은 2+3*4를 후위식으로 바꿔 스택으로 계산하는 절차를 소개해요. 이는 이 장의 수식 처리 알고리즘이며 모든 컴파일러나 CPU가 실제로 반드시 후위 문자열로 바꾼다는 뜻은 아니에요.

정확히 말하면

후위식은 피연산자이면 쌓고, 연산자이면 두 값을 꺼내 계산 결과를 다시 쌓아요. 먼저 꺼낸 값이 second, 다음이 first이므로 계산은 first op second예요. 특히 8 / 2와 4 - 3을 뒤집지 않도록 해요. 수업의 식 8 2 / 3 - 3 2 * +를 따라가요.

  1. 8을 쌓아요: [8].
  2. 2를 쌓아요: [8, 2].
  3. /: 2를 second, 8을 first로 꺼내 8 / 2 = 4를 쌓아요: [4].
  4. 3을 쌓아요: [4, 3].
  5. -: 4 - 3 = 1을 쌓아요: [1].
  6. 3, 2를 차례로 쌓아요: [1, 3, 2].
  7. *: 3 * 2 = 6을 쌓아요: [1, 6].
  8. +: 1 + 6 = 7을 쌓아요: [7].

마지막 한 값 7이 결과예요. 연산자 앞에 값이 두 개보다 적거나 끝에 값이 여러 개 남으면 정상적인 이항 연산식이 아니에요. 각 토큰을 왼쪽부터 차례대로 처리해요.

문자를 숫자로 바꾸는 C 코드

1012 수업S5 p27

종이에 적힌 숫자 모양을 계산할 수 있는 숫자로 바꿔요. 계산한 답은 다시 쌓아 두어요.

정확히 말하면

강의록의 eval은 문자열을 한 글자씩 읽어요. 이 예시는 한 자리 숫자만 다루므로 value = ch - '0';으로 숫자 문자를 정수 값으로 바꿔요. 연산자이면 op2 = pop(&s);로 오른쪽 값을 먼저 꺼내고 op1 = pop(&s);로 왼쪽 값을 꺼내요. 각 연산 결과를 다시 쌓은 뒤 마지막 값을 반환해요.

// 후위표기수식계산함수
int eval(char exp[])
{
    int op1, op2, value, i=0;
    int len = strlen(exp);
    char ch;
    StackType s;
    init(&s);
    for( i=0; i<len; i++){
        ch = exp[i];
        if( ch != '+' && ch != '-' && ch != '*' && ch != '/' ){
            value = ch - '0';
            push(&s, value);
        }
        else{
            op2 = pop(&s);
            op1 = pop(&s);
            switch(ch){
                case '+': push(&s,op1+op2); break;
                case '-': push(&s,op1-op2); break;
                case '*': push(&s,op1*op2); break;
                case '/': push(&s,op1/op2); break;
            }
        }
    }
    return pop(&s);
}

슬라이드의 함수 선언에는 반환형이 생략되어 있어요. 실제 C 코드로 사용하려면 int eval(char exp[])처럼 반환형을 명시해야 해요. 이 예시에는 공백·다자리 수·잘못된 문자·0으로 나누기 검사가 없으므로 그런 입력까지 처리하는 일반 계산기로 보아서는 안 돼요.

예를 들어 A+B*C는 A를 출력하고 +를 쌓은 뒤 B를 출력해요. *는 +보다 우선순위가 높으므로 쌓아요. C를 출력하고 끝에 *와 +를 꺼내 A B C * +가 돼요. 반대로 (A+B)*C는 괄호가 A+B를 먼저 묶어요.

  1. (: 스택 [(], 출력은 비어요.
  2. A: 스택 [(], 출력 A.
  3. +: 스택 [(, +], 출력 A.
  4. B: 스택 [(, +], 출력 A B.
  5. ): +를 꺼내 출력하고 (는 버려요. 스택 [], 출력 A B +.
  6. *: 스택 [*], 출력 A B +.
  7. C: 스택 [*], 출력 A B + C.
  8. 끝: *를 꺼내 출력해 최종 A B + C *예요.

왼쪽 괄호는 밖의 연산자가 안쪽으로 끼어들지 못하게 경계를 만들고, 오른쪽 괄호를 만나면 그 경계까지 꺼내요. 괄호 자체는 출력하지 않아요.

정확히 말하면

강의록의 미로는 벽을 1, 갈 수 있는 칸을 0으로 나타내요. 현재 위치를 방문 처리하고 아직 방문하지 않았으며 갈 수 있는 이웃 위치를 스택에 쌓아요. 그다음 맨 위 후보를 꺼내 현재 위치로 삼아요. 후보가 없으면 실패하고 출구에 도달하면 성공해요. 방문 표시는 같은 칸을 다시 후보로 넣어 무한히 돌지 않게 해요.

수업에서 갈림길에 리본을 묶는 비유로 설명한 추적이에요. 교수님은 한쪽 벽만 따라가다 섬처럼 떨어진 벽 때문에 같은 자리를 반복했던 미로 공원 경험도 들었어요. 아래 스택은 아직 조사하지 않은 후보를 아래부터 위 순서로 적은 것이며, 로봇이 실제로 걸은 모든 칸의 경로 기록은 아니에요.

  1. 시작 (1, 0)에서 (1, 1)을 쌓았다 꺼내 이동해요. 후보 스택은 []예요.
  2. (1, 1)에서 (2, 1)을 먼저, (1, 2)를 나중에 쌓아요. 스택 [(2, 1), (1, 2)]에서 (1, 2)를 꺼내요.
  3. (1, 2)에서 (1, 3)을 쌓았다 꺼내요. 남은 후보는 [(2, 1)]이에요.
  4. (1, 3)에서 (2, 3)을 먼저, (1, 4)를 나중에 쌓아요. 스택 [(2, 1), (2, 3), (1, 4)]에서 (1, 4)를 꺼내요.
  5. (1, 4)는 막다른 길이라 새 후보가 없어요. 남은 스택의 위 (2, 3)을 꺼내며 스택은 [(2, 1)]이에요. 그림의 이 이동은 후보 선택을 압축해 나타낸 것이고, 실제 되돌아가는 걸음은 따로 기록해야 해요.
  6. (2, 3)에서 (3, 3)을 쌓았다 꺼내요. 스택은 [(2, 1)]이에요.
  7. (3, 3)에서 (4, 3)을 먼저, (3, 4)를 나중에 쌓고 (3, 4)로 이동해요. 스택은 [(2, 1), (4, 3)]이에요.
  8. (3, 4)에서 (3, 5)를 쌓았다 꺼내 출구에 도달해요. (2, 1)과 (4, 3)은 후보로 남아 있어도 탐색은 끝나요.

후보 스택은 다음 탐색 대상을 고를 뿐, (1, 4)에서 (2, 3)까지의 물리적 이동 경로를 자동으로 알려 주지는 않아요.

교수님 말씀
“먼저 처리하고 싶은 애가 top에 올라오게 push를 해야 됩니다.”

다음에 먼저 볼 후보를 나중에 넣는다는 뜻이에요.

스택에는 다음 후보가 남고 출구에 닿으면 후보가 남아도 끝나요.

용어

방문
이미 조사한 칸임을 표시하는 것
출구
탐색이 성공하는 목표 위치

조건·구분과 확인

  • 방문 표시로 반복 방문을 막고 갈 수 있는 미방문 이웃을 넣어요. 후보가 없으면 실패하며 먼저 볼 곳을 나중에 push해요. 후보 스택은 실제 걸은 경로 기록과 달라요.

3. 큐가 필요한 이유와 구조

먼저 들어온 것을 먼저 꺼내기

1012 수업S6 p2–3
쉽게 말하면

줄을 선 순서대로 차례가 와요.

정확히 말하면

큐(queue)는 선입선출(FIFO: First-In First-Out) 자료구조예요. 먼저 들어온 요소가 먼저 나가요. 스택과 달리 삽입과 삭제가 양 끝에서 일어나요. 전단(front)에서 꺼내고 후단(rear)에 넣어요.

큐 추상 데이터 타입(ADT)의 연산은 create() 생성, init(q) 초기화, is_empty(q) 공백 검사, is_full(q) 포화 검사, enqueue(q, e) 후단 삽입, dequeue(q) 전단 요소 반환과 삭제, peek(q) 전단 요소를 삭제하지 않고 반환하기예요. 삽입·삭제 위치를 호출자가 따로 지정하지 않아요.

  1. 빈 큐에 A를 enqueue하면 대기 순서는 A예요.
  2. B를 enqueue하면 대기 순서는 A, B예요.
  3. dequeue하면 A를 꺼내고 B가 앞에 남아요.
  4. peek하면 B를 읽고 큐의 내용은 그대로예요.
교수님 말씀

매표소 대기열과 빨대 안의 음료를 비유로 들었어요. 빨대에 먼저 들어온 것이 먼저 입에 닿듯 큐도 순서를 지켜요. “순서, 들어온 순서를 유지하는 게 매우 중요한 자료구조입니다.”

큐는 먼저 들어온 요소를 앞에서 먼저 꺼내요.

용어

선입선출(FIFO: First-In First-Out)
먼저 들어온 요소가 먼저 나가는 순서예요.
enqueue
큐의 후단에 요소를 넣어요.
dequeue
큐의 전단 요소를 꺼내요.

조건·구분과 확인

  • enqueue는 rear 삽입, dequeue는 front 삭제·반환, peek는 전단을 제거 없이 반환해요. create·init은 생성·초기화, is_empty·is_full은 상태 검사예요.

생산자와 소비자 사이에서 기다리기

1012 수업S6 p4
쉽게 말하면

보내는 쪽이 빠르고 받는 쪽이 느리면, 보낸 것을 줄 세워 잠시 기다리게 해요.

정확히 말하면

생산자(producer)는 데이터를 만들고 소비자(consumer)는 데이터를 처리해요. 생산자가 더 빠르거나 두 쪽의 속도가 다르면, 중간의 버퍼(buffer)가 데이터를 순서대로 보관해요. 큐는 이 버퍼를 구현하기 좋은 자료구조예요. 프린터는 컴퓨터가 보낸 출력 작업을 물리적으로 인쇄하는 데 시간이 걸려요. 인쇄 대기열은 먼저 요청된 작업부터 처리해요. 통신 패킷의 대기열도 응용 사례예요.

시뮬레이션(simulation)은 실제 상황을 소프트웨어로 모의실험하는 일이에요. 공항에서는 항공기 이착륙과 연착에 따른 대기를, 은행에서는 시간대별 고객 대기와 행원 수를 모델링할 수 있어요. 교수는 은행의 점심시간 인력을 줄였을 때 고객 평균 대기시간이 어떻게 바뀔지 시험하는 예를 들었어요. 이 수업은 사례의 목적을 설명했으며 구체적인 시뮬레이션 코드는 다루지 않았어요.

교수님 말씀

컴퓨터가 명령을 보내는 속도와 프린터가 종이를 찍는 속도의 차이를 비교했어요. 은행주가 적은 인력으로 대기시간을 관리하려고 여러 인력 배치를 모의실험하는 사례도 들었어요. “둘 사이에 속도 차이가 클 때 잠깐 데이터가 순서대로 머물러야 될 자리가 필요해요.”

속도가 다른 두 작업 사이에서 큐가 데이터를 순서대로 기다리게 해요.

용어

생산자(producer)
데이터를 만들어요.
소비자(consumer)
데이터를 처리해요.
버퍼(buffer)
처리 전 데이터를 순서대로 보관해요.

조건·구분과 확인

  • 은행·공항의 대기 시뮬레이션은 실제 상황을 소프트웨어로 모의실험하는 예이며, 이번 수업에서 구체적 코드는 다루지 않았어요.

선형 배열에서 빈자리를 못 쓰는 문제

1012 수업S6 p5
쉽게 말하면

긴 의자의 앞자리가 비어도 새 사람이 끝자리 뒤에만 서면 자리가 없다고 느껴져요.

정확히 말하면

선형 큐(linear queue)는 배열을 일직선의 대기열로 사용해요. 앞에서 꺼낼 때마다 앞 인덱스만 옮기는 방식은 삭제 때 요소를 옮기지 않아도 되지만, 뒤 인덱스가 배열 끝에 닿으면 앞쪽에 빈 칸이 있어도 새 요소를 삽입할 수 없어요. 대기 중인 요소들을 앞쪽으로 당기는 대이동을 하면 빈 칸을 재사용할 수 있지만 그만큼 복사 작업이 들어요. 매번 삭제나 삽입에서 반드시 대이동이 생긴다는 뜻은 아니에요.

  1. 여섯 칸에 A, B, C, D, E, F를 차례로 넣어요.
  2. A, B를 꺼내면 앞 두 칸은 비지만 뒤 인덱스는 끝에 있어요.
  3. 그대로 뒤에 G를 넣으려 하면 자리가 없어요.
  4. 남은 C, D, E, F를 앞쪽으로 당기면 빈 칸을 되찾아요.

원형 큐(circular queue)는 배열 끝 다음을 처음으로 이어지는 자리처럼 생각해, 앞에서 비운 칸을 다시 쓰는 개념이에요. 이번 수업에서는 개념을 소개했고 실제 순환 갱신식은 다루지 않았어요.

교수님 말씀

“선형 큐는 문제점이 많아서 사용하지 않습니다.” 이어서 배열 자체를 버리는 것이 아니라 배열을 원처럼 보아 빈 칸을 재사용하는 구상을 설명했어요.

선형 큐는 앞 칸이 비어도 뒤 인덱스가 끝에 이르면 삽입할 수 없어요.

용어

선형 큐(linear queue)
배열을 일직선의 대기열로 사용해요.
원형 큐(circular queue)
배열 끝 다음을 처음으로 이어지는 자리처럼 생각해요.

조건·구분과 확인

  • 남은 원소를 앞당기면 빈칸을 재사용하지만 복사가 들어요. 대이동이 매 연산 필수라는 뜻은 아니며 원형의 순환 갱신식은 아직 다루지 않았어요.

front와 rear가 가리키는 자리

1012 수업S6 p5–7
쉽게 말하면

둥근 식탁에서 앞사람이 떠나면 그 자리를 나중에 다시 쓸 수 있어요.

정확히 말하면

원형 큐(circular queue)는 배열의 위치가 끝에서 처음으로 이어진다고 보는 개념이에요. 수업에서 rear는 마지막 요소의 인덱스, front는 첫번째 요소 하나 앞의 인덱스로 정의했어요. 두 변수가 큐의 전단과 후단을 관리하므로 모든 요소를 옮길 필요가 없어요. head, tail이라는 변수 이름을 쓰기도 한다고 했어요.

  1. 수업 그림은 front = 0, rear = 2이고 A는 1번, B는 2번 칸에 있어요.
  2. C를 넣으면 C가 3번 칸에 놓이고 rear = 3이 돼요.
  3. A를 꺼내면 front = 1이 되고 B, C가 남아요.

(전사본의 front = 2 발언은 제작 과정에서 강의록 그림을 기준으로 front = 1로 바로잡았어요.)

강의에서는 왜 front를 첫번째 요소 하나 앞에 두는지 설명을 미뤘어요. 공백·포화 조건과 인덱스를 순환시키는 계산식은 다음 범위예요.

교수님 말씀

원형 식탁의 빈자리에 새 사람이 앉는 모습으로 배열의 자리 재사용을 설명했어요. “front는 실제 첫 번째 element보다 하나 앞을 가리키게 만들어 놨어요. 이 이유는 뒤에서 볼게요.” 끝에서 “다음 시간에 여기서부터 다시 할게요?”라고 말했어요.

원형 큐는 front와 rear를 옮겨 배열의 빈자리를 다시 써요.

용어

front
첫번째 요소 하나 앞의 인덱스예요.
rear
마지막 요소의 인덱스예요.

조건·구분과 확인

  • front=0·rear=2에서 C를 넣으면 rear=3, A를 꺼내면 front=1이에요. front를 하나 앞에 두는 이유와 공백·포화·순환식은 다음 범위예요.

Q1. 높은 점수 네 개

점수 200개가 최대 힙에 들어 있어요. 가장 높은 점수 네 개를 큰 것부터 꺼내고 나머지는 힙에 남겨 두려면 무엇을 할까요?

  1. 힙의 루트를 네 번 삭제해요.
  2. 힙 배열의 앞 네 칸을 꺼내요.
  3. 힙의 루트를 네 번 읽어요.
  4. 힙을 비운 뒤 앞의 네 점수를 골라요.
힌트 보기

루트를 하나 꺼낸 직후 다음 최댓값이 어디에 오는지 떠올려 보세요.

풀이 보기
  1. 최대 힙은 삭제할 때마다 남은 점수 중 가장 큰 점수를 내놓아요.
  2. "힙 배열을 내림차순 배열로 봄" — 최대 힙은 부모와 자식 사이의 크기만 보장해요. 배열 앞 네 칸에 최고점 네 개가 모여 있다는 보장은 없어요.
  3. "최댓값 조회와 삭제를 같은 연산으로 봄" — 루트를 읽기만 하면 같은 점수가 남아요. 다음으로 큰 점수를 보려면 지금 루트를 삭제해야 해요.
  4. "상위 몇 개를 꺼낼 때도 전체 정렬이 필요하다고 봄" — 원하는 점수 네 개가 나온 뒤에 멈춰야 나머지가 힙에 남아요.

정답: A

Q2. 배열을 덮어쓰는 시점

원소가 두 개 이상인 배열 a를 heap_sort로 정렬해요. a를 읽어 최대 힙을 만든 뒤, 꺼낸 값을 같은 배열의 뒤쪽부터 써요. 원소를 모두 힙에 먼저 넣는 이유는 무엇일까요?

  1. 처음 읽은 값을 바로 써도 원래 값이 모두 보존되기 때문이에요.
  2. 삽입 루프에서 배열 자체를 정렬해 두기 위해서예요.
  3. 첫 삭제에서 배열의 맨 뒤 값을 직접 꺼내야 하기 때문이에요.
  4. 아직 힙에 넣지 못한 원소를 덮어쓰는 일을 막기 위해서예요.
힌트 보기

첫 삽입에서 읽는 칸과 첫 삭제에서 쓰는 칸을 비교해 보세요.

풀이 보기
  1. "두 루프가 동시에 돌아도 된다고 봄" — 처음 읽는 곳은 배열 맨 앞이고 첫 결과를 쓰는 곳은 맨 뒤예요. 삽입과 삭제를 번갈아 하면 아직 읽지 않은 맨 뒤 원소를 덮어쓰게 돼요.
  2. "힙에 삽입하면 원본 배열도 정렬된다고 봄" — 삽입 루프는 배열 원소를 읽어 별도의 힙에 넣어요. 배열에 정렬 결과를 쓰는 곳은 삭제 루프예요.
  3. "결과를 쓰는 칸을 삭제 대상이라고 봄" — 삭제 함수가 돌려주는 값은 힙의 루트예요. 배열 맨 뒤는 그 값을 쓰는 곳이에요.
  4. 삽입 루프가 끝난 뒤에는 원래 값들이 모두 힙에 들어 있어서 배열을 덮어써도 돼요.

정답: D

Q3. 출력을 앞에서 채우면

heap_sort에서 최대 힙을 만드는 부분은 같아요. 삭제한 값을 쓰는 순서만 a[0]부터 a[n-1]까지로 바꾸면 배열은 어떻게 될까요?

  1. 작은 값부터 놓여서 오름차순이 돼요.
  2. 원래 힙의 배열 순서대로 놓여요.
  3. 큰 값부터 놓여서 내림차순이 돼요.
  4. 마지막 노드부터 뽑혀서 입력마다 방향이 달라져요.
힌트 보기

처음 꺼낸 값이 어느 칸에 놓이는지 확인해 보세요.

풀이 보기
  1. "최대 힙에서 작은 값이 먼저 나온다고 봄" — 최대 힙에서는 큰 값부터 나와요. 그 값을 앞에서부터 쓰면 큰 값이 앞에 와요.
  2. "반복 삭제를 힙 배열 순회로 봄" — 힙 배열을 앞에서부터 읽는 과정이 아니에요. 삭제할 때마다 힙을 다시 정비하고 현재 루트를 꺼내요.
  3. 남은 값 중 최댓값이 매번 나와요. 그 순서대로 배열 왼쪽부터 쓰면 내림차순이에요.
  4. "정비에 쓰는 마지막 노드를 반환값으로 봄" — 마지막 노드는 힙을 정비할 때 루트로 옮기는 값이에요. 삭제 함수가 돌려주는 값은 옮기기 전의 루트예요.

정답: C

Q4. 아주 가까운 두 시점

한 손님의 행동을 기록했어요. 도착은 8.000초, 주문은 8.001초에 찍혔어요. 두 기록을 어떻게 해석할까요?

  1. 간격이 아주 짧아서 연속 변화로 봐요.
  2. 각각 다른 시각이 있으므로 두 이산 사건으로 봐요.
  3. 같은 손님이어서 한 사건으로 봐요.
  4. 시각에 소수점이 있어서 연속 변화로 봐요.
힌트 보기

기록에서 각 시각에 어떤 행동이 일어났는지 짚어 보세요.

풀이 보기
  1. "시각 차이가 작으면 연속이라고 봄" — 간격이 작아도 각 사건이 일어난 시각을 구별할 수 있어요.
  2. 도착과 주문이 각각 구별되는 시각에 발생했어요.
  3. "한 손님의 도착·주문을 하나의 사건으로 봄" — 같은 손님의 행동이라도 도착과 주문은 각각의 시각을 가진 별도 사건이에요.
  4. "이산 사건은 정수 시각에만 일어난다고 봄" — 이산 사건도 8.001초처럼 소수로 된 시각에 일어날 수 있어요.

정답: B

Q5. 이벤트를 꺼내는 기준

시뮬레이션에서 12분 도착을 먼저 등록하고 9분 주문을 나중에 등록했어요. 사건이 일어날 시각대로 처리할 때 우선순위 큐를 쓰는 이유는 무엇일까요?

  1. 예정 시각이 더 늦은 12분 도착을 먼저 꺼내요.
  2. 먼저 등록한 12분 도착을 먼저 꺼내요.
  3. 이벤트 종류에 따라 12분 도착을 먼저 꺼내요.
  4. 예정 시각이 더 이른 9분 주문을 먼저 꺼내요.
힌트 보기

각 기록에 적힌 시각과 큐에 들어온 순서를 따로 보세요.

풀이 보기
  1. "우선순위 큐는 항상 큰 키부터 꺼낸다고 봄" — 시각이 작은 이벤트가 먼저 일어나요. 여기서는 작은 시각에 높은 우선순위를 줘요.
  2. "줄을 모델링한 FIFO를 이벤트에도 그대로 씀" — 등록 순서대로 꺼내면 12분 도착이 먼저 나와서 예정 시각 순서를 어겨요.
  3. "한 손님의 도착·주문 순서를 모든 손님에게 적용함" — 종류만으로 처리 순서를 정하면 이른 주문이 늦은 도착보다 뒤로 밀려요.
  4. 우선순위 큐에서 예정 시각을 기준으로 고르면 나중에 등록된 9분 주문이 먼저 나와요.

정답: D

Q6. 코드의 자리 수

한 메시지에 서로 다른 기호 일곱 종류가 나와요. 각 기호를 서로 다른 같은 길이의 비트열로 적을 때 필요한 최소 길이는 얼마일까요?

  1. 3비트면 돼요. 기호 일곱 종류에 서로 다른 비트열을 줄 수 있어요.
  2. 2비트면 돼요. 출현 횟수가 많은 기호부터 배정하면 돼요.
  3. 4비트가 필요해요. 3비트는 비트별로 0과 1을 더해 여섯 가지뿐이에요.
  4. 7비트가 필요해요. 기호 한 종류마다 별도의 자리를 줘야 해요.
힌트 보기

$0$과 $1$로 두 자리를 채워 만들 수 있는 비트열을 떠올려 보세요.

풀이 보기
  1. 2비트는 $2^2=4$가지, 3비트는 $2^3=8$가지여서 3비트부터 충분해요.
  2. "빈도가 높은 기호부터 배정하면 고정 길이 코드의 부족한 가짓수를 메울 수 있다고 봄" — 2비트로는 네 종류만 구별할 수 있어요. 빈도순으로 배정해도 비트열의 가지 수는 같아요.
  3. "자리마다 가능한 비트 수를 더해 전체 가짓수를 구함" — 각 자리는 0과 1 중 하나를 독립적으로 골라요. 세 자리에서 나오는 비트열은 $2+2+2$가 아니라 $2^3$가지예요.
  4. "기호 한 종류에 비트열 하나 대신 비트 자리 하나를 배정함" — 기호 하나에 비트열 하나를 배정해요. 비트 자리 한 칸을 따로 잡을 필요는 없어요.

정답: A

Q7. 짧은 코드를 줄 글자

한 메시지에서 여러 글자 중 R은 30번, S는 5번 나와요. R과 S에 길이 2비트와 4비트인 코드를 하나씩 나눠 준다면 어떤 배정이 비트를 아낄까요?

  1. 드물게 나오는 S에 짧은 코드를 주면 더 아껴요.
  2. 두 길이를 한 번씩 쓰니까 어느 쪽에 줘도 같아요.
  3. 자주 나오는 R에 짧은 코드를 주면 더 아껴요.
  4. 0이 많이 들어간 코드를 R에 줘야 더 아껴요.
힌트 보기

코드 길이가 한 비트 줄면 그 이득이 글자마다 몇 번 생기는지 생각해 보세요.

풀이 보기
  1. "빈도가 낮을수록 짧은 코드를 줘야 한다고 봄" — 짧은 코드를 더 자주 쓰는 R에 줘야 줄어드는 비트가 더 많아요.
  2. "각 코드 길이를 한 번씩만 더해 전체 비트를 셈" — 메시지에서는 코드표의 각 코드를 한 번씩 쓰는 게 아니에요. R의 코드는 30번, S의 코드는 5번 써요.
  3. R은 S보다 더 많이 나오므로, R을 적을 때마다 비트를 줄이는 쪽이 합계가 작아요.
  4. "비트열의 길이보다 0의 개수가 중요하다고 봄" — 0과 1은 각각 한 비트예요. 전체 비트 수에는 코드의 길이와 출현 횟수가 중요해요.

정답: C

Q8. 다음에 묶을 후보

허프만 트리를 만드는 중이에요. 후보는 현재 적힌 순서대로 9, 8, 14, 6이에요. 맨 앞의 9는 방금 합쳐서 만든 노드의 빈도예요. 다음에 묶을 두 노드는 어떻게 고를까요?

  1. 방금 만든 9와 나머지 중 가장 작은 6을 묶어요.
  2. 전체 후보 중에서 빈도가 가장 작은 6과 8을 묶어요.
  3. 전체 후보 중에서 빈도가 가장 큰 9와 14를 묶어요.
  4. 적힌 순서에서 이웃한 두 수의 합이 가장 작은 9와 8을 묶어요.
힌트 보기

방금 만든 노드까지 포함해서 네 후보의 빈도를 한 번 비교해 보세요.

풀이 보기
  1. "직전에 만든 노드를 매번 포함함" — 새 노드도 다른 노드와 같은 기준으로 비교해요. 더 작은 후보가 둘 있으면 새 노드는 남겨 둬요.
  2. 합쳐서 생긴 9까지 포함해 비교해도 6과 8이 가장 작아요.
  3. "자주 등장하는 큰 빈도의 노드부터 묶음" — 허프만 트리는 빈도가 작은 노드부터 묶어요. 그 노드들이 후속 합치기에 계속 포함되며 더 깊어질 수 있어요.
  4. "이웃한 두 쌍만 비교하는 설명을 일반 규칙으로 봄" — 적힌 순서에서 이웃한 후보만 보면 6과 8을 함께 고를 수 없어요. 전체에서 가장 작은 두 후보를 골라야 해요.

정답: B

Q9. 만드는 동안과 완성 뒤

허프만 코드를 만들 때 쓰는 최소 힙과 완성된 허프만 트리는 각각 어떤 일을 할까요?

  1. 최소 힙은 코드 경로를 보여 주고, 허프만 트리는 합칠 후보를 골라요.
  2. 최소 힙은 합칠 후보를 고르고, 허프만 트리는 글자의 코드 경로를 보여 줘요.
  3. 최소 힙으로 후보를 고르고, 완성 트리 역시 최소 힙 조건을 만족해야 해요.
  4. 최소 힙으로 후보를 고르고, 완성 트리는 항상 최대 힙 모양으로 배치해요.
힌트 보기

후보 중 다음에 합칠 둘을 고를 때와 글자의 코드를 정할 때를 떠올려 보세요.

풀이 보기
  1. "후보 관리 구조와 코드 경로를 읽는 트리의 역할을 바꿈" — 노드 후보는 만드는 도중 최소 힙에서 꺼내요. 코드는 후보가 하나로 합쳐진 뒤 완성 트리에서 읽어요.
  2. 최소 힙에서 빈도가 작은 후보 두 개를 꺼내요. 완성 트리에서는 루트부터 각 글자의 단말까지 내려가며 코드를 읽어요.
  3. "완성 트리도 후보를 담은 최소 힙이라고 봄" — 완성 트리의 부모 빈도는 두 자식 빈도의 합이에요. 가장 작은 값이 루트에 와야 하는 최소 힙과 달라요.
  4. "강의 예제의 최대 힙 모양을 모든 허프만 트리에 적용함" — 부모의 빈도는 자식보다 크지만, 완성 트리가 최대 힙이려면 완전 이진 트리여야 해요. 한쪽으로 깊어지는 허프만 트리도 나올 수 있어요.

정답: B

Q10. 가지의 숫자 바꾸기

허프만 트리에서 어떤 글자의 코드는 1000이에요. 트리 모양은 두고 모든 가지에 붙은 0과 1만 서로 바꾸면 이 글자의 코드와 길이는 어떻게 될까요?

  1. 0111로 바뀌고, 길이는 4비트예요.
  2. 1000 그대로이고, 길이는 4비트예요.
  3. 0001로 바뀌고, 길이는 4비트예요.
  4. 111로 바뀌고, 길이는 3비트예요.
힌트 보기

루트에서 그 글자까지 가는 길을 그대로 두고, 각 가지에 붙은 숫자만 다시 읽어 보세요.

풀이 보기
  1. 같은 가지 네 개를 따라가며 원래 1은 0으로, 원래 0은 1로 읽어요.
  2. "트리 모양이 같으면 비트열도 같다고 봄" — 트리의 경로가 같아도 각 가지의 표시가 바뀌므로 읽는 비트열은 달라져요.
  3. "0과 1의 교환을 비트열의 순서 뒤집기로 봄" — 가지에 붙은 값을 바꿔도 루트에서 단말로 내려가는 순서는 같아요. 경로를 뒤집어 읽지 않아요.
  4. "경로를 나타내는 비트열을 정수로 읽고 앞의 0을 버림" — 코드 앞의 0도 실제로 지난 가지를 나타내요. 0111을 정수처럼 줄여 쓰면 그 가지를 빠뜨리게 돼요.

Q11. 한 글자가 차지하는 비트

허프만 코드 0110로 적는 글자 M이 메시지에 7번 나와요. 압축한 비트열에서 M을 적은 부분만 모으면 몇 비트일까요?

힌트 보기

M이 한 번 나올 때 적는 코드에서 비트가 몇 개인지 먼저 세어 보세요.

풀이 보기
  1. M의 코드 0110은 맨 앞의 0까지 세어서 4비트예요.
  2. M이 나올 때마다 4비트를 쓰므로 M에 쓰이는 비트 수는 $7 \times 4=28$비트예요.

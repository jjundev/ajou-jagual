핵심 조건과 구할 것

강의 S8 p15의 heap_sort(a, 5)에 입력 1, 23, 7, 8, 20을 넣었을 때 (a) 첫 for 루프 직후 힙 배열, (b) 둘째 for 루프의 단계별 변화와 최종 a[], (c) 뒤에서부터 채우는 이유와 시간 복잡도를 구해요.

  • 컴파일·정의 동작 조건: 원 코드 순서 그대로는 C99 이후 선언 없는 호출·미정의 타입 오류가 나지만, 문제가 두 typedef와 세 함수(init, insert_max_heap, delete_max_heap)의 원형이 heap_sort 앞에 있다고 보고 풀기로 약속했어요. 이 전제에서 n = 5 실행은 범위 밖 접근 없는 정의된 동작(UB 없음)이에요(0번 칸 미사용, MAX_ELEMENT = 200).

이 문제를 봤을 때 떠올릴 개념과 공식

문제 단서꺼낼 도구·코드 규칙이유와 조건
(a) 첫 루프: insert_max_heap 1-indexed upheap: i = ++heap_size, 부모 i / 2 새 값이 부모보다 크면 부모를 아래로 밀고 올라가며 최대 힙 불변식을 유지해요(1109 정리노트).
(b) 둘째 루프: delete_max_heap downheap: child < heap_size 일 때만 오른쪽 비교 루트 반환 후 끝 원소 temp를 내리되, 줄어든 heap_size 경계 밖을 읽지 않도록 해요(1109 정리노트).
(c) i = n-1부터 0까지 + 복잡도 최대 힙 추출 순서 + $2n \cdot O(\log n) = O(n \log n)$ 최대 힙은 큰 값부터 나오므로 맨 뒤부터 채워야 오름차순이 되고, 두 루프는 순차 실행이에요(정리노트).

종이에 쓰는 실제 첫 줄

init(&h) → heap_size = 0
i = 0: a[0] = 1 삽입 → i = 1, (i != 1) 거짓 → h.heap[1..1] = [1]

왜 이렇게 푸는지 함께 따라가요

(a) 첫 번째 for 루프: 삽입 5회

따라서 첫 루프 직후 h.heap[1..5]는 23, 20, 7, 1, 8이에요.

(b) 두 번째 for 루프: 삭제 5회 (i = 4부터 0까지)

a[]의 원소는 이미 모두 h에 복사되어 있으므로 뒤에서부터 덮어써도 데이터가 손실되지 않아요.

(c) 뒤에서부터 채우는 이유와 시간 복잡도
  • 뒤(n-1)부터 채우는 이유: delete_max_heap은 남은 원소 중 최댓값부터 꺼내므로, 가장 큰 23을 맨 뒤 a[4]에 놓고 인덱스를 줄여야 오름차순(1, 7, 8, 20, 23)이 돼요. 0부터 채우면 내림차순(23, 20, 8, 7, 1)이 돼요.
  • 시간 복잡도 근거: 두 for 루프는 중첩이 아니라 순차 실행돼요. 삽입 1회(최대 높이 $\lfloor \log_2 n \rfloor$ 상승)와 삭제 1회(최대 높이 하강)가 각각 $O(\log n)$이므로, $n \cdot O(\log n) + n \cdot O(\log n) = O(n \log n)$이에요.

완성 답과 검산

(a) 완성 답: h.heap[1..5] = [23, 20, 7, 1, 8].

검산: 부모-자식 쌍 (23; 20, 7), (20; 1, 8)이 모두 부모 ≥ 자식이고, 두 typedef와 세 함수 원형이 앞에 있다는 문제 약속 아래 C11 실행 결과와 100% 일치해요.

(b) 완성 답: i=4: 23(20 8 7 1) → i=3: 20(8 1 7) → i=2: 8(7 1) → i=1: 7(1) → i=0: 1(빈 힙), 최종 a[] = [1, 7, 8, 20, 23].

검산: C11 실행 시 0번 칸과 힙 밖을 더미 값(0xABABABAB)으로 채워도 결과나 남은 힙에 섞이지 않아 범위 밖 읽기가 없음을 확인했고, 최종 a[]가 입력 5개의 오름차순 정렬과 일치해요.

(c) 완성 답: 최대 힙은 큰 값부터 나오므로 a[n-1]부터 채워 오름차순 완성, 시간 복잡도 $O(n \log n)$.

검산(루프 불변식 및 경계): 각 반복 후 a[i..n-1]에는 가장 큰 $n-i$개가 오름차순으로 놓이고 힙에는 나머지 $i$개가 남아요. i=n-1(최댓값)에서 성립하고, 매 반복 꺼낸 값은 남은 최댓값이므로 a[i] <= a[i+1]이 유지돼 i=0 종료 시 전체 정렬이 보장돼요.

오해하기 쉬운 이유와 반례

  • (b)에서 child < h->heap_size 조건을 놓치고 방금 빠진 끝 칸까지 비교하면: i = 4의 두 번째 내려가기에서 child = 4일 때 heap_size = 4인데 5번 칸(옛 값 8 또는 쓰레기 값)을 읽어 heap[child+1]과 잘못 비교하게 돼요.
  • (c)에서 두 루프를 “중첩 루프”나 “동시 실행”으로 오해하면: 루프 2개가 나란히 있으므로 시간은 $O(n \cdot n) = O(n^2)$이 아니라 $O(n \log n) + O(n \log n) = O(n \log n)$이에요. 또 n = 200이면 heap[200]이 배열 크기 MAX_ELEMENT=200 범위를 벗어나므로 n <= 199여야 안전해요.

해설을 닫고 스스로 확인해요

  1. delete_max_heap 코드를 볼 때 → heap_size--가 먼저 실행된다는 점에 표시하고, 매 반복마다 줄어든 heap_size로 child < heap_size를 판정해 보세요.
  2. 만약 delete_min_heap(최소 힙)으로 바꾼다면 두 번째 루프의 인덱스 i는 0부터 올려야 할까요, n-1부터 내려야 할까요?

떠올릴 개념·공식

문제 약속(두 typedef·세 함수 원형 선행) 아래 정의된 C11 동작. upheap(i/2), downheap(child < heap_size), 순차 2루프 $O(n\log n)$.

첫 줄

i=0: key 1을 1번 칸(루트)에 삽입 → h.heap[1..1] = [1].

핵심 판단

(a) [23, 20, 7, 1, 8]. (b) a[4..0]에 23, 20, 8, 7, 1 저장 → [1, 7, 8, 20, 23]. (c) 큰 값부터 나와 뒤부터 채움.

검산

C11 실행 출력·범위 밖 미접근 확인, 루프 불변식(a[i..n-1] 정렬) 성립.

무엇을 구하라는 문제일까요?

글자 A부터 H까지가 섞인 100글자짜리 문서가 있고, 표는 각 글자가 몇 %(곧 100글자 중 몇 개) 나오는지 알려 줘요. 1)은 모든 글자를 같은 길이의 비트로 적을 때 글자당 몇 비트, 전체 몇 비트인지 묻고, 2)는 허프만 코딩(Huffman coding)으로 줄였을 때 전체 비트 수, 트리 그림, 글자별 code를 묻는 거예요. 가지에는 left 0, right 1을 붙이라는 조건이 있어요.

원문 1)은 “7가지의 character”라고 적었지만 표의 글자는 A~H로 8개예요. 원문 오기이고, 원본 시험지에서도 채점자가 7을 8로 고쳐 두었어요. 7로 읽어도 8로 읽어도 답이 3비트로 같아서 답에는 영향이 없어요.

이 문제를 봤을 때 떠올릴 개념과 공식

‘본래는 … 하나의 문자당 ( )bit’라는 단서에서 고정 길이 코드를 떠올려요. 비트 $b$개로는 $2^b$가지를 구별하니, 글자 $k$종류에는 $2^b \ge k$를 만족하는 가장 작은 $b$가 필요해요. 전체 비트는 글자 수 × $b$예요(정리노트: 자주 나오는 글자에 짧은 코드).

‘허프만 코딩으로 압축’과 빈도표라는 단서에서 허프만 코딩 트리를 떠올려요. 빈도마다 단말 노드를 만들고, 가장 작은 빈도 두 개를 자식으로 하는 새 노드(값은 두 빈도의 합)를 만드는 일을 노드가 하나 남을 때까지 반복해요(S8 p18). 가장 작은 둘을 꺼내고 합을 다시 넣는 일이 최소 힙(min heap), 곧 우선순위 큐가 잘하는 일이라 ‘히프 응용 3’이에요(정리노트: 가장 작은 두 개를 묶어 트리 만들기).

code는 루트에서 그 글자까지 내려가며 만난 가지 비트를 이은 것이고, 코드 길이는 그 글자의 깊이예요. 그래서 전체 비트 수는 $\sum (\text{빈도} \times \text{코드 길이})$예요(정리노트: 비트 코드와 100비트).

종이에 쓰는 실제 첫 줄

먼저 1)을 식 한 줄로 끝내요.

글자 8종: 2^2 = 4 < 8 <= 2^3 = 8 → 3 bit, 100 × 3 = 300 bit

2)는 빈도를 작은 순서로 한 줄에 늘어놓는 것부터 시작해요: D 1, H 2, E 5, B 8, G 9, A 15, C 20, F 40. 그다음 맨 앞 두 개 D 1, H 2를 묶어 3을 만드는 행이 병합 표의 첫 행이에요.

왜 이렇게 푸는지 함께 따라가요

1) 고정 길이 코드

2비트는 $2^2 = 4$가지만 구별해서 8글자에 모자라고, 3비트는 $2^3 = 8$가지라 딱 맞아요. 원문처럼 7가지로 읽어도 $4 < 7 \le 8$이라 3비트예요. 100글자이니 $100 \times 3 = 300$ bit예요.

2) 허프만 트리 만들기

매번 남은 노드 중 가장 작은 두 개를 꺼내 합치고, 합을 다시 넣어요.

문제는 어느 자식을 왼쪽에 둘지 정하지 않았어요. 같은 부모 아래 두 자식을 바꾸면 code의 0과 1은 달라질 수 있지만, 깊이는 그대로라 코드 길이(F 1, A·C·G 3, B 4, E 5, D·H 6)와 총 247 bit는 같아요.

완성 답과 검산

완성 답: 1) 3 bit, 300 bit(원문 “7가지”는 오기, 글자는 8개) 2) 247 bit, 위 트리, code A 100, B 1110, C 110, D 111111, E 11110, F 0, G 101, H 111110.

검산 1: 빈도 합 $15+8+20+1+5+40+9+2 = 100$이 루트 값 100과 같아요.

검산 2: 내부 노드 값의 합도 총 비트와 같아야 해요. 글자 하나가 깊이만큼의 내부 노드를 지나기 때문이에요. $3+8+16+24+36+60+100 = 247$로 표의 합과 같아요.

검산 3: 문제·그림만 보고 따로 짠 우선순위 큐 시뮬레이션(evidence/independent_verify.py)도 병합 순서 1+2, 3+5, 8+8, 9+15, 16+20, 24+36, 40+60과 총 247 bit를 냈어요. 동점 처리 순서를 고정 규칙 4가지와 무작위 순서 200가지, 모두 204가지로 바꿔 봐도 글자별 코드 길이와 247 bit는 한 가지로만 나왔어요. 그 시뮬레이션은 좌우를 다르게 놓아 F 0, G 100, A 101 …처럼 비트가 다르지만 길이는 모두 같아요. 원본 시험지의 채점 답안 code와도 일치해요.

검산 4: 어떤 code도 다른 code의 앞부분이 아니에요(예: 0으로 시작하는 것은 F 하나뿐). 그래서 구분자 없이도 하나로만 풀려요.

이 문제에서 특히 조심할 점

원문의 “7가지”를 그대로 믿고 글자 수를 7로 세면 안 돼요. 표를 직접 세면 8개예요. 이 문제는 3비트로 답이 같지만, 다른 문제에서는 $2^b$ 경계를 넘어 답이 바뀔 수 있어요.

방금 만든 노드를 무조건 다음 글자와 합치면 틀려요. 매번 남은 모든 노드 중 가장 작은 둘을 골라야 해요. 4단계에서 남은 값은 9, 15, 16, 20, 40이라 가장 작은 둘은 G 9와 A 15예요. 만든 노드를 계속 다음 글자에 붙여 3, 8, 16, 25, 40, 60, 100으로 합치면 내부 노드 합이 252가 되어 247보다 커져요.

총 비트를 ‘코드 길이의 합’으로 계산하면 안 돼요. 빈도를 곱한 $\sum(\text{빈도}\times\text{길이})$가 문서 전체 비트예요. 좌우 배치가 달라 code 비트가 채점 답과 달라도, 길이와 247이 같으면 같은 허프만 트리예요.

해설을 닫고 다시 해 봐요

  1. 글자 수를 직접 세고 $2^b \ge 8$인 가장 작은 $b$로 1)의 두 빈칸을 채워요.
  2. 빈도를 오름차순으로 적고 “가장 작은 둘을 합쳐 다시 넣기”를 일곱 번 하며 병합 표를 써요.
  3. 트리에 left 0, right 1을 붙여 code를 읽고, 내부 노드 합과 $\sum(\text{빈도}\times\text{길이})$가 둘 다 247인지 확인해요.

떠올릴 개념·공식

고정 길이: $2^b \ge$ 글자 종류 수인 최소 $b$. 허프만: 가장 작은 빈도 둘을 자식으로 하는 노드(값은 합)를 하나 남을 때까지 반복, 가장 작은 둘은 최소 힙으로 꺼내요. 총 비트 $= \sum(\text{빈도}\times\text{코드 길이})$.

첫 줄

글자 8종(원문 “7가지”는 오기) → 3 bit, 300 bit. 빈도 정렬 D 1, H 2, E 5, B 8, G 9, A 15, C 20, F 40에서 1+2=3부터 합쳐요.

핵심 판단

병합 3, 8, 16, 24, 36, 60, 100. code(채점 답안 배치) F 0, A 100, G 101, C 110, B 1110, E 11110, H 111110, D 111111. 좌우를 바꾸면 비트는 달라도 길이 F 1, A·C·G 3, B 4, E 5, D·H 6과 247 bit는 같아요.

검산

내부 노드 합 3+8+16+24+36+60+100 = 247, 독립 시뮬레이션·동점 변형 모두 247, 채점된 원본 답안과 일치해요.

### P1. 함수 foo는 무엇을 하는 함수일까요

2019-mid-q8 · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0917_Recursion.html#p1)

#### 주어진 조건

아래에 함수 foo의 코드가 있어요. 이 함수를 호출(사용)했을 때 무엇을 하는 함수인지 답해 보세요.

함수 foo는 ( ) 함수이다.

`int foo (int x, int y){
    if (x % y == 0) return y;
    else
        return foo(y, x % y);
}`

#### 기출 원문

2019 중간 8번 · 2점 · 출제자 미상

> "아래에는 함수 foo에 대한 코드가 있으며 이 함수를 호출(사용)하였을 때 무엇을 하는 함수인지에 대해서 답을 하시오.<br>함수 foo는 ( ) 함수이다. (2점)
>
> `int foo (int x, int y){
    if (x % y == 0) return y;
    else
        return foo(y, x % y);
}`
>
> "

#### 문제를 내 말로 읽어요

코드가 어떤 문제를 푸는지 이름이 아니라 인자 변화로 판단해요. 입력은 양의 정수 x,y로 두어요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

x%y라는 “나머지”와 (y,x%y) 호출은 Euclidean algorithm의 단서예요. x=qy+r일 때 x,y의 공약수 집합은 y,r의 공약수 집합과 같아요. y&gt;0일 때 0≤r&lt;y예요.

#### 종이에 적을 첫 줄

foo(48,18)에서 나머지 12를 첫 줄에 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

(48,18)→(18,12)→(12,6)에서 나머지가 0이 되어 6을 반환해요. 공약수 d가 x,y를 나누면 x−qy=r도 나누고, 반대로 y,r을 나누면 qy+r=x도 나눠요. 그래서 매 호출의 최대공약수가 같아요. 나머지가 양의 이전 y보다 작아 종료해요.

#### 완성 답과 검산

48의 약수와 18의 약수 중 공통 최대는 6이에요. 순서를 바꾼 foo(18,48)도 (48,18)로 이어져 6이에요. 따라서 답은 최대공약수 GCD예요.

#### 이 문제에서 조심할 점

원 함수는 y=0에서 %0이므로 정의되지 않아요. 양의 입력 조건 없이 모든 정수에 안전하다고 쓰지 않아요.

#### 설명을 닫고 다시 해 봐요

1. foo(48,18)에서 나머지 12를 첫 줄에 적어요.
2. 나머지로 줄이는 유클리드 호제법
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

#### 첫 줄

foo(48,18)에서 나머지 12를 첫 줄에 적어요.

#### 떠올릴 개념·공식

나머지로 줄이는 유클리드 호제법

### P2. 세 겹 for 루프의 T(n)과 빅오

다음 코드의 시간 복잡도를 n에 대한 함수 T(n)으로 나타내고, 빅오 표기법으로 표시해 보세요. 시간 복잡도를 구할 때는 `buffer[i][j] = 0;`의 대입 연산만 고려해요.

`int i, j, k;
for(i=0; i<n; i++){
    for(j=i; j<n; j++){
        for(k=0; k<30; k++){
            buffer[i][j] = 0;
        }
    }
}`

답: T(n) =<br>빅오 표기법:

#### 기출 원문

2018 중간 8번 · 2점 · 출제자 미상

> "다음의 코드의 시간 복잡도를 n에 대한 함수 T(n)으로 나타내고 빅오 표기법으로 표시하시오. ( 시간 복잡도를 구할 때 buffer[i][j] = 0; 의 대입 연산만 고려 ) [2 points].

#### 문제를 내 말로 읽어요

대입문 실행 횟수만 세어요. n은 비음수 정수이고 배열의 유효한 접근 범위를 가정해요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

j가 i부터 시작하므로 각 i의 j 반복 횟수는 n−i예요. k는 입력과 무관한 상수 30번이에요. 중첩 개수만 보고 n³이라고 판단하지 않아요.

#### 종이에 적을 첫 줄

i=0일 때 j는 n번, i=1일 때 n−1번이라고 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

T(n)=30×[n+(n−1)+…+1]=30n(n+1)/2예요. 상수와 낮은 차수를 지우면 O(n²), 더 정확한 성장률은 Θ(n²)이에요. 합 공식은 앞뒤 항을 짝지으면 각 쌍의 합이 n+1인 데서 나와요.

#### 완성 답과 검산

n=3이면 j 횟수는 3+2+1=6이라 대입은 180번이에요. n=0에서는 0번, n=1에서는 30번으로 공식과 맞아요. 별도 반복문으로 n=0..20의 횟수를 확인해요.

#### 이 문제에서 조심할 점

변형 카드의 k 상수와 아래 기출 원문 30을 구별해요. 답은 현재 카드의 상수로 계산해요.

#### 설명을 닫고 다시 해 봐요

1. i=0일 때 j는 n번, i=1일 때 n−1번이라고 적어요.
2. 상수×삼각수, O(n²)
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

#### 첫 줄

i=0일 때 j는 n번, i=1일 때 n−1번이라고 적어요.

#### 떠올릴 개념·공식

상수×삼각수, O(n²)

임의의 두 양의 정수의 최대 공약수를 구해주는 gcd를 순환 함수로 구현해 보세요. 두 양의 정수는 main 함수에서 입력받아요.

`#include <stdio.h>
int gcd(int i, int j){

}
int main(){
    int i, j;
    printf("임의의 두 양의 정수 입력:");
    scanf("%d %d", &i, &j);
    printf("gcd:%d\n", gcd(i, j));
    return 0;
}`

int gcd(int i, int j){

#### 문제를 내 말로 읽어요

빈 gcd 본문을 채워 양의 두 정수의 최대공약수를 반환해요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

“순환 함수”와 “최대공약수”에서 gcd(i,j)=gcd(j,i%j)를 떠올려요. %를 계산하기 전에 j=0을 검사해야 나눗셈 오류 없이 종료해요.

#### 종이에 적을 첫 줄

`if (j == 0) return i;`

#### 왜 이렇게 푸는지 함께 따라가요

`int gcd(int i, int j) {
    if (j == 0) return i;
    return gcd(j, i % j);
}`

#### 완성 답과 검산

gcd(48,18)→(18,12)→(12,6)→(6,0)→6이에요. 반환값은 추가 계산 없이 위 호출로 전달돼요. 공약수 집합 보존과 두 번째 인자의 감소가 정확성과 종료를 증명해요. 입력 변환 성공과 양의 int 범위를 가정해요.

#### 이 문제에서 조심할 점

if 앞에서 i%j를 계산하면 마지막 호출에서 %0을 하게 돼요. “0이 모든 수를 나눈다”가 아니라 모든 양의 수가 0을 나눈다는 뜻이에요.

#### 설명을 닫고 다시 해 봐요

1. if (j == 0) return i;
2. j=0 종료, 아니면 gcd(j,i%j)
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

#### 첫 줄

#### 떠올릴 개념·공식

j=0 종료, 아니면 gcd(j,i%j)

### P4. 자기 자신을 다시 부르는 기법

2018-mid-c102-q1 · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0917_Recursion.html#p4)

#### 주어진 조건

빈칸에 알맞은 말을 써 보세요.

함수가 수행 도중에 자기 자신을 다시 호출하여 문제를 해결하는 기법을 ( ) 이라고 한다.

#### 기출 원문

2018 중간 1번 · 2점 · 출제자 미상

> "1. 함수가 수행 도중에 자기 자신을 다시 호출하여 문제를 해결하는 기법을 ( ) 이라고 한다. [2 points]"

#### 문제를 내 말로 읽어요

함수가 자기 자신을 호출한다는 설명에 맞는 이름을 쓰는 문제예요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

“자기 자신을 다시 호출”은 recursion, 수업 용어로 순환(재귀)이에요. 일반 반복 iteration은 루프를 돌지만 별도의 자기 호출을 만들지 않아요.

#### 종이에 적을 첫 줄

빈칸에 순환(recursion)을 적어요.

#### 왜 이렇게 푸는지 함께 따라가요

답은 순환, 또는 동의어 재귀예요. 예를 들어 factorial(3)이 factorial(2)를 호출하면 작은 문제의 답을 받아 현재 답을 만들어요. 올바른 순환은 즉시 답을 주는 바닥 조건과 그 조건으로 다가가는 감소를 함께 가져요.

#### 완성 답과 검산

반복문만 있는 sum은 자기 호출이 없어요. 반대로 함수 안의 자기 호출은 루프가 없어도 순환이에요. 이 차이로 용어를 확인해요.

#### 이 문제에서 조심할 점

함수 이름을 두 번 썼다고 항상 실행 중 자기 호출은 아니에요. 실제 호출 관계를 보아요.

#### 설명을 닫고 다시 해 봐요

1. 빈칸에 순환(recursion)을 적어요.
2. 자기 호출 = 순환/재귀
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

#### 첫 줄

빈칸에 순환(recursion)을 적어요.

#### 떠올릴 개념·공식

자기 호출 = 순환/재귀

#### 종이에 적을 첫 줄

`if (n == 1) return 1;`

#### 왜 이렇게 푸는지 함께 따라가요

`int sum(int n) {
    if (n == 1) return 1;
    return n + sum(n - 1);
}`

#### 완성 답과 검산

n=4에서 4+3+2+1=10이에요. 귀납적으로 sum(n−1)이 1..n−1의 합이면 현재 n을 더해 1..n의 합이 돼요. n은 양의 정수이며 결과가 int에 표현 가능하다고 가정해요.

#### 이 문제에서 조심할 점

n≤0 입력에 이 바닥 조건을 그대로 쓰면 정상 종료가 안 돼요. 입력 범위를 적어요.

#### 설명을 닫고 다시 해 봐요

1. if (n == 1) return 1;
2. 바닥 1, n+sum(n−1)
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

### P12. 재귀 합을 반복문으로

textbook-ch02-q16 · [원 문제 보기](../%EB%B3%B5%EC%8A%B5%EB%AC%B8%EC%A0%9C_0917_Recursion.html#p12)

#### 주어진 조건

다음의 순환적인 프로그램을 반복 구조를 사용한 비순환적 프로그램으로 바꾸시오.

`int sum(int n)
{
    if(n == 1 ) return 1;
    else return (n + sum(n-1));
}`

#### 기출 원문

2장 순환 · 16번 · 책 65쪽

다음의 순환적인 프로그램을 반복 구조를 사용한 비순환적 프로그램으로 바꾸시오.

`int sum(int n)
{
    if(n == 1 ) return 1;
    else return (n + sum(n-1));
}`

#### 문제를 내 말로 읽어요

원래 sum의 결과를 유지하면서 자기 호출을 반복문으로 바꿔요.

#### 이 문제를 봤을 때 떠올릴 개념과 공식

“비순환적”은 accumulator와 loop의 단서예요. 원 코드가 양의 n에서 더한 항 1..n을 반복문도 한 번씩 더하면 같아요.

#### 종이에 적을 첫 줄

`int total = 0;`

#### 왜 이렇게 푸는지 함께 따라가요

`int sum(int n) {
    int total = 0;
    for (int i = 1; i <= n; ++i) total += i;
    return total;
}`

#### 완성 답과 검산

n=1→1, n=4→10으로 원 순환과 같아요. 각 i 뒤 total=1+…+i 불변식이 모든 양의 입력의 동일성을 보장해요. 계산이 int 범위 안이고 i++도 범위를 넘지 않는 입력을 가정해요.

#### 이 문제에서 조심할 점

순환이 아닌 코드를 요구하므로 본문에서 sum을 다시 부르면 안 돼요. n≤0은 원 코드의 정의된 입력이 아니에요.

#### 설명을 닫고 다시 해 봐요

1. int total = 0;
2. 0에서 1..n 누적, 호출 제거
3. 조건·끝 상태와 검산 근거를 직접 다시 확인해요.

**페이지 요약**

#### 첫 줄

int total = 0;

#### 떠올릴 개념·공식

0에서 1..n 누적, 호출 제거

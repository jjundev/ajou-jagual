P1. 원형 큐의 get_count

원형큐에 큐에 존재하는 요소의 개수를 반환하는 연산 get_count를 추가하여 보라. C언어를 이용하여 구현하여 보라.

front는 첫 원소 직전, rear는 마지막 원소이며 한 칸을 비우는 강의 규약이에요.

문제를 읽어 볼게요

빙글 돌아가는 줄에서 앞 표시와 뒤 표시만 보고, 실제로 몇 칸이 차 있는지 세는 함수를 만들어요.

이 문제를 봤을 때 떠올릴 개념과 공식

‘원형 큐’, ‘요소의 개수’, ‘get_count’라는 단서에서 두 인덱스 사이의 순환 거리를 떠올려요. 수업의 원형 큐에서 front는 첫 요소 하나 앞, rear는 마지막 요소의 칸이에요. 크기 $M$인 배열에서 다음 칸은 $(i+1)\bmod M$이고 한 칸을 비워 실제 개수는 $0$부터 $M-1$까지예요. 그래서 순환 거리 (rear - front + MAX_QUEUE_SIZE) % MAX_QUEUE_SIZE가 개수예요. $M$은 MAX_QUEUE_SIZE, 나머지 연산은 끝에서 0으로 돌아간 위치를 정규화해요.

첫 줄을 이렇게 써요

종이에 front 다음 칸부터 rear까지 시계 방향으로 세어 보고, “개수 = 순환 거리”라고 적어요.

왜 이렇게 푸는지 함께 따라가요

front가 3이고 rear가 5라면 방문 칸은 4, 5이므로 두 개예요. 7에서 1로 감겨도 방문 칸은 0, 1이므로 두 개예요. 단순 차이는 음수가 될 수 있어 $M$을 더한 뒤 나머지를 취해요. 공백이면 두 인덱스가 같아 0이에요.

#define MAX_QUEUE_SIZE 8
typedef struct {
    int front;
    int rear;
} QueueType;

int get_count(const QueueType *q) {
    return (q->rear - q->front + MAX_QUEUE_SIZE) % MAX_QUEUE_SIZE;
}

이 함수는 유효한 인덱스와 한 칸 비우는 원형 큐 규칙을 전제해요. 인덱스 두 개를 읽고 일정 횟수로 계산해 $O(1)$이에요.

완성 답과 검산

정답은 (rear - front + MAX_QUEUE_SIZE) % MAX_QUEUE_SIZE예요. $M=8$에서 $(5-3+8)\bmod8=2$, $(1-7+8)\bmod8=2$예요. 별도의 시계 방향 순회 계산으로 유효한 front·rear 조합 64개를 모두 대조했고 값이 일치했어요. 포화 상태도 한 칸 비워 7로 나와요.

여기서 헷갈리기 쉬워요

front 칸 자체를 세면 하나가 많아져요. rear - front만 쓰면 인덱스가 7에서 0으로 돌아갈 때 음수가 돼요. 모든 칸을 채우는 다른 원형 큐 구현에는 별도의 포화 구분 정보가 필요하므로 이 식을 그대로 적용할 수 없어요.

설명을 닫고 다시 해 봐요

  1. front=7, rear=1에서 실제 점유 칸을 적으세요.
  2. 순환 거리 식에 대입하세요.
  3. 공백과 포화 경계에서 각각 0과 7이 되는지 확인하세요.

첫 줄

front 다음부터 rear까지 세어요.

떠올릴 개념·공식

원형 큐의 순환 거리: (rear - front + MAX_QUEUE_SIZE) % MAX_QUEUE_SIZE.

답과 검산

64개 인덱스 쌍을 직접 순회한 개수와 식이 모두 같아요.

조건·구분과 확인

  • 0≤front,rear<M이며 한 칸 비우는 구현에만 적용해요. 공백 0·포화 M-1개이고 계산 O(1)이에요. 모든 칸을 채우는 구현은 별도 포화 구분이 필요해요.

문제를 읽어 볼게요

위에서만 꺼낼 수 있는 두 통으로, 먼저 넣은 물건을 먼저 꺼내는 줄을 만들어요.

이 문제를 봤을 때 떠올릴 개념과 공식

‘두 스택’, ‘입력은 스택 #1’, ‘출력은 스택 #2’라는 단서에서 스택의 후입선출(LIFO) 순서를 두 번 뒤집어 큐의 선입선출(FIFO)을 만드는 방법을 떠올려요. 입력 스택 in에는 새 값을 쌓아요. 출력 스택 out이 비었을 때에만 in의 값을 모두 옮기면, 가장 오래된 값이 out의 맨 위에 와요. out에 값이 남아 있을 때 옮기면 나중에 온 값이 먼저 나오는 오류가 생겨요.

각 값은 입력·이동·출력에서 상수 번만 다뤄지므로 여러 연산을 합친 분할상환(amortized) 비용은 연산당 $O(1)$이에요. 한 번의 이동을 포함한 dequeue 최악 비용은 $O(n)$이에요.

첫 줄을 이렇게 써요

“enqueue는 #1에 push, dequeue는 #2가 빌 때만 #1 전체를 #2로 이동한 뒤 pop”이라고 적어요.

왜 이렇게 푸는지 함께 따라가요

아래 C 함수는 원 카드의 용량 256, 두 top 초기값 0, 성공 1·실패 0 계약을 그대로 사용해요. in.top + out.top은 전체 저장 개수라 용량 검사는 두 스택을 합쳐야 해요.

#define CAP 256
typedef struct { int a[CAP], top; } Stack;
typedef struct { Stack in, out; } TwoStackQueue;
/* 두 top은 0으로 초기화해 사용해요. 1은 성공, 0은 실패예요. */
int enqueue(TwoStackQueue *q, int value) {
    if (q->in.top + q->out.top >= CAP) return 0;
    q->in.a[q->in.top++] = value;
    return 1;
}
int dequeue(TwoStackQueue *q, int *value) {
    if (q->out.top == 0) {
        while (q->in.top > 0)
            q->out.a[q->out.top++] = q->in.a[--q->in.top];
    }
    if (q->out.top == 0) return 0;
    *value = q->out.a[--q->out.top];
    return 1;
}
  1. 10, 20, 30을 넣으면 in의 아래에서 위로 10, 20, 30이에요.
  2. 첫 삭제 때 #2가 비었으므로 30, 20, 10 순서로 옮겨 out의 위가 10이 돼요. 10을 꺼내요.
  3. 40을 새로 넣어도 out에 20, 30이 남아 있으므로 이동하지 않아요. 이어서 20, 30을 꺼내요.
  4. 그다음 #2가 비면 #1의 40을 옮겨 꺼내요. 전체 출력은 10, 20, 30, 40이에요.

완성 답과 검산

두 스택으로 FIFO 큐를 구현할 수 있어요. 독립 시뮬레이션에서 enqueue(10), enqueue(20), enqueue(30), dequeue(), enqueue(40), dequeue(), dequeue(), dequeue()의 출력이 10, 20, 30, 40이었어요. 빈 큐 삭제는 0을 반환하고 출력 포인터의 기존 값을 유지해요. 총 256개 저장 후 추가 삽입은 0을 반환해요. q와 value는 유효한 포인터여야 해요.

여기서 헷갈리기 쉬워요

#2에 값이 남았는데 #1을 옮기면 나중에 들어온 40이 먼저 나올 수 있어요. #1만 보고 용량을 검사하면 두 스택의 합이 배열 용량을 넘어갈 수 있어요.

설명을 닫고 다시 해 봐요

  1. #1과 #2의 아래·위 방향을 그리세요.
  2. 10, 20, 30을 넣고 한 번 꺼낸 뒤 40을 넣으세요.
  3. #2가 남은 동안 다음 값이 무엇인지 쓰세요.

첫 줄

입력은 #1, 출력은 #2가 빌 때만 옮긴 뒤 pop.

떠올릴 개념·공식

스택을 두 번 뒤집으면 FIFO. 분할상환 $O(1)$, 이동하는 한 번은 최악 $O(n)$.

답과 검산

교차 삽입·삭제의 출력은 10, 20, 30, 40이에요.

조건·구분과 확인

  • 두 top은 0으로 시작하고 in.top+out.top으로 총 용량 256을 검사해요. 성공 1·실패 0이며 빈 삭제는 출력값을 유지하고 q·value는 유효해야 해요.
  • out에 값이 남아 있으면 in을 옮기지 않아요. 먼저 옮기면 새로 온 값이 앞서 FIFO가 깨져요.

문제를 읽어 볼게요

문장의 양끝 글자를 하나씩 꺼내 비교해요. 쉼표와 빈칸은 건너뛰고, 끝까지 같으면 거꾸로 읽어도 같은 말이에요.

이 문제를 봤을 때 떠올릴 개념과 공식

‘앞뒤 어느 쪽에서 읽어도 같음’, ‘덱을 이용’이라는 단서에서 덱(deque)의 앞·뒤 삭제를 떠올려요. 회문(palindrome)은 무시할 구두점·공백을 걷어 내고 대소문자를 맞춘 문자들의 양 끝이 매번 같은 문자열이에요. 양끝이 다르면 즉시 거짓이고, 길이가 0 또는 1이 되도록 모두 맞으면 참이에요. 문자 수가 $k$이면 비교는 최대 $\lfloor k/2\rfloor$번이에요.

교과서에는 C 구현을 위한 인코딩·로캘 규칙이 없어요. 아래 카드의 C 코드는 UTF-8 입력과 실행 환경의 UTF-8 로캘을 전제로 wchar_t 문자로 해독해요. 이 해독과 iswalnum·towlower는 수업의 덱 원리에서 유도한 내용이 아니라 구현 보충이에요. 로캘별 문자 분류와 한 글자씩의 소문자화에 한정하며 모든 유니코드 정규화·완전한 대소문자 접기는 수행하지 않아요.

첫 줄을 이렇게 써요

“문자를 정리해 덱에 넣고, 두 개 이상 남는 동안 앞과 뒤를 하나씩 꺼내 비교한다”라고 적어요.

왜 이렇게 푸는지 함께 따라가요

원 카드의 코드에서는 head와 tail이 배열 덱의 양쪽 경계예요. 유효한 문자만 뒤에 추가해 d[head..tail)을 만들고, 앞에서는 d[head++], 뒤에서는 d[--tail]을 꺼내요. 코드 자체는 카드와 같은 구현이에요.

#include <locale.h>
#include <stdlib.h>
#include <string.h>
#include <wchar.h>
#include <wctype.h>
#define CAP 256
/* UTF-8 로캘에서 1=회문, 0=비회문, -1=입력·로캘 오류/용량 초과 */
int is_palindrome(const char *s) {
    if (!s) return -1;
    const char *loc = setlocale(LC_CTYPE, "");
    if (!loc || !(strstr(loc, "UTF-8") || strstr(loc, "utf8"))) return -1;
    wchar_t d[CAP];
    size_t head = 0, tail = 0, i = 0;
    mbstate_t state = {0};
    while (s[i] != '\0') {
        wchar_t ch;
        size_t n = mbrtowc(&ch, s + i, strlen(s + i), &state);
        if (n == (size_t)-1 || n == (size_t)-2 || n == 0) return -1;
        if (iswalnum(ch)) {
            if (tail == CAP) return -1;
            d[tail++] = towlower(ch);
        }
        i += n;
    }
    while (tail - head > 1) {
        if (d[head++] != d[--tail]) return 0;
    }
    return 1;
}
  1. radar: r와 r, a와 a가 같고 d 한 글자가 남아 참이에요.
  2. A man, a plan, a canal: Panama!: 빈칸·구두점·대소문자를 정리하면 amanaplanacanalpanama가 되어 양끝 비교가 모두 같아요.
  3. 가나: UTF-8 로캘에서 가와 나가 달라 거짓이에요. 한글 바이트를 버리고 빈 문자열로 오판하지 않아요.

완성 답과 검산

양 끝에서 꺼낸 문자가 모두 같으면 회문이에요. 제시한 코드의 반환값은 회문 1, 비회문 0, 입력·로캘 오류나 용량 초과 -1이에요. 독립 실행에서 radar, 문장 예시, 빈 문자열, 한 글자는 1이고 가나는 0이에요. 잘못된 UTF-8 바이트와 정리 후 257자는 -1이에요. 입력이 NULL인 경우도 -1이에요. 양 끝을 하나씩 없애므로 덱에서 $O(k)$번의 삭제를 해요.

여기서 헷갈리기 쉬워요

바이트마다 isalnum을 호출하면 UTF-8 한글을 문자로 읽지 못해 가나를 잘못 참으로 판단할 수 있어요. 실행 환경에 UTF-8 로캘이 없으면 이 코드는 -1을 반환해요. 배열 크기 CAP은 원본 바이트가 아니라 정리 후 문자 수의 상한이에요. 원문 그림의 rear·front 방향보다 양 끝에서 같은 문자를 하나씩 꺼낸다는 규칙이 핵심이에요.

설명을 닫고 다시 해 봐요

  1. 구두점·공백·대소문자를 어떻게 처리할지 적으세요.
  2. radar의 양끝을 두 차례 비교하세요.
  3. 비회문과 잘못된 입력에서 반환값을 구별하세요.

첫 줄

정리한 문자를 덱에 넣고 양 끝을 하나씩 비교해요.

떠올릴 개념·공식

덱 양끝 삭제로 최대 $\lfloor k/2\rfloor$번 비교해요. UTF-8 문자 해독은 구현 보충이에요.

답과 검산

같으면 1, 다르면 0, 입력·로캘·용량 오류는 -1이에요.

조건·구분과 확인

  • 구두점·공백을 빼고 대소문자를 맞춘 뒤 양끝이 다르면 거짓, 0개나 1개만 남을 때까지 같으면 참이에요.
  • 구현 보충: UTF-8 로캘에서 wchar_t로 해독하고 정리 후 문자 최대 256개를 다뤄요. 로캘별 분류·한 문자 소문자화에 한정하며 완전한 유니코드 정규화·대소문자 접기는 하지 않아요.

P4. 연결 큐 의사코드를 대입문으로 옮기기

lecture-s06-p11-linked-queue · 원 문제 보기

강의 예제 기반 자체 출제 S6 p11

단순 연결 큐의 노드는 data, link 필드를 가지며 공백 큐 상태는 front = rear = NULL이에요. 아래 의사코드를 C 포인터 대입문으로 옮겨 보세요.

/* 대입문으로 옮길 연산의 의사코드 */
enqueue: 새 노드 N(이미 할당되어 N->link = NULL)을 rear 뒤에 연결하고 rear를 갱신
dequeue: front 노드(old)의 값을 보관하고 front를 다음으로 이동한 뒤 old를 해제

구할 것

  1. (a) 이미 할당·초기화되어 N->link = NULL인 새 노드 N을 삽입할 때, 공백 큐(front == NULL)인 경우와 비공백 큐인 경우를 처리하는 enqueue의 포인터 대입문을 쓰세요.
  2. (b) 비어 있지 않은 큐에서 첫 노드 old = front를 꺼내는 dequeue의 대입문을 쓰고, 노드가 하나뿐이어서 삭제 후 front == NULL이 되었을 때 rear = NULL까지 함께 갱신해야 하는 이유를 설명하세요.
강의 예제 보기

S6 p11 · Software_6_Queue.pdf. 강의 연결 그림의 동작을 요약한 자체 의사코드이며 강의 원문 C 코드는 아닙니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

/* 강의 연결 큐 그림을 바탕으로 작성할 의사코드 */
enqueue: 새 노드를 rear 뒤에 연결하고 rear를 갱신
dequeue: front 노드의 값을 보관하고 front를 다음으로 이동

문제를 내 말로 읽어요

단순 연결 큐의 enqueue와 dequeue 의사코드를 공백·단일 노드 경계 조건에 주의하며 C 포인터 대입문으로 옮기는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “연결 큐 의사코드를 대입문으로 옮기기”예요. 첫 노드를 넣을 때는 기존 rear가 없으므로 front = N으로 두고, 마지막 노드를 꺼내 front == NULL이 되면 rear = NULL까지 함께 초기화해야 해요.

종이에 적을 첫 줄

공백 큐 조건 front == NULL(양 끝 모두 NULL)을 먼저 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) enqueue에서 큐가 비어 있으면(front == NULL) front = N;으로 첫 노드를 가리키게 하고, 비어 있지 않으면 rear->link = N;으로 기존 꼬리 뒤에 연결한 뒤, 두 경우 모두 rear = N;으로 꼬리 포인터를 갱신해요.

(b) dequeue에서는 old = front; item = old->data; front = old->link;로 값을 꺼내고 머리를 옮긴 뒤, 만약 front == NULL이면 마지막 노드가 삭제된 것이므로 rear = NULL;로 함께 비워 주고 free(old);를 호출해요. 그렇지 않으면 rear가 해제된 노드를 가리키게 돼요.

완성 답과 검산

(a) 빈 큐에 N 하나를 enqueue하면 front = rear = N, N->link = NULL이 되어 단일 노드 큐 불변식이 성립해요.

(b) 그 유일한 노드 N을 dequeue하면 front = N->link = NULL이 되고 if (front == NULL) rear = NULL;에 의해 초기 공백 상태 front = rear = NULL로 정확히 돌아와요.

이 문제에서 조심할 점

의사코드의 각 단계를 빠짐없이 대입문으로 옮기세요. 빈 큐와 노드가 하나뿐인 경우를 따로 확인해요.

설명을 닫고 다시 해 봐요

  1. front == NULL일 때와 아닐 때 enqueue의 대입문을 각각 적어요.
  2. dequeue에서 노드 해제 전후로 수행할 포인터 갱신문을 순서대로 적어요.
  3. front == NULL일 때 rear = NULL을 생략하면 남는 문제를 확인해요.

첫 줄

공백 큐 조건 front == NULL(양 끝 모두 NULL)을 먼저 적어요.

떠올릴 개념·공식

빈 큐 삽입은 front = rear = N, 마지막 노드 삭제 후에는 front = rear = NULL로 맞춰요.

검산

(a) if (front == NULL) front = N; else rear->link = N; rear = N; (b) old = front; item = old->data; front = old->link; if (front == NULL) rear = NULL; free(old);

P5. 시뮬레이션의 if/else가 만드는 한 틱

강의 예제 기반 자체 출제 S6 p22

은행 대기열 시뮬레이션에서 시각 clock이 1씩 증가할 때마다 실행되는 루프 본문이에요. clock = 1에서 아래 코드 실행 직전 service_time = 1이고 고객 B(서비스 시간 2)가 방금 도착하며, clock = 2, 3에는 새 고객 도착이 없다고 가정해요(remove_customer()는 큐에서 고객을 꺼내 서비스 시간을 반환하고 대기 시간을 기록해요).

else service_time = remove_customer();

  1. (a) clock = 1, 2, 3 각 시각에서 위 코드가 실행된 직후 service_time의 변화와, 고객 B의 서비스 시작 시각 및 대기 시간을 쓰세요.
  2. (b) 만약 두 번째 문장의 else를 떼어 별도의 if (service_time == 0) service_time = remove_customer();로 바꾸면, clock = 1에서의 동작과 고객 B의 대기 시간이 어떻게 달라지는지 설명하세요.
강의 예제 보기

S6 p22 · Software_6_Queue.pdf. 강의 코드의 해당 연산을 발췌해 들여쓰기를 정리했습니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

else service_time=remove_customer();

문제를 내 말로 읽어요

은행 대기열 시뮬레이션 루프에서 if (service_time > 0) ... else ... 구조 때문에 한 틱에 시간 감소와 새 고객 서비스 시작 중 하나만 실행되는 흐름을 추적하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “시뮬레이션의 if/else가 만드는 한 틱”예요. if 조건이 참이어서 service_time--로 0이 되었더라도 그 if에 묶인 else는 같은 틱에 실행되지 않고 다음 틱에 실행돼요.

종이에 적을 첫 줄

clock = 1 진입 시점의 상태 service_time = 1을 먼저 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) clock = 1에 고객 B가 도착해 큐에 들어가고, 진입 시 service_time = 1 > 0이므로 service_time이 1 -> 0으로 줄며 else는 건너뛰어요. clock = 2에는 처음부터 service_time == 0이므로 else가 실행되어 고객 B를 꺼내 service_time = 0 -> 2가 되고 대기 시간은 2 - 1 = 1이 돼요. clock = 3에는 service_time이 2 -> 1로 줄어요.

(b) 만약 else 대신 별도의 if (service_time == 0)를 쓰면, clock = 1에서 service_time이 1 -> 0이 된 직후 같은 틱에 두 번째 if 조건도 참이 되어 고객 B가 clock = 1에 즉시 시작하고 대기 시간이 0이 돼요.

완성 답과 검산

(a) if/else는 상호 배타적이므로 clock = 1에서는 감소만, clock = 2에서는 꺼내기만, clock = 3에서는 감소만 일어나요.

(b) 두 개의 독립된 if로 분리하면 한 틱 안에서 상태 변경 후 재평가가 일어나 이벤트 시각이 1틱 앞당겨짐을 확인할 수 있어요.

이 문제에서 조심할 점

말로 된 설명과 실제 if/else 순서를 구별하세요. 서비스가 0이 된 직후 같은 틱에 즉시 다음 고객을 꺼내는 코드가 아니에요.

설명을 닫고 다시 해 봐요

  1. clock = 1, 2, 3마다 분기 진입 전 service_time과 실행 후 service_time을 적어요.
  2. 고객 B의 도착 시각과 서비스 시작 시각으로 대기 시간을 계산해요.
  3. else를 별도 if (service_time == 0)로 바꿨을 때 clock = 1의 실행 흐름을 비교해요.

첫 줄

clock = 1 진입 시점의 상태 service_time = 1을 먼저 적어요.

떠올릴 개념·공식

if/else는 한 틱에 한 분기만 실행하므로 1 -> 0 감소와 새 고객 시작은 서로 다른 틱에 일어나요.

검산

(a) clock = 1: 1 -> 0, clock = 2: 0 -> 2(B 시작, 대기 1), clock = 3: 2 -> 1 (b) 별도 if 사용 시 clock = 1에 즉시 시작해 대기 0

P6. 원형 큐의 인덱스를 먼저 옮기기

lecture-s06-p9-circular-queue · 원 문제 보기

강의 예제 기반 자체 출제 S6 p9

배열 크기 MAX_QUEUE_SIZE = 5(M = 5)인 원형 큐에서 현재 front = 3, rear = 1이며 유효 원소는 queue[4] = A, queue[0] = B, queue[1] = C예요.

/* enqueue의 정상 경로 */
q->rear = (q->rear + 1) % MAX_QUEUE_SIZE;
q->queue[q->rear] = item;
/* dequeue의 정상 경로 */
q->front = (q->front + 1) % MAX_QUEUE_SIZE;
return q->queue[q->front];

구할 것

  1. (a) 위 상태에서 dequeue(), enqueue(D), enqueue(E)를 순서대로 실행할 때, 각 연산의 반환값(해당 시), 실행 직후 (front, rear), 큐의 논리적 원소 나열을 쓰고 마지막 상태의 포화 여부를 판정하세요.
  2. (b) 크기 M = 5인 원형 큐에서 한 칸을 비워 둘 때의 최대 저장 가능 원소 수(유효 용량)와 포화 상태 판정식을 쓰세요.
강의 예제 보기

S6 p9 · Software_6_Queue.pdf. 강의 코드의 해당 연산을 발췌해 들여쓰기를 정리했습니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

/* enqueue의 정상 경로 */
q->rear=(q->rear+1)%MAX_QUEUE_SIZE;
q->queue[q->rear]=item;
/* dequeue의 정상 경로 */
q->front=(q->front+1)%MAX_QUEUE_SIZE;
return q->queue[q->front];

문제를 내 말로 읽어요

크기 M = 5인 원형 큐에서 나머지 연산(% M)으로 인덱스를 먼저 한 칸 옮긴 뒤 읽거나 쓰는 동작을 추적하고 유효 용량과 포화 조건식을 구하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “원형 큐의 인덱스를 먼저 옮기기”예요. front는 첫 원소 하나 앞을, rear는 마지막 원소를 가리키며, 한 칸을 비워 공백(front == rear)과 포화((rear + 1) % M == front)를 구별해요.

종이에 적을 첫 줄

첫 연산 dequeue()에서 front = (3 + 1) % 5 = 4부터 계산해요.

왜 이렇게 푸는지 함께 따라가요

(a) dequeue()는 front를 4로 옮겨 queue[4] = A를 반환하고 (front, rear) = (4, 1), 원소 [B, C]가 남아요. 이어 enqueue(D)는 rear를 2로 옮겨 (4, 2), [B, C, D]가 되고, enqueue(E)는 rear를 3으로 옮겨 (4, 3), [B, C, D, E]가 되며 (3 + 1) % 5 == 4 == front이므로 포화 상태가 돼요.

(b) 크기 M = 5인 배열에서 공백과 포화를 구별하기 위해 항상 한 칸을 비워 두므로 유효 용량은 M - 1 = 4이고, 포화 판정식은 (rear + 1) % M == front예요.

완성 답과 검산

(a) 최종 상태에서 원소는 queue[0]=B, queue[1]=C, queue[2]=D, queue[3]=E 총 4개이고 queue[4](front = 4) 한 칸만 비어 있어 포화 상태와 일치해요.

(b) 만약 queue[4]까지 채우면 rear = 4가 되어 공백 조건 front == rear와 같아지므로 한 칸을 비워 두어야 함을 확인할 수 있어요.

이 문제에서 조심할 점

front 자리의 값을 먼저 반환하면 이미 삭제한 자리나 빈자리를 읽어요.

설명을 닫고 다시 해 봐요

  1. dequeue(), enqueue(D), enqueue(E) 실행 직후의 (front, rear)와 원소 목록을 차례대로 적어요.
  2. 마지막 상태에서 (rear + 1) % 5를 계산해 front와 비교해요.
  3. 유효 용량 M - 1과 포화 판정식을 적어요.

첫 줄

첫 연산 dequeue()에서 front = (3 + 1) % 5 = 4부터 계산해요.

떠올릴 개념·공식

원형 큐는 인덱스를 먼저 (idx + 1) % M으로 옮긴 뒤 접근하며, 포화 조건은 (rear + 1) % M == front예요.

검산

(a) dequeue: A, (4, 1), [B, C]; enqueue(D): (4, 2), [B, C, D]; enqueue(E): (4, 3), [B, C, D, E], 포화 (b) 유효 용량 M - 1 = 4, 포화식 (rear + 1) % M == front

구할 것

  1. (a) 빈 덱(dq->head = dq->tail = NULL)에 add_rear(dq, A)를 실행한 직후와 이어서 add_rear(dq, B)를 실행한 직후, dq->head, dq->tail 및 각 노드의 llink, rlink 값을 모두 쓰세요.
  2. (b) create_node 내부에서 새 노드의 세 필드를 초기화하는 대입문을 쓰고, is_empty(dq)가 참일 때 dq->head = new_node;도 함께 설정해야 하는 이유를 설명하세요.
강의 예제 보기

S6 p16 · Software_6_Queue.pdf. 강의 코드의 해당 연산을 발췌해 들여쓰기를 정리했습니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

void add_rear(DequeType *dq,element item)
{
    DlistNode *new_node=create_node(dq->tail,item,NULL);
    if(is_empty(dq)) dq->head=new_node;
    else dq->tail->rlink=new_node;
    dq->tail=new_node;
}

문제를 내 말로 읽어요

이중 연결 리스트 기반 덱의 빈 상태에서 add_rear를 두 번 호출할 때 양 끝 포인터(head, tail)와 노드 링크(llink, rlink)가 어떻게 연결되는지 추적하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “덱의 첫 삽입과 양 끝 포인터”예요. 빈 덱에서는 첫 노드가 head이자 tail이 되며, create_node(left, item, right)가 새 노드의 세 필드를 초기화해요.

종이에 적을 첫 줄

첫 삽입의 create_node(NULL, A, NULL) 호출부터 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) 빈 덱에 A를 넣으면 create_node(NULL, A, NULL)로 A.llink = A.rlink = NULL이 되고, is_empty(dq)가 참이어서 head = tail = A가 돼요. 이어서 B를 넣으면 create_node(A, B, NULL)로 B.llink = A, B.rlink = NULL이 되고, else 분기로 A.rlink = B를 연결한 뒤 tail = B가 되어 head = A, tail = B가 돼요.

(b) create_node 내부 대입문은 node->llink = left; node->data = item; node->rlink = right;예요. 공백 덱에서 첫 노드를 넣을 때 dq->head = new_node;를 설정하지 않으면 head가 계속 NULL로 남아 앞쪽에서 첫 노드를 참조할 수 없어요.

완성 답과 검산

(a) 두 번 삽입한 뒤 head(A)->rlink == B이고 tail(B)->llink == A이며 양 끝 외곽 링크(A.llink, B.rlink)는 모두 NULL이어서 이중 연결 불변식이 성립해요.

(b) 첫 삽입에서 head와 tail이 모두 A를 가리켜야 이후 delete_front나 두 번째 add_rear가 정상 동작함을 확인할 수 있어요.

이 문제에서 조심할 점

tail만 새 노드로 옮기면 이전 노드에서 새 노드로 가는 오른쪽 연결(rlink)이 생기지 않아요.

설명을 닫고 다시 해 봐요

  1. 첫 삽입 직후 head, tail, A.llink, A.rlink를 적어요.
  2. 두 번째 삽입 직후 head, tail과 A, B의 양쪽 링크를 모두 적어요.
  3. create_node의 세 필드 대입문과 빈 덱에서 head를 갱신하는 이유를 적어요.

첫 줄

첫 삽입의 create_node(NULL, A, NULL) 호출부터 적어요.

떠올릴 개념·공식

빈 덱에 첫 원소를 넣을 때는 head와 tail을 모두 새 노드로 설정하고, 비공백 덱에서는 기존 tail->rlink와 새 노드의 llink를 상호 연결해요.

검산

(a) 1회: head = tail = A; 2회: head = A, tail = B, A.rlink = B, B.llink = A (b) node->llink = left; node->data = item; node->rlink = right;, 빈 덱 첫 노드 접근 보장

조건·구분과 확인

  • 첫 A의 llink는 NULL, 새 B의 rlink도 NULL로 유지해 양 끝 바깥으로 연결되지 않게 해요.

P8. 덱에서 마지막 원소를 삭제할 때

lecture-s06-p17-deque-delete · 원 문제 보기

강의 예제 기반 자체 출제 S6 p17

이중 연결 리스트로 구현한 덱에서 맨 앞 노드를 꺼내는 delete_front 함수예요.

element delete_front(DequeType *dq)
{
    element item; DlistNode *removed_node;
    if (is_empty(dq)) error("공백 덱에서 삭제");
    else {
        removed_node = dq->head;
        item = removed_node->data;
        dq->head = dq->head->rlink;
        free(removed_node);
        if (dq->head == NULL) dq->tail = NULL;
        else dq->head->llink = NULL;
    }
    return item;
}

구할 것

  1. (a) 두 노드가 A <-> B로 연결된 덱(dq->head = A, dq->tail = B)에서 delete_front(dq)를 연속으로 두 번 호출할 때, 각 호출의 반환값과 호출 직후 dq->head, dq->tail 및 남은 노드의 링크 상태를 쓰세요.
  2. (b) 함수 마지막의 if (dq->head == NULL) dq->tail = NULL; else dq->head->llink = NULL; 두 분기가 각각 유지하는 불변식과, 이 분기를 생략했을 때 생기는 문제를 설명하세요.
강의 예제 보기

S6 p17 · Software_6_Queue.pdf. 강의 코드의 해당 연산을 발췌해 들여쓰기를 정리했습니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

element delete_front(DequeType *dq)
{
    element item; DlistNode *removed_node;
    if(is_empty(dq)) error("공백 덱에서 삭제");
    else {
        removed_node=dq->head;
        item=removed_node->data;
        dq->head=dq->head->rlink;
        free(removed_node);
        if(dq->head==NULL) dq->tail=NULL;
        else dq->head->llink=NULL;
    }
    return item;
}

문제를 내 말로 읽어요

A <-> B 두 노드가 있는 덱에서 delete_front를 두 번 호출할 때 포인터 변화를 추적하고, 삭제 후 남은 노드가 있는지 여부에 따라 갈리는 마지막 if/else의 역할을 확인하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “덱에서 마지막 원소를 삭제할 때”예요. 머리 노드를 지운 뒤 dq->head == NULL이면 빈 덱이므로 dq->tail = NULL로 맞추고, 노드가 남아 있으면 새 머리의 왼쪽 링크 dq->head->llink = NULL로 끊어 줘요.

종이에 적을 첫 줄

첫 호출에서 removed_node = A, item = A를 먼저 보관해요.

왜 이렇게 푸는지 함께 따라가요

(a) 첫 호출에서는 A를 꺼내고 dq->head를 B로 옮긴 뒤 else 분기로 B.llink = NULL로 만들어 head = tail = B(B.llink = B.rlink = NULL)가 돼요. 두 번째 호출에서는 B를 꺼내고 dq->head = NULL이 되어 if 분기로 dq->tail = NULL로 맞추므로 head = tail = NULL이 돼요.

(b) 마지막 if/else는 공백 덱의 head = tail = NULL 불변식과 비공백 덱의 head->llink = NULL 불변식을 각각 유지해요. 이를 생략하면 빈 덱의 tail이나 남은 첫 노드의 llink가 이미 해제된 노드를 가리키는 댕글링 포인터가 돼요.

완성 답과 검산

(a) 첫 호출에서는 else 분기가, 두 번째 호출에서는 if 분기가 각각 한 번씩 실행되어 두 경계 경우를 모두 거치게 돼요.

(b) 두 번째 호출에서 if (dq->head == NULL) 검사 없이 무조건 dq->head->llink = NULL을 실행하면 NULL 포인터 역참조 오류가 발생함도 확인할 수 있어요.

이 문제에서 조심할 점

dq->head == NULL인 경우 dq->head->llink = NULL을 실행하면 NULL 역참조가 발생하므로 반드시 두 경우를 나눠야 해요.

설명을 닫고 다시 해 봐요

  1. 첫 번째 delete_front 후 반환값과 head, tail, B.llink를 적어요.
  2. 두 번째 delete_front 후 반환값과 head, tail을 적어요.
  3. 마지막 if/else를 생략했을 때 남는 잘못된 포인터를 설명해요.

첫 줄

첫 호출에서 removed_node = A, item = A를 먼저 보관해요.

떠올릴 개념·공식

삭제 후 dq->head == NULL이면 dq->tail = NULL로, 아니면 dq->head->llink = NULL로 갱신해요.

검산

(a) 1회: 반환 A, head = tail = B, B.llink = NULL; 2회: 반환 B, head = tail = NULL (b) 양 끝 NULL 불변식 유지 및 해제 노드 참조 방지

조건·구분과 확인

  • 분기를 빼면 tail이나 새 머리의 llink가 해제 노드를 가리켜요. 공백에서 무조건 head->llink를 쓰면 NULL 역참조예요.

P9. 원형 큐의 front와 rear

문제를 먼저 읽어요

여덟 칸짜리 원형 줄에서 처음 앞·뒤 표시가 0이에요. 여섯 값을 넣고 넷을 빼고 다시 넷을 넣은 뒤 두 표시의 위치를 구해요.

이 문제를 봤을 때 떠올릴 개념과 공식

“원형 큐”, “크기 8”, “front와 rear”가 단서예요. 이 강의의 원형 큐(circular queue)는 front가 첫 원소 하나 앞, rear가 마지막 원소를 가리켜요. 삽입(enqueue)은 rear만 한 칸 옮기고 저장하고, 삭제(dequeue)는 front만 한 칸 옮긴 뒤 그 칸의 값을 읽어요.

배열 인덱스는 0부터 7까지라 다음 칸은 (현재 인덱스 + 1) % 8이에요. 포화 조건 (rear + 1) % 8 == front를 확인해야 해요. 한 칸을 비워 실제 용량은 7개예요. 이 문제의 최대 점유는 6개라 모든 삽입이 가능해요. 값 04는 원문 그대로 보관하고, 인덱스 계산에는 값의 크기를 쓰지 않아요.

첫 줄을 이렇게 써요

종이에 크기 8, front=0, rear=0을 적고, 첫 삽입을 rear=(0+1)%8=1, 1번 칸=10으로 시작해요.

왜 이렇게 푸는지 함께 따라가요

넣을 때는 rear만, 뺄 때는 front만 움직여요. 아래 표에서 ·는 현재 큐에 속하지 않는 칸이에요.

여기서 실수하기 쉬워요

04를 임의로 40으로 고치지 않아요. 값의 표기는 인덱스 답에 영향을 주지 않아요. 7번 칸 다음 rear는 8이 아니라 0이에요.

설명을 닫고 다시 해 봐요

  1. 각 삽입·삭제가 어느 포인터를 움직이는지 적어요.
  2. 7 다음에 0으로 돌아가는 지점을 표시해요.
  3. 마지막 요소 수를 별도로 세어 검산해요.

떠올릴 개념·공식

원형 큐: 다음 인덱스=(현재+1)%8, front는 첫 원소 하나 앞이에요.

첫 줄

front=rear=0에서 첫 삽입의 rear를 1로 옮겨요.

핵심 판단

삭제 4회와 삽입 10회를 각각 세어 front=4, rear=2예요.

검산

(rear-front+8)%8=6이며 실제 남은 값도 6개예요.

조건·구분과 확인

  • 한 칸을 비우는 용량 7에서 최대 점유는 6이라 모든 삽입이 가능해요. 원문 04를 바꾸지 않고 삭제된 칸의 잔여 값은 현재 원소로 세지 않아요.

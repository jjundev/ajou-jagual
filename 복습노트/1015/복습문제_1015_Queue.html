P1. 원형 큐의 get_count

구현 조건: 강의처럼 front는 첫 원소 직전, rear는 마지막 원소의 인덱스이며 M칸 중 한 칸을 비워요. 0≤front,rear<M이에요.

  2. #define MAX_QUEUE_SIZE 8
typedef struct {
    int front;
    int rear;
} QueueType;

int get_count(const QueueType *q) {
    return (q->rear - q->front + MAX_QUEUE_SIZE) % MAX_QUEUE_SIZE;
}
  3. 예: front=3, rear=5면 (5 - 3 + 8) % 8 = 2예요. front=7, rear=1이면 (1 - 7 + 8) % 8 = 2예요.

힌트 보기

풀이 보기
  1. #1에 넣은 순서를 #2로 옮길 때 뒤집으면 먼저 넣은 값이 먼저 나와 FIFO가 돼요.
  2. #define CAP 256
typedef struct { int a[CAP], top; } Stack;
typedef struct { Stack in, out; } TwoStackQueue;
/* 두 top은 0으로 초기화해 사용해요. 1은 성공, 0은 실패예요. */
int enqueue(TwoStackQueue *q, int value) {
    if (q->in.top + q->out.top >= CAP) return 0;
    q->in.a[q->in.top++] = value;
    return 1;
}
int dequeue(TwoStackQueue *q, int *value) {
    if (q->out.top == 0) {
        while (q->in.top > 0)
            q->out.a[q->out.top++] = q->in.a[--q->in.top];
    }
    if (q->out.top == 0) return 0;
    *value = q->out.a[--q->out.top];
    return 1;
}
  3. 예: 10, 20, 30을 넣고 꺼내면 10이에요. 그 뒤 40을 넣어도 다음 출력은 #2에 남은 20이에요.
  4. 두 top을 0으로 초기화하고, 실패 때 출력 포인터의 값은 바꾸지 않아요. 전체 CAP개면 삽입 실패, 빈 큐면 삭제 실패예요.

#include <stdlib.h>
#include <string.h>
#include <wchar.h>
#include <wctype.h>
#define CAP 256
/* UTF-8 로캘에서 1=회문, 0=비회문, -1=입력·로캘 오류/용량 초과 */
int is_palindrome(const char *s) {
    if (!s) return -1;
    const char *loc = setlocale(LC_CTYPE, "");
    if (!loc || !(strstr(loc, "UTF-8") || strstr(loc, "utf8"))) return -1;
    wchar_t d[CAP];
    size_t head = 0, tail = 0, i = 0;
    mbstate_t state = {0};
    while (s[i] != '\0') {
        wchar_t ch;
        size_t n = mbrtowc(&ch, s + i, strlen(s + i), &state);
        if (n == (size_t)-1 || n == (size_t)-2 || n == 0) return -1;
        if (iswalnum(ch)) {
            if (tail == CAP) return -1;
            d[tail++] = towlower(ch);
        }
        i += n;
    }
    while (tail - head > 1) {
        if (d[head++] != d[--tail]) return 0;
    }
    return 1;
}

P4. 연결 큐 의사코드를 대입문으로 옮기기

강의 예제 기반 자체 출제 S6 p11

단순 연결 큐의 노드는 data, link 필드를 가지며 공백 큐 상태는 front = rear = NULL이에요. 아래 의사코드를 C 포인터 대입문으로 옮겨 보세요.

/* 대입문으로 옮길 연산의 의사코드 */
enqueue: 새 노드 N(이미 할당되어 N->link = NULL)을 rear 뒤에 연결하고 rear를 갱신
dequeue: front 노드(old)의 값을 보관하고 front를 다음으로 이동한 뒤 old를 해제
  1. (a) 이미 할당·초기화되어 N->link = NULL인 새 노드 N을 삽입할 때, 공백 큐(front == NULL)인 경우와 비공백 큐인 경우를 처리하는 enqueue의 포인터 대입문을 쓰세요.
  2. (b) 비어 있지 않은 큐에서 첫 노드 old = front를 꺼내는 dequeue의 대입문을 쓰고, 노드가 하나뿐이어서 삭제 후 front == NULL이 되었을 때 rear = NULL까지 함께 갱신해야 하는 이유를 설명하세요.
강의 예제 보기

/* 강의 연결 큐 그림을 바탕으로 작성할 의사코드 */
enqueue: 새 노드를 rear 뒤에 연결하고 rear를 갱신
dequeue: front 노드의 값을 보관하고 front를 다음으로 이동
힌트 보기

첫 노드를 넣을 때는 기존 rear가 없으므로 rear->link에 접근하지 않고 front = N으로 정한 뒤 공통으로 rear = N을 실행해요.

풀이 보기
  1. (a) 첫 노드를 넣는 공백 상태(front == NULL)에서는 기존 rear가 없으므로 front = N;으로 설정하고, 비공백 상태에서는 rear->link = N;으로 기존 꼬리 뒤에 연결한 다음, 두 경우 모두 공통으로 rear = N;으로 꼬리 포인터를 갱신해요.
  2. (b) 삭제에서는 old = front; item = old->data; front = old->link;로 값을 보관하고 머리를 다음 노드로 옮긴 뒤, 만약 front == NULL이면 마지막 노드가 제거된 빈 큐이므로 rear = NULL;로 함께 초기화하고 free(old);를 호출해요. 그렇지 않으면 rear가 이미 해제된 노드를 가리키는 댕글링 포인터가 되기 때문이에요.

정답: (a) enqueue: if (front == NULL) front = N; else rear->link = N; rear = N; (b) dequeue: old = front; item = old->data; front = old->link; if (front == NULL) rear = NULL; free(old);이며, 빈 큐에서 rear도 NULL로 바꾸지 않으면 rear가 해제된 노드를 가리키게 된다.

의사코드의 각 단계를 빠짐없이 대입문으로 옮기세요. 빈 큐와 노드가 하나뿐인 경우를 따로 확인해요.

P5. 시뮬레이션의 if/else가 만드는 한 틱

강의 예제 기반 자체 출제 S6 p22

은행 대기열 시뮬레이션에서 시각 clock이 1씩 증가할 때마다 실행되는 루프 본문이에요. clock = 1에서 아래 코드 실행 직전 service_time = 1이고 고객 B(서비스 시간 2)가 방금 도착하며, clock = 2, 3에는 새 고객 도착이 없다고 가정해요(remove_customer()는 큐에서 고객을 꺼내 서비스 시간을 반환하고 대기 시간을 기록해요).

if (is_customer_arrived()) insert_customer(clock);
if (service_time > 0) service_time--;
else service_time = remove_customer();
  1. (a) clock = 1, 2, 3 각 시각에서 위 코드가 실행된 직후 service_time의 변화와, 고객 B의 서비스 시작 시각 및 대기 시간을 쓰세요.
  2. (b) 만약 두 번째 문장의 else를 떼어 별도의 if (service_time == 0) service_time = remove_customer();로 바꾸면, clock = 1에서의 동작과 고객 B의 대기 시간이 어떻게 달라지는지 설명하세요.
강의 예제 보기

S6 p22 · Software_6_Queue.pdf. 강의 코드의 해당 연산을 발췌해 들여쓰기를 정리했습니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

if(is_customer_arrived()) insert_customer(clock);
if(service_time>0) service_time--;
else service_time=remove_customer();
힌트 보기

if 조건은 분기에 들어갈 때 한 번만 평가해요. service_time을 1에서 0으로 줄였더라도 그 if에 묶인 else가 같은 틱에 이어서 실행되지는 않아요.

풀이 보기
  1. (a) clock = 1에서는 고객 B가 큐에 들어가고, 진입 시점 service_time > 0(1 > 0)이 참이므로 service_time이 1 -> 0으로만 줄고 else는 실행되지 않아요. clock = 2에서는 처음부터 service_time == 0이므로 else 분기가 실행되어 고객 B를 꺼내 서비스를 시작(service_time = 0 -> 2)하며, 대기 시간은 2 - 1 = 1이에요. clock = 3에서는 service_time이 2 -> 1로 줄어요.
  2. (b) else 대신 별도의 if (service_time == 0)를 쓰면, clock = 1에서 앞 문장이 service_time을 1 -> 0으로 줄인 직후 같은 틱 안에서 두 번째 if 조건이 참이 되어 고객 B가 clock = 1에 바로 서비스를 시작하고 대기 시간이 0으로 바뀌어요.

정답: (a) clock = 1: 1 -> 0(else 미실행); clock = 2: 0 -> 2(고객 B 서비스 시작, 대기 시간 2 - 1 = 1); clock = 3: 2 -> 1 (b) 별도의 if (service_time == 0)로 바꾸면 clock = 1에서 1 -> 0 감소 직후 같은 틱에 remove_customer()가 실행되어 고객 B가 clock = 1에 바로 시작하고 대기 시간이 0이 된다.

말로 된 설명과 실제 if/else 순서를 구별하세요. 서비스가 0이 된 직후 같은 틱에 즉시 다음 고객을 꺼내는 코드가 아니에요.

P6. 원형 큐의 인덱스를 먼저 옮기기

강의 예제 기반 자체 출제 S6 p9

배열 크기 MAX_QUEUE_SIZE = 5(M = 5)인 원형 큐에서 현재 front = 3, rear = 1이며 유효 원소는 queue[4] = A, queue[0] = B, queue[1] = C예요.

/* enqueue의 정상 경로 */
q->rear = (q->rear + 1) % MAX_QUEUE_SIZE;
q->queue[q->rear] = item;
/* dequeue의 정상 경로 */
q->front = (q->front + 1) % MAX_QUEUE_SIZE;
return q->queue[q->front];
  1. (a) 위 상태에서 dequeue(), enqueue(D), enqueue(E)를 순서대로 실행할 때, 각 연산의 반환값(해당 시), 실행 직후 (front, rear), 큐의 논리적 원소 나열을 쓰고 마지막 상태의 포화 여부를 판정하세요.
  2. (b) 크기 M = 5인 원형 큐에서 한 칸을 비워 둘 때의 최대 저장 가능 원소 수(유효 용량)와 포화 상태 판정식을 쓰세요.
강의 예제 보기

S6 p9 · Software_6_Queue.pdf. 강의 코드의 해당 연산을 발췌해 들여쓰기를 정리했습니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

/* enqueue의 정상 경로 */
q->rear=(q->rear+1)%MAX_QUEUE_SIZE;
q->queue[q->rear]=item;
/* dequeue의 정상 경로 */
q->front=(q->front+1)%MAX_QUEUE_SIZE;
return q->queue[q->front];
힌트 보기

front는 첫 원소 바로 앞자리예요. 먼저 (3 + 1) % 5 = 4로 옮기고 A를 꺼내요.

풀이 보기
  1. (a) dequeue()는 front를 (3 + 1) % 5 = 4로 옮겨 A를 반환하고 (front, rear) = (4, 1), 남은 원소는 [B, C]가 돼요. 이어 enqueue(D)는 rear를 2로 옮겨 (4, 2), [B, C, D]가 되고, enqueue(E)는 rear를 3으로 옮겨 (4, 3), [B, C, D, E]가 되며 (3 + 1) % 5 == 4 == front이므로 포화 상태예요.
  2. (b) 공백 상태(front == rear)와 구별하려고 항상 한 칸을 비워 두므로 유효 용량은 M - 1 = 4개이고, 포화 판정식은 (rear + 1) % M == front예요.

정답: (a) dequeue(): 반환 A, (front, rear) = (4, 1), [B, C]; enqueue(D): (4, 2), [B, C, D]; enqueue(E): (4, 3), [B, C, D, E] (포화 상태) (b) 유효 용량은 M - 1 = 4이며, 포화 판정식은 (rear + 1) % M == front이다.

front 자리의 값을 먼저 반환하면 이미 삭제한 자리나 빈자리를 읽어요.

P7. 덱의 첫 삽입과 양 끝 포인터

강의 예제 기반 자체 출제 S6 p16

이중 연결 리스트로 구현한 덱(deque)에서 create_node(left, item, right)는 새 노드의 llink, data, rlink를 각각 설정해 반환해요. 아래는 꼬리에 원소를 넣는 add_rear 함수예요.

void add_rear(DequeType *dq, element item)
{
    DlistNode *new_node = create_node(dq->tail, item, NULL);
    if (is_empty(dq)) dq->head = new_node;
    else dq->tail->rlink = new_node;
    dq->tail = new_node;
}
  1. (a) 빈 덱(dq->head = dq->tail = NULL)에 add_rear(dq, A)를 실행한 직후와 이어서 add_rear(dq, B)를 실행한 직후, dq->head, dq->tail 및 각 노드의 llink, rlink 값을 모두 쓰세요.
  2. (b) create_node 내부에서 새 노드의 세 필드를 초기화하는 대입문을 쓰고, is_empty(dq)가 참일 때 dq->head = new_node;도 함께 설정해야 하는 이유를 설명하세요.
강의 예제 보기

{

    if(is_empty(dq)) dq->head=new_node;
    else dq->tail->rlink=new_node;

힌트 보기

빈 덱에서는 새 노드가 첫 노드이자 마지막 노드예요. create_node(NULL, A, NULL)가 양 끝 링크를 NULL로 만들어요.

풀이 보기
  1. (a) 첫 삽입에서는 create_node(NULL, A, NULL)로 A.llink = A.rlink = NULL이 되고, 빈 덱이므로 dq->head = dq->tail = A가 돼요. 두 번째 삽입에서는 create_node(A, B, NULL)로 B.llink = A, B.rlink = NULL이 되고, else 분기로 A.rlink = B를 연결한 뒤 dq->tail = B로 옮겨 dq->head = A, dq->tail = B가 돼요.
  2. (b) create_node는 node->llink = left; node->data = item; node->rlink = right;로 세 필드를 설정해요. 공백 덱에 첫 원소를 넣을 때는 그 노드가 유일한 노드여서 머리이자 꼬리가 되므로, dq->head를 함께 설정하지 않으면 head가 NULL로 남아 앞쪽에서 첫 노드에 접근할 수 없어요.

정답: (a) 첫 삽입 후: head = tail = A, A.llink = A.rlink = NULL; 두 번째 삽입 후: head = A, tail = B, A.llink = NULL, A.rlink = B, B.llink = A, B.rlink = NULL (b) create_node 대입문은 node->llink = left; node->data = item; node->rlink = right;이며, 빈 덱에서 dq->head를 설정하지 않으면 head가 NULL로 남아 첫 노드에 접근할 수 없다.

tail만 새 노드로 옮기면 이전 노드에서 새 노드로 가는 연결이 생기지 않아요.

P8. 덱에서 마지막 원소를 삭제할 때

강의 예제 기반 자체 출제 S6 p17

이중 연결 리스트로 구현한 덱에서 맨 앞 노드를 꺼내는 delete_front 함수예요.

element delete_front(DequeType *dq)
{
    element item; DlistNode *removed_node;
    if (is_empty(dq)) error("공백 덱에서 삭제");
    else {
        removed_node = dq->head;
        item = removed_node->data;
        dq->head = dq->head->rlink;
        free(removed_node);
        if (dq->head == NULL) dq->tail = NULL;
        else dq->head->llink = NULL;
    }
    return item;
}
  1. (a) 두 노드가 A <-> B로 연결된 덱(dq->head = A, dq->tail = B)에서 delete_front(dq)를 연속으로 두 번 호출할 때, 각 호출의 반환값과 호출 직후 dq->head, dq->tail 및 남은 노드의 링크 상태를 쓰세요.
  2. (b) 함수 마지막의 if (dq->head == NULL) dq->tail = NULL; else dq->head->llink = NULL; 두 분기가 각각 유지하는 불변식과, 이 분기를 생략했을 때 생기는 문제를 설명하세요.
강의 예제 보기

S6 p17 · Software_6_Queue.pdf. 강의 코드의 해당 연산을 발췌해 들여쓰기를 정리했습니다. 주변 선언·main·입출력을 생략한 발췌·번역은 완전한 실행 프로그램과 구별해요. 아래 질문·입력 조건은 자체 출제예요.

element delete_front(DequeType *dq)
{

    if(is_empty(dq)) error("공백 덱에서 삭제");
    else {
        removed_node=dq->head;
        item=removed_node->data;

힌트 보기

첫 삭제에서는 A를 해제한 뒤 남은 B의 왼쪽 링크를 NULL로 끊고, 두 번째 삭제에서는 dq->head가 NULL이 되므로 dq->tail도 NULL로 맞춰요.

풀이 보기
  1. (a) 첫 번째 호출은 A를 반환하고 dq->head를 B로 옮긴 뒤 else 분기로 B.llink = NULL로 끊어 dq->head = dq->tail = B(B.llink = B.rlink = NULL)가 돼요. 두 번째 호출은 B를 반환하고 dq->head = B.rlink = NULL이 되어 if 분기로 dq->tail = NULL까지 설정하므로 dq->head = dq->tail = NULL이 돼요.
  2. (b) if 분기는 "공백 덱의 head와 tail은 모두 NULL이다"라는 불변식을 지키고, else 분기는 "비공백 덱의 첫 노드 왼쪽 링크(head->llink)는 항상 NULL이다"라는 불변식을 지켜요. 이를 생략하면 빈 덱의 tail이나 새 첫 노드의 llink가 이미 해제된 노드를 가리키는 댕글링 포인터가 돼요.

정답: (a) 첫 호출: 반환 A, head = tail = B, B.llink = B.rlink = NULL; 두 번째 호출: 반환 B, head = tail = NULL (b) 공백 덱은 head = tail = NULL이고 비공백 덱은 head->llink = NULL이라는 불변식을 유지하며, 생략하면 tail이나 새 head->llink가 해제된 노드를 가리킨다.

dq->head == NULL인 경우 dq->head->llink = NULL을 실행하면 NULL 역참조가 발생하므로 반드시 두 경우를 나눠야 해요.

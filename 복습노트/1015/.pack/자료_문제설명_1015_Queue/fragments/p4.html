문제를 먼저 읽어요

둥근 줄에 아무도 없는 상태를 알려 주는 표시를 골라요. 앞·뒤 표시가 어디에서 만나는지 살펴봐요.

이 문제를 봤을 때 떠올릴 개념과 공식

“원형큐에서 공백상태”가 단서예요. 이 강의의 원형 큐(circular queue)는 front가 첫 원소 하나 앞, rear가 마지막 원소예요. 삽입과 삭제를 모두 마치면 위치가 0이 아니어도 두 인덱스가 같아져요.

따라서 공백(empty)의 조건은 front == rear예요. 포화(full)는 다음 rear가 front에 닿는 (rear+1)%MAX_QUEUE_SIZE == front예요. 둘을 구별하려고 한 칸을 비워요. 보기의 조건이 모든 공백 상태를 잡는지 확인해야 해요.

첫 줄을 이렇게 써요

종이에 공백 ⇔ front == rear를 적고, 예로 front=rear=3을 대입해 각 선택지가 모두 성립하는지 살펴봐요.

왜 이렇게 푸는지 함께 따라가요

(a) front == 0 && rear == 0은 0에서 비는 경우만 잡아요. 둘 다 3인 공백 상태를 놓치므로 일반 조건이 아니에요.

(b) front == MAX_QUEUE_SIZE-1 && rear == MAX_QUEUE_SIZE-1은 마지막 칸에서 비는 경우만 잡아요. 둘 다 3인 공백 상태를 놓쳐요.

(c) front == rear는 같은 위치가 0이든 3이든 모두 공백으로 판정해요. 정답이에요.

(d) front == (rear+1)%MAX_QUEUE_SIZE는 다음 삽입 위치가 front와 같다는 뜻이라 포화 조건이에요.

완성 답과 검산

(a)에 front=rear=3을 대입하면 거짓이지만 큐는 비어 있어요. 따라서 오답이에요.

(b)에도 front=rear=3을 대입하면 거짓이라 공백을 놓쳐요.

(c)는 front=rear=0, front=rear=3, front=rear=7 모두 참이에요. 정답은 (c) front == rear예요.

(d)는 8칸에서 front=3, rear=2를 넣으면 3==(2+1)%8로 참이고 점유 수는 (2-3+8)%8=7이에요. 즉 공백이 아니라 포화예요.

여기서 실수하기 쉬워요

초기값이 0이라고 해서 공백이 항상 0에서만 생기지는 않아요. 삭제를 마치면 두 인덱스가 다른 위치에서도 같아질 수 있어요.

설명을 닫고 다시 해 봐요

  1. 초기 위치 외의 공백 예를 하나 만들어요.
  2. 각 보기에 그 값을 대입해요.
  3. 포화 조건과 공백 조건을 구분해요.

떠올릴 개념·공식

공백: front == rear; 포화: (rear+1)%MAX_QUEUE_SIZE == front예요.

첫 줄

공백 ⇔ front == rear를 먼저 적어요.

핵심 판단

모든 위치의 공백을 잡는 (c)를 골라요.

검산

front=rear=3은 (a)·(b)를 반박하고, front=3·rear=2는 (d)가 포화임을 보여 줘요.

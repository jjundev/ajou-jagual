문제를 읽어 볼게요

위에서만 꺼낼 수 있는 두 통으로, 먼저 넣은 물건을 먼저 꺼내는 줄을 만들어요.

이 문제를 봤을 때 떠올릴 개념과 공식

‘두 스택’, ‘입력은 스택 #1’, ‘출력은 스택 #2’라는 단서에서 스택의 후입선출(LIFO) 순서를 두 번 뒤집어 큐의 선입선출(FIFO)을 만드는 방법을 떠올려요. 입력 스택 in에는 새 값을 쌓아요. 출력 스택 out이 비었을 때에만 in의 값을 모두 옮기면, 가장 오래된 값이 out의 맨 위에 와요. out에 값이 남아 있을 때 옮기면 나중에 온 값이 먼저 나오는 오류가 생겨요.

각 값은 입력·이동·출력에서 상수 번만 다뤄지므로 여러 연산을 합친 분할상환(amortized) 비용은 연산당 $O(1)$이에요. 한 번의 이동을 포함한 dequeue 최악 비용은 $O(n)$이에요.

첫 줄을 이렇게 써요

“enqueue는 #1에 push, dequeue는 #2가 빌 때만 #1 전체를 #2로 이동한 뒤 pop”이라고 적어요.

왜 이렇게 푸는지 함께 따라가요

아래 C 함수는 원 카드의 용량 256, 두 top 초기값 0, 성공 1·실패 0 계약을 그대로 사용해요. in.top + out.top은 전체 저장 개수라 용량 검사는 두 스택을 합쳐야 해요.

#define CAP 256
typedef struct { int a[CAP], top; } Stack;
typedef struct { Stack in, out; } TwoStackQueue;
/* 두 top은 0으로 초기화해 사용해요. 1은 성공, 0은 실패예요. */
int enqueue(TwoStackQueue *q, int value) {
    if (q->in.top + q->out.top >= CAP) return 0;
    q->in.a[q->in.top++] = value;
    return 1;
}
int dequeue(TwoStackQueue *q, int *value) {
    if (q->out.top == 0) {
        while (q->in.top > 0)
            q->out.a[q->out.top++] = q->in.a[--q->in.top];
    }
    if (q->out.top == 0) return 0;
    *value = q->out.a[--q->out.top];
    return 1;
}
  1. 10, 20, 30을 넣으면 in의 아래에서 위로 10, 20, 30이에요.
  2. 첫 삭제 때 #2가 비었으므로 30, 20, 10 순서로 옮겨 out의 위가 10이 돼요. 10을 꺼내요.
  3. 40을 새로 넣어도 out에 20, 30이 남아 있으므로 이동하지 않아요. 이어서 20, 30을 꺼내요.
  4. 그다음 #2가 비면 #1의 40을 옮겨 꺼내요. 전체 출력은 10, 20, 30, 40이에요.

완성 답과 검산

두 스택으로 FIFO 큐를 구현할 수 있어요. 독립 시뮬레이션에서 enqueue(10), enqueue(20), enqueue(30), dequeue(), enqueue(40), dequeue(), dequeue(), dequeue()의 출력이 10, 20, 30, 40이었어요. 빈 큐 삭제는 0을 반환하고 출력 포인터의 기존 값을 유지해요. 총 256개 저장 후 추가 삽입은 0을 반환해요. q와 value는 유효한 포인터여야 해요.

여기서 헷갈리기 쉬워요

#2에 값이 남았는데 #1을 옮기면 나중에 들어온 40이 먼저 나올 수 있어요. #1만 보고 용량을 검사하면 두 스택의 합이 배열 용량을 넘어갈 수 있어요.

  2. 10, 20, 30을 넣고 한 번 꺼낸 뒤 40을 넣으세요.
  3. #2가 남은 동안 다음 값이 무엇인지 쓰세요.

첫 줄

입력은 #1, 출력은 #2가 빌 때만 옮긴 뒤 pop.

떠올릴 개념·공식

스택을 두 번 뒤집으면 FIFO. 분할상환 $O(1)$, 이동하는 한 번은 최악 $O(n)$.

답과 검산

교차 삽입·삭제의 출력은 10, 20, 30, 40이에요.

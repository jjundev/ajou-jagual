front는 첫 원소 직전, rear는 마지막 원소이며 한 칸을 비우는 강의 규약이에요.

문제를 읽어 볼게요

빙글 돌아가는 줄에서 앞 표시와 뒤 표시만 보고, 실제로 몇 칸이 차 있는지 세는 함수를 만들어요.

이 문제를 봤을 때 떠올릴 개념과 공식

‘원형 큐’, ‘요소의 개수’, ‘get_count’라는 단서에서 두 인덱스 사이의 순환 거리를 떠올려요. 수업의 원형 큐에서 front는 첫 요소 하나 앞, rear는 마지막 요소의 칸이에요. 크기 $M$인 배열에서 다음 칸은 $(i+1)\bmod M$이고 한 칸을 비워 실제 개수는 $0$부터 $M-1$까지예요. 그래서 순환 거리 (rear - front + MAX_QUEUE_SIZE) % MAX_QUEUE_SIZE가 개수예요. $M$은 MAX_QUEUE_SIZE, 나머지 연산은 끝에서 0으로 돌아간 위치를 정규화해요.

첫 줄을 이렇게 써요

종이에 front 다음 칸부터 rear까지 시계 방향으로 세어 보고, “개수 = 순환 거리”라고 적어요.

왜 이렇게 푸는지 함께 따라가요

front가 3이고 rear가 5라면 방문 칸은 4, 5이므로 두 개예요. 7에서 1로 감겨도 방문 칸은 0, 1이므로 두 개예요. 단순 차이는 음수가 될 수 있어 $M$을 더한 뒤 나머지를 취해요. 공백이면 두 인덱스가 같아 0이에요.

#define MAX_QUEUE_SIZE 8
typedef struct {
    int front;
    int rear;
} QueueType;

int get_count(const QueueType *q) {
    return (q->rear - q->front + MAX_QUEUE_SIZE) % MAX_QUEUE_SIZE;
}

이 함수는 유효한 인덱스와 한 칸 비우는 원형 큐 규칙을 전제해요. 인덱스 두 개를 읽고 일정 횟수로 계산해 $O(1)$이에요.

완성 답과 검산

정답은 (rear - front + MAX_QUEUE_SIZE) % MAX_QUEUE_SIZE예요. $M=8$에서 $(5-3+8)\bmod8=2$, $(1-7+8)\bmod8=2$예요. 별도의 시계 방향 순회 계산으로 유효한 front·rear 조합 64개를 모두 대조했고 값이 일치했어요. 포화 상태도 한 칸 비워 7로 나와요.

여기서 헷갈리기 쉬워요

front 칸 자체를 세면 하나가 많아져요. rear - front만 쓰면 인덱스가 7에서 0으로 돌아갈 때 음수가 돼요. 모든 칸을 채우는 다른 원형 큐 구현에는 별도의 포화 구분 정보가 필요하므로 이 식을 그대로 적용할 수 없어요.

설명을 닫고 다시 해 봐요

  1. front=7, rear=1에서 실제 점유 칸을 적으세요.
  2. 순환 거리 식에 대입하세요.
  3. 공백과 포화 경계에서 각각 0과 7이 되는지 확인하세요.

첫 줄

front 다음부터 rear까지 세어요.

떠올릴 개념·공식

원형 큐의 순환 거리: (rear - front + MAX_QUEUE_SIZE) % MAX_QUEUE_SIZE.

답과 검산

64개 인덱스 쌍을 직접 순회한 개수와 식이 모두 같아요.

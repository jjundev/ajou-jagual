문제를 내 말로 읽어요

A <-> B 두 노드가 있는 덱에서 delete_front를 두 번 호출할 때 포인터 변화를 추적하고, 삭제 후 남은 노드가 있는지 여부에 따라 갈리는 마지막 if/else의 역할을 확인하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “덱에서 마지막 원소를 삭제할 때”예요. 머리 노드를 지운 뒤 dq->head == NULL이면 빈 덱이므로 dq->tail = NULL로 맞추고, 노드가 남아 있으면 새 머리의 왼쪽 링크 dq->head->llink = NULL로 끊어 줘요.

종이에 적을 첫 줄

첫 호출에서 removed_node = A, item = A를 먼저 보관해요.

왜 이렇게 푸는지 함께 따라가요

(a) 첫 호출에서는 A를 꺼내고 dq->head를 B로 옮긴 뒤 else 분기로 B.llink = NULL로 만들어 head = tail = B(B.llink = B.rlink = NULL)가 돼요. 두 번째 호출에서는 B를 꺼내고 dq->head = NULL이 되어 if 분기로 dq->tail = NULL로 맞추므로 head = tail = NULL이 돼요.

(b) 마지막 if/else는 공백 덱의 head = tail = NULL 불변식과 비공백 덱의 head->llink = NULL 불변식을 각각 유지해요. 이를 생략하면 빈 덱의 tail이나 남은 첫 노드의 llink가 이미 해제된 노드를 가리키는 댕글링 포인터가 돼요.

완성 답과 검산

(a) 첫 호출에서는 else 분기가, 두 번째 호출에서는 if 분기가 각각 한 번씩 실행되어 두 경계 경우를 모두 거치게 돼요.

(b) 두 번째 호출에서 if (dq->head == NULL) 검사 없이 무조건 dq->head->llink = NULL을 실행하면 NULL 포인터 역참조 오류가 발생함도 확인할 수 있어요.

이 문제에서 조심할 점

dq->head == NULL인 경우 dq->head->llink = NULL을 실행하면 NULL 역참조가 발생하므로 반드시 두 경우를 나눠야 해요.

설명을 닫고 다시 해 봐요

  1. 첫 번째 delete_front 후 반환값과 head, tail, B.llink를 적어요.
  2. 두 번째 delete_front 후 반환값과 head, tail을 적어요.
  3. 마지막 if/else를 생략했을 때 남는 잘못된 포인터를 설명해요.

첫 줄

첫 호출에서 removed_node = A, item = A를 먼저 보관해요.

떠올릴 개념·공식

삭제 후 dq->head == NULL이면 dq->tail = NULL로, 아니면 dq->head->llink = NULL로 갱신해요.

검산

(a) 1회: 반환 A, head = tail = B, B.llink = NULL; 2회: 반환 B, head = tail = NULL (b) 양 끝 NULL 불변식 유지 및 해제 노드 참조 방지

조건·구분과 확인

  • 분기를 빼면 tail이나 새 머리의 llink가 해제 노드를 가리켜요. 공백에서 무조건 head->llink를 쓰면 NULL 역참조예요.

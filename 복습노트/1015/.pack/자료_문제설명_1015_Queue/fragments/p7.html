문제를 내 말로 읽어요

이중 연결 리스트 기반 덱의 빈 상태에서 add_rear를 두 번 호출할 때 양 끝 포인터(head, tail)와 노드 링크(llink, rlink)가 어떻게 연결되는지 추적하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “덱의 첫 삽입과 양 끝 포인터”예요. 빈 덱에서는 첫 노드가 head이자 tail이 되며, create_node(left, item, right)가 새 노드의 세 필드를 초기화해요.

종이에 적을 첫 줄

첫 삽입의 create_node(NULL, A, NULL) 호출부터 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) 빈 덱에 A를 넣으면 create_node(NULL, A, NULL)로 A.llink = A.rlink = NULL이 되고, is_empty(dq)가 참이어서 head = tail = A가 돼요. 이어서 B를 넣으면 create_node(A, B, NULL)로 B.llink = A, B.rlink = NULL이 되고, else 분기로 A.rlink = B를 연결한 뒤 tail = B가 되어 head = A, tail = B가 돼요.

(b) create_node 내부 대입문은 node->llink = left; node->data = item; node->rlink = right;예요. 공백 덱에서 첫 노드를 넣을 때 dq->head = new_node;를 설정하지 않으면 head가 계속 NULL로 남아 앞쪽에서 첫 노드를 참조할 수 없어요.

완성 답과 검산

(a) 두 번 삽입한 뒤 head(A)->rlink == B이고 tail(B)->llink == A이며 양 끝 외곽 링크(A.llink, B.rlink)는 모두 NULL이어서 이중 연결 불변식이 성립해요.

(b) 첫 삽입에서 head와 tail이 모두 A를 가리켜야 이후 delete_front나 두 번째 add_rear가 정상 동작함을 확인할 수 있어요.

이 문제에서 조심할 점

tail만 새 노드로 옮기면 이전 노드에서 새 노드로 가는 오른쪽 연결(rlink)이 생기지 않아요.

설명을 닫고 다시 해 봐요

  1. 첫 삽입 직후 head, tail, A.llink, A.rlink를 적어요.
  2. 두 번째 삽입 직후 head, tail과 A, B의 양쪽 링크를 모두 적어요.
  3. create_node의 세 필드 대입문과 빈 덱에서 head를 갱신하는 이유를 적어요.

첫 줄

첫 삽입의 create_node(NULL, A, NULL) 호출부터 적어요.

떠올릴 개념·공식

빈 덱에 첫 원소를 넣을 때는 head와 tail을 모두 새 노드로 설정하고, 비공백 덱에서는 기존 tail->rlink와 새 노드의 llink를 상호 연결해요.

검산

(a) 1회: head = tail = A; 2회: head = A, tail = B, A.rlink = B, B.llink = A (b) node->llink = left; node->data = item; node->rlink = right;, 빈 덱 첫 노드 접근 보장

조건·구분과 확인

  • 첫 A의 llink는 NULL, 새 B의 rlink도 NULL로 유지해 양 끝 바깥으로 연결되지 않게 해요.

문제를 내 말로 읽어요

은행 대기열 시뮬레이션 루프에서 if (service_time > 0) ... else ... 구조 때문에 한 틱에 시간 감소와 새 고객 서비스 시작 중 하나만 실행되는 흐름을 추적하는 문제예요.

이 문제를 봤을 때 떠올릴 개념과 공식

문제의 단서는 “시뮬레이션의 if/else가 만드는 한 틱”예요. if 조건이 참이어서 service_time--로 0이 되었더라도 그 if에 묶인 else는 같은 틱에 실행되지 않고 다음 틱에 실행돼요.

종이에 적을 첫 줄

clock = 1 진입 시점의 상태 service_time = 1을 먼저 적어요.

왜 이렇게 푸는지 함께 따라가요

(a) clock = 1에 고객 B가 도착해 큐에 들어가고, 진입 시 service_time = 1 > 0이므로 service_time이 1 -> 0으로 줄며 else는 건너뛰어요. clock = 2에는 처음부터 service_time == 0이므로 else가 실행되어 고객 B를 꺼내 service_time = 0 -> 2가 되고 대기 시간은 2 - 1 = 1이 돼요. clock = 3에는 service_time이 2 -> 1로 줄어요.

(b) 만약 else 대신 별도의 if (service_time == 0)를 쓰면, clock = 1에서 service_time이 1 -> 0이 된 직후 같은 틱에 두 번째 if 조건도 참이 되어 고객 B가 clock = 1에 즉시 시작하고 대기 시간이 0이 돼요.

완성 답과 검산

(a) if/else는 상호 배타적이므로 clock = 1에서는 감소만, clock = 2에서는 꺼내기만, clock = 3에서는 감소만 일어나요.

(b) 두 개의 독립된 if로 분리하면 한 틱 안에서 상태 변경 후 재평가가 일어나 이벤트 시각이 1틱 앞당겨짐을 확인할 수 있어요.

이 문제에서 조심할 점

말로 된 설명과 실제 if/else 순서를 구별하세요. 서비스가 0이 된 직후 같은 틱에 즉시 다음 고객을 꺼내는 코드가 아니에요.

설명을 닫고 다시 해 봐요

  1. clock = 1, 2, 3마다 분기 진입 전 service_time과 실행 후 service_time을 적어요.
  2. 고객 B의 도착 시각과 서비스 시작 시각으로 대기 시간을 계산해요.
  3. else를 별도 if (service_time == 0)로 바꿨을 때 clock = 1의 실행 흐름을 비교해요.

첫 줄

clock = 1 진입 시점의 상태 service_time = 1을 먼저 적어요.

떠올릴 개념·공식

if/else는 한 틱에 한 분기만 실행하므로 1 -> 0 감소와 새 고객 시작은 서로 다른 틱에 일어나요.

검산

(a) clock = 1: 1 -> 0, clock = 2: 0 -> 2(B 시작, 대기 1), clock = 3: 2 -> 1 (b) 별도 if 사용 시 clock = 1에 즉시 시작해 대기 0

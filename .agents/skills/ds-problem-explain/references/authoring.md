# 문제풀이 입문 설명 저작

이론을 읽었지만 문제풀이 경험이 부족한 학생에게 실제 첫 줄부터 완성 답과 검산까지 설명해요. 기존 카드의 풀이를 길게 바꾸는 것으로 끝내지 말고, 왜 그 첫 줄과 계산 방법을 선택하는지 밝혀요. 원 기출·문제은행·강의록·기존 정리노트의 관련 페이지를 먼저 확인해요. STT는 필요한 경우 보조로 사용하고 수업 밖 보충은 표시해요.

각 `explanations/pN.html`은 다음 직계 구역을 각각 하나 포함해요. 본문 답은 모두 펼쳐요.

| data-explanation | 작성할 내용 |
|---|---|
| understand | 핵심 요구사항과 주어진 조건을 1~2문장 + 단서 글머리(또는 2열 표)로 압축해요. 문제 전문 복사나 불필요한 서론은 금지해요. `layer eli5` |
| recall | 정의·공식 제시에 그치지 않고 이 문제에서 왜 쓰이는지, 어떤 단서가 어디에 대입되는지 1줄 연결을 필수로 적어요. `layer formal` |
| start | “먼저 ~를 살펴보아요” 같은 메타 선언 없이 구체적 첫 대입·초기 상태·첫 그림을 첫 문장부터 바로 제시해요. |
| solve | 번호 매긴 상태 변화/추론 단계로 쓰고, 상태 추적·트리/힙 연산·다중 조건 비교는 `<table class="cmp">` 등 표/상태 비교를 우선해요. 단순 1~2줄 선지 판별·단답형은 간결한 글머리 리스트를 허용해요. `layer formal` |
| verify | 결론 숫자/답 재진술만 하지 말고 단위·경계값($n=0,1$, 빈 트리/배열)·역연산·선지 소거 교차검산을 구체적 값으로 확인해요. |
| pitfall | 단순 “조심하세요”를 금지하고 오해하는 이유 → 실제 반례/틀린 결과 구조로 1~2항목 적어요. `layer warn` |
| retry | 개념명 나열이나 본문 지시 반복을 금지하고 “문제에서 X를 보면 → Y부터 적는다” 식의 행동형 체크리스트(또는 자가 점검 질문) 1~3개를 적어요. |

표 순서대로 일곱 구역을 작성해요. 각 구역은 왼쪽 문제 패널의 원문을 전제로 학생 관점에서 압축·시각화해요.

- **understand**: 구할 것과 핵심 제약·단서만 1~2문장 + 단서 글머리(또는 2열 표)로 압축해요. 문제 전문을 풀어서 다시 번역하거나 불필요한 서론을 붙이지 않아요. 원문 오기·주석·단위 조건이 있으면 여기에서 1줄로 짚어요.
- **recall**: 제목은 **이 문제를 봤을 때 떠올릴 개념과 공식**이에요. 개념 이름·정의·공식만 나열하지 말고, `[문제 단서] → [꺼낼 도구·공식] → [이유와 조건]` 표나 1줄 연결로 **이 문제에서 왜 쓰이는지, 어떤 단서가 어디에 대입되는지**를 반드시 연결해요. 영어 전문용어, 각 기호의 뜻, 적용 조건을 입문형으로 밝히되 `start`와 긴 설명을 복제하지 않아요.
- **start**: “먼저 ~를 살펴보아요”, “이제 ~해 봅시다” 같은 메타 선언을 금지해요. 주어진 값·기호·초기 상태로 종이에 적을 **구체적 첫 대입·초기 상태·첫 그림**을 첫 문장(또는 `<pre><code>` 첫 줄)부터 바로 제시해요.
- **solve**: 번호 매긴 상태 변화 또는 추론 단계로 작성해요. 연산 추적·트리/힙 변화·다중 조건 비교는 `<div class="table-wrap"><table class="cmp">` 등 표와 상태 비교를 우선 사용하고(다음 단계에 뽑힐 후보를 `<b>` 등으로 강조), 단순 1~2줄짜리 선지 판별·단답형은 과잉 표 대신 간결한 글머리 리스트를 허용해요. 객관식은 정답 근거뿐 아니라 오답 선지 소거 이유를 빠짐없이 명시해요.
- **verify**: 결론 숫자나 완성 답을 다시 적고 끝내지 않아요. 단위 일치, 경계값($n=0,1$, 빈 트리/배열), 역연산(내부 노드 합 = 총 비트, 삽입-삭제 원소 수 보존 등), 선지 소거 교차검산을 **구체적 값으로 확인**해요. 내부 검산 스크립트 파일명(`evidence/*.py`)이나 제작자 QA 로그는 학생용 본문에 노출하지 않고 `.pack/`과 `review.json`에만 남겨요.
- **pitfall**: “실수하기 쉬워요”, “조심하세요” 같은 일반 경고를 금지해요. **오해하는 이유(잘못된 습관·코드 패턴) → 실제 반례/틀린 결과(망가지는 수치·인덱스)** 구조로 1~2항목을 적어요.
- **retry**: 개념명 나열이나 본문 지시사항 복제를 금지해요. 해설을 가리고 바로 손이 움직이도록 **“문제에서 X를 보면 → Y부터 적는다”** 식의 행동형 체크리스트 또는 조건 변화를 묻는 자가 점검 질문 1~3개를 적어요.

```html
<div class="layer formal" data-explanation="recall">
  <h4>이 문제를 봤을 때 떠올릴 개념과 공식</h4>
  <div class="table-wrap">
    <table class="cmp">
      <thead><tr><th>문제 단서</th><th>꺼낼 도구·공식</th><th>이 문제에 쓰는 이유</th></tr></thead>
      <tbody>
        <tr><td>‘push 후 pop’</td><td>스택(stack)의 후입선출(LIFO)</td><td>나중에 넣은 원소가 <code>top</code>에서 먼저 나와 연산 순서를 결정해요.</td></tr>
        <tr><td>초기 <code>top = -1</code></td><td>선증가(<code>push</code>) / 선읽기(<code>pop</code>)</td><td><code>top</code>이 맨 위 원소의 인덱스를 가리키므로 공백·포화 검사를 먼저 확인해요.</td></tr>
      </tbody>
    </table>
  </div>
</div>
```

공통 개념은 한 번 설명하고, 서로 다른 개념을 요구하는 소문항은 (a), (b)처럼 구분해요. 개념 수를 고정하지 않아요. 공식이 필요 없는 정성·증명 문항에서는 정의·판단 기준과 논증 조건이 문제의 어떤 단서와 맞물리는지 1줄로 연결해요. 우측 `sum`(`<div class="sum" hidden>`)에는 `summary-group`을 두고 핵심 개념·공식·첫 줄·판단·검산을 **1~2줄 요약**으로 유지해요. 본문 전체를 요약에 복제하지 않아요.

`source.json`의 subparts가 a,b이면 **solve와 verify 모두** 각각 아래 표지를 한 번씩 사용해요. 단일 문항도 `main` 표지가 필요해요.

```html
<div class="layer formal" data-explanation="solve">
  <h4>왜 이렇게 푸는지 함께 따라가요</h4>
  <div data-subpart="a"><p>(a) 실제 식, 변형 이유, 완성 답을 써요.</p></div>
  <div data-subpart="b"><p>(b) 실제 식, 변형 이유, 완성 답을 써요.</p></div>
</div>
<div class="layer formal" data-explanation="verify">
  <h4>완성 답과 검산</h4>
  <div data-subpart="a"><p>(a) 계산을 별도로 확인한 결과를 써요.</p></div>
  <div data-subpart="b"><p>(b) 조건에 대입한 결과를 써요.</p></div>
</div>
```

재귀는 종료 조건과 호출·반환 순서, 반복문은 변수 변화와 실행 횟수, 포인터는 변수·주소·객체를 구분해요. 자료구조 추적은 연산별 상태 표와 불변식을 보여 주고, 5단계 이상이면 `RUN/<대상>/traces/<id>.json` 을 만들어 `.agents/skills/ds-review-pack/scripts/trace_figs.py render --target explain` 그림을 붙여요. `~해요` 체와 영어 전문용어 병기를 사용해요. 기존 원문·조건·질문·그림은 조립기가 붙이므로 재작성하지 않아요. `lecture-` 카드(`lecture-code` 등)는 조건·코드 블록을 `[data-source-field="conditions"]`에, `(a)`/`(b)` 소문항 질문 목록을 `<h4>구할 것</h4><div data-source-field="ask">`에 분리해 렌더링하므로 `understand`는 문제 전문을 반복하지 않고 1~2문장으로 간결하게 요약해요. 기출 원문은 조립기가 문제 안에 '기출 원문 보기'로 접어 보존해요.

마지막에 직계 `<div class="sum" hidden>` 하나를 넣어 시작·핵심 판단·검산을 요약해요. 이 요약만 UI의 우측으로 이동해요. 본문 hidden/details, 인라인 style, 실행 코드와 on* 속성은 사용할 수 없어요. 수식은 `$...$`/`$$...$$`, 그림은 저장소 내부 파일 상대경로나 정적인 inline SVG를 사용해요. 소문항 표지를 임의로 합치지 않아요.

개념 링크는 실제 존재하는 정리노트의 문항/토픽 anchor만 연결해요. 조각의 상대 링크와 그림은 입력 카드 HTML의 디렉터리 기준이에요. 소문항별 증명과 정성 문항은 적용 조건과 논증을 확인하며, 몇 개 숫자 예제로 증명이 끝났다고 쓰지 않아요.

## 수식과 여백

짧은 수식은 문장 안에 두고 수식마다 스크롤 컨테이너를 만들지 않아요. 여러 행렬 답은 각각 독립된 줄에 배치해요. 긴 유도는 의미가 유지되는 등호·항을 기준으로 여러 식으로 나눠요. 한 수식의 여러 줄이 필요하면 `aligned`를 사용하고 수식 내용을 생략하지 않아요. 표 셀(`<td>`, `<th>`) 경계에서 인접한 `$...$`가 `$$`로 합쳐지면 `unbalanced $$` 오류가 나므로, 셀 내부 앞뒤에 공백이나 줄바꿈을 두거나(`<td> $x$ </td>`) `<code>` 표기를 사용해요. 원문은 다시 쓰지 않고 템플릿의 표시 규칙으로 배치해요.

요약은 `<div class="summary-group"><h4>첫 줄</h4><p>...</p></div>`처럼 의미별로 묶어요. 제목과 내용 사이는 12px, 요약 그룹과 설명 구역 사이는 24px, 소문항 사이는 16px인 템플릿 규칙을 사용해요. 간격을 만들려고 빈 문단이나 연속 br을 넣지 않아요. 화면을 바꾸거나 요약 너비를 조절한 뒤에도 수식이 읽혀야 해요.

## C 코드와 원자료 충돌

원문 오타·참고 답 오류를 몰래 수정하지 않아요. 원 기출·은행·강의록·STT·정리노트가 충돌하면 disputed로 남기고 조건과 다른 해석을 밝혀요. 실제 자료를 필요한 범위에서 읽고 자료/페이지를 기록해요. C 실행 전 입력 가정과 정의된 동작을 확인해요. 미정의 동작(UB), 비종료, 구현 의존 결과를 정상 정답으로 승인하지 않아요. 정의된 코드의 독립 실행 또는 손 추적과 별도 시뮬레이션을 비교해요. 증명은 불변식·귀납 가정과 경계 조건을 확인하며 몇 개 실행 예제를 증명으로 취급하지 않아요. pre/code의 $, <, &는 코드 문자로 보존해요.

## 독립 코드와 실행결과

독립된 코드 조각과 실행결과는 한 줄이어도 `<pre><code>...</code></pre>`로 묶는다. 설명 문장은 블록 밖의 문단에 두고, 문장 속 `head`, `p->link` 같은 짧은 표기는 인라인 `<code>`로 유지한다. pre에는 직계 code 하나와 공백만 허용하며 빈 블록을 만들지 않는다. 코드의 문자·공백·들여쓰기·줄바꿈·연산 순서를 보존하고 `<`, `&`는 HTML escape한다. `$`는 수식으로 해석하지 않는다. 공통 템플릿의 테마 배경·테두리·여백을 사용하고 긴 줄은 블록 안에서만 스크롤한다. 일반 문장에서 코드를 자동 추측해 변환하지 않는다.


## 용어·보기·문항 결함의 일관성

recall은 원천에서 확인한 이름과 개념을 짧게 대응하고, pitfall은 인접 오답과의 결정적 차이를 설명한다. 비교 대상·단위·조건·결과를 분명히 한다. 자료에 없는 동의어·번역·가정을 원문에 끼워 넣지 않는다. 긴 설명을 start·solve·pitfall에 복제하지 않는다.

객관식은 understand에서 긍정/부정 질문 방향과 단일/복수 선택 조건을 밝힌다. solve에서는 정답 근거뿐 아니라 오답 보기마다 소거 이유를 판정하고, 진술의 참·거짓과 질문에 대한 선택 적합성을 구별한다. ‘항상’ 같은 절대 표현만으로 오답으로 정하지 않는다. ㄱㄴㄷ형은 개별 진술을 판정한 뒤 조합을 고른다. 선택지 목록을 소문항으로 바꾸지 않는다.

표현 결함·필요 가정·출제 의도상 답과 엄밀한 답의 차이는 understand·solve에 밝히고, verify의 소거·검산과 pitfall·sum에도 같은 조건과 유보를 유지한다. 공식 답 미확인이면 그 사실을 밝힌다. 공식 답 부재만으로 독립 검산 성공/실패를 추정하지 않는다. 정상 문항에는 불필요한 모호성 문구를 붙이지 않는다. 이 원칙은 과목별 기존 disputed 정책을 완화하지 않는다. DS의 UB·비종료·은행 충돌, ML의 미해결 수학적 모호함, EC2의 workbook 풀이와 독립 검산 불일치는 계속 발행을 보류한다. 원자료를 몰래 수정하지 않는다.

해설·답을 본 뒤의 성공을 독립 회상이나 학생 숙달 확인으로 보고하지 않는다. retry는 해설을 닫고 개념·첫 줄을 다시 떠올리게 한다. 객관식 정답 모델은 입력의 검증된 데이터만 사용하며 해설에서 새로 추정하지 않는다.

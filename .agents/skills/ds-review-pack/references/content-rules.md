# 섹션 작성 규칙

## 작성자 브리프 (메인 에이전트가 섹션마다 1명, 병렬, 모델은 SKILL.md "에이전트 모델")

---
자료구조및알고리즘이해 정리노트의 섹션 `<sid>`(`<섹션 title>`)를 쓴다.

- 읽기: `<SKILL>/references/content-rules.md`(이 파일 전체), 위젯이 있으면 `<SKILL>/references/widget-rules.md`
- 위젯: <위젯> (메인 에이전트가 정한 것만 만든다. "위젯 없음"이면 이 섹션에는 위젯을 넣지 않는다)
- 계약: `<RUN>/manifest.json`의 섹션 `<sid>` — 토픽 id·제목·`required_terms`·`layers`·`supp`가 정확히 여기 적힌 대로여야 한다.
- 링크: manifest `links` 중 `topic`이 이 섹션에 있는 항목 `<이 섹션의 links 목록>`을 모두 그 토픽 안에 `<a href="…">`로 넣는다. `href`는 글자 그대로 복사(`%20` 포함). PDF 자료는 이름과 쪽 번호를 텍스트로 적는다. 작업용 복습문제 HTML은 연결하지 않는다.
- 근거: `<RUN>/summaries/stt-*.md`(해당 날짜), `<RUN>/slides.txt`(강의록 텍스트, 쪽 표시 `=== S<N> p<k> ===`). 슬라이드 그림·코드가 텍스트로 깨졌으면 `<RUN>/repo/자료구조_강의록_2026/`의 해당 PDF 쪽을 직접 본다.
- 출력: `<RUN>/sections/<sid>.html` **한 파일만**. `<section>`/`<h2>`는 쓰지 않는다(조립기가 감싼다). 임시 파일은 아래 규칙.
- 임시·보조 파일(스크립트, 초안, 그림 생성 폴더)은 `<RUN>/work/` 아래에만 둔다. 저장소(`STT/`, `자료구조_강의록_2026/`, `from_the_past/`, `복습노트/`)와 scratchpad 루트, `/tmp`에는 아무것도 쓰지 않는다. 한글(NFD) 파일명은 복사하거나 이름을 바꾸지 말고 Python `os.listdir` + `unicodedata.normalize('NFC', …)`로 찾아 그 경로로 연다.
- 신규 레이아웃 자기 검사에는 `"$LAYOUT_PYTHON" "$SKILL/scripts/preview_layout.py" author --run "$RUN" --section "$SID"`를 쓴다. 375×812와 1280×900의 라이트 화면에서 본문·요약·위젯을 확인한다. 주요 SVG 라벨은 렌더링 높이 12 CSS px 이상으로 설계한다. 9px 미만이면 그림을 다시 배치하고, 9px 이상 12px 미만이면 실제 읽히는지 확인한다. 인라인 수식이 바깥으로 넘치면 여러 수식으로 나누거나 디스플레이 수식으로 옮긴다. 로컬 그림은 팩 상대 경로로 참조하고 `RUN` 아래의 같은 `.pack/...` 경로에 준비한다. 보고에는 판정, 출력된 `RUN/work/preview/.../layout.json`, 남은 영역별 결함을 적는다. `unavailable`일 때는 확인할 토픽과 사유를 메인에 넘긴다.
- 자기 검사(끝내기 전): 토픽별로 `required_terms`가 모두 문자 그대로 들어갔는지(코드 조각은 `&lt;`가 `<`로 풀린 글자 기준), `$` 짝, `links` 항목이 해당 토픽 안에 있는지, 금지어 `<forbidden 목록>`이 없는지. 금지어는 예고 토픽 `<preview_topic>` 안에서만 허용된다 — 이 토픽에는 예고 제목을 빠뜨리지 말고 쓴다. eli5 레이어마다 문장 수(figcaption 포함)가 3 이하이고 전문용어·기호(식, 코드, 영어 용어)가 없는지 — 있으면 formal 레이어로 옮긴다. 조각 어디에도 이모지를 쓰지 않았는지. 코드 블록 안에 `$`가 없는지. `layers`가 빈 목록이 아닌 토픽마다 마지막에 `<div class="sum" hidden>`이 있고, 그 식·용어가 본문과 같은 표기인지. layout-v2 이면: 토픽마다 `dl.gist` 첫 줄 결론이 `sum-lead`와 글자 그대로 같은지, `required_terms`가 `details`·`.sum` 밖에도 있는지, 두 문장 이상인 formal `<p>`가 `<b>`로 시작하는지. 그림 설명(글, `aria-label`)이 SVG 클래스의 실제 모양(채움/윤곽)과 맞는지.
- 계산 설명 자기 검사: 아래 [계산 결과 설명](#계산-결과-설명)에 해당하는 표나 식에서 대표 결과를 가리고, 정리노트에 보이는 입력과 규칙으로 직접 다시 구한다. 막힌 곳에는 빠진 입력의 뜻이나 계산 단계를 보완하고 다시 확인한다.
- 보고: 파일 경로, 토픽별 한 줄, 요약에 있었지만 넣지 않은 것과 이유.
---

## 범위
- 요약의 슬라이드 대조표에서 "다룸/일부"인 내용만 쓴다. "예고만/안 다룸"은 `s<N>-next`에 제목만.
- 수업에서 말한 모든 개념, 코드 설명, 동작 추적(칠판에 그린 스택·큐·트리 상태 변화 포함), 교수님 비유와 강조 발언을 빠짐없이 싣는다(잡담 제외).
- STT 오인식과 말실수는 올바른 형태로 쓴다. 코드나 추적 결과가 틀렸던 경우만 각주 한 줄로 "(수업 중 X로 적었다가 정정)".

## 토픽 마크업 (이 순서)
manifest `rules` 에 `layout-v2` 가 있으면(신규 팩) 아래 형태로 쓴다. 없으면(옛 팩 수정) 결론 상자·`details` 없이 예전처럼 모든 레이어를 `<div>` 로 쓴다.
```html
<article class="topic" id="…"><h3>…</h3><div class="tags"><span class="tag date">MMDD 수업</span><span class="tag slide">S2 p7</span></div>
  <dl class="gist"><dt>결론</dt><dd>…</dd><dt>왜</dt><dd>…</dd><dt>언제</dt><dd>…</dd></dl>   ← 결론 상자(아래), layers가 빈 목록이 아닌 토픽만
  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">한 문장 비유</p> …그림… </div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span>
    <p><b>주장 한 문장.</b> 근거 문장…</p> …정의·C 코드(pre)·동작 추적·시간복잡도…
    <details class="more"><summary>더 보기 · 무엇</summary> …곁가지… </details>                  ← 곁가지가 있을 때만, formal 맨 끝
  </div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span> …비유·일화, 원문은 blockquote… </div>
  <div class="layer warn"><span class="layer-title">꼭 기억해요</span> …원문 인용… </div>   ← 강조 발언이 있을 때만
  <details class="layer supp"><summary><span class="badge supp">보충 · 수업에서 유도하진 않았어요</span> · 요지</summary> … </details>   ← manifest supp=true만
  <div class="sum" hidden>…페이지 요약(아래)…</div>                                                    ← layers가 빈 목록이 아닌 토픽만, 맨 끝
</article>
```

### 결론 상자 (`dl.gist`, layout-v2)
학생이 토픽을 열자마자 핵심을 잡게 한다. 오른쪽 요약 패널이 닫혀 있는 좁은 화면에서는 이 상자가 유일한 결론이다.
- 2~3줄. 첫 줄은 반드시 `<dt>결론</dt>`, 그 `<dd>`는 같은 토픽 `sum-lead`와 **글자 그대로** 같다(`gist-sum-mismatch`).
- 둘째 줄은 `<dt>왜</dt>`: 결론이 성립하는 이유 한 문장.
- 셋째 줄은 선택. `언제`(쓰임새), `시간`(복잡도 식), `조건`(성립 조건), `주의`(혼동 구분) 중 이 토픽에 가장 중요한 하나.
- dd 하나에 한 문장. 식은 인라인 `$…$`만. 새 내용을 쓰지 않는다 — formal 레이어에 이미 있는 주장을 줄인다.

### 펼쳐 두는 것과 접는 것 (layout-v2)
- 펼쳐 둔다: 정의, 절차, 수업 코드, 동작 추적, 시간복잡도, 성립 조건, 혼동 구분, 교수님 말씀, 꼭 기억해요.
- formal 끝 `details.more`로 접는다: 다른 과목·하드웨어와의 연결(예: 로드·스토어), 슬라이드 코드의 오류·컴파일 메모, 추적이나 코드와 같은 내용을 한 줄씩 다시 푼 설명, 수업 중 정정 각주. summary는 `더 보기 · <무엇인지 몇 단어>`.
- 보충(supp) 레이어는 통째로 `details.layer.supp`로 접는다. summary 에 배지와 ` · 요지`를 둔다.
- `required_terms`는 접힌 곳과 페이지 요약 **밖** 본문에 한 번 이상 있어야 한다(`term-only-folded`).
- 접기 때문에 지우는 내용은 없다. 위 "범위"의 빠짐없이 싣기는 그대로다.
- 슬라이드 태그는 `S<강의록 번호> p<쪽>`(예: `S2 p7`, 여러 쪽이면 `S2 p7–9`). 다음 팩이 이 태그로 이전 범위를 찾는다.
- 독자용 HTML에는 인용 내용만 싣고 녹음 위치 표시는 넣지 않는다. `(0907 01:11)`, `(1012 Part 02–03)`, `(1105 Part 05 · 시각 미제공)`, `시간 정보 없음`과 Part 표기 안내 문장은 모두 금지한다. 토픽 머리의 수업 날짜 태그(`<span class="tag date">`)·강의록 페이지·푸터의 일반 출처는 유지한다. 인용 끝 `(MMDD)`도 금지다. 시각·Part 근거는 내부 STT 요약에만 보관한다. 자기 검사에 이 항목을 포함하며 `check_html.py`의 `recording-locator`가 있으면 수정한다.
- 레이어 제목과 배지 글자는 위와 글자 그대로 쓴다. 이모지, 장식 기호(★, ↗, → 같은 화살표 아이콘), "아래를 보세요" 같은 안내 문장은 쓰지 않는다.
- 템플릿이 토픽 하나를 한 화면에 보여 준다. 토픽은 그것만 읽어도 이해되게 쓰고, "위에서 본 것처럼"처럼 앞 토픽의 위치에 기대는 말 대신 `<a href="#토픽id">토픽 제목</a>`으로 잇는다.
- 요약·예고 섹션: 치트시트는 표(`<div class="table-wrap"><table>`), 예고는 `<ul>`, 관련 자료는 `<ul><li>`로 쓰고 manifest에 등록된 링크는 `<a>`로 연결한다.

## 페이지 요약 (`.sum`)
화면 오른쪽 "페이지 요약" 패널에 그 토픽의 핵심만 보여 준다. 템플릿이 토픽의 **직계 자식** `.sum`을 패널로 옮기므로 토픽 안 맨 끝에, 레이어 밖에 둔다. `hidden`은 꼭 붙인다(본문에 두 번 보이지 않게).
```html
<div class="sum" hidden>
  <p class="sum-lead">토픽 핵심 한 문장("~해요" 체)</p>
  <p class="panel-label">핵심 식</p>
  <ul class="eq-list"><li><span class="eq-name">식 이름</span>$$…$$</li></ul>
  <p class="panel-label">용어</p>
  <dl class="terms"><dt>용어(영어)</dt><dd>한 줄 뜻</dd></dl>
</div>
```
- 새 내용을 쓰지 않는다. 본문(formal 레이어)에 이미 나온 식·용어를 **같은 표기로** 필요한 만큼 고른다. 요약에만 있는 식이나 설명은 두지 않는다.
- 핵심 식에는 점화식·시간복잡도처럼 식으로 쓸 수 있는 것만 둔다. 코드 블록은 요약에 넣지 않는다.
- 식이 없는 토픽은 "핵심 식" 줄과 `eq-list`를 빼고, 용어가 없으면 "용어" 줄과 `dl`을 뺀다. `sum-lead`는 항상 쓴다.
- 요약·예고 섹션처럼 `layers`가 `[]`인 토픽에는 두지 않는다.

## 문체
- 쉽게 말하면(eli5): 초등학생이 이해할 1~3문장(figcaption 포함) + 그림. 전문용어·기호·코드 없이(필요하면 정확히 말하면에 쓴다). 토스처럼 짧고 다정한 "~해요" 체.
- 정확히 말하면(formal): 빠짐없이, 정확하게. layout-v2 에서는 두 문장 이상인 `<p>`를 `<b>주장 한 문장.</b>`으로 시작한다. 굵은 줄만 이어 읽어도 토픽 줄거리가 되게 쓴다. 추적은 한 줄에 한 단계. 문장은 "~해요" 체, 추적 단계는 상태 위주로 짧게(예: `push(3) → [1, 3]`).
- 5단계 이상 상태 추적은 [trace 생성기](trace-figures.md)로 만든다. 손으로 쓴 `ol.steps` 는 4단계까지만 쓴다. 생성 조각은 손으로 고치지 않는다.
- 교수님 말씀(prof)/꼭 기억해요(warn): 원문 인용은 15단어 안팎으로 줄이고 인용 끝에 출처·날짜 꼬리표(`(0914 26:00)`, `(1112)`, `(1112 수업)` 등)를 붙이지 않는다. 수업 날짜는 토픽 머리의 `<span class="tag date">`가 맡는다. `check_html.py`의 `quote-date`가 잡는다.
- UI 글은 한국어, 전문용어는 영어 병기(예: 재귀(recursion)). 한 문장에 한 가지만 말하고, 군더더기 수식어("아주", "정말", "한번")는 뺀다.

## 계산 결과 설명

- 새 개념이나 연산을 가르치는 표·식에서 계산 결과를 처음 보여줄 때, 그 옆의 본문이나 표 안에 대표 한 건의 **입력값과 그 뜻 → 적용하는 규칙 → 값을 넣은 계산과 결과**를 보여준다. 예를 들어 `e`의 코드 `00`은 두 자리라 2비트이고, 원문에 15번 나오므로 `2 × 15 = 30비트`가 든다.
- 같은 규칙이 반복되면 대표 한 건으로 설명한다. 표에 나온 결과 중 적용 규칙이나 조건이 달라지면 달라지는 경우별로 대표 한 건을 보여준다. 강의에서 주어진 입력값은 무엇을 뜻하는지 밝힌다.
- 합계나 비교 자체가 학습 내용이면 무엇을 더하거나 비교했는지 밝힌다. 예를 들어 허프만 코드에서는 각 글자의 등장분이 차지하는 비트 수를 더해 원문 전체의 비트 수를 구한다. 계산 근거는 수업에서 주어진 입력과 규칙에 맞춘다.

## 수식
- `$…$`(인라인), `$$…$$`(디스플레이)만. 본문에 리터럴 `$` 금지.
- TeX 안에 `<`, `>`, `&` 금지 → `\lt`, `\gt`. 정렬 환경 대신 `$$` 줄을 나눈다.
- 시간복잡도는 `$O(n^2)$`, 점화식은 `$T(n) = T(n-1) + 1$`처럼 쓴다. manifest `required_terms`와 같은 표기.

## C 코드
- `<pre><code class="language-c">…</code></pre>`만 쓴다. 한 줄 조각은 `<code>`.
- 수업 코드는 슬라이드 그대로 옮기고(변수명·들여쓰기 포함), 설명용으로 줄일 때는 `/* … */`로 생략을 표시한다. 30줄을 넘기지 않는다.
- 들여쓰기는 공백 4칸. HTML이므로 `<`, `>`, `&`는 `&lt;`, `&gt;`, `&amp;`로 쓴다.
- 코드 안에 `$`를 쓰지 않는다(KaTeX와 검사기가 수식으로 오인한다).
- 코드 조각이 `required_terms`에 있으면 글자 그대로(공백 포함) 코드 블록이나 `<code>` 안에 둔다.

## SVG 그림
- 개념 토픽마다 eli5 레이어에 그림 1개 이상(노드와 화살표로 된 리스트, 칸으로 된 배열·스택·큐, 트리, 재귀 호출 상자 쌓기 등).
- 실제 예제(트리·배열·스택·리스트)의 상태는 formal 레이어에서 trace 생성기 그림으로 보여 준다. eli5 그림은 비유여도 된다.
- `<figure class="figure"><svg id="fig-<kebab>" viewBox="…" role="img" aria-label="한국어 설명">…</svg><figcaption>…</figcaption></figure>`
- 색은 클래스로만: `fig-ink`, `fig-accent`, `fig-danger`, `fig-dot`, `fig-text`, `fig-muted`. 하드코딩 색 금지(다크모드).
- 채움과 윤곽: `fig-ink`, `fig-accent`, `fig-danger`는 선만 그린다(`fill:none`). 속이 칠해진 점·도형은 `fig-dot`(강조색 채움)뿐이다(`fig-text`, `fig-muted`는 글자용). 글·figcaption·`aria-label`에서 "색칠된", "채워진"은 `fig-dot` 도형에만 쓰고, 선만 있는 도형은 "테두리", "선"으로 부른다.
- 화살표 머리는 `<path>`로 직접 그린다(`marker`는 MD 변환에서 색이 사라질 수 있다).
- 글자 12~14px, SVG `<text>`에 `$` 금지(₁, → 같은 유니코드).
- id는 페이지 전체에서 유일해야 한다(`fig-` + 토픽 고유 단어).

## 패널 제목과 요약 계약
중앙 제목과 고정 패널 제목을 유지하고 오른쪽의 중복 주제·문항 제목은 출력하지 않는다. `sum-for`는 `.sums` 컨테이너의 유일한 ID로 보존하며 `aid-for`와 제거한 제목의 JavaScript 참조는 두지 않는다.

요약 항목 수에 고정 상한을 두지 않는다. 같은 토픽 본문의 핵심 개념·원리·성립 조건·혼동 구분을 압축하고, 본문에 없는 사실을 추가하지 않는다. 보충의 범위·출처·불확실성을 유지한다. 모든 학습 토픽의 일반·강조·주의·보충 핵심을 본문 주장, 대응 요약, 판정 또는 생략 이유로 대조한다. 누락은 unresolved로 기록하고 보완된 실제 요약을 다시 읽은 뒤 pass로 바꾼다. 기존 동반 MD와 실제 생성 원고를 동기화하고 동반 MD가 없으면 새 형식을 만들지 않는다.

브라우저는 HTTP 임시 stage에서 1280×900, 375×812 각각 light/dark로 검사한다. 요약·풀이 패널을 열어 중앙 제목 표시, 우측 중복 제목 없음, 토픽별 요약 하나와 정확한 내용, 표지 안내, 이전 요약 숨김, 수식 오류와 페이지 오류 0을 확인한다. 문제·원문 탭, 이전/다음, 힌트·풀이, 푼 문제 토글과 기존 read/solved 저장 키를 유지한다. missing-sum 실패 탐지와 no-panel legacy 검사를 유지한다.

의미 감사표는 `자료·토픽`을 키로 서로 다른 일반·강조·주의·보충 핵심을 별도 행에 둔다. 검증 JSON은 `{schema_version:1, html, html_sha256, audit_path, audit_sha256, semantic_status, browser_status, evidence, unresolved}`를 기록한다. `pass | unresolved`는 실제 검사 뒤에만 판정하며 산출물 해시가 바뀌면 기존 근거는 갱신 전까지 오래된 것으로 취급한다.

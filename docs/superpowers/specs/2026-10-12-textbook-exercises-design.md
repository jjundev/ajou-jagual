# 교과서 연습문제 JSON 추출 설계

## 의도와 확정 범위

`교과서/origin`의 1~14장 연습문제를 원문 그대로 JSON으로 추출한다. 그림과 표는 구조를 분석한 뒤 직접 새 SVG 파일로 제작한다. 모든 문제와 자산에 원본 위치를 연결하고, 누락·판독 오류·시각 오류를 검증한다.

분류는 architectural이다. 생명과학의 검증 절차를 참고하되 교과서 혼합 문항에 맞는 별도 스키마를 사용한다. 사용자가 후속 writing-plans를 호출하면서 정답 범위를 변경하지 않았으므로 결정 #6은 grill-yourself의 기본 확정 규칙에 따라 `원문 추출만`으로 확정했다. 직접 풀거나 해설을 작성하지 않는다.

2026-10-12 읽기 전용 조사에서 PDF 14개, 총 44쪽, 모든 페이지의 텍스트 층이 비어 있음을 확인했다. 대표 5쪽을 시각 확인했으며 전체 문항 수는 아직 집계하지 않았다. 아래쪽 인쇄 쪽번호가 잘린 경우가 있어 기존 분할 manifest의 책 쪽번호는 직접 확인을 대체하지 않는다.

## 완료 후의 동작

- `교과서/[NN]_*_연습문제.json`에서 장·문항 번호로 문제를 찾는다.
- 글·코드·그림·표·소문항·보기의 원래 순서를 유지한다.
- `교과서/assets/`의 새 SVG는 원본 스캔 크롭이나 이미지 삽입을 사용하지 않는다.
- 표는 행·열·셀 데이터와 새 SVG를 함께 제공한다.
- `교과서/제작자료/preview.html`에서 전체 문제와 자산을 확인한다.
- 읽을 수 없는 내용과 원본 오류는 위치와 함께 기록한다. 불완전한 후보를 완성본으로 확정하지 않는다.

## 접근 방식

| 선택 | 방식 | 판단 |
|---|---|---|
| A | 생명과학 스키마 그대로 사용 | 단일 선택형·평가 정보 중심이므로 제외 |
| B | 교과서 스키마와 검증 도구를 만들고 생명과학 절차 참고 | 채택 |
| C | 기존 자구알 기출 스키마 확장 | 강의 장 번호·정답 의무 필드·기존 소비 코드에 영향이 있어 제외 |

참고 근거는 생명과학 `.agents/skills/web-quiz-extract/SKILL.md:16-32`, `scripts/question_bank/model.py:20-124`, `scripts/question_bank/svg.py:10-63`이다. 원문과 선택 관찰을 분리하고, 직접 만든 SVG를 대조하며, 검토 대상의 현재 해시를 검증한 후보만 확정하는 원칙을 사용한다. 생명과학 스키마의 응시일·배점·정답 분석 필드를 교과서에 강제로 채우지 않는다. 자구알 `.agents/skills/ds-review-pack/scripts/bank.py:88-97`의 강의 장 번호 1~12와 필수 답 필드는 이번 교과서 1~14장에 그대로 적용하지 않는다.

## 자료 계약

최상위는 `schema_version`, `sources`, `chapters`, `questions`, `assets`이다. 원본 파일명은 실제 Unicode 바이트 표기를 유지하고 NFC는 검색 비교에만 쓴다. source·asset 경로는 교과서 폴더 기준 상대 경로다. PDF 쪽번호는 1부터 시작하며 책 쪽번호는 직접 읽은 경우만 숫자로 저장하고, 확인할 수 없으면 null이다.

- 큰 문항 하나를 한 question으로 저장한다. `id`는 `ch05-q06`처럼 장과 문항 번호를 최소 두 자리로 표현하고 `number`는 원문 문자열을 보존한다.
- `content`는 순서 있는 text/code/figure/table/subquestions 블록이다. `options`도 원문 label과 순서 있는 content를 지원한다. 소문항과 수행 연산 목록을 임의로 같은 것으로 취급하지 않는다.
- 코드·수식·원문의 오타를 보존한다. 필요하면 원문과 분리된 `issues`에 오류를 설명한다.
- `answer`는 null이다. 인쇄된 공식 답이 실제로 있다면 내용을 독립 `printed_answer` 증거로 보존하되 직접 푼 답이나 손글씨 표시를 정답으로 승격하지 않는다.
- 그림 구조에는 노드·간선·방향·가중치·라벨, 트리의 좌우 자식, 배열 인덱스·값·빈칸·포인터를 기록한다. 표 구조에는 행·열·헤더·병합 셀·빈칸을 기록한다.
- 문제용 SVG와 대체 설명에는 원본에 없는 정답 힌트를 추가하지 않는다. 손글씨·동그라미는 `observations`에 분리하고 새 문제 그림에 옮기지 않는다.
- `source_refs`는 관련 PDF 페이지와 책 쪽번호를 연결한다. 페이지 경계 문항은 관련 페이지를 모두 연결한다.
- 검토 상태는 pending/verified/blocked이다. verified에는 실제 원본 대조 기록과 현재 payload SHA256이 필요하다. 해시는 검토의 대체 증거가 아니다.

## 산출물과 검증

최종 산출물은 장별 JSON 14개, 교과서/readme.md, SVG 자산, schema, inventory, asset-models, 검증 도구, preview, verification 기록이다. 임시 전체 페이지 렌더링·전사 초안·후보는 `tmp/textbook-exercises/<run-id>/`에 둔다. 전체 페이지 렌더링은 검토용이며 최종 문제 그림에 재사용하지 않는다.

원본 페이지별 인벤토리와 JSON의 문항·보기·소문항·자산을 대조한다. 모든 44쪽을 직접 읽고 코드와 그림·표를 확인한다. SVG 외부 이미지·스크립트·링크를 금지한다. 출처·자산·구조 데이터의 경로와 해시를 검증하고 원본 PDF가 바뀌면 재검토한다. 데스크톱과 375px에서 모든 자산의 잘림·겹침·가독성을 확인한다. 코드·넓은 표는 내부 스크롤을 허용하되 문서 전체의 가로 넘침은 허용하지 않는다.

후보 검증과 시각 대조가 모두 끝난 다음 최종 경로를 확정한다. 기존 산출물이 있으면 덮어쓰지 않는다. 게시 실패 시 이번 실행이 독점 생성한 파일만 제거하고 기존 자료는 유지한다. 장별 JSON 14개를 마지막에 생성하며, 미완료 상태에서는 후보와 미해결 기록만 남긴다.

## 범위 밖

복습문제 생성, 강의 범위에 따른 선별, 직접 정답·해설 작성, 원문 교정, 기존 기출 문제은행·복습 스킬 수정, 신규 추출 스킬 설치는 이번 작업에 포함하지 않는다. 현재 사용자는 계획 작성을 요청했다. 실제 추출·도구 구현·커밋·푸시는 아직 실행하지 않는다.

## 장별 배포 구조

각 장은 기존 Bank 스키마를 사용하되 chapters 배열에 해당 장 하나만 담는다. 출처·문제·자산도 해당 장으로 제한한다. bank.py는 14개 파일을 메모리에서 합쳐 전체 검증에 사용하며 통합 JSON을 저장하지 않는다. validate.py·preview.py·assets.py의 bank 인자는 교과서 폴더다.

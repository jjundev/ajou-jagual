# 과제1 Notion 현행본 기준 보고서 양식 갱신 설계

## 목적과 범위

현재 과제1 Notion 페이지를 내려받은 `과제/과제1/보고서_노션.md`의 구조를 근거로, `[2026-2] 자료구조 및 알고리즘 이해` 후속 프로그래밍 과제의 반복 보고서 양식을 갱신한다. 사용자는 대화에서 제안한 결정 전부를 승인했다. 이 문서는 기존 과목 양식 참고 파일의 수정 범위를 정한다. 과제1 본문, Notion 페이지, 코드, PDF는 수정 대상이 아니다.

## 근거

- 현재 다운로드: `과제/과제1/보고서_노션.md`. 이전 다운로드와 내용은 같고 이미지 URL의 만료 서명만 바뀌었다. 이전본은 `과제/과제1/검토자료/노션_백업/보고서_노션-backup-20260926-231655-013264.md`에 보존됐다.
- 기존 양식: `.agents/skills/programming-assignment-report/references/data-structures-course-format.md`. 스킬 본문은 이미 이 파일을 후속 과제에 조건부로 참조한다.
- 과제1 본문은 자동 목차, 제목 1의 구현 목적·소스코드 분석·실행결과 및 분석, 제목 2의 함수·사례, 그리고 실행 화면 묶음의 제목 3을 사용한다. 코드 분석은 편집 가능한 2열 표이며, 공식 예제에는 입력·실제 출력·이미지·필요한 표·결과 분석이 이어진다. 경계값·예외 입력은 요약 표 뒤에 개별 이미지와 설명이 이어진다.
- Markdown의 이미지 링크는 만료 가능한 서명 URL이다. Markdown만으로 이미지의 실제 크기, PDF의 페이지 분리, 표의 좌우 대응, 가독성은 확인할 수 없다.

## 승인된 양식 결정

1. 기존 양식 파일만 갱신한다. 스킬 본문의 참조 연결과 일반 보고서 검토 원칙은 유지한다.
2. 자동 목차와 번호 없는 제목 1·2를 기본으로 한다. 한 소단원의 실행 증빙을 묶어야 할 때 제목 3을 허용한다. 제목의 이름·개수는 과제 요구에 따라 정한다.
3. 코드 분석은 편집 가능한 2열 표로 유지한다. 왼쪽 텍스트 코드를 실제 소스와 대조할 수 있어야 하며, 오른쪽은 같은 행 코드의 기능 명세·동작 원리를 설명한다. 긴 함수는 대응 관계를 유지한 채 여러 행으로 나눌 수 있다.
4. 개별 실행 사례의 예시 흐름은 입력, 실제 출력, 실행 화면, 필요할 때 상태·계산 표, 결과 분석이다. 여러 경계값·예외 사례를 한 표에 모으면 표 뒤에 화면과 해당 설명을 표의 사례 순서대로 둔다. 화면은 인접한 제목이나 설명으로 어느 사례인지 식별돼야 한다.
5. 목차와 첫 대단원 사이는 빈 블록 한 칸, 대단원 사이는 두 칸, 같은 대단원의 소단원 사이는 한 칸을 기본으로 한다. 대단원 바로 뒤 첫 소단원에는 빈 블록을 추가하지 않는다. 출력·이미지·표·분석 사이에는 기계적으로 한 칸씩 넣지 않고 실제 본문의 읽기 흐름에 맞춘다. 작성자가 의도한 줄바꿈과 셀 내용은 임의로 재배열하지 않는다.
6. 함수명, 사례·스크린샷 수, 표 열 너비, 날짜, 점수는 과제1에서 후속 과제로 고정하지 않는다. 새 과제의 공식 지시 또는 작성자의 새로운 명시적 선택이 다르면 이를 우선한다.
7. 별도 표지, A4 가로 본문 PDF, 페이지 번호 생략은 기존 과목 양식으로 유지한다. 실제 PDF를 검사하기 전에는 PDF 레이아웃이나 제출 완료를 확인된 상태로 표시하지 않는다.

## 검증 경계

양식 수정 뒤 현재 다운로드 Markdown과 문장의 대응을 확인한다. 스킬의 과목 제한·과제별 공식 지시 우선·PDF 실물 검증·텍스트 코드 보존 원칙을 다시 읽어 유지 여부를 확인한다. 현재 PDF를 새로 검증하거나 Notion 페이지를 편집하지 않는다.

# 자료구조 보고서 반복 양식 스킬 설계

## 목적과 범위

프로젝트 로컬 `programming-assignment-report` 스킬이 이 과목의 후속 프로그래밍 과제 보고서에서 동일한 Notion 작성 양식을 재사용하게 한다. 적용 범위는 **[2026-2] 자료구조 및 알고리즘 이해**의 후속 과제다. 사용자가 다른 범위를 지정하지 않고 계획 작성을 요청했으므로 앞선 설계의 이 범위를 기본 확정한다. 다른 과목의 보고서에는 이 양식을 자동 적용하지 않는다.

기존 스킬의 과제별 지시 확인, 작성자 본인의 설명과 실제 실행 근거, 최종 PDF 실물 검증 원칙은 유지한다. 이번 과제의 함수명, 사례 수, 스크린샷 8장, 점수와 날짜는 양식에 넣지 않는다.

## 근거와 우선순위

- `과제/과제1/과제 채점기준.pdf`: 함수별 칸, 왼쪽 텍스트 코드·오른쪽 분석, 페이지 반분, 텍스트 코드 의무의 근거다.
- `과제/과제1/보고서_노션.md`: 현재 합의한 제목 계층과 빈 블록 배치의 예시다. 내용이나 함수명은 후속 과제의 템플릿이 아니다.
- 이 대화에서 사용자가 정한 선택: Notion에서 본문 완성 후 A4 가로 PDF 내보내기, 별도 A4 가로 표지와 병합, 페이지 번호 생략, 텍스트 입출력과 실제 터미널 스크린샷 병행, 의도한 한 칸·두 칸 간격 보존.
- 후속 과제의 공식 지시와 사용자의 새로운 명시적 선택이 이 과목 양식과 다르면 차이를 밝히고 해당 과제의 실제 요구사항을 따른다. 충돌 여부를 확인하지 않고 기존 양식을 강행하지 않는다.

## 반복 양식

1. 본문은 Notion 자동 목차로 시작한다. 대단원은 제목 1, 소단원은 제목 2로 두고 제목에 번호를 붙이지 않는다. 목차에 둘 다 표시한다.
2. 목차와 첫 대단원 사이에는 빈 블록 한 칸, 대단원 사이에는 두 칸, 같은 대단원의 소단원 사이에는 한 칸을 둔다. 대단원 바로 뒤 첫 소단원에는 빈 블록을 추가하지 않는다. 작성자가 정한 수동 줄바꿈과 표 셀 안 항목 순서는 임의로 정리하지 않는다.
3. 소스 분석은 함수별 편집 가능한 2열 표로 둔다. 왼쪽은 실제 소스와 같은 텍스트 코드, 오른쪽은 같은 행 코드의 기능 명세와 분석이다. 제공된 전역 정의·매크로·구조체·함수 원형도 과제 요구에 맞게 분석한다. 코드의 원래 줄바꿈을 보존하고 PDF에서 생기는 추가 자동 줄바꿈은 줄이도록 한다.
4. 실행 사례는 입력·실제 출력의 텍스트 블록과 실제 터미널 스크린샷을 함께 둔다. 스크린샷에는 사례명을 표시하고 읽을 수 있는 크기로 한 줄에 한 장씩 배치한다. 개별 예제의 이미지는 해당 결과 분석 가까이에 둔다. 여러 검증 사례를 한 표에 묶었다면 이미지는 표 아래에 행 순서대로 둔다. 출력 텍스트·이미지·분석 사이는 각각 한 칸, 다음 사례 전은 기존 소단원 간격을 따른다. 과제별 사례 수는 실제 검증과 지시에서 정한다.
5. 표가 여러 페이지에 걸리면 행 사이에서 넘어갈 수 있다. 같은 행의 코드와 분석이 서로 다른 페이지로 갈라지지 않게 확인한다. PDF에서 머리행 반복 여부, 제목만 남는 페이지, 코드·이미지 글자 크기, 6열 등 넓은 표의 가독성을 확인한다. 필요하면 정해 둔 간격을 유지하며 Notion 페이지 나누기, 열 너비, 행 높이를 조정한다.
6. 학번·이름·보고서 제목은 별도 표지에 둔다. 상세 실행 환경은 실제 빌드 근거와 확인 범위에 맞게 기술한다. 본문 첫머리에 학생 정보나 자동 생성된 실행 방식 안내를 기계적으로 복원하지 않는다.

## 산출물과 검증 경계

스킬 본문에는 이 과목일 때 읽을 참조 문서 링크와 적용 조건만 짧게 추가한다. 상세 반복 양식은 `references/data-structures-course-format.md`에 둔다. 현재 보고서와 Notion 페이지, 소스코드, PDF는 이 스킬 변경의 수정 대상이 아니다.

Markdown 또는 Notion API 조회는 원고 검증이다. 최종 내보낸 본문 PDF와 표지 병합 PDF를 각각 확인하기 전에는 페이지 배치·코드 복사 가능성·이미지 가독성을 통과로 표시하지 않는다. 실제 제출과 아주BB 업로드도 별도 상태로 둔다.

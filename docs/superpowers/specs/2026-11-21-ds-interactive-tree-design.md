# ds-interactive 재귀 트리 설계

2026-11-21 대화에서 확정한 첫 버전은 C 이진 트리의 중위 순회다. 학생이 한 줄을 실행하고 전체 트리에서 현재 위치를 찾고, NULL 호출에서 돌아온 직후 어느 호출이 어느 줄을 실행하는지 설명할 수 있게 한다.

## 학생 화면

- 왼쪽은 다음에 실행할 코드, 중앙은 전체 트리, 오른쪽은 호출 스택·메모리 표다. 현재 호출과 방금 실행한 줄을 다음 줄과 구별한다. 트리 노드의 위치는 재생 중 고정한다.
- 대기 호출의 복귀 위치와 각 호출의 독립적인 `p` 칸을 표시한다. 칸 자신의 주소와 저장된 포인터 값에 각각 레이블을 붙인다. 선택한 노드의 `key`, `left`, `right` 및 그 노드를 가리키는 포인터를 강조한다. 메모리에서도 트리의 대상을 선택할 수 있다.
- 현재 호출 경로, 현재 NULL 가지, 출력 순번을 글자와 모양으로 구별한다. 출력 번호는 해당 노드의 키를 실제로 출력한 단계부터 표시한다. 호출에서 돌아올 때 그 호출의 지역 저장 공간은 수명이 끝난다. 트리 객체는 해당 객체의 수명에 따라 표시한다.
- `다음 줄`은 강조된 줄을 한 번 실행한다. 같은 소스 줄이라도 다른 호출에서 실행하면 새 단계다. 초기 화면은 호출 전이며 정상 종료 화면에는 다음 줄을 강조하지 않는다. `이전 줄`, 재생, 단계 선택과 슬라이더는 모두 동일한 줄 단위 위치를 사용한다. `이전 출력 / 다음 출력`은 현재 위치보다 엄격히 앞/뒤인 출력 직후에 멈춘다.
- 1024px 미만 화면은 중앙에 트리·현재 줄 요약·활성 호출·출력을 유지한다. 왼쪽 서랍은 전체 코드, 오른쪽 서랍은 스택·메모리 표를 담는다. 선택·서랍·크기 전환은 실행 위치를 바꾸지 않는다. 사례를 바꾸면 재생을 멈추고 위치와 선택을 초기화한다.

## 기준 예시와 범위

학습용 보충 코드의 여섯 줄은 아래와 같다. 별도 호출자 화면에 `inorder(root);`를 표시한다.

```c
void inorder(Node *p) {
    if (p == NULL) return;
    inorder(p->left);
    printf("%d ", p->key);
    inorder(p->right);
}
```

| 단계 | 다음 위치 | 화면에서 확인할 상태 |
|---|---|---|
| 노드 1에서 3행 실행 | NULL 호출의 2행 | `1.left`의 NULL을 새 `p`에 복사. 노드 1 호출은 4행에서 재개할 상태로 대기 |
| NULL 호출의 2행 실행 | 노드 1 호출의 4행 | NULL 호출의 `p` 수명 종료. 노드 1 호출이 활성. 출력은 비어 있음 |
| 노드 1에서 4행 실행 | 노드 1 호출의 5행 | `1.key` 읽기. 출력에 `1` 추가. 트리의 노드 1에 출력 ① 표시 |

기본 입문 트리는 8의 자식 3·10과 3의 왼쪽 자식 1이다. 1105 강의 사례는 18의 자식 7·26, 7의 자식 3·12, 26의 오른쪽 자식 31, 31의 왼쪽 자식 27이다. 빈 트리를 기저 사례로 제공한다. 1105 정리노트 `s0-inorder`에서 새 자료를 같은 탭으로 연다. 전위·후위 비교, 예측 학습, 트리 변경 연산은 중위 순회 결과를 검토한 뒤 각각 확장할 수 있다.

## 구조와 제작 제약

후보는 기존 C 엔진 확장, 1105 순회 위젯 확장, 범용 C 실행기였다. 기존 C 엔진을 확장하면 호출·수명·읽기·쓰기 기록을 보존하면서 트리와 코드 화면을 함께 검증할 수 있다. 1105 위젯은 강의 트리와 출력 순서의 대조 자료로 활용한다.

- Node.js 20 이상, CommonJS 시나리오·CLI, 브라우저 네이티브 DOM·SVG. 새 런타임 의존성은 0개다.
- 공개 HTML은 `file://`에서 오프라인으로 열리며 외부 HTTP 요청은 0건이다. 기존 공용 Pretendard 상대 경로를 사용한다.
- 주소는 기호 주소다. 포인터는 값으로 전달하고 노드의 정체성은 객체 ID로 비교한다.
- 기존 `c-memory` 시나리오·자료의 이벤트 단위 동작과 화면을 유지한다. `c-tree`는 같은 엔진의 상세 이벤트 위에 줄 단위 스냅샷을 투영한다.
- 기본 한도는 상세 스냅샷 2,000개, 호출 깊이 64, 객체 256개다. 오류·한도 진단에서는 재생을 멈춘다.
- 1024px 이상에서 좌우 패널을 사용한다. 1024px 미만은 기존 서랍 규칙, 44px 이상 주요 조작부, 키보드·포커스·텍스트 상태·reduced-motion을 지원한다.
- 현재 `review → save → link-notes` 경로를 사용한다. 스키마·내용·독립 검산·브라우저 증거가 모두 현재 해시와 일치할 때 강의 노트에 연결한다.

## 검증 기준

기본 출력은 `1 3 8 10`, 1105 출력은 `3 7 12 18 26 27 31`, 빈 트리의 출력은 없다. 독립 C 실행에서 호출 진입·NULL 검사·출력·복귀 순서를 확인한다. 브라우저에서 기준 세 장면, 역방향과 임의 이동, 객체 선택, 사례 전환, 모바일, 키보드, 동일 키 객체 구별을 확인한다. 0928 포인터 예제도 현재 엔진으로 빌드해 오프라인 회귀를 검사한다.

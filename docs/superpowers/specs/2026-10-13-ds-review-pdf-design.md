# 자구알 복습팩 PDF 설계

## 목표와 확정 사항

앞으로 생성·갱신하는 복습팩에 문제지·답안 PDF를 포함하고, 기존 9개 팩에도 추가한다. 사용자는 전자회로2 PDF 템플릿 유지를 요청했다. 따라서 처음 제안한 A4 가로·새 템플릿은 폐기하고 전자회로2의 현재 영상용 16:9 템플릿을 보존한다.

- 입력: 검증된 최종 `복습문제_<range>_<slug>.html`.
- 출력: 입력과 같은 폴더의 `복습문제_<range>_<slug>-문제.pdf`, `복습문제_<range>_<slug>-답안.pdf`.
- 해설 내용: 기존 `.solution` 전체와 `.answer`. 별도 문제설명의 일곱 구역은 포함하지 않는다. 이전 설계의 권장값을 사용하며 사용자 변경 요청은 없었다.
- 기존 HTML·MD·그림·은행·기존 검증 보고서는 바꾸지 않는다. PDF 전용 보고서는 `자료_PDF/pdf-validation.json`에 별도로 저장한다.
- backfill은 PDF만 추가한다. 교과서 문항을 추가하는 `update-existing all`을 호출하지 않는다.
- 신규·lite·update-existing는 최종 리뷰 검증 이후 PDF 생성을 실행한다. 문제설명 생성과 PDF 생성은 같은 리뷰에서 파생되는 독립 단계이므로 한쪽 실패가 다른 쪽의 검증된 결과를 삭제하지 않는다.
- 정리노트 PDF·영상·ZIP·Git push는 범위 밖이다.

## 내용 변환과 페이지 분할

저장된 HTML을 파싱하여 DOM 실행 전 원본 카드 순서를 따른다. `.problem`의 선택지·코드·소문항·그림, `.solution`의 단계 목록 밖 완성 코드·표·그림까지 모두 수집한다. `summary`만 제거하고 답을 별도 필드로 분리한다. 출처는 `data-source`와 원문 보기의 출처 문장을 기록한다. 기출·교과서의 종류를 허위로 바꾸지 않는다.

기존 카드에 조건/구할 것 구분이 없으므로 문장을 추측해서 분해하지 않는다. 원문 문제 전체를 `html.ask`로 전달하고 `html.conditions`와 `html.original`은 빈 문자열로 둔다. 기존 템플릿의 빈 조건 표시는 그대로 둔다. 그림은 템플릿의 figure band에 연결하고 출현 순서를 보고서에 기록한다. SVG는 원본을 독립 자산으로 보존하고 viewBox 비율과 크기를 유지한다.

풀이의 `ol.steps > li`와 그 밖의 직접 자식 블록을 원래 순서의 `solution.steps[].html`로 전달한다. 문제지와 답안지의 페이지 계획은 공통이며, 각 페이지는 동일한 논리 문항과 질문 조각을 갖는다. 긴 문제·해설은 블록, 소문항, 코드의 개행 경계에서 연속 페이지로 나눈다. 헤더는 첫 페이지 `P4`, 이후 `P4 (계속 2)` 형태, 물리 ID는 `p4`, `p4-c2` 형태다. 힌트는 첫 조각에만 연결하여 appendix를 중복 생성하지 않는다. 정답은 마지막 조각에만 표시한다.

템플릿 자체의 기존 fitting을 먼저 사용한다. 임의 글꼴 축소·CSS 덮어쓰기·말줄임·코드 개행 변경은 하지 않는다. 단일 코드 줄·분할 불가 표·그림이 끝까지 넘치면 해당 팩 발행을 보류하고 문항·영역을 보고한다. 각 분할은 남은 블록/줄을 실제로 감소시켜야 하고 문항당 최대 128조각을 허용한다. 실패는 데이터 손실로 숨기지 않는다.

## 발행과 검증

팩별 staging에서 문제·답안 PDF와 별도 보고서를 만들고 모든 검증 후 세 파일을 발행한다. 보고서는 source/template/assets SHA-256, 논리 문항 순서, 물리 페이지 대응, 내용 블록·코드·그림 해시, 실제 기계/실화면 검증 결과, 실패 이유를 포함한다.

동일 팩의 동시 발행을 잠금으로 막고 발행 직전에 입력 SHA-256을 다시 확인한다. 기존 대상 파일은 백업하고 일반 저장 오류는 rollback한다. 여러 파일의 OS 원자성이나 강제 종료까지 완전한 복원을 보장한다고 표현하지 않는다. 이전 PDF가 새 HTML과 불일치한 상태에서 새 빌드가 실패하면 stale로 명시한다.

0문항은 PDF 없이 skipped, 손상된 카드·중복 ID·수식 오류·깨진 자원·내용 누락·넘침은 withheld다. backfill은 다른 팩을 계속 처리하되 withheld가 하나라도 있으면 종료 코드 1이다. 합성 승인 결과를 실제 발행 승인으로 사용하지 않는다.

현재 대상은 0907(4), 0914(12), 0917(12), 0921(8), 0928(4), 1001(4), 1005(4), 1008(4), 1012(12): 총 9팩·64문항·PDF 18개다. 실행 시 다시 발견하고 실제 개수가 바뀌면 새 목록을 보고한다. 각 문항은 최소 한 페이지를 갖지만 힌트·연속 페이지 때문에 PDF 쪽수는 문항 수와 다를 수 있다.

모든 생성 페이지를 렌더링하여 코드·넓은 SVG·수식·힌트·하단 예약 영역·페이지 순서를 실화면 확인한다. 화면 검토가 끝난 stage의 해시에 승인 기록을 묶는다. PDF 추출 텍스트는 보조 증거이며 그것만으로 그림이나 코드의 시각적 완전성을 증명하지 않는다.

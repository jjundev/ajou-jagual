# 실습1 코드 주석 및 보고서 설계

## 목적

`실습/실습1/Practice 1.c`의 실행 동작을 유지하면서 필요한 주석을 보강하고, 카탈란 경로 문제의 코드와 실행 결과를 사용자가 자기 말로 설명할 수 있게 돕는 Markdown 보고서 초안을 만든다.

## 확정된 범위

- `Practice 1.c`에서는 함수 형식, 계산식, 입출력 문자열을 변경하지 않는다.
- C 파일의 변경은 주석 추가와 기존 주석 정리에 한정한다.
- 보고서 초안은 `실습/실습1/실습1_보고서.md`에 작성한다.
- 보고서에는 `combination`, `catalan_comb`, `catalan`, `main` 네 함수를 모두 포함한다.
- 보고서의 코드는 이미지가 아닌 텍스트로 작성한다.
- 함수마다 소스 코드와 분석 영역을 분리하여, 향후 Notion에서 왼쪽 코드·오른쪽 분석의 2단 형식으로 옮길 수 있게 한다.
- 실행 결과에는 실제 프로그램 출력과 결과가 나온 이유를 함께 다룬다.
- 이번 작업에는 Notion 업로드와 PDF 변환을 포함하지 않는다.

## 자료에서 확인된 문제 요구사항

- 허용 좌표는 `x >= y`, `y >= 0`이다.
- `y == 0`이면 가능한 경로 수는 1이다.
- 허용 영역 밖의 좌표는 경로 수가 0이다.
- 일반 좌표에서는 `f(x,y) = f(x-1,y) + f(x,y-1)`을 사용한다.
- 작성 대상 함수는 `catalan`이며, `combination`과 `catalan_comb`은 비교 기준을 계산한다.

## 보고서 기준

실습1 PDF에는 별도 보고서 기준이 없으므로, 같은 과목의 `과제/과제1/과제 채점기준.pdf`를 안전 기준으로 적용한다.

- 소스코드 분석: 함수의 기능과 동작 원리를 설명한다.
- 실행결과 분석: 출력값을 나열하는 데 그치지 않고 값이 나온 이유를 설명한다.
- 함수별로 코드와 분석을 분리한다.
- 주석은 보고서의 함수 분석을 대신하지 않는다.
- 최종 제출용 코드와 보고서의 코드는 텍스트여야 한다.
- 최종 제출 단계에서는 C 파일과 PDF 보고서를 개별 파일로 준비한다.

과제1의 마감일과 함수별 배점은 실습1에 적용하지 않는다.

## 작성 윤리와 문체

- AI 사용을 감추기 위한 표현 조작이나 인위적인 실수 삽입을 하지 않는다.
- 제출용 분석 문단을 대신 완성하지 않고, 확인된 사실·수식·실행 근거와 구체적인 작성 질문을 제공한다.
- 사용자가 자기 설명을 작성한 뒤 사실관계, 누락, 문장 흐름을 검토하는 방식으로 진행한다.
- 문체는 짧고 구체적인 한국어 기술문으로 유지한다.

## 현재 검증 기준선

- `-std=c11 -Wall -Wextra -Wpedantic`으로 컴파일 경고가 없다.
- `(0..7, 0..x)`의 유효 좌표 36개에서 `catalan`과 `catalan_comb` 결과가 모두 일치한다.
- `(2,4)` 입력에서 잘못된 좌표 메시지를 출력하고 종료한다.
- 확인할 대표 결과는 `(2,2)=2`, `(3,2)=5`, `(5,2)=14`, `(5,4)=42`, `(4,2)=9`, `(7,7)=429`이다.

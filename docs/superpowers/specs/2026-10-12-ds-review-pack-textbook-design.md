# 기출·교과서 통합 복습문제 설계

## 확정된 의도

ds-review-pack에서 기출과 교과서 연습문제를 함께 사용한다. 기존 9개 리뷰팩은 기존 문제를 유지하고 교과서 원문 4~8개씩 추가한다. 사용자가 2026-10-12에 이 분량과 구현·업데이트 범위를 명시적으로 선택했다. 구현 방식은 writing-plans 실행 인계에서 선택한다.

분류: bounded. 기존 후보 선별, manifest, 카드, HTML/MD 검증 흐름을 확장한다. 새로운 교과서 정답은행이나 별도 사이트는 만들지 않는다.

## 조사 기준

현재 교과서에는 장별 JSON 14개와 문항 213개가 있다. 문항의 review.status는 모두 verified이고 answer는 모두 null이다. verified는 원문 대조 상태이며 정답의 검증 상태가 아니다. 교과서/제작자료/scripts/validate.py는 원본·자산·검토 payload의 현재 해시를 검사한다. 기출 BANK와 교과서 추출본은 다른 스키마로 보존한다.

기출 선별 규칙은 현재 기출만 허용한다. bank.py의 select는 강의록 장 번호와 기존 data-source를 이용한다. check_manifest는 기출 ID만 조회한다. manifest.py의 part ID는 고정 열거가 아니고 assemble.py의 build_review는 임의의 parts 목록을 지원한다. test_skill_files.py의 ML_WORDS에는 교과서가 들어 있어 이번 기능과 모순된다.

기존 카드 수는 0907=0, 0914=8, 0917=8, 0921=4, 0928=0, 1001=0, 1005=0, 1008=0, 1012=8이다. 합계 28개이며 실행 직전에 다시 조사한다. 1012에는 기존 8개 문항의 문제설명과 검토 자료가 있다.

## 동작과 선별

- 새 팩은 총 8~12문항이며 적합한 교과서 후보가 있으면 교과서 원문을 최소 2개 포함한다. 기출과 교과서 원문을 함께 선별한 후 부족할 때 기존 기출 숫자 변형 규칙을 적용한다.
- 기존 9개 팩은 기존 문제를 유지하고 교과서 원문 4~8개씩 추가한다. 기존 팩에는 총 12개 상한을 적용하지 않는다. 기본 추가 목표는 4개이며, 같은 개념 3개 이상 중복을 피하고 배운 핵심 개념을 더 다뤄야 할 때 최대 8개까지 늘린다.
- 대상 날짜: 0907, 0914, 0917, 0921, 0928, 1001, 1005, 1008, 1012.
- 해당 날짜까지 실제 배운 내용으로 문제·보기·소문항 전체를 풀 수 있어야 한다. 예고만 한 내용이나 보충 전용 내용은 포함 근거가 아니다.
- 이미 쓴 교과서 원문은 다음 팩의 원문 후보에서 제외한다. 갱신 대상 자신은 used에서 제외한다. 날짜 오름차순으로 선별한다.
- 4개 미만의 적합한 원문밖에 없으면 가능한 원문만 추가하고 날짜·개수·제외 이유를 미해결로 보고한다. 범위를 넓히거나 변형으로 교과서 원문 수를 채우지 않는다.
- 선택지는 label과 순서, C 코드, 재귀 소문항, 그림·표를 보존한다. 선행 문제에 의존하는 문항은 그 선행 문항을 함께 싣거나 제외한다. 누락된 본문을 추측하지 않는다.
- 교과서 원문 숫자·코드·오타는 교정하지 않는다. 풀이가 불확실해지는 source-error, external-context, blocking issue는 제외한다. 의미에 영향 없는 오타를 포함하려면 selection.json에 근거를 적는다.

## 장 번호와 개념 대응

| 강의록 | 교과서 |
|---|---|
| S1, S2, S3 | 1, 2, 3장 |
| S4 List | 6·7장 연결 리스트 |
| S5 Stack | 4장 |
| S6 Queue | 5장 |
| S7 Tree | 8장 |
| S8 Heap | 9장 |
| S9 Sorting | 12장 |
| S10 Graph | 10·11장 |
| S11 Hash | 14장 |
| S12 Search | 13장 |

이 대응은 후보 검색용이다. 교과서 3장의 배열 삽입·삭제와 복잡도 문항(ch03-q08~q11)은 강의록 S4의 배열 리스트와도 연결될 수 있다. 문항별 개념 대응은 실제 강의록·STT 근거를 검토한 후 selection.json에 기록한다. 이를 이용해 해당 개념 후보를 조회할 수 있으나 전체 장이나 미학습 개념을 허용해서는 안 된다. 1001은 연결 리스트 장 전체를 배운 것으로 처리하지 않는다.

## 출처·정답·화면 계약

- 기출 source ID와 기존 pN을 유지한다. 교과서 source는 textbook-ch04-q03 형식이다.
- manifest 문제에 source_kind: past-exam|textbook을 지원한다. 생략한 기존 문제는 past-exam으로 해석한다. 출처 종류와 ID 불일치는 검사 오류다.
- 교과서 source_refs, 원문 JSON 경로, source/asset 해시와 검토 payload를 제작자료에서 추적한다. 교과서 원본은 수정하지 않는다.
- partD의 제목은 D. 교과서 연습문제, short는 D 교과서이다. 0문항 part는 넣지 않는다. 기존 partA/B/C는 유지한다.
- 카드 data-source는 manifest source와 같아야 한다. 원문 보기에는 교과서 장 제목·문항 번호·책 쪽번호(없으면 PDF 쪽번호)를 표시한다. 배지는 추가하지 않는다.
- 새 문제의 원문 보기는 교과서 원문 보기, 공통 안내는 문제 원문, 힌트, 풀이로 쓴다. 제목은 복습문제 N선 — <range> 수업 범위로 한다. 기존 카드의 기출 원문 보기 문구는 유지한다.
- 직접 작성한 answer와 풀이를 검증한 뒤 팩에 싣는다. Python 추적·계산, C11 컴파일·실행, 개념 문항의 강의 근거, 구현형의 요구 조건·실제 실행을 구분해 기록한다.
- 인쇄 실행 예시가 문제 단서로 존재하면 보존하지만 인쇄 정답과 observations의 필기를 풀이 대신 사용하지 않는다. 새 풀이에 수업 밖 개념을 도입하지 않는다.
- 교과서 figure/table은 검토된 구조와 SVG를 재사용한다. 카드에 inline SVG로 넣을 때 모든 id와 href/url(#...) 참조를 카드·출처별로 함께 바꿔 중복을 피한다. 흰 배경·대체 설명을 유지하고 정답 그림과 원문 그림을 구별한다.

## 기존 팩 갱신과 보존

먼저 HTML/MD/그림을 백업하고 기존 카드의 id, source, raw HTML 및 해시를 기록한다. 기존 정리노트 HTML과 문항 카드 28개, 문제설명 HTML/MD/자료는 변경하지 않는다. 문제 카드 뒤에 partD를 추가하며 기존 마지막 pN 다음 번호를 사용한다. 재실행은 기존 partD를 같은 source→pN 대응으로 교체하고 중복 카드를 덧붙이지 않는다.

기존 팩은 전체 조립기로 재생성하지 않는다. 검증된 기존 카드의 raw HTML과 기존 노트·진행 저장 키를 보존하는 갱신 함수를 쓴다. 제목·소개·목차·footer·공통 패널 안내만 새 구성에 맞춰 고친다. 이전 문제설명에는 신규 문항이 없음을 검증 보고서에 명시한다.

날짜마다 복습노트/<range>/자료_복습팩/에 manifest.json, selection.json, answers.py, validation.json을 저장한다. selection.json에는 실제 source와 수업 범위 근거, 제외/의존 문항, 정답 검증 방법, 추가 개수를 기록한다. answers.py는 직접 계산·추적·C harness의 재현 가능한 검산이며 읽기 전용으로 실행 가능해야 한다. 임시 C/렌더링은 RUN/work에 둔다. 저장 자료는 다음 실행에서도 검증·재생성에 사용한다.

복습문제 MD를 갱신한다. html2md.py에 단일 HTML 변환을 사용하는 동안 정리노트 MD를 다시 쓰지 않는다. inline SVG 추출에서 기존 figures 파일을 충돌 덮어쓰기하지 않는다. 검증 실패 시 해당 날짜는 발행하지 않고 기존 파일을 유지한다.

## 검증과 완료 조건

- 기존 기출 validate/select/check-manifest CLI와 기존 manifest 호환성을 유지한다.
- 교과서 경로를 명시한 경우 누락 폴더·검증 실패는 오류다. 조용히 기출 전용으로 진행하지 않는다.
- 교과서/기출 양쪽의 원본 무수정, 기존 카드/노트/문제설명 무변경, 재실행 멱등성, source 종류와 ID 일치, 정답·자료 검증을 확인한다.
- 기계 검사는 manifest.py, bank.py check-manifest --textbook-dir, check_html.py, html2md.py --check를 사용한다. 기존 범위의 모순이 드러나면 문제를 몰래 지우거나 수정하지 않고 보고한다.
- 모든 9개 팩을 1280×900/375×812와 light/dark에서 확인한다. 모든 신규 카드의 보기·코드·그림·힌트·풀이·목차·이전/다음·기존 링크를 확인한다. 콘솔·KaTeX 오류, 누락 자원, 문서 가로 넘침은 0이며 코드/넓은 표의 내부 스크롤은 허용한다.
- 전체 보고서에 날짜별 기존/추가/최종 개수, 제외 이유, 부족한 팩, 검산·브라우저 결과와 백업 위치를 남긴다. 검증하지 않은 것을 완료로 표시하지 않는다.
- 커밋·푸시는 별도 사용자 요청 없이 실행하지 않는다.

## 범위 밖

교과서 전체 정답은행, 원문 교정/재추출, 기출은행 재생성, 기존 문제설명 전체 확장, 프런트엔드 재설계는 제외한다.

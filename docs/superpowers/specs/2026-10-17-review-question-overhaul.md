# 복습문제 전면 개편 설계

## 확정된 목표

2026-10-17 대화에서 사용자가 승인한 grill-yourself 설계와 결정 #7을 기록한다.

- `복습노트/` 전체 날짜의 중복 문제를 제거한다.
- 실제 강의 예제 코드를 이해·추적·완성·작성하는 문제를 직접 출제한다.
- 생성 스킬의 지침과 실행 검증을 함께 고쳐 재발을 막는다.
- **핵심 범위 충족 우선**, 보통 8~12개를 목표로 하되 부족하면 적게, 필요하면 초과한다.
- 문제 수를 채우기 위한 숫자 변형은 만들지 않는다.

기존 복습팩 생성 체계의 보완 작업이다. 문제·해설·PDF는 하나의 출제 결과를 전달하는 연결된 산출물이며, 별도 제품으로 나누지 않는다.

## 중복 판정

1. 기출의 `duplicate_of`를 원문 대표 ID로 정규화한다. 같은 원문과 숫자만 바꾼 변형의 재사용은 날짜 전체에서 차단한다.
2. 실제 질문·코드·보기·그림의 내용을 비교한다. 원문 보기·힌트·풀이의 동일성만으로 중복 처리하지 않는다.
3. ID가 달라도 상수·변수명만 바꾸고 같은 풀이 절차를 요구하면 통합하거나 교체한다.
4. 코드 구조·풀이 절차 유사성은 검토 후보다. 자동 삭제하지 않으며 현재 입력 해시와 연결된 판정·이유를 남긴다.
5. 같은 개념이어도 평가 능력이 다르면 허용한다. 같은 예제의 빈칸·추적 등 밀접한 질문은 가급적 한 카드의 소문항으로 묶는다.
6. 대표 문항은 해당 내용을 실제로 배운 날짜와 풀이 품질로 정한다. 늦은 날짜에 배운 내용을 최초 사용 날짜에 억지로 남기지 않는다.

## 강의 코드 출제

- `source_kind: lecture-code`를 추가한다. 기출·교과서 원문 출처와 혼용하지 않는다.
- ID 예: `lecture-s02-p10-power`. manifest의 `lecture_ref`에는 `path`, `pdf_page`(1부터), `sha256`, `example`, `taught_on`을 기록한다.
- `objectives`는 해당 카드의 평가 목표 ID 목록이다. `task_family`는 원문 출처가 다른 의미상 중복을 검토하는 데 쓸 풀이 절차 식별자다.
- 모든 출처 경로는 저장소 상대 경로이며 실제 파일과 SHA-256을 대조한다. 해당 PDF 페이지를 실제로 열어 코드와 그림을 확인한다.
- 강의록·STT에서 다룸/일부/예고/미학습을 구분한다. 해당 날짜까지 배운 범위로 모든 소문항을 풀 수 있어야 한다.
- 실제 예제가 없는 날짜는 강의 코드 문항을 강제하지 않는다. 기존 코드·개념 문제가 이미 같은 목표를 충족하면 중복 추가하지 않는다.
- 카드의 원문 영역은 `강의 예제 보기`이고 `강의 예제 기반 자체 출제`임을 명시한다. 자체 질문과 강의 원 예제의 경계를 보존한다.
- 강의 코드의 오래된 `main`, 누락된 헤더, 오타 등과 실행용 harness의 차이는 기록한다. UB·비종료·모호한 코드를 정상 출력 문제로 승인하지 않는다.
- 정답은 독립 추적, Python 계산, C11 컴파일·실행, 강의 근거 대조 중 실제 필요한 방법으로 확인한다.

## 전체 문항 개편

전 문항에 유지/이동/통합/교체 판정과 근거를 남긴다. 핵심 개념·예제별 coverage 표에 문항과 출처를 연결하며 누락 또는 예제 없음의 이유도 기록한다. 기출·교과서의 유효한 문제는 활용하고 원문을 임의로 바꾸지 않는다.

개편용 `revise-existing [MMDD|all]` 모드를 추가한다. 기존 `update-existing`의 교과서 추가·카드 보존 계약은 유지한다. 신규 생성과 두 갱신 모드 모두 최종 전체 팩 중복 검사를 통과해야 한다.

팩별 `p1..pN`을 다시 부여할 수 있다. 이전 source/id/content hash와 새 source/id/content hash의 대응을 저장한다. 변경된 팩은 내용 버전별 풀이 저장 키를 사용해 이전 pN의 완료 표시를 다른 문제에 적용하지 않는다. 테마·패널 설정·정리노트 읽음 상태는 유지한다.

## 산출물과 검증

- 날짜 폴더·slug·현재 파일명을 유지한다. 루트 HTML 3개·PDF 2개, 보조 파일은 `.pack/`에 둔다.
- 정리노트 본문·MD·기존 그림, STT, 강의록, 기출·교과서 원본은 보존한다.
- 복습문제 HTML·MD·manifest·selection·answers·validation과 문제설명 HTML·MD·검토 자료, 문제·답안 PDF를 갱신한다.
- 문항 번호에 의존한 PDF 작성용 표 배치는 source ID로 바꾼다. 참고 표를 작성 표로 오인하지 않는다.
- 검토 기준 `review-questions-2026-10-17`을 기록한다. 옛 검토 기록은 보존하되 변경한 내용의 검증으로 재사용하지 않는다.
- 전체 코드·자동 검사 통과 후 1280×900/375×812와 light/dark에서 모든 문항·링크·힌트·풀이·목차·pager를 확인한다.
- 문제설명은 현재 입력에 대한 source_visual/content/independent/browser가 모두 pass여야 한다. PDF는 문제·답안의 모든 페이지를 실제 검토한다.
- 백업 후 검증된 결과만 교체한다. 오류가 발생한 팩은 실패·stale 이유와 복구 상태를 보고하고 다른 독립 팩은 계속한다. 미검토를 pass로 기록하지 않는다.
- 재실행으로 같은 카드·part·출처가 추가되지 않아야 한다. 전체 팩의 최종 중복 0과 미판정 후보 0을 확인한다.
- 커밋·푸시는 자동으로 하지 않는다.

## 출제 예시

S2 p10의 `power` 예제에서 홀수 분기의 반환식을 완성하고 `power(2,5)`의 인자·반환을 추적한다. 정답 기준은 `x*power(x*x,(n-1)/2)`, `(2,5)→(4,2)→(16,1)→(256,0)`, 최종 32이다. 동일 예제를 숫자만 바꿔 다른 날짜에 다시 싣지 않는다.

이후 후보는 S3 포인터 swap·동적 할당, S4 리스트 삽입·삭제, S5 스택·후위식·괄호 검사, S6 원형 큐·연결 큐·덱의 경계 처리다. 모든 후보는 배운 날짜와 페이지를 확인한 뒤 채택한다.

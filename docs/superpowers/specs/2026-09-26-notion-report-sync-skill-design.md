# Notion 보고서 동기화 스킬 설계

## 목적과 범위

- 프로젝트 로컬 스킬 `.agents/skills/notion-report-sync/SKILL.md`를 만든다.
- 현재 범위는 과제1 HW1 보고서의 기존 Notion 페이지 한 개다. 페이지 ID와 파일 경로는 `codex/course-report-format` 브랜치의 `과제/과제1/검토자료/notion_sync.py`에 있는 값을 사용한다.
- 구현은 그 브랜치의 기존 도구를 확장한다. 현재 `main`에는 동기화 도구가 없다.

## 읽기와 비교

- 기본 동작은 `notion_sync.py pull`로 Notion Markdown을 내려받아 `보고서_노션.md`와 기존 로컬 보고서를 비교하고 변경사항을 설명하는 것이다.
- Notion 응답이 잘렸거나 알 수 없는 블록이 있으면 파일을 저장하지 않는다. 변경된 다운로드는 기존 파일을 백업한 뒤 저장한다. `보고서.md`는 자동으로 덮어쓰지 않는다.
- 문장, 표 셀, 코드, 제목, 빈 줄과 `<br>`을 구별해 비교한다. Markdown 표현만 달라진 경우와 실제 내용 변경을 구별한다. Notion Markdown만으로 판정할 수 없는 배치·PDF 요소는 블록 또는 PDF에서 확인한다.

## 지정 블록 수정

- 사용자가 특정 Notion 내용을 수정하라고 요청했을 때만 수행한다. 페이지 전체 `push`와 `layout-table`은 이 스킬의 일상적 수정 경로가 아니다.
- 변경 대상 블록의 소속, 타입, 기존 텍스트, 수정 전 시각을 **모두** 확인한 뒤 단일 백업을 저장한다. 하나라도 불일치하면 어떤 PATCH도 보내지 않는다.
- 각 변경은 기존 rich-text 조각의 annotation과 링크를 보존한다. 지원 범위를 벗어난 복잡한 rich-text 구조는 임의로 재구성하지 않고 중단한다.
- PATCH 응답이 불확실하면 자동 재시도하지 않는다. 원격 블록을 다시 읽어 상태를 보고한다. 성공한 PATCH도 재조회하여 내용과 구조를 확인한다. 부분 완료는 숨기지 않고 대상별로 보고한다.
- 토큰은 `NOTION_TOKEN` 환경변수에서만 읽고 기록에 남기지 않는다.

## 제외

- 다른 Notion 페이지나 데이터베이스의 일반 동기화.
- 페이지 전체 재업로드, 표 레이아웃 마이그레이션.
- Notion PDF 내보내기와 최종 표지 합치기 자동화. PDF는 사용자가 Notion에서 내보낸 뒤 별도로 확인한다.

## 2026-09-26 범위 변경: 다른 과제에서도 사용

사용자가 이 스킬을 다른 과제의 노션 보고서에도 사용한다고 명시했다. 공통 스크립트는 `.agents/skills/notion-report-sync/scripts/notion_report.py`에 두고, 페이지 ID·로컬 보고서·다운로드 파일·증거 폴더를 실행 인자로 받는다. 이전의 고정 HW1 페이지 범위는 이 절로 대체한다. HW1 전용 초기 업로드와 표 마이그레이션은 기존 `과제/과제1/검토자료/notion_sync.py`에 역사적 도구로 남긴다. 공통 스킬은 이를 호출하지 않는다.

# 보고서 작성 전 이해 확인 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 보고서 본문 작성 전에 필요한 이해를 객관식 보기와 추천 답안이 있는 질문 도구로 하나씩 확인하고, 답변을 근거와 대조하여 보고서에 반영한다.

**Architecture:** 기존 보고서 스킬에 이해 확인 절을 추가하고 기존 질문 규칙을 연결한다. 자료 조사·실행 검증과 작성자 이해 확인을 구분하며, 기존 과목 기준·저자성·최종 PDF 검증 규칙은 유지한다.

**Tech Stack:** Markdown skill instructions, Codex question tools, skill-creator quick_validate.py.

**Spec:** 이 문서의 ‘확정 명세’. 채팅의 grill-yourself 설계와 이후 사용자의 객관식·추천 답안 요청을 함께 반영한 자족적인 명세다.

## Global Constraints

- 질문 도구로 한 번에 하나씩 질문하고 답변을 기다린다.
- 질문마다 객관식 보기와 추천 답안을 함께 제시한다. 자유 입력도 허용한다.
- 보기 선택만으로 독립적인 이해나 직접 작성이 입증됐다고 판단하지 않는다.
- 보고서에 필요한 핵심 이해만 확인하며, 고정 질문 수나 모든 함수에 대한 면담을 강제하지 않는다.
- 답변에 없는 의도·이해·소감을 만들어 넣지 않는다.
- 과목 공통 기준, 보존 PDF·소스, 과제 코드, 기존 보고서 및 다른 스킬은 수정하지 않는다.
- 커밋·푸시는 별도 사용자 지시가 있을 때만 수행한다.

## Review Focus

- 보기만 선택한 답변: 필요한 경우 이유나 작은 실행 예를 추가 확인하고 선택 사실을 이해 증명으로 확대하지 않는다.
- 잘못되거나 모호한 답변: 그대로 보고서에 넣지 않고 설명·후속 확인을 거친다.
- 무응답·건너뛰기: 추천 답안을 사용자 답으로 간주하지 않고 관련 주장만 보류한다.
- 이미 충분한 답변 또는 서식 수정: 불필요하게 같은 면담을 반복하지 않는다.
- 질문 도구가 없는 환경: 부재를 알리고 일반 채팅에서 같은 형식으로 하나씩 질문한다.

## 확정 명세

1. 새 보고서 작성 또는 설명을 실질적으로 다시 쓰기 전에 과제 요구·제공 코드·현재 구현·실행 근거를 읽고 이해 확인 필요성을 점검한다. 자료에 동작이 나와 있어도 작성자의 이해가 확인된 것은 아니다.
2. 핵심 조건·상태 변화의 이유, 작은 입력의 실행 흐름, 작성자 본인의 구현 선택 이유에서 필요한 질문을 선정한다. 제공 설계를 작성자의 선택으로 묻지 않는다. 기존 대화·작성자 초안에 충분한 설명이 있으면 재사용한다.
3. 사용 가능한 질문 도구로 질문 하나를 보낸다. Codex 기본 모드에서는 request_user_input_async를 사용하고, request_user_input은 실제 사용 가능한 Plan 모드에서만 사용한다. 도구별 제약을 따르되 객관식 보기와 추천 답안을 제공한다. 추천 보기는 먼저 두고 ‘추천 답안’으로 표시한다. 도구가 제공하는 자유 입력을 허용하고, 없는 경우 질문에 직접 답변 가능함을 명시한다. 기술적 정답이 있는 질문의 추천은 코드 근거를 따르고, 개인 의도 질문의 추천은 가능한 제안이지 사용자의 실제 의도라는 뜻이 아니다.
4. 응답이 오기 전 다음 이해 질문이나 관련 설명 문단을 완성하지 않는다. 독립적인 조사·실행 검증은 계속할 수 있다. 경과 시간이나 미리 선택된 추천 보기는 응답이 아니다.
5. 답변을 코드·실행 근거와 대조한다. 선택만으로 충분하지 않은 핵심 설명에는 이유·작은 실행 예를 후속 질문으로 확인한다. 후속 질문에도 객관식 보기·추천 답안·자유 입력 원칙을 적용하며, 구체적인 이유를 직접 덧붙일 수 있게 한다. 모호하면 한 가지 구체적 사례로 좁히고, 오해가 있으면 짧게 설명한 뒤 다른 작은 사례로 재확인한다. 횟수 제한 없는 시험처럼 반복하지 말고 해결되지 않은 이해는 미확인으로 남긴다.
6. 확인된 답변의 의미와 설명 수준을 보고서에 반영한다. 추천 답안을 선택한 사실만으로 독립적인 이해를 입증했다고 하지 않는다. 설명 후 확인한 내용을 원래 알고 있었던 것으로 꾸미지 않는다. 과제의 본인 작성 규칙이 있으면 해당 제한을 우선 적용한다.
7. 건너뛰면 관련 이해를 미확인으로 남기고 필요한 주장만 보류한다. 확인된 사실의 작성은 가능하다. 단순 검토·오탈자·서식 수정에는 면담을 강제하지 않고, 이해에 영향을 주는 내용 변경에만 필요한 부분을 다시 확인한다. 문답 원문을 별도 파일에 자동 저장하지 않는다.

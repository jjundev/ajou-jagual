# Independent qualitative proofs

These arguments supplement `verify_new.py`; simulations alone do not prove asymptotic or C language claims.

- **Array boundary:** `int A[3][4]` permits row indices 0–2 and column indices 0–3. `(2,1)` is valid; flat displacement is `2*4+1=9` elements, or 36 bytes under the stated size assumption. One-past pointers, although sometimes formable, cannot be dereferenced as an extra array element.
- **Local storage:** an automatic array has one instance per simultaneously active invocation. Thus recursion depth k can need k arrays of B bytes each. Changing scope alone cannot reduce the size B. A local static object has static storage duration, so local/global is not itself a complete lifetime classification. C does not require a hardware stack implementation.
- **Uninitialized pointer:** an automatic `pc` without initialization does not designate a known valid object. Dereferencing it cannot be assigned a reliable output. Setting it NULL does not create an object. Taking `&c` supplies a live, correctly typed destination. These statements are language-level claims, not claims that a particular machine must crash.
- **Dense polynomial:** D+1 coefficient positions must be processed or emitted, giving Θ(D+1). Saying Θ(D) presumes positive/unbounded D; the +1 includes constant polynomials.
- **Sparse/linked polynomial:** let the remaining potential be the total number of unconsumed input terms. Every comparison consumes one or two terms and decreases the potential; remainder copying consumes each leftover once. Constant-time append gives O(m+n). Disjoint exponents require outputting all m+n input terms, yielding worst-case Ω(m+n). The final question explicitly states that the output tail is maintained for O(1) append, satisfying this implementation assumption.
- **Linked insertion versus search:** after a valid predecessor and new node are available, a bounded number of link assignments gives Θ(1) link-update work. Finding a predecessor at an arbitrary indexed position can require following Θ(n) links. Allocation cost is not established by this pointer-update count.
- **Insertion order qualification:** with `N.link=A.link; A.link=N;`, reversing these exact assignments makes N point to itself and loses A's path to C. If a separate pointer to C has already been saved, `A.link=N; N.link=saved_C;` can also produce the desired final graph. The final question now explicitly restricts the operation to these two assignments without a temporary pointer, so the required order and reversed self-cycle are unambiguous. The former wording dispute is resolved.
- **Traversal termination:** in a finite acyclic list, remaining nodes to NULL is a nonnegative integer that decreases by one per next-link move. Recursive display and unsuccessful iterative search terminate. Cyclic inputs do not have that measure and are outside the prompt's precondition.
- **Length field:** returning `list->length` requires one field access, Θ(1), even with three or arbitrarily many nodes. Correctness requires insertion/deletion maintain the invariant `length = number of data nodes`.
- **Position adapter:** valid insertion positions are 0 through length inclusive. For positive position, the predecessor index is position−1. For position 0, the lecture helper returns NULL for negative index and the insertion primitive updates the head via its pointer-to-pointer argument. Positional predecessor search makes worst-case insertion Θ(n), although range checking and length update are Θ(1).
- **Activation record order:** nested sub2 was entered while sub1 was suspended, and sub1 while main was suspended. Restoring the most recently suspended continuation resumes sub1, then main. Restoring main first would skip sub1's remaining computation. Local values alone do not encode the continuation location. Physical ABI details and numerical C code addresses are unnecessary.

The brick/data/structure wording in the first draft was ambiguous. The final blind question now explicitly distinguishes brick itself, organized wall, and procedure; that ambiguity is resolved.

- **Dynamic node capacity:** a fixed array has its specified capacity. Allocating linked nodes on demand removes that particular fixed-capacity ceiling, but memory allocation can fail. Allocate/check the new node before linking it or updating length; the existing structure remains valid on failure. Constant-time pointer updates do not imply allocation can always succeed.
- **Active versus waiting calls:** while sub2 executes with b=5, main and sub1 are its suspended callers. The full conceptual hierarchy is main, sub1, sub2; this must not be mislabeled as three waiting callers. ABI storage layout is not assumed.
- **Array-stack guards:** for M=3, valid top lies in [-1,2]. At top=2, a successful push would require index3, outside the storage; test fullness before increment or access and preserve top/storage on rejection. At top=-1, no element can be read; test emptiness before read/decrement and preserve state on rejection. Logical emptiness permits stale physical cells, which do not authorize a pop. Both boundary states are independently tested in the simulation.

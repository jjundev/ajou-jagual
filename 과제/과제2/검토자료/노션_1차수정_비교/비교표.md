# 과제02 노션 1차 수정 비교

기준: 마지막 업로드·서식 적용 후 보관한 Markdown과 당시 원격 블록 기록. 비교 대상: 사용자의 1차 수정 후 내려받은 Markdown 및 원격 전체 블록. 비교 중 노션 문서·로컬 C/초안/PDF·스킬은 수정하지 않았다.

## 실행 사례별 세부 비교

빈 칸 수는 Markdown 줄 수가 아닌 실제 빈 paragraph 블록 수다. 사례 입력·실제 출력·결과 분석 및 이미지는 6개 모두 유지된다.

| 사례 | 입력→출력 빈 칸 기존→현재 | 실행 화면 표제 앞 빈 칸 기존→현재 | 이미지 앞 중복 사례명 | 캡션 앞부분 |
|---|---|---|---|---|
| 공식 예제 1: 연속 할당과 분할 | 0 → 1 | 0 → 1 | 삭제 | 터미널 |
| 공식 예제 2: 반납과 양쪽 병합 | 0 → 1 | 0 → 1 | 삭제 | 터미널 |
| 공식 예제 3: 할당 실패와 예외 처리 | 0 → 1 | 0 → 1 | 삭제 | 터미널 |
| 경계 사례: 정확한 크기와 최소 크기 | 0 → 1 | 0 → 1 | 유지 | Antigravity IDE 내장 터미널 |

## 로컬 초안 → 현재 다운로드

| 비교 대상 | 해석 |
|---|---|
| 이전 노션 다운로드와 비교 | 이번 사용자의 실제 수정 사항을 판별하는 기준이다. |
| 로컬 보고서_초안.md와 비교 | 최초 네이티브 업로드 때 생긴 표/코드 셀/TOC/빈 블록/이미지 표현 차이와 이번 수정이 함께 포함된다. 전체 diff를 모두 이번 수정으로 보지 않는다. |
| `<colgroup>`·`<col width>` 추가 | 편집한 표 너비가 Markdown에 기록된 변화다. |
| 서명 이미지 URL 차이 | 원격 파일 경로·이미지 ID·순서 및 픽셀 비교로 실제 이미지가 유지된 것을 확인했다. |
| 페이지 글꼴·작은 텍스트·너비 | Markdown만으로 판별하지 않고 현재 UI에서 확인했다. |
| PDF 배치 | 이번 비교에서 내보내거나 검증하지 않았다. |

## 사용자 답변으로 확정한 통일 기준

| 항목 | 확정한 기준 | 현재 문서에 남은 차이 |
|---|---|---|
| 목차 | 회색 자동 목차 1개 | 기존 목차가 추가로 남아 있음 |
| 입력과 출력 간격 | 모든 사례 사이 빈 블록 1개 | 외부 단편화 사례만 0개 |
| 이미지 앞 중복 사례명 | 모두 삭제 | 정확한 크기 사례만 남아 있음 |
| 이미지 캡션 | ‘터미널’로 통일 | 경계·First-Fit·외부 단편화 3개는 IDE 명칭 남음 |
| 코드 표 너비 | 내용에 맞춰 표마다 조정 | 현재 수치를 후속 과제 고정값으로 사용하지 않음 |

확정 기준과 현재 문서의 실제 상태를 구분했다. 이 비교 작업에서는 노션 본문이나 스킬에 후속 변경을 적용하지 않았다.

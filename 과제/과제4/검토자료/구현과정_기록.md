# HW4.c 구현 과정 기록 (보고서 본문 아님)

작성자가 2026-11-16에 준 구현 과정 자료를 현재 HW4.c·HW4.pdf·실행 결과와 대조해 정리했다. 버그는 AI가 짚었고 수정은 작성자가 직접 했다(작성자 답). 보고서 본문에는 버그 이력을 넣지 않고, 여기 이해한 내용만 함수 설명의 근거로 썼다.

## 출발점

- 제약(12쪽): 함수 형식·매크로·구조체 그대로, 새 함수 금지.
- `read_timers`의 `TimerNode **root`(205행 주석)에서 시작했다. `*root = insert_timer(*root, timer)`는 매번 대입하지만 값이 바뀌는 건 첫 삽입 때 한 번(218행 주석의 답). 삽입만 하는 동안 루트는 다시 안 바뀌고, 루트가 바뀌는 건 `delete_timer`가 루트 자체를 지울 때다.
- 공통 계약: 트리를 바꾸는 함수는 넘겨받은 서브트리의 (바뀌었을 수 있는) 루트를 돌려주고, 호출자는 반드시 다시 대입받는다.

## delete_timer에서 정리한 개념

- C에는 GC가 없고 `destroy_tree`는 트리에 연결된 노드만 해제한다. 떼어 낸 노드는 그때 `free`해야 한다. 순서는 `child` 백업 → `free(root)` → `return child`.
- 자식 2개: 노드를 옮기지 않고 `root->timer`만 덮어쓴 뒤 후보 노드를 재귀로 지운다. 그 재귀가 자식 0·1개 경우로 들어가 `free`와 `*removed = 1`을 처리한다.
- 왼쪽 최댓값은 `find_min_timer`로 못 찾고 새 함수도 못 만들어 `while`로 찾는다. 오른쪽 최솟값만 `find_min_timer` 재사용.
- `left_diff < right_diff`일 때만 왼쪽, 같으면 오른쪽(8쪽). 공식 예시 11쪽 `CANCEL 20 1`이 바로 이 동률 경우(10 = 10 → 30(03)이 루트).

## print_timers 가지치기

`expires < from`이면 왼쪽, `expires > to`면 오른쪽을 건너뛸 수 있지만 8쪽 요구가 아니어서 넣지 않았다(335~337행 주석). 같은 만료 시각이 왼쪽에도 있을 수 있어, 넣는다면 경계값에서는 양쪽을 다 봐야 한다.

## 자료와 다르게 고친 점

- “ASan 기준 메모리 누수 0건”: 이 Mac의 ASan은 누수 검사를 지원하지 않는다(`detect_leaks is not supported on this platform`). 2026-11-16에 `leaks --atExit`로 한 입력을 돌려 0 leaks를 확인했다. 입력 하나의 결과다.
- “p.10과 경계 케이스는 `<cstddef>` 제거 직전 로직에서”: 2026-11-16에 현재 HW4.c로 10·11쪽 예시와 경계 사례를 모두 다시 돌렸고 출력이 같다.
- switch fall-through는 case에 따라 1이 되는 플래그 수가 다르다(-1: 셋, 0: 둘, 1: 하나).
- 자료 3.3의 `int found_key = (compare_timer(…) == 0);`은 최종 코드에 없다. 지금은 switch로 플래그를 정한다.
- 자료 2절 제목의 “`return root;`가 비효율적인 이유?”는 질문이었고, 결론은 비효율이 아니라는 것이다.
- 자료 2절의 “id가 고유해서 insert_timer가 루트를 교체하지 않는다”는 근거가 아니다. insert_timer는 NULL 자리에서만 새 노드를 만들고 나머지 경우 받은 root를 그대로 반환해서 루트가 안 바뀐다(224~237행). 루트에 자식이 둘이면 그 루트를 지워도 노드 주소는 그대로이고 값만 바뀐다(316~324행).

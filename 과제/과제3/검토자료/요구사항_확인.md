## 보고서에서 설명이 필요한 지점(작성자 이해 확인 대상)

코드가 생기면 실제 구현을 보고 확인할 후보다. 정답을 미리 본문에 쓰지 않는다.

- 인터럽트로 중단된 프로세스가 복원될 때 `quantum_left`가 유지되는지(18쪽 T5 `Q 0`이 근거)와, 재선택될 때 다시 `QUANTUM`이 되는 이유(T7 `Q 1`).
- `finish_tick`에서 완료와 퀀텀 소진이 같은 tick에 겹칠 때의 처리 순서(18쪽 T6 P2 `R0 Q1`, T7 P1 `R0 Q1`은 겹치지 않음 → 겹치는 경우는 추가 사례로 확인할 거리).
- 중첩 인터럽트에서 스택이 LIFO여야 하는 이유(18쪽 T3: I2 끝난 뒤 I1 재개).
- 인터럽트가 CPU가 IDLE일 때 도착하는 경우, 모든 프로세스가 끝난 뒤 인터럽트만 남은 경우(`T IDLE` 출력 경로).

## 2026-10-29 참고 구현 초안

- 사용자가 초안 구현을 요청해 `HW3_참고구현_초안.c`를 만들었다. **AI가 작성한 참고본이며 제출용이 아니다.** HW3 21쪽은 ChatGPT 등으로 구현한 코드가 적발되면 구현 0점, 참고는 가능하나 실제 구현은 본인이 하라고 한다.
- 스켈레톤 1~144줄과 145줄 이후의 제공 함수·`main`은 바꾸지 않았다. 세 함수 본문만 채웠다. 사용한 함수는 제공 함수(`is_empty_queue`·`is_empty_stack`·`enqueue`·`dequeue`·`push`·`pop`)와 `printf`·`exit`뿐이다.
- `push`·`enqueue` 실패 시 `SIMULATION_ERROR` 후 종료하는 방어 분기를 넣었다. 정상 입력에서는 도달하지 않는다(큐 9칸에 프로세스 최대 8개, 스택 16칸에 프로세스 1 + 중첩 인터럽트 최대 15개가 쌓임). 넣을지 말지는 작성자가 정할 사항이다.
- `cc -std=c99 -Wall -Wextra` 경고 없이 빌드. 공식 예시 출력이 18쪽 화면과 한 줄씩 일치(`FINISHED 2 INTERRUPTS 2 TICKS 7`).
- 내부 확인(보고서 본문 아님): 인터럽트 없는 라운드로빈, 완료·퀀텀 소진 동시, 프로세스 종료 뒤 IDLE 중 인터럽트, 3중 중첩, 퀀텀 경계 인터럽트, 프로세스 8개, 인터럽트 16개 연속 중첩(스택 최대), 도착 시각 1000. ASan·UBSan 빌드에서 오류 없음.

01 · 친구들과 블록 창고

🧒

친구 = 프로세스

일을 끝내려는 프로그램이에요.
P0, P1은 친구의 번호예요.
🧱

블록 = 자원

A와 B는 서로 다른 종류예요.
A가 남아도 B 대신 쓸 수 없어요.
🏠

창고 = Available

지금 바로 빌려줄 수 있는 양.
친구가 들고 있는 블록은 제외해요.

친구가 일을 끝내면 갖고 있던 블록을 전부 창고로 반환해요. 그러면 다음 친구가 쓸 수 있어요.

02 · 표의 네 단어만 알면 돼요

Maximum · 목표량

완성에 필요한 최대 총량

A 3개
Allocation · 이미 가진 양

지금 친구 손에 있는 양

A 1개
Need · 더 필요한 양

앞으로 추가로 빌릴 양

A 2개

Need = Maximum − Allocation

배열은 숫자를 나란히 둔 줄, 행렬은 그런 줄을 쌓은 표예요. need[i][j]는 친구 i가 자원 j를 더 필요로 하는 양이에요.

모든 종류에서 Need ≤ Available → 실행 가능

필요량 (A 0, B 1), 창고 (A 1, B 0)이면? 총 개수는 같지만 B가 부족해서 실행 불가예요. 이미 완료한 친구는 다시 고르지 않아요.

04 · 왜 Allocation만 더할까?

창고에 A가 2개, 친구 손에 A가 1개, 추가로 필요한 A가 2개라고 해 봐요.

① 2개 빌려주기
2 → 0
창고에서 Need만큼 빠져요.
② 완성하고 3개 반환
0 → 3
원래 1개 + 빌린 2개가 돌아와요.
③ 전체 변화
2 → 3
결국 원래 갖고 있던 1개만큼 늘어요.

새 Available = 이전 Available + Allocation

Available − Need + (Allocation + Need)에서 Need가 서로 지워져요. 이 과제에서는 성공한 친구가 즉시 완료하므로 중간 대여 상태를 생략할 수 있어요.

05 · 갈림길을 전부 걸어보기

재귀는 “한 명 고른 뒤, 남은 친구들에게 똑같은 질문을 다시 하는 것”이에요. 백트래킹은 한 갈래를 살펴본 뒤 되돌아와 다른 갈래를 보는 거예요.

1. 선택

아직 안 끝났고, 자원이 충분한 친구 한 명을 골라요.

2. 가정하고 내려가기

완료 표시 + 자원 반환.
남은 친구들의 순서 개수를 물어요.

3. 복구하고 다른 선택

반환량을 다시 빼고 완료 표시도 풀어요.

시작  (p.15는 처음부터 셋 모두 실행 가능)
├─ P0 → P1 → P2  ✓ 1개
│      └ P2 → P1  ✓ 1개
├─ P1 → P0 → P2  ✓ 1개
│      └ P2 → P0  ✓ 1개
└─ P2 → P0 → P1  ✓ 1개
       └ P1 → P0  ✓ 1개
                       합계 6개
되돌리기는 실제 완료를 취소하는 일이 아니에요.
이 프로그램은 가능한 미래를 가상으로 시험해요. 다른 미래를 시험할 때는 같은 출발 상태로 돌아와야 해요.

depth는 지금까지 고른 친구 수예요. 전체 친구 수에 도달하면 완성된 순서 1개를 반환해요. 아직 남았는데 고를 친구가 없으면 0개. 여러 갈래의 반환값은 모두 더해요.

안전한 순서 하나만 찾고 멈추면 이 과제의 “총 개수”를 구할 수 없어요. 친구 8명이 언제나 실행 가능하면 최대 8! = 40,320개예요.

06 · 안전하지 않다 ≠ 이미 교착됐다

안전 상태

최대 필요량을 고려해도 모두 완료할 순서가 적어도 하나 있어요.

불안전 상태

그런 순서가 없어요.
모두 끝난다고 보장할 수 없어요.

교착 상태

서로가 가진 자원을 기다려 실제로 계속 멈춰 있는 상태예요.

예: P0가 A를 쥐고 B를 기다리고, P1이 B를 쥐고 A를 기다리면 서로 못 나아가요.

일반 은행원 알고리즘은 요청을 받아도 안전한지 검사해요(p.5–10). 이번 구현은 주어진 초기 상태에서 모두 완료할 안전 순서의 총 개수를 세는 단순화 버전이에요(p.11).

07 · 빈 함수 네 개의 역할

스켈레톤 이름해야 할 일결과
read_statep, r → Available → Allocation → Maximum 순서로 입력·검사정상 1 / 오류 0
calculate_need친구별·종류별로 Maximum − Allocationneed 표 채우기
can_run각 종류의 필요량과 창고량 비교가능 1 / 불가능 0
search_safe_sequence선택 → 재귀 → 복구, 모든 갈래의 수 합산안전 순서 개수

SystemState는 자원 장부, SearchState는 탐색 장부예요. finish는 현재 갈래에서 완료한 친구 표시이고, safe_count는 최종 개수예요.

main은 입력 → Need 계산·출력 → 완료 표시 초기화 → 깊이 0부터 탐색 → 개수 출력 순서로 움직여요.

입력·경계 조건에서 확인할 것
  • 화면상 명시: 1 ≤ p ≤ 8, 0 ≤ r ≤ 5, 음수는 오류. 오류 메시지를 출력하고 종료.
  • r = 0이면 자원 비교 자체가 없어요. 모든 친구 순서가 가능해서 결과는 p!예요.
  • 숫자 사이에는 공백/줄바꿈이 있어요. PDF의 “1 0”은 두 자원 값이지 정수 10이 아니에요.
  • Maximum ≥ Allocation은 모델이 의미 있으려면 필요한 조건이에요. 이를 위반한 입력의 처리 방식은 화면상 과제 조건에 별도로 명시되어 있지 않아요.
  • 숫자가 아닌 입력·입력 누락 검사는 구현 견고성을 위한 추가 고려 사항이에요.

한 문제 더: 다른 갈래 전에 왜 상태를 복구할까요?

앞 갈래에서 돌려받은 자원을 그대로 두면, 다른 갈래가 실제보다 많은 자원으로 시작해요. 그러면 불가능한 순서를 가능하다고 잘못 셀 수 있어요.

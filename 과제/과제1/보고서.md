## 2. 소스코드 분석

### 2.1. 헤더·매크로·구조체·전역변수·함수 원형

```c
#include <stdio.h>
#include <stdlib.h>

// 프로세스 수와 자원 종류 수의 입력 상한
#define MAX_PROCESS 8
#define MAX_RESOURCE 5

// available: 현재 추가로 할당할 수 있는 자원의 수
// allocation: 각 프로세스에 이미 할당된 자원의 수
// maximum: 각 프로세스가 최대로 요구하는 자원의 수
// need: 완료하기 위해 추가로 필요한 자원의 수
typedef struct {
  int n_process, n_resource;
  int available[MAX_RESOURCE];
  int allocation[MAX_PROCESS][MAX_RESOURCE];
  int maximum[MAX_PROCESS][MAX_RESOURCE];
  int need[MAX_PROCESS][MAX_RESOURCE];
} SystemState;

// finish: 현재 탐색 경로에서 완료를 가정한 프로세스 표시
// safe_count: 탐색이 끝난 뒤 저장하는 안전 순서의 총개수
typedef struct {
  int finish[MAX_PROCESS];
  int safe_count;
} SearchState;

// 여러 함수에서 함께 사용하는 시스템 정보와 탐색 상태
static SystemState system_state;
static SearchState search_state;

int read_state(void);
void calculate_need(void);
int can_run(int process);
int search_safe_sequence(int depth);
```

**기능 명세**

- `stdio.h`는 표준입출력에 사용한다. `stdlib.h`는 현재 코드에서 사용하지 않는다.
- 프로세스 수의 상한은 8, 자원 종류 수의 상한은 5이다.
- `SystemState`는 입력받은 시스템 정보와 계산한 Need를, `SearchState`는 재귀 탐색 상태와 최종 개수를 저장한다.
- `allocation`, `maximum`, `need`는 프로세스가 행이고 자원 종류가 열인 2차원 배열이다.

**본인 작성 질문**

1. 각 배열의 행과 열은 각각 무엇을 뜻하는가?
2. `finish`와 `safe_count`는 각각 무엇을 저장하며, 시스템 정보와 탐색 상태를 구조체 둘로 나눈 이유는 무엇이라고 이해했는가?
3. 현재 사용하지 않는 `stdlib.h`를 확인하고도 원본에 남겨 둔 이유를 설명할 수 있는가?

### 2.2. read_state

```c
int read_state(void) {
  // 시스템 상태를 입력받는다. 입력이 잘못되면 0, 모두 읽으면 1을 반환한다.
  printf("프로세스의 수를 입력하세요. (1~8): ");
  if (scanf("%d", &system_state.n_process) != 1 ||
      system_state.n_process < 1 || system_state.n_process > MAX_PROCESS) {
    printf("잘못된 값을 입력하셨습니다.\n");
    return 0;
  }

  printf("자원의 종류의 개수를 입력하세요. (0~5): ");
  if (scanf("%d", &system_state.n_resource) != 1 ||
      system_state.n_resource < 0 || system_state.n_resource > MAX_RESOURCE) {
    printf("잘못된 값을 입력하셨습니다.\n");
    return 0;
  }

  printf("현재 추가로 할당 가능한 각 자원의 수(AVAILABLE)를 입력하세요. (자원 "
         "종류 %d개)\n",
         system_state.n_resource);
  for (int i = 0; i < system_state.n_resource; ++i) {
    if (scanf("%d", &system_state.available[i]) != 1 ||
        system_state.available[i] < 0) {
      printf("잘못된 값을 입력하셨습니다.\n");
      return 0;
    }
  }

  printf("각 프로세스에 이미 할당된 자원의 수(ALLOCATION)를 입력하세요. (%d x "
         "%d)\n",
         system_state.n_process, system_state.n_resource);
  for (int i = 0; i < system_state.n_process; ++i) {
    for (int j = 0; j < system_state.n_resource; ++j) {
      if (scanf("%d", &system_state.allocation[i][j]) != 1 ||
          system_state.allocation[i][j] < 0) {
        printf("잘못된 값을 입력하셨습니다.\n");
        return 0;
      }
    }
  }

  printf("각 프로세스가 최대로 요구하는 자원의 수(MAXIMUM)를 입력하세요. (%d x "
         "%d):\n",
         system_state.n_process, system_state.n_resource);
  for (int i = 0; i < system_state.n_process; ++i) {
    for (int j = 0; j < system_state.n_resource; ++j) {
      // 최대 요구량이 이미 할당된 양보다 작으면 올바른 상태가 아니다.
      if (scanf("%d", &system_state.maximum[i][j]) != 1 ||
          system_state.maximum[i][j] < system_state.allocation[i][j]) {
        printf("잘못된 값을 입력하셨습니다.\n");
        return 0;
      }
    }
  }
  return 1;
}
```

**기능 명세**

- 인자: 없음
- 입력: 표준입력의 프로세스 수, 자원 종류 수, Available, Allocation, Maximum
- 변경: `system_state`
- 반환: 입력을 모두 읽으면 1, 형식 또는 범위 검사를 통과하지 못하면 0

**본인 작성 질문**

1. 프로세스 수, 자원 종류 수, Available, Allocation, Maximum 중 입력 검사가 실패하면 각각 어느 위치에서 함수가 종료되는가?
2. `Maximum < Allocation`인 상태를 왜 거부해야 하는가?
3. 자원 종류가 0이면 세 행렬 입력 반복문이 어떻게 동작하는가?

### 2.3. calculate_need

```c
void calculate_need(void) {
  // 최대 요구량에서 이미 가진 양을 빼서 추가로 필요한 양을 구한다.
  for (int i = 0; i < system_state.n_process; ++i) {
    for (int j = 0; j < system_state.n_resource; ++j) {
      system_state.need[i][j] =
          system_state.maximum[i][j] - system_state.allocation[i][j];
    }
  }
}
```

**기능 명세**

- 인자와 반환값: 없음
- 읽는 값: `maximum`, `allocation`, 프로세스 수, 자원 종류 수
- 변경: `need`
- 계산: `Need = Maximum - Allocation`

**본인 작성 질문**

1. 프로세스가 실행 가능한지 판단할 때 최대 요구량 전체가 아니라 앞으로 추가로 필요한 양을 구해야 하는 이유는 무엇인가?
2. `Maximum < Allocation` 검사를 앞에서 하지 않았다면 Need에는 어떤 값이 생길 수 있는가?

### 2.4. can_run

```c
// 모든 자원 종류에서 필요량을 만족해야 이 프로세스를 완료할 수 있다.
int can_run(int process) {
  for (int i = 0; i < system_state.n_resource; ++i) {
    if (system_state.need[process][i] > system_state.available[i]) {
      return 0;
    }
  }

  return 1;
}
```

**기능 명세**

- 인자: 확인할 프로세스의 인덱스
- 읽는 값: 해당 프로세스의 `need`, 현재 `available`
- 반환: 모든 자원 종류에서 `need <= available`이면 1, 하나라도 부족하면 0
- 상태 변경: 없음

**본인 작성 질문**

1. 자원의 총합을 한 번만 비교하지 않고 각 자원 종류를 따로 비교해야 하는 이유는 무엇인가?
2. 어떤 한 자원이 부족한 순간 바로 0을 반환해도 되는 이유는 무엇인가?

### 2.5. search_safe_sequence

```c
int search_safe_sequence(int depth) {
  int count = 0;

  // depth는 현재까지 순서에 넣은 프로세스 수이다.
  if (depth == system_state.n_process) {
    // 모든 프로세스를 선택했으므로 안전 순서 하나를 찾은 것이다.
    return 1;
  }

  for (int i = 0; i < system_state.n_process; ++i) {
    if (!search_state.finish[i] && can_run(i)) {
      // 현재 경로에서 이 프로세스를 다시 고르지 않도록 표시한다.
      search_state.finish[i] = 1;

      for (int j = 0; j < system_state.n_resource; ++j) {
        // 완료 후에는 기존에 할당받았던 자원만큼 가용 자원이 늘어난다.
        system_state.available[j] += system_state.allocation[i][j];
      }

      // 이 프로세스 다음에 이어질 수 있는 안전 순서의 개수를 더한다.
      count += search_safe_sequence(depth + 1);

      // 다른 후보도 같은 상태에서 검사하도록 자원과 완료 표시를 되돌린다.
      for (int j = 0; j < system_state.n_resource; ++j) {
        system_state.available[j] -= system_state.allocation[i][j];
      }

      search_state.finish[i] = 0;
    }
  }

  return count;
}
```

**기능 명세**

- 인자: 현재 안전 순서에 넣은 프로세스 수 `depth`
- 변경: 탐색 중 `finish`와 `available`을 임시로 변경한 뒤 원래 값으로 복원
- 반환: 현재 상태에서 이어질 수 있는 안전 순서의 개수
- 원리: 실행 가능한 미완료 프로세스를 하나씩 선택하여 모든 경우를 재귀적으로 탐색한다.

**본인 작성 질문**

1. `depth == n_process`일 때 0이나 프로세스 수가 아니라 1을 반환하는 이유는 무엇인가?
2. 프로세스 완료를 가정한 뒤 `need`나 `maximum`이 아니라 `allocation`만 Available에 더하는 이유는 무엇인가?
3. 재귀 호출의 반환값을 `count`에 누적하면 정확히 무엇을 세게 되는가?
4. 재귀 호출 뒤 Available과 `finish`를 복원하지 않으면 다음 후보의 탐색이 어떻게 달라지는가?

### 2.6. main

```c
int main(void) {
  int i, j;

  // 사용자 입력으로 시스템 상태 초기화
  if (!read_state()) {
    return 0;
  }

  // 추가 필요량 계산
  calculate_need();

  // 계산한 Need 행렬 출력
  printf("\nNeed matrix:\n");
  for (i = 0; i < system_state.n_process; ++i) {
    printf("P%d:", i);
    for (j = 0; j < system_state.n_resource; ++j) {
      printf(" %d", system_state.need[i][j]);
    }
    printf("\n");
  }

  // 안전 순서 탐색 상태 초기화
  search_state.safe_count = 0;
  for (i = 0; i < system_state.n_process; ++i) {
    search_state.finish[i] = 0;
  }

  search_state.safe_count = search_safe_sequence(0);
  printf("가능한 시퀀스의 개수: %d\n", search_state.safe_count);

  return 0;
}
```

**기능 명세**

- 입력이 잘못되면 `read_state`의 0을 확인하고 계산 없이 종료한다.
- 정상 입력이면 Need를 계산·출력하고 탐색 상태를 초기화한 뒤 안전 순서 개수를 출력한다.
- 마지막 출력값은 안전 순서 자체가 아니라 가능한 안전 순서의 총개수이다.

**본인 작성 질문**

1. 입력, Need 계산, Need 출력, 탐색 상태 초기화, 재귀 탐색이 이 순서로 실행되어야 하는 이유는 무엇인가?

### 3.4. 경계값과 예외 입력

아래 15건은 공식 예제 3건과 함께 같은 검증 기록에 저장되어 있다. 입력의 줄바꿈은 `/`로 표시했다. 모든 사례의 프로세스 종료 코드는 0이었고 표의 실제 결과는 표준출력에서 확인했다.

| 사례 | 입력 | 기대 결과 | 실제 결과 | 판정 |

## 4. 확인 범위와 정리

- 컴파일 경고 없이 빌드되었고 기록된 18개 사례가 모두 기대 결과와 일치했다.
- 공식 예제의 Need와 안전 순서 개수는 각각 `[[1,0],[0,1]]`·1개, `[[0],[1],[2]]`·6개, `[[0,1],[2,0],[0,1]]`·0개였다.
- 검증 범위는 기록된 정상·경계·오류 입력에 한정된다. 큰 정수의 산술 오버플로 등은 확인하지 않았다.
- 실행 결과가 0개이면 이 상태에서 모든 프로세스를 끝낼 안전 순서를 찾지 못했다는 뜻이다. 현재 교착 상태와 같은 뜻으로 단정하지 않는다.
- 함수별 제출용 분석은 아직 작성되지 않았다. 각 질문에 대한 본인 설명을 받은 뒤 코드와 일치하는지 검토해야 한다.

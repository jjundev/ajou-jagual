# 구현 목적
은행원 알고리즘(Banker's Algorithm)을 기반으로 각 프로세스의 추가 필요 자원(`Need`)을 계산하고, 현재 가용 자원(`Available`)으로 교착상태 없이 모든 프로세스를 완료할 수 있는 **안전 순서(Safe Sequence)의 총개수**를 백트래킹 재귀 탐색으로 구한다.

<tr>
<td>`  for (int i = 0; i < system_state.n_process; ++i) {<br>    if (!search_state.finish[i] && can_run(i)) {<br>      search_state.finish[i] = 1;<br><br>      for (int j = 0; j < system_state.n_resource; ++j) {<br>        // 완료 후에는 기존에 할당받았던 자원만큼 가용 자원이 늘어난다.<br>        system_state.available[j] += system_state.allocation[i][j];<br>      }<br><br>      // 다음 깊이 탐색에서 찾은 안전 순서의 개수를 누적<br>      count += search_safe_sequence(depth + 1);<br><br>`</td>
<td>분석<br>• 자원 회수 원리: 프로세스가 실행되면 추가로 필요했던 Need를 할당받고, 작업 완료 후에는 보유하고 있던 모든 자원(Allocation + Need)을 반납한다. 시스템 관점에서 가용 자원은 Available - Need + (Allocation + Need) = Available + Allocation이 되므로, 코드상에서는 단순히 available\[j\] += allocation\[i\]\[j\]로 처리한다.</td>
</tr>
<tr>
<td>`      // 다른 후보도 같은 상태에서 검사하도록 자원과 완료 표시를 되돌린다.<br>      for (int j = 0; j < system_state.n_resource; ++j) {<br>        system_state.available[j] -= system_state.allocation[i][j];<br>      }<br><br>      search_state.finish[i] = 0;<br>    }<br>  }<br><br>  return count;<br>}`</td>
<td>기능 명세<br>• 상태 변경: 재귀 호출 중 finish 플래그와 available을 임시 변경한 뒤 백트래킹 시 원상 복원<br>분석<br>• 백트래킹(Backtracking): 한 프로세스를 선택한 하위 경로 탐색이 끝나면, 다른 프로세스를 해당 위치에 두었을 때의 경우의 수를 온전히 탐색할 수 있도록 available에서 더했던 allocation을 다시 빼고 finish\[i\] = 0으로 복원한다. 이를 통해 동일한 깊이의 다른 분기 탐색에 영향을 주지 않는다.</td>
</tr>

**결과 분석:** 초기 Available이 `(1, 0)`일 때, P1은 두 번째 자원(B)이 1개 필요(`Need: 0 1`)하므로 실행할 수 없습니다. 반면 P0은 첫 번째 자원(A)만 1개 필요(`Need: 1 0`)하므로 실행 가능합니다. P0이 완료되면 기존에 할당받았던 `(0, 1)`을 반환하여 Available이 `(1, 1)`이 되며, 그제야 P1을 실행할 수 있습니다. 따라서 유일하게 가능한 안전 순서는 `P0 → P1`로 총 1개입니다.
